qFT8とは？

qFT8 は、Android のスマートフォンやタブレット、および Windows・macOS・Linux のパソコンで動作するアマチュア無線用アプリです。トランシーバーを使って FT8、FT4、FT2、LQ8、JS8、WSPR のデジタルメッセージをデコード・送信します。同じトランシーバーと同じケーブルで、音声（SSB）、モールス符号（CW）、RTTY、画像（SSTV）の運用もできます。

どちらの版も使い方は同じです。違いがある箇所では、このマニュアルにその旨を記しています（「Android では…」「パソコンでは…」）。スクリーンショットは Android アプリのものです。「タップ」は、Android では画面をタップすること、パソコンではマウスでクリックすることを指します。

qFT8 は QMX と ICOM 7300 にそのまま（プラグアンドプレイで）対応していますが、VOX を有効にしてスマートフォンやパソコンをスピーカーとマイクの近くに置くか、オーディオ接続ケーブルを使えば、どのトランシーバーでも使えます。トランシーバーなしで qFT8 を試すこともできます。その場合はスピーカーから送信し、マイクで信号を聞きます。qFT8 を動かしている複数のスマートフォンやパソコンは、十分近くにあれば音声で互いに交信できます。

qFT8 は無料のアプリで、広告はありません。ソースコードのライセンスは、ソースコードを公開するときに決定します（LICENSE）。

qFT8 は Luis Quesada Torres（HB9IPH）が 2026 年に開発しました。著作権は同氏が保有し、すべての権利を留保します。

qFT8 には、次のものの一部が含まれています: usb-serial-for-android (Copyright © 2011-2020 Google Inc., Mike Wakerly, Andreas Butti, Kai Morich, BSD-3-Clause)、Roboto (Copyright © 2015 Google Inc. / Christian Robertson, Apache-2.0)、Roboto Mono (Copyright © 2015 Google / The Roboto Mono Project Authors, OFL-1.1)、Natural Earth (Public Domain)、hamradio-zones-geojson (Copyright © 2024 HB9HIL, HA8TKS, MIT license)、Big CTY (Copyright © Jim Reisert AD1C)、Eclipse Temurin / BellSoft Liberica (OpenJDK) Java Runtime (Copyright © Oracle and/or its affiliates and other contributors, GPLv2 with the Classpath Exception)。これらの第三者の作者およびプロジェクトは、いずれも qFT8 を推奨しておらず、qFT8 と提携もしていません。

設定 > デバイス は AUTO のままにしてください。対応する無線機を USB で接続すると自動的に認識されます。一覧から自分で選ぶこともできます。

外部インターフェース（Digirig、汎用の USB シリアルケーブル）についての注意: 自動検出（AUTO）は、USB コントローラーを内蔵したトランシーバーや、機種専用のケーブルを想定しています。汎用の外部インターフェース（Digirig など）を使うと、自動検出では汎用のインターフェースチップしか見えないため、VOX モードになります。外部インターフェース経由で接続した無線機（Lab599 TX-500 など）で CAT 制御を使うには、設定 > デバイス でトランシーバーの機種を手動で選んでください。シリアルポートと通信速度は 設定 > デバイス設定 で設定します。

このほかの機種は VOX で使えます。VOX はオーディオだけの部分的な連携です。

注: 安全上の理由から、qFT8 ではトランシーバーの送信出力を変更できません。出力はトランシーバー側で手動で調整してください。

そのほかのトランシーバー

  • 汎用のオーディオ接続で使えます

パソコン版 qFT8（Windows、macOS、Linux）

パソコン版 qFT8 は Android 版 qFT8 と同じ働きをします。モードも、AUTO 運用と CALL 運用も、ログもサービスも同じです。このセクションでは、Windows、macOS、Linux で使うときに違う点を説明します。インストールの方法、ウィンドウの並び方、2 つの音量スライダー、サウンドデバイスと無線機の選び方、マウスの使い方です。このマニュアルのそれ以外の部分はそのまま当てはまります。パソコンで違う部分には、その旨（「パソコンでは ...」）が書いてあります。

インストールと初回起動

お使いのシステム用のファイルを qft8.com からダウンロードします。ダウンロードには、プログラム、ライセンス、このマニュアルが入った 1 つのフォルダーまたはアプリが含まれています。ほかに何かをインストールする必要はありません。qFT8 に必要な Java ランタイムは中に入っています。

システム ダウンロード 必要なもの
Windows .zip、64 ビット版または 32 ビット版 Windows 10 以降。32 ビット版のファイルは 32 ビット版の Windows でのみ使ってください。
macOS .dmg、すべての Mac 用の 1 ファイル（Apple Silicon と Intel） macOS 10.13 以降
Linux .tar.gz: 64 ビット PC、32 ビット PC、ARM 64 ビット、ARM 32 ビット（Raspberry Pi） サウンドサーバー（PulseAudio または PipeWire）のあるデスクトップ。最近の Ubuntu の X11 と Wayland（XWayland 経由）で動作確認済みです。
その他のパソコン .jar Java 21 以降（ご自身でインストール）

qFT8 には、プロセッサーコアが 2 つ以上（4 つ以上を推奨）あるパソコンと、960 x 560 ピクセル以上のウィンドウを置ける広さが必要です。2 コアでも動作しますが、動作は遅くなります。低速なパソコンをご覧ください。

Windows

  1. .zip を開き、qFT8 フォルダーをプログラムを置いている場所（たとえばドキュメントやデスクトップのフォルダー）にドラッグします。zip の中から qFT8 を実行しないでください。
  2. フォルダーを開き、qFT8.exe をダブルクリックします。
  3. 初回は Windows に "Windows protected your PC" と表示されることがあります。More info を押してから Run anyway を押してください。qFT8.exe には作者の証明書で署名してありますが、Windows は新しいプログラムをなかなか信頼してくれません。
  4. Windows が qFT8（"OpenJDK Platform binary" と表示されます）のファイアウォール通過を許可するかどうか尋ねてきたら、プライベートネットワークでのみ、かつWeb リモコンまたは bridge を使う場合にのみ許可してください。

macOS

  1. .dmg を開き、qFT8 を同じウィンドウのアプリケーションのショートカットにドラッグします。その後、.dmg を取り出します。
  2. qFT8 をアプリケーションから起動します。.dmg のウィンドウの中から、またはブラウザーが保存した場所から起動すると、qFT8 が「qFT8 を「アプリケーション」に移動しますか?」と尋ねます。移動を押す（Finder と同じように、macOS がパスワードを求めることがあります）か、今はしないを押してください。
  3. macOS は、qFT8 がマイクを使ってよいかどうかを一度だけ尋ねます。Allow を押してください。qFT8 はこれで無線機の音を聞きます。押しそびれたり拒否したりした場合、qFT8 はマイクの許可を待っているというカードを表示します。System Settings > Privacy & Security > Microphone（macOS 13 以降）または System Preferences > Security & Privacy > Privacy > Microphone（それ以前の macOS）で許可し、qFT8 をもう一度起動してください。

Linux

  1. .tar.gz を展開します（tar -xzf qFT8-*.tar.gz、またはファイルマネージャーで）。qFT8 フォルダーができます。
  2. そのフォルダーで ./qFT8 を実行します（ファイルマネージャーがプログラムを実行できるなら、ダブルクリックでも動きます）。初回起動ではプログラムを ~/.cache/qft8 に展開するため、数秒かかります。新しいバージョンは、そこにある古いバージョンを自動的に置き換えます。
  3. 無線機のシリアル（CAT）ポートはあるグループに属しています。Ubuntu、Debian、Fedora では dialout、Arch では uucp です。USB サウンドカードは audio に属しています。お使いのアカウントがポートのグループに入っていない場合、qFT8 はカードで知らせます。修正するを押すと、あなたをそのグループに追加し（パスワードを求められます）、qFT8 を再起動するので、ログアウトしなくても変更が反映されます。うまくいかない場合は、ターミナルで試すとコマンドをコピーで、ご自身で実行するコマンドが得られます。その後、一度ログアウトして再度ログインしてください。

初回起動

qFT8 は Android 版と同じようにコールサインを尋ねます（コールサインの入力をご覧ください）。その直後に、デバイス設定というカードが開きます。無線機を選び、続いてそれにつながっているサウンドデバイスを選びます。入力の下のウォーターフォールには、無線機から届いている音が表示されます。無線機の電源が入っていれば、ノイズや信号が見えるはずです。同じカードは、下部バーの歯車の右にあるボタンでいつでも開けます。ウォーターフォール上の赤い音声なしのバッジからも開けます。サウンドデバイスと無線機の接続をご覧ください。

同じところと違うところ

運用に関することはすべて同じです。最初の QSO、デジタルモード、AUTO、CALL、ログ、ADIF、QRZ、LoTW などのサービス、SSB、CW、RTTY、SSTV、送信制限、そして安全のための決まりも同じです。qFT8 の起動時は TX が必ずオフで、TX を入れられるのは TX ボタンだけです。また qFT8 が無線機の送信出力を変えることはありません。このマニュアルのスクリーンショットは Android アプリのものです。「タップ」はマウスでのクリックに読み替えてください。違いは次のとおりです。

Android パソコン
画面 1 つの画面: スペクトログラムと 1 つのタブ。向きと 4 分割は設定で選びます 3 つのレイアウトをレイアウトボタンで切り替えます。すべて 1 つのウィンドウ、スマートフォンのような左右並び、またはすべてのペインを別々のウィンドウにする方式です。 詳細
音量 スマートフォンの音量と、設定の「トーン出力音量」および「送信時にシステム音量を ... に設定」 下部バーに 2 つのスライダー: サウンドデバイス自体の音量と、qFT8 のトーン音量。qFT8 がデバイスの音量を勝手に変えることはありません。詳細
サウンドデバイス スマートフォン内蔵のもの、または無線機の USB サウンドカード デバイス設定の無線機とあなた（オペレーター）で選びます。 詳細
無線機の接続 許可ダイアログ付きの USB シリアル（COM）ポート。ダイアログはありませんが、Linux ではグループ、macOS ではマイクの許可が必要です。 詳細
入力 タッチ: タップ、長押し、スワイプ マウス: クリック、右クリック、ホイール。キーボードでは操作部品を操作できません。 詳細
設定とデータ アプリの内部 ユーザーフォルダー内のフォルダー。設定ファイルは Android と同じです。 詳細
バックグラウンド フォアグラウンドサービス、画面オフ、バッテリー節約 どれもありません。ウィンドウが開いている間は動き続けます。低速なパソコン用のモードがあります。 詳細
アップデート Google Play ダウンロードボタン付きの通知。プログラムは自分で置き換えます。 詳細

画面レイアウトとレイアウトボタン

下部バーの右端にあるボタンがレイアウトボタンです。クリックするたびに、レイアウトが次のものに変わります。フローティング、固定、オールインワン、そしてまたフローティングの順です。ボタンの絵は現在のレイアウトを示します（スクリーンリーダーは「レイアウト: 固定」のようにその名前を読み上げます）。qFT8 は次回の起動に備えてレイアウトを記憶し、各レイアウトごとに別々に、すべてのウィンドウの大きさと位置も記憶します。

  • オールインワン（初回に qFT8 が起動するレイアウト）。同じ大きさの 4 つの部分に分かれた 1 つのウィンドウです。左上にスペクトログラム、右上にステーションのタブ、左下に世界地図、右下に QSO ログが、下部バーの上に並びます。設定は同じウィンドウの右側にある縦長の列です。下部バーの歯車ボタンで表示と非表示を切り替えられ、見出しの X でも切り替えられます。下部バーには 4 つの部分のためのボタンはありません。それらは常に表示されています。
  • 固定（Android アプリと同じ）。左にスペクトログラム、右にステーションのタブを置いた 1 つのウィンドウが、下部バーの上に並びます。両者の間の細い仕切りをドラッグすると、どちらかを広げられます（割合は 20 % から 80 % の間）。下部バーの QSOログ、世界地図、設定のボタンで、この 3 つが別のウィンドウとして開きます。もう一度押すと閉じます。
  • フローティング。メインウィンドウは下部バーだけに縮み、すべてのペインが独立したウィンドウになります。別の画面にも含め、好きな場所に置けます。スペクトログラム、ステーション、QSO ログ、世界地図、設定です。下部バーには、この 5 つそれぞれを開閉するボタンが並びます。qFT8 を 2 台のモニターに広げたいとき、または小さい画面でスペクトログラムとバーだけを残したいときに使ってください。

レイアウトを変えても、ウィンドウが並べ替えられるだけです。失われるものはなく、送信中の送信は続き、TX もそのままです。 世界地図には全画面ボタン（地図の右上）があります。もう一度ボタンを押すか Esc を押すまで、地図が画面いっぱいに広がります。

ヒント: Android の設定 向き、4分割、アプリで覆う領域（画面レイアウトをご覧ください）はパソコンにはありません。レイアウトボタンとウィンドウの大きさがその代わりになります。

ウィンドウの扱い方

  • タスクバーには 1 つのプログラム。レイアウトに関係なく、qFT8 はタスクバー、Dock、Alt-Tab に 1 つの項目（メインウィンドウ）だけを出します。フローティングと固定のレイアウトのペインウィンドウは、それぞれの項目を持ちません。（Linux では GNOME、KDE Plasma、Xfce、Cinnamon、MATE、LXQt で動作確認しています。）
  • ペインウィンドウには小さな専用の枠があります（どのシステムでも同じ）。どの辺や角からでもウィンドウの大きさを変えられる細い縁、ドラッグしてウィンドウを動かせるペイン名入りのタイトル帯、そして下部バーのボタンと同じようにペインを閉じる X です。Esc も、そのウィンドウがアクティブなときにペインウィンドウを閉じます。
  • メインウィンドウは通常どおり大きさの変更と最大化ができます。オールインワンのレイアウトでは 960 x 560 ピクセルより小さくできず、初回は画面の 85 % の大きさで開きます。
  • 設定の幅は一定です。設定のウィンドウ（と列）は、すべての行が収まるよう Android の設定ページと同じ幅を保ちます。高さは変えられます。
  • すべての大きさ。設定 > アプリケーションには、Android と同じ 2 つのサイズスライダー（ユーザーインターフェースとフォントスケールとUIコンポーネント（フォント除く）のスケール）があります。高解像度の画面（Retina の Mac や、125 % から 200 % の Windows）では、qFT8 はシステムの倍率に従います。

音量: デバイスとトーン

下部バーのデバイス設定ボタンとレイアウトボタンの間に、2 つの小さなスライダーが上下に並んでいます。2 つは別々のものを制御し、どちらも送信に関係します。

  • 上のスライダー（スピーカーの絵）: デバイスの音量。これはqFT8 が送信に使うサウンドデバイスの音量です。無線機の USB サウンドカード、または音声をそこに送っているならスピーカーやヘッドホンです。システム自身の音量コントロールがそのデバイスについて示すのと同じレベルで、どちらかを変えるともう一方も追従します（スライダーは数秒以内に）。
  • 下のスライダー（波の絵）: トーン音量。これはqFT8 自身が生成する送信音声（FT8、FT4、WSPR、JS8、LQ8 のトーンや TUNE の音）の大きさで、0 から 100 % です。送信中にも変えられ、同じ送信の中で結果を聞いて確かめられます。初期値は 100 % です。トーン音量は無線機ごとに記憶されます。Web リモコンにも同じスライダーがあり、こちらを動かします。

デバイススライダーの動作。

  • qFT8 は起動時にデバイスの音量を読み取って表示し、2 秒ごとに読み直します。システムで音量を変えると、スライダーが追従します。出力デバイスを切り替えると、スライダーには新しいデバイスの音量が表示されます。
  • qFT8 がデバイスの音量を変えるのは、このスライダーを動かしたときだけです。送信の前に自分から設定することはありません。これは Android と違う点です。Android では、qFT8 が送信時にスマートフォンの音量を設定の値に合わせられますが、パソコンにはその 2 つの設定はありません。
  • 動かした後、qFT8 は音量を読み戻すので、スライダーにはデバイスが実際に受け取った値が表示されます。
  • 音量コントロールのないデバイス（macOS の一部の出力）では、スライダーはグレーアウトされ、つまみがありません。
  • qFT8 の起動後に初めて送信するか TUNE を押すと、デバイススライダーのスピーカーの絵とつまみが、5 秒間グレーから白へ、また元へと明滅します。これは、このレベルが無線機をどれだけ強く駆動するかを決めるものだと知らせるためです。触れると止まります。
  • スライダーをドラッグしている間、その値がパーセントで横に表示されます。

ヒント: この 2 つのスライダーは、[QMX のみ] オーディオの確認にある Android 向けの音量の助言と同じ役目を果たします。無線機が音声が小さすぎる、または大きすぎると示している場合（QMX ではバーの代わりに 2 つの点が出ます）は、まずデバイス音量スライダーの位置を変えてみてください（たとえば 70 %、80 %、60 %、100 %）。そして微調整にトーン音量を使います。それ以外のときは、トーン音量は初期値（100 %）のままにしてください。qFT8 が無線機の送信出力を設定することはありません。それは無線機側で調整してください。

サウンドデバイスと無線機の接続

デバイス設定カード

歯車の右にあるボタンで開きます（初回起動時と、音声なしのバッジからも自動的に開きます）。2 つの半分に分かれています。

  • 無線機（左）: 無線機と、無線機自身のサウンドカード。無線機デバイスからの入力（無線機が聞いているもの。qFT8 がデコードするもの）と無線機デバイスへの出力（qFT8 が送信するもの）があり、それぞれにサンプルレート、ビット数、チャンネル数があります。無線機が別のものを必要としない限り、システムの既定のままにしてください。入力の下にある小さなライブウォーターフォールで、音が届いているかどうかが分かります。
  • あなた（オペレーター）（右）: SSB と CW のための、ご自身のマイクとスピーカーまたはヘッドホン（同じものを説明しているスピーカーとマイクをご覧ください）、テストボタン、そしてデジタルモードで無線機の音をスピーカーで再生です。ここには無線機自身のサウンドカードを決して選ばないでください。

同じ選択肢と、さらに多くの項目（バッファーサイズ、音切れの警告）が設定 > デバイス設定にあります。Android の「オーディオシステム」と「音声入力ソース」の行は、パソコンにはありません。デバイスは AUTO のままにしてください。無線機用には無線機自身のサウンドカードを、あなた用には無線機のものではないデバイスを優先して選びます。

表示されることのある通知

  • 出力が無線機へ（バッジ）: パソコンの既定のサウンド出力が無線機のサウンドカードになっているため、システム音、ブラウザー、通知音が無線機に入り、無線機が VOX またはデータ入力で送信する設定の場合は電波に乗るおそれがあります。qFT8 は、別の出力を使う（... を使う）、サウンド設定を開く、または今後尋ねないことを提案します。qFT8 の送信音声も既定の出力に従います。先に無線機のサウンドカードを qFT8 の出力に選び、その後でパソコンの既定を変更してください。
  • 無線機の入力なし（バッジ、Linux）: 無線機のサウンドカードが出力専用のプロファイルになっているため、サウンドシステム上に入力がありません。無線機を直接読み取る（推奨）を押すと、qFT8 がカードを直接読み取ります。PRO AUDIO に切り替えは、すべてのプログラムに対してカードのプロファイルを変更します。
  • 入力デバイスなし: システムに入力がありません。無線機またはサウンドカードを接続し、パソコンのサウンド設定に入力として表示されることを確認してください。
  • 無線機の USB ドライバーがインストールされていません（Windows と macOS）: Icom IC-7300 など、Silicon Labs の USB チップを使う無線機には CP210x ドライバーが必要な場合があります。メーカーのドライバーページからダウンロードしてインストールし、無線機をつなぎ直してください。
  • 別の無線機?（バッジ）: つながっている無線機が、qFT8 で選んだものと違います。

システム別

  • Windows: qFT8 は Windows 自身のオーディオエンジン（WASAPI）を通して無線機の音を聞きます。従来の方式より安定したストリームが得られます。無線機は COM ポート（COM3、...）と、「USB Audio CODEC」などのサウンドデバイスとして現れます。Windows では COM ポートを使えるプログラムは 1 つだけです。アクセスが拒否されたと qFT8 が表示したら、もう一方のプログラム（ロガー、デジタルモードのプログラム、無線機付属のソフトウェア）を閉じて、再試行を押してください。
  • macOS: 無線機のポートは /dev/cu.usbmodem...（QMX）または /dev/cu.SLAB_USBtoUART（IC-7300）のように見えます。macOS ではポートにグループや許可は不要で、上で述べたマイクの許可だけが必要です。ポートが拒否された場合は、別のプログラムがそれを開いています。
  • Linux: ポートは /dev/ttyACM0 や /dev/ttyUSB0 のように見え、上で述べたグループが必要です。サウンドデバイスはサウンドサーバー（PulseAudio または PipeWire）のものなので、無線機のスピーカー、ヘッドホン、マイクをそれぞれ別のデバイスにできます。デバイス音量スライダーは、パッケージ pulseaudio-utils の pactl を使います（PipeWire でも動作します）。

無線機とポートの選び方

Android と同じく、設定 > デバイスは AUTO のままにしてください。対応する無線機は、接続すると認識されます。汎用の USB シリアルインターフェース（たとえば Digirig）の先にある無線機は、手動で無線機を選び、その後 設定 > デバイス設定 > 通信ポート設定 > USB デバイスでポートを選びます。ボーレート、データビット、ストップビット、パリティ、キーイング方式（DTR、RTS、CAT）もそこにあり、設定のオーバーライドを許可にチェックを入れない限り、選んだ無線機に合わせて qFT8 が設定します。音声だけを使う無線機（VOX）には、ポートはまったく必要ありません。コマンドラインでは、qFT8 が認識しているポートとサウンドデバイスを一覧表示できます。

設定: 保存場所と、スマートフォンからの引っ越し

qFT8 は保存するものすべてを、プロファイルフォルダーという 1 つのフォルダーに置きます。設定、パスワード、QSO ログ、バックアップ、画像です。

  • Windows: C:\Users\<あなた>\qFT8
  • macOS と Linux: ホームフォルダーの .qft8（~/.qft8。Finder や多くのファイルマネージャーでは非表示）

このフォルダーは、プログラムを更新または削除しても残るので、新しいバージョンでも設定とログがそのまま使えます。メインの設定ページの最下部、バージョンの下にある設定ディレクトリ:にそのフォルダーが表示され（クリックで開きます）、バグを報告の横にあるログフォルダを開くボタンで、qFT8 のログのフォルダーが開きます。バグレポートを送るときに便利です。 以前の Windows 版では qFT8.exe の隣の settings フォルダーに置いていました。新しいバージョンの初回起動で、それを移動し、コピーを確認し、古いフォルダーを settings.old として残します。

設定をスマートフォンから（またはスマートフォンへ）移す

設定をエクスポートと設定をインポート（メインの設定ページの設定ファイルの下）は、Android でもパソコンでも同じ1 つのファイルを作成し、読み込みます。スマートフォンでエクスポートし、ファイルをパソコンにコピーして（メール、クラウド、ケーブル）、そこでインポートします。逆の向きもできます。

  • このファイルには、QRZ API キー、LoTW 証明書、パスワードが入っています。決して共有しないでください。
  • QSO は入っていません。ログは ADIF で移すか、qFT8 ログサーバーにコピーさせてください。
  • このパソコンだけに関することは入っていません。サウンドデバイスの選択（デバイスが違うため）、レイアウト、ウィンドウです。パソコンで選び直してください。
  • インポートでは、確認のために yes と入力する必要があり、TX がオフである必要があります。QSO はそのまま残り、TX が入ることは決してありません。

パソコンでは、エクスポートが既存のファイルを置き換えることはありません（ADIF のインポート/エクスポートをご覧ください）。

複数のコピー、bridge、Web リモコン、コマンドライン

  • プロファイルフォルダーごとに 1 つのコピー。同じフォルダーを使う別のコピーが動いているときに qFT8 を起動すると、既に実行中ですと表示され、再試行または終了が提案されます。1 つのフォルダーで 2 つのコピーを動かすと、設定とログが壊れるおそれがあるためです。複数のコピーを同時に動かすには（たとえば無線機ごとに 1 つ）、起動するときにそれぞれ専用のフォルダーを指定します。qFT8 --qft8_profile D:\qft8-radio2（Windows では qFT8.exe）。そのフォルダーに書き込めない場合、qFT8 はエラーで停止します。
  • Web リモコン。パソコン版には、Android と同じリモートコントロール Web サーバーがあり（初期設定ではオフ、ポート 13497）、音量スライダーを含め、同じページを表示します。ネットワーク上のスマートフォンや別のパソコンから操作するのに使います。
  • bridge。パソコンは、よく使われる bridge です。無線機をパソコンにつなぎ、スマートフォン、iPhone、または別のパソコンの qFT8 から操作します。ほかに用途のないパソコンでは、ウィンドウなしで動かすこともできます（qFT8 --bridge）。
  • コマンドライン。qFT8 --help でオプションの一覧が表示されます（Windows では小さなウィンドウに表示されます）。--list-devices は、qFT8 が認識しているすべてのシリアルポートとサウンドデバイスを一覧表示して終了します。--port <デバイス> は既定のシリアルポート（COM3、/dev/ttyACM0）を設定します。--qft8_profile <フォルダー> はプロファイルフォルダーを選びます。--bridge は bridge を起動します。--opengl はウィンドウを OpenGL で描画します（うまく動かないときをご覧ください）。

低速なパソコン

設定 > アプリケーション > 低速デバイス / 低バッテリーモードは、qFT8 を軽くします。1 秒あたり約 30 フレームの描画になり、ウォーターフォールの再描画の頻度が下がり、世界地図は表示されている間だけ動作します。変わるのは描画だけで、デコーダーは変わりません。オンでもオフでも、qFT8 のデコード結果は同じです。

低速モードはチェックボックスをオンにしたときだけ有効になり、勝手にオンになることはありません。プロセッサーコアが 1 つか 2 つのパソコンでは、qFT8 は起動時にオンにするかどうかを尋ねます。低速モードを有効にするはチェックボックスをオンにし、閉じるは次回の起動時にもう一度尋ね、今後表示しないは尋ねるのをやめます。そのようなパソコンでは、低速モードかどうかにかかわらず、qFT8 は自動的にデコーダーにプロセッサーの公平な取り分を与えるので、ほかの忙しいプログラムにデコーダーが飢えさせられることはありません。

アップデートとアンインストール

アップデート

起動時に新しいバージョンを確認するにチェックが入っていると（初期設定。起動時に新しいバージョンを確認するをご覧ください）、qFT8 は 1 日に一度、新しいバージョンがあるかどうかを問い合わせ、あれば新しいバージョンがありますと、閉じるおよび今すぐダウンロードを表示します。後者はダウンロードページをブラウザーで開きます。qFT8 が自分で更新することはありません。更新するには、新しいファイルをダウンロードして古いプログラムを置き換えます。

  • Windows: qFT8 を閉じ、qFT8 フォルダー（または qFT8.exe だけ）を新しいものに置き換えます。
  • macOS: qFT8 を閉じ、新しい qFT8 をアプリケーションにドラッグして、Replace を選びます。
  • Linux: qFT8 を閉じ、新しい qFT8 を実行します。自動的に展開され、キャッシュにある古いバージョンが削除されます。

設定とログはプロファイルフォルダーに残ります。

アンインストール

qFT8 を閉じてプログラムを削除します。qFT8 フォルダー（Windows、Linux）、またはアプリケーションの qFT8（macOS）です。Linux では ~/.cache/qft8 も削除します。これでも設定とログは残ります。それらも削除するには、プロファイルフォルダー（上記）を削除します。 その場合、QSO ログが消えます。先に ADIF でエクスポートしてください。

うまく動かないとき

  • ウォーターフォールが空で、バッジに 音声なし と出ている。デバイス設定を開いてください。無線機のサウンドカードが入力になっていますか。無線機の電源は入っていますか。macOS ではマイクの許可を、Linux では 無線機の入力なし のバッジとグループを確認してください。
  • 無線機は受信するが送信しない、TUNE で何もキーイングされない。ポートが拒否されました。別のプログラムがそれを開いている（Windows、macOS）か、お使いのアカウントがグループに入っていません（Linux）。どちらかは qFT8 が表示します。もう一方のプログラムを閉じて再試行を押すか、Linux のカードの指示に従ってください。 スマートフォンやパソコンがトランシーバーを認識しない、または接続が切れるもご覧ください。
  • 無線機の音が小さすぎる、大きすぎる、またはバーの代わりに 2 つの点が出る（QMX）: デバイス音量スライダー（音量）を動かしてください。パソコン自身のそのデバイスの音量がミュートになっていないかも確認してください。
  • パソコンの音が電波に乗る。既定の出力が無線機のサウンドカードになっています。出力が無線機へのバッジに答えるか、システムで別の既定の出力を選んでください。
  • 「既に実行中です」。別のコピーがプロファイルフォルダーを使っています。それを閉じるか、このコピーを専用の --qft8_profile フォルダーで起動してください。
  • ウィンドウが真っ黒、または表示が乱れる（古いグラフィックドライバー、仮想マシン、リモートデスクトップ）: グラフィックドライバーを更新してください。直らない場合は、qFT8 を --opengl（qFT8 --opengl）で起動してください。ウィンドウを別の方法で描画します。それでも直らない場合は、お使いのシステムとグラフィックカードを添えて、（設定の）バグを報告から報告してください。
  • ウィンドウが画面の外にある（画面が取り外された）: qFT8 は、ウィンドウを開くときに各ウィンドウの保存された位置を確認し、その画面がなくなっている場合や、大部分が画面の外に出てしまう場合は、メイン画面の中央で開きます。それでもウィンドウに手が届かない場合は、下部バーのボタンでそのペインを閉じてからもう一度開くか、qFT8 を再起動してください。
  • ウォーターフォールが固まる、音が途切れる、1 コアまたは 2 コアのパソコンで負荷が高い: 低速なパソコンをご覧になり、ほかのプログラムを閉じてください。続く場合はバグを報告で報告してください。

クイックセットアップ

トランシーバーには必ず適切な電源（たとえば QMX では 12V 以下）を使ってください。そうしないと故障の原因になります。

また、スマートフォンやパソコンとトランシーバーをつなぐ USB ケーブルとアダプターがデータ転送に対応していることを確認してください。Android では、USB-C 以外のコネクターを持つ端末には専用の OTG（On-The-Go）ケーブルが必要なことがよくあります。qFT8 がトランシーバーを認識しない接続トラブルの多くは、対応していないケーブルやアダプターが原因です。

Android では、端末によっては USB OTG が初期設定で無効になっています。その場合は端末の設定で有効にする必要があります（この項目は、詳細設定、システム設定、追加設定などの奥にあることがあります）。接続がうまくいかないとき、特に、qFT8 で信号は受信できるのに送信できず、機種が完全に対応している（デバイスのドロップダウンに表示される、AUTO で自動認識されるなど）にもかかわらず CAT コマンドが効かないときは、これが原因である可能性が非常に高いです。

初期権限の許可

Android では、qFT8 を初めて開くと、いくつかの権限を求められます:

  • qFT8 に音声の録音を許可: この権限は必須です。qFT8 がトランシーバーからの信号を取り込むために必要です。qFT8 が音声の録音を保存、共有、アップロードすることはありません。
  • qFT8 にこの端末のおおよその位置情報へのアクセスを許可: 任意ですが、許可をおすすめします。qFT8 は、FT8 の交信でやり取りする Maidenhead グリッドロケーターを得るために使います。正確な位置情報にアクセスしたり、それを共有したりすることはありません。
  • qFT8 に通知の送信を許可: 任意ですが、許可をおすすめします。qFT8 は、バッテリーを節約するために最小化中や画面オフの間もフォアグラウンドサービスとして動作するのに使います。通知が有効になるのは、トランシーバーに接続している間だけです。
  • アプリが常にバックグラウンドで動作することを許可: 任意ですが、許可をおすすめします。画面オフの間も qFT8 が安定して動作するために必要です。

パソコンでは、必要な許可はもっと少なくなります。macOS では、qFT8 にマイクの使用を許可するかどうかをシステムが一度だけ尋ねます。qFT8 はマイク入力でトランシーバーの音を聞くので、許可してください。Linux では、無線機のシリアル（CAT）ポートを使うために、アカウントがそのポートのグループ（通常は dialout）に入っている必要があります。入っていない場合は、qFT8 がその旨を説明し、修正を提案します。

基本方針: qFT8 は、このアプリ専用のサーバーに情報を送信することはありません。すべてのデータ処理は端末上で行われます。有効な QRZ APIキー を入力した場合は、コールサイン、日付と時刻、そして任意でおおよその位置情報の共有を、ご自身で明示的に許可することになります。

詳しくは、qFT8 の プライバシーポリシーとライセンスをご覧ください。

コールサインの入力

qFT8 を使うには、コールサインの入力が必須です。実際のトランシーバーに接続する予定がない場合は、テスト用にどんなコールサインを入力してもかまいません（例: XX1XXX）。

qFT8 は、コールサインの入力と、次の事項の確認を求めます:

  • トランシーバーに接続してこのソフトウェアを使用するには、有効な免許を持っている必要があります。
  • このソフトウェアを無人で動作させてはいけません。
  • 免責事項: qFT8 を使用することにより、法令の順守、安全、機器の損傷についてのすべての責任を、ご自身が負うものとします。

USB 接続の権限の許可

Android では、トランシーバーを接続して qFT8 を開くと、システムのダイアログが表示されます（パソコンでは表示されません。上記の Linux の注記を参照してください）:

「qFT8 を開いて Transceiver を処理しますか？」

  • この権限は、トランシーバーとの通信に必須です。
  • 許可しない場合、qFT8 は信号を受信できますが、送信はできません。
  • 「Transceiver が接続されたら常に qFT8 を開く」を選んでおくと便利です。

トランシーバーの接続で問題が起きた場合は、トラブルシューティングのスマートフォンやパソコンがトランシーバーを認識しない、または接続が切れるを参照してください。

qFT8 は、トランシーバーが接続されるたびに自動で設定を行います。

[QMX のみ] オーディオの確認

運用を始める前に、スマートフォンまたはパソコンと QMX の間でオーディオ信号が正しくやり取りされていることを確認することが大切です。TX ボタンを押し、次のいずれかのシーケンスで QMX が送信を始めるのを待ちます。

すべて正常に動作している場合

TX ボタンに出力（例: 5W）が表示されていれば、すべて正常に動作しています。QMX LCD では、画面左上の「A」の VFO マーカーの下にバーが表示されるはずです。これは、QMX が qFT8 から良好なオーディオ信号を受け取っていることを示します。また、LCD の周波数の後ろに、SWR 保護を示す「S」が表示されていないことも確認してください。

周波数の後ろに「S」が表示される場合

QMX LCD の周波数の後ろに「S」が表示されている場合は、SWR 保護が働いています。アンテナが現在のバンドにきちんと調整されていません。QMX のメニューにある SWR チェックで SWR を測定し、アンテナを調整してください。

  • ファームウェア 1_04_004 以降: qFT8 がサイクルの終わりに SWR 保護を自動でリセットします。
  • ファームウェア 1_03_000 以降: QMX の Protection メニューで "SWR Protection reset options" を TX->RX に設定すると、自動でリセットされます。
  • 旧ファームウェア（1_03_000 より前）: SWR 保護をリセットするには、QMX の TUNE メニューに入ってから出るか、電源を入れ直す必要があります。

バーではなく 2 つの点が表示される場合

画面左上の「A」の VFO マーカーの下に、バーではなく 2 つの点が QMX に表示される場合は、オーディオの音量が小さすぎるか大きすぎるかのどちらかです。

対処法: qFT8 の設定を開き、「無線機使用時にシステム音量を [X] に設定」の項目でいろいろな値（例: 70%、80%、60%、100%）を試してください。どれかの値で 2 つの点がバーに変わるはずです。

スマートフォンによっては、この項目が効かないことがあります。その場合はチェックを外し、バーが表示されるまでスマートフォンの音量を手動でいろいろな値（100%、90%、80% など）に変えてみてください。

また、コモンモード電流が QMX の動作に影響していることもあります。アンテナにコモンモードチョークを入れると、オーディオの問題が改善する場合があります。

「A」の下に何も表示されない場合

QMX LCD の画面左上の「A」の VFO マーカーの下に、バーも点も表示されない場合は、qFT8 がトランシーバーを正しく制御できていない可能性があります。多くの場合、USB の権限が許可されていないか、誤ってダイアログを閉じてしまったことが原因です。受信はできますが、送信はできません。

対処法: QMX のケーブルを抜いて、もう一度差し込みます。Android では、権限のダイアログがもう一度表示されるはずです。ケーブルが QMX に合っていない可能性もあるので、別の USB-C ケーブルを試してください。

QMX LCD の画面左上の「A」の VFO マーカーの下にバーが表示され、TX ボタンに出力が表示されれば、QMX の設定は完了です。運用を始められます。

[任意] QSO のインポート

ここで、これまでの QSO をインポートできます。方法はいくつかあります。いずれも、qFT8 の下部バーのいちばん右のボタンで設定を開いて行います。

手動で行う方法: 設定の「ADIFファイルのインポート」セクションを開き、「ADIFからQSOをインポート」ボタンを押して、インポートする .adi ファイルを選びます。

QRZ から自動で行う方法: QRZ の有料サブスクリプションが必要です。設定の「QSO同期」セクションを開き、自局のコールサインの QRZ APIキー を入力して「検証」を押し、「QRZからQSOをインポート」ボタンを押します。これで、QRZ への自動アップロードと交信証明の確認も設定されます。

LoTW から自動で行う方法: 無料です。設定の「QSO同期」セクションを開き、LoTW のユーザー名とパスワードを入力し、必要に応じてバックグラウンド同期を有効にします。これで、最初の「LoTWからQSOをインポート」も行えるようになります。

qFT8 での最初の QSO

注: FT8 では正確な時刻が非常に重要です。qFT8 は、アプリの起動時に NTP（インターネット）または GPS（衛星）で自動的に時刻を同期します。インターネットのない場所で移動運用するときは、「設定」タブの GPS同期ボタンで、GPS 衛星から直接時計を合わせられます。これには正確な位置情報の権限と、空がよく見える場所が必要です。

この時点で、トランシーバーは適切な電源とアンテナに接続され、すべての権限が許可されているはずです。アンテナが、SWR 保護が働かない程度の SWR（できれば常に 2 未満）になるよう、使うバンドに調整されていることを確認してください。QMX の SWR 保護を無効にするのはやめてください。終段やアンテナチューナーを壊すおそれがあります。

次に、使いたいバンドを qFT8 の下部バーまたはトランシーバーで選びます。どちらか一方で設定すれば、もう一方にも反映されます。

この時点で、スペクトログラムに信号が表示されてメッセージのデコードが始まり、「ステーション」タブは聞こえている局で更新されていきます。

TX ボタン（下部のいちばん左のボタン）を押すと、送信が有効になります。

すべてが正常であれば、やがて TX ボタンが「TX Transmitting」と点灯し、送信出力と SWR が表示されます（例: 「5.0W SWR 1.2」）。

既定では「AUTO」モードが選ばれているので、qFT8 は QSO を始め、「ログ」タブに記録していきます。

スペクトログラムをタップすると Tx の周波数オフセットを変更できます（スペクトログラム上部の、ピーク表示のある部分をタップすると、周波数を手動で入力できます）。下部バーの 0 と 1 のボタンをタップするとシーケンスを変更でき、それぞれの「CALL」ボタンをタップすると特定の局を呼び出せます。「ステーション」タブの「AUTO」ボタンのある行を調整して、運用の方針を決めることもできます。これらの高度な機能については、以降の章で詳しく説明します。

qFT8 は局の呼び出しを始め、届く局がなければ CQ を出し始めます。すべてが正しく設定され、伝搬が良ければ、やがて QSO が成立します。

qFT8 が信号をきちんと受信できず、メッセージもデコードできない場合は、どこかに問題があります。そのバンドの伝搬が開けていない、アンテナの調整が合っていない、アンテナがトランシーバーに正しく接続されていない、トランシーバーがスマートフォンやパソコンに正しく接続されていない、機器のどれかが正常に動作していない、といった可能性があります。よくある問題については、下のトラブルシューティングを参照してください。

デジタルモードの概要

アマチュア無線のデジタルモードは、テキストやデータを可聴周波数の周波数偏移変調（FSK）のトーンに変換し、SSB（単側波帯）の無線機で送信します。狭い帯域幅、高度な前方誤り訂正（FEC）、厳密な時刻同期を組み合わせることで、信号が耳で聞こえるノイズフロアよりずっと下に埋もれていても、世界中と確実に交信できます。qFT8 は、現在の主要なデジタルモードである FT8、FT4、FT2、JS8、WSPR、LQ8 に対応しています。それぞれ、極めて弱い信号での伝搬ビーコンから、スピードの求められるコンテスト、キーボードでの会話まで、異なる目的のために設計されています。

FT8

FT8（Franke と Taylor の設計、8-GFSK）は、世界で最も広く使われている微弱信号用のデジタルプロトコルで、HF / VHF の厳しいコンディション、マルチホップのスポラディック E 層伝搬、混雑したバンドのために設計されています。定型のメッセージ、15 秒単位の正確な時刻同期、強力な誤り訂正で動作します。

サイクルとシーケンス

FT8 は 15 秒のサイクルで動作します。すべての通信サイクルは厳密に時間が決まっており、毎分の 00、15、30、45 秒ちょうどに始まります。そのため、端末の時計が UTC 時刻に正確に同期している必要があります。

プロトコルには 2 つのシーケンスがあります:

  • シーケンス 0（偶数）: 00 秒と 30 秒に始まるサイクル。
  • シーケンス 1（奇数）: 15 秒と 45 秒に始まるサイクル。

局は通常、送信と受信を交互に行います。シーケンス 0 で送信する局は、シーケンス 1 で応答を待ち、その逆も同様です。15 秒の各サイクルの中で、メッセージはおよそ +0.5 秒から +13 秒の間に送信されます。これにより、サイクルの終わりにデコードの時間が、始めに次の送信を準備する時間が確保されます。

信号の特徴

FT8 の各メッセージは、周波数がわずかに変化するトーンの並びとして送信されます（「くねくねした」信号と表現されることもあります）。FT8 の信号は非常に狭く、占有するのは約 50Hz の帯域幅だけです。この効率の良さのおかげで、3kHz の 1 つの無線帯域の中に、同時に数十の交信が収まります。

QSO の 6 つの段階

標準的な FT8 の交信は、通常 6 つの段階で進みます。HB9IPH と XX1XXX のやり取りを例にします:

  1. 1/6 CQ: ある局が、誰でもよいので交信相手を探します。
    例: CQ HB9IPH JN47
    注: JN47 は Maidenhead グリッドロケーターで、その局のおおよその地理的な位置を示します。ほかの運用者に向けたメモである CQ修飾子が付くこともあります（たとえば Summits On The Air プログラム向けの CQ SOTA HB9IPH や、米国の局と交信したいときの CQ US HB9IPH）。修飾子と位置の両方が 1 つのメッセージに収まらないこともあり、その場合は位置が省かれます。コールサインがとても長いと、位置も修飾子も CQ に収まらないことがあります。
  2. 2/6 CALL: 別の局が CQ に応答します。
    例: HB9IPH XX1XXX JO21
    注: 応答する局も自局の位置（JO21）を伝えますが、コールサインが長くて全部が収まらないときは省かれることがあります。
  3. 3/6 RPT: 最初の局がシグナルレポートを送ります。
    例: XX1XXX HB9IPH -10
    注: シグナルレポート（例: -10）は、ノイズフロアに対する信号の強さを dB で表します。
  4. 4/6 RRPT: 2 番目の局がレポートを了解し、自分からのレポートを送ります。
    例: HB9IPH XX1XXX R-12
    注: 先頭の「R」は前のレポートを受信したことの確認で、そのあとに最初の局へのシグナルレポートが続きます。
  5. 5/6 RR73: 最初の局がすべてを確認し、「Roger-Roger 73」を送ります。
    例: XX1XXX HB9IPH RR73
  6. 6/6 73: 2 番目の局が最後の「73」を送って交信を締めくくります。
    例: HB9IPH XX1XXX 73

二人の将軍問題のため、相手局が確認を返してこない限り、自分の最後の送信を相手が受信したかどうかを確実に知ることは理論上できません。しかし、確認を受け取ればその確認への確認が必要になり、相手もまたそれを確認する必要があり、と際限がなくなります。FT8 デジタルモードは、段階を定めることでこの問題を和らげています。QSO は技術的には段階 4/6 のあと（双方のシグナルレポートを交換した時点）で成立したとみなせます。実際には、交信が成立したことを双方が確実に認識できるよう、RR73 を受信して 73 を送った時点で QSO がログに記録されます。つまり、RR73 または 73 を送信したときに QSO が記録されます。

局は、相手が先に CQ を出していなくても呼び出すことがあります。たとえば珍しい場所の局には、多くの局が同時に呼びかける「パイルアップ」ができることがあります。その場合、珍しい局は CQ で新しい局を募ることなく、QSO から次の QSO へと移っていくことがあります。

段階 5 で RR73 の代わりに RRR を使う局もあります。その場合は、交信にもう 1 往復が必要になります。2 番目の局が 73 を送り、それから最初の局がもう一度 73 を送って終わります。

FT8 はフリーテキストメッセージ（最大 13 文字）にも対応していますが、qFT8 は現在、こうした自由なメッセージの送信には対応していません。

プロトコルの制限とフォールバック

FT8 のメッセージは 77 ビットに高度に圧縮されています。複雑な情報（長い非標準のコールサインなど）は、標準のメッセージ形式に収まらないことがあります。

  • ハッシュ化されたコールサイン: コールサインが長すぎると、ハッシュとして送られることがあります。受信側の局がそのコールサインの CQ を最近見ていれば、ソフトウェアがハッシュを元のコールサインに戻せます。そうでなければ <...> と表示されます。コールサインが標準形式でない場合、QSO を成立させるのはずっと難しくなります。
  • フリーテキストへの切り替え: メッセージによっては 13 文字のフリーテキスト形式で送らざるを得ないことがあり、この形式は標準の構造化メッセージほど確実ではありません。
  • 非標準のコールサイン: 2 つの局がどちらも非常に長い非標準のコールサインを使っている場合、FT8 デジタルモードでは互いに交信することがそもそもできないことがあります。
  • 段階の省略: コールサインが長すぎると、プロトコル上シグナルレポート（3/6 と 4/6 の段階）を収められないことがあります。その場合、やり取りは最初の CALL (2/6) から最後の確認（5/6 と 6/6）へ直接進むことがあります。

目にすることはあっても自分では送らないメッセージ

局によっては、qFT8 が表示はするものの自分では送信しない形式のメッセージを送ることがあります:

  • 2 局あての 1 つのメッセージ: 一度に多くの局と交信する DX ペディション局は、1 回の送信で 1 つの QSO を終え、次の QSO を始めることがあります: K1ABC RR73; W9XYZ <VP8XYZ> -08。これは VP8XYZ からの「K1ABC、あなたとの QSO は完了です」と「W9XYZ、あなたのレポートは -08 です」の両方を意味します。qFT8 はこれを送信されたとおりに、ステーションリストに表示し、ウォーターフォールには 1 回だけ表示します。あなたがその 2 局のどちらかであれば、DX ペディション局があなただけに送った場合とまったく同じように、あなたあての RR73 またはレポートとして扱われ、QSO は通常どおり続くか、ログに記録されます。どちらでもなければ何もする必要はなく、AUTO も何もしません。
  • コンテストナンバー: 一部のコンテストでは、グリッドロケーターとレポートの代わりに、クラスとセクション（フィールドデー）や、州名またはシリアルナンバー付きのレポート（RTTY コンテスト）を送ります。qFT8 はバンドの様子が分かるようにこれらのメッセージを表示しますが、応答することはありません。コンテストナンバーの送信は行いません。

FT4

FT4 は、交信をどれだけ速くこなせるかが重要になるアマチュア無線のコンテスト専用に設計された、簡素化されたデジタルモードです:

  • 速度が 2 倍: 7.5 秒のサイクル（FT8 の 2 倍の速さ）で動作し、送信時間は約 4.48 秒、送信の機会は 1 分間に 4 回です。
  • 帯域幅が 2 倍: 約 90 Hz の帯域幅を占有します（FT8 の約 50 Hz のおよそ 2 倍）。
  • 感度の低下: 速度を 2 倍にした代わりに、FT4 のデコード限界は約 -16.4 dB から -17.5 dB SNR です（FT8 に比べて約 3.5 から 4 dB の感度低下）。
  • 運用上の用途: 4-GFSK 変調と、標準の 77 ビットの定型メッセージを使います。伝搬が許せば、標準的なコンテストのやり取りを半分の時間で終えられます。

FT2

FT2 は、信号の条件が良いときの超高速のやり取り、VHF / UHF の流星散乱のバースト、ハイレートのコンテストのために設計されています:

  • FT4 の 2 倍の速度（FT8 の 4 倍）: 3.75 秒のサイクルで動作し、送信時間は約 2.24 秒、1 分間に最大 16 サイクルが可能です。
  • FT4 の 2 倍の帯域幅（FT8 の 4 倍）: 約 180 Hz の帯域幅を占有します（FT4 の 2 倍、FT8 のほぼ 4 倍）。
  • さらなる感度の低下: デコード限界は約 -13 dB から -14 dB SNR です（FT4 よりさらに約 3 dB、FT8 より約 6 から 7 dB 感度が低い）。
  • 運用上の用途: 信号の強いオープニングや、交信できる時間がごく短いバースト的な伝搬で、信号がノイズフロアを十分に上回っているときの矢継ぎ早の交信に最適です。

JS8

JS8（Jordan Sherer の設計、8-GFSK）は、定型のコンテスト交信ではなく、会話を楽しむラグチュー、キーボード同士のチャット、アドホックなネットワークのために作られています:

  • メッセージの分割とフレーム化: 基本となる 8-GFSK 変調と 77 ビットのフレームは FT8 と同じですが、メッセージを分割して組み立て直す上位層のトランスポートプロトコルを加えています。これにより、任意の長さの自由な文章を、連続するサイクルにまたがって途切れなく送れます。
  • 複数の速度モード: バンドのコンディションに合わせて、4 つの速度から選べます:
    • Slow: 30 秒のサイクル、帯域幅約 25 Hz、-25 dB SNR までデコード。
    • Normal: 15 秒のサイクル、帯域幅約 50 Hz、-21 dB SNR までデコード。
    • Fast: 10 秒のサイクル、帯域幅約 80 Hz、-18 dB SNR までデコード。
    • Turbo: 6 秒のサイクル、帯域幅約 160 Hz、-15 dB SNR までデコード。
  • ネットワーク機能: 宛先を指定したメッセージ、中間の局を経由するメッセージの自動中継、ハートビートによる在席の確認、非同期のストア・アンド・フォワード型メールボックスに対応しています。

WSPR

WSPR（Weak Signal Propagation Reporter）は、双方向の会話による QSO のためではなく、電波の伝搬経路の調査と自動ビーコンのためだけに設計されています:

  • 2 分のサイクル: 厳密に同期した 2 分（120 秒）のサイクルで動作し、162 シンボルの 4-FSK のトーン列を 110.6 秒かけて送信します。
  • 極めて狭い帯域幅: 占有する帯域幅は約 6 Hz だけで、送信電力をごく狭いスペクトルに集中させます。
  • 極めて高い微弱信号感度: 標準の 2.5 kHz の基準帯域幅で -28 dB から -31 dB SNR という弱い信号までデコードでき、ミリワット級（QRPp）の送信機でも地球規模の距離に届きます。
  • 伝搬レポートの自動化: 局のコールサイン、Maidenhead グリッドロケーター（4 桁または 6 桁）、送信電力（dBm）を送信します。デコードされたスポットは世界規模の WSPRnet データベースに自動的に送られ、電離層伝搬の様子がリアルタイムで地図に示されます。

LQ8

LQ8 は、qFT8 の作者である Luis Quesada（HB9IPH）が開発した、先進的な微弱信号用デジタルモードです:

  • 感度を犠牲にせず、QSO をより早く完了: LQ8 は、感度をまったく犠牲にせずに、双方向の QSO を FT8 よりかなり早く完了します。微弱信号のデコード限界 -21 dB SNR（FT8 と同じ）をそのまま保ちながら、最適化されたプロトコル設計により、大幅に少ない送信回数で有効な交信を終えます。
  • 複合メッセージ: レポートと確認をまとめた送信（REPORT+RR73）や、複数の局への並行した応答（MULTI_CALL）に対応しており、標準的な QSO の所要時間を 4～6 サイクルからわずか 2～3 サイクルに短縮します。
  • 現代的な設計: 標準の 15 秒サイクルで動作し、79 シンボルの 8-GFSK 変調（帯域幅約 65 Hz）、最適化したハフマン符号で圧縮した 77 ビットのペイロード、14 ビット CRC による誤り検出、定型の非常通信用の信号を備えています。

詳しい情報、仕様、ツールについては、LQ モードのポータルサイト https://lq8.org をご覧ください。

qFT8 ユーザーインターフェース

qFT8 アプリは 3 つの部分に分かれています:

  1. 下部バー: 常に表示されます。送信の監視と制御、そして qFT8 の操作に使います。
  2. スペクトログラム: 常に表示されます。デコードされたメッセージ、現在の UTC 時刻、同調している周波数を表示し、送信周波数オフセットの操作に使います。
  3. タブエリア: 4 つのタブ（ステーション、ログ、世界地図、設定）のいずれかを表示します。どのタブを表示するかは、下部バーの右端にあるボタンで切り替えます。

以降の章で、これらの各部を詳しく説明します。

下部バー

下部バーには重要な情報が表示されます。送信が有効か無効か、qFT8 が送信中かどうか、送信出力、定在波比（SWR）、送信中のメッセージ、現在のシーケンスと選択中のシーケンス、バンドセレクター、そして各タブに移動するボタンです。

下部バーの各部の詳細は次のとおりです:

  1. サイクル進行バー: 黄色のバーは、サイクルの 0 秒（左端）から始まり、15 秒（右端）で終わります。
  2. Tx トリガーマーカー: バーの左側にある赤い点は、Tx のトリガー時刻を示します。Tx が ON（項目 4 を参照）で、現在のシーケンスが選択中のシーケンス（項目 6 を参照）であれば、この時点で送信が始まります。
  3. デコード時刻マーカー: バーの右側にある白い点は、デコードの時刻、つまり受信した信号からメッセージがデコードされ、続いて処理される時点を示します。
  4. TX ボタン: 無効（OFF）または有効（ON）にできます。送信中であること、送信出力、SWR も表示します。QMX のファームウェアが 1_04 より新しい場合、このボタンには「HOLD: TUNE」と表示されます。ボタンを長押しするとチューニングモードになり、SWR がリアルタイムで表示されます。
  5. メッセージセレクター: 送信するよう選択されているメッセージ、または送信中のメッセージを表示します（送信中は黄色で強調表示されます）。AUTO モードでは自動で管理されます。CALL モードでも既定では自動で管理されますが、タップして次に送るメッセージを手動で選ぶこともできます。
  6. シーケンスセレクター: ボタンの上の黄色の線が現在のシーケンス（0 または 1）を示します。0 または 1 をタップすると、そのシーケンスで送信するようになります。
  7. モードセレクター: 使用する送信モード（例: FT8、FT4、FT2、LQ8、JS8、WSPR）を切り替えます。SSB、CW、RTTY、SSTV にも切り替えられ、これらを選ぶと、それぞれの章で説明するとおり下部バーと「ステーション」タブが変わります。デジタルモードからこの 4 つのいずれかへ、その逆へ、またはこの 4 つの間で切り替えると、TX OFF になります。準備ができたら、もう一度送信を有効にしてください。デジタルモード同士の切り替えでは、状態は変わりません。
  8. バンドセレクター: トランシーバーが接続されているときは、トランシーバーのバンドを切り替えます。
  9. 「ステーション」タブのボタン: これまでに聞こえた局、または交信できる局の一覧のタブを開きます。
  10. 「ログ」タブのボタン: これまでに行ったすべての QSO の一覧のタブを開きます。QRZ にアップロードされていない QSO があるときは、このボタンに黄色の点が付きます。
  11. 「世界地図」タブのボタン: インタラクティブな世界地図のタブを開きます。
  12. 「設定」タブのボタン: qFT8 を設定するタブを開きます。

スペクトログラム

スペクトログラムには、ピーク表示とウォーターフォールが表示されます。ウォーターフォールには、受信した信号とメッセージ、送信した信号とメッセージ、UTC 時刻とデコード時間が添えられたシーケンスの切り替わりのマーカー、そして送信用に選択した周波数オフセットが表示されます。

スペクトログラムの各部の詳細は次のとおりです:

  1. ウォーターフォール表示: 受信した信号の最近の履歴を時間の流れに沿って表示します。この表示をタップすると、選択中の周波数オフセットが変わります。
  2. リアルタイムのピーク: 周波数範囲全体の、その瞬間の信号の強さを表示します。この表示をタップすると、周波数オフセットを正確に入力するダイアログが開きます。
  3. シーケンスの区切り: この赤い横線はサイクルの区切りを示し、UTC 時刻とデコードにかかった時間が添えられます。
  4. 選択中の周波数オフセット: スペクトログラム上のこの黄色の縦の帯は、現在選択している送信用の周波数オフセットを示します。
  5. 受信メッセージ。色分けして表示されます:
    • 緑: CQ のメッセージ。
    • シアン: ほかの局どうしのメッセージ。
    • 黄色: 自局が送信したメッセージ。
    • オレンジ: 自局あての受信メッセージ。
  6. 現在の UTC 時刻とシーケンス: ウォーターフォールの上部に表示されます。
  7. 同調している周波数とバンド: トランシーバーが現在同調している周波数とバンド。
  8. 周波数軸: 選択中のバンド内の周波数目盛りを Hz で表示します。

「ステーション」タブ

「ステーション」タブは、バンドの様子を見ながら qFT8 を操作するための中心となる場所です。上部にフィルターと自動運用の操作部品があり、その下に活動中の局の一覧が表示されます。

「ステーション」タブの各部の詳細は次のとおりです:

  1. AUTO 呼び出しモードボタン: 「AUTO」を有効にすると、選択した条件に従って最適な局を呼び出そうとします。
  2. 手動の CALL モードボタン: ある局の「CALL」を有効にすると、QSO が成立するまでその局を呼び続け、そのあと「AUTO」に戻ります。
  3. ターゲット: AUTO モードの条件を設定します:
    • 誰でも: まだ QSO のないすべてのコールサイン。
    • 近い: Maidenhead グリッドの距離をもとに、近い局を優先します。
    • 遠い: Maidenhead グリッドの距離をもとに、遠い局を優先します。
    • 信号強度: 信号（SNR）がもっとも強い局を優先します。
    • CQ呼び出し: CQ を出すだけで、自局を呼んできた局に応答します。
    • POTAハンター: Parks on the Air の局を優先します。
    • SOTAハンター: Summits on the Air の局を優先します。
    • POTA + SOTAハンター: Parks on the Air と Summits on the Air の両方の局を優先し、そのあとにどちらでもない局を SNR の順に並べます。
    • DXCC: 新しい国・エンティティを優先します。
    • グリッド: 新しい Maidenhead グリッドスクエアを優先します。
    • ITUゾーン: 新しい ITU ゾーンを優先します。
    • CQゾーン: 新しい CQ ゾーンを優先します。
    • I/C/D/G: ITU ゾーン、CQ ゾーン、DXCC、グリッド の順に優先します。
    どの場合も、同じ条件を満たす局は信号の強い順に並びます。たとえば 誰でも では新しいコールサインが優先されますが、その中では信号の強い局が一覧の上に来ます。
  4. 頻度: そのターゲットとどのくらいの間隔で交信するか:
    • 1回: 生涯で 1 回。
    • 毎日: UTC の日付ごとに 1 回。
    • 毎週: 直近 7 日間に 1 回。
    • 毎月: 直近 1 か月間に 1 回。
    • 毎年: 直近 1 年間に 1 回。
  5. 条件の適用範囲: これらの制約をどう適用するか:
    • コールサインごと
    • 異なるバンド
    • 異なるモード
    • ゾーン確認まで
    • バンドごと+ゾーンまで
    • モードごと+ゾーンまで
    • 異なるバンドまたはモード
    • バンド/モードごと+ゾーンまで
  6. スパイモード: 有効にすると、まだ CQ を出すのを聞いていない局（DIRECT と表示されます）も呼び出そうとします。呼べる局を増やしたり、パイルアップに参加したりするのに便利です。
  7. 交信中モード: 有効にすると、ほかの局と QSO 中の局（BUSY と表示されます）も呼び出そうとします。パイルアップに参加するのに便利です。
  8. + ボタン: コールサインを入力して、任意の局を手動で呼び出します。
  9. 局の情報: デコードした各局の詳しい状態を表示します。

局ごとのエントリーは、情報の詰まった 4 つの行で構成されます:

1 行目には局の詳細が表示されます（左から右へ）:

  • QSO の状態: その局との QSO の履歴を示します（✗ = QSO なし、✓ = 端末内に記録済み、★ = QRZ または LoTW で確認済み）。
  • コールサイン: その局のコールサイン。
  • DXCC: その局のコールサインが属する国またはエンティティ。
  • グリッド: その局が伝えている Maidenhead グリッドスクエア。
  • CQゾーン: その局のコールサインが属する CQ ゾーン。
  • ITUゾーン: その局のコールサインが属する ITU ゾーン。
  • バンド: その局が最後に聞こえたバンド。

2 行目には通信の状態が表示されます（左から右へ）:

  • 状態: 通信の現在の段階:
    • DIRECT: 聞こえていて、いまは空いているようですが、CQ を出したことがない局。
    • 1/6 CQ: CQ を出しているのが聞こえ、いまは空いているようです。
    • 2/6 CALL: 自局を呼んできました。
    • 3/6 RPT: 自局にシグナルレポートを送ってきました。
    • 4/6 RRPT: 自局のレポートに、相手からのレポートを返してきました。
    • 5/6 RR73: 自局のレポートを RR73 で確認してきました。
    • 6/6 DONE: QSO 完了（73 を交換済み）。
    • GONE: ここ数サイクル聞こえていません。
    • TOO LONG: FT8 デジタルモードの制限により、自局と相手局のコールサインを合わせると長すぎて交信できません。
  • 信号強度: dB 単位の強さ（最近聞こえていない場合は「????」と表示されます）。
  • シーケンス: その局が最後に送信しているのが聞こえたシーケンス（0 または 1）。
  • 時間差（Δt）: 相手の時刻と自局の時刻の同期のずれ（秒）。
  • 距離: 相手局と自局のグリッドの間の推定距離。

3 行目と 4 行目には、その局とのメッセージのやり取りが表示されます。UTC 時刻、周波数オフセット、メッセージの本文（受信したメッセージには RX:、送信したメッセージには TX: が先頭に付きます）です。設定 → アプリケーション → ユーザーインターフェースで設定する局の表示設定（既定はコンパクト - 最終Rx。ほかにコンパクト - 最終Rx/Tx交互、コンパクト - 最終Rx/Tx、拡張 - 最終RxとTxの両方があります）に応じて、局のカードは 3 行、または Rx と Tx の両方のメッセージを含む 4 行で表示されます。

注目すべき主な表示:

  • コーラル色の Rx メッセージ（UTC、オフセット、本文）: その局から受信した Rx メッセージが、現在または直前のサイクルで自局のコールサインあて（/P などの付いたコールサインや、ハッシュ化されたコールサインの一致も含みます）に送られたものであることを示します。その局がたったいま自局を呼んできた、または自局の送信に応答してきたことが、ひと目で分かります。全局あての CQ や、ほかの局あてのメッセージが強調表示されることはなく、メッセージが直前のサイクルより古くなると、文字は自動的に通常のグレーに戻ります。送信した（TX:）メッセージは、常に通常のグレーのままです。
  • 赤のコールサイン: AUTO モードがこの局に対する再試行の上限を超えました。「CALL」を押して手動でリセットしない限り、一時的に無視されます。
  • 紫のコールサイン: このコールサインは、現在の条件でのターゲットです。
  • グレーのコールサイン: このコールサインは、カンマ区切りの除外プリフィックス設定に一致しています。AUTO モードがこの局をターゲットにすることはありません。
  • 紫で強調されたゾーン: このゾーン・エンティティ（DXCC、グリッド、CQゾーン、ITUゾーン）は、現在の条件でのターゲットです。
  • 赤のシーケンス番号: その局が自局の選択しているシーケンスと同じシーケンスにいて、ぶつかっています。「CALL」を押すと、自局のシーケンスが自動的に切り替わります。
  • 赤のバンド: その局が最後に聞こえたのは別のバンドです。

局は関連性の高い順に自動で並べ替えられます。ターゲットの条件や制約を変えると、一覧はすぐに並べ替えられます。

「ログ」タブ

「ログ」タブには、成立した QSO が表示されます。

「ログ」タブの各部の詳細は次のとおりです:

  1. コールサインのテキストフィルター: 入力した文字がコールサインに含まれているかどうかで QSO を絞り込みます。
  2. 状態フィルター: 次の条件で QSO を絞り込みます:
    • すべて: 記録されているすべての QSO を表示します。
    • 交信証明済: 確認済みの QSO だけを表示します。
    • 未交信証明: まだ確認されていない QSO を表示します。
    • 未アップロード: QRZ にアップロードされていない QSO を表示します。
    • 重複: QRZ が重複と判定した QSO を表示します。
    • 拒否: QRZ で相手局に拒否された QSO を表示します。
    • 別のコールサイン: 現在設定されているものとは別のコールサインで記録された QSO を表示します。
    • FT8/FT4 以外: FT8 と FT4 以外のモードで記録された QSO を表示します。
  3. 最近の件数フィルター: 指定した条件に合う QSO のうち、最近の 100 件だけを表示します。
  4. QSO の一覧: ログのエントリーを、次の列で表示します（左から右へ）:
    • QRZ: その局との履歴を示します:
      • ✗: QSO の記録なし。
      • ✓: 端末内に記録済み / アップロード待ち。
      • ✓🕒: LoTW にアップロード済みで、確認待ち。
      • ✓: QRZ にアップロード済み。
      • ★: QRZ または LoTW で確認済み（QRZ にアップロードした QSO の場合）、または手動で確認済み。
      • ⟳ / ♻️: 円形の矢印: QRZ から重複として報告されたもの（ログに実際に重複したエントリーがある場合だけ表示されます。すでに QRZ にある重複のない QSO は、自動的に緑のチェックでアップロード済みと表示されます）。
      • ❕: 自局のコールサインが一致せず、アップロード済み。
      • ⚠️: 自局のコールサインが一致せず、未アップロード。
      • ⛔: 拒否された状態。
    • コールサイン: その局のコールサイン。
    • DXCC: その局のコールサインが属する国またはエンティティ。
    • グリッド: その局が伝えている Maidenhead グリッドスクエア。
    • CQゾーン: その局のコールサインが属する CQ ゾーン。
    • ITUゾーン: その局のコールサインが属する ITU ゾーン。
    • バンド: その局が最後に聞こえたバンド。

注目すべき主な表示:

  • コールサインの下の黄色の注記: この QSO は、現在設定されているものとは別の自局コールサインで行われたものです。
  • 緑で強調されたゾーン（DXCC、グリッド、ITUゾーン、CQゾーン）: そのゾーンについて、ログで最初の未確認の QSO です。
  • 黄色で強調されたゾーン（DXCC、グリッド、ITUゾーン、CQゾーン）: そのゾーンについて、ログで最初の確認済みの QSO です。

QSO の編集: リスト内の QSO をタップすると QSO エディターが開きます。そこでは QSO のすべての項目を修正でき、QSO を手動で確認済みまたは未確認にしたり、もう一度アップロードしたり、削除したりできます。QSO の削除はアプリ内だけで行われ、QRZ や LoTW から削除されることはありません。エクスポートしたログファイルの控えがあるか、QRZ にアップロード済みでない限り、削除は元に戻せません。

手動での記録と選択: + ボタンでロガーが開き、自分で行った QSO を記録できます。QSO を長押しすると、複数の QSO の選択が始まります。

「世界地図」タブ

「世界地図」タブには、リアルタイムで更新されるインタラクティブな世界地図が表示されます。局の位置、デコードしたメッセージ、QSO の達成状況、太陽と伝搬の状況が分かります。

「世界地図」タブの各部と機能の詳細は次のとおりです:

  1. インタラクティブな地図と操作:
    • 移動と拡大・縮小: ドラッグすると地図が滑らかに動き、東西方向は日付変更線（180 度の子午線）を越えてつながっています。2 本の指でピンチすると拡大・縮小できます。
    • 地図のテーマ: 上部のツールバーで、4 つの配色（ブライトフューチャー、コンソール、地球、ミッドナイトネイビー）を切り替えられます。
    • HUD の座標: 指で触れている位置の地理座標（緯度、経度）と Maidenhead グリッドロケーターをリアルタイムで表示します。
  2. 左のツールバー（重ね表示と情報の切り替え）:
    • INFO: 画面上の情報カード（時刻、昼夜の境界線、太陽直下点、十字線の座標）の表示を切り替えます。
    • MSGs: 自局が直接やり取りしたメッセージの経路とマーカーの表示を切り替えます。受信したメッセージ（自局あて）はオレンジ、送信したメッセージ（自局から）は黄色で表示されます。矢印の中央をタップすると、メッセージの本文が表示されます。
    • QSOs: 今回のセッションで最近交信した局のマーカーの表示を切り替えます（アンバーは記録済み、エメラルドは確認済み）。
    • Spot: 自局がバンドで受信してデコードした局のスポット（RX / CQ はシアン）と、自局の信号を PSKReporter / WSPRnet に報告した受信局（赤いひし形）の表示を切り替えます。
    • SOTA: Summits On The Air の山頂リファレンスと、運用中の山頂アクティベーター（⛰️）の表示を切り替えます。
    • POTA: Parks On The Air の公園リファレンスと、運用中の公園アクティベーター（🌲）の表示を切り替えます。
    • バンド: オンラインのレポートから得たバンドの伝搬状況と、自局の周囲の不感地帯を表示します。インターネットに接続していれば、バンドを切り替えるとリアルタイムで更新されます。

    SOTA、POTA、STATS、Spot の各ボタンが点滅することがあります。これは、更新データをダウンロードできなかったことを示します。

  3. 右のツールバー（達成状況と境界のレイヤー）:
    • STATS: 選択中の境界レイヤーについて、記録済みと確認済みの合計数を示す統計パネルの表示を切り替えます。
    • DXCC: 国と地域の境界を、ログの状況に応じて色分けして表示します（緑は記録済みで未確認、黄色は確認済み）。小さな島やごく小さなエンティティは、見やすいマーカーで表示されます。
    • GRID: 全世界の Maidenhead グリッド（フィールドと 4 文字のスクエア）を、達成状況に応じて塗り分けて表示します。
    • ITU: 90 の ITU ゾーンを、達成状況に応じて塗り分けて重ねて表示します。
    • CQ: CQ 誌の WAZ の 40 ゾーンを、達成状況に応じて塗り分けて重ねて表示します。
  4. 詳細カードと、すぐに呼び出せる CALL:

    局、スポット、公園、山頂のどれかをタップすると、次の情報を示す詳細カードが開きます:

    • コールサインまたはリファレンス、DXCC エンティティ、公園や山頂の名前。
    • デコードしたメッセージの本文、周波数、バンド、モード。
    • 信号強度（SNR）またはシグナルレポート（RST）。
    • グリッドロケーター、距離（km / mi）、方位角（°）、経過時間。
    • CALL ボタン: その局の呼び出しをすぐに始めます（必要ならバンドとモードを自動で切り替えます）。

「設定」タブ

「設定」タブでは qFT8 の設定を行います。

「設定」タブの構成は次のとおりです:

  • コールサイン: 自局のアマチュア無線コールサイン（送信には必須）。免許の内容に合っている必要があります。
  • CQ修飾子: CQ の呼び出しに付け加える任意のテキスト（例: 「SOTA」）。
  • デバイス: トランシーバー（例: QMX、QDX、Kenwood TS-480 / TS-590 / TS-2000 シリーズ、VOX / オーディオのみ）と接続パラメーターを選択・設定します。
  • 無線機 / アンテナ: 運用に使う無線機とアンテナです。記録する各 QSO にこれらが保存され（ADIF MY_RIG / MY_ANTENNA）、PSKReporter にもスポットと一緒に送られます。無線機が空のときは、接続中の無線機の名前が使われます。

サブメニューとオプション

  • デバイス設定: オーディオデバイスの選択、送信音量と VOX しきい値の設定、無線機のキーイング方法の設定を行います。無線機ごとのスペクトログラムのチューニングオフセットと連続送信時間の上限もここにあります（どちらも機能の説明で説明します）。
  • スピーカーとマイク: SSB と CW で使う、あなた自身のマイクとスピーカーまたはヘッドホンです（すぐ下のスピーカーとマイクを参照）。
  • POTA アクティベーション / SOTA アクティベーション: アクティベーションの開始、表示、終了を行います。それぞれの横の虫めがねボタンで、過去のアクティベーションの一覧が表示されます。
  • ログのインポート/エクスポート: 標準の ADIF（.adi）ファイルで QSO ログをインポートまたはエクスポートします。
  • QSO同期: ログの同期と確認のために、QRZ および LoTW との連携を設定します。
  • QSOを削除: 端末内の QSO を消去します（この操作はアプリ内のログにだけ影響します）。
  • アプリケーション: ユーザーインターフェースの言語などの全般的な設定。
  • スペクトログラム: ウォーターフォールに重ねて表示するものを選びます — デコード時間、UTC 時刻とシーケンス、メッセージ、ピーク線、選択した局の周波数 — あわせて重ね表示のフォントの大きさも設定します。
  • 世界地図: 地図に何をどのくらいの期間表示するかを選びます。成立した QSO、スポット、送受信したメッセージのそれぞれに、表示期間を設定できます。
  • 時刻と位置情報: 時刻オフセットの同期（NTP または GPS）と、Maidenhead グリッドロケーターを設定します。
  • 自動運用: 自動運用の設定、再試行回数、プリフィックスの除外、そして自局あてではない指向性 CQ に AUTO が応答するかどうかを設定します。
  • デジタルモード: すべてのモードのデコードオプションを 1 か所にまとめています — FT8/FT4/FT2、LQ8、JS8、WSPR — 共通のディープデコード設定と、デコードに使えるスレッド数も含みます。
  • SSB、CW、RTTY, JTTY、SSTV: これらのモードそれぞれの設定です。内容は各モードの章で説明します。各モードのペインにある歯車ボタンでも同じページが開きます。
  • バンド選択: 使用するバンドと、バンド切り替えの動作を設定します。
  • リモートコントロールWebサーバー: リモートコントロール用の内蔵ウェブサーバーを有効にして設定します。
  • PSKReporter 設定: 受信した局を PSKReporter にアップロードします。
  • WSPRnet 設定: WSPR のスポットを WSPRnet にアップロードし、最近のアップロードログを確認します。
  • 起動時に新しいバージョンを確認する: qFT8 の新しいバージョンがあるときに通知を表示します（バグ報告と新しいバージョンを参照）。
  • 匿名の日次パフォーマンス概要を送信する（「言語」のすぐ上、既定ではオフ）: アプリを開いている間に、およそ週に 1 回、お使いの端末で qFT8 がどのくらい速く動いているかの短い概要（起動時間、画面の滑らかさ、デコード時間、オーディオと無線機のタイミング、端末の機種と画面）を送信します。コールサイン、グリッド、ログ、設定、その他の識別情報が含まれることはありません。

スピーカーとマイク

デジタルモードに必要なサウンドデバイスは 1 つ、無線機のものだけです。SSB と CW では、あなたのための 2 つ目のデバイスが必要です。無線機の音を聞くスピーカーまたはヘッドホン、そして SSB では話しかけるマイクです。この 2 つに無線機自身のサウンドカードを選んではいけません。話した声がそのまま戻ってきてしまうからです。

  • Android の場合: 設定 > スピーカーとマイク。デバイス設定のすぐ下にあります。
  • パソコンの場合: デバイス設定カードは 2 つに分かれています。左が 無線機（無線機のサウンドカード: 無線機が聞く音と送り出す音）、右が あなた（オペレーター） です。

設定項目は 2 つです:

  • あなたのマイク（あなたが話し、無線機が送信）。その下の小さなライブのウォーターフォールとレベル表示で、マイクが拾っている音が分かります。話しかけると動くはずです。
  • あなたのスピーカー / ヘッドホン（無線機の音を聞く）。テスト ボタンを押すと、そのデバイスで短い音が鳴ります。

どちらも最初は AUTO になっており、無線機のものではないデバイスが選ばれます。スマートフォンでは、ヘッドセットが接続されていればヘッドセット、なければ本体のマイクとスピーカーです。パソコンでは、無線機のサウンドカードではない最初のサウンドデバイスです。AUTO が違うデバイスを選んだ場合にだけ変更してください。

ヒント: SSB ではヘッドホンを使ってください。マイクのそばでスピーカーを鳴らすと、受信音で VOX が働いたり、受信音が自分の送信に乗ったりすることがあります。

自動運用（AUTO）

AUTO モード は、qFT8 の基本的な使い方です。このモードでは、アプリが各サイクルの終わりにデコードしたメッセージを自動で分析し、ターゲットの条件に基づいて、交信するのにもっともふさわしい局を選びます。

ターゲット選択の仕組み

「ステーション」タブには活動中の局の一覧が表示され、（条件に基づいて）もっともふさわしい候補が上に来るように並べられます。各デコードサイクルの終わりに、qFT8 はこの並べ替えた一覧を見て、条件に合う最初の局を呼び出そうとします。条件に合うターゲットが見つからなければ、相手を募るために自動で CQ を出し始めます。AUTO モードでは、qFT8 は呼び出しに必ず応答します。

条件とフィルター

自動運用は、「ステーション」タブ上部の 3 つのドロップダウンメニューで細かく調整できます:

  • ターゲット: どんな「成果」を目指すかを決めます（誰でも、DXCC、CQゾーン、ITUゾーン、グリッド）。
  • 間隔: 同じエンティティとどのくらいの頻度で交信するかを決めます（1回、常に、毎日、毎週、毎月）。
  • 条件の適用範囲: 重複とみなす範囲を絞り込みます（コールサインごと、異なるバンド、ゾーン確認まで）。

手動での割り込み: 特定の局の CALL ボタンをタップすれば、いつでも手動で介入できます。その QSO に限って CALL モードに入ります。終わると、qFT8 はそのまま AUTO モードに戻ります。

指向性 CQ

世界の一部の地域だけに向けて CQ を出す局があります: CQ DX、CQ NA、CQ JA。CQ の後ろの語が、その局の CQ修飾子です。CQ修飾子が自局を対象としない局は呼び出さないにチェックが入っていると（設定 > 自動運用、既定でオン）、AUTO は、自局に向けられていない CQ を出している局を呼びません。自局の場所は、コールサインの国から判断し、それが分からないときはグリッドロケーターから判断します。

再試行の仕組み

応答のない局を qFT8 がいつまでも呼び続けないように、再試行と一時除外の仕組みが組み込まれており、既定で有効になっています。「設定」タブの自動運用で設定できます:

  • 再試行の上限: 応答のない局に対して、qFT8 が同じ送信段階を繰り返す最大回数。
  • 再試行の集計期間: これらの試行を数える期間。
  • 再試行後の待機時間: 上限に達すると、その局はこの時間だけ「除外」されます。AUTO モードは、待機時間が終わるか、その局が応答してくるまで、除外された局を無視します。

手動運用（CALL）

qFT8 は高度に自動化されていますが、いつでも自分で操作できます。「ステーション」タブで局の横にある CALL ボタンをタップすると、すぐに CALL モードに入り、その局との QSO を試みます。

手動で選んだターゲットとの QSO が（成立してもしなくても）終わると、qFT8 は自動的に AUTO モードに戻り、それまでの自動運用の方針（CQ の呼び出しなど）を再開します。

手動で操作するときのタイミング

サイクルの終わりに手動で判断する時間がもう少しほしい場合は、「設定」タブの FT8設定を調整して余裕を作れます:

  • 「デコード開始時間」を小さくする: オーディオの処理を早めに始めます。
  • 「送信開始時間」を大きくする: 応答の送信開始を遅らせます。

警告: これらの値を余裕のぎりぎりまで詰めると、同期ウィンドウの中で実際の FT8 信号に使える時間が短くなるため、ほかの局が自局のメッセージをデコードしにくくなることがあります。

QSO の手動編集と記録

デジタルモードで行った QSO は、qFT8 が自動でログに記録します。この章では、「ログ」タブで手動で行う 3 つの操作を説明します。QSO の修正、別の方法（音声、モールス、別の無線機）で行った QSO の記録、そして複数の QSO の一括操作です。

QSO エディター

「ログ」タブで QSO をタップすると、タブがその QSO のエディターになります。保存されているすべての項目が並びます。自局のコールサインとグリッドロケーター、相手局のコールサインとグリッドロケーター、モード、バンド、周波数、日付と時刻、出力、レポート、POTA と SOTA のリファレンス、コメントです。

  1. 編集中の QSO: コールサイン、モード、バンド、日付と時刻。
  2. 状態: QSO が確認済みかどうか。タップすると手動で確認済みにするまたは手動で確認を解除を選べます（自分のログだけが変わります）。
  3. アップロード: QRZ と LoTW での QSO の状況。タップすると、QSO を 1 つのサービスまたはすべてのサービスにもう一度アップロードできます。
  4. 変更した項目は強調表示され、横に元の値が赤で表示されます。その横の矢印で元の値に戻せます。値をタップすると変更できます。モードとバンドはアプリのリストから選び、バンドは入力した周波数に合わせて変わります。正しいはずのない値（コールサイン、グリッドロケーター、日付など）は、理由を示して受け付けません。
  5. 戻る: エディターを閉じます。変更がある場合は、破棄するかどうかを尋ねます。
  6. まだ保存していない変更の件数。
  7. 削除: yes と入力すると、このアプリのログからだけ QSO を削除します。
  8. 保存: 確認を求めたうえで保存します。

保存したとき QRZ と LoTW で起きること。 確認メッセージに、編集中の QSO について次のように表示されます:

  • QRZ: QSO は QRZ 上で更新されます。コールサイン、日付、時刻、バンド、モードのいずれかを変更した場合、QRZ は別の QSO として扱います。新しいエントリーが作られ、古いエントリーは残るので、qrz.com で自分で削除してください。
  • LoTW: 修正した QSO が新しいエントリーとしてもう一度アップロードされます。古いエントリーは未確認のまま残りますが、害はありません。
  • 交信証明が崩れる変更（QSO の相手局コールサイン、自局コールサイン、日付、時刻）は、yes と入力して確認する必要があります。その QSO が相手局のログと一致しなくなるためです。
  • 「設定」のコールサインとは別のコールサインで行った QSO は、アップロードされません。

qFT8 が QRZ や LoTW 上のデータを削除することは決してありません。 QSO を削除しても、アプリから消えるだけです。その QSO がサービス上にある場合、次の同期で戻ってくることがあります。先にサービス側で削除してください。エクスポートしたログの控えがない限り、削除は元に戻せません。

ロガー

「ログ」タブの + ボタンでロガーが開きます。自分で行う QSO をすばやく記録するための入力フォームです。スマートフォンでは画面が縦向きになり、上部にスペクトログラムが細い帯で表示されます（設定 > アプリケーション > ユーザーインターフェースでオフにできます）。

  1. コールサイン: コールサインを入力してキーボードの Enter を押すと、現在時刻で QSO が記録され、入力欄が空になり、次のコールサインを入力できます。キーボードは QSO をまたいで開いたままです。
  2. 記録: Enter と同じです。
  3. クリア / 取り消し: コールサインを入力している間は クリア と表示され、入力欄を空にします。それ以外のときは 取り消し と表示され、このセッションの最後の QSO をログから取り出してフォームに戻すので、修正できます。
  4. 完了: ロガーを閉じます。コールサインを入力したまま記録していない場合は、記録するかどうかを尋ねます。
  5. 照会行: コールサインの国、その局との前回の QSO、重複かどうか。オレンジ色の DUPE は、今日そのバンドとモードでその局をすでに記録していることを示します（それでも記録はできます）。
  6. 詳細（横にスワイプすると続きが表示されます）: 時刻（現在。タップすると日付と時刻を指定できます）、バンド、モード、kHz 単位の周波数、異なる場合の受信周波数、出力、送ったレポートと受け取ったレポート、相手局の POTA / SOTA リファレンスと自局のリファレンス。初期値にはアプリが現在合わせている内容が入り、次の QSO にも引き継がれます。
  7. このセッション: ロガーを開いてから記録した QSO の数。スマートフォンでは、タップすると一覧で表示されます。
  8. このセッションの QSO は、コーラル色で時計のアイコン付きで表示されます。すでにログに入っていますが、完了 を押すまでは QRZ や LoTW にアップロードされません。入力ミスをまだ取り消せるようにするためです。タップすると、取り消しまたは編集ができます。

SSB、CW、RTTY、SSTV の各ペインの QSO ボタンを押すと、同じフォームが小さなカードとして開きます。モード、周波数、相手局がすでに入力されており、QSO を 1 件ずつ記録できます。

複数の QSO を選択する

「ログ」タブで QSO を長押しすると選択が始まります（パソコンでは Ctrl を押しながらクリック、範囲を選ぶには Shift を押しながらクリック）。続けてほかの QSO をタップすると、選択に追加したり外したりできます。

  1. X: 何もせずに選択を終了します。
  2. 選択中の QSO の数。
  3. 範囲選択: これをタップしてから、範囲の終わりの QSO をタップすると、その間がすべて選択されます。
  4. すべて と なし。
  5. 操作: 選択した QSO に対して行う操作:
    • 手動で確認済みにする / 手動確認を取り消す。
    • エクスポート (ADIF): これらの QSO だけを含むファイル。
    • POTA / SOTA リファレンス付きでエクスポート: 同じ内容で、ファイル内のすべての QSO に自局の公園または山頂を書き込みます（ログそのものは変わりません）。
    • POTA / SOTA アクティベーションに追加と所属するアクティベーションから外す（公園・山頂のアクティベーションを参照）。
  6. 選択した QSO にはチェックが付き、強調表示されます。

どの操作も、まず何件の QSO が変更されるかを示して確認を求めます。変更は直後に取り消せます。QRZ や LoTW 上のデータが削除されることは決してありません。

ADIF のインポート／エクスポート

qFT8 は、ほかのログソフトやクラウドサービスとの相互運用と手動バックアップのために、標準の ADIF（Amateur Data Interchange Format）に対応しています。

QSO のインポート

インポート機能を使うと、ほかの場所（ほかのログソフトや、ほかの端末のバックアップなど）の記録を、qFT8 の端末内のログに取り込めます。

  • 絞り込みオプション: すべてのモードがインポートされます。インポートを現在のコールサインに限定するか、すべてのオペレーターを含めるかを選べます。
  • 自動重複排除: qFT8 は記録を適切に統合します。QRZ のログ ID と QSO のタイムスタンプを照合して、重複を防ぎます。インポートした記録に、端末内の記録にはない確認済みの状態や有効なログ ID がある場合は、より良いデータで端末内のエントリーを更新します。

QSO のエクスポート

QSOのエクスポート をタップすると ADIF 3.1.6 ファイルが作成されます。Android ではシステムの共有シートが開き、ログを端末に保存したり、メールやメッセージで送ったりできます。パソコンでは、ファイルの保存先を選びます。

  • 期間: 履歴全体をエクスポートすることも、UTC の日付と時刻を指定して、特定のアクティベーションやコンテストの期間だけを取り出すこともできます。
  • 状態フィルター: アワードの申請（「交信証明済のみ」でエクスポート）や、ほかのサービスへの手動アップロード（重複を避けるため 「QRZ未アップロードのみ」でエクスポート）に便利です。
  • ハンター条件: ログを 「すべてのログをエクスポート」、「POTAハンターのみエクスポート」、「SOTAハンターのみエクスポート」 で絞り込むと、相手局のリファレンス（<POTA_REF> / <SOTA_REF>）の入った、アワード申請用のファイルを作成できます。
  • SOTA参照: SOTA の章で説明しているとおり、qFT8 はエクスポートするすべてのレコードの <MY_SOTA_REF> フィールドに山頂のリファレンスを自動で書き込めます。
  • POTA参照: POTA の章で説明しているとおり、qFT8 はエクスポートするすべてのレコードの <MY_SIG>、<MY_SIG_INFO>、<MY_POTA_REF> フィールドに公園のリファレンスを自動で書き込めます。カンマで区切って複数の公園を指定すると、公園ごとに 1 つのファイルになります（「ファイルにはどの公園を書きますか？」を参照）。

エクスポートされるファイルの名前

  • リファレンスなし: qFT8-YYYYMMDD-HHMMSS.adi。エクスポートした日付と時刻（UTC）で、たとえば qFT8-20261006-181500.adi です。状態フィルターを使うと時刻の後ろに _confirmed または _notuploaded が付くので、フォルダー内のファイルは日付順に並びます。
  • POTA リファレンス付き: CALLSIGN@PARK-YYYYMMDD.adi。たとえば K1ABC@US-1234-20261006.adi です。これは POTA プログラムが求める名前です。公園ごと、UTC の日ごとに 1 つのファイルになるので、UTC の 0 時をまたぐエクスポートでは 2 つのファイルができます。
  • SOTA リファレンス付き: 1 つのファイル。たとえば K1ABC@W1_HA-001-20261006.adi です（山頂やコールサインの「/」はファイル名に使えないため、「_」と書かれます）。
  • パソコンでは、エクスポートがすでにあるファイルを置き換えることはありません: 同じ名前がすでにある場合、新しいファイルは name (1).adi、次は name (2).adi というように保存されます。

注: 非常に大きなログ（100KB 超）では、重複排除と並べ替えに少し時間がかかることがあるため（特にスマートフォンの場合）、qFT8 は警告を表示します。

QSOアップロードサービス

qFT8 は、ログに記録したすべての QSO を、複数のオンラインまたは自宅ネットワーク内のログブックに送信できます: QRZ、LoTW、Wavelog、 Cloudlog、eQSL、そして別の qFT8（qFT8log）です。 それぞれ設定の上部に 1 行あり、オンにするためのチェックボックスと、そのサービス専用のページを開く歯車ボタンがあります。

  • サービスが検証されるまで、チェックボックスはグレー表示のままです。そのページを開き、 必要な情報を入力して検証を押してください。
  • 各ページの先頭には短い説明と?ボタンがあり、このマニュアルのそのサービスの節が開きます。 まだアップロードされていない QSO の数と今すぐアップロード、および デフォルトにリセットボタンも表示されます（アカウント、キー、パスワードは決して消去されません）。
  • サービスが最後に動作して以降、接続できていないときは、その行が赤くなり、その下の赤い行に 日時 から接続できませんと表示されます。

QSOがアップロード済みとみなされるのはいつ?

ログ、局リスト、地図、Web リモートに表示される緑のチェックマークは、すべて 1 つの規則に従います。各サービスのページには ここにアップロード済みならQSOをアップロード済みとみなすというチェックボックスがあります。 これは QRZ と LoTW ではオン、それ以外ではオフです。

  • サービスが対象になるのは、設定済み、つまり検証済みでオンになっているときだけです。
  • 対象のサービスのどれかにその QSO があれば、アップロード済みになります。
  • 設定済みのサービスのどれにもこのチェックが入っていないときは、設定済みのすべてのサービスが対象になります。 そのため qFT8log だけを設定した場合、アプリは qFT8log だけを待ち、 QRZ や LoTW を待つことはありません。
  • 設定済みのサービスがまったくないときは、QSO 自体が持っている情報をもとに、チェックの入ったボックスで判断します （たとえば、他のプログラムから取り込んだログは、そのチェックを保ちます）。
  • LoTW から取り込んだ QSO は、すでに QRZ にあるものとみなされ、そこへは送信されません。あるサービスから届いた QSO は、 そのサービスにアップロード済みとみなされ、そのサービスへ送り返されることはありません。
  • 星印（確認済み）には、この規則に従ってアップロード済みであり、いずれかのサービスで確認済みであることが必要です。 ただし、手動で確認済みまたは未確認にした場合は除きます。

ADIF エクスポートでは、一度に 1 つのサービスについてサービスに未アップロードを選べます。 設定されていないサービスの選択肢はグレー表示です。qFT8 は、どのサービス上の QSO も 削除しません。ここで QSO を削除すると、それがまだそちらに残っていることが警告されるだけです。

qFT8 サーバー

設定の下のほう、2 本の線の間にあるqFT8 サーバーには、この端末が他のプログラムに提供できるものがまとまっています。 リモートコントロール Web サーバー、qFT8 bridge、そして Wavelog、Cloudlog、qFT8log のサーバーです。

QRZ 連携

qFT8 は QRZ.com と密接に連携し、ログブックを自動で同期します。QRZ 連携は有料のサービスで、QRZ の有料サブスクリプション（XML Logbook Data 以上）が必要です。無料の方法を希望する場合は、ARRL が無料で提供している LoTW 連携を検討してください。

仕組み

QRZ 連携を有効にするには、「設定」タブで QRZ APIキーを入力する必要があります。API キーは QRZ Logbook API の公式ページで確認できます。入力して 検証 が済むと、「交信成立時にバックグラウンドでQRZへQSOをアップロードする」を有効にして、バックグラウンドでの自動管理を行えます。

  • 自動アップロード: QSO が完了する（6/6 DONE の状態に達する）たびに、qFT8 はすぐに QRZ のログブックへのアップロードを試みます。
  • バックグラウンドでの確実な処理: アップロードに失敗しても（インターネット接続がない、サーバーがタイムアウトした、など）、qFT8 はあきらめません。バックグラウンドの処理が、失敗したアップロードを 5 分ごとに自動で再試行します。この処理は表に出ることなく行われ、接続が回復すればログは最終的にクラウドに届きます。
  • 適切なスキップ: qFT8 は、現在設定されているコールサインと FT8 モードに一致する QSO だけをアップロードすることで、ログブックの整合性を守ります。FT8 以外のエントリー、別のコールサインの QSO、LoTW からインポートした QSO は、API へのリクエストが増えすぎないよう、自動的にスキップされます。

確認状況の同期

連携はアップロードだけではありません。qFT8 は QRZ に問い合わせて、QSO が確認されたかどうかも調べます。

  • 直後の確認: QSO が完了してアップロードされてから 30 秒後に、qFT8 は QRZ に問い合わせ、相手局もその QSO をアップロードしたかどうかを調べます。アップロードされていれば、その QSO はすぐに確認済みとして同期されます。
  • 自動同期: 既定では、qFT8 は 6 時間ごと（変更可能）に、一度に 250 件の QSO ずつ QRZ に問い合わせます。未確認のログ全体を順に回っていくので、古い QSO も最終的には新しい確認があるかどうか調べられます。
  • 確認の星（★）: QRZ にアップロードした QSO が QRZ または LoTW で確認されると、金色の星で強調表示されます。どの QSO も手動で確認済みにして、この表示を付けることができます。QRZ から確認が報告されると、「ログ」タブの状態アイコンは自動的に金色の星に変わります。
  • 手動同期: 同期してからもっとも時間のたった 250 件の QSO の更新は、設定から手動で実行することもできます。

ヒント: 同期の進み具合は、設定の「最も古い同期済みQSOの日付」で確認できます。qFT8 が時間をかけて処理していくので、急いで最新の状態にする必要はありません。

ログ同期の方針

同期の設定では、「次へのアップロードをもってQSOアップロード済み (✓) とみなす:」オプションで、qFT8 が QSO を「アップロード完了」とみなす条件を選べます:

  • LoTWまたはQRZのいずれか: どちらか一方のサービスだけを設定している場合に適した既定値です。
  • 両方: もっとも安全にしたい場合に選びます。QSO が両方のサービスに正常に送られて初めて、完了したもの、確認を調べる対象とみなされます。
  • QRZ (LoTWからインポートされたものを除く): QRZ をメインのログブックにしている場合におすすめです。注: LoTW からインポートした QSO は、API の制限（1 件ずつのアップロードしかできません）を避けるため、同期済みとして扱われますが、QRZ にはアップロードされません。これらは、あとで QRZ 側で同期できます。
  • LoTW: LoTW を自分のログの基準にしている場合におすすめです。

Logbook of the World (LoTW) 連携

qFT8 は ARRL Logbook of the World (LoTW) としっかり連携します。交信の確認を得て DXCC や WAS などのアワードを獲得するために、LoTW との連携を強くおすすめします。

必要な設定

自動アップロードや確認のチェックなど、LoTW の機能をすべて使うには、「設定」タブで次の 4 つの情報を入力する必要があります:

  • 1. LoTW のユーザー名: LoTW のサービスで使っている、正式なコールサインです。
  • 2. LoTW のパスワード: LoTW のウェブサイトにログインするときのパスワードです。証明書のパスワードとは別のものです。
  • 3. .p12 形式の TQSL 証明書: TQSL アプリケーションからエクスポートした電子署名用のファイルです。この証明書の申請とエクスポートの手順は、LoTW の公式ヘルプページを参照してください。
  • 4. 証明書パスワード: TQSL から .p12 ファイルをエクスポートするときに設定したパスワードです（設定しなかった場合は空欄のままでかまいません）。

局の所在地情報の自動設定: ITU ゾーン、CQ ゾーン、局名などの詳細は、コールサインから自動的に決まります。これらの項目を手動で設定する必要はありません。

機能

  • 自動アップロード: 交信成立時にバックグラウンドでLoTWへQSOをアップロードするを有効にすると、qFT8 は新しい QSO がログに記録されるたびに、バックグラウンドで自動的に署名して LoTW にアップロードします。
  • 確認の自動チェック: 有効にすると、qFT8 はアップロードが成功してからちょうど 30 秒後に、確認のチェックを 1 回だけすぐに行います。これにより、交信が確認されたかどうかをほとんど即座に知ることができます。
  • 定期的なバックグラウンド同期: __ ごとに確認を同期を設定すると、好みの間隔（たとえば 6 時間ごと）で、バックグラウンドで新しい確認をチェックします。これにより、手動で操作しなくてもログブック全体が最新に保たれます。
  • ログブックのインポート: LoTWからQSOをインポートを押すと、LoTW の履歴全体が qFT8 にダウンロードされます。インポートしたこれらの QSO は、API のレート制限を避けるため、QRZ には自動でアップロードされません。
  • 保留の表示: 「ログ」タブのボタンに付く小さな黄色の点は、LoTW へのアップロードを待っている QSO があることを示します。

ログ同期の方針

同期の設定では、「次へのアップロードをもってQSOアップロード済み (✓) とみなす:」オプションで、qFT8 が QSO を「アップロード完了」とみなす条件を選べます:

  • LoTWまたはQRZのいずれか: どちらか一方のサービスだけを設定している場合に適した既定値です。
  • 両方: もっとも安全にしたい場合に選びます。QSO が両方のサービスに正常に送られて初めて、完了したもの、確認を調べる対象とみなされます。
  • QRZ (LoTWからインポートされたものを除く): QRZ をメインのログブックにしている場合におすすめです。注: LoTW からインポートした QSO は、API の制限（1 件ずつのアップロードしかできません）を避けるため、同期済みとして扱われますが、QRZ にはアップロードされません。これらは、あとで QRZ 側で同期できます。
  • LoTW: LoTW を自分のログの基準にしている場合におすすめです。

Wavelog

Wavelogは、自分のWebサーバー(自宅の小型コンピューターやレンタルのWebスペース)で動かし、ブラウザーで開くログブックプログラムです。qFT8はQSOをログに記録するとすぐにそこへ送信し、そのうちどれがWavelogで確認済みになったかを読み戻します。qFT8はWavelogが公開しているインターフェース経由で通信します: docs.wavelog.org/developer/api。

設定方法

  1. Wavelogでアカウントメニュー > API Keys を開き、読み取りと書き込みの権限を持つキーを作成します。
  2. qFT8で設定を開き、Wavelogの横の歯車を押して、サーバーのアドレス(Wavelogを開くアドレス。例: https://log.example.org)とAPIキーを入力します。 http:// や https:// を付けずに入力したアドレスは、まず https で試されます。サーバーが通常の http しか話さない場合(別の qFT8 のサーバーがそうです)、qFT8 は http を使い、ページにキーが保護されずに送られると表示されます。
  3. 任意。編集内容も送るには、Wavelog で API v2 トークンを作成し(アカウントメニュー > API Keys、API v2 タブ、スコープは qso:read と qso:write)、編集トークン として入力します。検証 は何も変更せずにそれを確認します。
  4. 検証を押します。qFT8はキーを確認し、Wavelogのステーションロケーションを一覧表示します。QSOsの記録先にするものを選んでください(1つだけの場合は自動的に選ばれます)。
  5. 設定の上部でWavelogにチェックを入れます。以後、新しいQSOはすべてここへ送信され、それ以前に記録したものも送信されます。

動作

  • オフライン: 送信できないQSOはログ内で待機し、サーバーが再び応答したときに送信されます(1分後に試行し、その後は間隔を広げて最長で1時間に1回)。サーバーに接続できない間、設定のその行は「Couldn't connect as of ...」と表示されて赤くなります。
  • 重複: WavelogにすでにあるQSOはアップロード済みとして扱われます。
  • 拒否: Wavelogが拒否したQSOは、編集するか再アップロードするまで再送されません。理由はQSOエディターに表示されます。キーが使えなくなった場合は、もう一度「検証」を押すまでアップロードが止まります。
  • 確認:1 時間に 1 回(および 今すぐアップロード を押したとき)、qFT8 は Wavelog に QSOs のうちどれが確認済みか(LoTW、紙の QSL、eQSL)を問い合わせ、QSO エディターの アップロード 行と 状態 行に印を付けます。QRZ や LoTW と同じ行、同じ印です。
  • 編集:編集トークン を設定している場合、編集した QSO はあなたの Wavelog で見つかり、そこで更新されます(最新の変更が優先され、Wavelog が持つ確認の印には一切触れません)。設定していない場合、Wavelog のアップロード用インターフェースは QSOs を追加することしかできないため、編集は送られません。Wavelog でも変更してください。
  • 他のコールサインの QSOs:あなたのものとは別のコールサイン(クラブや特別運用のコールサイン)で記録された QSO は、QRZ と LoTW には送られませんが、他のコールサインでの QSO も送る にチェックが入っている間は Wavelog に送られます(初期設定)。
  • 削除: qFT8はWavelog内のものを一切削除しません。QSOを削除する場合は、そちらでご自身で削除してください。
  • ページ上の「ここにアップロードした場合もQSOをアップロード済みとみなす」は、Wavelogへのアップロードを「アップロード済み」マークの対象にするかどうかを決めます(初期設定ではオフ)。

WavelogからQSOをインポートする

Wavelogページの下部にあるWAVELOGからQSOをインポートは、選んだ局ロケーションのQSOsを、LoTW、紙のQSL、eQSLの確認情報とともにqFT8のログにコピーします。

  • 取り込む範囲: すべてのモードです。開始日、終了日、バンド、コールサインの先頭で絞り込めます(すべて = 制限なし)。自分以外のコールサインで行ったQSOsは、現在のコールサイン以外のQSOをインポートするにチェックを入れない限りスキップされます。
  • すでにログにあるもの: ログにすでにあるQSOは統合され、二重には追加されません(QRZやLoTWのインポートと同じ規則)。ここで修正したQSOは修正内容を保ち、確認情報だけを取り込みます。
  • 送り返されません: インポートしたQSOsはWavelogにすでにあるものとして扱われます。後でqFT8で行った修正はそちらに送られます(編集トークンを使用)。
  • 停止は、処理中の部分が終わった時点でインポートを終了します。それまでに入ったものは残ります。ボタンの下の行に、受信、追加、統合した件数が表示されます。
  • 何も削除されません。ここでもWavelogでも同様です。qFT8で削除したQSOは、次回のインポートで戻ってきます。

セキュア接続

  • https://のアドレスを推奨します。http://ではキーが保護されずに送信されるため、自宅のネットワーク内でのみ使用してください。
  • Android 6および7.0は、こうしたサーバーの多くが使う比較的新しい証明書の一部を信頼しません。そのためhttps://のサーバーには接続できない場合があります。自宅のネットワークでは、サーバーのhttp://アドレスで接続できます。
  • iPhoneはhttps://のアドレスにのみ接続します。

Cloudlog

CloudlogはWavelogの元になったプログラムで、自分のWebサーバー上で動かすログブックです。qFT8では独立したサービスとして独自の設定を持ち、Wavelogとまったく同じ手順で設定します(Cloudlogでは、アカウントメニュー > API > 読み取りと書き込みの権限を持つキーを作成)。公開されているインターフェース: github.com/magicbug/Cloudlog/wiki/API。

Wavelogとの違い

  • 確認の読み戻しなし: Cloudlogには、他のプログラムがどのQSOsが確認済みかを読み取る手段がないため、qFT8はアップロードのみを行います。
  • ステーションのコールサイン: Cloudlogは、ステーションのコールサインが選択したステーションロケーションのものと異なるQSOを拒否します。そのようなQSOはエディターで拒否と表示されます。Cloudlogで一致するステーションロケーションを選んでください。
  • 編集は送信されません。何も削除されません。オフライン時の動作、重複、赤い「Couldn't connect」の表示、セキュア接続に関する注意はWavelogと同じです。
  • インポート: Cloudlogは他のプログラムから読み取れません。そのログをqFT8に取り込むには、CloudlogでADIFファイルをエクスポートし、設定 > ログのインポート/エクスポートのADIFからQSOをインポートを使います(ADIFを参照)。

eQSL

eQSL（eqsl.cc）は電子QSLカードをやり取りします。そこへ送ったQSOは、相手局のeQSL受信箱にカードとして届きます。qFT8はカードを追加するだけで、eQSL上のものを削除することはありません。

設定方法

  1. 設定の先頭にあるQSOをeQSLと同期の行の歯車をタップします。
  2. eQSLユーザー名（通常はコールサイン）とeQSLパスワードを入力します。1つのコールサインに複数のeQSLアカウント（ロケーション）がある場合は、eqsl.ccに書かれているとおりにそのロケーションのQTHニックネームを入力します。そうでない場合は空欄のままにすると、eQSLがQSOの日付でアカウントを選びます。
  3. 検証を押します。ログインを確認するためにeQSLの受信箱を読み取るだけで、カードは送信されません。
  4. QSOをeQSLと同期にチェックを入れます。まだ送信していないQSOsはすぐに1秒に1件ずつ送られ、新しいQSOは記録されたときに送られます。

知っておくこと

  • eQSLではここにアップロード済みならQSOをアップロード済みとみなすはオフです。eQSLにカードがあるだけでは、ログの緑のチェックマークは付きません（QSOアップロードサービスを参照）。付けたい場合はチェックを入れてください。
  • カードは変更できません。 すでにeQSLにあるQSOを編集しても、自動では何も送信されません。修正したカードを送るには、QSOエディタのeQSL に再アップロードを使います。古いカードは、eqsl.ccで削除するまで相手局の受信箱に残ります。
  • LQ8：eQSLは公式のADIFモードしか受け付けないため、そのQSOsはMFSKとして送信され、コメントに実際のモードが記されます（「QSO by qFT8, mode LQ8」）。ほかのサービスは元の形式のままです。
  • eQSLにすでにあるQSOは重複として応答され、送信済みとして扱われます。eQSLが拒否したもの（たとえばどのアカウントにも含まれない日付や、未対応のモード）は、QSOエディタにeQSL自身の言葉で拒否と表示され、再アップロードするまで再試行されません。
  • オフラインのとき、またはeQSLがメンテナンスで停止しているときは、カードは待機し、後で再試行されます（1分後、その後は間隔が長くなり、最長1時間）。行の赤いCouldn't connectの表示がいつからかを示します。パスワードが拒否された場合（たとえばeqsl.ccで変更した場合）は、もう一度検証を行うまで送信は停止します。
  • 確認（受信したカード）はまだ読み戻されません。

WavelogサーバーとしてのqFT8

設定 > qFT8サーバー > Wavelogサーバーで、qFT8は自宅ネットワーク上でWavelogであるかのように応答します。WavelogへQSOsを送信できるプログラム(別のqFT8も含む)は、代わりにこのqFT8へ送信できます。

設定方法

  1. Wavelogサーバーを実行をオンにし、ポート(13500)はそのままにするか別の番号を選び、8文字以上のAPIキーを入力します(長くランダムなものにしてください。他の人を締め出す唯一の手段です)。
  2. もう一方のプログラムでは、ページに表示されるアドレスを省略せずに入力して Wavelog を設定します。http://、この端末のアドレス、コロン、ポートの順で、例えば http://192.168.1.20:13500/ です(多くのログプログラムでは http:// とポートを書く必要があります。別の qFT8 は自動で見つけます)。キーは同じもの、局は 1 です(別の qFT8 では 検証 が選びます)。

ポートはいつでも変更できます。サーバーはすぐに新しいポートに移ります(オフにするとすぐに停止します)。

ブラウザーでログを見る

家庭内ネットワークのブラウザーで同じアドレス(http://192.168.1.20:13500/)を開き、サーバーのキーを入力すると、QSO ログが新しい順に読み取り専用で表示されます。古い QSOs はスクロールすると読み込まれ、新しい QSOs や変更された QSOs は自動的に現れます。キーそのものは送られません。ブラウザーは、キーから作った値で一回限りのチャレンジに答え、誤った答えを返したアドレスはしばらく締め出されます。Cloudlog サーバーと qFT8 ログサーバーも、それぞれのポートで、それぞれのキーまたはパスワードにより同じページを表示します。

動作内容

  • 受信したQSOは、モードやコールサインを問わず、ログとQSOリストに入り、ここで設定したサービス(QRZ、LoTW、Wavelogなど)にも送られますが、送信元には戻されません。ログにすでにあるQSOは重複として応答され、再転送されません。
  • ログ記録プログラムが使うエンドポイントに応答します: api/qso(ADIF形式のQSOsを1件または複数件)、api/version、api/station_info、api/check_auth、api/auth、api/get_contacts_adif(チェーンの下流にあるqFT8が確認を読み戻せるようにするため)、api/radio(受け付けるが無視)。これを通じてQSOを変更・削除する手段はありません。
  • セキュリティ: 自宅ネットワーク内のみ、通常のhttp(リモート操作用Webサーバーと同じ)。キーは漏れない方法で照合されます。誤ったキーを10回送ってきたアドレスは10分間ブロックされます。1アドレスあたり毎秒最大20リクエスト、1リクエストあたり128 KBおよび500件のQSOsまで。不正な形式のものにはエラーが返されます。
  • 動作する場所: Androidでは「バックグラウンドで実行」がオンならバックグラウンドでも動作します。コンピューターではプログラムを開いている間、iPhoneではqFT8を開いている間のみ動作します。

チェーン

サーバーとサービスを組み合わせてチェーンを作れます。複数のステーション(スマートフォン、コンピューター)がQSOsを1台のqFT8に送り、そのqFT8がそれらを集めてQRZとLoTWへアップロードする唯一の存在となります。そのqFT8は、すべてをWavelogやバックアップ用の別のqFT8にも転送できます。確認は下流へ戻ります。集約するqFT8はQRZ / LoTW / 自分のWavelogから確認を取得し、そのWavelogサーバーに送信しているqFT8が1時間ごとにそれを読み戻します。重複は転送されないので、チェーン内のループは自然に止まります。

Summits On The Air（SOTA）

qFT8 には、SOTA（Summits On The Air）のチェイサー（ハンター）とアクティベーターの両方のためのツールがそろっています。スポットの自動取得、リファレンスのリアルタイム追跡、達成状況の強調表示、専用の ADIF エクスポートフィルターなどです。

山頂スポットの自動取得

インターネットに接続していると、qFT8 はバックグラウンドで SOTA の公式 API に自動的に接続し（90 秒ごとに更新）、世界中で運用中の山頂アクティベーションを取得します。

  • 世界地図での表示: 運用中の山頂アクティベーターが、山頂のマーカー（⛰️）、コールサイン、山頂の名前、標高、周波数とともに世界地図に表示されます。
  • リファレンスの自動照合: アクティベーターが聞こえると、qFT8 はそのコールサインをスポットのデータベースと照合し、正確な山頂リファレンス（例: HB/BE-001、W6/NC-001）を取得します。
  • あとからの自動補完: CQ SOTA を出している局との QSO が、その局のスポットをダウンロードする前やリファレンスを受け取る前に完了した場合でも、qFT8 は届くスポットを見て、最近（1 時間以内）記録した QSO に山頂リファレンスを自動的に補います。

SOTA のチェイサー（ハンター）として運用する

山頂をアクティベーション中の局を追いかけるには:

  1. 「ステーション」タブで、ターゲットのドロップダウンを SOTAハンター（または POTA + SOTAハンター）にします。
  2. バッジとリファレンスの列: 運用中の SOTA 局（オンラインでスポットされた局、または CQ SOTA を送信している局）には、2 行目に SOTA バッジが付きます。さらに、DXCC の列の見出しが SOTAリファレンス に変わり、山頂のコードがそのまま表示されます。
  3. 交信済みの山頂と未交信の山頂の区別:
    • 未交信の山頂: 鮮やかな紫の SOTA バッジと紫のリファレンスで表示され、新しく追いかける山頂であることを示します。
    • 交信済みの山頂: 控えめなグレーのバッジで表示されるので、新しい山頂と、すでにログにある山頂をひと目で見分けられます。
  4. AUTO での追いかけ: AUTO モードでは、qFT8 は未交信の SOTA アクティベーターを通常の CQ 局より優先して自動的に呼び出します。順番は信号（SNR）の強い順です。

ログの SOTA リファレンスの管理と編集

qFT8 には、SOTA の交信履歴を確認して編集するための専用の機能があります:

  • 「ログ」タブの SOTA ハンター表示: 「ログ」タブで SOTAハンター 表示を選ぶと、山頂リファレンスを確認できます。その山頂で最初の確認済みの交信は金色、最初の未確認の交信は黄色で強調表示されます。
  • 山頂リファレンスの編集: ログの QSO をタップして QSO エディターを開き、SOTA 欄をタップすると、山頂コード（例: HB/BE-001）を追加、変更、修正できます。
  • QRZ ログブックとの自動同期（ACTION=REPLACE）: QSO がすでに QRZ にアップロードされている場合、山頂リファレンスを編集すると、そのレコードに自動的に印が付けられ、重複したエントリーを作らずに QRZ ログブックのレコードがそのまま更新されます。
  • LoTW についての注意: リファレンスを編集しても、LoTW（Logbook of The World）は自動では更新されません。LoTW は、アップロード済みの QSO の変更に対応していないためです。

SOTA のアクティベーターとして運用する

山頂から SOTA のアクティベーションを行うには:

  1. 時刻を同期する: 出かける前に、端末の時計が正確であることを確認します。
  2. アクティベーションを開始する: 設定タブで SOTA アクティベーション を押し、山頂を入力します。以後、すべての QSO がその山頂付きで記録され、数えられます（公園・山頂のアクティベーションを参照）。
  3. CQ修飾子を設定する: 「設定」タブで CQ修飾子 を SOTA にします。CQ を出すたびに CQ SOTA [コールサイン] が送信されます。
  4. AUTO モードを設定する: 「ステーション」タブでターゲットを CQ呼び出し にし、AUTO モードを有効にします。
  5. アクティベーションを始める: TX を有効にします。qFT8 が自動で CQ を出し、呼んできたチェイサーに順番に応答します。

手動での割り込み: 複数のチェイサーから同時に呼ばれ、特定の局を選びたいときは、その局の CALL をタップします。その交信が終わると、qFT8 は自動的に CQ の送信に戻ります。

SOTA ログのエクスポート（チェイサーとアクティベーター）

qFT8 では、ハンターとしての申請用にも、アクティベーターのログ用にも、それぞれに合った ADIF ファイルを作成できます:

  1. 「設定」を開き、ADIFファイルのエクスポート をタップします。
  2. チェイサー / ハンターの場合:
    • ハンター条件 を SOTAハンターのみエクスポート にすると、山頂リファレンスのある相手と交信した QSO（<SOTA_REF> が入っているもの）だけがエクスポートされます。
  3. アクティベーターの場合（いちばん早いのはアクティベーションの エクスポート ボタンです。以下の手順は同じことを手動で行います）:
    • 指定した期間 を選び、アクティベーションの開始時刻と終了時刻に合わせます。
    • イベント で SOTA を選び、アクティベーションした山頂のコード（例: HB/BE-001）を入力します。qFT8 はすべてのレコードの <MY_SOTA_REF> に自局のリファレンスを書き込みます。
  4. Summit-to-Summit（S2S）: 山頂のアクティベーション中にほかのアクティベーターと交信した場合、エクスポートするファイルには、自局の山頂（<MY_SOTA_REF>）と相手局の山頂（<SOTA_REF>）の両方が入ります。
  5. QSOのエクスポート を押して、標準の ADIF ファイルを共有または保存します。

Parks On The Air（POTA）

qFT8 は、POTA（Parks On The Air）プログラムのハンターとアクティベーターの両方にしっかり対応しています。スポットの自動取得、交信済みの公園の追跡、リファレンスの編集、柔軟なエクスポートなどです。

公園スポットの自動取得

インターネットに接続していると、qFT8 はバックグラウンドで POTA の公式 API に自動的に問い合わせ（90 秒ごと）、世界中で運用中の公園アクティベーションをすべて取得します。

  • 世界地図での表示: 運用中の公園アクティベーターが、公園のマーカー（🏞️）、コールサイン、公園の名前、運用周波数とともに世界地図に表示されます。
  • リファレンスの自動判別: 運用中の公園局の送信を受信すると、qFT8 はそのコールサインを運用中のスポットと照合し、公園リファレンス（例: K-1234、US-0001、VE-0123）を自動的に判別します。
  • あとからの自動補完: CQ POTA を出している局との交信を、その局の公園リファレンスを受け取る前やスポットされる前に記録した場合でも、qFT8 は届くスポットを見て、最近（1 時間以内）記録した QSO に公園のコードを自動的に補います。

POTA のハンターとして運用する

公園をアクティベーション中の局を追いかけるには:

  1. 「ステーション」タブで、ターゲットのドロップダウンを POTAハンター（または POTA + SOTAハンター）にします。
  2. バッジとリファレンスの列: 運用中の POTA 局には 2 行目に POTA バッジが付き、DXCC の見出しが POTAリファレンス に変わって、公園のコードが表示されます。
  3. 交信済みの公園と未交信の公園の区別:
    • 未交信の公園: 明るい紫の POTA バッジと紫のリファレンスで表示され、まだ交信していない公園であることを示します。
    • 交信済みの公園: 控えめなグレーのバッジで表示されるので、バンドが混んでいるときでも未交信の公園を優先しやすくなります。
  4. AUTO での追いかけ: AUTO モードでは、qFT8 は未交信の POTA アクティベーターを通常の局より優先し、候補を信号（SNR）の強い順に並べます。

ログの POTA リファレンスの管理と編集

公園ハンターとしてのログは、アプリの中でそのまま確認して手入れできます:

  • 「ログ」タブの POTA ハンター表示: 「ログ」タブの表示を POTAハンター に切り替えると、交信と一緒に公園リファレンスが表示されます。その公園で最初の確認済みの交信は金色、未確認の交信は黄色で強調表示されます。
  • 公園リファレンスの編集: ログの QSO をタップして QSO エディターを開き、POTA 欄をタップすると、公園コード（例: K-1234）を追加、変更、削除できます。
  • QRZ ログブックとの自動同期（ACTION=REPLACE）: QSO の公園リファレンスを更新すると、qFT8 は重複したエントリーを作らずに、QRZ ログブックの既存のレコードをそのまま自動で更新します。
  • LoTW についての注意: リファレンスを編集しても、LoTW（Logbook of The World）は自動では更新されません。LoTW は、アップロード済みの QSO の変更に対応していないためです。

POTA のアクティベーターとして運用する

公園をアクティベーションするには:

  1. 時刻を同期する: アクティベーションを始める前に、端末の時計が正確であることを確認します。
  2. アクティベーションを開始する: 設定タブで POTA アクティベーション を押し、公園を入力します。以後、すべての QSO がその公園付きで記録され、数えられます（公園・山頂のアクティベーションを参照）。
  3. CQ修飾子を設定する: 「設定」タブで CQ修飾子 を POTA にすると、CQ POTA [コールサイン] が送信されます。
  4. AUTO モードを設定する: 「ステーション」タブでターゲットを CQ呼び出し にし、AUTO モードを有効にします。
  5. アクティベーションを始める: TX を有効にします。qFT8 は CQ を出し続け、呼んできたハンターと自動的に交信します。

手動での割り込み: 待っている局のどれかの CALL をタップすると、その QSO を先に行い、そのあと AUTO での CQ に戻ります。

POTA ログのエクスポート（ハンターとアクティベーター）

pota.app にそのままアップロードできる標準の ADIF ファイルを作成します:

  1. 「設定」を開き、ADIFファイルのエクスポート をタップします。
  2. ハンターの場合:
    • ハンター条件 を POTAハンターのみエクスポート にすると、公園と交信した QSO（<POTA_REF> が入っているもの）だけがエクスポートされます。
  3. アクティベーターの場合（いちばん早いのはアクティベーションの エクスポート ボタンです。以下の手順は同じことを手動で行います）:
    • 指定した期間 を選び、アクティベーションの時間帯に合わせます。
    • イベント で POTA を選び、公園リファレンス（例: K-1234）を入力します。qFT8 は、エクスポートするすべてのレコードに <MY_SIG>POTA、<MY_SIG_INFO>、<MY_POTA_REF> を自動で書き込みます。
  4. Park-to-Park（P2P）と Park-to-Summit（P2S）: アクティベーション中にほかの公園や山頂と交信した場合、自局の公園（<MY_POTA_REF>）と相手局のリファレンス（<POTA_REF> / <SOTA_REF>）の両方が同時にエクスポートされます。
  5. QSOのエクスポート を押して、ログファイルを共有または保存します。

公園・山頂のアクティベーション

公園（POTA）や山頂（SOTA）から運用するときは、qFT8 でアクティベーションを開始します。それ以降に記録する QSO には、どのモードでも自動的に公園または山頂が付き、qFT8 がその数を数え、最後にはワンタップで各プログラムが求めるファイルを書き出します。

開始する

  1. 「設定」タブで POTA アクティベーション または SOTA アクティベーション を押します（設定をエクスポート / 設定をインポートのすぐ上にあります）。
  2. リファレンスを入力します。たとえば公園なら US-1234、山頂なら W1/HA-001 です。同時に複数の公園にいる場合（「two-fer」）は、カンマで区切ります。qFT8 は入力中に形式を確認し、最近使ったリファレンスを候補として表示します。
  3. 開始 を押します。ボタンが青くなり、リファレンスと QSO の数が表示されます。

公園と山頂のアクティベーションは同時に開いておけます。その場合、すべての QSO に両方のリファレンスが付きます。デジタルモードで CQ POTA や CQ SOTA を出すには、POTA と SOTA の章で説明しているとおりに CQ修飾子 を設定します。

qFT8 のほうから開始を提案することもあります。世界地図用にダウンロードしたスポットに自局のコールサインがアクティベーターとして載っていると、そこで POTA アクティベーションを開始しますか? と尋ねます。また、ロガーの空の自局の POTA / 自局の SOTA 欄に公園や山頂を入力すると、それでアクティベーションを開始するかどうかを尋ねます。

告知して、ハンターに見つけてもらう

すでにあなたを告知しているスポットからではなく、自分でアクティベーションを開始すると、qFT8 は POTA に告知しますか?（または SOTA）と尋ね、ハンターに表示される内容（例：FT8 on 20m (14074 kHz)）を示します。今はしない は何も告知しません。告知する は短いダイアログを開きます。

  • バンド と モード：それぞれ 1 つ以上にチェックを入れます。qFT8 が使用中のバンドとモードは最初からチェックされています。qFT8 は、選んだ公園・バンド・モードの組み合わせごとに告知を 1 件送り、告知する を押す前にその件数を表示します。
  • プログラムの一覧にないモードは DATA として告知され、実際のモードは告知のコメントに入ります。通常の周波数がないバンドとモードの組み合わせ（60 m の RTTY）は除外され、ダイアログでそのことが示されます。
  • 周波数は、使用中のバンドとモードについては無線機の現在の周波数、それ以外については通常のコール周波数です。
  • SOTA のみ：ダイアログは SOTAwatch のユーザー名とパスワード（ご自身の SOTA サインイン）も求めます。qFT8 は他のサービスのパスワードと同様に、次回のために保存します。

その後、アクティベーションが開いていて qFT8 が動作している間（画面上、または最小化してバックグラウンドで qFT8 を動かし無線機を接続したままの状態）、qFT8 は 30 分ごとにアクティベーションを再告知します（告知は約 1 時間後に一覧から消えます）。アクティベーションを終了すると止まり、qFT8 が閉じていたときは自動では告知しません。次回の起動時、アクティベーションを続けると選んだ後に もう一度告知しますか? と尋ねます。

告知が届かない場合（インターネットがない、サイトに拒否された、SOTA のサインインが正しくない）、qFT8 は何が起きたかを伝え、再試行 または 手動で告知 を提示します。後者はプログラムのスポットページをブラウザで開くので、ご自身で告知できます。接続がないときは、5 分ごとに自動で再試行もします。

別のバンドやモードで告知したい場合や、最後に告知した時刻を確認したい場合は、アクティベーションのカード（青いマーカーをタップ）またはアクティベーションの QSO ビューで 告知する を押します。このダイアログには 再告知を停止 も表示されます。告知済みのアクティベーション中にモードを変えると、新しいモードも告知するかどうか qFT8 が尋ねます。

開いている間: 青いマーカー

アクティベーションが開いている間は、ウォーターフォールの右下に青い POTA または SOTA のマーカーが表示され、その横にアクティベーションの QSO 数が表示されます: POTA 10。記録した QSO はすべて数えられ、QSO をアクティベーションから外したり、削除したり、ロガーで取り消したりすると、数は減ります。2 つの公園を同時に運用していても数字は 1 つです。各 QSO が両方の公園に数えられるからです。表示する場所が狭いときは、マーカーはアイコンの横に数字だけを表示し、それも入らないときは、同じ行にある赤い警告とともに小さく描かれます。タップすると、アクティベーションの状態が表示されます:

  • リファレンスとカウント: 行った QSO の数と、プログラムが有効なアクティベーションに求める数（公園は 10、山頂は 4）、そしてそのうち別の公園や山頂との QSO（P2P / S2S）がいくつあるか。
  • アクティベーションを表示: その QSO の一覧（後述）。
  • アクティベーションを終了: アクティベーションを終了します。必ず先に確認があり、続ける で続行できます。
  • 閉じる: カードを閉じます。

アクティベーションの QSO

  1. QSO ログ全体に戻る。
  2. アクティベーション: プログラムとリファレンス、開始時刻（UTC）、その QSO。
  3. +: ロガーを開き、QSO を手動でこのアクティベーションに直接記録します。
  4. QSO を追加: すでにログにある QSO を、時間の範囲を指定して追加します。アクティベーションの開始を忘れたときに使います。開始と終了を選ぶと、qFT8 は追加する前に何件の QSO を追加するかを知らせます。
  5. エクスポート: アップロード用のファイルを書き出します（後述）。
  6. 相手局の公園または山頂（相手局もアクティベーション中だった場合）。
  7. 開いているアクティベーションのマーカー。

QSO をアクティベーションから外すには、1 つを長押しして選択し、ほかの QSO もタップしてから、操作 を押して このアクティベーションから外す を選びます。QSO はログに残り、自局のリファレンスだけが取り除かれます。QSO エディターの POTAアクティベーション / SOTAアクティベーションの行から、QSO を 1 件だけ移すこともできます。

終了と再開

アクティベーションを終了 を押すと、概要が表示されます。リファレンス、開始時刻と終了時刻、モードごとの QSO 数、アクティベーションが有効かどうかです。終了後に記録した QSO は含まれません。

  • 間違えて終了した場合、または休憩から戻った場合。 24 時間以内であれば、概要、アクティベーションの一覧、そして POTA アクティベーション / SOTA アクティベーション の開始ダイアログに アクティベーションを再開 が表示され、何事もなかったようにもう一度開けます。
  • UTC の日付が変わった場合。 POTA では、UTC の 1 日ごとに別のアクティベーションになります。UTC の 0 時を過ぎると、qFT8 は再開ではなく、同じ公園での 新しく開始 を提案します。
  • 開いたままにした場合。 qFT8 をしばらく閉じていたとき、または QSO のないまま長い時間が過ぎたときは、次に起動したときに 続ける か終了するかを尋ねます。

エクスポート

エクスポート（概要とアクティベーションの一覧にあります）は、各プログラムが求める名前の付いた ADIF ファイルを書き出します。そのままプログラムのウェブサイトにアップロードできます:

  • POTA: 公園ごと、UTC の日ごとに 1 つのファイルで、名前は CALLSIGN@PARK-DATE.adi です（たとえば K1ABC@US-1234-20261006.adi）。two-fer の場合は公園ごとに 1 つのファイルになります。相手局自身が 2 つの公園にいた場合は、その公園ごとに 1 回ずつ書き出されるので、どちらもパーク・トゥ・パークとして数えられます。
  • SOTA: 山頂に対して 1 つのファイルで、名前の付け方は同じです（K1ABC@W1_HA-001-20261006.adi）。

ファイルは保存することも共有することもできます。「設定」の POTA アクティベーション / SOTA アクティベーション の横にある虫めがねボタンを押すと、過去のアクティベーションが新しい順に表示され、それぞれに 実行中、再開可能、エクスポート済み、または未エクスポートの表示が付きます。タップすると開いて、もう一度エクスポートできます。qFT8 自体がプログラムのウェブサイトにアップロードすることはありません。

複数の公園を続けて回る

1 日にいくつかの公園を順に回る場合、公園ごとに別のアクティベーション、別のファイルになります:

  1. 最初の公園で、「設定」の POTA アクティベーション を押し、リファレンスを入力して 開始 を押します。
  2. 運用します。すべての QSO にその公園が付き、青いマーカーが数を数えます。
  3. 移動する前に、マーカーをタップして アクティベーションを終了 を押し、概要の エクスポート を押して、ファイル（K1ABC@US-1234-20261006.adi）を保存または共有します。
  4. 次の公園では、新しいリファレンスでもう一度開始します。

帰宅してから入力し直したり整理したりするものはありません。現地でエクスポートする時間がなければ、過去のアクティベーションの一覧（虫めがね）から、あとで 1 つずつエクスポートできます。

「ファイルにはどの公園を書きますか？」

公園のファイルには、公園を 1 つしか書けません。複数の公園から同時に行った QSO を、アクティベーションを通さずにエクスポートすると（「設定」からのログ全体、または選択した QSO のエクスポート (ADIF)）、qFT8 はファイルにはどの公園を書きますか？ と尋ねます。このファイルの対象となる公園を選び、もう一方の公園についてはもう一度エクスポートしてください。ログは変わりません。アクティベーションからのエクスポートでは尋ねられることはなく、公園ごとに 1 つのファイルが書き出されます。

アクティベーションなしですべての公園のファイルを作るには、公園を自分でカンマ区切りで入力します（US-1234, US-5678）。入力先はログのインポート/エクスポートの POTA参照欄、または選択した QSO の POTA リファレンス付きでエクスポートです。qFT8 は公園ごとに 1 つのファイルを書き出し、それぞれに同じ QSO が入ります。山頂のリファレンスは常に 1 つです。

交信する相手局が同時に 2 つの公園にいる場合、qFT8 は両方を保持します。スポットした人がコメントに 2 つ目の公園を書いていれば、そこから読み取ります。ログには最初の公園と、ほかにいくつあるかが表示されます（US-1234 +1）。公園が間違っていたり抜けていたりする場合は、QSO エディターでその QSO の POTA 欄を修正してください。カンマで区切って複数の公園を入力できます。同じ局について同じ公園が 2 回挙げられていても（スポットとそのコメントの両方にある、または入力したリストに 2 回ある）、ログでもエクスポートされるどのファイルでも 1 回として数えられます。

JS8 チャット

JS8 モードで運用しているとき、qFT8 は従来の FT8/FT4 の QSO 運用に加えて、会話形式のフリーテキストのチャット画面を提供します。JS8 では、弱い信号でも確実な、キーボードどうしのメッセージのやり取りを、複数の速度から選んで行えます（Slow 30 秒、Normal 15 秒、Fast 10 秒、Turbo 6 秒のスロット）。

チャンネルの種類と振り分け

右側のチャットパネルでは、送受信したメッセージがチャンネルごとのタブに整理されます:

  • [GLOBAL] メインチャンネル: オーディオ通過帯域全体でデコードしたすべての JS8 の送信と、自局のすべての送信を表示します。バンド全体の動きを 1 か所でリアルタイムに見渡せます。
  • ブロードキャスト用のグループチャンネル（@CQ、@ALLCALL）: 聞いているすべての局に向けた一般の呼び出しやお知らせに使います。@CQ または @ALLCALL あてのメッセージは、その周波数を聞いている誰にでも見えます。
  • カスタムのグループチャンネル（@GROUPNAME）: qFT8 はカスタムのグループあてメッセージに対応しています（例: @EMERGENCY、@SOTA、@NET）。@GROUP タグの付いたメッセージを送受信すると、専用のチャンネルタブに自動で整理されます。
  • 局ごとのダイレクトチャンネル（コールサインのタブ）: チャンネル一覧またはステーションの表から特定の局を選ぶと、そのコールサインとの専用の会話スレッドが開きます。

電波での送信（非公開ではありません）: JS8 のメッセージはすべて、通常のアマチュア無線のデジタル信号として、暗号化されずに送信されます。局ごとのダイレクトチャットは、便利なように会話の履歴を専用のタブにまとめますが、暗号化も非公開化もされておらず、その周波数を聞いているどの局でも受信できます。

メッセージの作成と送信

  1. あて先を選ぶ: 右側のパネルで、チャンネルのタブ（[GLOBAL]、@CQ、@ALLCALL、グループ、特定の局のコールサイン）をタップします。
  2. メッセージを入力する: 下部の入力欄にテキストを入力します（標準の ASCII 文字を 100 文字まで使えます）。
  3. 送信する: 送信ボタンをタップします。

メッセージをタップする（すぐにチャット、詳細）

チャットログのメッセージをタップすると（パソコンではダブルクリック）、詳細ダイアログが開き、完全な UTC タイムスタンプ、オーディオ周波数、SNR、Maidenhead グリッド、メッセージの内容が表示されます:

  • 受信メッセージ（RX）: チャット をタップすると、送信した局とのダイレクトチャットのタブがすぐに開きます。グループあてのメッセージの場合は グループチャット です。
  • 送信メッセージ（TX）: 再送信 をタップすると、入力欄とあて先のチャンネルに同じ内容が自動で入り、簡単に再送信できます。

複数チャンクでのメッセージ送信

メッセージが JS8 の 1 回の送信フレームに収まらない長さの場合:

  • qFT8 はメッセージを連続する複数のチャンクのフレームに自動で分割します。
  • アプリは、メッセージ全体を送り終えるまで、各チャンクを連続するタイムスロットで自動的に送信します。
  • 進行状況の表示で、複数スロットにわたる送信の状態が分かります（例: TX (1/3)）。
  • すべてのチャンクが終わる前に送信を止めたいときは、送信／停止ボタンをタップすると確認が表示され、残りの送信待ちをキャンセルできます。

チャンネルの管理（長押しの操作）

右側のパネルで局のコールサインのタブやグループチャンネルのタブを長押しすると（パソコンでは右クリック）、管理用のメニューが開きます:

  • チャットを消去: 選択したチャンネルのタブのメッセージ履歴を消去します。
  • チャットを閉じる: タブを閉じ、使用中のチャンネルのバーから取り除きます。
  • チャットをエクスポート: 選択したチャンネルのメッセージ履歴全体を、テキストファイルに書き出すか、共有シートに渡します。

問い合わせへの自動応答（AUTO モード）

AUTO ボタンが有効なとき、qFT8 は、ほかの局から自局あてに届いた問い合わせ（SNR?、HW CPY?、GRID?、INFO?、STATUS?、HEARING? など）と、ハートビートのメッセージ（@HB HEARTBEAT）に自動で応答します。

たとえば、ほかの局が 自局コールサイン SNR? や 自局コールサイン HW CPY? を送信すると、qFT8 は手動の操作なしに、シグナルレポートの応答（例: SNR -08）を自動で送信待ちに入れて送信します。同じように、ハートビートの送信（@HB HEARTBEAT）を受信すると、qFT8 はハートビートへの応答（HEARTBEAT SNR -08）を自動で送信待ちに入れ、受信できたことを送信した局に知らせます。

あて先を指定した問い合わせとリクエストボタン

リクエスト ボタンを使うと、コマンドの書式を手で入力しなくても、選択中のあて先の局またはグループに、標準の問い合わせをすばやく送れます:

  • SNR? / HW CPY?: 相手局にシグナルレポートを求めます。
  • GRID?: 相手局の Maidenhead グリッドロケーターを求めます。
  • INFO?: 相手局が設定している情報メッセージを求めます。
  • STATUS?: 相手局の運用状況のテキストを求めます。
  • HEARING?: その局が直近の 10 分間に受信した局の一覧を問い合わせます。

WSPR モード

WSPR（Weak Signal Propagation Reporter）は、ごく小さな電力の送信で電波の伝搬経路を調べるために設計された、専用のデジタルプロトコルです。WSPR の信号は、狭帯域の 4-FSK 変調、強力な畳み込み符号、ファノの逐次復号を使い、ノイズフロアを大きく下回る −28 dB SNR までの信号をデコードできます。

2 分のサイクルとタイミング

WSPR の送信は、同期した 2 分間の UTC スロットで行われます（送信時間は 110.6 秒、162 個のトーンシンボル）。送信は必ず UTC の偶数分のちょうど 1 秒後に始まります（:00, :02, :04, :06...）。1 回の送信が 2 分近く続くため、小型の無線機ではそれだけの時間送信できるように設定しておく必要があります。連続送信時間の上限を参照してください。スペクトログラムの縦スクロールは、120 秒のサイクルに合わせて自動的に滑らかでゆっくりした速度になります。

1 つのペインでの受信状況の表示

WSPR は双方向の会話のモードではなく、ビーコンと伝搬レポートのためのプロトコルです。そのため qFT8 は、QSO ログとの分割のない、すっきりした全幅 1 ペインの受信ログを表示します:

  • コールサイン: 局のコールサイン。
  • DXCC エンティティ: 自動的に判別された国・DXCC エンティティの名前（幅は可変）。
  • グリッドロケーター: 4 文字の Maidenhead ロケーター（例: JN45）。
  • SNR: 受信した信号の信号対雑音比（dB）。ほかの WSPR 受信機と同じく、2,500 Hz 幅のノイズを基準に測定します。
  • 送信電力: その局が報告している送信電力（dBm。例: 37 dBm）。
  • 日付と UTC 時刻: 送信スロットの UTC のタイムスタンプ。形式は yyMMdd HH:mm です。

自動ビーコンと送信率（Tx %）

WSPR の受信状況画面の上部には、次のものがあります:

  • ビーコン の切り替え: 自動ビーコン送信を有効または無効にします。有効にすると（明るい緑で強調表示されます）、qFT8 は設定した送信率に基づき、決まった間隔でビーコン送信を自動的に予定します。
  • Tx % セレクター: 前回の送信からの経過時間をもとにした、決まった送信の割合を設定します（0% [受信のみ]、10%、20%、25%、33%、50%、100% 連続）。たとえば 20% では、前回の送信から 10 分ごとに必ず送信します（50% = 4 分ごと、33% = 6 分ごと、25% = 8 分ごと、10% = 20 分ごと、100% = 2 分のサイクルごとに連続）。
  • Tx 次 ボタン: 次の 2 分サイクルの区切りで、手動の送信をすぐに 1 回行うよう予約します。送信後は、そのサイクルを起点に、決まった間隔の自動ビーコンの予定が続きます。

WSPRnet と PSKReporter へのスポットのアップロード

qFT8 は、受信したスポットを世界規模の WSPRnet データベースと PSKReporter に自動でアップロードできます:

  • WSPRnetからスポットをダウンロード: 既定で有効です。自局のコールサインとバンドのスポットをリアルタイムで取得し、世界地図に表示します。
  • レポートをWSPRnetにアップロード: 設定 → WSPRnet で有効にすると、受信したスポットがまとめて WSPRnet にアップロードされます。15 分間の重複排除と送信頻度の制限があります。
  • WSPRnetを開く: 自局のコールサインで絞り込んだ WSPRnet のデータベースをブラウザーで直接開きます。

単独の ADIF エクスポート

WSPR の受信状況パネルの右上にある エクスポート ボタンをタップすると、現在のセッションで記録したすべてのスポットを、伝搬の研究や記録の保存のために標準の ADIF 形式（.adi）でエクスポートできます。

SSB（音声）

SSB モードでは、qFT8 がトランシーバーのマイクとスピーカーになります。無線機が受信した信号は、あなたのスピーカーまたはヘッドホンから音声として聞こえ、あなたの声はマイクから無線機に送られます。無線機の接続はデジタルモードのときとまったく同じ（同じ USB ケーブル、同じサウンドカード）なので、FT8 と音声を行き来するのに何もつなぎ替える必要はありません。

下部バーのモードセレクターで SSB を選びます。メッセージ欄、シーケンスボタン、サイクルバーが消え（音声にはタイムスロットがありません）、モードセレクターの横に USB / LSB ボタンが現れ、「ステーション」タブが SSB ペインになります:

SSB 画面の各部の詳細は次のとおりです:

  1. RX / TX / RX/TX: チューニングホイール（項目 12）で動かす対象を選びます。RX/TX では、同じ周波数で受信と送信を行います。RX または TX ではその一方だけが動くので、ある周波数で聞きながら別の周波数で送信できます（スプリット）。
  2. AUTO RIT: 周波数が少しずれている局を中央に保ち、ホイールに触れなくても相手の声が自然に聞こえるようにします。
  3. 歯車: 設定 > SSB を開きます（後述）。戻るでこのペインに戻ります。
  4. QSO: モード、サイドバンド、周波数が入力済みのロガーを開き、いま行った交信を記録します（ロガーを参照）。1 回押すごとに 1 件の QSO です。
  5. ボイスメモリー: 録音しておいたメッセージ（CQ の呼び出し、自局のコールサインなど）。1 つも録音していない間は、この場所にボイスメモリーは設定で登録しますというリンクが表示されます。
  6. IN: マイクのレベルとゲインのスライダー。VOX と書かれた線は、VOX がオンのとき（項目 10）に、声がこれを超えると無線機が送信に切り替わるレベルです。ドラッグして動かせます。
  7. OUT: 受信音のレベルとスピーカーの音量スライダー。スマートフォンの音量キーでも同じ操作ができます。
  8. FILTER と NR: 受信フィルター（オフ、2.7、2.4、1.8 kHz）とノイズ低減（オフ、1、2、3）。タップするたびに次の値に切り替わります。
  9. PTT: プッシュ・トゥ・トーク。PTT モードの設定に応じて「押している間話す」または「タップして話す」と表示され、送信中は「送信中」と表示されます。パソコンでは、ペインにフォーカスがある間はスペースキーで同じ操作ができます。
  10. VOX: オンにすると、PTT ボタンの代わりに声で無線機が送信に切り替わります。
  11. USB / LSB: サイドバンド。バンドを変えると自動的に選ばれます（10 MHz 未満は LSB、それ以上は USB）。タップすると切り替わり、表示されている周波数は変わりません。
  12. チューニングホイール: SSB では、スペクトログラムの周波数目盛りがホイールになります。目盛りに沿ってスワイプすると無線機の周波数が変わり、速くスワイプするほどステップが大きくなります。タップでは何も起きないので、周波数が誤って飛ぶことはありません。パソコンではマウスホイールでも同調できます（Shift を押している間は 1 Hz ステップ）。同調には無線機との CAT 接続が必要です。
  13. 周波数とバンド: オンエアで口にする周波数（キャリア）と、バンド。オレンジ色の線とその下の RX/TX ラベルは、スペクトログラムのうち、聞いている部分と送信する部分を示します。

話す

  1. 下部バーの TX ボタンで送信を有効にします。ほかのモードと同じく、TX OFF と表示されている間は何も送信されません。赤い行の 送信するには TX ON を押してください がそれを知らせます。
  2. PTT を押したまま話し、話し終えたら離します。または VOX をオンにして、そのまま話します。
  3. ボイスメモリーを送るには、それをタップします。TX ON のときは送信され、自分のスピーカーからも聞こえます。TX OFF のときは自分に向けて再生されるだけなので、録音の確認に便利です。長押し（パソコンでは右クリック）すると、常に自分に向けて再生するだけになります。

自分の生の声が自分のスピーカーから再生されることはありません。送信しようとしている周波数がアマチュアバンドの外にある場合、qFT8 は無線機を送信に切り替えず、その旨を表示します。

PTT 制限: タップで切り替えと VOX では、PTT 制限（変更しなければ 100 秒）が過ぎると送信が自動的に止まり、PTT ボタンに残りの秒数が表示されます。制限に達したあと、VOX は同じ時間だけ、または PTT をタップするまで休止します。これは、マイクがノイズを拾い続けた場合に無線機を守るためのものです。無線機自体の連続送信時間の上限も適用され、2 つのうち短いほうが優先されます。

ボイスメモリー

設定 > SSB > ボイスメモリーを開き（またはペインのボイスメモリーは設定で登録しますをタップし）、新しいボイスメモリーを録音 を押します。メモリーは 6 個まで、それぞれ 30 秒まで保存できます。メモリーごとに、名前を付ける、録音し直す、音量を設定する、ノーマライズ を押す、といった操作ができ、音の波形の上にある 2 つのハンドルをドラッグして先頭と末尾の無音を切り取ることもできます。再生 は残した部分を再生し、保存するまでは何も変わりません。メモリーは、録音も含めて設定のエクスポートに含まれます。

設定 > SSB

  • PTT 方式: PTT ボタン、または VOX。
  • PTT モード: 押している間話すまたはタップで切り替え。
  • PTT 遅延: 無線機を送信に切り替えてから声を送り出すまでの時間。話した内容が欠けることはありません。最初の音節は無線機の準備ができるまで待たされます。
  • PTT 制限: 上記を参照（10～600 秒）。
  • サイドバンド: バンドに応じて自動、常に USB、または常に LSB。
  • SSB に入るときのフィルターとSSB に入るときのノイズ低減。
  • 受信音をスピーカーで再生すると送信中はスピーカーを消音する。
  • ボイスメモリーと デフォルトにリセット。

SSB に必要なもの

  • 無線機のサウンドカードではないマイクとスピーカー。 スマートフォンには内蔵されていますし、ヘッドセットも使えます。スピーカーとマイクを参照してください。無線機とマイクまたはスピーカーが同じデバイスになっている場合は、赤い行でその旨が表示され、送信も再生も行われません。
  • 無線機。 無線機がないと、ペインの代わりに SSB を使うには無線機を接続してくださいと書かれたカードが表示されます。無線機を接続すると、ペインは自動的に戻ります。CAT がなく、無線機自身の VOX で送信に切り替わる無線機でも使えますが、その場合はアプリから同調できません。
  • QMX または QMX+ には、ファームウェア 1_02_000 以降が必要です。 アプリから音声を送信するための条件です。古いファームウェアでは、下部バーに SSBなしと表示され、このモードは受信専用になります。
  • あるバンドを SSB で初めて開くと、qFT8 はそのバンドで、お住まいの地域で一般的な音声の周波数に合わせます。2 回目以降は、そのバンドで最後に使った周波数に戻ります。30 m バンドには音声の区分がないため、選べません。

QSO はサイドバンドとともに SSB として記録され、ほかの QSO と同じように QRZ と LoTW にアップロードされます。

CW（モールス符号）

CW モードでは、qFT8 が通過帯域内のすべてのモールス信号を解読し、その文字をスペクトログラム上に書き出します。送信は、画面上のパドル、自分のキー、用意された定型文、入力した文字のいずれかで行えます。TX OFF のときは、すべてが練習として動作します。自分の送信はスピーカーから聞こえ、電波は出ません。

下部バーのモードセレクターで CW を選びます:

CW 画面の各部の詳細は次のとおりです:

  1. AUTO: qFT8 に CW の QSO 全体を任せます（CW での AUTO を参照）。
  2. RX / TX / RX/TX: ウォーターフォールのタップやチューニングホイールで動かすバーを選びます。受信バー、送信バー、または両方を一緒に動かせます。
  3. 歯車は 設定 > CW を開き、QSO は CW、周波数、ターゲットが入力済みのロガーを開きます。
  4. ターゲット: 交信している相手局のコールサイン。メッセージの [TARGET] の部分に入ります。タップして入力するか、デコーダー行（項目 10）のコールサインをタップして取り込みます。
  5. メモリー: 用意された定型文。タップすると送信されます。自局のコールサインは青、レポートは黄色で表示されます。まだ足りない項目（ターゲット、自分の名前など）があるメモリーは薄く表示されます。タップすると、何が足りないかが分かります。
  6. WPM と FARNSWORTH: 1 分あたりの語数で表した送信速度と、オプションのファーンズワース速度（文字の速度はそのままで、文字の間隔が長くなります）。
  7. FILTER と NR: 受信バーを中心とした受信フィルターの幅と、ノイズ低減。
  8. パドル: 左が短点、右が長点です。アイアンビックのモードでは両方を押します。
  9. 赤い行: 送信するには TX ON を押してください。これが表示されている間、キーイングは練習になります。
  10. デコーダー行: FT8 でメッセージセレクターがある場所です。フィルター内の局の文字を緑で、自分が送っている内容を赤で表示します。新しいものが右側です。
  11. ウォーターフォール上のデコード文字: すべての信号について、その軌跡に沿って文字が書き出されるので、バンド全体を一度に読めます。受信バーの下のラベルには、いま合わせている局のコールサインと速度が表示されます。
  12. チューニングホイール: 周波数目盛りです。目盛りに沿ってスワイプすると、選択中のバーが動きます（バーが端に達すると無線機の周波数も動きます）。ウォーターフォールをタップまたはドラッグすると、バーを直接動かせます。
  13. 周波数へ移動: 白い信号強度の線が表示されている帯をタップすると、周波数を kHz で入力できます。

送信する

送信方法は 4 つあり、どれも WPM で設定した速度を使います:

  • 画面上のパドル。1 本または 2 本の指で操作します。
  • 自分のキー: キーボードのキー、マウスボタン（パソコンでは左ボタンが左パドル、右ボタンが右パドル）、または USB や Bluetooth で接続し、キーボードとして動作するキーヤーアダプター。パドルとキーヤーを参照してください。
  • メモリー: タップします。その間に 2 つ目のメモリーをタップすると、順番を待ちます。文字を送信している間は 停止 のある帯が表示され、パドルに触れても送信が止まります。
  • キーボード（メモリーの最後にあります）: メッセージを入力して 送信 を押します。入力欄の下の行に、実際に送信される内容がそのまま表示されます。Android では、音声 で同じことを音声入力で行えます。メッセージを話すと、モールス符号で送信されます。

オンエアでの CW は、どのサイドトーンを選んで聞いていても、常に立ち上がりと立ち下がりのなめらかなきれいなトーンです。安全のため、キーを 10 秒間押し続けると解放され、送信は 3 分で停止します。

TX OFF での練習

下部バーに TX OFF と表示されている間も、パドル、自分のキー、メモリー、キーボード入力欄はすべて動作しますが、音が出るのは自分のスピーカーだけです。キーイングした内容はデコードされ、デコーダー行に赤で表示されるので、自分の符号が読み取れるかどうかを確認できます。無線機には何も届きません。この練習に無線機はまったく必要ありません。

パドルとキーヤー

設定 > CW のキーヤーセクションで、パドルの動作を設定します:

  • キーヤーモード: 縦振り電鍵、Iambic A、Iambic B、その両方の 1 本指版、Ultimatic、Bug（半自動）、Cootie（サイドスワイパー）。
  • 速度、Farnsworth、語間、厳密なタイミング（文字間と語間を標準の長さにします）。
  • パドルを左右反転: 短点と長点を入れ替えます。
  • ブレークイン遅延: 最後の短点または長点のあと、無線機が送信状態を保つ時間。
  • 速度合わせ: 受信している局の速度に合わせて送信します。

パドル入力セクションでは、何をパドルとして扱うかを設定します:

  • パドル: メインのスイッチです。オフにすると、画面にパドルが表示されず、どのキー、マウスボタン、アダプターでも送信機をキーイングできなくなります。
  • 画面上のパドル、マウスボタン、キーボードのキー、外部アダプター (USB / Bluetooth): 入力元ごとに個別にオフにできます。
  • キー割り当て: 既定では、あらかじめ用意されたキーの一覧を使います（[ と ]、左右の Ctrl キー、F1 と F2 など）。カスタムでは、左パドルと右パドルのキーの一覧を自分で作ります。キーを追加 を押してから、割り当てたいキーを押します。すでにもう一方のパドルに割り当てられているキーは受け付けられません。

テキスト入力欄が開いている間は、Ctrl キーと F1 / F2 だけがパドルとして働くので、コールサインを入力していてモールスが送信されることはありません。

アダプター、キーボード、マウスでのキーイング

モールスを送信するのに、画面をタップする必要はありません。次の 4 つがパドルとして働き、すべて同時に使えます:

  • 画面上のパドル。指で操作します。
  • USB 電鍵アダプターにつないだ本物の電鍵やパドル: 片側に電鍵をつなぐジャック、反対側に USB プラグのある小さな箱またはケーブルです。スマートフォンやパソコンからは、キーボード（電鍵の接点ごとにキーボードのキーが押されます）またはマウス（接点ごとにマウスボタンが押されます）として見えます。Bluetooth のアダプターも同じように働きます。
  • キーボード: 左パドル用のキーと右パドル用のキーを使います。
  • マウス: 左右のボタンを使います。

どれも、選んだキーヤーモードと速度に従い、TX OFF のときは練習として使えます（TX OFF での練習を参照してください）。

アダプターを接続する

  1. 電鍵またはパドルをアダプターにつなぎ、アダプターをスマートフォン、タブレット、またはパソコンにつなぎます。何もインストールする必要はなく、qFT8 が権限を求めることもありません。アダプターはふつうのキーボードやマウスと同じです。USB 端子が 1 つしかなく、それをトランシーバーが使っているスマートフォンでは、USB ハブか Bluetooth のアダプターを使ってください。
  2. CW の画面を開いてキーイングします。キーボードとして動作するアダプターは、下の既定の一覧にあるキーを送るものであれば、そのまま使えます（左右の Ctrl キーや [ と ] が一般的です）。オリジナルの VBand アダプターで動作を確認しています。
  3. 何も鳴らない場合は、アダプターが別のキーを送っています。設定 > CW > パドル入力を開き、左パドル（短点）の下のキーを追加を押してから、電鍵の短点側の接点を閉じます。続いて右パドル（長点）の下で、長点側の接点について同じことをします。
  4. マウスとして動作するアダプターには、画面上のパドルが必要です。マウスポインターを左パドルの上に置いたままキーイングします。ふつうのマウスでも同じです。

縦振り電鍵、パドル、バグキー

キーヤーモード（設定 > CW > キーヤー）で、何を使ってキーイングする場合でも、左右それぞれの側の働きが決まります:

  • 縦振り電鍵: 電鍵は 1 つで、短点も長点もすべて自分の手で作ります。キーイングできるのは左パドル側だけです。縦振り電鍵はアダプターの短点側の接点につなぐか、そのキーを左パドル（短点）の一覧に入れてください。画面上では、2 つのパドルが 1 つの電鍵になります。
  • Iambic A と Iambic B: レバーが 2 枚のパドル用です。左側で短点、右側で長点が出て、両方を押すと交互に出ます。Iambic A、1 本指と Iambic B、1 本指は画面用で、中央のゾーンが両方のパドルを押したものとして扱われます（その幅は中央ゾーン（1 本指モード）で決めます）。
  • Ultimatic: パドルと同じですが、両側を押しているときは、あとから押した側が優先されます。
  • Bug（半自動）: 短点側は短点を自動で出します。長点側は手動の電鍵で、押している間だけ鳴ります。
  • Cootie（サイドスワイパー）: 左右どちらの側も、同じ 1 つの手動の電鍵として働きます。

自分に合わせて設定する

すべて設定 > CWのパドル入力セクションにあります:

  • パドル: 以下すべてのメインのスイッチです。
  • 画面上のパドルとパドルの高さ: 本物の電鍵だけを使うときはパドルを隠してウォーターフォールを広くでき、指で操作しやすいように高くすることもできます。マウスで使うには、パドルを表示しておく必要があります。
  • マウスボタン: パドルをクリックしても何も起きないようにしたいときは、オフにします。
  • キーボードのキーと外部アダプター (USB / Bluetooth): どれでキーイングできるかを決めます。Android とパソコンの違いは下を参照してください。
  • キー割り当て: 既定は上の表のとおりです。その下に左パドル（短点）と右パドル（長点）の 2 つの一覧があります。キーを追加を押すと、キーが押される（または電鍵の接点が閉じられる）のを待ち、そのキーを追加します。キーの横のごみ箱を押すと、そのキーが外れます。最初に変更した時点で割り当てはカスタムに切り替わり、その内容は既定の一覧のコピーから始まります。既定に戻しても、自分で作った一覧は消えません。使えるのは、英字、数字、F1 から F12、矢印キー、Ctrl、Shift、Alt、テンキー、Space、Enter、Tab、および一般的な記号のキーです。1 つのキーは、どちらか一方のパドルにしか割り当てられません。

キーヤーセクションには、さらに 2 つの項目があります。パドルを左右反転は、すべての入力元について短点と長点をまとめて入れ替えます（配線が逆のパドルや、左利きの方のために）。キーヤーモードは上で説明したとおりです。ページの最後にあるデフォルトにリセットは、キーの一覧を含め、CW のすべての設定を元に戻します。

Android とパソコン

  • Android では、スイッチが 2 つあります。キーボードのキーは端末自身のキーボード、外部アダプター (USB / Bluetooth)は接続またはペアリングしたすべてのキーボードとアダプターです。Android 10 より前では、物理キーボードはすべて外部として扱われます。USB または Bluetooth のマウスは、パソコンと同じようにパドルの上で使えます。
  • パソコンでは、アダプターはもう 1 台のキーボードにすぎないので、両方をまとめたキーボードのキーというスイッチが 1 つあるだけです。画面上のパドルはマウスで押します。キーが働くのは、CW の画面がある qFT8 のウィンドウがアクティブで、ダイアログが開いていないときだけです。

うまくいかないとき

  • 短点と長点が逆になる: パドルを左右反転にチェックを入れます。マウスの場合は、ポインターが右パドルではなく左パドルの上にあることを確認してください。
  • キーイングしても何も起きない: CW の画面が表示されていること、パドルと使っている入力元のスイッチがオンであること、AUTO がオフであること（オンの間は画面に手動で送信するには AUTO を無効にしてくださいと表示されます）を確認してください。パソコンでは、先に qFT8 のウィンドウをクリックします。次に、使っているキーが一覧にあるかを確かめます。キーを追加を押してキーイングしてください。ダイアログが反応しない場合は、アダプターが使えないキーを送っているか、接続されていません。
  • モールスは聞こえるのに無線機が送信しない: 赤い行に送信するには TX ON を押してくださいと表示されています。これは練習の状態です。
  • 縦振り電鍵 のモードで縦振り電鍵が働かない: 右パドル側につながっています。左パドル側に移してください（上を参照）。
  • キーイングすると、送信されずに入力欄に文字が入ってしまう: テキスト入力欄が開いている間は、Ctrl キーと F1 / F2 だけがパドルになります。コールサインを入力していてモールスが送信されることがないようにするためです。入力欄を閉じるか、アダプターにこれらのキーのどれかを割り当ててください。
  • キーイングすると別のプログラムに文字が入ってしまう: パソコンでは、キーはアクティブなウィンドウに送られます。qFT8 をクリックしてください。
  • 電鍵を押し続けていると音が止まる: 10 秒間押し続けた電鍵は解放され、キーが長く押されすぎたため解放しましたという通知が出ます。

メモリー、マクロ、略符号

メッセージは 設定 > CW > メモリーで編集します（メモリーを追加 を押すか、変更したいものをタップします）。メッセージには 2 種類の特別な語を使えます:

  • 角かっこで囲んだマクロは、メッセージの送信時に置き換えられます。[MYCALL] は自局のコールサイン、[TARGET] は「ターゲット」欄のコールサイン、[RST] は送るレポート、[NAME] は自分の名前、[QTH] は自局の場所、[EXCH] はコンテストナンバー、[MYPOTA] は開いているアクティベーションの公園または山頂です。エディターにはそれぞれのボタンがあり、メッセージは送信されるとおりの形で表示されます。
  • 山かっこで囲んだ略符号は、間隔を空けずに 1 文字として送信されます: <BK>、<SK>、<KN>、<AR>。

レポート、名前、場所、コンテストナンバーは、同じ設定ページで一度入力しておきます。これらのどれかを必要とする定型文は、入力するまで薄く表示され、タップすると入力する場所に移動します。POTA または SOTA のアクティベーションが開いている間は、最初のメモリーとして CQ POTA のメッセージが用意されます。

受信する

デコードは自動で行われ、局ごとの速度に追従します。下部バーのデコーダー行に文字が表示されるのは、フィルター内にいる局です。別の信号を追いかけたいときは、受信バーをその信号に移動します（その周波数ですでに受信していた内容がすぐに表示されます）。フィルター内に 2 局いるときは、下部バーにその旨が表示されます。受信信号は、選択したモニターの音程でスピーカーから再生されます。これは自分のサイドトーンと同じ音程なので、サイドトーンと同じ高さに聞こえる局は、ちょうど自分の周波数にいることになります。

設定 > CW には、このほかトーン（サイドトーンの鳴り方: 音程、音量、なめらかな、または鋭い立ち上がり、トーンまたはサウンダーのクリック音）、デコードと表示（自動デコード、ウォーターフォール上のすべての信号の文字を表示するマルチデコーダー、横向きのスペクトログラム、モードに入るときのフィルター）、モニター（スピーカー）、略符号と記号があります。

CW での AUTO

ペイン左上の AUTO ボタンを使うと、qFT8 が CW の QSO を最初から最後まで行います。このモードに入るたびにオフになっています。タップするとオンになり（緑色になります）、もう一度タップするとオフになります。送信するのは TX が ON の間だけです。AUTO が自分から送信を有効にすることはありません。

AUTO がオンで、TX が ON の間、qFT8 は次のように動作します:

  • 周波数が空いていれば CQ を出し、聞こえた CQ には応答します。
  • レポート、名前、場所を交換し、挨拶をして終わり、QSO をログに記録します。
  • 受信できなかったコールサインやレポートは聞き直し、再送やゆっくり送ってほしいという要求にも応えます。
  • 設定した WPM より速く送ることはなく、相手局の速度まで落とします。
  • 周波数が動く局を追いかけ、その日すでに交信した局は呼ばず、他局の QSO にかぶせて送信を始めることもありません。
  • 完了できなかった QSO をログに記録することはありません。

AUTO がオンの間はパドルが無効になり、手動で送信するには AUTO を無効にしてください という行が表示されます。停止 を押しても AUTO はオフになります。まったく使わない場合は、設定 > CW でAUTO モードを表示をオフにすると、ボタンが表示されなくなります。

RTTY

RTTY（ラジオテレタイプ）は、交互に切り替わる 2 つのトーンで文字を送ります。qFT8 では CW と同じ画面を使いますが、パドルはありません。通過帯域内のすべての RTTY 信号が、それぞれの速度とシフトでデコードされ、ウォーターフォール上の軌跡に沿って書き出されます。

RTTY 画面の各部の詳細は次のとおりです:

  1. ターゲット と ナンバー: 交信している相手局のコールサインと、コンテストナンバー。メッセージの [TARGET] と [EXCH] に入ります。
  2. BAUD: 速度。45.45（一般的な値）、50、75 のいずれかです。タップするたびに次の値に切り替わります。
  3. SHIFT: 2 つのトーンの間隔。170 Hz（一般的な値）、200、425、850 Hz のいずれかです。
  4. REV: 2 つのトーンを入れ替えます。逆向きに送ってくる局に使います。
  5. FILTER と NR: 受信フィルターとノイズ低減。
  6. メモリー: CW と同じマクロを使った定型文。タップすると送信されます。空の項目があるメッセージは薄く表示されます。キーボード（Android では 音声 も）は一覧の最後にあります。
  7. デコーダー行: 受信バーの下にいる局の文字は緑、自分が送る内容は赤で表示されます。
  8. 受信バーとそのラベル: ラベルには、バーの下にいる局のコールサイン、速度、シフトが表示されます。信号の近くをタップすると、バーがその中心に合います。
  9. タップして合わせる: バーの下にいる局の速度、シフト、トーンの順序が自分の設定と違うときは、オレンジ色の行でその旨が表示されます。タップすると qFT8 がその局の値を取り込むので、その局に応答できるようになります。
  10. そのほかの信号: それぞれの軌跡に沿って文字が書き出されます。50 Bd や 425 Hz のようなオレンジ色のタグは、自分の設定と異なる信号を示します。
  11. 周波数: RTTY では、ヘッダーにマーク周波数が表示されます。これは運用者どうしが伝え合う周波数であり、ログに書き込まれる周波数でもあります。

送信する

TX を有効にしてから、メモリーをタップするか、キーボード を開いて入力し、送信 を押します。文字が送出されている間は、停止 のある帯が表示されます。TX OFF のときは、同じ操作がプレビューになります。メッセージは自分のスピーカーで再生されて赤で表示され、電波は出ません。RTTY の符号にない文字は省かれ、一覧で示されます。

RTTY はフルパワーの連続送信なので、無線機の連続送信時間の上限が適用されます。上限より長いメッセージは送信が始まらず、送信中に上限に達すると停止します。

設定 > RTTY

  • モデム: 速度、シフト、リバース、数字表（国際（ITA2） または 米国。5 つの記号が異なり、両局が同じものを使う必要があります）、そして受信時と送信時のスペースの後は文字に戻す（スペースの後は文字に戻るため、シフトを取りこぼしても崩れるのは多くて 1 語です）。気象局のように数字のグループを放送する局は、スペースのたびにシフトを送り直しません。受信時、スペースの後は文字に戻すがオンだと、こうした数字のグループが文字として表示されるので、読むときはオフにしてください。
  • 送信: 各送信の最初と最後での改行、送るものがない間のアイドル文字、一定の文字数ごとの自動改行。
  • デコードと表示、モニター（スピーカー）、メモリーとその値（レポート、名前、場所、コンテストナンバー）、デフォルトにリセット。

QSO ボタンで記録した QSO は、RTTY としてログに記録されます。RTTY に AUTO はありません。

設定 > JTTY

JTTY（モードセレクターの JTTY（実験的） の行）は、この同じパネルを JTTY モデムで使います。その設定には専用のページがあり、設定一覧で RTTY の隣にあります。パネルが JTTY で動いている間は、パネルの歯車ボタンでそのページが開きます。JTTY が使うものだけがあります：デコードと表示、モニター（スピーカー）、値付きの メモリー、そして デフォルトにリセット。RTTY の モデム と 送信 の設定は適用されません。JTTY を初めて使うとき、設定 > RTTY で変更した内容（メモリー、名前、場所など）を引き継ぎます。変更していなかったものは JTTY 独自の既定値から始まります（例えば、それぞれ JTTY メッセージ1つに収まる短いメモリー）。その後は、一方を変えても他方は変わりません。

SSTV（画像）

SSTV（スロースキャンテレビジョン）は、静止画を音に変えて 1 行ずつ、1～4 分かけて送ります。このモードにしている間、qFT8 は画像を自動で受信します。また、ギャラリーの画像に自局のコールサインを書き込んで送信できます。

下部バーのモードセレクターで SSTV を選びます。ペインの左半分が送信用、右半分が受信用です:

SSTV 画面の各部の詳細は次のとおりです:

  1. 送信: 画像を送信するモードとそのサイズ。モードは項目 12 で選びます。
  2. 読み込み: 「画像を選ぶ」（ギャラリーまたはファイルから）、「写真を撮る」（カメラ付きのスマートフォンやタブレットで）、「用意された画像」を選べます。「用意された画像」は、qFT8 がモードの大きさで描いた約 20 枚の絵で、あなたのコールサインが入っています（CQ カード、qFT8 のロゴ、風景、錯視、QSL カード、73 など）。ほかのアプリから qFT8 に画像を共有することもできます。別のモードを使用中の場合、qFT8 は SSTV に切り替える前に確認します。
  3. 送信する画像。送信されるとおりに表示されます。タップすると、モードの縦横比に合わせて調整できます。全体を表示する、切り抜く（ドラッグで移動、ピンチで拡大・縮小）、回転する、明るさとコントラストを調整する、といった操作ができます。
  4. 文字スタイル: 矢印で、コールサインを画像に書き込む方法を順に切り替えます（下部の帯、隅、太い縁取りなど、またはコールサインなし）。鉛筆ボタンで自由なテキストを追加できます。
  5. 取り除く は読み込んだ画像を取り除きます。送信 には送信にかかる秒数が表示され、送信中は残りの秒数が付いた 停止 に変わります。
  6. 赤い行: 画像を送信するには TX ON を押してください。その下の残りの場所には小さな画像が並びます。最近読み込んだ画像、続いて用意された画像です。1 回タップすると、その画像が送る画像として読み込まれます（送信 を押すまで送信されることはありません）。画像の縦横比がモードと違う場合は、先に調整の手順が開きます。
  7. 受信状態: 待受中、または 受信中 とともにモード、相手局の周波数のずれ、描画中の行が表示されます。
  8. 受信した画像。届くそばから描かれます。その下には時刻、モード、進み具合が表示され、画像が完成するとコールサイン欄が表示されます。
  9. 保存 は、画像を端末の画像フォルダーに保存します（画像がまだ届いている途中で押すと、受信が終わった時点で保存されます）。編集 は、受信した画像を補正します（コントラスト、明るさ、色、色合い、シャープネス、ノイズ除去）。受信したままの画像は必ず残るので、どの変更も元に戻せます。返信 は、受信した画像を送信用の画像として読み込み、自局のコールサインの横に相手局のコールサインを入れます。
  10. 保持している画像: 最近受信した画像。タップすると、もう一度表示されます。
  11. 歯車は 設定 > SSTV を開き、QSO はモードが SSTV のロガーを開きます。
  12. SSTV モードセレクター: Martin、Scottie、Robot、PD、Wraase、Pasokon の各モード。その横のメッセージ欄に、いま何が起きているかが表示されます（「待受中」、「受信中」、残り秒数付きの「送信中」）。
  13. SSTV の帯域: 画像は 1100～2300 Hz の間で送受信されます。聞こえた画像と送った画像には、それぞれウォーターフォール上にモード名付きの枠が表示されます。

画像を受信する

設定するものは何もありません。qFT8 は、送信ごとに開始信号からモードを判別し、画像が始まったあとで周波数を合わせた場合でも判別します（すでに逃した行は空のままになります）。周波数が少しずれて送られた画像や、タイミングが少しずれた局からの画像は、自動的にまっすぐに補正されます。2 つの局がはっきり離れた周波数で同時に送信した場合は、両方の画像を受信して保持します。ウォーターフォール上の枠をタップすると、表示する画像を選べます。

最近の画像はアプリが自動で保持します。受信した画像をすべて端末に自動保存をオンにすると、画像フォルダーにも書き込まれます。オフの場合は、必要な画像を自分で保存します。

誰の画像か: コールサイン欄

多くの局は、画像の前後にモールス符号で、または画像のあとの短いデータバーストで、自局を名乗ります。qFT8 はその両方を読み取り、画像の下の、時刻とモードの横にある欄にコールサインを書き込みます。何も聞こえなかったときは、欄に コールサイン不明 と表示されます。欄をタップすると、コールサインを自分で入力したり（画像に書かれていることがよくあります）、修正したりできます。入力した内容は、聞き取った内容を置き換えます。

保存した画像には、日付と時刻（UTC）、バンド、kHz 単位の周波数、モード、コールサインから成る名前が付きます。たとえば 2026-10-05_1431_20m_14230_M1_F4ABC.png で、コールサインがないときは ..._UNKNOWN.png になります。画像を保存したあとでコールサインが届いたり入力されたりした場合は、保存済みのファイルの名前が変更され、2 つ目のコピーは作られません。

画像を送信する

  1. 下部バーのセレクターでモードを選びます。ある局に応答するときは、その局が使ったモードを使います。よく使われるのは Robot 36、Martin 1、Scottie 1 です。
  2. 送信 の下にある小さな画像のどれかをタップするか、読み込み を押して画像を選び、求められたら縦横比を調整します。
  3. 矢印で、コールサインの入れ方を選びます。
  4. TX を有効にして 送信 を押します。

TX をオフにする、停止 を押す、バンドまたはモードを変える、のいずれかで、画像の送信はすぐに止まります。送信 を押したときに画像を受信中だった場合、qFT8 は受信をやめる前に確認します。

長いモードと小型の無線機: 1 枚の画像は、フルパワーでの 1 回の連続送信です。Robot 36 で約 40 秒、Martin 1 で 2 分、もっとも遅いモードでは 4 分を超えます。無線機の連続送信時間の上限より長いモードは、一覧でグレー表示になり、選ぶと理由が表示されます。QMX では、既定の 60 秒のままで短いモードが使えます。

設定 > SSTV

  • コールサインを CW で送出: オフ、画像の前（既定）、画像のあと、または両方。送るのはコールサインだけで、速度は 20 WPM です。その秒数は送信時間に含まれます。
  • 画像ごとに FSK ID を送出: 相手局のプログラムが自局のコールサインを読み取れるようにする、短いデータバーストです。
  • 文字スタイル、自動コントラスト、自動でシャープにする。
  • 受信した画像をすべて端末に自動保存と、アプリに保持する受信画像の数。

QMX または QMX+ で画像を送信するには、ファームウェア 1_02_000 以降が必要です。古いファームウェアでは、SSTV は受信専用になります。

機能の説明

特定のモードに結び付かない設定とツールです。デバイス設定にある無線機ごとの 2 つの設定、別の端末から qFT8 を操作するためのウェブページ、無線機を別の部屋に置いたままにできる bridge、そして画面の配置を説明します。

スペクトログラムのチューニングオフセット

設定 > デバイス設定のチューニング（この無線機）にあるスペクトログラムのチューニングオフセットは、スペクトログラムに表示される範囲を最大 300 Hz、下または上にずらします。既定値は QMX シリーズで −100 Hz、IC-7300 で −90 Hz、その他の無線機で −50 Hz です。設定した値（0 を含む）は無線機ごとに別々に保持されます。

ほとんどの無線機はオーディオのもっとも低い部分をカットするため、スペクトログラムの最初の数百ヘルツにある信号は弱いか、見えません。たとえばオフセットを −100 Hz にすると、qFT8 は無線機を 100 Hz 低く同調させ、オーディオを同じだけずらすので、こうした信号が無線機のよく聞こえる部分に移ります。

そのほかは何も変わりません。表示される周波数、各局のオフセット、スポット、送信周波数、ログは、これまでとまったく同じです。無線機本体の表示だけが、オフセットの分だけ違って見えます。オフセットはすべてのモードで有効で、CAT 接続が必要です。VOX やスピーカーを使う場合は何も起きません。

連続送信時間の上限

これは送信機を守るための安全設定です。小型の無線機は、休止をはさんだ短い送信を前提に作られています。FT8 の送信は 13 秒足らずで、そのあと少なくとも 15 秒は休みます。モードによっては、はるかに長い時間、休みなくフルパワーで無線機を送信状態にするものがあり、小型の無線機では終段アンプが過熱するおそれがあります。連続送信時間の上限は、qFT8 があなたの無線機を一度に送信状態にしておく最長の時間です。

設定 > デバイス設定のチューニング（この無線機）にあります。選択肢は 20、40、60、90、120、150 秒と上限なしです。qFT8 は各選択肢の下に、その選択肢で新たに使えるようになるものを表示するので、上限を上げると何が得られるかが分かります。この設定は無線機ごとに別々に保存されます。

無線機ごとの既定値

  • 60 秒: QRPLabs の QMX、QMX+、QDX と、(tr)uSDX。
  • 120 秒: Xiegu X6100 と X6200。
  • 上限なし: そのほかのすべての無線機と、VOX またはスピーカー経由で使う無線機（qFT8 にはそれがどの無線機か分からないため）。

これらの既定値は控えめに設定されています。ご自分の無線機、その出力設定、冷却の状態はあなたがご存じです。問題がなければ上限を変更してください。qFT8 が自分から上限を上げることはありません。

上限の働き

  • 長さが決まっていて、上限より長い送信は開始されません。 WSPR や長い SSTV モードで上限を上げるよう求められるのはこのためです。WSPR の送信は 111 秒続き、SSTV の画像の多くは 2 分以上かかります。そのようなモードを選んだとき、またはそのモードで TX ON を押したときは、必要な秒数と無線機の上限を知らせるメッセージが、設定を開くボタンとともに表示されます。上限がそのモードを許すようになるまで、送信は有効になりません。
  • 長さの決まっていない送信は、上限に達すると停止し、無線機は受信に戻ります。対象は TUNE、SSB（PTT ボタン、VOX、ボイスメモリー）、RTTY です。上限に達したことが通知で知らされます。
  • CW は制限されません: キーが押されているのは一部の時間だけだからです。

QMX と WSPR: QMX、QMX+、QDX で WSPR を使うには、上限を 60 秒から 120 秒に上げる必要があります。無線機の安全のため、qFT8 はこの変更を一度だけ手動で行うよう求めます。WSPR では無線機の出力を下げることを検討してください。もともと小電力で使うモードです。

リモートコントロール Webサーバー

qFT8 は HTTP サーバーを内蔵しており、同じネットワーク上の任意のウェブブラウザーからアプリの監視と操作ができます。リモート運用や、サブディスプレイとしての利用に特に便利です。

このページは見た目も操作もアプリそのものと同じで、ブラウザーのウィンドウがどんな大きさでも全体に広がります。横長のウィンドウでは、スペクトログラムが左、選択したペインが右に表示されます。縦に持ったスマートフォンのような縦長のウィンドウでは、スペクトログラムが上になります。下部のバーにはアプリと同じ操作部品が並びます。TX ボタン、メッセージ、シーケンス、モードとバンド、そしてステーション、QSO ログ、世界地図、設定のボタンです。ウォーターフォールは、アプリと同じラベル付きでリアルタイムに動きます。次は、縦長のウィンドウでのステーション表示です:

AUTO ボタン、条件のドロップダウン、コールサインを直接追加する + ボタン、そして手動で呼び出すための CALL ボタンが付いたステーションの一覧を使って運用できます。バーの右端にある小さなランプは、ページが qFT8 に接続されている間、緑色に点灯します。

ネットワークと接続

サーバーは、スマートフォンまたはパソコン上で特定の TCP ポート（既定は 13497）を開きます。アクセスするには、端末どうしがネットワーク上で互いに「見える」必要があります:

  • ローカルネットワーク: qFT8 を動かしているスマートフォンまたはパソコンと、操作する側の端末（パソコン、タブレット、スマートフォン）が、同じネットワーク上にある必要があります。
  • ルーターの設定: ルーターによっては、AP アイソレーション（クライアント分離）という機能が既定で有効になっています。端末どうしが通信するには、これを無効にする必要があります。
  • モバイルホットスポットを使う場合: 移動運用では、（インターネットにつながる）スマートフォンの 1 台で Wi-Fi ホットスポットを開き、qFT8 を動かすスマートフォンをその Wi-Fi ネットワークに接続できます。接続したら、qFT8 の設定でウェブサーバーをいったん閉じて開き直します。表示される IP アドレスに、ホットスポットを提供しているスマートフォンからアクセスできるようになります。
  • インターネット経由のアクセス: 自宅の外から（インターネット経由で）サーバーにアクセスするには、ルーターの設定でポートフォワーディング（内部の IP アドレスとポートを外部のものに対応づける設定）が必要です。5G/LTE 回線では、通信事業者の NAT の制限により、通常は使えません。

アクセスレベル

リモートのセキュリティレベルは、設定のペインで選べます:

  • 読み取り専用: リアルタイムのスペクトログラム、活動中の局、QSO ログを見ることができます。操作は一切できません。
  • 読み取りおよび送信停止: 主に安全のためのモードです。すべてのデータを見ることができ、緊急時に送信機を無効にする（TX を止める）ことはできますが、TX の開始や設定の変更はできません。
  • フルコントロール: アプリのすべての操作を許可し、対話的な機能をすべて使えるようにします。

セキュリティ上の注意: あなたのネットワーク、IP アドレス、ポートにアクセスできる人は誰でも、設定したレベルの操作ができます。フルコントロールに設定していると、あなたの局を使って送信を始められてしまうおそれがあります。

できること

フルコントロールモードでは、ウェブ画面でアプリの画面とほぼ同じことができます:

  • 運用モード: AUTO と手動の CALL モードを切り替えます。
  • 方針: AUTO の条件（誰でも、DXCC、グリッド など）と検索の制約を変更します。
  • 送信: TX を手動で開始・停止し、送る TX メッセージを選び、FT8 のシーケンス（0/1）を変更します。
  • 周波数とバンド: ウェブ上のスペクトログラムをタップして周波数オフセットを動かしたり、使用する無線バンドを変更したりします。

SSB、CW、RTTY、SSTV は、qFT8 本体で操作します。アプリがこれらのいずれかのモードになっている間、ウェブページにはウォーターフォールとアプリが送信中かどうかが表示されますが、ページからは送信しません。もう一度ページから運用するには、ページでデジタルモードを選びます。

無線機の連続送信時間の上限は、アプリとまったく同じようにページにも適用されます。上限のために TX がオフのままになったとき（たとえば上限 60 秒での WSPR）や、TUNE が停止したときは、ページに理由を示す通知が数秒間表示されるので、反応しないボタンの前で戸惑うことはありません。上限そのものは、アプリでしか変更できません。

注: ウェブ画面は、RF の回り込みでスマートフォンの画面の反応が鈍くなったときでも操作できるように設計されており、頼れる代替の操作手段になります。

注: バックグラウンドで動作する設定が有効であれば、ウェブサーバーは画面がオフのときも動作します（既定では、qFT8 がトランシーバーに接続されている間はバックグラウンドで動作を続けます）。

qFT8 bridge

qFT8 bridge を使うと、無線機をある場所に置いたまま、別の場所から運用できます。無線機のそばにある端末（これが bridge です）が、無線機のコマンドと音声を自宅のネットワーク経由で別の端末の qFT8 に渡します。それ以外はすべてその qFT8 が行います。デコードもログも、何を送信するかの判断もです。qFT8 から見ると、無線機は USB で直接つないだときと同じように動作します。

無線機がアンテナの近く（屋根裏、ガレージ、庭の物置など）にあって、もっと快適な場所から運用したいときに使います。また、無線機のそばの端末には無線機の面倒だけを見させたいとき、たとえば Raspberry Pi のような小型コンピューターや、古いスマートフォンやタブレットを使う場合にも便利です。

これは リモートコントロール Webサーバーとは別のものです。そちらでは qFT8 が無線機のそばで動き、あなたはブラウザーからそれを見ます。bridge では、qFT8 は目の前の端末で動き、無線機だけが別の場所にあります。

必要なもの

  • 無線機のそばに置く端末。無線機はいつもどおり USB でこれにつなぎます。Windows、 macOS、Linux のコンピューター（Raspberry Pi で十分です）、または Android のスマートフォンやタブレットです。これが bridge になります。
  • 運用に使う端末の qFT8。パソコン版でも Android アプリでもかまいません。どれでもどの bridge でも使えます。スマートフォンからコンピューターのそばの無線機を、コンピューターからスマートフォンのそばの無線機を操作する、といった組み合わせが自由にできます。
  • 両方が同じローカルネットワークにあること。 ネットワークケーブルも Wi-Fi と同じように使え、より安定します。できれば少なくとも bridge はケーブルでつないでください。スマートフォンやタブレットは Wi-Fi を使い、モバイルデータ通信は決して使いません。
  • bridge のパスワード。 bridge がパスワードを作って表示します。

bridge の準備

bridge を動かす方法は 2 つあります。どちらか 1 つを選んでください。

1. qFT8 の設定から（パソコン版または Android アプリ）。無線機のそばの端末で設定 > qFT8 BRIDGE を開き、qFT8 bridge として動作するポートにチェックを入れます。ほかのプログラムが使っていない限り、ポートはそのままにしておきます。

パスワードには、もう一方の端末で必要になるパスワードが表示されます。新しいパスワードで別のパスワードを作ります。パスワード自体をタップすると、自分で決めたパスワード（7 文字以上）を入力できます。

bridge として動いている間、その端末の qFT8 はほかに何もしません。TXはオフになり、その端末自身による無線機の使用は止まり、画面にはqFT8 は bridge モードで動作中と、もう一方の端末に入力するアドレスとパスワード、そして無線機を使っている相手（誰も接続していません、または端末の名前）だけが表示されます。Android では画面がオフでも bridge は動き続け、通知でそれがわかります。スマートフォンやタブレットは充電器につないだままにしてください。

BRIDGE モードをオフにするは、もう一方の端末がすぐに無線機を使えなくなるため、まず確認を求めます。その後 qFT8 を元の状態に戻します。TX はオフのままです。 bridge として動いている間に qFT8 を閉じると、次回も bridge として起動します。

2. コマンドラインから（コンピューターのみ）。ほかの用途のないコンピューター向けで、Raspberry Pi や画面のないサーバーでも使えます。qFT8 を --bridge 付きで起動します。するとウィンドウなしで bridge としてだけ動き、qFT8 のほかの部分（設定、デコード）は何も読み込まないため、メモリーをほとんど使いません。そのコンピューター用にダウンロードした qFT8 を、ターミナルから使います。

  • Windows：qFT8 のフォルダーでコマンドプロンプトを開き、qFT8.exe --bridge --tx-volume 70 と入力します。"OpenJDK Platform binary" をネットワークで許可するか Windows に聞かれたら、許可してください。
  • macOS：ターミナルで /Applications/qFT8.app/Contents/MacOS/qFT8 --bridge --tx-volume 70 と入力します。初回は macOS がマイクへのアクセスを求めます。許可してください。無線機の音声はこの方法で読み取ります。
  • Linux：qFT8 のフォルダーで ./qFT8 --bridge --tx-volume 70 と入力します。
  • Java 21 以降が入っている任意のコンピューター（たとえばシステムの Java を使う Raspberry Pi）：ダウンロード版 qFT8 の .jar はどのシステムでも動きます。java -jar、.jar ファイルの名前、--bridge の順に入力します。Windows、macOS、Linux（PC と ARM ボード、32 ビットと 64 ビット）でシリアルポートを使うのに必要なものはすべて含まれています。

初回起動時にターミナルにパスワードが表示され、次回以降もそのパスワードが使われます。ターミナルは開いたままにしてください。ターミナルが開いている間だけ bridge が動きます。Ctrl+C またはターミナルを閉じると bridge が止まり、無線機は受信に戻ります。

--bridge のあとに付けられる便利なオプション:

  • --tx-volume N: 必須: 送信時にブリッジが無線機のサウンドデバイスに設定する音量(1〜100 %)。qFT8 自身の TX 音量設定と同じです(既定 70、QRP Labs の無線機は 100)。音の大きさだけで、無線機の出力は決して変更しません。
  • --password TEXT：作られたパスワードの代わりに自分のパスワードを使います。
  • --show-password：保存されているパスワードをもう一度表示します。
  • --new-password：新しいパスワードを作ります。
  • --name TEXT：ほかの端末の一覧に表示される名前（指定しなければ "qFT8 bridge"）。 bridge が複数あるときに便利です。
  • --only TEXT：名前の一部で指定した、無線機のシリアルポートとサウンドデバイスだけを共有します（たとえば --only QMX）。コンピューターのほかのものは何も提供しません。

そのほかのオプションは --bridge --help で一覧できます。

qFT8 から接続する

運用に使う端末で 設定 > デバイス設定 を開き、いちばん上にあるqFT8 bridge 経由で接続 にチェックを入れます。次の行が現れます。

  • 方式：qFT8 bridge。
  • Bridge：qFT8 がネットワーク上で見つけた bridge の一覧を開きます。自分の bridge を選んでください。もう一度検索でもう一度探します。一覧にない場合はアドレスを入力を選び、bridge に表示されているアドレスを入力します。
  • パスワード：bridge に表示されているパスワードです。
  • 接続：横の枠が緑色になり、bridge の名前のあとにに接続しましたと表示されます。
  • bridge 側の無線機ポート、bridge 側のサウンドデバイス（受信）、bridge 側のサウンドデバイス（送信）：bridge 側で無線機がつながっている先です。AUTO で自動的に見つかります。bridge に複数ある場合だけ手動で選んでください。bridge のコンピューター上の専用プログラム経由で使う無線機（仮想シリアルポートと仮想オーディオケーブル）は、AUTO が認識できないポートを使います。ポートを手動で選び、2 つのサウンドデバイスがどちらもそのケーブルのものであることを確認してください。

ここから先は USB でつないだ無線機と同じです。qFT8 は無線機を認識し、周波数を読み取り、受信と送信を行います。qFT8 は bridge とそのパスワードを覚えており、設定をエクスポートすればほかの端末にも引き継がれます。チェックが入っている間は、運用に使う端末に直接つないだ無線機は使われません。そちらに戻すには qFT8 bridge 経由で接続 のチェックを外します。再起動は不要です。

スマートフォンやタブレットが Wi-Fi ネットワークにつながっていないときは、状態欄にWi-Fi がありません。この端末を bridge と同じネットワークに接続してください。と表示されます。bridge はそのネットワーク内でしか探しません。

リンクの表示

bridge のデバイスの下に、リンクの状態を示す 1 行が表示されます。たとえば遅延 120 ms（自動調整）。リンク：安定（ジッター 3.0 ms）。

  • 遅延：ネットワークは音声を完全に均等には届けないため、音声は再生前に少しの間ためておき、そのむらをならします。設定するものはありません。遅延は qFT8 と bridge が自分で決め、音声が遅れて届くと大きくし、しばらくリンクが安定していればまた小さくします。デジタルモードのタイミングには影響しません。送信は時間どおりに始まり、受信した信号は無線機がそれを受けた時刻に合わせて扱われます。
  • リンク：安定：問題ありません。
  • リンク：不安定：音声の届き方にむらがあります。遅延がそれを吸収するので、この状態が続かない限り何もする必要はありません。
  • 赤色で bridge へのリンクで送信音声が失われています：送信の一部が時間内に無線機に届きませんでした。遅延はすぐに引き上げられます。何度も起こる場合はトラブルシューティングを参照してください。
  • 赤色で bridge へのリンクが追いつきません：最大の遅延でも足りず、送信音声が途切れます。トラブルシューティングを参照してください。

接続した直後は まだ測定されていません。 と表示されます。

送信の安全

  • TX をオンにできるのはあなただけです。目の前の qFT8 の TX ボタンで行います。bridge が自分から送信を始めることはありません。
  • リンクが切れた場合（Wi-Fi がなくなる、端末がスリープする、qFT8 が閉じられるなど）、bridge は 1、2 秒以内に自分で無線機を受信に戻します。qFT8 は送信中のものを止め、TX をオフにし、接続が切れました。再接続中...のように理由を示す赤いカードを表示します。再接続は自動で行われます。10 秒以内にリンクが戻り、TX がオンだった場合は、qFT8 が元どおり 1 回だけオンに戻します。それより長く切れた場合は、もう一度押すまでオフのままです。
  • 無線機の連続送信時間の上限は bridge でも守られます。
  • どちらの方法で bridge を止めても、無線機は受信に戻ります。

セキュリティ上の注意: パスワードが守るのは無線機の操作です。パスワードがなければ誰も bridge を使えず、パスワード自体がネットワーク上に送られることもありません。ただし、リンクの内容が秘密になるわけではありません。音声と無線機のコマンドは暗号化されていません。bridge は自宅のネットワーク内だけで使い、インターネットに公開しないでください。

制限

  • ローカルネットワークのみ。 bridge はインターネット越しに使うようには作られていません。 自宅ネットワークの通信をトンネル経由にする VPN は bridge も見えなくします。両方の端末で VPN をオフにするか、VPN 側でローカルネットワークへのアクセスを許可してください。
  • 一度に 1 台の端末だけ。 2 台目の端末が接続すると、そちらが引き継ぎます。 1 台目には 別のデバイスが bridge を引き継ぎました。取り戻すには「接続」を押してください。 と表示されます。
  • すべてのモードが bridge 経由で動作します。受信も送信もできます: FT8、FT4、FT2、JS8、WSPR、LQ8、SSB、CW、RTTY、SSTV、TUNE。スピーカーとマイクは目の前の端末のものが使われ、ネットワークを通るのは無線機の音声だけです。
  • コマンドではなく制御線（RTS または DTR）で送信に切り替わる無線機も、bridge 経由で送信に切り替えられます。

qFT8log

qFT8log は、複数の qFT8 のログを自分のネットワーク経由でまとめます。1 台の qFT8 が qFT8log サーバーになり、ほかの qFT8 は自分が行ったすべての QSO をそこへ送ります。サーバーはそれらを 自分のログ（QSO リスト、地図、統計）に追加し、サーバーに設定されたサービス、たとえば QRZ や LoTW へ転送します。 その後に QSO に起きること、つまり確認や修正は、両者がつながっている間、その QSO を行った qFT8 に戻ります。

どの qFT8 も、サーバーとクライアントの両方になれます。コンピューター用プログラム、Android アプリ、iPhone アプリのいずれでも同じです。 Android では、バックグラウンドで実行がオンのとき、サーバーはバックグラウンドで動き続けます。 iPhone では、アプリを開いている間だけ動作します。

サーバーの設定

  1. QSO を集めたい qFT8 で設定を開き、 qFT8 サーバーへ進んでqFT8log サーバーを開きます。
  2. パスワードを入力します。 qFT8 bridge と同じ種類のパスワードを使ってください。7 文字以上です。
  3. ほかのものが使っていなければポートは 13510 のままにして、サーバーをオンにします。ページにはサーバーのアドレスと、 接続している qFT8 が表示されます。ポートを変更すると、すぐに反映されます。
  4. 同じアドレスをブラウザーで開き（たとえば http://192.168.1.20:13510/）、サーバーのパスワードを入力すると （パスワードは送信されません）、ログを読み取り専用で見られます。 ブラウザーでログを見るを参照してください。

クライアントの設定

  1. QSO を送信したい各 qFT8 で設定を開き、上部の qFT8log の横にある歯車を押します。
  2. 検索を押します。ネットワーク上の qFT8log サーバーが名前の一覧で表示されます。 1 つを選ぶか、サーバーのアドレスとポートを自分で入力します。
  3. サーバーのパスワードを入力し、検証を押します。サーバーが受け付けたら、 設定の上部で qFT8log にチェックを入れます。

以降、クライアントは起動するたびに自動的に接続し、ネットワークやサーバーが復旧したときも自動的に再接続します。 サーバーに届かない間に行った QSO はログの中で待機し（qFT8log に未アップロードとして表示されます）、 接続が戻りしだい、再起動後でも送信されます。クライアントがサーバーに届かないときは、設定の qFT8log の行が赤くなり、(日時) から接続できませんと表示されます。

qFT8log では、ここにアップロード済みならQSOをアップロード済みとみなすはデフォルトでオフです。 QSO の送り先がサーバーである場合はオンにしてください。サーバーが QSO を受け取りしだい、QSO の「アップロード待ち」の印が消えます。

送られるもの

  • 新しい QSO：クライアントからサーバーへ。qFT8 が保持するすべてのフィールドを含みます。 レポート、グリッド、公園と山頂、機材、コメント、そして QSO がすでに QRZ、LoTW、その他のサービスにアップロードされたか、確認されたか（LoTW から取り込んだ QSO は確認済みのままです）です。
  • 確認：双方向で、届きしだい送られます。サーバーが LoTW から受け取った確認は、その QSO を行った クライアントに表示され、逆も同じです。
  • QSO エディターで行った修正：双方向です。同じ QSO が両側で変更された場合は、あとの変更が優先されます。
  • 削除は伝わりません。 QSOを削除すると、その qFT8 でだけ削除されます。ほかの qFT8 はそのまま残します。各 qFT8 は自分で削除したQSOを覚えていて、インポートでもライブ同期でも、他の qFT8 から取り戻すことはありません。

サーバーはすべてのモード、すべてのコールサインの QSO を受け付けます。ここは集める場所であり、何を表示するかはログのフィルターが決めます。 サーバーがすでに持っている QSO（同じコール、時刻、バンド、モード）は、持っているものに統合され、二重に追加されることはなく、 再び転送されることもありません。

サーバーからのインポートとライブ同期

クライアントは自分のQSOだけを送ります。サーバーのログもクライアントに取り込む方法が2つあります。

  • クライアントの qFT8log ページにあるサーバーからQSOをインポートは、開始日、終了日、バンド、コールサインの先頭の範囲内にあるサーバーのすべてのQSOを、全モードについて1回だけコピーします。自分以外のコールサインで行ったQSOは、現在のコールサイン以外のQSOをインポートするにチェックを入れない限りスキップされます。設定の上部で qFT8log にチェックが入っていなくても使えます。その場合、インポートは自分のためだけに接続し、何も送りません。
  • このサーバーとライブで同期(設定の上部で qFT8log にチェックが必要): サーバーのQSOがここに入り、以後、サーバーまたはそれに接続された他の qFT8 で記録、修正、確認されたQSOはすぐにここに表示され、自分のQSOはそちらに送られます。このボックスにチェックを入れた複数の qFT8 は、サーバーを通じて1つのログを共有し、チェーンの場合はチェーン内のすべてのサーバーを通じて共有します。
  • 接続が切れても何も失われません。接続が戻ると、再起動後も含めて、双方が追いつきます。
  • 修正の時刻はサーバーの時計に従うため、時計が狂った機器がすべての修正で勝ったり負けたりすることはありません。

チェーン：集約とバックアップ

サーバー自身が別のサーバーのクライアントになることもできるので、qFT8 は連結できます。QSO は、すでに通過した qFT8 には送り返されないため、 qFT8 が輪になっていても堂々巡りにはなりません。例を 2 つ挙げます。

  • アップロードを 1 か所で行う。スマートフォンとポータブルコンピューターは、シャックのコンピューターへ送ります。 QRZ と LoTW を設定するのはシャックのコンピューターだけです。そこがすべてをアップロードし、受け取った確認は それぞれの QSO を行った qFT8 に戻ります。
  • バックアップ。シャックのコンピューターは、すべてを別の qFT8、たとえばログを保管して世界地図を表示するだけの 古いタブレットにも送ります。バックアップ側で設定が必要なのは、そのサーバーだけです。

セキュリティ上の注意: パスワードはネットワーク上に送られません。2 台の qFT8 は互いにパスワードを知っていることを証明し、 それ以降のメッセージはすべて署名されるので、途中で改ざんや再送はできません。 QSO 自体は暗号化されていません。qFT8log は自分のネットワーク内だけで使い、そのポートをインターネットに公開しないでください。

制限

  • 自宅ネットワークのみ。qFT8 bridge と同じです。
  • 2 台の qFT8 は同じ qFT8log バージョンで動作している必要があります。サーバーは別のバージョンの クライアントを拒否し、クライアントの行にどちらを更新すべきかが表示されます。
  • 1 台のサーバーにつき、同時に最大 16 台のクライアントまでです。
  • サーバーが読み取れない QSO（たとえば日付のないもの）は、クライアント側で拒否されたものとして印が付き、 修正するまで再送されません。

qFT8log プロトコル（バージョン 2）

2 台の qFT8 が互いにやり取りする内容の完全な説明です。数値はすべてビッグエンディアン、テキストは UTF-8 です。

サーバーの検出

クライアントは、自分のネットワークのブロードキャストアドレスのポート 13510 に、UDP データグラムを 1 つ送ります。 "qFT8L?"（6 バイト）、API バージョン（2 バイト）、ランダムな id（8 バイト）です。各サーバーは 送信元に応答します。"qFT8L!"、API バージョン（2）、同じ id（8）、TCP ポート （2）、インスタンス id（16 桁の ASCII 16 進数）、名前の長さ（1）、名前（最大 64 バイト）です。この応答に秘密の情報は含まれません。

フレーム

TCP（既定ではポート 13510）では、すべてがフレームで送られます。種別（1 バイト）、本体の長さ（3 バイト）、本体（最大 16384 バイト）です。 最初の 4 種類は鍵ができる前に送られます。それ以外のフレームの本体はすべて封印されます。 8 バイトのカウンター、メッセージ、そして種別、カウンター、メッセージに対する HMAC-SHA256（その方向の鍵）の先頭 16 バイトです。 各方向は 0 から数え、フレームは次の番号をちょうど持っていなければなりません。変更されたフレーム、繰り返されたフレーム、 抜けたフレームがあると、接続は終了します。

ハンドシェイク

双方が k = PBKDF2-HMAC-SHA256(パスワード, ソルト, ラウンド数)（32 バイト）を知っています。サーバーが ソルトとラウンド数を選びます（200000。クライアントは 10000 未満または 5000000 超を拒否します）。トランスクリプト t は、HELLO の本体に、証明を除いた CHALLENGE の本体を続けたものです。 L = ASCII テキスト "qFT8 log v1 " とします。

  • サーバーの証明 = HMAC-SHA256(k, L + "server proof" + t)、クライアントの証明 = HMAC-SHA256(k, L + "client proof" + t)
  • クライアントからサーバーへの鍵 = HMAC-SHA256(k, L + "key client>server" + t)、サーバーからクライアントへの鍵 = HMAC-SHA256(k, L + "key server>client" + t)

クライアントはまずサーバーの証明を確認し、誤っていれば応答せずに接続を閉じます。そのため、パスワードから導かれたものは、 パスワードを知らないサーバーには一切渡りません。サーバーはクライアントの証明を確認します。誤っていると、そのアドレスは 1 秒間ロックアウトされ、 連続して誤るたびに倍になり、最大 60 秒までです。両方の乱数は接続ごとに新しくなるので、録音されたハンドシェイクは役に立ちません。 API バージョンは一致している必要があります。サーバーは別のバージョンを理由 1 で拒否し、クライアントは別のバージョンの CHALLENGE を拒否します。 サーバーは同時に 8 件のハンドシェイク、各ステップ 5 秒、16 台のクライアントを許可します。再接続したクライアントは、 古い接続を引き継ぎます。

レコード

QSO レコードは、qFT8 が保存するフィールド名を持つ JSON オブジェクトです（call、 qso_date（YYYYMMDD）、time_on（HHMM または HHMMSS）、band、 mode、submode、rst_sent、rst_rcvd、 gridsquare、freq、station_callsign、 my_gridsquare、comment、公園と山頂の参照、QRZ と LoTW の状態 app_qrzlog_logid、app_qrzlog_status、 app_lotw_qsl_rcvd、app_lotw_logid、app_lotw_upload_time、そして app_svc）。最大 16000 バイトです。call、qso_date、 time_on は必須で、どのモードもどのコールサインも受け付けられます。app_svc には、ほかのサービスの状態と、プロトコル自身の 3 つのレコードが、 id:key=value,... の形の部分として ; で区切って入ります。

  • q8u：id = QSO の uid（最初にそれを送った qFT8 が一度だけ作り、 すべての修正を通じて保たれます）、t = 内容が最後に修正された時刻（UTC ミリ秒、 ない場合は一度もなし）
  • q8v：id = QSO が通過したインスタンスの id を、ドットで区切ったもの （最大 32 個）
  • 送信側は自分の管理用情報を含めません。相手ごとのハッシュ、自分のアップロード状態、ローカルの作業フラグです。

ハッシュと統合

QSO のハッシュは、内容、修正時刻、アップロードと確認の状態（通過したインスタンスは含みません）の name=value 行に対する SHA-256 の先頭 8 バイトを、16 桁の 16 進数で表したものです。同じ QSO の 2 つのコピーは、 どこでも同じ方法で 1 つになります。あとで修正されたコピーの内容が全体として優先されます（時刻が同じ場合は、内容のハッシュが大きいほう）。 アップロードと確認の状態は前へ進むだけです（確認が取り消されることはありません）。 インスタンスは両方の和集合です。統合は順序によらず、2 回統合しても何も変わらないので、すべてのコピーが最終的に同じになります。

誰が何を送るか

  • クライアントは、サーバーをまだ通過していないすべての QSO と、両者が以前にやり取りしたもののうちハッシュがその後に変わったすべての QSO を、 サーバーに送ります。
  • サーバーは、両者がすでに交換済みでハッシュが変わったQSO(確認、修正)をクライアントに送ります。SUBSCRIBE の後は、購読の範囲内にある、両者がまだ交換しておらずクライアントを経由していないログのすべてのQSOもクライアントに送り、その後 BACKLOG_DONE を送ります。live では、接続が続く限り、後から受け取るすべてのQSOについて送信を続けます(クライアントは再接続のたびに購読し直します)。once は BACKLOG_DONE で終わり、off は購読を終了します。
  • 受信側は uid で自分のコピーを探し、なければコールサイン、日付、時刻 (HHMM)、バンド、モードで探します。サーバーは持っていないQSOを追加し、クライアントは自分が送った購読の範囲内でのみ追加します。どちらも、自分側で削除されたQSOは追加しません(どちらの場合も結果 3)。それ以外はコピーが統合されます。ACK には受信側のハッシュが入り、統合したコピーが送られたものと異なる場合は統合したレコードも入り、送信側がそれをさらに統合します。
  • 各側は、QSO ごと、相手ごとに、両者が最後に合意したハッシュを覚えておき、自分のコピーがそれと異なるときだけ再送します。 削除は送られません。
  • 応答待ちにできる PUT は最大 16 件です。サーバーは各クライアントから 1 秒あたり 100 件の PUT（バーストは 200 件）を受け付け、 それを超えると NACK 2 で応答します。読み取れないレコードが 50 件になると、接続を終了します。
  • 各側は、15 秒間何も送っていなければ PING を送り、45 秒間何も受信していなければ接続を終了します。クライアントは 1 秒、2 秒、4 秒 …… 最大 60 秒の間隔で再接続します。

バグ報告と新しいバージョン

問題を報告する

「設定」タブのいちばん下にある バグを報告 を押すと、カードが開きます。何が起きたかを記入し、返信が必要な場合はメールアドレスを入力します。送信 を押すと、記入した内容がアプリのログ（設定、無線機とオーディオの詳細、最近の動作）とともに送信されます。パスワード、API キー、証明書、QSO サービスのログイン情報が含まれることは決してありません。あとで問い合わせに使える QFT8-7K3P9 のような受付番号が表示されます。レポートサーバーに接続できない場合、qFT8 は代わりにメールでレポートを送ることを提案します。

「この件についてレポートを送信しますか？」

qFT8 は、一時的に応答しなくなったことや、お使いの端末でデコードに時間がかかりすぎていることに気づくと、それについてレポートを送るかどうかを尋ねる小さなカードを表示することがあります。カードには 送信、送信しない、今後表示しない があります。あなたがタップしない限り、何も送信されません。このカードが表示されるのは多くても 1 日 1 回で、今後表示しない を選ぶと 1 週間表示されなくなります。強制終了のあとは、次の起動時にクラッシュレポートを送るかどうかを尋ねます。

起動時に新しいバージョンを確認する

このチェックボックスをオンにすると（「設定」のメインページ、下のほう）、qFT8 は起動時に新しいバージョンを探し、あればダウンロードボタン付きの通知を表示します。自動で更新されることはありません。

匿名のパフォーマンス概要

匿名の日次パフォーマンス概要を送信する（「設定」のメインページ、「言語」のすぐ上）は、自分でオンにしない限りオフです。オンにすると、qFT8 はおよそ週に 1 回、お使いの端末でどのくらい速く動いているかの短い概要を送信します。内容は、起動時間、画面の滑らかさ、デコード時間、オーディオと無線機のタイミング、端末の機種と画面です。コールサイン、グリッド、ログ、設定、そのほか個人を特定できる情報が含まれることは決してありません。同じような端末で qFT8 を速くするのに役立ちます。

トラブルシューティング

スマートフォンやパソコンがトランシーバーを認識しない、または接続が切れる

これは、ほとんどの場合、ハードウェアの接続か電波の回り込みの問題です。USB 接続は、振動、ケーブルの品質、そして USB ポートに住みついた綿ぼこりの影響を受けやすいものです。Android では、端末で USB OTG が既定で無効になっていることも、よくある原因です（特に、qFT8 で信号は受信できるのに送信ができず、機種が完全に対応していて、デバイスのドロップダウンに表示され、AUTO モードで自動認識されているのに CAT コマンドが効かない場合は、これが原因である可能性が非常に高いです）。

対処法:

  • Android では、端末の設定で USB OTG を有効にします（端末によっては OTG が既定で無効になっており、詳細設定、システム設定、その他の設定の中にあることがあります）。
  • 品質の良い、短い USB ケーブルを使います（短いケーブルにするだけでかなり改善することがあります）。また、USB ポートが汚れておらず、しっかり差し込まれていることを確認します。
  • Linux で、無線機のポートを開く権限がないと qFT8 が表示した場合は、修正の提案を受け入れるか（アカウントがポートのグループに追加されます）、システム管理者に相談してください。
  • 問題が送信中にだけ起きる場合は、電波の回り込みが原因かもしれません。USB ケーブルにチョークやフェライトを付けると改善することがあります。機器によっては特定のバンドでだけ回り込みの影響を受けるので、別のバンドで送信してみるのも一つの方法です。

スマートフォンが満充電になるとトランシーバーが見えなくなる（Android）

これは、トランシーバーをつないだままスマートフォンを充電できるように、充電用の入力が付いた USB OTG アダプターで起こります。アダプターによっては、バッテリーが 100% になるとスマートフォンがトランシーバーとの USB 接続を切り、充電器を抜くまで接続が戻りません。このとき qFT8 はトランシーバーを未接続と表示し、オーディオも CAT も何も動作しません。

対処法: アダプターから充電器を抜く（トランシーバーが戻ってきます）、充電せずに運用する、別のアダプターやセルフパワーのハブを使う。

qFT8 bridge：「このネットワークに bridge が見つかりません」

qFT8 がネットワークに問い合わせましたが、どの bridge も応答しませんでした。よくある原因は、bridge が動いていない、2 台の端末が同じネットワークにない（ゲスト用 Wi-Fi は別のネットワークです）、または間にある何かが問い合わせを遮断している、のいずれかです。

対処法:

  • bridge が動いているか確かめます。ウィンドウが開いているか、その端末の qFT8 にqFT8 は bridge モードで動作中と表示されているかを見てください。そのあともう一度検索します。
  • アドレスを入力を選び、bridge に表示されているアドレスを入力します。検索で見つからない bridge でも、直接アドレスを指定すると応答することがよくあります。
  • bridge のコンピューターのファイアウォールで bridge を許可します。TCP と UDP のポート 13498、および UDP のポート 13499（検索に使うポート）です。
  • ルーターのAP Isolation（または Client Isolation）をオフにします。リモートコントロール Webサーバーの場合と同じです。
  • 両方の端末で VPN をオフにするか、VPN 側でローカルネットワークへのアクセスを許可します。すべての通信をトンネル経由にする VPN は、2 台を並べて置いていても bridge を見えなくします。

qFT8 bridge：「パスワードが違います」、または bridge が接続を拒否する

パスワードは bridge に表示されているとおり正確に入力する必要があります。bridge が作るパスワードは英小文字と数字だけでできており、見間違えやすい i、l、o、0、1 は使われません。続けて何度か間違えると、 bridge はその端末に次の試行まで待たせます（最大 1 分）。

対処法: bridge でパスワードをもう一度確認します。qFT8 の bridge モードの画面か、ダウンロード版 bridge を --show-password 付きで起動して確認できます。迷ったら新しいパスワードを作り（新しいパスワード、または --new-password）、それを入力してください。

qFT8 bridge：接続できたが、無線機が使えない、または音声が出ない

リンクは動いていますが、bridge が無線機のポートかサウンドデバイスを使えていません。枠には bridge の名前のあとに に接続しました と表示され、続けて「サウンドデバイスを開けませんでした」と出ることがあります。

対処法:

  • bridge 側の無線機ポートと両方のサウンドデバイスの行を、AUTO ではなく手動で選びます。
  • bridge の端末で無線機を使っているほかのプログラムを閉じます。bridge モードでない qFT8 も含みます。
  • macOS では、システム設定 > プライバシーとセキュリティ > マイク で bridge にマイクの使用を許可します。
  • Linux では、bridge を動かすアカウントがシリアルポート（通常は dialout グループに入っていること）とサウンドを使えることを確認します。
  • Android の bridge では、Android に聞かれたときに qFT8 による無線機の使用を許可します。スマートフォンに直接つないだ無線機の場合と同じです。

qFT8 bridge：「bridge へのリンクで送信音声が失われています」または「追いつきません」

2 台の端末の間のネットワークのむらが大きすぎて、送信音声が再生に間に合いません。遅延をまだ大きくできる間は、qFT8 は遅延を引き上げ、リンクで音声が失われていると表示します。最大の遅延でも足りなくなると、リンクが追いつかないと表示し、送信が途切れます。これはネットワークの問題で、無線機の問題ではありません。

対処法: Wi-Fi アクセスポイントに近づく、bridge（または両方の端末）をネットワークケーブルでつなぐ、ネットワークに負荷をかけているほかの通信を一時停止する。

トランシーバーからの信号ではなく、マイクの音を qFT8 が拾っている

Android では、スマートフォンがトランシーバーを外部オーディオソースとして認識できず、内蔵マイクを使っていることを示します。パソコンでは、設定のデバイス設定でどの入力が選ばれているかを確認し、トランシーバーのオーディオデバイスを選んでください。よくある原因は次のとおりです:

  • USB ケーブルがデータ通信に対応していない（充電専用ケーブル）。
  • USB アダプター（OTG）が故障しているか、対応していない（Android）。
  • ケーブルを逆向きに差し込んでいる（向きのあるケーブルがあります）。

対処法: 別の USB ケーブルや別のアダプターを使うか、ケーブルの向きを入れ替えます。

無線機のダイヤルが qFT8 の表示周波数と合わない

無線機自身の表示と qFT8 の表示が、数 Hz から最大で約 100 Hz ずれることがあります。たいていはスペクトログラムのチューニングオフセットによるもので、意図的な動作です。qFT8 は無線機をわずかに低くチューニングし、音声を同じ量だけずらすので、スペクトログラムの最下部にある信号が、無線機の低音域の不感帯から外れます。デコード結果、スポット、ログ、qFT8 が表示する周波数は、すべて本来の周波数のままです。

対処法: 故障ではないので、修正は不要です。既定値は無線機ごとに異なります（QMX シリーズは −100 Hz、IC-7300 は −90 Hz、その他の無線機は −50 Hz）。変更する場合や 0 にする場合は、設定 > デバイス設定 > チューニング（この無線機） > スペクトログラムのチューニングオフセット を開いてください（スペクトログラムのチューニングオフセット を参照）。

信号がまったく受信できず、ウォーターフォールが真っ黒

トランシーバーを接続していてもいなくてもウォーターフォールが真っ黒なままの場合は、qFT8 にオーディオへのアクセスに必要な権限がない可能性が高いです。

対処法: Android では、スマートフォンの設定 > アプリ > qFT8 > 権限を開き、qFT8 の使用中にマイク（または音声の録音）が許可されていることを確認します。または、qFT8 を完全にアンインストールしてから再インストールし、初回起動時にすべての権限の確認を許可します。macOS では、システム設定 > プライバシーとセキュリティ > マイクを開き、qFT8 を許可します。どのパソコンでも、デバイス設定で選ばれている入力を確認してください。

信号は見えているのに、メッセージがデコードされない

ウォーターフォールに縦の「くねくねした線」（FT8 の信号）が見えるのに、「ステーション」タブに文字が表示されない場合は、時計が同期していないのかもしれません。

対処法:

  • インターネットに接続できることを確認し、アプリを開き直して NTP同期 を実行させます。
  • インターネットが使えない場合は、GPS 同期を試します（Android）。
  • それでもうまくいかず、スペクトログラムにメッセージのトーンが見えている場合は、時刻と位置情報の設定メニューで「メッセージからの緊急同期」を実行します。
  • 無線機が実際に電波を受信していることを確認します。

ウォーターフォールにくねくねした縞がまったく現れない場合は、バンドが開けていないか、アンテナが外れているか調整されていないのかもしれません。

メッセージのデコードが遅すぎる

スマートフォン（または古いパソコン）のプロセッサーが遅く、メッセージのデコードが間に合わない可能性があります。

対処法: 設定で ディープデコード をオフにして、速いデコードに切り替えてください。デコードの開始時間を早めて（たとえば 13000ms に）デコードの余裕を増やすこともできますが、サイクルごとに遅れて届くメッセージを取りこぼす可能性があります。

QMX トランシーバーで 「SWR exceeded threshold — transmission stopped」 のエラーが出る

送信中に qFT8 に 0W と表示される場合、考えられる原因はいくつかあります:

1. SWR 保護

QMX の LCD の周波数の後ろに「S」が表示されている場合は、SWR 保護が働いています。アンテナが現在のバンドにきちんと調整されておらず、QMX が回路を守るために送信を止めたということです。

これとは別に、qFT8 にも、アプリの設定で変更できる独自の SWR しきい値があります。測定した SWR がこのしきい値を超えると、機器を守るために qFT8 が自動的に送信を止めます。

  • ファームウェア 1_04_004 以降: qFT8 がサイクルの終わりに SWR 保護を自動でリセットします。
  • ファームウェア 1_03_000 以降: QMX のメニューで "SWR Protection reset options" を Timer または TX->RX に設定できます。こうしておくと、トランシーバー本体に触れなくても qFT8 が運用を続けられます。
  • 旧ファームウェア: 1_03_000 より前の QMX ファームウェアでは、エラーを解除するために、トランシーバーを手動でリセットする（電源の入れ直し）か、QMX の TUNE メニューに入ってから出る必要があります。

注: QMX の出力が立ち上がる間の誤検出を避けるため、qFT8 は送信開始から 1 秒待ってから 0W かどうかを確認します。QMX が回復して出力が 1W を超えれば、問題の表示は自動的に消えます。

2. ファームウェアが出力の測定に対応していない

QMX に SWR 保護が働いている表示がなく、送信が正常に行われていると表示されている場合は、ファームウェアが古く、出力の測定に対応していないのかもしれません。QDX のような機種も出力の測定には対応していません。qFT8 は 0W をどう解釈すればよいか分からず、混乱します。

対処法: QMX のファームウェアが古い場合は、更新してください。QDX を使っている場合、これを回避する方法はありません。

3. オーディオ信号が QMX に届いていない

QMX の周波数の後ろに「S」のアイコンが表示されていない場合は、トランシーバーが qFT8 から適切なオーディオ信号を受け取れていないだけの可能性が高いです。音量が小さすぎる（信号が足りない）か、大きすぎる（クリッピングやひずみのために QMX が信号を受け付けない）かのどちらかです。

対処法: QMX の信号インジケーターを確認します。点が 1 つならオーディオなし、点が 2 つならオーディオはあるものの音量が足りません。FT8 の設定（デバイス設定のオーディオ設定）を開き、「無線機使用時にシステム音量を [X] に設定」の設定をいろいろな値（例: 70%、80%、90%）に変えて、お使いの端末に合うレベルを見つけてください。

4. アンテナチューナーでの調整時は SWR が低いのに、SWR 保護が働く

実際の送信中に、高い出力で SWR が一瞬だけ跳ね上がり、それで SWR 保護が働いているようです。扱いの難しいアンテナ（マグネチックループなど）、不良のケーブル、接触不良、またはセットアップの問題の兆候です。

対処法: コモンモード電流チョーク（フェライトビーズなど）を追加すると、コモンモード電流を減らせるはずです。

qFT8 の Android の通知は何ですか？（Android）

この通知があることで、アプリを最小化したり画面をオフにしたりしても、qFT8 はオーディオの処理と QSO の管理を続けられます。

  • 既定では、トランシーバーを接続すると自動的に表示されます。
  • qFT8 の設定で無効にできますが、その場合 qFT8 はバックグラウンドで動作しなくなります。
  • 通知の 停止 を押すと、qFT8 を完全に終了できます。

画面をオフにすると qFT8 が動作しなくなる（Android）

Android のメーカーによっては、非常に強力なバッテリー最適化を行っており、最初に権限を許可していても、バックグラウンドのアプリを終了させてしまうことがあります。

権限を許可したことをもう一度確認してください: スマートフォンの設定 > アプリ > qFT8 > バッテリーを開き、「制限なし」（または「最適化しない」）を選びます。

送信中にボタンの動作がおかしくなる、または画面が反応しなくなる

原因は高周波の回り込み（RFI）です。アンテナがスマートフォンやパソコンに近い場合や、ケーブルのシールドが不十分な場合、高周波エネルギーがタッチスクリーン、マウス、USB 接続に干渉することがあります。

  • ヒント: シールド付きの USB ケーブルを使うか、ケーブルにフェライトビーズを取り付けてください。

qFT8 の画面が、このマニュアルのスクリーンショットと違って見える

アプリのユーザーインターフェースはときどき更新されるため、スクリーンショットを撮ったあとで細かな見た目が変わっていることがあります。ただし、UI の大事な部分がまったく表示されない場合や、色が大きく変わって見える場合（黄色の進行バーやシーケンスセレクターなど）は、スマートフォンのシステムのダークモードが、アプリの配色を誤って上書きして崩している可能性があります。

対処法: システムのダークモードが原因の場合は、一時的に無効にするか、qFT8 を除外リストに追加すると、正しいデザインに戻ることがあります。

トランシーバーを接続しているのに qFT8 に「NO RADIO」と表示される

qFT8 をトランシーバーに接続するための権限を許可していないことが原因と考えられます。権限のダイアログの外側をタップしてしまい、ダイアログが閉じたときに起こることがあります。

対処法: トランシーバーをいったん外して接続し直すと、確認がもう一度表示されるはずです。今後この問題が起きないように、「Transceiver が接続されたら常に qFT8 を開く」のオプションにチェックを入れておくと便利です。

qFT8 の距離の表示がマイルだが、キロメートルにしたい（またはその逆）

これは、オペレーティングシステムのロケール（言語の選択）によるものです。

対処法: この設定を適切な国に切り替えると解決します（たとえばマイル表示なら English (United States)、キロメートル表示なら English (United Kingdom)）。

QMX で 10W を超えて送信すると、qFT8 に低い送信出力（例: 0.1W）が表示される

これは QMX のファームウェア（少なくとも 1.03.000 まで）の既知の不具合です。2x4 の改造をしていて（QMX+ など）、送信出力が 9.9W を超えると、無線機側の数値の表示が一巡してしまいます。たとえば 10.1W は、セカンダリーの CAT プロトコルを通じて、トランシーバーからアプリに 0.1W と報告されます。

対処法: アプリは受け取った値をそのまま表示しているため、qFT8 側での回避策はありません。この表示の誤りは無視してかまいません。または、トランシーバーのファームウェアでこの不具合が修正されるまで、出力を 10W 未満に下げておけば、正しい値が表示されます。

共有で ADIF ログを端末内のストレージにエクスポートできない（Android）

既定の 共有 の方法は、Android 標準の共有の仕組みを使ってログをエクスポートします。端末に組み込まれた共有メニューに、端末内のファイルシステムへ直接保存する選択肢が出ないことがあります。

対処法: 設定で、エクスポートの 方法 を ローカルに保存 に変更します。この方法では Android のファイル選択画面を使うので、共有メニューに頼らずに、ファイルを端末内のストレージに直接保存できます。

qFT8 が一部のメッセージをデコードできない

対処法: 設定でディープデコードを有効にします。ディープデコードは再帰的にデコードを行い、バンドが混んでいるときにより多くのメッセージをデコードできますが、その分処理能力を多く使います。また、非常に強い局の高調波（過大入力の信号が、より高いオーディオ周波数に残す読み取れない写し）を取り除き、その下にある弱い局を見つけます。スペクトログラムに注意してください。お使いの端末でディープデコードの時間が長すぎて（たとえば 1 秒を超えて）、アプリの判断が間に合わない場合は、ディープデコードを無効にしてください。

qFT8 が固まる、またはおかしな動作をする

これが送信中にだけ起きる場合は、前述の強い高周波の回り込みである可能性が高いです。それ以外のときに起きる場合は、「設定」タブのいちばん下までスクロールして バグを報告 を押すか（問題を報告するを参照）、「問題やバグを報告するには メールを送る」のリンクを使ってください。
