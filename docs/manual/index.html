What is qFT8?

qFT8 is an amateur radio app for Android phones and tablets and for Windows, macOS and Linux computers that decodes and transmits FT8, FT4, FT2, LQ8, JS8, or WSPR digital data messages using a transceiver. It also works voice (SSB), Morse code (CW), RTTY and pictures (SSTV) with the same transceiver and the same cable.

Both versions work the same way. Where they differ, this manual says so ("On Android ...", "On the computer ..."). The screenshots show the Android app, and "tap" means tapping the screen on Android or clicking with the mouse on the computer.

Although qFT8 features out-of-the-box (plug-and-play) support for the QMX and ICOM 7300, you may also use it with any transceiver by placing the phone or computer close to the speaker and microphone with VOX enabled, or using an audio link cable. You may also just try qFT8 without a transceiver: it transmits using the speaker and listens to signals using the microphone. Several phones or computers running qFT8 can contact each other via audio when they are close enough.

qFT8 is a free app and does not contain ads. The license for its source code will be decided when the source code is released (LICENSE).

Leave Settings > Device on AUTO: a supported radio connected by USB is recognized automatically. You can also pick your radio from that list yourself.

Note on External Interfaces (Digirig, generic USB-serial cables): Auto-detection (AUTO) is designed for transceivers with native USB controllers or model-branded cables. To use CAT control with radios connected via external interfaces (e.g., Lab599 TX-500), please select your transceiver model by hand in Settings > Device; its serial port and speed are set in Settings > DEVICE CONFIGURATION.

More devices are supported via VOX, which is a partial audio-only integration.

Note: For safety reasons, qFT8 does not allow changing the Tx power of the transceiver. Adjust power manually in your transceiver.

qFT8 on a computer (Windows, macOS, Linux)

qFT8 for the computer does the same job as qFT8 for Android: the same modes, the same AUTO and CALL operation, the same log and services. This section is for what is different when you use it on Windows, macOS or Linux: how to install it, how the window is arranged, the two volume sliders, how the sound devices and the radio are chosen, and how to use the mouse. The rest of this manual applies as it is; where a part is different on the computer it says so ("On the computer ...").

Install and first start

Download the file for your system from qft8.com. Every download holds one folder or app with the program, the license and this manual. Nothing else has to be installed: the Java runtime qFT8 needs is inside.

System Download You need
Windows .zip, 64-bit or 32-bit Windows 10 or newer. Use the 32-bit file only on a 32-bit Windows.
macOS .dmg, one file for every Mac (Apple Silicon and Intel) macOS 10.13 or newer
Linux .tar.gz: 64-bit PC, 32-bit PC, ARM 64-bit or ARM 32-bit (a Raspberry Pi) A desktop with a sound server (PulseAudio or PipeWire). Tested on recent Ubuntu, on X11 and on Wayland (through XWayland).
Any other computer .jar Java 21 or newer, installed by you

qFT8 needs a computer with at least 2 processor cores (4 are recommended) and room for a window of at least 960 x 560 pixels. On 2 cores it works, only more slowly: see Slow computers.

Windows

  1. Open the .zip and drag the qFT8 folder somewhere you keep programs, for example your Documents or Desktop folder. Do not run qFT8 from inside the zip.
  2. Open the folder and double-click qFT8.exe.
  3. Windows may show "Windows protected your PC" the first time. Press More info, then Run anyway. qFT8.exe is signed with the author's certificate; Windows learns to trust a new program slowly.
  4. If Windows asks whether to allow qFT8 (shown as "OpenJDK Platform binary") through the firewall, allow it only on a private network, and only if you use the web remote or the bridge.

macOS

  1. Open the .dmg and drag qFT8 onto the Applications shortcut in the same window. Then eject the .dmg.
  2. Start qFT8 from Applications. If you start it from inside the .dmg window, or from where the browser put it, qFT8 asks "Move qFT8 to Applications?": press MOVE (macOS may ask for your password, as the Finder does) or NOT NOW.
  3. macOS asks once whether qFT8 may use the microphone. Press Allow: this is how qFT8 hears the radio. If you missed or refused it, qFT8 shows a card saying it is waiting for microphone permission; grant it in System Settings > Privacy & Security > Microphone (macOS 13 and newer) or System Preferences > Security & Privacy > Privacy > Microphone (older macOS), and start qFT8 again.

Linux

  1. Unpack the .tar.gz (tar -xzf qFT8-*.tar.gz, or your file manager). It gives a qFT8 folder.
  2. Run ./qFT8 in that folder (double-click works if your file manager runs programs). The first start unpacks the program into ~/.cache/qft8, which takes a few seconds; a newer version replaces the older one there by itself.
  3. The radio's serial (CAT) port belongs to a group: dialout on Ubuntu, Debian and Fedora, uucp on Arch. Its USB sound card belongs to audio. If your account is not in the port's group, qFT8 says so in a card: FIX IT adds you to the group (it asks for your password) and restarts qFT8, so the change applies without logging out. If that does not work, TRY IN A TERMINAL and COPY COMMAND give you the command to run yourself; then log out and back in once.

First start

qFT8 asks for your callsign, as on Android (see Enter Callsign). Right after it, a card named Device configuration opens: choose the radio, then the sound devices connected to it. The waterfall under the input shows what the radio is sending: with the radio on, you should see noise or signals. You can open the same card at any time with the button right of the gear in the bottom bar, and the red No audio badge on the waterfall opens it too. See Sound devices and the radio's connection.

The screen layouts and the layout button

The button at the right end of the bottom bar is the layout button. Each click on it changes the layout to the next one: Floating, then Pinned, then All in one, then Floating again. Its picture shows the layout you are in now (a screen reader says its name, for example "Layout: Pinned"). qFT8 remembers the layout for the next start, and the size and place of every window in each layout separately.

  • All in one (the layout qFT8 starts in the first time). One window with four equal parts: the spectrogram top left, the Stations tab top right, the World Map bottom left and the QSO log bottom right, above the bottom bar. Settings is a tall column at the right of the same window; the gear button in the bottom bar shows or hides it, and so does the X in its heading. The bottom bar has no buttons for the four parts: they are always there.
  • Pinned (like the Android app). One window with the spectrogram on the left and the Stations tab on the right, above the bottom bar. Drag the thin divider between them to give one more room (the share is between 20 % and 80 %). The QSO log, World map and Settings buttons of the bottom bar open those three as separate windows, and press them again to close them.
  • Floating. The main window shrinks to just the bottom bar, and every pane is a window of its own that you place where you like, even on another screen: Spectrogram, Stations, QSO log, World map and Settings. The bottom bar then has one button for each of the five, to open and close them. Use it to spread qFT8 over two monitors, or to keep only the spectrogram and the bar on a small screen.

Changing the layout only rearranges the windows: nothing is lost, a transmission goes on and TX stays as it was. The World Map has a full screen button (top right of the map): it fills the screen until you press the button again or Esc.

Tip: The Android settings Orientation, Quadrants and App covers (see Screen layouts) do not exist on the computer: the layout button and the size of the window replace them.

Working with the windows

  • One program in the taskbar. Whatever the layout, qFT8 has one entry in the taskbar, the Dock or Alt-Tab: the main window. The pane windows of the Floating and Pinned layouts do not get their own. (On Linux this is tested with GNOME, KDE Plasma, Xfce, Cinnamon, MATE and LXQt.)
  • Pane windows have their own small frame (the same on every system): a thin edge that resizes the window from any side or corner, a title strip with the pane's name that you drag to move the window, and an X that closes the pane like its bottom-bar button does. Esc closes a pane window too, while it is the active window.
  • The main window can be resized and maximized as usual. In the All in one layout it cannot be made smaller than 960 x 560 pixels, and it opens at 85 % of the screen the first time.
  • Settings keeps one width. The Settings window (and column) keeps the width the Android settings page has, so every row fits; you can change its height.
  • Size of everything. Settings > APPLICATION has the two size sliders (User interface and font scale and User interface component (no font) scale) as on Android. On high-resolution screens (a Retina Mac, Windows at 125 % to 200 %) qFT8 follows the system's scale.

Volumes: the device and the tone

Two small sliders sit in the bottom bar, between the Device configuration button and the layout button, one above the other. They control two different things, and both matter for transmitting.

  • Top slider, with the speaker picture: the device volume. It is the volume of the sound device qFT8 transmits through: the radio's USB sound card, or the speaker or headphones if that is where you send the audio. It is the same level that your system's own volume control shows for that device, and if you change one, the other follows (the slider within a couple of seconds).
  • Bottom slider, with the wave picture: the tone volume. It is how loud qFT8 itself generates the transmit audio (the tones of FT8, FT4, WSPR, JS8 and LQ8, the sound of TUNE), from 0 to 100 %. It is changed while you transmit: you hear and see the result in the same transmission. It starts at 100 %. Each radio remembers its own tone volume. The web remote shows the same slider and moves this one.

How the device slider behaves.

  • When qFT8 starts, it reads the device's volume and shows it; it reads it again every two seconds, so if you change the volume in the system, the slider follows. If you switch the output device, the slider shows the new device's volume.
  • qFT8 changes the device volume only when you move this slider. It never sets it by itself before a transmission. This is different from Android, where qFT8 can set the phone's volume to the value in Settings when it transmits; on the computer those two settings do not exist.
  • After you move it, qFT8 reads the volume back, so the slider shows what the device really took.
  • A device that has no volume control (some outputs on macOS) shows the slider greyed out and without a knob.
  • The first time you transmit or press TUNE after starting qFT8, the speaker picture and the knob of the device slider fade from grey to white and back for five seconds, to remind you that this is the level that decides how hard the radio is driven. Touching it stops that.
  • While you drag a slider, its value in percent shows next to it.

Tip: The two sliders do the work of the volume advice for Android in [QMX Only] Audio Check: if the radio shows that the audio is too low or too high (the QMX's two dots instead of a bar), try other positions of the device volume slider first (for example 70 %, 80 %, 60 %, 100 %), and use the tone volume to fine-tune. Otherwise leave the tone volume at its default (100 %). qFT8 never sets your radio's transmit power: adjust that on the radio.

Sound devices and the radio's connection

The Device configuration card

Open it with the button right of the gear (it also opens by itself at the first start and from the No audio badge). It has two halves:

  • THE RADIO (left): the radio, and the radio's own sound card: Input from Radio Device (what the radio hears: what qFT8 decodes) and Output to Radio Device (what qFT8 transmits), each with its sample rate, bits and channels. Leave them on their system default unless the radio needs something else. A small live waterfall under the input shows whether sound is arriving.
  • YOU (THE OPERATOR) (right): your own microphone and your own speakers or headphones, for SSB and CW (see Speakers and microphone, which is the same thing), the TEST button, and Play radio sound on the speaker in digital modes. These must never be the radio's own sound card.

The same choices, and more (buffer sizes, the glitch warning), are in Settings > DEVICE CONFIGURATION. The Android rows "Audio system" and "Audio input source" do not exist on the computer. Leave the devices on AUTO: it prefers the radio's own sound card for the radio, and for you a device that is not the radio's.

Notices you may see

  • Output to radio (badge): your computer's default sound output is the radio's sound card, so system sounds, the browser and alerts go into the radio and could go on the air if it transmits on VOX or its data input. qFT8 offers to use another output (USE ...), to open the sound settings, or to stop asking. The qFT8 transmit audio follows the default output too: choose the radio's sound card as qFT8's output first, then change the computer's default.
  • No radio input (badge, Linux): the radio's sound card has no input in the sound system because it is on an output-only profile. READ RADIO DIRECTLY (recommended) lets qFT8 read the card itself; SWITCH TO PRO AUDIO changes the card's profile for every program.
  • No input devices: the system offers no input; connect the radio or a sound card and check that it appears as an input in the computer's sound settings.
  • The radio's USB driver is not installed (Windows and macOS): the Icom IC-7300 and other radios with a Silicon Labs USB chip may need the CP210x driver. Download it from the maker's driver page, install it and plug the radio in again.
  • Different radio? (badge): the radio that is plugged in is not the one chosen in qFT8.

By system

  • Windows: qFT8 hears the radio through Windows' own audio engine (WASAPI), which gives a steadier stream than the older way. The radio shows up as a COM port (COM3, ...) and a "USB Audio CODEC" or similar sound device. Windows lets only one program use a COM port: if qFT8 says access is denied, close the other program (a logger, a digital-mode program, the radio's own software) and press RETRY.
  • macOS: the radio's port looks like /dev/cu.usbmodem... (a QMX) or /dev/cu.SLAB_USBtoUART (an IC-7300). macOS needs no group or permission for the port, only the microphone permission above. If a port is refused, another program has it open.
  • Linux: the port looks like /dev/ttyACM0 or /dev/ttyUSB0 and needs the group above. The sound devices are those of the sound server (PulseAudio or PipeWire), so the radio's speaker, your headphones and your microphone can each be a different device. The device volume slider uses pactl, from the package pulseaudio-utils (it works with PipeWire too).

Choosing the radio and its port

As on Android, leave Settings > Device on AUTO: a supported radio is recognized when it is plugged in. For a radio behind a generic USB-serial interface (a Digirig, for example), pick the radio by hand, then choose its port in Settings > DEVICE CONFIGURATION > Communication Port Settings > USB Device; baud rate, data bits, stop bits, parity and the keying method (DTR, RTS or CAT) are there too, set by qFT8 for the radio you chose unless you tick Allow overriding settings. Radios that only use sound (VOX) need no port at all. The command line can list the ports and sound devices qFT8 sees.

Mouse and keyboard

The computer program is operated with the mouse. For safety, the keyboard never presses a control: Tab does not move between controls, and Space and Enter never press a button, tick a box or turn TX on. (A key that is pressed by accident cannot transmit.) What the keyboard does:

  • Text fields take every key as usual: type a callsign, a message or a search. Enter confirms a dialog's text box. Copy and paste work: Ctrl on Windows and Linux, Cmd on macOS (Ctrl also works there).
  • Esc closes a dialog, a pane window, the full-screen map, and the QSO editor or the logger.
  • Ctrl-S (Cmd-S on macOS) saves in the QSO editor.
  • CW: your keyboard can be the key or the paddles (Settings > CW); those keys, Space and Tab included, work while the CW screen is the active window (see CW).
  • SSB: Space is push-to-talk while it is held and the SSB pane has the focus (see SSB).

Settings: where they live, moving from a phone

qFT8 keeps everything it stores in one folder, the profile folder: settings, passwords, the QSO log, backups and pictures.

  • Windows: C:\Users\<you>\qFT8
  • macOS and Linux: .qft8 in your home folder (~/.qft8; hidden in the Finder and in most file managers)

The folder stays when you update or delete the program, so a new version finds your settings and your log. At the bottom of the main Settings page, under the version, Configuration directory: shows the folder (click it to open it), and the Open log folder button beside REPORT BUG opens the folder with qFT8's logs, which is useful when you send a bug report. Earlier Windows versions kept it in a settings folder beside qFT8.exe: the first start of a newer version moves it, checks the copy, and keeps the old folder as settings.old.

Moving your settings from a phone (or to one)

EXPORT SETTINGS and IMPORT SETTINGS, on the main Settings page (under Settings files), make and read one file that is the same on Android and on the computer. Export on the phone, copy the file to the computer (mail, cloud, cable), import it there; the other way works as well.

  • The file holds your QRZ API key, your LoTW certificate and your passwords. Never share it.
  • It does not hold QSOs: move the log with ADIF, or let the qFT8 log servers copy it.
  • It does not hold what is only about this computer: the sound device choices (they are different devices), the layout and the windows. Choose them again on the computer.
  • Import asks you to type yes to confirm, needs TX to be off, keeps your QSOs, and never turns TX on.

On the computer, an export never replaces a file that is already there (see ADIF Import/Export).

Several copies, the bridge, the web remote, the command line

  • One copy per profile folder. If you start qFT8 while another copy uses the same folder, it says Already Running and offers RETRY or QUIT: two copies on one folder could damage your settings and log. To run several copies at the same time, for example one per radio, give each its own folder when you start it: qFT8 --qft8_profile D:\qft8-radio2 (Windows: qFT8.exe). qFT8 stops with an error if it cannot write to that folder.
  • The web remote. The computer program has the same Remote Control Web Server as Android (off by default, port 13497) and shows the same pages, including the volume slider. Use it to operate from a phone or another computer on your network.
  • The bridge. A computer is the usual bridge: the radio plugged into it, and qFT8 on a phone, iPhone or another computer operating it. It can also run without a window (qFT8 --bridge), for a computer with no other job.
  • The command line. qFT8 --help lists the options (in Windows a small window shows them): --list-devices lists every serial port and sound device qFT8 sees and quits; --port <device> sets the default serial port (COM3, /dev/ttyACM0); --qft8_profile <folder> chooses the profile folder; --bridge starts a bridge; --opengl draws the window through OpenGL (see If something does not work).

Slow computers

Settings > APPLICATION > Slow device / low battery mode makes qFT8 lighter: about 30 pictures a second, the waterfall redrawn less often, and the world map working only while it is shown. It changes only what is drawn, never the decoder: qFT8 decodes the same with it on or off.

Slow mode turns on only when you tick its checkbox, never by itself. On a computer with one or two processor cores, qFT8 asks when it starts whether to turn it on: ENABLE SLOW MODE ticks the box, DISMISS asks again at the next start, and DON'T ASK AGAIN stops asking. On such a computer qFT8 also gives its decoder a fair share of the processor by itself, slow mode or not, so another busy program cannot starve it.

Updates and uninstalling

Updates

With Check for new versions on startup ticked (the default; see Check for new versions on startup), qFT8 asks once a day whether a newer version exists and shows A new version is available with DISMISS and DOWNLOAD NOW, which opens the download page in your browser. qFT8 never updates itself. To update, download the new file and replace the old program:

  • Windows: close qFT8, replace the qFT8 folder (or just qFT8.exe) with the new one.
  • macOS: close qFT8, drag the new qFT8 onto Applications and choose Replace.
  • Linux: close qFT8 and run the new qFT8. It unpacks itself and removes the old version from the cache.

Your settings and log stay in the profile folder.

Uninstalling

Close qFT8 and delete the program: the qFT8 folder (Windows, Linux) or qFT8 in Applications (macOS); on Linux also ~/.cache/qft8. This keeps your settings and your log. To remove those as well, delete the profile folder (above). That erases your QSO log: export it first with ADIF.

If something does not work

  • The waterfall is empty and the badge says No audio. Open Device configuration: is the radio's sound card the input, and is the radio on? On macOS check the microphone permission; on Linux the No radio input badge and the groups.
  • The radio receives but does not transmit, TUNE keys nothing. The port was refused: another program has it (Windows, macOS) or your account is not in the group (Linux). qFT8 says which; close the other program and press RETRY, or follow the Linux card. See also The phone or computer doesn't recognize the transceiver or it gets disconnected.
  • The radio is too quiet, too loud, or shows two dots instead of a bar (QMX): move the device volume slider (Volumes). Check that the computer's own volume for that device is not muted.
  • Computer sounds are heard on the air. The default output is the radio's sound card: answer the Output to radio badge, or choose another default output in your system.
  • "Already Running". Another copy uses the profile folder. Close it, or start this one with its own --qft8_profile folder.
  • The window is black or garbled (old graphics drivers, a virtual machine, remote desktop): update the graphics driver. Intro to digital modes

Amateur radio digital modes encode text and data into audio frequency-shift keying (FSK) tones transmitted over single-sideband (SSB) radio. Combining narrow bandwidths, advanced forward error correction (FEC), and strict time synchronization, digital modes enable reliable worldwide communication even when signals are buried deep below the audible noise floor. qFT8 supports the leading modern digital modes—FT8, FT4, FT2, JS8, WSPR, and LQ8—each engineered for distinct operational goals ranging from ultra-weak-signal propagation beaconing to rapid contesting and conversational keyboard-to-keyboard messaging.

FT8

FT8 (Franke-Taylor design, 8-GFSK) is the world's most widely used weak-signal digital protocol, engineered for challenging HF/VHF conditions, multi-hop sporadic-E, and crowded bands. It operates with structured messages, precise 15-second time synchronization, and robust error correction.

Cycles and Sequences

FT8 operates in 15-second cycles. Every communication cycle is strictly timed, starting exactly at 00, 15, 30, and 45 seconds of every minute. For this reason, your device's clock must be accurately synchronized to UTC time.

There are two sequences within the protocol:

  • Sequence 0 (Even): Cycles starting at 00 and 30 seconds.
  • Sequence 1 (Odd): Cycles starting at 15 and 45 seconds.

Stations generally alternate between transmitting and receiving. A station transmitting in Sequence 0 will listen for a response in Sequence 1, and vice versa. Within each 15-second cycle, the message is transmitted in a window between approximately +0.5s and +13s. This leaves time at the end of the cycle for decoding and at the beginning for preparing the next transmission.

Signal Characteristics

Each FT8 message is transmitted as a sequence of tones with slight frequency variations (sometimes described as "wiggliness"). An FT8 signal is very narrow, occupying only about 50Hz of bandwidth. This efficiency allows dozens of simultaneous conversations to fit within a single 3kHz radio band.

The 6 Stages of a QSO

A standard FT8 contact typically moves through six stages. Here is an example of an exchange between HB9IPH and XX1XXX:

  1. 1/6 CQ: A station looks for anyone to talk to.
    Example: CQ HB9IPH JN47
    Note: JN47 is a Maidenhead grid locator, which indicates the station's approximate geographic location. There may also be a CQ modifier, which is a note for other operators (e.g., CQ SOTA HB9IPH for the Summits On The Air program, or CQ US HB9IPH when trying to contact someone in the US). Both the modifier and location might not fit in the same message; in such cases, the location is omitted. If the callsign is very long, it is possible that neither the location nor the modifier will fit in the CQ!
  2. 2/6 CALL: Another station responds to the CQ.
    Example: HB9IPH XX1XXX JO21
    Note: The responder also shares their location (JO21), which may be omitted if the callsigns are too long to fit everything.
  3. 3/6 RPT: The first station sends a signal report.
    Example: XX1XXX HB9IPH -10
    Note: The signal report (e.g., -10) indicates the signal strength relative to the noise floor in dB.
  4. 4/6 RRPT: The second station acknowledges the report and sends their own.
    Example: HB9IPH XX1XXX R-12
    Note: The "R" prefix confirms the previous report was received, followed by the signal report for the first station.
  5. 5/6 RR73: The first station confirms everything and sends a "Roger-Roger 73".
    Example: XX1XXX HB9IPH RR73
  6. 6/6 73: The second station sends a final "73" to close the contact.
    Example: HB9IPH XX1XXX 73

Because of the Two Generals' Problem, it is theoretically impossible to know for certain that the other station received your last communication unless they confirm so. However, then you would need to confirm their confirmation, and they would need to confirm that, and so on. The FT8 digital mode mitigates this by having structured stages: a QSO can technically be considered complete after stage 4/6 (when both signal reports have been exchanged). In practice, to ensure both stations agree that the exchange happened, a QSO is logged when a station has received an RR73 and has sent out a 73. Effectively, either transmitting an RR73 or a 73 triggers the logging of a QSO.

Note that stations may also call other stations even if they haven't transmitted a CQ first. For example, stations in rare locations may have a "pile-up" of many stations calling them simultaneously; in such cases, the rare station may simply move from one QSO to the next without needing to invite new callers with a CQ.

Some stations may use RRR instead of RR73 in stage 5. In that case, the contact requires an extra exchange: the second station sends 73, and then the first station sends 73 again to finish.

FT8 also supports free text messages (up to 13 characters), but qFT8 does not currently support sending these custom messages.

Protocol Limitations and Fallbacks

FT8 messages are highly compressed into 77 bits. Sometimes, complex information (like long, non-standard callsigns) does not fit in the standard message format.

  • Hashed Callsigns: If a callsign is too long, it may be sent as a hash. If the receiving station has seen that callsign calling CQ recently, their software can map the hash back to the original callsign. Otherwise, it will be displayed as <...>. It is much harder to achieve QSOs when your callsign is not standard.
  • Free Text Fallback: Some messages may be forced into the 13-character free text format, which is less robust than the standard structured messages.
  • Non-standard Callsigns: If two stations both use very long, non-standard callsigns, they may be fundamentally unable to communicate with each other using the FT8 digital mode.
  • Stage Skipping: If callsigns are too long, the protocol may not be able to fit signal reports (stages 3/6 and 4/6). In these cases, the exchange may skip directly from the initial CALL (2/6) to the final confirmations (5/6 and 6/6).

Messages you will see but never send

Some stations send message shapes that qFT8 shows but does not send itself:

  • One message for two stations: An expedition that works many stations at once can close one QSO and start the next in a single transmission: K1ABC RR73; W9XYZ <VP8XYZ> -08. It means "K1ABC, your QSO is complete" and "W9XYZ, your report is -08", both from VP8XYZ. qFT8 shows it as it was sent, in the station list and once on the waterfall. If you are one of the two stations, it counts as your RR73 or as your report, exactly as if the expedition had sent it to you alone, and the QSO goes on or is logged as usual. If you are neither, there is nothing to do, and AUTO does nothing with it.
  • Contest exchanges: In some contests stations send a class and a section (Field Day) or a report with a state or a serial number (RTTY contests) instead of a locator and a report. qFT8 shows these messages so that you can see what is on the band, and never answers them: it does not send contest exchanges.

FT4

FT4 is a streamlined digital mode designed specifically for amateur radio contesting, where rapid contact turnover is vital:

  • Double Speed: Operates in 7.5-second cycles (twice as fast as FT8), transmitting for approximately 4.48 seconds with four transmission intervals per minute.
  • Double Bandwidth: Occupies approximately 90 Hz of RF bandwidth (about twice the ~50 Hz bandwidth of FT8).
  • Sensitivity Loss: In exchange for doubled throughput, FT4 has a decode sensitivity threshold of approximately -16.4 dB to -17.5 dB SNR (a sensitivity loss of about 3.5 to 4 dB compared to FT8).
  • Operational Use: Uses 4-GFSK modulation and the standard 77-bit structured message payload, allowing operators to complete standard contest exchanges in half the time when propagation permits.

FT2

FT2 is designed for ultra-high-speed exchanges under favorable signal conditions, VHF/UHF meteor scatter bursts, and high-rate contesting:

  • Double Speed of FT4 (4x FT8): Operates in 3.75-second cycles with approximately 2.24 seconds of transmission time, permitting up to 16 cycles per minute.
  • Double Bandwidth of FT4 (4x FT8): Occupies approximately 180 Hz of RF bandwidth (twice that of FT4 and nearly four times that of FT8).
  • Additional Sensitivity Loss: Has a decode threshold of approximately -13 dB to -14 dB SNR (an additional ~3 dB sensitivity loss compared to FT4, or ~6 to 7 dB less sensitive than FT8).
  • Operational Use: Ideal for rapid-fire contacts during high-signal openings and burst propagation modes where contact windows are momentary and signals are comfortably above the noise floor.

JS8

JS8 (Jordan Sherer design, 8-GFSK) is created for conversational ragchewing, keyboard-to-keyboard chat, and ad-hoc networking rather than structured contest exchanges:

  • Message Slicing and Framing: Utilizes the same fundamental 8-GFSK modulation and 77-bit frames as FT8, but introduces an upper-layer transport protocol for message fragmentation and reassembly. This allows free-form text messages of arbitrary length to flow seamlessly across consecutive cycles.
  • Multiple Speed Modes: Offers four selectable speed profiles to match band conditions:
    • Slow: 30-second cycles, ~25 Hz bandwidth, decodes down to -25 dB SNR.
    • Normal: 15-second cycles, ~50 Hz bandwidth, decodes down to -21 dB SNR.
    • Fast: 10-second cycles, ~80 Hz bandwidth, decodes down to -18 dB SNR.
    • Turbo: 6-second cycles, ~160 Hz bandwidth, decodes down to -15 dB SNR.
  • Networking Capabilities: Supports directed messaging, automatic message relaying across intermediate stations, heartbeat presence monitoring, and asynchronous store-and-forward mailbox networking.

WSPR

WSPR (Weak Signal Propagation Reporter) is designed exclusively for probing radio propagation paths and automated beaconing rather than two-way conversational QSOs:

  • Two-Minute Cycles: Operates in strictly synchronized 2-minute (120-second) cycles, transmitting a 162-symbol 4-FSK tone sequence over 110.6 seconds.
  • Ultra-Narrow Bandwidth: Occupies only about 6 Hz of RF bandwidth, concentrating radiated power into an exceptionally compact spectrum slice.
  • Extreme Weak-Signal Sensitivity: Capable of decoding signals as faint as -28 dB to -31 dB SNR in a standard 2.5 kHz reference bandwidth, enabling milliwatt-level (QRPp) transmitters to span global distances.
  • Automated Propagation Reporting: Transmits the station callsign, Maidenhead grid locator (4 or 6 digits), and transmitter power in dBm. Decoded spots are automatically forwarded to the worldwide WSPRnet database to map ionospheric propagation in real time.

LQ8

LQ8 is an advanced weak-signal digital mode developed by Luis Quesada (HB9IPH), the author and creator of qFT8:

  • Closes QSOs Faster Without Penalty: LQ8 completes two-way QSOs significantly faster than FT8 without any sensitivity penalty. It preserves the full weak-signal decoding threshold of -21 dB SNR (matching FT8) while finishing valid contacts in substantially fewer transmission rounds through an optimized protocol design.
  • Compound Messages: Supports aggregated transmissions such as combined report and confirmation (REPORT+RR73) and parallel multi-station responses (MULTI_CALL), cutting the standard QSO duration from 4–6 cycles down to just 2–3 cycles.
  • Modern Architecture: Operates in standard 15-second cycles with 8-GFSK modulation across 79 symbols (~65 Hz bandwidth), 77-bit payloads compressed with optimized Huffman encoding, 14-bit CRC error detection, and structured emergency dispatch signaling.

For more information, specifications, and tools, visit https://lq8.org, the portal for the LQ modes.

The Stations tab

The Stations tab is the command center for monitoring activity on the band and operating qFT8. It features filtering and automation controls at the top, followed by a list of active stations.

These are the components of the Stations tab in detail:

  1. AUTO call mode button: Engaging "AUTO" will try to call the best station according to the criteria selected by the user.
  2. Manual CALL mode button: Engaging "CALL" for a station will insist on calling that station until achieving a QSO, then will fall back to "AUTO".
  3. Target: Sets the criteria for the AUTO mode:
    • Anyone: Any callsign that you don't have a QSO for yet.
    • Nearby: Prioritize nearest stations based on Maidenhead grid distance.
    • Far: Prioritize farthest stations based on Maidenhead grid distance.
    • Signal strength: Prioritize stations with the strongest signal (SNR).
    • Call CQ: Just calls CQ and replies to any station that calls your station.
    • POTA hunter: Prioritize Parks on the Air stations.
    • SOTA hunter: Prioritize Summits on the Air stations.
    • POTA + SOTA hunter: Prioritize both Parks on the Air and Summits on the Air stations, then stations that are neither, ordered by SNR.
    • DXCC: Prioritize new countries/entities.
    • Grid: Prioritize new Maidenhead grid squares.
    • ITU zone: Prioritize new ITU zones.
    • CQ zone: Prioritize new CQ zones.
    • I/C/D/G: Prioritize first ITU zone, then CQ zone, then DXCC, then Grid.
    In all cases, stations that meet the same criteria are sorted by signal strength. For example, Anyone will prioritize new callsigns first, but among them the strongest signals will be at the top of the list.
  4. Periodicity: How often to contact that target:
    • once: In a lifetime.
    • daily: Once per UTC date.
    • weekly: Once every 7 days rolling window.
    • monthly: Once every month rolling window.
    • yearly: Once every year rolling window.
  5. Qualifier: How those constraints apply:
    • per callsign
    • in different bands
    • in different modes
    • until zone confirmed
    • per band+until zone
    • per mode+until zone
    • in different bands or modes
    • per band/mode+until zone
  6. Spy mode: When enabled, qFT8 will also try to call stations you haven't heard call CQ yet (marked as DIRECT). This is useful to have more stations at reach and join pile-ups.
  7. Busy mode: When enabled, qFT8 will also try to call stations engaged in a QSO with someone else (marked as BUSY). This is useful to join a pile-up.
  8. + button: Manually call any arbitrary station by inputting their callsign.
  9. Station information: Displays detailed status for each decoded station.

Individual station entries consist of four information-rich rows:

The first row shows station details (left to right):

  • QSO Status: Indicates your QSO history with this station (✗ = no QSO, ✓ = logged locally, ★ = confirmed via QRZ or LoTW).
  • Callsign: The station's callsign.
  • DXCC: The country or entity this station's callsign belongs to.
  • Grid cell: The Maidenhead grid square this station is reporting.
  • CQ zone: The CQ zone this station's callsign belongs to.
  • ITU zone: The ITU zone this station's callsign belongs to.
  • Band: The band on which the station was last heard.

The second row shows communication status (left to right):

  • State: Current phase of communication:
    • DIRECT: Heard and seemingly free right now, but never called CQ.
    • 1/6 CQ: Heard calling CQ and seemingly free right now.
    • 2/6 CALL: Called you.
    • 3/6 RPT: Sent you a signal report.
    • 4/6 RRPT: Replyed back to your report with their own.
    • 5/6 RR73: Confirmed your report with RR73.
    • 6/6 DONE: QSO completed (73 exchanged).
    • GONE: Not heard in the last couple of cycles.
    • TOO LONG: Your callsign and their callsigns are too long together to establish a communication, per FT8 digital mode limits.
  • Signal strength: Strength in dB (shows "????" if not heard recently).
  • Sequence: The last sequence this station was heard transmitting in (0 or 1).
  • Delta time (Δt): Time synchronization offset in seconds between their time and yours.
  • Distance: Estimated distance between their and your station Grid cells.

The third and fourth rows show message exchanges with that station, including UTC time, frequency offset, and the message text (prefixed with RX: for received messages or TX: for transmitted messages). Automated operation (AUTO)

AUTO mode is the primary way to use qFT8. In this mode, the application automatically analyzes the decoded messages at the end of every cycle and selects the most relevant station to contact based on your target criteria.

How Target Selection Works

The Stations tab displays a list of active stations, sorted such that the most relevant candidates (based on your criteria) appear at the top. At the end of each decode cycle, qFT8 looks at this sorted list and attempts to call the first eligible station. If no eligible target is found, it will automatically start calling CQ to attract callers. qFT8 always replies to calls in AUTO mode.

Criteria and Filters

You can fine-tune the automation using the three dropdown menus at the top of the Stations tab:

  • Target: Defines what "achievement" you are looking for (Anyone, DXCC, CQ Zone, ITU Zone, Grid).
  • Interval: How often you are willing to contact the same entity (Once, Always, Daily, Weekly, Monthly).
  • Qualifier: Narrow down the uniqueness requirement (Per callsign, Per band, Until zone/entity confirmed).

Manual Override: You can always manually intervene by tapping the CALL button for a specific station. This enters CALL mode for that specific QSO. Once finished, qFT8 seamlessly drops back into AUTO mode.

Directed CQs

Some stations call CQ for a part of the world only: CQ DX, CQ NA, CQ JA. The word after CQ is their CQ modifier. With Avoid calling stations whose CQ modifier does not target us ticked (Settings > AUTO OPERATION, on by default), AUTO does not call a station whose CQ is not meant for you.   • Retry Window: The time period during which these attempts are counted.
  • Retry Cooldown: If the limit is reached, the station is "Banned" for this duration. AUTO mode will ignore banned stations until the cooldown expires or the station replies.

While qFT8 is highly automated, you can take control at any time. Tapping the CALL button next to any station in the Stations tab will immediately enter CALL mode and attempt to establish a QSO with that specific station.

  • Increase "Start transmission time": Delays the onset of your reply.

Editing and logging QSOs by hand

qFT8 logs the QSOs it makes in the digital modes by itself. This section covers the three things you do by hand in the Log tab: correcting a QSO, logging a QSO you made in another way (voice, Morse, another radio), and working on several QSOs at once.

The QSO editor

Tap a QSO in the Log tab and the tab becomes its editor. Every stored field is there: your callsign and locator, theirs, mode, band, frequencies, date and times, power, reports, POTA and SOTA references, and the comment.

  1. The QSO being edited: callsign, mode, band, date and time.
  2. Status: whether the QSO is confirmed. Tap it to Manually confirm or Manually unconfirm it (this only changes your own log).
  3. Uploaded: where the QSO stands on QRZ and LoTW. Tap it to upload the QSO again to one service or to all.
  4. A changed field is highlighted, with its old value in red next to it and an arrow that puts the old value back. Tap any value to change it. Mode and band are picked from the app's lists, the band follows a frequency you type, and a value that cannot be right (a callsign, a locator, a date...) is refused with the reason.
  5. BACK: Leaves the editor. If there are changes it asks whether to discard them.
  6. The number of changes not saved yet.
  7. DELETE: Deletes the QSO from this app's log only, after you type yes.
  8. SAVE: Asks for confirmation, then saves.

What happens on QRZ and LoTW when you save. The confirmation question tells you, for the QSO you are editing:

  • QRZ: the QSO is updated there. If you changed the callsign, date, time, band or mode, QRZ treats it as a different QSO: a new entry is created and the old one stays, for you to delete on qrz.com.
  • LoTW: the corrected QSO is uploaded again as a new entry; the old one stays there, unconfirmed and harmless.
  • A change that breaks a confirmation (the callsign, your callsign, the date or the time of a QSO) must be confirmed by typing yes, because the QSO will no longer match the other station's log.
  • A QSO made under a callsign other than the one in Settings is not uploaded.

qFT8 never deletes anything on QRZ or LoTW. Deleting a QSO only removes it from the app. If that QSO is on a service, it may come back at the next sync: delete it on the service first. Deleting is irreversible unless you keep an exported copy of the log.

The logger

The + button of the Log tab opens the logger, a fast form for QSOs you make yourself. On a phone it turns the screen to portrait, with a thin strip of the spectrogram on top (this can be switched off in Settings > APPLICATION > User interface).

  1. Callsign: Type the callsign and press Enter on the keyboard: the QSO is logged with the current time, the box empties, and you can type the next one. The keyboard stays open from one QSO to the next.
  2. LOG: The same as Enter.
  3. CLEAR / UNDO: While a callsign is typed it reads CLEAR and empties the box. Otherwise it reads UNDO and takes the last QSO of this session out of the log and back into the form, to correct it.
  4. DONE: Closes the logger. If a callsign is typed but not logged, it asks whether to log it.
  5. The lookup line: The country of the callsign, your last QSO with it, and whether it is a duplicate. DUPE in orange means you already logged that station on that band and mode today (you can still log it).
  6. The details (swipe sideways for more): the time (Now, or tap it to set a date and time), band, mode, frequency in kHz, the receive frequency when it differs, power, reports sent and received, their POTA / SOTA reference and yours. They start from what the app is tuned to and are kept from one QSO to the next.
  7. This session: How many QSOs you logged since opening the logger. On a phone, tap it to see them as a list.
  8. The session's QSOs are shown in coral with a clock icon: they are already in your log, but they are not uploaded to QRZ or LoTW until you press DONE, so that a typing mistake can still be undone. Tap one of them to undo or edit it.

The QSO button of the SSB, CW, RTTY and SSTV panes opens the same form as a small card, already filled in with the mode, the frequency and the station, for one QSO at a time.

ADIF Import/Export

qFT8 supports the standard ADIF (Amateur Data Interchange Format) for interoperability with other logging software, cloud services, and for manual backups.

Importing QSOs

The import feature allows you to bring records from other sources (like other logging programs or backups from other devices) into your local qFT8 log.

  • Filtering Options: every mode is imported. You choose whether to restrict the import to your current callsign or include all operators.
  • Automatic Deduplication: qFT8 intelligently merges records. It prevents duplicates by matching QRZ Log IDs and QSO timestamps. If an imported record has a confirmed status or a valid Log ID that your local record is missing, entry by updating it with the better data.

Exporting QSOs

Tapping EXPORT QSOs generates an ADIF 3.1.6 file. On Android it opens the system Share sheet, allowing you to save the log to your device or send it via email/messaging; on the computer you choose where to save the file.

  • Time Range: You can export your entire history or use the UTC date/time pickers to isolate a specific activation or contest period.
  • Status Filters: Useful for claiming awards (export "Confirmed Only") or for manual uploads to other services (export "Not Uploaded to QRZ" to avoid duplicates).
  • Hunter Criteria: Filter your log to export "All logs", "Only POTA contacts (parks)", or "Only SOTA contacts (summits)" to generate targeted award submission files containing populated contact references (<POTA_REF> / <SOTA_REF>).
  • SOTA reference: As detailed in the SOTA section, qFT8 can automatically inject the summit reference into the <MY_SOTA_REF> field of every exported record.
  • POTA reference: As detailed in the POTA section, qFT8 can automatically inject the park reference into the <MY_SIG>, <MY_SIG_INFO>, and <MY_POTA_REF> fields of every exported record. Several parks, separated by commas, give one file per park (see "Which park goes in the file?").

The names of the exported files

  • Without a reference: qFT8-YYYYMMDD-HHMMSS.adi, the date and time (UTC) of the export, for example qFT8-20261006-181500.adi. The status filters add _confirmed or _notuploaded after the time, so the files of a folder sort by date.
  • With a POTA reference: CALLSIGN@PARK-YYYYMMDD.adi, for example K1ABC@US-1234-20261006.adi. This is the name the parks programme asks for. There is one file for each park and each UTC day, so an export that crosses UTC midnight gives two files.
  • With a SOTA reference: one file, for example K1ABC@W1_HA-001-20261006.adi (the "/" of a summit or of a callsign cannot be part of a file name and is written "_").
  • On the computer, an export never replaces a file that is already there: if the name is taken, the new file is saved as name (1).adi, then name (2).adi, and so on.

Note: For very large logs (over 100KB), qFT8 will display a warning as the deduplication and sorting process may take a few moments to complete, especially on a phone.

QSO upload services

qFT8 can send every QSO you log to several online or home-network logbooks: QRZ, LoTW, Wavelog, Cloudlog, eQSL and another qFT8 (qFT8log). Each one has a row at the top of Settings: a check box to switch it on, and a gear button that opens the service's own page.

  • The check box stays greyed out until the service is validated: open its page, enter its details and press VALIDATE.
  • Each page starts with a short explanation and a ? button that opens this manual at the service's section. It also shows how many QSOs are not uploaded yet, with UPLOAD NOW, and a RESET TO DEFAULTS button (it never clears an account, a key or a password).
  • When a service could not be reached since it last worked, its row turns red and a red line under it says Couldn't connect as of and the date and time.

When does a QSO count as uploaded?

The green tick in the log, the stations list, the map and the web remote all follow one rule. Every service's page has a check box Consider a QSO uploaded if it is uploaded here. It is on for QRZ and LoTW and off for the others.

  • A service only counts when it is set up: validated and switched on.
  • A QSO is uploaded as soon as any counted service has it.
  • When none of the set-up services has its box ticked, every set-up service counts. So if you only set up qFT8log, the app waits for qFT8log alone, never for QRZ or LoTW.
  • With no service set up at all, the ticked boxes decide from what the QSO itself carries (for example a log imported from another program keeps its ticks).
  • A QSO imported from LoTW counts as already on QRZ and is not sent there. A QSO that arrived from a service counts as uploaded to that service and is never sent back to it.
  • The star (confirmed) needs the QSO uploaded under this rule and confirmed by any service, unless you confirmed or unconfirmed it by hand.

The ADIF export can pick Not uploaded to one service at a time; the choices of services that are not set up are greyed out. qFT8 never deletes a QSO on any service: deleting a QSO here only warns you that it is still there.

QRZ Integration

qFT8 offers deep integration with QRZ.com to keep your logbook automatically synchronized. Note that QRZ integration is a subscription service that requires a QRZ paid subscription (XML Logbook Data or higher). If you prefer a free alternative, consider using LoTW integration, which is provided at no charge by the ARRL.

How it Works

To enable QRZ integration, you need to provide your QRZ API Key in the settings tab. You can find your API Key on the official QRZ Logbook API page. Once entered and VALIDATED, you can enable "Upload QSOs to QRZ" for automatic background management.

  • Automatic Uploads: Every time a QSO is completed (successfully reaching the 6/6 DONE state), qFT8 immediately attempts to upload it to your QRZ logbook.
  • Background Reliability: If an upload fails (e.g., due to no internet connection or server timeouts), qFT8 doesn't give up. A background worker will automatically retry failed uploads every 5 minutes. This process is silent and ensures your log eventually reaches the cloud once connectivity is restored.
  • Smart Skipping: qFT8 protects your logbook integrity by only uploading QSOs that match your current configured callsign and the FT8 mode. Non-FT8 entries, QSOs for different callsigns, or QSOs imported from LoTW are skipped automatically to prevent excessive API requests.

Syncing Confirmations

The integration goes beyond just uploading. qFT8 also polls QRZ to see if your QSOs have been confirmed.

  • Immediate check: 30 seconds after a QSO is completed and uploaded, qFT8 will check back with QRZ to see if the other station has also uploaded the QSO; if they have, the QSO will be synchronized as confirmed immediately.
  • Automatic Sync: By default, qFT8 queries QRZ every 6 hours (configurable) in batches of 250 QSOs at a time, rotating through your entire unconfirmed log to ensure that even older QSOs are eventually checked for new confirmations.
  • Confirmation Star (★): When a QSO uploaded to QRZ is confirmed on either QRZ or LoTW, it is highlighted with a gold star. You can also manually confirm any QSO to show this indicator. When QRZ reports a confirmation, the status icon in your Log tab will automatically change to a gold star.
  • Manual Sync: Updates to the 250 least recently synchronized QSOs can also be triggered manually in the settings.

Pro Tip: You can see the sync progress in settings under "Oldest QSO synced for confirmation". There's no urgency in keeping this up to date, as qFT8 will take care of it over time.

Log Syncing Strategy

In the synchronization settings, you can choose how qFT8 determines if a QSO is "fully uploaded" via the "Consider a QSO uploaded when uploaded to:" option:

  • Any of LoTW and QRZ: A good default if you only have one of the services configured.
  • Both: Select this for maximum safety, requiring the QSO to be successfully sent to both services before being considered finalized and ready to be checked for confirmation.
  • QRZ (except imported from LoTW): Recommended if QRZ is your primary logbook. Note: QSOs imported from LoTW are marked as synced but not uploaded to QRZ to avoid API limits (which only allow one-by-one uploads); these can be synced within QRZ itself later.
  • LoTW: Recommended if you consider LoTW your primary source of truth.

Wavelog

Wavelog is a logbook program you run on a web server of your own (a small computer at home or rented web space) and open in a browser. qFT8 sends each QSO to it as soon as it is logged, and reads back which of them your Wavelog has confirmed. qFT8 talks to it through Wavelog's published interface: docs.wavelog.org/developer/api.

Setting it up

  1. In Wavelog, open the account menu > API Keys and create a key with read and write rights.
  2. In qFT8, open Settings, press the gear next to Wavelog and type the Server address (the address you open Wavelog at, for example https://log.example.org) and the API key. An address typed without http:// or https:// is tried with https first; when the server only speaks plain http (another qFT8's server does), qFT8 uses http and the page says the key travels unprotected.
  3. Optional: to have edits sent too, create an API v2 token in Wavelog (account menu > API Keys, the API v2 tab, with the qso:read and qso:write scopes) and type it as the Edit token. VALIDATE checks it without changing anything.
  4. Press VALIDATE. qFT8 checks the key and lists your Wavelog station locations; pick the one your QSOs belong to (with only one, it is picked for you).
  5. Tick Wavelog at the top of Settings. From now on every new QSO goes to it, and the ones logged before are sent too.

What happens

  • Offline: a QSO that cannot be sent waits in the log and is sent when the server answers again (tried after 1 minute, then less often, up to once an hour). While the server cannot be reached its row in Settings turns red with "Couldn't connect as of ...".
  • Duplicates: a QSO your Wavelog already has counts as uploaded.
  • Refused: a QSO Wavelog refuses is not sent again until you edit it or re-upload it; the QSO editor shows the reason. A key that stops working stops the uploads until you press VALIDATE again.
  • Confirmations: once an hour (and when you press UPLOAD NOW) qFT8 asks Wavelog which of your QSOs are confirmed (LoTW, paper QSL, eQSL) and marks them in the QSO editor's Uploaded and Status rows, the same rows and marks as QRZ and LoTW.
  • Edits: with the Edit token set, an edited QSO is found in your Wavelog and updated there (the newest change wins; the confirmation marks Wavelog keeps are never touched). Without it, Wavelog's upload interface can only add QSOs, so an edit is not sent: change it in Wavelog too.
  • QSOs of other callsigns: a QSO logged under another callsign than yours (a club or special-event call) is held back from QRZ and LoTW, but goes to Wavelog while Also send QSOs made under other callsigns is ticked (the default).
  • Deletes: qFT8 never deletes anything in Wavelog. Delete a QSO there yourself.
  • "Consider a QSO uploaded if uploaded here" on the page decides whether an upload to Wavelog counts for the "uploaded" mark (off by default).

Importing QSOs from Wavelog

IMPORT QSOs FROM WAVELOG, at the bottom of the Wavelog page, copies the QSOs of the chosen station location into the log of qFT8, with their LoTW, paper QSL and eQSL confirmations.

  • What it takes: every mode. From, To, Bands and Callsign starts with limit it (any = no limit). QSOs made under another callsign than yours are skipped unless Import QSOs for callsigns other than the current is ticked.
  • Already in the log: a QSO the log has is merged, never added twice (the same rules as the QRZ and LoTW imports); a QSO you corrected here keeps your correction and takes only the confirmations.
  • Never sent back: imported QSOs count as already on Wavelog. A correction you make later in qFT8 goes there (with the Edit token).
  • STOP ends the import after the part it is on; what came in so far stays. The line under the button counts what was received, added and merged.
  • Nothing is deleted, here or in Wavelog. A QSO you deleted in qFT8 comes back with the next import.

Secure connections

  • Prefer an https:// address. With http:// the key travels unprotected: use it only on your home network.
  • Android 6 and 7.0 do not trust some newer certificates many such servers use; there, an https:// server may fail to connect. On your home network the server's http:// address works.
  • The iPhone connects to https:// addresses only.

eQSL

eQSL (eqsl.cc) exchanges electronic QSL cards: every QSO sent there becomes a card in the other station's eQSL inbox. qFT8 only adds cards; it never deletes anything on eQSL.

Setting it up

  1. Tap the gear of the Sync QSOs with eQSL row at the top of Settings.
  2. Enter your eQSL user name (usually your callsign) and eQSL password. If you have several eQSL accounts (locations) under one callsign, enter the location's QTH nickname as it is written on eqsl.cc; otherwise leave it empty and eQSL picks the account by the QSO's date.
  3. Press VALIDATE. It only reads your eQSL inbox to check the login: no card is sent.
  4. Tick Sync QSOs with eQSL. The QSOs not sent yet go at once, one a second, and every new QSO goes when it is logged.

What to know

  • Consider a QSO uploaded if it is uploaded here is off for eQSL: a card on eQSL does not by itself make the log's green tick (see QSO upload services). Tick it if you want it to.
  • A card cannot be changed. When you edit a QSO that is already on eQSL, nothing is sent by itself. To send a corrected card use Re-upload to eQSL in the QSO editor; the old card stays in the other station's inbox until you delete it on eqsl.cc.
  • LQ8: eQSL accepts only the official ADIF modes, so its QSOs are sent as MFSK, and the comment names the real mode ("QSO by qFT8, mode LQ8"). The other services keep their own form.
  • A QSO eQSL already has is answered as a duplicate and counts as sent. One it refuses (for example a date no account of yours covers, or a mode it does not know) shows as refused in the QSO editor, with eQSL's own words, and is not tried again until you re-upload it.
  • Offline, or while eQSL is down for maintenance, the cards wait and are tried again later (after 1 minute, then longer, up to an hour); the row's red Couldn't connect note says since when. If the password is refused (for example you changed it on eqsl.cc), sending stops until you VALIDATE again.
  • Confirmations (cards received) are not read back yet.

qFT8 as a Wavelog server

In Settings > qFT8 servers > Wavelog server, qFT8 answers on your home network as if it were a Wavelog: any program that can send QSOs to Wavelog (another qFT8 among them) can send them to this qFT8 instead.

Setting it up

  1. Turn on Run the Wavelog server, keep the Port (13500) or choose another, and type an API key of at least 8 characters (make it long and random: it is the only thing keeping others out).
  2. In the other program set up Wavelog with the address the page shows, written in full: http://, this device's address, a colon and the port, for example http://192.168.1.20:13500/ (most logging programs need the http:// and the port typed out; another qFT8 finds them by itself), the same key, and station 1 (in another qFT8: VALIDATE picks it).

The port can be changed at any time: the server moves to the new port at once (and stops at once when switched off).

Looking at the log in a browser

Open the same address (http://192.168.1.20:13500/) in a browser on your home network: after you type the server's key, it shows your QSO log, newest first, read only; older QSOs load as you scroll, and new or changed ones appear by themselves. The key is never sent: the browser answers a one-time challenge with a value made from it, and an address that answers wrongly is locked out for a while. The Cloudlog server and the qFT8log server show the same page on their own ports, with their own key or password.

What it does

  • Every QSO received, in any mode and with any callsign, goes into the log and the QSO list, and on to the services set up here (QRZ, LoTW, Wavelog, ...), never back to where it came from. A QSO the log already has is answered as a duplicate and not forwarded again.
  • It answers the endpoints a logging program uses: api/qso (one or many QSOs as ADIF), api/version, api/station_info, api/check_auth, api/auth, api/get_contacts_adif (so a qFT8 further down a chain can read the confirmations back) and api/radio (accepted and ignored). There is no way to change or delete a QSO through it.
  • Security: home network only, plain http (as the remote-control web server); the key is compared in a way that does not leak it; an address that sends 10 wrong keys is locked out for 10 minutes; at most 20 requests a second per address, 128 KB and 500 QSOs per request; anything malformed gets an error answer.
  • Where it runs: on Android also in the background when "run in background" is on; on the computer while the program is open; on the iPhone only while qFT8 is open.

Chains

Servers and services combine into chains: several stations (phones, computers) send their QSOs to one qFT8 that collects them and is the only one uploading to QRZ and LoTW; that one can also send everything on to a Wavelog or another qFT8 kept as a backup. Confirmations travel back down: the collecting qFT8 learns them from QRZ / LoTW / its Wavelog, and the qFT8s that send to its Wavelog server read them back every hour. Duplicates are never forwarded, so a loop in a chain stops by itself.

Activating a park or a summit

When you operate from a park (POTA) or a summit (SOTA), start an activation in qFT8. From then on every QSO you log, in any mode, automatically carries your park or summit, qFT8 counts them for you, and at the end it writes the files the programmes ask for with one tap.

Starting

  1. In the Settings tab, press POTA ACTIVATION or SOTA ACTIVATION (right above EXPORT / IMPORT SETTINGS).
  2. Type your reference, for example US-1234 for a park or W1/HA-001 for a summit. If you are in several parks at once (a "two-fer"), separate them with commas. qFT8 checks the format as you type and offers the references you used recently.
  3. Press START. The button turns blue and shows the reference and the number of QSOs.

A park and a summit activation can be open at the same time; every QSO then gets both references. To call CQ POTA or CQ SOTA in the digital modes, set the CQ modifier as described in the POTA and SOTA sections.

qFT8 can also offer to start for you: if the spots it downloads for the world map show your own callsign as an activator, it asks Start a POTA activation there? And if you type your park or summit into the empty My POTA / My SOTA box of the logger, it asks whether to start an activation with it.

Announcing it, so hunters find you

When you start an activation yourself (not from a spot that already announced you), qFT8 asks Announce it on POTA? (or SOTA) and says what hunters would see, for example FT8 on 20m (14074 kHz). NOT NOW announces nothing. ANNOUNCE opens a short dialog:

  • Bands and Modes: tick one or more of each. The band and mode qFT8 is on are ticked already. qFT8 sends one announcement for every park, band and mode you chose, and says how many before you press ANNOUNCE.
  • Modes the programme does not list are announced as DATA, with the real mode in the announcement's comment. A band and mode with no usual frequency (RTTY on 60 m) is left out, and the dialog says so.
  • The frequency is where your radio is for the band and mode you are on, and the usual calling frequency for the others.
  • SOTA only: the dialog also asks for your SOTAwatch user name and password (your own SOTA sign-in). qFT8 keeps them for the next time, like the other services' passwords.

After that, qFT8 announces the activation again every 30 minutes (announcements disappear from the list after about an hour), as long as the activation is open and qFT8 is working: on screen, or minimised with qFT8 kept running in the background and the radio connected. It stops when you finish the activation, and it never announces by itself when qFT8 was closed: at the next start, once you have chosen to continue the activation, it asks Announce again?

If an announcement does not get through (no internet, the site refuses it, or the SOTA sign-in is wrong), qFT8 says what went wrong and offers RETRY, or SPOT BY HAND, which opens the programme's spot page in your browser so you can announce yourself. Without a connection it also tries again by itself every 5 minutes.

To announce with other bands or modes, or to see when it was last announced, press ANNOUNCE on the activation's card (tap the blue marker) or in the activation's QSO view. The dialog then also offers STOP RE-ANNOUNCING. When you change mode during an announced activation, qFT8 asks whether to announce the new mode too.

While it is open: the blue marker

A blue POTA or SOTA marker stays at the bottom right of the waterfall for as long as the activation is open, with the number of QSOs of the activation next to the word: POTA 10. Every QSO you log counts, and the number goes down again when a QSO is removed from the activation, deleted, or undone in the logger. With two parks at once there is still one number, because each QSO counts for both parks. Where there is little room the marker shows the number alone beside its icon, and where even that does not fit it is drawn smaller, together with the red warning that shares its line. Tap it for the state of the activation:

  • The reference and the count: QSOs made, out of the number the programme requires for a valid activation (10 for a park, 4 for a summit), and how many of them were with another park or summit (P2P / S2S).
  • SHOW ACTIVATION: the list of its QSOs (below).
  • FINISH ACTIVATION: ends it. It always asks first, with KEEP GOING to carry on.
  • DISMISS: closes the card.

The activation's QSOs

  1. Back to the whole QSO log.
  2. The activation: programme and reference, when it started (UTC), and its QSOs.
  3. +: Opens the logger to log a QSO by hand straight into this activation.
  4. ADD QSOs: Adds QSOs that are already in your log, by time range. Use it when you forgot to start the activation: choose from and to, and qFT8 says how many QSOs it will add before doing it.
  5. EXPORT: Writes the files to upload (below).
  6. The other station's park or summit, when it was activating too.
  7. The marker of the open activation.

To take QSOs out of an activation, long-press one to select it, tap any others, press ACTIONS and choose REMOVE FROM THIS ACTIVATION. The QSOs stay in your log; only your reference is removed from them. You can also move a single QSO from the QSO editor, with its POTA activation / SOTA activation row.

Finishing, and resuming

FINISH ACTIVATION shows a summary: references, start and end time, QSOs per mode, and whether the activation is valid. QSOs logged after finishing are not part of it.

  • Finished by mistake, or back after a break? For 24 hours, the summary, the activation's list and the POTA ACTIVATION / SOTA ACTIVATION start dialog offer RESUME ACTIVATION, which opens it again as if nothing had happened.
  • A new UTC day. For POTA, each UTC day is a separate activation. After UTC midnight qFT8 offers START NEW at the same park instead of resuming.
  • Left open. If qFT8 was closed for a while, or a long time passed without a QSO, it asks at the next start whether to CONTINUE or finish.

Exporting

EXPORT (in the summary and in the activation's list) writes ADIF files named the way each programme expects, ready to upload on its website:

  • POTA: one file for each park and each UTC day, named CALLSIGN@PARK-DATE.adi (for example K1ABC@US-1234-20261006.adi). A two-fer gives one file per park. A station that was itself in two parks is written once for each of its parks, so both count as park-to-park.
  • SOTA: one file for the summit, named the same way (K1ABC@W1_HA-001-20261006.adi).

You can save the files or share them. The magnifying-glass button next to POTA ACTIVATION / SOTA ACTIVATION in Settings lists your past activations, newest first, and marks each as ACTIVE, CAN RESUME, EXPORTED or not exported; tap one to open it and export it again. qFT8 does not upload to the programmes' websites itself.

Several parks in a row

On a day with several parks, one after the other, each park is its own activation and its own file:

  1. At the first park, press POTA ACTIVATION in Settings, type its reference and press START.
  2. Operate. Every QSO gets the park, and the blue marker counts them.
  3. Before you leave, tap the marker and press FINISH ACTIVATION, then EXPORT in the summary, and save or share the file (K1ABC@US-1234-20261006.adi).
  4. At the next park, start again with the new reference.

There is nothing to retype or to sort out at home. If you have no time to export in the field, the list of past activations (the magnifying glass) exports each one later.

"Which park goes in the file?"

A park's file can only name one park. When you export QSOs that were made from several parks at once without going through an activation (the whole log from Settings, or Export (ADIF) on a selection), qFT8 asks Which park goes in the file? Choose the park this file is for; export again for the other one. The log is not changed. Exporting from the activation itself never asks: it writes one file per park.

To get a file for every park without an activation, type the parks yourself, separated by commas (US-1234, US-5678), in the POTA reference box of EXPORT LOGS or in Export with a POTA reference on a selection: qFT8 writes one file per park, with the same QSOs in each. A summit is always one reference.

When the station you work is in two parks at once, qFT8 keeps both: it reads the second park from the spot's comment when the spotter wrote it there. The log shows the first park and how many more (US-1234 +1). If a park is wrong or missing, correct the POTA field of the QSO in the QSO editor; it takes several parks separated by commas. A park that is named twice for the same station (in the spot and again in its comment, or twice in a typed list) counts once, in the log and in every exported file.

JS8 Chat

When operating in JS8 mode, qFT8 provides a conversational free-text chat interface alongside traditional FT8/FT4 QSO operations. JS8 enables robust, weak-signal keyboard-to-keyboard messaging at multiple configurable speeds (Slow 30s, Normal 15s, Fast 10s, and Turbo 6s slots).

Channel Types & Routing

The chat panel on the right-hand side organizes incoming and outgoing traffic into separate channel tabs:

  • [GLOBAL] Master Channel: Displays every decoded JS8 transmission across the entire audio passband, as well as all of your own transmissions. This gives you a complete live overview of all band activity in one place.
  • Broadcast Group Channels (@CQ, @ALLCALL): Used for general calls and announcements to all listening stations. Messages sent to @CQ or @ALLCALL will be seen by anyone tuned to the frequency.
  • Custom Group Channels (@GROUPNAME): qFT8 supports custom directed groups (e.g. @EMERGENCY, @SOTA, @NET). When a message is sent or received with a @GROUP tag, it is automatically organized into its dedicated channel tab.
  • Direct Station Channels (Callsign Tabs): Selecting a specific station from the channel list or the stations table opens a dedicated conversation thread with that callsign.

Over-the-Air Transmission (Not Private): All JS8 messages are transmitted in the clear as standard amateur radio digital signals. Direct station chats route conversation history into a dedicated tab for convenience, but they are not encrypted or private and can be received by any station monitoring the frequency.

Composing & Sending Messages

  1. Select a Target: In the right-hand panel, tap a channel tab ([GLOBAL], @CQ, @ALLCALL, a group, or a specific station callsign).
  2. Enter Message: Type your text in the input box at the bottom (supports full standard ASCII text up to 100 characters).
  3. Send: Tap the Send button.

Tapping on Messages (Quick Chat & Details)

Tapping on any message in the chat log (on the computer: double-clicking it) opens a detail dialog showing the full UTC timestamp, audio frequency, SNR, Maidenhead grid, and message content:

  • Received Messages (RX): Tap CHAT to immediately open a direct chat tab with the transmitting station, or GROUP CHAT if the message was addressed to a group.
  • Transmitted Messages (TX): Tap RESEND to automatically re-populate the text input box and target channel to easily resend the message.

Multi-Chunk Message Streaming

If your message is longer than what can fit inside a single JS8 transmission frame:

  • qFT8 automatically splits the message into consecutive multi-chunk frames.
  • The app automatically transmits each chunk in sequential time slots until the entire message has been delivered.
  • A visual progress indicator displays the ongoing multi-slot transmission status (e.g. TX (1/3)).
  • If you need to stop sending before all chunks finish, tapping the Send/Stop button opens a prompt allowing you to cancel the remaining queued transmission.

Managing Channels (Long-Press Actions)

Long-pressing (holding; on the computer: right-clicking) on any station callsign tab or group channel tab in the right-hand panel opens a context menu with management options:

  • Clear Chat: Clears the message history for the selected channel tab.
  • Close Chat: Closes the tab and removes it from the active channel bar.
  • Export Chat: Exports the entire message history of the selected channel to a text file or share sheet.

Automated Query Replies (AUTO Mode)

When the AUTO button is enabled, qFT8 automatically responds to incoming directed queries sent by other stations (such as SNR?, HW CPY?, GRID?, INFO?, STATUS?, and HEARING?) as well as heartbeat messages (@HB HEARTBEAT).

For example, if another station transmits YOURCALL SNR? or YOURCALL HW CPY?, qFT8 will automatically enqueue and transmit your signal report response (e.g. SNR -08) without requiring manual intervention. Similarly, when receiving a heartbeat transmission (@HB HEARTBEAT), qFT8 will automatically enqueue a heartbeat acknowledgment (HEARTBEAT SNR -08) to report reception back to the transmitting station.

Directed Queries & The Request Button

The Request button allows you to quickly send standard directed queries to the currently selected target station or group without having to type the command syntax manually:

  • SNR? / HW CPY?: Requests a signal report from the distant station.
  • GRID?: Requests the station's Maidenhead grid locator.
  • INFO?: Requests the station's configured informational message.
  • STATUS?: Requests the station's operating status text.
  • HEARING?: Queries the list of stations heard by that station in the last 10 minutes.

WSPR Mode

WSPR (Weak Signal Propagation Reporter) is a specialized digital protocol designed for probing radio propagation paths using very low power transmissions. WSPR signals use narrow 4-FSK modulation with robust convolutional coding and sequential Fano decoding, capable of decoding signals well below the noise floor down to −28 dB SNR.

2-Minute Cycles & Timing

WSPR transmissions take place in synchronized 2-minute UTC slots (transmitting for 110.6 seconds with 162 tone symbols). Transmissions always start exactly one second into even UTC minutes (:00, :02, :04, :06...). Because one transmission lasts almost two minutes, a small radio must be allowed to transmit that long: see Continuous transmission limit. The spectrogram vertical scrolling automatically adapts to a smooth, slow scroll rate matching the 120-second cycle length.

Single-Pane Activity View

Because WSPR is a beaconing and propagation reporting protocol rather than a two-way conversational mode, qFT8 provides a streamlined, full-width single-pane activity log without QSO log splits:

  • Callsign: Station callsign.
  • DXCC Entity: Automatically resolved country / DXCC entity name (with flexible width).
  • Grid Locator: 4-character Maidenhead locator (e.g. JN45).
  • SNR: Received signal-to-noise ratio in dB, measured against the noise in 2,500 Hz as other WSPR receivers do.
  • Power Level: Transmit power reported by the station in dBm (e.g. 37 dBm).
  • Date & UTC Time: Timestamp of the transmission slot in UTC formatted as yyMMdd HH:mm.

Automated Beaconing & Tx Percentage

In the top header of the WSPR Activity screen:

  • BEACON Toggle: Arm or disarm automated beacon transmissions. When armed (highlighted in bright green), qFT8 automatically schedules beacon transmissions at deterministic intervals based on your configured Tx Percentage.
  • Tx % Selector: Configure the deterministic transmission duty cycle based on time elapsed since your last transmission (0% [Rx Only], 10%, 20%, 25%, 33%, 50%, or 100% Continuous). For example, 20% transmits deterministically every 10 minutes from your last transmission (50% = every 4 min, 33% = every 6 min, 25% = every 8 min, 10% = every 20 min, 100% = every 2-minute cycle continuously).
  • Send Button: Queue an immediate manual transmission for the upcoming 2-minute cycle boundary. After transmitting, automated deterministic beacon scheduling continues from that cycle.

WSPRnet & PSKReporter Spot Uploads

qFT8 can automatically upload received spots to the global WSPRnet database and PSKReporter:

  • Download spots from WSPRnet: Enabled by default, pulls real-time spots for your callsign and band to display on the World Map.
  • Upload reports to WSPRnet: When enabled under Settings → WSPRnet, received spots are batched and uploaded to WSPRnet with 15-minute deduplication and rate limiting.
  • Open WSPRnet in Browser: Directly opens the WSPRnet database filtered for your station's callsign.

Standalone ADIF Export

Tap the EXPORT button at the top right of the WSPR activity panel to export all spots recorded during the current session into standard ADIF format (.adi) for propagation study and record keeping.

SSB (voice)

In SSB mode qFT8 is the microphone and the loudspeaker of your transceiver: the signal the radio receives is turned into voice on your speaker or headphones, and your voice goes from your microphone to the radio. The radio stays connected exactly as it is for the digital modes (the same USB cable, the same sound card), so nothing needs to be re-plugged to change from FT8 to voice and back.

Pick SSB with the mode selector of the bottom bar. The message area, the sequence buttons and the cycle bar disappear (voice has no time slots), a USB / LSB button appears next to the mode selector, and the Stations tab becomes the SSB pane:

These are the components of the SSB screen in detail:

  1. RX / TX / RX/TX: Chooses what the tuning wheel (item #12) moves. With RX/TX you receive and transmit on the same frequency. With RX or TX only that one moves, so you can listen on one frequency and transmit on another (split).
  2. AUTO RIT: Keeps a station that is slightly off frequency centred, so its voice sounds natural without touching the wheel.
  3. The gear: Opens Settings > SSB (see below). BACK returns to this pane.
  4. QSO: Opens the logger with the mode, the sideband and the frequency already filled in, to log the contact you just made (see The logger). One QSO per press.
  5. Voice memories: Your recorded messages (a CQ call, your callsign...). Until you record one, this area shows the link Configure voice memories in Settings.
  6. IN: The level of your microphone and its gain slider. The line marked VOX is the level your voice must pass to key the radio when VOX is on (item #10): drag it.
  7. OUT: The level of the received audio and the volume slider of your speaker. The volume keys of the phone do the same.
  8. FILTER and NR: The receive filter (off, 2.7, 2.4 or 1.8 kHz) and the noise reduction (off, 1, 2 or 3). Each tap steps to the next value.
  9. PTT: Push to talk. It reads "hold to talk" or "tap to talk" depending on the PTT mode setting, and "ON AIR" while you are transmitting. On the computer the space bar does the same while the pane has the focus.
  10. VOX: When on, the radio is keyed by your voice instead of the PTT button.
  11. USB / LSB: The sideband. It is chosen for you when you change band (LSB below 10 MHz, USB above); a tap changes it and the frequency you read stays the same.
  12. The tuning wheel: In SSB the frequency scale of the spectrogram is a wheel. Swipe along it to tune the radio; a faster swipe takes bigger steps. A tap does nothing, so the frequency never jumps by accident. On the computer the mouse wheel tunes too (hold Shift for 1 Hz steps). Tuning needs a CAT connection to the radio.
  13. Frequency and band: The frequency you would say on the air (the carrier), and the band. The orange line and the RX/TX label under it mark the part of the spectrogram you are listening to and transmitting on.

Talking

  1. Arm transmission with the TX button of the bottom bar. As in every other mode, nothing transmits while it says TX OFF: the red line Press TX ON to transmit reminds you.
  2. Hold PTT and talk, then release it. Or turn VOX on and just talk.
  3. To send a voice memory, tap it. With TX ON it is transmitted, and you hear it on your speaker too. With TX OFF it is only played to you, which is a good way to check a recording. A long press (a right click on the computer) always only plays it to you.

Your own live voice is never played back on your speaker. If the frequency you are about to transmit on is outside the amateur band, qFT8 does not key the radio and says so.

PTT limit: With Tap to toggle and with VOX, a transmission stops by itself after the PTT limit (100 seconds unless you change it), and the PTT button counts the seconds left. After the limit, VOX stays paused for the same time, or until you tap PTT. This protects the radio from a microphone that keeps hearing noise. The radio's own continuous transmission limit also applies: the shorter of the two wins.

Voice memories

Go to Settings > SSB > Voice memories (or tap Configure voice memories in Settings in the pane) and press RECORD A NEW VOICE MEMORY. You can keep up to 6 voice memories of 30 seconds each. For each one you can give it a name, record it again, set its volume or press NORMALIZE, and cut silence from its start and end by dragging the two handles on the picture of the sound; PLAY plays the part you kept, and nothing changes until you save. Voice memories are part of the settings export, recordings included.

Settings > SSB

  • PTT mechanism: The PTT button, or VOX.
  • PTT mode: Hold to talk or Tap to toggle.
  • PTT delay: The time between keying the radio and sending your voice. Nothing you say is lost: your first syllable waits for the radio.
  • PTT limit: See above (10 to 600 seconds).
  • Sideband: Automatic by band, always USB, or always LSB.
  • Filter and noise reduction when entering SSB.
  • Play the received audio on the speaker and Mute the speaker while transmitting.
  • Voice memories and RESET TO DEFAULTS.

What SSB needs

  • A microphone and a speaker that are not the radio's sound card. A phone has its own; a headset works too. See Speakers and microphone. If the radio and your microphone or speaker are the same device, a red line says so and nothing is sent or played.
  • A radio. Without one the pane is replaced by a card that says Connect a radio to use SSB; the pane comes back by itself when the radio is connected. A radio without CAT that is keyed by its own VOX works as well, but then the app cannot tune it.
  • A QMX or QMX+ needs firmware 1_02_000 or newer to transmit voice from the app. With older firmware the bottom bar says No SSB and the mode is receive only.
  • The first time you visit a band in SSB, qFT8 tunes to the usual voice frequency of that band for your part of the world; after that it comes back to the last frequency you used there. The 30 m band has no voice segment and is not offered.
  • The radio stays in its USB data mode (USB-D, DATA-U, DIGU on a Flex) on purpose: qFT8 makes USB or LSB itself, so on LSB bands the radio's display shows a frequency 3 kHz below the one qFT8 shows. Talk into the microphone chosen in Speakers and microphone and use qFT8's PTT, not the radio's own.

QSOs are logged as SSB with their sideband, and are uploaded to QRZ and LoTW like any other QSO.

CW (Morse code)

In CW mode qFT8 reads every Morse signal in the passband and writes its text on the spectrogram, and sends Morse from on-screen paddles, your own keys, ready-made messages or typed text. With TX OFF everything works as practice: you hear your sending on the speaker and nothing goes on the air.

Pick CW with the mode selector of the bottom bar:

These are the components of the CW screen in detail:

  1. AUTO: Lets qFT8 hold whole CW QSOs by itself (see AUTO in CW).
  2. RX / TX / RX/TX: Chooses which bar a tap on the waterfall or the tuning wheel moves: the receive bar, the transmit bar, or both together.
  3. The gear opens Settings > CW, and QSO opens the logger with CW, the frequency and the target already filled in.
  4. Target: The callsign of the station you are working. It fills the [TARGET] part of your messages. Tap it to type one, or tap a callsign in the decoder line (item #10) to take it from there.
  5. Memories: Ready-made messages. A tap sends one. Your own callsign is shown in blue and the report in yellow. A memory that still needs something (a target, your name...) is dimmed; tap it to see what is missing.
  6. WPM and FARNSWORTH: The sending speed in words per minute, and the optional Farnsworth speed (the letters keep their speed and the gaps between them get longer).
  7. FILTER and NR: The width of the receive filter around the receive bar, and the noise reduction.
  8. The paddles: The left one sends dits and the right one sends dahs. Press both for the iambic modes.
  9. The red line: Press TX ON to transmit. While it shows, your keying is practice.
  10. The decoder line: Where the message selector is in FT8. It shows the text of the station inside your filter in green and what you send in red, newest at the right.
  11. Decoded text on the waterfall: Every signal has its text written along its own trace, so you can read the whole band at once. The label under the receive bar shows the callsign and speed of the station you are on.
  12. The tuning wheel: The frequency scale. Swipe along it to move the selected bar (and the radio, when the bar reaches the edge). A tap or a drag on the waterfall moves the bar directly.
  13. Go to frequency: Tap the strip with the white signal-strength line to type a frequency in kHz.

Sending

There are four ways to send, and all of them use the speed set with WPM:

  • The paddles on the screen, with one or two fingers.
  • Your own keys: keyboard keys, the mouse buttons (on the computer the left button is the left paddle and the right button the right paddle), or a keyer adapter connected by USB or Bluetooth that behaves as a keyboard. See Paddles and keyer.
  • A memory: tap it. A second memory tapped meanwhile waits its turn. A strip with STOP appears while a text is being sent, and touching a paddle stops it too.
  • Keyboard (at the end of the memories): type a message and press SEND. A line under the box shows exactly what will be sent. On Android, Voice does the same from speech: say the message and it is sent as Morse.

On the air, CW is always a clean tone with soft edges, whatever sidetone you choose to hear. As a safety net, a key held down for 10 seconds is released and a transmission is stopped after 3 minutes.

Practice with TX OFF

While the bottom bar says TX OFF, the paddles, your keys, the memories and the Keyboard box all work, but only on your speaker. What you key is decoded and shown in red in the decoder line, so you can see whether your sending is readable. Nothing reaches the radio. No radio is needed at all for this.

Paddles and keyer

In Settings > CW, the Keyer section sets how the paddles behave:

  • Keyer mode: Straight key, Iambic A, Iambic B, the one-finger versions of both, Ultimatic, Bug (semi-automatic) and Cootie (sideswiper).
  • Speed, Farnsworth, Word spacing and Strict timing (standard gaps between letters and words).
  • Inverse paddles: swaps dits and dahs.
  • Break-in delay: how long the radio stays on transmit after your last dit or dah.
  • Speed matching: send at the speed of the station you are copying.

The Paddle input section sets what counts as a paddle:

  • Paddles: the main switch. Off means no paddles on the screen, and no key, mouse button or adapter can key the transmitter.
  • On-screen paddles, Mouse buttons, Keyboard keys and External adapters (USB / Bluetooth): each source can be switched off on its own.
  • Key mapping: Default uses a ready-made list of keys (among them [ and ], the left and right Ctrl keys, F1 and F2). With Custom you build your own lists for the left and the right paddle: press ADD A KEY and then the key you want. A key that is already on the other paddle is refused.

While a text box is open, only the Ctrl keys and F1 / F2 act as paddles, so typing a callsign never sends Morse.

Keying with an adapter, the keyboard or the mouse

You do not have to tap the screen to send Morse. Four things can act as the paddles, and they can all be used at the same time:

  • The paddles on the screen, with your fingers.
  • A real key or paddle on a USB key adapter: a small box or cable with a socket for the key on one side and a USB plug on the other. To the phone or the computer it is a keyboard (each contact of the key presses a keyboard key) or a mouse (each contact presses a mouse button). Bluetooth adapters work in the same way.
  • A keyboard: one key for the left paddle and one for the right paddle.
  • A mouse: its left and right buttons.

All of them follow the Keyer mode and the speed you have chosen, and all of them work with TX OFF as practice (see Practice with TX OFF).

Connecting an adapter

  1. Plug your key or paddle into the adapter, and the adapter into the phone, the tablet or the computer. Nothing has to be installed and qFT8 asks for no permission: the adapter is an ordinary keyboard or mouse. On a phone whose only USB socket is taken by the transceiver, use a USB hub or a Bluetooth adapter.
  2. Open the CW screen and key. An adapter that acts as a keyboard works at once when it sends keys of the default list below (the left and right Ctrl keys, and [ and ], are the usual ones). It was tested with the original VBand adapter.
  3. If nothing sounds, the adapter sends other keys. Go to Settings > CW > Paddle input, press ADD A KEY under Left paddle (dit) and close the dit contact of your key; then do the same under Right paddle (dah) with the dah contact.
  4. An adapter that acts as a mouse needs the paddles on the screen: leave the mouse pointer over the left paddle and key. The same goes for an ordinary mouse.

A straight key, a paddle, a bug

Keyer mode (Settings > CW > Keyer) decides what the two sides do, whatever you key with:

  • Straight key: one key, and you make every dit and dah by hand. Only the left paddle side keys: connect a straight key to the adapter's dit contact, or put its key in the Left paddle (dit) list. On the screen the two paddles become one single key.
  • Iambic A and Iambic B: for a paddle with two levers. The left side makes dits, the right side dahs, and both together alternate them.   • Ultimatic: like a paddle, but with both sides pressed the one pressed last wins.
  • Bug (semi-automatic): the dit side makes dits by itself; the dah side is a hand key, and sounds for as long as you hold it.
  • Cootie (sideswiper): both sides are the same hand key.

Making it yours

Everything is in Settings > CW, in the section Paddle input:

  • Paddles: the main switch for all that follows.
  • On-screen paddles and Paddles height: hide the paddles to leave more room for the waterfall when you only use a real key, or make them taller for your fingers. The mouse needs them shown.
  • Mouse buttons: switch it off if a click on the paddles should do nothing.
  • Keyboard keys and External adapters (USB / Bluetooth): who may key. See the differences between Android and the computer below.
  • Key mapping: Default is the table above. Under it are the two lists, Left paddle (dit) and Right paddle (dah). ADD A KEY waits for you to press a key (or to close a contact of your key) and adds it; the bin beside a key removes it. The first change turns the mapping to Custom, which starts as a copy of the default lists. Going back to Default does not erase your own lists. You can use letters, digits, F1 to F12, the arrows, Ctrl, Shift, Alt, the numeric pad, Space, Enter, Tab and the common punctuation keys. A key can be on one paddle only.

Two more options are in the Keyer section: Inverse paddles swaps dits and dahs for every source at once (for a paddle wired the other way round, or a left-handed operator), and Keyer mode is described above. RESET TO DEFAULTS, at the end of the page, puts every CW setting back, the key lists included.

Android and the computer

  • On Android there are two switches: Keyboard keys is the device's own keyboard, and External adapters (USB / Bluetooth) is every keyboard or adapter you plug in or pair. Before Android 10 every physical keyboard counts as external. A USB or Bluetooth mouse works over the paddles as on the computer.
  • On the computer an adapter is one more keyboard, so there is one switch, Keyboard keys, for both. The paddles on the screen are pressed with the mouse. Keys only act while the qFT8 window with the CW screen is the active window and no dialog is open.

If something does not work

  • Dits and dahs are swapped: tick Inverse paddles. With the mouse, check that the pointer is over the left paddle, not the right one.
  • Nothing happens when you key: the CW screen must be showing, Paddles and the switch of your source must be on, and AUTO must be off (the screen says Disable AUTO to transmit manually). On the computer, click on the qFT8 window first. Then check that your key is in the lists: press ADD A KEY and key. If the dialog does not react, the adapter is sending a key that cannot be used, or it is not connected.
  • You hear the Morse but the radio does not transmit: the red line says Press TX ON to transmit. That is practice.
  • A straight key does nothing in the mode Straight key: it is on the right paddle side. Move it to the left one (see above).
  • Keying types letters into a box instead of sending: while a text box is open only the Ctrl keys and F1 / F2 are paddles, so that typing a callsign never sends Morse. Close the box, or give your adapter one of those keys.
  • Keying types into another program: on the computer the keys go to the active window. Click on qFT8.
  • The tone stops while you hold the key: a key held for 10 seconds is released, with the notice Key held down too long: released.

Memories, macros and prosigns

Edit your messages in Settings > CW > Memories (ADD MEMORY, or tap one to change it). Two kinds of special words can be used in a message:

  • Macros, in square brackets, are replaced when the message is sent: [MYCALL] your callsign, [TARGET] the callsign in the Target box, [RST] the report to send, [NAME] your name, [QTH] your location, [EXCH] your contest exchange and [MYPOTA] the park or summit of your open activation. The editor has a button for each of them, and shows the message exactly as it will be sent.
  • Prosigns, in angle brackets, are sent as one character without gaps: <BK>, <SK>, <KN>, <AR>, <BT>, <AS>, <SN> (understood), <KA>, <CL>, <HH>, <SOS> and the other standard ones. Two names for the same sign (<SN> and <VE>, <SK> and <VA>, <KA> and <CT>, <DO> and <NJ>) send the same thing; the decoder shows the first name unless you choose otherwise in the CW settings (below).

Your report, name, location and exchange are typed once, in the same Settings page. A ready-made message that needs one of them stays dimmed until you fill it in, and tapping it takes you to the place to do so. While a POTA or SOTA activation is open, a CQ POTA message is offered as the first memory.

Receiving

Decoding is automatic and follows each station's own speed. The station inside your filter is the one written in the decoder line of the bottom bar; move the receive bar onto another signal to follow that one instead (what was already copied on that frequency is shown at once). When two stations are inside the filter the bottom bar says so. The received signal is played on your speaker at the Monitor pitch you choose, the same pitch as your own sidetone, so a station that sounds at the same note as your sidetone is exactly on your frequency.

Settings > CW also has Tones (how your sidetone sounds: pitch, volume, soft or hard edges, a tone or sounder clicks), Decoding and display (Auto-decode, Multi-decoder for the text of every signal on the waterfall, the horizontal spectrogram, the filter when entering the mode), Monitor (speaker) and Prosigns and signs.

AUTO in CW

The AUTO button at the top left of the pane lets qFT8 hold complete CW QSOs. It is off every time you enter the mode. Tap it to switch it on (it turns green) and again to switch it off. It only ever sends while TX is ON: AUTO never arms transmission by itself.

While it is on, and TX is ON, qFT8:

  • calls CQ when the frequency is quiet, or answers a CQ it hears;
  • exchanges reports, name and location, signs off, and logs the QSO;
  • asks again for a callsign or a report it could not copy, and answers requests to repeat or to slow down;
  • never sends faster than your WPM, and slows down to the other station's speed;
  • follows a station that drifts, does not call a station already worked that day, and does not start over somebody else's QSO;
  • never logs a QSO it could not complete.

While AUTO is on the paddles are disabled and a line says Disable AUTO to transmit manually. STOP also switches AUTO off. If you never want it, turn Show auto mode off in Settings > CW and the button is hidden.

RTTY

RTTY (radioteletype) sends text as two alternating tones. In qFT8 it shares the screen of CW, without the paddles: every RTTY signal in the passband is decoded, each at its own speed and shift, and written along its trace on the waterfall.

These are the components of the RTTY screen in detail:

  1. Target and Exch: The callsign of the station you are working and the contest exchange. They fill [TARGET] and [EXCH] in your messages.
  2. BAUD: The speed: 45.45 (the usual one), 50 or 75. Each tap steps to the next.
  3. SHIFT: The distance between the two tones: 170 Hz (the usual one), 200, 425 or 850 Hz.
  4. REV: Swaps the two tones, for a station that sends them the other way round.
  5. FILTER and NR: The receive filter and the noise reduction.
  6. Memories: Ready-made messages with the same macros as in CW. A tap sends one. A message with an empty field is dimmed. Keyboard (and Voice on Android) are at the end of the list.
  7. The decoder line: The text of the station under the receive bar, in green; what you send, in red.
  8. The receive bar and its label: The label shows the callsign, speed and shift of the station under the bar. A tap near a signal puts the bar on its centre.
  9. tap to match: When the station under the bar uses a different speed, shift or tone order than yours, an orange line says so. Tap it and qFT8 takes that station's values, so that you can answer it.
  10. Other signals: Their text is written along their own traces. An orange tag such as 50 Bd or 425 Hz marks a signal that differs from your settings.
  11. Frequency: In RTTY the header shows the mark frequency , which is the frequency operators quote and the one written to the log.

Sending

Arm TX, then tap a memory, or open Keyboard, type and press SEND. A strip with STOP shows while the text goes out. With TX OFF the same actions are a preview: the message is played on your speaker and shown in red, and nothing goes on the air. Characters that the RTTY code does not have are left out and listed.

RTTY is a continuous full-power transmission, so the radio's continuous transmission limit applies: a message longer than the limit is not started, and a transmission stops when the limit is reached.

Settings > RTTY

  • Modem: speed, shift, Reverse, the Figures table (International (ITA2) or US: they differ on five signs, and both stations must use the same one) and Unshift on space when receiving and when sending (after a space the text goes back to letters, so a lost shift spoils one word at most). Stations that broadcast groups of numbers, such as weather stations, do not repeat the shift after each space: their number groups print as letters while Unshift on space when receiving is on, so switch it off to read them.
  • Transmit: a new line at the start and end of each transmission, idle characters while there is nothing to send, and an automatic new line after a number of characters.
  • Decoding and display, Monitor (speaker), Memories with their values (report, name, location, exchange) and RESET TO DEFAULTS.

QSOs made with the QSO button are logged as RTTY. There is no AUTO in RTTY.

Settings > JTTY

JTTY (the JTTY (experimental) row of the mode selector) uses this same pane with the JTTY modem. Its settings have their own page, next to RTTY in the settings list; the pane's gear button opens it while the pane runs JTTY. It has only what JTTY uses: Decoding and display, Monitor (speaker), Memories with their values and RESET TO DEFAULTS; the Modem and Transmit settings of RTTY do not apply to it. The first time JTTY is used it takes over what you had changed in Settings > RTTY (for example your memories, name and location); anything you had not changed starts at JTTY's own defaults, such as short memories that each fit one JTTY message. After that, changing one does not change the other.

SSTV (pictures)

SSTV (slow-scan television) sends a still picture as sound, line by line, in one to four minutes. qFT8 receives pictures by itself while you are in the mode, and sends pictures from your gallery with your callsign written on them.

Pick SSTV with the mode selector of the bottom bar. The left half of the pane is for sending and the right half for receiving:

These are the components of the SSTV screen in detail:

  1. SEND: The mode the picture will be sent in, with its size. The mode is chosen with item #12.
  2. LOAD: Offers "Choose a picture" (from the gallery or a file), "Take a photo" (on a phone or tablet with a camera) and "Ready-made pictures": about twenty drawings made by qFT8 at the size of the mode with your callsign on them (CQ cards, the qFT8 logo, landscapes, optical illusions, a QSL card, 73...). You can also share a picture to qFT8 from another app; if another mode is in use, qFT8 asks before switching to SSTV.
  3. The picture to send, shown exactly as it will be sent. Tap it to fit it to the shape of the mode: show it whole, crop it (drag to move, pinch to zoom), rotate it, and adjust brightness and contrast.
  4. Text style: The arrows step through the ways your callsign is written on the picture (a band at the bottom, a corner, a big outline... or no callsign). The pencil adds a free text.
  5. DROP removes the loaded picture. SEND shows how many seconds the transmission will take, and becomes STOP with the seconds left while it is on the air.
  6. The red line: Press TX ON to send pictures. Under it, the room left is filled with small pictures: the last pictures you loaded, then the ready-made ones. One tap loads one as the picture to send (it is never sent until you press SEND).
  7. Receive status: LISTENING, or RECEIVING with the mode, how far off frequency the station is, and the line being drawn.
  8. The received picture, drawn as it arrives. Under it: the time, the mode and the progress, and, once the picture is complete, the callsign field.
  9. SAVE stores the picture in the pictures folder of the device (pressed while the picture is still arriving, it saves it when it ends). EDIT improves a received picture (contrast, brightness, colour, hue, sharpening, noise removal); the picture as received is always kept, so every change can be undone. REPLY loads the received picture as the one to send, with the other station's callsign next to yours.
  10. Kept pictures: The latest received pictures. Tap one to show it again.
  11. The gear opens Settings > SSTV, and QSO opens the logger with mode SSTV.
  12. The SSTV mode selector: Martin, Scottie, Robot, PD, Wraase and Pasokon modes. Next to it, the message area says what is happening ("listening", "receiving", "sending" with the seconds left).
  13. The SSTV slot: Pictures are sent and received between 1100 and 2300 Hz. Each picture heard or sent gets a box on the waterfall with its mode.

Receiving pictures

There is nothing to set. qFT8 recognises the mode of every transmission from its start signal, and also when you tune in after the picture has started (the lines already missed stay empty). A picture sent slightly off frequency, or by a station whose timing is a little off, is straightened automatically. If two stations send at the same time on clearly different frequencies, both pictures are received and kept; tap a box on the waterfall to choose the one shown.

The app keeps the latest pictures by itself. With Auto-save every received image to the device they are also written to the pictures folder; otherwise you save the ones you want.

Whose picture is it? The callsign field

Many stations identify themselves around their picture, in Morse code before or after it, or with a short data burst after it. qFT8 reads both, and writes the callsign in the field beside the time and mode under the picture. When nothing was heard the field says Callsign unknown. Tap the field to type the callsign yourself (often it is written on the picture) or to correct it; what you type replaces what was heard.

Saved pictures are named with the date and time (UTC), the band, the frequency in kHz, the mode and the callsign, for example 2026-10-05_1431_20m_14230_M1_F4ABC.png, or ..._UNKNOWN.png when there is no callsign. If the callsign arrives or is typed after the picture was saved, the saved file is renamed; no second copy is made.

Sending a picture

  1. Choose the mode with the selector of the bottom bar. If you answer a station, use the mode it used. Robot 36, Martin 1 and Scottie 1 are the common ones.
  2. Tap one of the small pictures under SEND, or press LOAD, pick the picture, and fit it if asked.
  3. Choose how your callsign appears with the arrows.
  4. Arm TX and press SEND.

Switching TX off, pressing STOP, or changing band or mode stops the picture at once. If a picture is arriving when you press SEND, qFT8 asks before it stops receiving.

Long modes and small radios: A picture is one continuous transmission at full power: about 40 seconds in Robot 36, two minutes in Martin 1, and more than four minutes in the slowest modes. A mode that is longer than your radio's continuous transmission limit is greyed out in the list, and choosing it explains why. With a QMX at its default of 60 seconds, the short modes work as they are.

Settings > SSTV

  • Send your callsign in CW: off, before the picture (the default), after it, or both. Only the callsign, at 20 WPM; its seconds count in the transmission time.
  • Send FSK ID after each picture: a short data burst that lets the other station's program read your callsign.
  • Text style, Auto contrast and Sharpen automatically.
  • Auto-save every received image to the device and how many received pictures are kept in the app.

A QMX or QMX+ needs firmware 1_02_000 or newer to send pictures; with older firmware SSTV is receive only.

Feature documentation

Settings and tools that are not tied to one mode: two per-radio settings of DEVICE CONFIGURATION, the web page to operate qFT8 from another device, the bridge that lets you leave the radio in another room, and the arrangement of the screen.

Tune spectrogram offset

In Settings > DEVICE CONFIGURATION, under Tuning (this radio), Tune spectrogram offset shifts what the spectrogram shows by up to 300 Hz down or up. Its default is 0 Hz; a value you set is kept, separately for each radio.

What it is for: most radios have a blind spot at the very bottom of the audio, about 0–50 Hz (0–90 Hz on Icom radios), so the lowest part of the spectrogram stays empty. With an offset of −50 Hz (−90 Hz on an Icom), qFT8 tunes the radio that much lower and shifts the audio back by the same amount: the app shows what it should, and you gain 50 or 90 Hz of extra spectrogram.

Nothing else changes: the frequency shown, the stations' offsets, the spots, your transmit frequency and the log stay the same. Only the radio's own display reads lower by the amount of the offset. The offset works in every mode and needs a CAT connection; with VOX or the speaker it does nothing.

Continuous transmission limit

This is a safety setting for the transmitter. Small radios are built for short transmissions with pauses: an FT8 transmission lasts under 13 seconds and is followed by at least 15 seconds of rest. Some modes key the radio at full power for far longer without a break, and that can overheat the final amplifier of a small radio. The continuous transmission limit is the longest time qFT8 keys your radio in one go.

It is in Settings > DEVICE CONFIGURATION, under Tuning (this radio). The choices are 20, 40, 60, 90, 120 and 150 seconds, and No limit. Under each choice qFT8 lists what that choice adds, so you can see what you gain by raising it. The setting is kept separately for each radio.

The default for each radio

  • 60 seconds: QRPLabs QMX, QMX+ and QDX, and the (tr)uSDX.
  • 120 seconds: Xiegu X6100 and X6200.
  • No limit: every other radio, and a radio used through VOX or the speaker (qFT8 cannot know which radio that is).

These defaults are cautious. You know your radio, its power setting and its cooling: change the limit if they allow it. qFT8 never raises the limit by itself.

What the limit does

  • A transmission with a known length that is longer than the limit is not started. This is why WSPR and the long SSTV modes ask you to raise it: a WSPR transmission lasts 111 seconds, and many SSTV pictures take two minutes or more. When you choose such a mode, or press TX ON in it, a message tells you how many seconds it needs and what the limit of your radio is, with a button Open the setting. Transmission is not armed until the limit allows the mode.
  • A transmission without a fixed length stops when the limit is reached, and the radio goes back to receive: TUNE, SSB (the PTT button, VOX and voice memories) and RTTY. A notice says that the limit was reached.
  • CW is not limited: a key is down only part of the time.

QMX and WSPR: With a QMX, QMX+ or QDX, WSPR needs the limit raised from 60 to 120 seconds. For the radio's safety qFT8 asks you to do it once, by hand. Consider lowering the power of the radio for WSPR: it is a low-power mode by design.

In a wide window the spectrogram is on the left and the selected pane on the right; in a tall one, such as a phone held upright, the spectrogram is on top. The bar at the bottom has the same controls as the app's: the TX button, the message, the sequence, the mode and the band, and the buttons for the stations, the QSO log, the world map and the settings. The waterfall moves live, with the same labels as in the app. This is the stations view in a tall window:

It allows operating with the AUTO button, criteria dropdown, + button to directly add callsigns, and the list of stations with CALL buttons to manually call them. The small light at the right end of the bar is green while the page is connected to qFT8.

Network & Connectivity

The server opens a specific TCP port (default 13497) on your phone or computer. To access it, your devices must be able to "see" each other on the network:

  • Local Network: Both the phone or computer running qFT8 and your control device (computer, tablet, or phone) must be on the same network.
  • Router Settings: Some routers have a feature called AP Isolation (or Client Isolation) enabled by default. This must be disabled for devices to communicate with each other.
  • Mobile Hotspot Scenario: If you are in the field, you can open a Wi-Fi hotspot on one phone (with internet) and connect the qFT8 phone to that Wi-Fi network. After connecting, close and reopen the web server in qFT8 settings; the IP address shown will then be accessible from the hotspot-providing phone.
  • Internet Access: Accessing the server from outside your home (over the internet) requires Port Forwarding in your router settings (mapping the internal IP and port to an external one). Note that this generally will not work over 5G/LTE connections due to carrier NAT restrictions.

Access Levels

You can configure the remote security level in the settings pane:

  • Read only: Allows viewing the live spectrogram, active stations, and the QSO log. No actions can be performed.
  • Read + Stop TX: Primarily a safety mode. Allows viewing all data and permits disarming the transmitter (stopping TX) in case of an emergency, but does not allow starting TX or changing settings.
  • Full control: Grants complete authority over the application, enabling all interactive features.

Security Note: Anyone with access to your network, IP address, and port will have the level of control you have configured. If set to Full control, they could potentially start transmitting using your station.

Capabilities

In Full control mode, the web interface offers nearly everything the app UI does:

  • Operation Modes: Toggle between AUTO and manual CALL modes.
  • Strategy: Change the AUTO criteria (Anyone, DXCC, Grid, etc.) and search constraints.
  • Transmission: Manually start/stop TX, choose specific TX messages, and change the FT8 sequence (0/1).
  • Frequency & Band: Tap the web spectrogram to move your frequency offset or change the active radio band.

SSB, CW, RTTY and SSTV are operated in qFT8 itself. While the app is in one of them, the web page shows the waterfall and whether the app is transmitting, and does not transmit; choose a digital mode on the page to work from it again.

The radio's continuous transmission limit holds for the page exactly as for the app. When it keeps TX off (for example WSPR with a limit of 60 seconds) or stops TUNE, the page shows a notice for a few seconds that says why, so you are not left wondering in front of a button that does nothing. The limit itself is only changed in the app.

Note: The web UI is designed to remain responsive even if the phone's screen becomes sluggish due to RF interference, providing a reliable fallback for control.

Note: The web server will function when the screen is off if the settings to run in background are enabled (the default is to keep running in the background when qFT8 is connected to a transceiver).

qFT8 bridge

The qFT8 bridge lets you leave the radio in one place and operate from another. A device beside the radio, the bridge, passes the radio's commands and its audio over your own network to qFT8 on another device. That qFT8 does everything else: it decodes, logs and decides what to send. For it, the radio works as if it were plugged in by USB.

Use it when the radio sits near the antenna, in the attic, the garage or the garden shed, and you want to operate from somewhere more comfortable; or when the device beside the radio should only look after the radio: a small computer such as a Raspberry Pi, or an old phone or tablet.

This is not the same as the Remote Control Web Server. There, qFT8 runs beside the radio and you look at it from a browser. With the bridge, qFT8 runs on the device in front of you and only the radio is somewhere else.

What you need

  • A device beside the radio, with the radio connected to it by USB as usual: a computer with Windows, macOS or Linux (a Raspberry Pi is enough), or an Android phone or tablet. This one is the bridge.
  • qFT8 on the device you operate from: the computer program or the Android app. Any of them can use any bridge: a phone can operate a radio beside a computer, a computer a radio beside a phone, and so on.
  • Both on the same local network. A network cable works as well as Wi-Fi and is steadier; if you can, give at least the bridge a cable. A phone or tablet uses its Wi-Fi, never its mobile data.
  • The bridge's password. The bridge makes one and shows it to you.

Setting up the bridge

There are two ways to run a bridge. Pick one.

1. From qFT8's Settings (the computer program or the Android app). On the device beside the radio, open Settings > qFT8 BRIDGE and tick Run as a qFT8 bridge on port. Leave the port as it is unless another program uses it.

Password shows the password the other device will need. NEW PASSWORD makes another one; touch the password itself to type your own (7 characters or more).

While it is a bridge, qFT8 on that device does nothing else. TX is switched off, its own use of the radio stops, and the screen shows only qFT8 running in bridge mode, with the Address and the Password to enter on the other device and who is using the radio (Nobody is connected, or the device's name). On Android the bridge keeps running with the screen off, shown by a notification; keep the phone or tablet on its charger.

TURN BRIDGE MODE OFF asks first, because the other device loses the radio at once, and then brings qFT8 back as it was, with TX still off. If you close qFT8 while it is a bridge, it starts as a bridge again next time.

2. From the command line (computers only). For a computer that has no other job, also a Raspberry Pi or a server without a screen: start qFT8 with --bridge. It then runs only as a bridge, with no window, and loads nothing else of qFT8 (no settings, no decoding), so it needs very little memory. Use the qFT8 you downloaded for that computer, from a terminal:

  • Windows: open a Command Prompt in the qFT8 folder and type qFT8.exe --bridge --tx-volume 70. If Windows asks whether to allow "OpenJDK Platform binary" on your networks, allow it.
  • macOS: in Terminal, type /Applications/qFT8.app/Contents/MacOS/qFT8 --bridge --tx-volume 70. The first time, macOS asks for the microphone: allow it, that is how the radio's audio is read.
  • Linux: in the qFT8 folder, type ./qFT8 --bridge --tx-volume 70.
  • Any computer with Java 21 or newer, for example a Raspberry Pi with the Java of its system: the qFT8 .jar download runs on every system. Type java -jar, the name of the .jar file, and --bridge. It carries what it needs to use serial ports on Windows, macOS and Linux (PCs and ARM boards, 32 and 64 bits).

The terminal shows the password at the first start and keeps it for the next ones. Leave the terminal open: the bridge runs as long as it does. Ctrl+C, or closing the terminal, stops it and puts the radio back to receive.

Options you may want, added after --bridge:

  • --tx-volume N: required: the audio level, 1 to 100 %, the bridge sets on the radio's sound device for transmitting, as qFT8's own TX volume setting (70 is its default; QRP Labs radios: 100). It is the sound level only: the radio's power is never changed.
  • --password TEXT: your own password instead of the one it made.
  • --show-password: show the kept password again.
  • --new-password: make a new one.
  • --name TEXT: the name other devices see in their list (it is "qFT8 bridge" otherwise), useful with more than one bridge.
  • --only TEXT: share only the radio's serial port and sound device, named by a part of their name (for example --only QMX); nothing else of the computer is offered.

--bridge --help lists the rest.

Connecting from qFT8

On the device you operate from, open Settings > DEVICE CONFIGURATION and tick Connect through a qFT8 bridge, at the very top. These rows appear:

  • Method: qFT8 bridge.
  • Bridge: opens the list of the bridges qFT8 finds on your network. Pick yours. Search again looks once more. If yours is not listed, choose Type address and enter the address the bridge shows.
  • Password: the one the bridge shows.
  • CONNECT: the box beside it turns green and reads Connected to followed by the bridge's name.
  • Radio port on the bridge, Sound device on the bridge (receive) and Sound device on the bridge (transmit): what the radio is plugged into on the bridge's side. AUTO finds them; choose by hand only when the bridge has several. A radio reached through its own program on the bridge computer (a virtual serial port and a virtual audio cable) has a port AUTO cannot recognise: choose the port by hand, and check that both sound devices are the cable's.

From here on everything is as with a USB radio: qFT8 recognises the radio, reads its frequency, receives and transmits. qFT8 remembers the bridge and its password, and a settings export carries them to your other devices. While the box is ticked, a radio plugged into the device you operate from is not used. To go back to it, untick Connect through a qFT8 bridge; no restart is needed.

On a phone or tablet the status box reads No Wi-Fi. Connect this device to the bridge's network. when it is not on a Wi-Fi network: the bridge is only looked for there.

The link display

Under the bridge's devices, one line tells you how the link is doing, for example Delay 120 ms, adjusted by itself. Link: steady (jitter 3.0 ms).

  • Delay: a network never delivers sound perfectly evenly, so the audio is held for a moment before it is played, to iron that out. There is nothing to set: qFT8 and the bridge choose the delay themselves, raise it when audio arrives late and lower it again once the link has been clean for a while. It does not disturb the timing of the digital modes: your transmissions still start on time, and what you receive is placed by the moment the radio heard it.
  • Link: steady: all is well.
  • Link: irregular: audio is arriving unevenly. The delay takes care of it; there is nothing to do unless it stays like this.
  • In red, The link to the bridge is losing transmit audio: part of a transmission did not reach the radio in time. The delay is raised at once; if this keeps happening, see Troubleshooting.
  • In red, The link to the bridge cannot keep up: even the largest delay is not enough and transmit audio breaks up. See Troubleshooting.

Right after connecting the line reads Nothing measured yet.

Transmit safety

  • Only you switch TX on, with the TX button of the qFT8 in front of you. The bridge never starts a transmission by itself.
  • If the link drops (the Wi-Fi goes away, the device sleeps, qFT8 is closed), the bridge puts the radio back to receive by itself, within a second or two. qFT8 stops what it was sending, switches TX off and shows a red card that says why, such as Connection lost. Connecting again... It reconnects by itself. If the link is back within 10 seconds and you had TX on, qFT8 switches it on again once, as you had it; after a longer drop it stays off until you press it again.
  • The continuous transmission limit of your radio is kept by the bridge as well.
  • Stopping the bridge, either way, also puts the radio back to receive.

Security Note: The password protects control of your radio: nobody without it can use the bridge, and the password itself is never sent over the network. It does not make the link private: the audio and the radio's commands are not encrypted. Use the bridge inside your own network only, and do not open it to the internet.

Limits

  • Local network only. The bridge is not made to be reached over the internet. A VPN that sends your home network's traffic through its tunnel hides the bridge too: turn it off, or allow local network access in it, on both devices.
  • One device at a time. When a second device connects, it takes over; the first one reads Another device took over the bridge. Press CONNECT to take it back.
  • Every mode works through a bridge, receiving and transmitting: FT8, FT4, FT2, JS8, WSPR, LQ8, SSB, CW, RTTY, SSTV and TUNE. Your loudspeaker and microphone stay on the device in front of you; only the radio's audio crosses the network.
  • A radio that is switched to transmit by a control line (RTS or DTR) instead of a command is keyed through the bridge too.

qFT8log

qFT8log keeps the logs of several qFT8s together over your own network. One qFT8 is the qFT8log server; the others send it every QSO they make. The server adds them to its own log (the QSO list, the map, the statistics) and sends them on to the services set up on it, such as QRZ and LoTW. What happens to a QSO later, a confirmation or a correction, comes back to the qFT8 that made it while the two are connected.

Any qFT8 can be a server and a client at the same time: the computer program, the Android app and the iPhone app. On Android the server keeps running in the background when Run in background is on; on the iPhone it runs only while the app is open.

Setting up the server

  1. On the qFT8 that should collect the QSOs, open Settings, go to qFT8 servers and open qFT8log server.
  2. Type a password. Use the same kind of password as for the qFT8 bridge: seven characters or more.
  3. Leave the port at 13510 unless something else uses it, and switch the server on. The page shows the server's address and the qFT8s connected to it. A changed port takes effect at once.
  4. The same address opened in a browser (for example http://192.168.1.20:13510/) shows the log, read only, after you type the server's password (it is never sent): see Looking at the log in a browser.

Setting up a client

  1. On each qFT8 that should send its QSOs, open Settings, press the gear beside qFT8log at the top.
  2. Press FIND: the qFT8log servers on your network are listed by name. Pick one, or type the server's address and port yourself.
  3. Type the server's password and press VALIDATE. When the server accepts it, tick qFT8log at the top of Settings.

From then on the client connects by itself whenever it starts and reconnects by itself when the network or the server comes back. QSOs made while the server is not reachable wait in the log (they show as not uploaded to qFT8log) and are sent as soon as the connection is back, also after a restart. When the client cannot reach the server, the qFT8log row in Settings turns red with Couldn't connect as of and the time.

Consider a QSO uploaded if uploaded here is off for qFT8log by default. Tick it when the server is the place your QSOs go to, so the "waiting for upload" mark of a QSO clears once the server has it.

What travels

  • New QSOs, from the client to the server, with every field qFT8 keeps: the reports, grids, parks and summits, gear, comments, and whether the QSO was already uploaded to or confirmed by QRZ, LoTW or another service (a QSO imported from LoTW stays confirmed).
  • Confirmations, both ways, as soon as they arrive: a confirmation the server receives from LoTW shows on the client that made the QSO, and the other way round.
  • Corrections made in the QSO editor, both ways. When the same QSO was changed on both sides, the later change wins.
  • Deletes never travel. Deleting a QSO deletes it on that qFT8 only; the others keep theirs. Each qFT8 remembers the QSOs deleted on it and never takes them back from another qFT8, neither by an import nor by the live sync.

The server takes QSOs of every mode and every callsign: it is the place where you collect, and the log's filters choose what you see. A QSO the server already has (the same call, time, band and mode) is merged into the one it has, never added twice, and not sent on again.

Importing from the server, and live sync

A client sends only its own QSOs. Two ways bring the server's log to it as well:

  • IMPORT QSOs FROM THE SERVER, on the client's qFT8log page, copies once every QSO of the server inside From, To, Bands and Callsign starts with, of every mode. QSOs made under another callsign than yours are skipped unless Import QSOs for callsigns other than the current is ticked. It also works when qFT8log is not ticked at the top of Settings: the import then connects only for itself and sends nothing.
  • Keep in sync live with this server (it needs qFT8log ticked at the top of Settings): the server's QSOs come here, and from then on every QSO logged, corrected or confirmed on the server, or on any other qFT8 connected to it, appears here at once, and yours go there. Several qFT8s with this box ticked share one log through their server, and with chains, through every server of the chain.
  • When the connection drops, nothing is lost: each side catches up when it is back, also after a restart.
  • Correction times follow the server's clock, so a device whose clock is wrong does not win, or lose, every correction.

Chains: collecting and backing up

A server can itself be the client of another server, so qFT8s can be chained. A QSO is never sent back to a qFT8 it already passed through, so even a ring of qFT8s does not loop. Two examples:

  • One place that uploads. The phones and the portable computer send to the shack computer. Only the shack computer has QRZ and LoTW set up: it uploads everything, and the confirmations it receives go back to the qFT8 that made each QSO.
  • A backup. The shack computer also sends everything to another qFT8, say an old tablet that only keeps the log and shows the world map. Nothing has to be set up on the backup but its server.

Security Note: the password is never sent over the network: both qFT8s prove they know it, and every message after that is signed, so nothing can be changed or replayed on the way. The QSOs themselves are not encrypted. Use qFT8log inside your own network only, and do not open its port to the internet.

Limits

  • Home network only, the same as the qFT8 bridge.
  • Both qFT8s must run the same qFT8log version. A server refuses a client of another version, and the client's row says which one to update.
  • At most 16 clients at a time per server.
  • A QSO the server cannot read (for example one without a date) is marked as refused on the client and sent again only after you correct it.

qFT8log protocol (version 2)

This is the complete description of what two qFT8s say to each other. Every number is big-endian. Text is UTF-8.

Finding servers

A client sends one UDP datagram to the broadcast addresses of its networks, port 13510: "qFT8L?" (6 bytes), the API version (2 bytes), a random id (8 bytes). Every server answers to the sender: "qFT8L!", its API version (2), the same id (8), its TCP port (2), its instance id (16 ASCII hex digits), the length of its name (1) and its name (at most 64 bytes). The answer says nothing secret.

Frames

Over TCP (port 13510 by default) everything travels in frames: the type (1 byte), the length of the body (3 bytes) and the body (at most 16384 bytes). The first four types travel before the keys exist; every other frame's body is sealed: an 8-byte counter, the message, and the first 16 bytes of HMAC-SHA256 (key of the direction) over the type, the counter and the message. Each direction counts from 0 and a frame must carry exactly the next number: a frame that was changed, repeated or left out ends the connection.

The handshake

Both sides know k = PBKDF2-HMAC-SHA256(password, salt, rounds), 32 bytes. The server chooses the salt and the rounds (200000; a client refuses fewer than 10000 or more than 5000000). The transcript t is the HELLO body followed by the CHALLENGE body without its proof. With L = the ASCII text "qFT8 log v1 ":

  • server proof = HMAC-SHA256(k, L + "server proof" + t); client proof = HMAC-SHA256(k, L + "client proof" + t);
  • key client to server = HMAC-SHA256(k, L + "key client>server" + t); key server to client = HMAC-SHA256(k, L + "key server>client" + t).

The client checks the server's proof first and closes without answering when it is wrong, so nothing derived from the password ever goes to a server that does not know it. The server checks the client's proof; a wrong one locks that address out for 1 s, doubling with each wrong try in a row up to 60 s. Both randoms are new for every connection, so a recorded handshake is worth nothing. The API versions must be equal: a server refuses any other with reason 1, and a client refuses a CHALLENGE of another version. A server allows 8 handshakes at a time, 5 s for each step, and 16 clients; a client that connects again takes over from its old connection.

Records

A QSO record is a JSON object with the field names qFT8 stores (call, qso_date as YYYYMMDD, time_on as HHMM or HHMMSS, band, mode, submode, rst_sent, rst_rcvd, gridsquare, freq, station_callsign, my_gridsquare, comment, the park and summit references, the QRZ and LoTW states app_qrzlog_logid, app_qrzlog_status, app_lotw_qsl_rcvd, app_lotw_logid, app_lotw_upload_time, and app_svc), at most 16000 bytes. call, qso_date and time_on are required; any mode and any callsign are accepted. app_svc holds the other services' states and three records of the protocol itself, as id:key=value,... parts separated by ;:

  • q8u: id = the QSO's uid (made once by the qFT8 that first sent it, kept through every correction), t = when its contents were last corrected (UTC ms, missing = never);
  • q8v: id = the instance ids the QSO passed through, separated by dots (at most 32);
  • a sender leaves out its own bookkeeping: its per-peer hashes, its own upload state and its local work flags.

Hash and merge

The hash of a QSO is the first 8 bytes of SHA-256, as 16 hex digits, over the lines name=value of its contents, its correction time and its upload and confirmation states (not the instances it passed through). Two copies of one QSO become one the same way everywhere: the contents of the copy corrected later win as a whole (equal times: the larger contents hash); the upload and confirmation states only move forward (a confirmation is never undone); the instances are the union of both. Merging is the same whatever the order and merging twice changes nothing, so all copies end the same.

Who sends what

  • A client sends its server every QSO that has not passed through that server yet, and every QSO the two exchanged before whose hash has changed since.
  • A server sends a client the QSOs the two exchanged before whose hash has changed (a confirmation, a correction). After a SUBSCRIBE it also sends that client every QSO of its log inside the subscription that the two never exchanged and that did not pass through the client, then BACKLOG_DONE. With live it goes on doing so for every QSO it gets later, for as long as the connection lasts (the client subscribes again after each reconnect); once ends with BACKLOG_DONE; off ends the subscription.
  • The receiver finds its copy by the uid, else by call, date, time (HHMM), band and mode. A server adds a QSO it does not have; a client adds one only inside the subscription it sent. Neither adds a QSO deleted on it (result 3 in both cases). Otherwise the copies are merged; the ACK carries the receiver's hash and, when the merged copy differs from what was sent, the merged record, which the sender merges in turn.
  • Each side remembers, per QSO and per peer, the hash both last agreed on, and sends again only when its own copy differs from it. Deletes are never sent.
  • At most 16 PUTs may wait for their answer. A server takes 100 PUTs per second from each client (bursts of 200) and answers NACK 2 above that; after 50 records it cannot read it ends the connection.
  • A side sends PING when it has sent nothing for 15 s and ends the connection when it has heard nothing for 45 s. A client reconnects 1 s, 2 s, 4 s ... up to 60 s apart.

Bug reports and new versions

Reporting a problem

REPORT BUG, at the bottom of the Settings tab, opens a card where you describe what went wrong and, if you want an answer, leave your e-mail. Pressing SEND sends your description together with the app's log: settings, radio and audio details, and recent activity. Passwords, API keys, certificates and the logins of your QSO services are never included. You get a reference such as QFT8-7K3P9 to quote later. If the report server cannot be reached, qFT8 offers to send the report by e-mail instead.

"Send a report about this?"

When qFT8 notices that it stopped responding for a moment, or that decoding is taking too long on your device, it may show a small card that offers to send a report about it, with SEND, DON'T SEND and DON'T ASK AGAIN. Nothing is ever sent without your tap. The card appears at most once a day, and DON'T ASK AGAIN silences it for a week. After a crash, qFT8 asks at the next start whether to send a crash report.

Check for new versions on startup

With this box ticked (main Settings page, near the bottom) qFT8 looks for a newer version when it starts and shows a notice with a download button when there is one. It never updates by itself.

Anonymous performance summary

Send an anonymous daily performance summary (main Settings page, just above Language) is off unless you turn it on. When on, about once a day qFT8 sends a short summary of how fast it runs on your device: start-up time, screen smoothness, decoding times, audio and radio timing, and the device model and screen. It never contains your callsign, grid, log, settings or anything that identifies you. It helps make qFT8 faster on devices like yours.

Troubleshooting

The phone or computer doesn't recognize the transceiver or it gets disconnected

This is almost always a hardware connectivity or radio interference issue. USB connections are sensitive to vibration, cable quality, and fluff phone raccoons dwelling in the USB port. On Android, another common cause is that USB OTG may be disabled by default in your device (in particular if you are able to receive signal from qFT8 but not transmit and CAT commands don't work even when the device is fully supported, shown in the device dropdown, autorecognized in AUTO mode, etc., this is very likely the cause).

Try:

  • On Android, enabling USB OTG in your device settings (on some devices, OTG is disabled by default and may be located under advanced, system, or additional settings).
  • Using a high-quality, short USB cable (using a shorter cable can significantly help), and ensure the USB port is clean and the connection is tight.
  • On Linux, if qFT8 says it has no permission to open the radio's port, accept its offer to fix it (your account joins the port's group), or ask your system administrator.
  • If the issues occur specifically while transmitting, it could be caused by radio interference. Adding chokes or ferrites to the USB cable could help. You can also try transmitting in a different band, as some devices are only sensitive to interference in certain bands.

The transceiver disappears when the phone is fully charged (Android)

This happens with USB OTG adapters that have a charging input, so that the phone can be charged while the transceiver is connected. With some of them, when the battery reaches 100% the phone stops the USB connection to the transceiver, and it stays away until the charger is unplugged. qFT8 then shows the transceiver as disconnected and nothing works: no audio, no CAT.

Try: Unplugging the charger from the adapter (the transceiver comes back), operating without charging, or using a different adapter or powered hub.

qFT8 bridge: "No bridge found on this network"

qFT8 asked the network and no bridge answered. The usual causes are that the bridge is not running, that the two devices are not on the same network (a guest Wi-Fi counts as another network), or that something between them blocks the question.

Try:

  • Checking that the bridge is running: its window is open, or qFT8 on that device shows qFT8 running in bridge mode. Then Search again.
  • Type address and entering the address the bridge shows. A bridge that is not found by the search often still answers when it is addressed directly.
  • Allowing the bridge through the firewall of its computer: TCP and UDP port 13498, and UDP port 13499 (the one the search uses).
  • Turning off AP Isolation (or Client Isolation) in the router, as for the Remote Control Web Server.
  • Turning off a VPN on both devices, or allowing local network access in it. A VPN that sends all the traffic through its tunnel hides the bridge, even with the two devices side by side.

qFT8 bridge: "Wrong password", or the bridge refuses the connection

The password must be typed exactly as the bridge shows it. A password the bridge made has only lowercase letters and digits, and never the look-alikes i, l, o, 0 and 1. After several wrong tries in a row the bridge makes that device wait before the next one, up to a minute.

Try: Reading the password again on the bridge: on the bridge mode screen of qFT8, or by starting the bridge download with --show-password. If in doubt, make a new one (NEW PASSWORD, or --new-password) and type that.

qFT8 bridge: connected, but no radio or no audio

The link works, but the bridge cannot use the radio's port or its sound device. The box may read Connected to the bridge's name, followed by "but its sound device could not be opened".

Try:

  • Choosing Radio port on the bridge and both sound device rows by hand instead of AUTO.
  • Closing any other program on the bridge's device that uses the radio, including a qFT8 that is not in bridge mode.
  • On macOS, allowing the microphone for the bridge in System Settings > Privacy & Security > Microphone.
  • On Linux, making sure the account that runs the bridge may use serial ports (usually by being in the group dialout) and sound.
  • On an Android bridge, allowing qFT8 to use the radio when Android asks, as for a radio plugged into the phone itself.

qFT8 bridge: "The link to the bridge is losing transmit audio" or "cannot keep up"

The network between the two devices is too uneven: transmit audio arrives too late to be played. While the delay can still grow, qFT8 raises it and says the link is losing audio; when even the largest delay is not enough, it says the link cannot keep up and transmissions break up. This is a matter of the network, not of the radio.

Try: Moving closer to the Wi-Fi access point, connecting the bridge (or both devices) with a network cable, and pausing whatever else is loading the network.

Instead of receiving signal from the transceiver, qFT8 is getting audio from the microphone

On Android, this indicates that the phone is using its internal microphone because it doesn't recognize the transceiver as an external audio source. On the computer, check which input is chosen in DEVICE CONFIGURATION in the settings: pick the transceiver's audio device. The most common causes are:

  • The USB cable is not rated for data (charge-only cable).
  • The USB adapter (OTG) is faulty or incompatible (Android).
  • The cable is plugged in the wrong direction (some cables are directional).

Try: Using a different USB cable, a different adapter, or flipping the cable connections.

The radio's dial does not match the frequency qFT8 shows

The radio's own display and qFT8 differ by a few Hz up to about 100 Hz. This is usually the Tune spectrogram offset you set, and it is on purpose: qFT8 tunes the radio slightly lower and shifts the audio by the same amount, so signals at the very bottom of the spectrogram leave the radio's low-audio blind spot. Decodes, spots, the log and the frequency qFT8 shows all stay the app's real frequency.

Try: Nothing is wrong, so nothing needs fixing. The default is 0 Hz, so this happens only if you set an offset. To change it, or to set it back to 0, open Settings > DEVICE CONFIGURATION > Tuning (this radio) > Tune spectrogram offset (see Tune spectrogram offset).

Not receiving any signal at all; the waterfall is pitch black

If the waterfall remains entirely black both when the transceiver is connected or disconnected, qFT8 likely lacks the necessary permissions to access audio.

Try: On Android, go to your phone's Settings > Apps > qFT8 > Permissions and ensure that Microphone (or Audio recording) is allowed while using qFT8. Alternatively, fully uninstall and reinstall qFT8 and accept all permission prompts on the first launch. On macOS, open System Settings > Privacy & Security > Microphone and allow qFT8. On every computer, check the input chosen in DEVICE CONFIGURATION.

Signals are visible, but no messages are decoded

If you see vertical "wiggly lines" in the waterfall (FT8 signals) but no text appears in the Stations tab, perhaps your clock is not synchronized.

Try:

  • Ensure you have internet access and reopen the app to trigger an NTP sync.
  • If no internet is available, try a GPS sync (Android).
  • If that also doesn't work but message tones are visible in the spectrogram, trigger an emergency time sync from the messages, from the time and location settings menu.
  • Ensure your radio is actually receiving signals from the air.

If no wiggly stripes appear at all in the waterfall, perhaps the band is closed or your antenna is disconnected/untuned.

Messages are decoded too late

The phone's (or an older computer's) processor may be too slow to decode messages on time.

Try: Make sure you switch to Fast decode in the settings, and feel free to move decoding time earlier (e.g. to 13000ms) to create more margin for decoding, at the expense of potentially missing some late messages every cycle.

Error "SWR exceeded threshold — transmission stopped" in the QMX transceiver

If qFT8 shows 0W while transmitting, there are several likely causes:

1. SWR Protection

If the QMX LCD display shows an "S" after the frequency, it means SWR protection kicked in. This means your antenna is not properly tuned for the current band, and the QMX has stopped transmitting to protect its circuitry.

Additionally, qFT8 has its own configurable SWR threshold setting in the app settings. When measured SWR exceeds this threshold, qFT8 will automatically stop transmission to protect your equipment.

  • Firmware 1_04_004+: qFT8 automatically resets SWR protection at the end of the cycle.
  • Firmware 1_03_000+: You can set "SWR Protection reset options" to Timer or TX->RX in the QMX menu. This allows qFT8 to continue operating without you having to touch the transceiver physically.
  • Legacy Firmware: On QMX firmware older than 1_03_000, you must manually reset the transceiver (off/on) or enter and leave the TUNE menu on the QMX to clear the error.

Note: qFT8 waits 1 second after the start of transmission before checking for 0W to avoid false positives while the QMX ramps up. If the QMX recovers and power rises above 1W, the problem indicator clears automatically.

2. Firmware doesn't support power measurement

If the QMX does not show that SWR protection is engaged, and it shows that transmission is happening properly, it may be that the firmware is old and does not support power measurement. Devices like the QDX also do not support power measurement. qFT8 does not know how to interpret 0W and it gets confused.

Try: If your QMX firmware is old, update it. If you are using a QDX, there is no way around this.

3. Audio signal not reaching the QMX

If the QMX does not show the "S" icon after the frequency, then it is likely that the transceiver is simply not receiving a suitable audio signal from qFT8. The volume may be too low (not enough signal) or too high (clipping/distortion causes the QMX to reject the signal).

Try: Check the signal indicator on your QMX. A single dot means no audio, two dots mean there's audio but it's not loud enough. Go to the FT8 Settings section and adjust the "Set device volume to [X] when using radio" setting to different values (e.g. 70%, 80%, 90%) to find the right level for your device.

4. SWR is low during tuner but SWR protection kicks in

This seems like SWR is spiking or peaking at high power for some instants during actual transmission, which triggers SWR protection. This is an indicator of a finnicky antenna (e.g. magloops), a bad cable, a bad connection, or an issue in the setup.

Try: adding common-mode current chokes (such as ferrite beads) should decrease common-mode current.

What is the qFT8 Android notification? (Android)

This notification allows qFT8 to continue processing audio and managing QSOs when you minimize the app or turn off the screen.

  • By default, it triggers automatically when a transceiver is plugged in.
  • You can disable this in qFT8 settings, but qFT8 will stop working in the background.
  • You can press STOP in the notification to fully close qFT8.

qFT8 stops working when the screen is off (Android)

Some Android manufacturers implement very aggressive battery optimizations that may kill background apps even if you granted the initial permissions.

Double check that you granted the permissions: Go to your phone's Settings > Apps > qFT8 > Battery and select "Unrestricted" (or "Don't optimize").

Buttons act weird or the screen is unresponsive during TX

This is caused by RF Interference (RFI). If your antenna is close to the phone or computer or the cable is poorly shielded, the radio energy can interfere with the touch screen, the mouse or the USB connection.

  • Tip: Use a shielded USB cable or clip a ferrite bead onto the cable.

qFT8 looks different than the screenshots in this manual

The app's user interface is occasionally updated, so some minor visual elements may have changed since the screenshots were taken. However, if significant parts of the UI are completely missing or the colors look heavily altered (e.g. the yellow progress bar, the sequence selectors, etc.), your phone's system dark mode may be incorrectly overriding and messing up the application's color palette.

Try: If your system's dark mode is causing issues, you can try temporarily disabling it or adding qFT8 to its exclusion list to restore the correct design.

qFT8 says "NO RADIO" even though transceiver is connected

The issue is likely that you didn't grant the permissions to connect qFT8 to the transceiver. Sometimes this happens because you tap somewhere out of the permission dialog and the dialog closes.

Try: Disconnect and reconnect the transceiver, this should trigger the prompt again. For comfort, mark the option "Always open qFT8 when transceiver is connected" so you never hit this issue again.

qFT8 shows distance in miles and I want it in kilometers (or vice versa)

This comes from the operating system locale (i.e. language selection).

Try: Switching that configuration to the right country (e.g. English (United States) for miles, English (United Kingdom) for kilometers) will fix it.

qFT8 shows low transmission power (e.g. 0.1W) when transmitting at >10W in QMX

This is a known bug in the QMX firmware (up to at least 1.03.000). If you are using the 2x4 mods (e.g. in a QMX+) and your transmission power exceeds 9.9W, the radio's formatting wraps around. For example, 10.1W is reported by the transceiver to the app as 0.1W over the secondary CAT protocol.

Try: There is no workaround inside qFT8, as the app is directly displaying the value it receives. You can safely ignore this display error or reduce your power below 10W to keep the readings accurate until this bug is patched in the transceiver firmware.

Cannot export ADIF logs to the local storage using Share (Android)

The default Share method relies on the native Android share mechanism to export logs. Sometimes, your device's built-in file sharing menu does not offer a direct option to save to your local filesystem.

Try: Change the export Method to Local save in the settings. This uses the Android file picker to directly save the file to your local storage without relying on the sharing menu.

qFT8 fails to decode some messages

Try: Enable deep decode in the settings. Deep decode does recursive decoding and is able to decode more messages when the band is busy, at the expense of extra processing power. It also removes the harmonics of very strong stations (the unreadable copies that an overdriven signal leaves at higher audio frequencies) to find weaker stations under them. Keep an eye on the spectrogram: if deep decode time is too high in your device (e.g. greater than 1 second) and the app is not able to make decisions on time, disable deep decode.

qFT8 hangs or behaves strangely

If this happens only during transmission, it is likely extreme RFI as mentioned above. If it happens at other times, please scroll to the bottom of the Settings tab and press REPORT BUG (see Reporting a problem), or use the "Email me to report issues and bugs" link.
