O que é o qFT8?

O qFT8 é uma aplicação de radioamadorismo para telemóveis e tablets Android, para iPhone e iPad e para computadores com Windows, macOS e Linux que descodifica e transmite mensagens de dados digitais FT8, FT4, FT2, LQ8, JS8 ou WSPR usando um transcetor. Também opera em voz (SSB), código Morse (CW), RTTY e imagens (SSTV) com o mesmo transcetor e o mesmo cabo.

As duas versões funcionam da mesma maneira. Onde diferem, este manual avisa («No Android...», «No computador...»). As capturas de ecrã mostram a aplicação para Android, e «tocar» significa tocar no ecrã no Android ou clicar com o rato no computador.

Embora o qFT8 ofereça suporte pronto para uso (plug-and-play) para o QMX e o ICOM 7300, também pode usá-lo com qualquer transcetor colocando o telemóvel ou o computador perto do altifalante e do microfone com o VOX ativado, ou usando um cabo de áudio. Também pode simplesmente experimentar o qFT8 sem transcetor: ele transmite pelo altifalante e escuta os sinais pelo microfone. Vários telemóveis ou computadores com o qFT8 podem fazer contacto entre si por áudio quando estão suficientemente próximos.

O qFT8 é uma aplicação gratuita e sem anúncios. A licença do código-fonte será decidida quando o código-fonte for publicado (LICENSE).

Deixe Definições > Dispositivo em AUTO: um rádio suportado ligado por USB é reconhecido automaticamente. Também pode escolher o seu rádio nessa lista.

Nota sobre interfaces externas (Digirig, cabos USB-serial genéricos): a deteção automática (AUTO) foi feita para transcetores com controladores USB nativos ou cabos da própria marca. Com uma interface externa genérica (como a Digirig), a deteção automática só vê o chip da interface genérica e usa o modo VOX. Para usar o controlo CAT com rádios ligados por interfaces externas (por exemplo, Lab599 TX-500), selecione manualmente o modelo do seu transcetor em Definições > Dispositivo; a porta série e a velocidade definem-se em Definições > CONFIGURAÇÃO DO DISPOSITIVO.

Mais dispositivos são compatíveis via VOX, que é uma integração parcial, apenas de áudio.

Nota: por segurança, o qFT8 não permite alterar a potência de transmissão do transcetor. Ajuste a potência manualmente no transcetor.

O qFT8 num computador (Windows, macOS, Linux)

O qFT8 para computador faz o mesmo trabalho que o qFT8 para Android: os mesmos modos, a mesma operação AUTO e CALL, o mesmo log e os mesmos serviços. Esta secção trata do que é diferente quando o utiliza no Windows, no macOS ou no Linux: como o instalar, como a janela está organizada, os dois controlos deslizantes de volume, como se escolhem os dispositivos de som e o rádio, e como usar o rato. O resto deste manual aplica-se tal como está; onde uma parte é diferente no computador, isso é indicado ("No computador ...").

Instalação e primeiro arranque

Transfira o ficheiro para o seu sistema a partir de qft8.com. Cada transferência contém uma pasta ou uma aplicação com o programa, a licença e este manual. Não é preciso instalar mais nada: o ambiente Java de que o qFT8 precisa vai incluído.

O qFT8 precisa de um computador com pelo menos 2 núcleos de processador (recomendam-se 4) e espaço para uma janela de pelo menos 960 x 560 píxeis. Com 2 núcleos funciona, apenas mais devagar: veja Computadores lentos.

Windows

  1. Abra o .zip e arraste a pasta qFT8 para um sítio onde guarde os programas, por exemplo a pasta Documentos ou o Ambiente de trabalho. Não execute o qFT8 a partir de dentro do zip.
  2. Abra a pasta e faça duplo clique em qFT8.exe.
  3. O Windows pode mostrar "Windows protected your PC" na primeira vez. Prima More info e depois Run anyway. O qFT8.exe está assinado com o certificado do autor; o Windows demora a passar a confiar num programa novo.
  4. Se o Windows perguntar se deve permitir que o qFT8 (mostrado como "OpenJDK Platform binary") passe pela firewall, permita apenas numa rede privada, e apenas se usar o controlo remoto web ou a bridge.

macOS

  1. Abra o .dmg e arraste o qFT8 para o atalho Applications na mesma janela. Depois ejete o .dmg.
  2. Inicie o qFT8 a partir de Aplicações. Se o iniciar a partir de dentro da janela do .dmg, ou do sítio onde o navegador o colocou, o qFT8 pergunta "Mover o qFT8 para Aplicações?": prima MOVER (o macOS pode pedir a sua palavra-passe, como faz o Finder) ou AGORA NÃO.
  3. O macOS pergunta uma vez se o qFT8 pode usar o microfone. Prima Allow: é assim que o qFT8 ouve o rádio. Se não viu a pergunta ou a recusou, o qFT8 mostra um cartão a dizer que está à espera da permissão do microfone; conceda-a em System Settings > Privacy & Security > Microphone (macOS 13 e mais recente) ou em System Preferences > Security & Privacy > Privacy > Microphone (macOS mais antigo) e inicie o qFT8 outra vez.

Linux

  1. Descompacte o .tar.gz (tar -xzf qFT8-*.tar.gz, ou com o seu gestor de ficheiros). Obtém uma pasta qFT8.
  2. Execute ./qFT8 nessa pasta (o duplo clique funciona se o seu gestor de ficheiros executar programas). O primeiro arranque descompacta o programa em ~/.cache/qft8, o que demora alguns segundos; uma versão mais recente substitui aí a anterior por si só.
  3. A porta série (CAT) do rádio pertence a um grupo: dialout no Ubuntu, Debian e Fedora, uucp no Arch. A placa de som USB do rádio pertence a audio. Se a sua conta não estiver no grupo da porta, o qFT8 avisa num cartão: CORRIGIR adiciona-o ao grupo (pede a sua palavra-passe) e reinicia o qFT8, para que a alteração se aplique sem terminar a sessão. Se isso não funcionar, TENTAR NUM TERMINAL e COPIAR COMANDO dão-lhe o comando para executar; depois termine a sessão e volte a entrar uma vez.

Primeiro arranque

O qFT8 pede o seu indicativo, como no Android (veja Indicar o indicativo). Logo a seguir abre-se um cartão chamado Configuração do dispositivo: escolha o rádio e depois os dispositivos de som ligados a ele. A cascata sob a entrada mostra o que o rádio está a enviar: com o rádio ligado, deve ver ruído ou sinais. Pode abrir o mesmo cartão em qualquer altura com o botão à direita da roda dentada na barra inferior, e o selo vermelho Sem áudio na cascata também o abre. Veja Dispositivos de som e a ligação do rádio.

Tudo o que diz respeito à operação é igual: o seu primeiro QSO, os modos digitais, AUTO, CALL, o log, o ADIF, o QRZ, o LoTW e os outros serviços, SSB, CW, RTTY, SSTV, o limite de transmissão e as regras de segurança: o TX está sempre desligado quando o qFT8 arranca e só o botão TX o liga, e o qFT8 nunca altera a potência de transmissão do seu rádio. As disposições do ecrã e o botão de disposição

O botão na extremidade direita da barra inferior é o botão de disposição. Cada clique nele passa para a disposição seguinte: Flutuante, depois Fixada, depois Tudo em um, e de novo Flutuante. A imagem dele mostra a disposição em que está agora (um leitor de ecrã diz o nome, por exemplo "Disposição: Fixada"). O qFT8 lembra-se da disposição para o próximo arranque, e do tamanho e da posição de cada janela em cada disposição em separado.

  • Tudo em um (a disposição em que o qFT8 arranca na primeira vez). Uma janela com quatro partes iguais: o espetrograma em cima à esquerda, o separador Estações em cima à direita, o Mapa mundial em baixo à esquerda e o log de QSOs em baixo à direita, por cima da barra inferior. As Definições são uma coluna alta à direita da mesma janela; o botão da roda dentada na barra inferior mostra-a ou oculta-a, e o X no cabeçalho dela também. A barra inferior não tem botões para as quatro partes: estão sempre lá.
  • Fixada (como a aplicação Android). Uma janela com o espetrograma à esquerda e o separador Estações à direita, por cima da barra inferior. Arraste o divisor fino entre eles para dar mais espaço a um (a proporção fica entre 20 % e 80 %). Os botões Log de QSOs, Mapa mundial e Definições da barra inferior abrem esses três como janelas separadas, e premi-los outra vez fecha-os.
  • Flutuante. A janela principal encolhe até ficar só a barra inferior, e cada painel é uma janela própria que coloca onde quiser, até noutro ecrã: Espetrograma, Estações, Log de QSOs, Mapa mundial e Definições. A barra inferior passa a ter um botão para cada um dos cinco, para os abrir e fechar. Use-a para espalhar o qFT8 por dois monitores, ou para manter só o espetrograma e a barra num ecrã pequeno.

Mudar a disposição só reorganiza as janelas: não se perde nada, uma transmissão continua e o TX fica como estava. O Mapa mundial tem um botão de ecrã inteiro (em cima à direita do mapa): preenche o ecrã até premir o botão outra vez ou Esc.

Dica: As definições do Android Orientação, Quadrantes e A aplicação cobre (veja Layouts de ecrã) não existem no computador: o botão de disposição e o tamanho da janela substituem-nas.

Trabalhar com as janelas

  • Um programa na barra de tarefas. Seja qual for a disposição, o qFT8 tem uma entrada na barra de tarefas, na Dock ou no Alt-Tab: a janela principal. As janelas de painel das disposições Flutuante e Fixada não têm uma própria. (No Linux isto foi testado com GNOME, KDE Plasma, Xfce, Cinnamon, MATE e LXQt.)
  • As janelas de painel têm a sua própria moldura pequena (igual em todos os sistemas): uma borda fina que redimensiona a janela por qualquer lado ou canto, uma faixa de título com o nome do painel que se arrasta para mover a janela, e um X que fecha o painel tal como o botão dele na barra inferior. O Esc também fecha uma janela de painel, enquanto for a janela ativa.
  • A janela principal pode ser redimensionada e maximizada como habitualmente. Na disposição Tudo em um não pode ficar mais pequena do que 960 x 560 píxeis, e na primeira vez abre com 85 % do ecrã.
  • As Definições mantêm uma só largura. A janela (e a coluna) das Definições mantém a largura que a página de definições do Android tem, para que cada linha caiba; pode alterar-lhe a altura.
  • Tamanho de tudo. Definições > APLICAÇÃO tem os dois controlos deslizantes de tamanho (Interface do utilizador e escala do tipo de letra e Escala dos componentes da interface (sem tipo de letra)) como no Android. Em ecrãs de alta resolução (um Mac Retina, o Windows a 125 % até 200 %) o qFT8 segue a escala do sistema.

Volumes: o dispositivo e o tom

Dois controlos deslizantes pequenos ficam na barra inferior, entre o botão Configuração do dispositivo e o botão de disposição, um por cima do outro. Controlam duas coisas diferentes, e ambas importam para transmitir.

  • Controlo de cima, com a imagem do altifalante: o volume do dispositivo. É o volume do dispositivo de som através do qual o qFT8 transmite: a placa de som USB do rádio, ou o altifalante ou os auscultadores, se for para aí que envia o áudio. É o mesmo nível que o controlo de volume do seu sistema mostra para esse dispositivo, e se alterar um, o outro acompanha (o controlo deslizante em poucos segundos).
  • Controlo de baixo, com a imagem da onda: o volume do tom. É a intensidade do áudio de transmissão que o próprio qFT8 gera (os tons do FT8, FT4, WSPR, JS8 e LQ8, o som do TUNE), de 0 a 100 %. É alterado enquanto transmite: ouve e vê o resultado na mesma transmissão. Começa em 100 %. Cada rádio lembra-se do seu próprio volume do tom. O controlo remoto web mostra o mesmo controlo deslizante e move este.

Como se comporta o controlo do dispositivo.

  • Quando arranca, o qFT8 lê o volume do dispositivo e mostra-o; volta a lê-lo a cada dois segundos, por isso, se alterar o volume no sistema, o controlo acompanha. Se mudar o dispositivo de saída, o controlo mostra o volume do novo dispositivo.
  • O qFT8 só altera o volume do dispositivo quando move este controlo. Nunca o define por si antes de uma transmissão. Isto é diferente do Android, onde o qFT8 pode definir o volume do telemóvel com o valor das Definições quando transmite; no computador essas duas definições não existem.
  • Depois de o mover, o qFT8 volta a ler o volume, para que o controlo mostre o que o dispositivo realmente aceitou.
  • Um dispositivo sem controlo de volume (algumas saídas no macOS) mostra o controlo esbatido e sem botão.
  • Na primeira vez que transmite ou prime TUNE depois de iniciar o qFT8, a imagem do altifalante e o botão do controlo do dispositivo passam de cinzento a branco e voltam durante cinco segundos, para lembrar que este é o nível que decide com que força o rádio é excitado. Tocar-lhe interrompe isso.
  • Enquanto arrasta um controlo deslizante, o valor dele em percentagem aparece ao lado.

Dica: Os dois controlos fazem o trabalho do conselho de volume para Android em [Apenas QMX] Verificação de áudio: se o rádio indicar que o áudio está demasiado baixo ou demasiado alto (os dois pontos do QMX em vez de uma barra), tente primeiro outras posições do controlo de volume do dispositivo (por exemplo 70 %, 80 %, 60 %, 100 %), e use o volume do tom para o ajuste fino. Caso contrário, deixe o volume do tom no valor predefinido (100 %). O qFT8 nunca define a potência de transmissão do seu rádio: ajuste-a no rádio.

Dispositivos de som e a ligação do rádio

O cartão Configuração do dispositivo

Abra-o com o botão à direita da roda dentada (também abre sozinho no primeiro arranque e a partir do selo Sem áudio). Tem duas metades:

  • O RÁDIO (esquerda): o rádio e a placa de som do próprio rádio: Entrada do dispositivo de rádio (o que o rádio ouve: o que o qFT8 descodifica) e Saída para o dispositivo de rádio (o que o qFT8 transmite), cada uma com a sua taxa de amostragem, bits e canais. Deixe-as no valor predefinido do sistema, a não ser que o rádio precise de outra coisa. Uma pequena cascata em direto sob a entrada mostra se está a chegar som.
  • O OPERADOR (direita): o seu próprio microfone e os seus próprios altifalantes ou auscultadores, para SSB e CW (veja Altifalantes e microfone, que é a mesma coisa), o botão TESTAR e a opção Reproduzir o som do rádio no altifalante nos modos digitais. Estes nunca devem ser a placa de som do rádio.

As mesmas escolhas, e mais (tamanhos de buffer, o aviso de falhas), estão em Definições > CONFIGURAÇÃO DO DISPOSITIVO. As linhas do Android "Sistema de áudio" e "Fonte de entrada de áudio" não existem no computador. Deixe os dispositivos em AUTO: prefere a placa de som do próprio rádio para o rádio e, para si, um dispositivo que não seja o do rádio.

Avisos que pode ver

  • Saída para o rádio (selo): a saída de som predefinida do seu computador é a placa de som do rádio, pelo que os sons do sistema, o navegador e os alertas entram no rádio e podem ir para o ar se ele transmitir por VOX ou pela entrada de dados. O qFT8 oferece-se para usar outra saída (USAR ...), abrir as definições de som ou deixar de perguntar. O áudio de transmissão do qFT8 também segue a saída predefinida: escolha primeiro a placa de som do rádio como saída do qFT8 e só depois altere a predefinição do computador.
  • Sem entrada do rádio (selo, Linux): a placa de som do rádio não tem entrada no sistema de som porque está num perfil só de saída. LER O RÁDIO DIRETAMENTE (recomendado) permite ao qFT8 ler a placa por si; MUDAR PARA PRO AUDIO muda o perfil da placa para todos os programas.
  • Sem dispositivos de entrada: o sistema não oferece entrada; ligue o rádio ou uma placa de som e verifique se aparece como entrada nas definições de som do computador.
  • O controlador USB do rádio não está instalado (Windows e macOS): o Icom IC-7300 e outros rádios com um chip USB da Silicon Labs podem precisar do controlador CP210x. Transfira-o da página de controladores do fabricante, instale-o e volte a ligar o rádio.
  • Outro rádio? (selo): o rádio ligado não é o escolhido no qFT8.

Por sistema

  • Windows: o qFT8 ouve o rádio através do motor de áudio do próprio Windows (WASAPI), que dá um fluxo mais estável do que a forma antiga. O rádio aparece como uma porta COM (COM3, ...) e um dispositivo de som "USB Audio CODEC" ou semelhante. O Windows só deixa um programa usar uma porta COM: se o qFT8 disser que o acesso foi negado, feche o outro programa (um logger, um programa de modos digitais, o software do próprio rádio) e prima REPETIR.
  • macOS: a porta do rádio parece-se com /dev/cu.usbmodem... (um QMX) ou /dev/cu.SLAB_USBtoUART (um IC-7300). O macOS não precisa de grupo nem de permissão para a porta, apenas da permissão de microfone acima. Se uma porta for recusada, outro programa tem-na aberta.
  • Linux: a porta parece-se com /dev/ttyACM0 ou /dev/ttyUSB0 e precisa do grupo acima. Os dispositivos de som são os do servidor de som (PulseAudio ou PipeWire), pelo que o altifalante do rádio, os seus auscultadores e o seu microfone podem ser, cada um, um dispositivo diferente. O controlo de volume do dispositivo usa o pactl, do pacote pulseaudio-utils (funciona também com o PipeWire).

Escolher o rádio e a sua porta

Tal como no Android, deixe Definições > Dispositivo em AUTO: um rádio suportado é reconhecido quando é ligado. Para um rádio atrás de uma interface USB-série genérica (um Digirig, por exemplo), escolha o rádio à mão e depois a porta dele em Definições > CONFIGURAÇÃO DO DISPOSITIVO > Definições da porta de comunicação > Dispositivo USB; o débito em baud, os bits de dados, os bits de paragem, a paridade e o método de acionamento (DTR, RTS ou CAT) também lá estão, definidos pelo qFT8 para o rádio escolhido, a não ser que assinale Permitir substituir definições. Os rádios que só usam som (VOX) não precisam de porta nenhuma. A linha de comandos pode listar as portas e os dispositivos de som que o qFT8 vê.

Rato e teclado

O programa de computador opera-se com o rato. Por segurança, o teclado nunca aciona um controlo: o Tab não passa de um controlo para outro, e o Espaço e o Enter nunca premem um botão, assinalam uma caixa nem ligam o TX. (Uma tecla premida por acidente não pode transmitir.) O que o teclado faz:

  • Os campos de texto aceitam todas as teclas como habitualmente: escreva um indicativo, uma mensagem ou uma pesquisa. O Enter confirma a caixa de texto de um diálogo. Copiar e colar funcionam: Ctrl no Windows e no Linux, Cmd no macOS (o Ctrl também funciona aí).
  • Esc fecha um diálogo, uma janela de painel, o mapa em ecrã inteiro e o editor de QSOs ou o logger.
  • Ctrl-S (Cmd-S no macOS) guarda no editor de QSOs.
  • CW: o seu teclado pode ser a chave ou as palhetas (Definições > CW); essas teclas, incluindo o Espaço e o Tab, funcionam enquanto o ecrã de CW for a janela ativa (veja CW (código Morse)).
  • SSB: o Espaço é o push-to-talk enquanto estiver premido e o painel de SSB tiver o foco (veja SSB (voz)).

No fim da página principal das Definições, sob a versão, Diretório de configuração: mostra a pasta (clique nele para a abrir), e o botão Abrir pasta de logs ao lado de COMUNICAR ERRO abre a pasta com os logs do qFT8, o que é útil quando envia um relatório de erro. Trazer as suas definições de um telemóvel (ou levá-las para um)

EXPORTAR DEFINIÇÕES e IMPORTAR DEFINIÇÕES, na página principal das Definições (sob Ficheiros de definições), criam e leem um ficheiro que é o mesmo no Android e no computador. Exporte no telemóvel, copie o ficheiro para o computador (e-mail, nuvem, cabo) e importe-o lá; o caminho inverso também funciona.

No computador, uma exportação nunca substitui um ficheiro que já lá esteja (veja Importação/exportação ADIF).

  • A bridge. Um computador é a bridge habitual: o rádio ligado a ele, e o qFT8 num telemóvel, num iPhone ou noutro computador a operá-lo. Também pode funcionar sem janela (qFT8 --bridge), num computador sem outra função.

Computadores lentos

Definições > APLICAÇÃO > Modo de dispositivo lento / bateria fraca torna o qFT8 mais leve: cerca de 30 imagens por segundo, a cascata redesenhada com menos frequência e o mapa mundial a trabalhar só enquanto é mostrado. Muda apenas o que é desenhado, nunca o descodificador: o qFT8 descodifica da mesma forma com ele ligado ou desligado.

O modo lento só se liga quando assinala a respetiva caixa, nunca por si. Num computador com um ou dois núcleos de processador, o qFT8 pergunta ao arrancar se deve ligá-lo: ATIVAR MODO LENTO assinala a caixa, IGNORAR volta a perguntar no arranque seguinte e NÃO VOLTAR A PERGUNTAR deixa de perguntar. Num computador assim, o qFT8 também dá por si ao descodificador uma parte justa do processador, com ou sem o modo lento, para que outro programa ocupado não o deixe sem recursos.

Atualizações e desinstalação

Atualizações

Com Procurar novas versões ao iniciar assinalado (o valor predefinido; veja Procurar novas versões ao iniciar), o qFT8 pergunta uma vez por dia se existe uma versão mais recente e mostra Há uma nova versão disponível com IGNORAR e TRANSFERIR AGORA, que abre a página de transferência no seu navegador. O qFT8 nunca se atualiza sozinho. Para atualizar, transfira o ficheiro novo e substitua o programa antigo:

  • Windows: feche o qFT8 e substitua a pasta qFT8 (ou só o qFT8.exe) pela nova.
  • macOS: feche o qFT8, arraste o novo qFT8 para Aplicações e escolha Replace.
  • Linux: feche o qFT8 e execute o novo qFT8. Descompacta-se sozinho e remove a versão antiga da cache.

As suas definições e o seu log ficam na pasta de perfil.

Desinstalação

Feche o qFT8 e apague o programa: a pasta qFT8 (Windows, Linux) ou o qFT8 em Aplicações (macOS); no Linux também ~/.cache/qft8. Isto mantém as suas definições e o seu log. Para os remover também, apague a pasta de perfil (acima). Isso apaga o seu log de QSOs: exporte-o antes com o ADIF.

Se algo não funciona

  • A cascata está vazia e o selo diz Sem áudio. Abra a Configuração do dispositivo: a placa de som do rádio é a entrada, e o rádio está ligado? No macOS verifique a permissão do microfone; no Linux o selo Sem entrada do rádio e os grupos.
  • O rádio recebe mas não transmite, o TUNE não aciona nada. A porta foi recusada: outro programa tem-na (Windows, macOS) ou a sua conta não está no grupo (Linux). O qFT8 diz qual; feche o outro programa e prima REPETIR, ou siga o cartão do Linux. Veja também O telemóvel ou o computador não reconhece o transcetor, ou a ligação cai.
  • O rádio está demasiado baixo, demasiado alto ou mostra dois pontos em vez de uma barra (QMX): mova o controlo de volume do dispositivo (Volumes). Verifique se o volume do próprio computador para esse dispositivo não está silenciado.
  • Ouvem-se no ar os sons do computador. A saída predefinida é a placa de som do rádio: responda ao selo Saída para o rádio ou escolha outra saída predefinida no seu sistema.
  • "Já em execução". Outra cópia usa a pasta de perfil. Feche-a, ou inicie esta com uma pasta --qft8_profile própria.
  • A janela está preta ou baralhada (controladores gráficos antigos, uma máquina virtual, ambiente de trabalho remoto): atualize o controlador gráfico. Se continuar, inicie o qFT8 com --opengl (qFT8 --opengl), que desenha a janela de outro modo; se isso também não ajudar, comunique-o com COMUNICAR ERRO (Definições), indicando que sistema e que placa gráfica tem.
  • Uma janela está fora do ecrã (um monitor foi desligado): o qFT8 verifica a posição guardada de cada janela quando a abre, e uma cujo monitor desapareceu, ou que ficaria em grande parte fora do ecrã, abre no meio do ecrã principal. Se uma janela continuar fora de alcance, feche o painel dela com o botão da barra inferior e abra-o de novo, ou reinicie o qFT8.
  • Cascata congelada, falhas de áudio ou carga alta num computador de um ou dois núcleos: veja Computadores lentos, feche outros programas e envie um relatório com COMUNICAR ERRO se continuar.

qFT8 no iPhone e no iPad

O qFT8 para iPhone e iPad funciona como o qFT8 para Android, e o resto deste manual aplica-se a ele; precisa do iOS 17 ou posterior. O que muda é a forma como chega ao rádio.

Um iPhone ou iPad não consegue controlar um rádio por cabo: não há CAT, por isso o qFT8 não consegue definir a frequência do rádio nem pô-lo em emissão por USB. Ouve o rádio e envia os seus tons pela interface de som USB do rádio, outra interface de áudio ou um cabo de áudio. Para o rádio emitir, use uma destas opções:

  • O VOX do rádio: o rádio entra em emissão sozinho quando os tons do qFT8 lhe chegam. Escolha VOX nas definições do qFT8.
  • Uma interface de áudio que aciona o rádio pelo próprio áudio: põe o rádio em emissão sempre que sai som do qFT8.
  • qFT8 bridge: um computador, um Raspberry Pi ou um telemóvel ou tablet Android junto ao rádio, com o rádio ligado a ele por USB. O qFT8 no iPhone ou iPad controla então o rádio pela sua própria rede como se estivesse ligado, incluindo frequência e emissão. Um computador sem outra função, também um servidor sem ecrã, pode correr o bridge a partir da linha de comandos, sem janela.

Configuração rápida

Certifique-se de usar a fonte de alimentação correta para o transcetor (por exemplo, ≤12V para um QMX), ou irá danificá-lo.

Certifique-se também de que o cabo USB e o adaptador que usa para ligar o telemóvel ou o computador ao transcetor são próprios para transferência de dados. No Android, para dispositivos com conectores diferentes de USB-C, é muitas vezes necessário um cabo OTG (on-the-go) específico. A maioria dos problemas de ligação em que o qFT8 não vê o transcetor deve-se ao uso de um cabo ou adaptador incompatível.

No Android, alguns dispositivos vêm com o USB OTG desativado por predefinição. Tem de ser ativado nas definições do dispositivo (a opção pode estar escondida nas definições avançadas, do sistema ou adicionais). Se tiver problemas de ligação — em especial, se consegue receber sinais no qFT8, mas não transmitir, e os comandos CAT não funcionam mesmo com um dispositivo totalmente compatível (mostrado na lista de dispositivos, reconhecido automaticamente no modo AUTO, etc.) —, é muito provável que seja esta a causa.

Conceder permissões iniciais

No Android, ao ser aberto pela primeira vez, o qFT8 pede várias permissões:

  • Permitir que a app qFT8 grave áudio: esta permissão é obrigatória. O qFT8 precisa dela para captar os sinais do transcetor. O qFT8 não armazena, não partilha e não envia nenhuma gravação de áudio.
  • Permitir que a app qFT8 aceda à localização aproximada deste dispositivo: opcional, mas recomendada. O qFT8 usa-a para obter o seu locator Maidenhead, que é partilhado durante as trocas em FT8. O qFT8 não acede a dados de localização exata nem os partilha.
  • Permitir que a app qFT8 envie notificações: opcional, mas recomendada. O qFT8 usa-a para funcionar como serviço em primeiro plano, minimizado ou com o ecrã desligado, para poupar bateria. As notificações só ficam ativas quando há um transcetor ligado.
  • Permitir que a app seja sempre executada em segundo plano: opcional, mas recomendada. Necessária para o qFT8 funcionar de forma estável com o ecrã desligado.

No computador há menos permissões. No macOS, o sistema pergunta uma vez se o qFT8 pode usar o microfone: permita, pois é assim que o qFT8 ouve o transcetor. No Linux, para usar a porta série (CAT) do rádio, a sua conta tem de estar no grupo da porta (normalmente dialout); se não estiver, o qFT8 explica-o e oferece-se para o corrigir.

Princípio fundamental: o qFT8 não envia nenhuma informação para um servidor dedicado a esta aplicação. Todo o processamento de dados acontece localmente no seu dispositivo. Pode autorizar explicitamente a partilha do indicativo, da data e hora e, opcionalmente, da localização aproximada, se indicar uma Chave de API do QRZ válida.

Para mais detalhes, consulte a Política de privacidade do qFT8 - Licença.

Indicar o indicativo

Conceder permissão de ligação USB

No Android, quando o transcetor está ligado e o qFT8 está aberto, aparece uma caixa de diálogo do sistema (o computador não pergunta: nesse caso, veja a nota sobre o Linux acima):

[Apenas QMX] Verificação de áudio

Antes de começar a operar, é importante verificar se o sinal de áudio entre o seu telemóvel ou computador e o QMX está a funcionar corretamente. Prima o botão TX e espere o QMX começar a transmitir numa das próximas sequências.

Tudo a funcionar

Se o botão TX mostrar a potência de saída (por exemplo, 5W), tudo está a funcionar corretamente. No LCD do QMX, deve ver uma barra sob o marcador de VFO «A», no canto superior esquerdo do ecrã — isto significa que o QMX está a receber um bom sinal de áudio do qFT8. Confirme também que não aparece um «S» depois da frequência no LCD, o que indicaria a proteção de SWR.

«S» depois da frequência

Se o LCD do QMX mostrar um «S» depois da frequência, a proteção de SWR foi acionada. A sua antena não está bem ajustada para a banda atual. Pode usar a opção de verificação de SWR no menu do QMX para medir a SWR, e precisará de ajustar a antena.

  • Firmware 1_04_004+: o qFT8 reinicia automaticamente a proteção de SWR no final do ciclo.
  • Firmware 1_03_000+: pode definir "SWR Protection reset options" como TX->RX no menu Protection do QMX, para que ela se reinicie automaticamente.
  • Firmware antigo (anterior a 1_03_000): é preciso entrar e sair do menu TUNE do QMX, ou desligá-lo e ligá-lo, para reiniciar a proteção de SWR.

Dois pontos em vez de uma barra

Se o QMX mostrar dois pontos em vez de uma barra sob o marcador de VFO «A», no canto superior esquerdo do ecrã, o volume do áudio está demasiado baixo ou demasiado alto.

Experimente: vá às Definições do qFT8, encontre a opção «Definir o volume do sistema para [X] ao usar o rádio» e experimente valores diferentes (por exemplo, 70%, 80%, 60%, 100%). Um deles deve transformar os dois pontos numa barra.

Em alguns telemóveis esta opção pode não funcionar. Nesse caso, desmarque-a e ajuste manualmente o volume do telemóvel para valores diferentes (100%, 90%, 80% etc.) até a barra aparecer.

Além disso, a corrente de modo comum pode estar a afetar o comportamento do QMX, e acrescentar um choke de modo comum à antena também pode ajudar nos problemas de áudio.

Nada sob o «A»

Se não houver barra nem pontos sob o marcador de VFO «A», no canto superior esquerdo do LCD do QMX, o qFT8 pode não estar a controlar o transcetor corretamente. Em geral isto significa que as permissões de USB não foram concedidas ou foram dispensadas sem querer. A receção funciona, mas a transmissão não.

Experimente: desligue o cabo do QMX e volte a ligá-lo — no Android, a caixa de diálogo de permissão deve aparecer de novo. Também pode ser que o cabo não seja adequado para o QMX; experimente outro cabo USB-C.

Quando vir uma barra sob o marcador de VFO «A», no canto superior esquerdo do LCD do QMX, e a potência de saída no botão TX, o seu QMX estará bem configurado e pronto para operar!

O seu primeiro QSO com o qFT8

Nota: a hora exata é fundamental para o FT8. O qFT8 sincroniza a hora automaticamente ao iniciar, por NTP (internet) ou GPS (satélites). Se estiver a operar em campo, sem acesso à internet, pode usar o botão SINCR. GPS no separador Definições para sincronizar o relógio diretamente pelos satélites GPS. Isto requer a permissão de localização precisa e céu aberto.

Neste ponto, o transcetor deve estar ligado à fonte de alimentação correta e à antena, e todas as permissões devem estar concedidas. Verifique se a antena está ajustada para uma banda com uma SWR razoável (de preferência sempre abaixo de 2), que não acione as proteções de SWR. É má ideia desativar a proteção de SWR do QMX; isto pode danificar os transistores finais ou o acoplador de antena.

Agora pode escolher a banda que quer usar na barra inferior do qFT8 ou no transcetor. Ao escolher num deles, o outro acompanha.

Neste ponto, o espetrograma mostra sinais e começa a descodificar mensagens, e o separador Estações vai sendo atualizado com as estações que está a ouvir.

Premir o botão TX (o botão mais à esquerda da barra inferior) ativa a transmissão.

Se tudo estiver certo, o botão TX acabará por acender com «TX Transmitting» e mostrará a potência de transmissão e a SWR (por exemplo, «5.0W SWR 1.2»).

Como o modo «AUTO» vem selecionado por predefinição, o qFT8 começa a fazer QSOs e a registá-los no separador Log de QSOs.

Pode tocar no espetrograma para mudar o desvio de frequência de Tx (além disso, tocar na parte de cima do espetrograma, onde ficam os indicadores de pico, permite escrever uma frequência), pode mudar de sequência tocando nos botões 0 e 1 da barra inferior, pode tocar nos vários botões «CALL» para chamar estações específicas, ou pode ajustar a barra do botão «AUTO» no separador Estações para definir a estratégia. As secções seguintes dão mais detalhes sobre todas estas funcionalidades avançadas.

Note que o qFT8 começa por chamar estações ou, se nenhuma estiver ao alcance, por chamar CQ. Com tudo bem configurado e boa propagação, o qFT8 acabará por fazer QSOs.

Se o qFT8 não está a receber sinais adequados e não descodifica mensagens, é um sinal claro de que algo está errado: a propagação nessa banda pode estar fechada, a antena pode não estar bem sintonizada, a antena pode não estar bem ligada ao transcetor, o transcetor pode não estar bem ligado ao telemóvel ou ao computador, ou algum dos seus equipamentos pode não estar a funcionar corretamente. Consulte a secção de resolução de problemas abaixo para ver os problemas mais comuns.

Introdução aos modos digitais

Os modos digitais de radioamador codificam texto e dados em tons de áudio com modulação por desvio de frequência (FSK), transmitidos em banda lateral única (SSB). Combinando larguras de banda estreitas, correção de erros avançada (FEC) e sincronização de tempo rigorosa, os modos digitais permitem comunicações fiáveis com todo o mundo, mesmo com sinais muito abaixo do ruído audível. O qFT8 opera os principais modos digitais modernos — FT8, FT4, FT2, JS8, WSPR e LQ8 —, cada um criado para um objetivo diferente, desde beacons de propagação com sinais ultrafracos até concursos rápidos e conversas de teclado a teclado.

FT8

O FT8 (projeto de Franke e Taylor, 8-GFSK) é o protocolo digital para sinais fracos mais usado no mundo, criado para condições difíceis em HF/VHF, esporádica-E com vários saltos e bandas congestionadas. Ele funciona com mensagens estruturadas, sincronização de tempo precisa em ciclos de 15 segundos e correção de erros robusta.

Ciclos e sequências

O FT8 funciona em ciclos de 15 segundos. Cada ciclo de comunicação tem horário rígido e começa exatamente aos 00, 15, 30 e 45 segundos de cada minuto. Por isso, o relógio do seu dispositivo precisa de estar sincronizado com precisão com a hora UTC.

Há duas sequências no protocolo:

  • Sequência 0 (par): ciclos que começam aos 00 e 30 segundos.
  • Sequência 1 (ímpar): ciclos que começam aos 15 e 45 segundos.

Em geral, as estações alternam entre transmitir e receber. Uma estação que transmite na sequência 0 escuta a resposta na sequência 1, e vice-versa. Dentro de cada ciclo de 15 segundos, a mensagem é transmitida numa janela entre aproximadamente +0,5s e +13s. Isto deixa tempo no fim do ciclo para a descodificação e no início para preparar a próxima transmissão.

Características do sinal

Cada mensagem FT8 é transmitida como uma sequência de tons com pequenas variações de frequência (às vezes descritas como um «ziguezague»). Um sinal FT8 é muito estreito e ocupa apenas cerca de 50Hz de largura de banda. Essa eficiência permite que dezenas de conversas simultâneas caibam numa única faixa de 3kHz.

As 6 etapas de um QSO

Um contacto FT8 padrão costuma passar por seis etapas. Veja um exemplo de troca entre HB9IPH e XX1XXX:

  1. 1/6 CQ: uma estação procura alguém para contactar.
    Exemplo: CQ HB9IPH JN47
    Nota: JN47 é um locator Maidenhead, que indica a localização geográfica aproximada da estação. Também pode haver um modificador de CQ, que é um aviso para os outros operadores (por exemplo, CQ SOTA HB9IPH para o programa Summits On The Air, ou CQ US HB9IPH para quem quer contactar alguém nos EUA). O modificador e a localização podem não caber juntos na mesma mensagem; nesse caso, a localização é omitida. Se o indicativo for muito longo, pode ser que nem a localização nem o modificador caibam no CQ!
  2. 2/6 CALL: outra estação responde ao CQ.
    Exemplo: HB9IPH XX1XXX JO21
    Nota: quem responde também informa a sua localização (JO21), que pode ser omitida se os indicativos forem demasiado longos para caber tudo.
  3. 3/6 RPT: a primeira estação envia um reporte de sinal.
    Exemplo: XX1XXX HB9IPH -10
    Nota: o reporte de sinal (por exemplo, -10) indica a intensidade do sinal em relação ao nível de ruído, em dB.
  4. 4/6 RRPT: a segunda estação confirma o reporte e envia o seu.
    Exemplo: HB9IPH XX1XXX R-12
    Nota: o prefixo «R» confirma que o reporte anterior foi recebido, e é seguido pelo reporte de sinal para a primeira estação.
  5. 5/6 RR73: a primeira estação confirma tudo e envia um «Roger-Roger 73».
    Exemplo: XX1XXX HB9IPH RR73
  6. 6/6 73: a segunda estação envia um «73» final para encerrar o contacto.
    Exemplo: HB9IPH XX1XXX 73

Por causa do problema dos dois generais, é teoricamente impossível ter a certeza de que a outra estação recebeu a sua última comunicação, a menos que ela confirme. Mas então teria de confirmar a confirmação dela, ela teria de confirmar a sua, e assim por diante. O modo digital FT8 contorna isto com etapas estruturadas: tecnicamente, um QSO pode ser considerado completo depois da etapa 4/6 (quando os dois reportes de sinal foram trocados). Na prática, para garantir que as duas estações concordem que a troca aconteceu, um QSO é registado quando uma estação recebeu um RR73 e enviou um 73. Ou seja, transmitir um RR73 ou um 73 dispara o registo do QSO.

Note que uma estação também pode chamar outra que não transmitiu um CQ antes. Por exemplo, estações em locais raros podem ter um «pile-up» de muitas estações a chamar ao mesmo tempo; nesses casos, a estação rara pode simplesmente passar de um QSO para o seguinte, sem precisar de convidar novas chamadas com um CQ.

Algumas estações usam RRR em vez de RR73 na etapa 5. Nesse caso, o contacto exige uma troca a mais: a segunda estação envia 73, e a primeira envia 73 de novo para terminar.

O FT8 também permite mensagens de texto livre (até 13 caracteres), mas o qFT8 ainda não envia essas mensagens personalizadas.

Limitações do protocolo e alternativas

As mensagens FT8 são fortemente compactadas em 77 bits. Às vezes, informações complexas (como indicativos longos e não padrão) não cabem no formato padrão de mensagem.

  • Indicativos com hash: se um indicativo é demasiado longo, ele pode ser enviado como um hash. Se a estação que recebe viu esse indicativo a chamar CQ recentemente, o programa dela consegue ligar o hash ao indicativo original. Caso contrário, ele aparece como <...>. É muito mais difícil fazer QSOs quando o seu indicativo não é padrão.
  • Recurso ao texto livre: algumas mensagens podem ser forçadas ao formato de texto livre de 13 caracteres, que é menos robusto que as mensagens estruturadas padrão.
  • Indicativos não padrão: se duas estações usam ambas indicativos muito longos e não padrão, pode ser simplesmente impossível que se comuniquem entre si no modo digital FT8.
  • Etapas saltadas: se os indicativos são demasiado longos, o protocolo pode não conseguir encaixar os reportes de sinal (etapas 3/6 e 4/6). Nesses casos, a troca pode saltar diretamente do CALL (2/6) inicial para as confirmações finais (5/6 e 6/6).

Mensagens que verá, mas nunca enviará

Algumas estações enviam formatos de mensagem que o qFT8 mostra, mas não envia:

  • Uma mensagem para duas estações: uma expedição que trabalha muitas estações ao mesmo tempo pode encerrar um QSO e começar o seguinte numa única transmissão: K1ABC RR73; W9XYZ <VP8XYZ> -08. Significa «K1ABC, o seu QSO está completo» e «W9XYZ, o seu reporte é -08», ambos de VP8XYZ. O qFT8 mostra a mensagem como foi enviada, na lista de estações e uma única vez na cascata. Se é uma das duas estações, ela vale como o seu RR73 ou como o seu reporte, exatamente como se a expedição a tivesse enviado só para si, e o QSO continua ou é registado como de costume. Se não é nenhuma das duas, não há nada a fazer, e o AUTO não faz nada com ela.
  • Trocas de concurso: em alguns concursos as estações enviam uma classe e uma secção (Field Day) ou um reporte com um estado ou um número de série (concursos de RTTY) em vez de um locator e um reporte. O qFT8 mostra essas mensagens para que veja o que há na banda, e nunca lhes responde: não envia trocas de concurso.

FT4

O FT4 é um modo digital simplificado, criado especificamente para concursos de radioamador, nos quais concluir contactos depressa é essencial:

  • O dobro da velocidade: funciona em ciclos de 7,5 segundos (duas vezes mais rápido que o FT8) e transmite por cerca de 4,48 segundos, com quatro intervalos de transmissão por minuto.
  • O dobro da largura de banda: ocupa cerca de 90 Hz de largura de banda de RF (aproximadamente o dobro dos ~50 Hz do FT8).
  • Perda de sensibilidade: em troca do dobro da débito, o FT4 tem um limiar de descodificação de cerca de -16,4 dB a -17,5 dB de SNR (uma perda de sensibilidade de uns 3,5 a 4 dB em relação ao FT8).
  • Uso na prática: usa modulação 4-GFSK e a mesma carga estruturada de 77 bits, o que permite concluir as trocas padrão de concurso na metade do tempo quando a propagação ajuda.

FT2

O FT2 foi criado para trocas ultrarrápidas com sinais favoráveis, rajadas de meteor scatter em VHF/UHF e concursos de ritmo alto:

  • O dobro da velocidade do FT4 (4x FT8): funciona em ciclos de 3,75 segundos, com cerca de 2,24 segundos de transmissão, o que permite até 16 ciclos por minuto.
  • O dobro da largura de banda do FT4 (4x FT8): ocupa cerca de 180 Hz de largura de banda de RF (o dobro do FT4 e quase quatro vezes a do FT8).
  • Perda adicional de sensibilidade: tem um limiar de descodificação de cerca de -13 dB a -14 dB de SNR (uma perda adicional de ~3 dB em relação ao FT4, ou ~6 a 7 dB menos sensível que o FT8).
  • Uso na prática: ideal para contactos em rajada durante aberturas com sinais fortes e em modos de propagação por rajadas, em que as janelas de contacto são momentâneas e os sinais estão bem acima do nível de ruído.

JS8

O JS8 (projeto de Jordan Sherer, 8-GFSK) foi criado para conversa descontraída, conversa de teclado a teclado e redes ad hoc, e não para trocas estruturadas de concurso:

  • Divisão e remontagem de mensagens: usa a mesma modulação 8-GFSK e as mesmas tramas de 77 bits do FT8, mas acrescenta um protocolo de transporte de camada superior para fragmentar e remontar mensagens. Assim, mensagens de texto livre de qualquer tamanho fluem naturalmente por ciclos consecutivos.
  • Vários modos de velocidade: oferece quatro perfis de velocidade selecionáveis, para acompanhar as condições da banda:
    • Slow: ciclos de 30 segundos, ~25 Hz de largura de banda, descodifica até -25 dB de SNR.
    • Normal: ciclos de 15 segundos, ~50 Hz de largura de banda, descodifica até -21 dB de SNR.
    • Fast: ciclos de 10 segundos, ~80 Hz de largura de banda, descodifica até -18 dB de SNR.
    • Turbo: ciclos de 6 segundos, ~160 Hz de largura de banda, descodifica até -15 dB de SNR.
  • Funcionalidades de rede: permite mensagens dirigidas, retransmissão automática de mensagens por estações intermediárias, monitorização de presença por heartbeat e caixas de correio assíncronas (store-and-forward).

WSPR

O WSPR (Weak Signal Propagation Reporter) foi criado exclusivamente para sondar caminhos de propagação e funcionar como beacon automático, e não para QSOs bidirecionais de conversa:

  • Ciclos de dois minutos: funciona em ciclos de 2 minutos (120 segundos) rigorosamente sincronizados e transmite uma sequência de tons 4-FSK de 162 símbolos ao longo de 110,6 segundos.
  • Largura de banda ultraestreita: ocupa apenas cerca de 6 Hz de largura de banda de RF, concentrando a potência irradiada numa fatia excepcionalmente compacta do espetro.
  • Sensibilidade extrema a sinais fracos: consegue descodificar sinais tão fracos quanto -28 dB a -31 dB de SNR numa largura de banda de referência padrão de 2,5 kHz, o que permite a transmissores de miliwatts (QRPp) cobrir distâncias globais.
  • Reportes automáticos de propagação: transmite o indicativo da estação, o locator Maidenhead (4 ou 6 caracteres) e a potência do transmissor em dBm. Os spots descodificados são encaminhados automaticamente à base de dados mundial WSPRnet, para mapear a propagação ionosférica em tempo real.

LQ8

O LQ8 é um modo digital avançado para sinais fracos desenvolvido por Luis Quesada (HB9IPH), autor e criador do qFT8:

  • Conclui QSOs mais rápido, sem penalização: o LQ8 completa QSOs bidirecionais bem mais rápido que o FT8 sem nenhuma perda de sensibilidade. Ele mantém todo o limiar de descodificação de sinais fracos de -21 dB de SNR (igual ao do FT8) e conclui contactos válidos em bem menos rondas de transmissão, graças a um protocolo otimizado.
  • Mensagens compostas: permite transmissões agregadas, como reporte e confirmação combinados (REPORT+RR73) e respostas paralelas a várias estações (MULTI_CALL), reduzindo a duração padrão de um QSO de 4–6 ciclos para apenas 2–3.
  • Arquitetura moderna: funciona em ciclos padrão de 15 segundos, com modulação 8-GFSK em 79 símbolos (~65 Hz de largura de banda), cargas de 77 bits compactadas com codificação de Huffman otimizada, deteção de erros por CRC de 14 bits e sinalização estruturada para tráfego de emergência.

Para mais informações, especificações e ferramentas, visite https://lq8.org, o portal dos modos LQ.

Interface do utilizador do qFT8

A aplicação qFT8 divide-se em três partes:

  1. A barra inferior: sempre visível, para acompanhar e controlar a transmissão e para controlar o qFT8.
  2. O espetrograma: sempre visível, para ver as mensagens descodificadas, a hora UTC em direto e a frequência sintonizada, e para controlar o desvio de frequência de transmissão.
  3. A área dos separadores: mostra um dos quatro separadores (Estações, Log de QSOs, Mapa mundial e Definições). Os botões da parte direita da barra inferior escolhem qual deles aparece.

As secções a seguir descrevem todos esses componentes em detalhe.

A barra inferior

A barra inferior mostra informações importantes: se a transmissão está armada ou desarmada, se o qFT8 está a transmitir, a potência de transmissão, a relação de ondas estacionárias (SWR), a mensagem que está a ser transmitida, a sequência atual e a selecionada, o seletor de banda e os botões para navegar entre os separadores.

Estes são os componentes da barra inferior, em detalhe:

  1. A barra de progresso do ciclo: a barra amarela começa em 0s do ciclo (extrema esquerda) e termina em 15s do ciclo (extrema direita).
  2. O marcador de início do Tx: o ponto vermelho na parte esquerda da barra indica o momento de início do Tx. Se o Tx está ON (veja o item 4) e a sequência atual é a selecionada (veja o item 6), a transmissão começa nesse ponto.
  3. O marcador do momento de descodificação: o ponto branco na parte direita da barra indica o momento da descodificação, isto é, quando as mensagens são descodificadas a partir dos sinais recebidos e depois processadas.
  4. O botão TX: pode estar desarmado (OFF) ou armado (ON). Também mostra quando há transmissão, a potência de transmissão e a SWR. Com firmwares do QMX acima de 1_04, este botão mostra «HOLD: TUNE». Manter o botão premido ativa o modo de sintonia e mostra a SWR em direto.
  5. O seletor de mensagem: mostra a mensagem selecionada para envio ou em envio (nesse caso, destacada em amarelo). No modo AUTO, ele é controlado automaticamente. No modo CALL, por predefinição também é automático, mas pode tocar nele para escolher manualmente a próxima mensagem a enviar.
  6. O seletor de sequência: a linha amarela acima dos botões mostra a sequência atual (0 ou 1). Tocar em 0 ou 1 seleciona essa sequência para as suas transmissões.
  7. O seletor de modo: muda o modo de transmissão usado (por exemplo, FT8, FT4, FT2, LQ8, JS8 ou WSPR), e também SSB, CW, RTTY e SSTV, que mudam a barra inferior e o separador Estações como descrevem as respetivas secções. Passar dos modos digitais para um destes quatro, voltar, ou trocar entre eles coloca o TX em OFF: arme-o de novo quando estiver pronto. Trocar entre modos digitais deixa-o como está.
  8. O seletor de banda: com um transcetor ligado, muda a banda no transcetor.
  9. O botão do separador Estações: abre o separador que lista todas as estações que ouviu ou com as quais pode comunicar.
  10. O botão do separador Log de QSOs: abre o separador que lista todos os QSOs que fez. Este botão fica marcado com um ponto amarelo quando há QSOs que não foram enviados ao QRZ.
  11. O botão do separador Mapa mundial: abre o separador que mostra o mapa-múndi interativo.
  12. O botão do separador Definições: abre o separador para configurar o qFT8.

O espetrograma

O espetrograma mostra uma vista de picos e a cascata, com os sinais e as mensagens que chegam, os sinais e as mensagens que saem, marcadores da mudança de sequência anotados com a hora UTC e o tempo de descodificação, e o desvio de frequência selecionado para transmissão.

Estes são os componentes do espetrograma, em detalhe:

  1. Vista da cascata: mostra o histórico recente dos sinais recebidos ao longo do tempo. Tocar nessa vista muda o desvio de frequência selecionado.
  2. Picos em tempo real: mostram a intensidade instantânea dos sinais em toda a faixa de frequências. Tocar nessa vista abre uma caixa de diálogo para escrever o desvio de frequência exato.
  3. Separadores de sequência: estas linhas horizontais vermelhas separam visualmente os ciclos e são anotadas com a hora UTC e o tempo gasto na descodificação.
  4. Desvio de frequência selecionado: esta faixa vertical amarela sobre o espetrograma indica o desvio de frequência atualmente selecionado para transmissão.
  5. Mensagens recebidas, mostradas com um código de cores:
    • Verde: mensagens de CQ.
    • Ciano: mensagens entre outras estações.
    • Amarelo: as mensagens que transmitiu.
    • Laranja: mensagens recebidas dirigidas a si.
  6. Hora UTC e sequência atuais: mostradas no topo da cascata.
  7. Frequência e banda sintonizadas: a frequência e a banda em que o transcetor está sintonizado.
  8. Eixo de frequência: mostra a escala de frequência em Hz dentro da banda selecionada.

O separador Estações

O separador Estações é o centro de comando para acompanhar a atividade na banda e operar o qFT8. Tem os controlos de filtro e de automação no topo, seguidos de uma lista das estações ativas.

Estes são os componentes do separador Estações, em detalhe:

  1. Botão do modo de chamada AUTO: com «AUTO» ativado, o qFT8 tenta chamar a melhor estação segundo os critérios escolhidos pelo utilizador.
  2. Botão do modo manual CALL: ativar «CALL» numa estação faz o qFT8 insistir em chamá-la até conseguir um QSO, e depois voltar para «AUTO».
  3. Alvo: define os critérios do modo AUTO:
    • Qualquer um: qualquer indicativo com o qual ainda não tem QSO.
    • Perto: prioriza as estações mais próximas, pela distância entre grids Maidenhead.
    • Distante: prioriza as estações mais distantes, pela distância entre grids Maidenhead.
    • Intensidade do sinal: prioriza as estações com o sinal mais forte (SNR).
    • Chamar CQ: apenas chama CQ e responde a qualquer estação que chame a sua.
    • Caçador POTA: prioriza as estações de Parks on the Air.
    • Caçador SOTA: prioriza as estações de Summits on the Air.
    • Caçador POTA + SOTA: prioriza as estações de Parks on the Air e de Summits on the Air, e depois as que não são nem uma coisa nem outra, ordenadas por SNR.
    • DXCC: prioriza países/entidades novos.
    • Locator: prioriza quadrículas Maidenhead novas.
    • Zona ITU: prioriza zonas ITU novas.
    • Zona CQ: prioriza zonas CQ novas.
    • I/C/D/L: prioriza primeiro a zona ITU, depois a zona CQ, depois o DXCC e depois o Locator.
    Em todos os casos, as estações que atendem ao mesmo critério são ordenadas pela intensidade do sinal. Por exemplo, Qualquer um prioriza primeiro os indicativos novos, mas, entre eles, os sinais mais fortes ficam no topo da lista.
  4. Periodicidade: com que frequência contactar esse alvo:
    • uma vez: uma vez na vida.
    • por dia: uma vez por data UTC.
    • por semana: uma vez a cada 7 dias (janela móvel).
    • por mês: uma vez por mês (janela móvel).
    • por ano: uma vez por ano (janela móvel).
  5. Qualificador: como essas restrições se aplicam:
    • por indicativo
    • em bandas diferentes
    • em modos diferentes
    • até zona confirmada
    • por banda + até zona
    • por modo + até zona
    • em bandas ou modos diferentes
    • por banda/modo + até zona
  6. Modo Espião: quando ativado, o qFT8 também tenta chamar estações que ainda não ouviu chamar CQ (marcadas como DIRECT). É útil para ter mais estações ao alcance e entrar em pile-ups.
  7. Modo Ocupado: quando ativado, o qFT8 também tenta chamar estações que estão em QSO com outra (marcadas como BUSY). É útil para entrar num pile-up.
  8. Botão +: chama manualmente qualquer estação, escrevendo o indicativo dela.
  9. Informações da estação: mostra o estado detalhado de cada estação descodificada.

Cada estação da lista tem quatro linhas cheias de informação:

A primeira linha mostra os dados da estação (da esquerda para a direita):

  • Estado do QSO: indica o seu histórico de QSOs com esta estação (✗ = nenhum QSO, ✓ = registado localmente, ★ = confirmado via QRZ ou LoTW).
  • Indicativo: o indicativo da estação.
  • DXCC: o país ou a entidade a que pertence o indicativo desta estação.
  • Grid: a quadrícula Maidenhead que esta estação informa.
  • Zona CQ: a zona CQ a que pertence o indicativo desta estação.
  • Zona ITU: a zona ITU a que pertence o indicativo desta estação.
  • Banda: a banda em que a estação foi ouvida pela última vez.

A segunda linha mostra o estado da comunicação (da esquerda para a direita):

  • Estado: a fase atual da comunicação:
    • DIRECT: ouvida e aparentemente livre agora, mas nunca chamou CQ.
    • 1/6 CQ: ouvida a chamar CQ e aparentemente livre agora.
    • 2/6 CALL: chamou-o.
    • 3/6 RPT: enviou-lhe um reporte de sinal.
    • 4/6 RRPT: respondeu ao seu reporte com o dela.
    • 5/6 RR73: confirmou o seu reporte com RR73.
    • 6/6 DONE: QSO concluído (73 trocados).
    • GONE: não foi ouvida nos últimos ciclos.
    • TOO LONG: o seu indicativo e o dela são, juntos, demasiado longos para estabelecer uma comunicação, pelos limites do modo digital FT8.
  • Intensidade do sinal: intensidade em dB (mostra «????» se não foi ouvida recentemente).
  • Sequência: a última sequência em que esta estação foi ouvida a transmitir (0 ou 1).
  • Delta de tempo (Δt): diferença de sincronização, em segundos, entre o relógio dela e o seu.
  • Distância: distância estimada entre o grid dela e o da sua estação.

A terceira e a quarta linhas mostram as trocas de mensagens com essa estação, incluindo a hora UTC, o desvio de frequência e o texto da mensagem (com o prefixo RX: para as mensagens recebidas ou TX: para as transmitidas). Conforme o modo de exibição das estações escolhido em Definições → Aplicação → Interface do utilizador (a predefinição é Compacto - Último Rx; as outras opções são Compacto - Último Rx/Tx em alternância, Compacto - Último Rx/Tx e Expandido - Últimos Rx e Tx), os cartões das estações mostram três linhas, ou quatro linhas com as mensagens de Rx e de Tx.

Indicadores visuais importantes:

  • Mensagem Rx em coral (UTC, desvio e texto): uma mensagem Rx recebida desta estação foi dirigida especificamente à sua estação / ao seu indicativo (incluindo indicativos compostos como /P e correspondências de indicativos com hash) no ciclo atual ou no anterior. É uma pista visual imediata de que a estação acabou de o chamar ou de responder às suas transmissões. As chamadas gerais de CQ e as mensagens dirigidas a outras estações nunca são destacadas, e o texto volta automaticamente ao cinzento normal quando a mensagem fica mais antiga do que o ciclo anterior. As mensagens transmitidas (TX:) ficam sempre em cinzento neutro.
  • Indicativo em vermelho: o modo AUTO ultrapassou o limite de tentativas para esta estação. Ela é ignorada temporariamente, a menos que toque em «CALL» para reiniciar a contagem manualmente.
  • Indicativo em roxo: este indicativo é um alvo segundo os seus critérios atuais.
  • Indicativo em cinzento: o indicativo corresponde à sua configuração de prefixos eliminados (separados por vírgulas). O modo AUTO nunca escolhe esta estação.
  • Zona destacada em roxo: esta zona/entidade (DXCC, Locator, Zona CQ, Zona ITU) é um alvo segundo os seus critérios atuais.
  • Número de sequência em vermelho: a estação está na mesma sequência que selecionou, o que causa um conflito. Tocar em «CALL» muda a sua sequência automaticamente.
  • Banda em vermelho: a estação foi ouvida pela última vez noutra banda.

As estações são ordenadas automaticamente por relevância. Mudar os seus critérios de alvo ou as suas restrições reordena a lista de imediato.

O separador Log de QSOs

O separador Log de QSOs mostra os QSOs realizados.

Estes são os componentes do separador Log de QSOs, em detalhe:

  1. Filtro de texto do indicativo: filtra os QSOs cujo indicativo contém o texto escrito.
  2. Filtro de estado: um filtro de QSOs que mostra:
    • Todos: todos os QSOs registados.
    • Confirmados: apenas os QSOs que foram confirmados.
    • Não confirmados: os QSOs que ainda não foram confirmados.
    • Não enviados: os QSOs que não foram enviados ao QRZ.
    • Duplicados: os QSOs que o QRZ reconhece como duplicados.
    • Rejeitados: os QSOs que foram rejeitados pela outra estação no QRZ.
    • Outro indicativo: os QSOs registados com um indicativo diferente do configurado atualmente.
    • Não FT8/FT4: os QSOs registados num modo que não é FT8 nem FT4.
  3. Filtro de recentes: mostra apenas os 100 QSOs mais recentes que atendem aos critérios.
  4. A lista de QSOs: mostra as entradas do log com as seguintes colunas (da esquerda para a direita):
    • QRZ: indica o seu histórico com esta estação:
      • ✗: nenhum registo de QSO.
      • ✓: registado localmente / envio pendente.
      • ✓🕒: enviado ao LoTW, a aguardar confirmação.
      • ✓: enviado ao QRZ.
      • ★: confirmado no QRZ ou no LoTW (para QSOs enviados ao QRZ) ou manualmente.

      • ⚠️: o indicativo da estação não coincide; não enviado.
      • ⛔: rejeitado.
    • Indicativo: o indicativo da estação.
    • DXCC: o país ou a entidade a que pertence o indicativo desta estação.
    • Grid cell: a quadrícula Maidenhead que esta estação informa.
    • Zona CQ: a zona CQ a que pertence o indicativo desta estação.
    • Zona ITU: a zona ITU a que pertence o indicativo desta estação.
    • Banda: a banda em que a estação foi ouvida pela última vez.

Indicadores visuais importantes:

  • Nota em amarelo abaixo do indicativo: este QSO pertence a uma estação diferente da configurada.
  • Zona destacada em verde (DXCC, Locator, Zona ITU, Zona CQ): este foi o primeiro QSO não confirmado do seu log para esta zona.
  • Zona destacada em amarelo (DXCC, Locator, Zona ITU, Zona CQ): este foi o primeiro QSO confirmado do seu log para esta zona.

Registar à mão e selecionar: o botão + abre o registo manual, para registar os QSOs que fez por si próprio. Um toque longo num QSO inicia uma seleção de vários QSOs.

O separador Mapa mundial

O separador Mapa mundial mostra um mapa global interativo, em tempo real, com a geografia das estações, o tráfego descodificado, as suas conquistas em QSOs e as condições de propagação solar.

Estes são os componentes e funcionalidades do separador Mapa mundial, em detalhe:

  1. Mapa interativo e controlos:
    • Navegação: arraste para percorrer o globo suavemente, com continuidade horizontal ao cruzar o antimeridiano. Use o gesto de pinça com dois dedos para aproximar e afastar.
    • Temas do mapa: alterne entre quatro estilos visuais (Futuro brilhante, Consola, Terra e Azul meia-noite) na barra de ferramentas superior.
    • Coordenadas no HUD: mostra em tempo real as coordenadas geográficas (latitude, longitude) e o locator Maidenhead do ponto que toca.
  2. Barra de ferramentas esquerda (camadas e informações):
    • INFO: liga e desliga os cartões de informação sobrepostos no ecrã (hora, terminador solar, posição subsolar e coordenadas da mira).
    • MSGs: liga e desliga as rotas e os marcadores de mensagens diretas: em laranja para as mensagens recebidas (endereçadas à sua estação) e em amarelo para as enviadas (transmitidas pela sua estação). Tocar no ponto médio da seta abre o texto da mensagem.
    • QSOs: liga e desliga os marcadores dos contactos recentes da sessão (âmbar para os registados, esmeralda para os confirmados).
    • Spot: liga e desliga os spots do tráfego descodificado em direto na banda, ouvidos pela sua estação (ciano para RX/CQ), e os spotters que informam o seu sinal no PSKReporter / WSPRnet (losangos vermelhos).
    • SOTA: liga e desliga as referências de cumes do Summits On The Air e os ativadores de cumes em atividade (⛰️).
    • POTA: liga e desliga as referências de parques do Parks On The Air e os ativadores de parques em atividade (🌲).
    • Banda: mostra a propagação da banda a partir de relatórios online e uma zona cega ao redor do utilizador. Com ligação à internet, é atualizado em tempo real ao mudar de banda.

    Os botões SOTA, POTA, STATS e Spot podem ficar a piscar; isto significa que não foi possível transferir as atualizações.

  3. Barra de ferramentas direita (conquistas e camadas de limites):
    • STATS: liga e desliga o painel de estatísticas, com o total de registados e de confirmados na camada de limites ativa.
    • DXCC: mostra os limites de países e territórios coloridos conforme o estado no seu log (verde para registado/não confirmado, amarelo para confirmado). Ilhas pequenas e microentidades aparecem como marcadores visíveis.
    • GRID: as quadrículas Maidenhead do mundo (campos e quadrículas de 4 caracteres), preenchidas conforme as conquistas.
    • ITU: sobrepõe as 90 zonas de rádio da ITU, preenchidas conforme as conquistas.
    • CQ: sobrepõe as 40 zonas WAZ da revista CQ, preenchidas conforme as conquistas.
  4. Cartão de detalhes e ação rápida CALL:

    Tocar em qualquer estação, spot, parque ou cume abre um cartão de detalhes com:

    • Indicativo ou nome da referência, entidade DXCC e nome do parque/cume.
    • Texto da mensagem descodificada, frequência, banda e modo.
    • Intensidade do sinal (SNR) ou reporte de sinal (RST).
    • Locator, distância (km / mi), rumo (°) e tempo decorrido.
    • Botão CALL: inicia de imediato o contacto com a estação (mudando automaticamente de banda e de modo, se necessário).

O separador Definições

O separador Definições permite configurar o qFT8.

O separador Definições está organizado assim:

  • Indicativo: o seu indicativo de radioamador (obrigatório para transmitir). Deve estar de acordo com a sua licença.
  • Modificador de CQ: texto opcional acrescentado às suas chamadas de CQ (por exemplo, «SOTA»).
  • Dispositivo: serve para selecionar e configurar o seu transcetor (por exemplo, QMX, QDX, série Kenwood TS-480 / TS-590 / TS-2000, ou VOX/apenas áudio) e os parâmetros de ligação.
  • Rádio / Antena: o rádio e a antena com que opera. Cada QSO registado guarda-os (ADIF MY_RIG / MY_ANTENNA) e o PSKReporter recebe-os juntamente com os seus spots. Com Rádio vazio, é usado o nome do rádio ligado.

Submenus e opções

  • CONFIGURAÇÃO DO DISPOSITIVO: selecione o dispositivo de áudio, ajuste o volume de transmissão e os limiares do VOX e configure como o rádio é colocado em transmissão. Também o Desvio de sintonia do espetrograma e o Limite de transmissão contínua de cada rádio (ambos em Documentação das funcionalidades).
  • Altifalantes e microfone: o seu próprio microfone e os seus altifalantes ou auscultadores, para SSB e CW (veja Altifalantes e microfone, logo abaixo).
  • ATIVAÇÃO POTA / ATIVAÇÃO SOTA: inicie, veja ou termine uma ativação; a lupa ao lado de cada uma lista as anteriores.
  • IMPORTAR/EXPORTAR LOGS: importe ou exporte o seu log de QSOs em ficheiros ADIF padrão (.adi).
  • SINCRONIZAÇÃO DE QSOs: configure a integração com QRZ e LoTW para sincronizar e confirmar o log.
  • ELIMINAR QSOs: apaga QSOs locais (esta ação só afeta o log local da aplicação).
  • APLICAÇÃO: definições gerais, incluindo o idioma da interface.
  • ESPETROGRAMA: escolha quais sobreposições a cascata desenha — tempo de descodificação, hora UTC e sequência, mensagens, linhas de picos e a frequência da estação selecionada — e a escala do tipo de letra das sobreposições.
  • MAPA MUNDIAL: escolha o que o mapa mostra e por quanto tempo: QSOs realizados, spots e mensagens enviadas e recebidas, cada um com a sua janela de tempo.
  • HORA E LOCALIZAÇÃO: configure a sincronização do desvio de tempo (NTP ou GPS) e o seu locator Maidenhead.
  • OPERAÇÃO AUTOMÁTICA: configure as preferências de automação, o número de tentativas, os prefixos eliminados e se o AUTO responde a CQs dirigidos que não são para si.
  • MODOS DIGITAIS: as opções de descodificação de todos os modos num só lugar — FT8/FT4/FT2, LQ8, JS8 e WSPR —, incluindo a definição comum Descodificação profunda e quantas threads a descodificação pode usar.
  • SSB, CW, RTTY, JTTY e SSTV: as definições de cada um desses modos, descritas nas respetivas secções. O botão de engrenagem do painel de cada modo abre a mesma página.
  • SELEÇÃO DE BANDA: personalize as bandas ativas e o comportamento da troca de banda.
  • SERVIDOR WEB DE CONTROLO REMOTO: ative e configure o servidor web integrado para controlo remoto.
  • DEFINIÇÕES DO PSKREPORTER: serve para enviar ao PSKReporter as estações que recebe.
  • DEFINIÇÕES DO WSPRNET: envie spots WSPR ao WSPRnet e consulte o log recente de envios.
  • Procurar novas versões ao iniciar: mostra um aviso quando existe uma versão mais nova do qFT8 (veja Relatórios de erros e novas versões).
  • Enviar um resumo diário anónimo de desempenho (logo acima de Idioma, desligado por predefinição): cerca de uma vez por semana, com a aplicação aberta, envia um breve resumo da velocidade com que o qFT8 funciona no seu dispositivo (tempo de arranque, fluidez do ecrã, tempos de descodificação, tempos de áudio e de rádio, o modelo do dispositivo e o ecrã). Nunca contém o seu indicativo, locator, log, definições nem qualquer identificador.

Altifalantes e microfone

Os modos digitais só precisam de um dispositivo de som: o do rádio. SSB e CW precisam de um segundo, para si: um altifalante ou auscultadores para ouvir o rádio e, para SSB, um microfone para falar. Estes dois nunca devem ser a própria placa de som do rádio, porque o que diz voltaria diretamente, em ciclo.

  • No Android: Definições > Altifalantes e microfone, logo abaixo de CONFIGURAÇÃO DO DISPOSITIVO.
  • No computador: o cartão CONFIGURAÇÃO DO DISPOSITIVO tem duas metades: O RÁDIO à esquerda (a placa de som do rádio: o que o rádio ouve e o que ele envia) e O OPERADOR à direita.

Há duas escolhas:

  • O seu microfone (fala e o rádio transmite). Por baixo, uma pequena cascata em direto e um medidor de nível mostram o que o microfone está a captar: fale, e deve vê-los mexer-se.
  • Os seus altifalantes / auscultadores (onde ouve o rádio), com um botão TESTAR que toca neles um som curto.

Os dois começam em AUTO, que escolhe um dispositivo que não é o do rádio: num telemóvel, um headset quando há um ligado e, caso contrário, o microfone e o altifalante do próprio telemóvel; no computador, o primeiro dispositivo de som que não seja a placa do rádio. Mude-os apenas se o AUTO escolheu o dispositivo errado.

Dica: use auscultadores para SSB. Com um altifalante ao lado do microfone, o áudio recebido pode acionar o VOX ou ser ouvido na sua transmissão.

Operação automática (AUTO)

O modo AUTO é a principal forma de usar o qFT8. Nesse modo, a aplicação analisa automaticamente as mensagens descodificadas ao fim de cada ciclo e escolhe a estação mais relevante para contactar, segundo os seus critérios de alvo.

Como funciona a escolha do alvo

O separador Estações mostra uma lista das estações ativas, ordenada de modo que as candidatas mais relevantes (segundo os seus critérios) fiquem no topo. No fim de cada ciclo de descodificação, o qFT8 examina essa lista ordenada e tenta chamar a primeira estação elegível. Se não houver nenhum alvo elegível, começa automaticamente a chamar CQ para atrair chamadas. No modo AUTO, o qFT8 responde sempre a quem o chama.

Critérios e filtros

Pode ajustar a automação com os três menus pendentes do topo do separador Estações:

  • Alvo: define que «conquista» procura (Qualquer um, DXCC, Zona CQ, Zona ITU, Locator).
  • Intervalo: com que frequência aceita contactar a mesma entidade (uma vez, sempre, diário, semanal, mensal).
  • Qualificador: restringe a exigência de unicidade (por indicativo, por banda, até zona/entidade confirmada).

Intervenção manual: pode sempre intervir tocando no botão CALL de uma estação específica. Isto entra no modo CALL para esse QSO. Ao terminar, o qFT8 volta naturalmente ao modo AUTO.

Operação manual (CALL)

Embora o qFT8 seja bastante automatizado, pode assumir o controlo a qualquer momento. Tocar no botão CALL ao lado de qualquer estação no separador Estações entra imediatamente no modo CALL e tenta estabelecer um QSO com essa estação.

Quando o QSO com o alvo manual termina (com sucesso ou não), o qFT8 volta automaticamente ao modo AUTO e retoma a sua estratégia automática anterior (por exemplo, chamar CQ).

Tempos para quem opera manualmente

Se quiser mais tempo no fim do ciclo para tomar decisões manuais, pode ganhar margem ajustando as Definições de FT8 no separador Definições:

  • Diminuir «Início da descodificação»: começa a processar o áudio mais cedo.
  • Aumentar «Início da transmissão»: atrasa o começo da sua resposta.

Aviso: levar esses valores muito para as margens pode tornar as suas mensagens bem mais difíceis de descodificar pelas outras estações, porque reduz o tempo efetivo disponível para o sinal FT8 dentro da janela de sincronização.

Editar e registar QSOs à mão

O qFT8 regista sozinho os QSOs que faz nos modos digitais. Esta secção trata das três coisas que faz à mão no separador Log de QSOs: corrigir um QSO, registar um QSO feito de outra maneira (voz, Morse, outro rádio) e trabalhar com vários QSOs de uma vez.

O editor de QSO

Toque num QSO no separador Log de QSOs e o separador torna-se o editor desse QSO. Estão lá todos os campos guardados: o seu indicativo e o seu locator, os da outra estação, modo, banda, frequências, data e horas, potência, reportes, referências POTA e SOTA e o comentário.

  1. O QSO que está a ser editado: indicativo, modo, banda, data e hora.
  2. Situação: se o QSO está confirmado. Toque nela para Confirmar manualmente ou Desconfirmar manualmente (isto só altera o seu próprio log).
  3. Enviado: em que situação o QSO está no QRZ e no LoTW. Toque nele para enviar o QSO de novo a um serviço ou a todos.
  4. Um campo alterado fica destacado, com o valor antigo em vermelho ao lado e uma seta que restaura o valor antigo. Toque em qualquer valor para alterá-lo. O modo e a banda são escolhidos nas listas da aplicação, a banda acompanha a frequência que escreve, e um valor que não pode estar certo (um indicativo, um locator, uma data...) é recusado, com o motivo.
  5. VOLTAR: sai do editor. Se houver alterações, pergunta se devem ser descartadas.
  6. O número de alterações ainda não guardadas.
  7. ELIMINAR: elimina o QSO apenas do log desta aplicação, depois de escrever yes.
  8. GUARDAR: pede confirmação e depois guarda.

O que acontece no QRZ e no LoTW quando guarda. A pergunta de confirmação indica, para o QSO que está a editar:

  • QRZ: o QSO é atualizado lá. Se alterou o indicativo, a data, a hora, a banda ou o modo, o QRZ trata-o como outro QSO: é criada uma entrada nova e a antiga permanece, para ser eliminada por si em qrz.com.
  • LoTW: o QSO corrigido é enviado de novo como entrada nova; a antiga fica lá, sem confirmação e inofensiva.
  • Uma alteração que quebra uma confirmação (o indicativo, o seu indicativo, a data ou a hora de um QSO) precisa de ser confirmada escrevendo yes, porque o QSO deixará de coincidir com o log da outra estação.
  • Um QSO feito com um indicativo diferente do que está nas Definições não é enviado.

O qFT8 nunca elimina nada no QRZ nem no LoTW. Eliminar um QSO só o remove da aplicação. Se esse QSO está num serviço, ele pode voltar na próxima sincronização: elimine-o primeiro no serviço. A eliminação é irreversível, a menos que guarde uma cópia exportada do log.

O registo manual

O botão + do separador Log de QSOs abre o registo manual, um formulário rápido para os QSOs que faz por si próprio. Num telemóvel, roda o ecrã para retrato, com uma faixa estreita do espetrograma no topo (isto pode ser desligado em Definições > APLICAÇÃO > Interface do utilizador).

  1. Indicativo: escreva o indicativo e prima Enter no teclado: o QSO é registado com a hora atual, a caixa esvazia e pode escrever o próximo. O teclado fica aberto de um QSO para o seguinte.
  2. REGISTAR: o mesmo que Enter.
  3. LIMPAR / ANULAR: enquanto há um indicativo escrito, o botão diz LIMPAR e esvazia a caixa. Caso contrário, diz ANULAR e tira do log o último QSO desta sessão, devolvendo-o ao formulário para ser corrigido.
  4. CONCLUÍDO: fecha o registo manual. Se há um indicativo escrito, mas não registado, pergunta se deve registá-lo.
  5. A linha de consulta: o país do indicativo, o seu último QSO com ele e se é um duplicado. DUPE em laranja significa que já registou hoje essa estação nessa banda e nesse modo (pode registá-la mesmo assim).
  6. Os detalhes (deslize para os lados para ver mais): a hora (Agora, ou toque nela para definir uma data e uma hora), banda, modo, frequência em kHz, a frequência de receção quando é diferente, potência, reportes enviado e recebido, a referência POTA / SOTA da outra estação e a sua. Eles partem do que a aplicação está a sintonizar e são mantidos de um QSO para o seguinte.
  7. Esta sessão: quantos QSOs registou desde que abriu o registo manual. Num telemóvel, toque nela para vê-los numa lista.
  8. Os QSOs da sessão aparecem em coral com um ícone de relógio: já estão no seu log, mas não são enviados para o QRZ nem para o LoTW até tocar em CONCLUÍDO, para que um erro de escrita ainda possa ser anulado. Toque num deles para o anular ou editar.

O botão QSO dos painéis SSB, CW, RTTY e SSTV abre o mesmo formulário como um pequeno cartão, já preenchido com o modo, a frequência e a estação, para um QSO de cada vez.

Selecionar vários QSOs

Mantenha premido um QSO no separador Log de QSOs para iniciar uma seleção (no computador, Ctrl-clique, ou Shift-clique para um intervalo). Depois toque noutros QSOs para adicioná-los ou removê-los.

  1. X: sai da seleção sem fazer nada.
  2. Quantos QSOs estão selecionados.
  3. SELECIONAR INTERVALO: toque nele e depois no QSO onde o intervalo termina: tudo o que está no meio é selecionado.
  4. TODOS e NENHUMA.
  5. AÇÕES: o que fazer com os QSOs selecionados:
    • Confirmar manualmente / Desconfirmar manualmente.
    • Exportar (ADIF): um ficheiro só com esses QSOs.
    • Exportar com uma referência POTA / SOTA: o mesmo, com o seu parque ou cume escrito em cada QSO do ficheiro (o log em si não é alterado).
    • Adicionar a uma ativação POTA / SOTA e Remover da respetiva ativação (veja Ativar um parque ou um cume).
  6. Os QSOs selecionados ficam marcados e destacados.

Cada ação informa primeiro quantos QSOs vai alterar e pede confirmação, e uma alteração pode ser desfeita logo em seguida. Nada é eliminado no QRZ nem no LoTW, nunca.

Importação/exportação ADIF

O qFT8 usa o formato padrão ADIF (Amateur Data Interchange Format) para a interoperabilidade com outros programas de log e serviços na nuvem, e para backups manuais.

Importar QSOs

A importação permite trazer para o seu log local do qFT8 registos de outras origens (como outros programas de log ou backups de outros dispositivos).

  • Opções de filtro: todos os modos são importados. Escolhe se restringe a importação ao seu indicativo atual ou se inclui todos os operadores.
  • Remoção automática de duplicados: o qFT8 combina os registos de forma inteligente. Ele evita duplicados comparando os Log IDs do QRZ e as datas e horas dos QSOs. Se um registo importado tem um estado de confirmado ou um Log ID válido que falta no seu registo local, a entrada local é atualizada com os dados melhores.

Exportar QSOs

Tocar em EXPORTAR QSOs gera um ficheiro ADIF 3.1.6. No Android abre-se o menu de partilha do sistema, que permite guardar o log no dispositivo ou enviá-lo por e-mail ou mensagem; no computador escolhe onde guardar o ficheiro.

  • Intervalo de tempo: pode exportar todo o seu histórico ou usar os seletores de data/hora UTC para isolar uma ativação ou um período de concurso.
  • Filtros de estado: úteis para pedir diplomas (exporte «Apenas confirmados») ou para envios manuais a outros serviços (exporte «Apenas não enviados para o QRZ», para evitar duplicados).
  • Critérios de caçador: filtre o seu log para exportar «Exportar todo o log», «Exportar apenas caçador POTA» ou «Exportar apenas caçador SOTA» e gerar ficheiros específicos para pedidos de diplomas, com as referências dos contactos preenchidas (<POTA_REF> / <SOTA_REF>).
  • Referência SOTA: como detalhado na secção SOTA, o qFT8 pode introduzir automaticamente a referência do cume no campo <MY_SOTA_REF> de cada registo exportado.
  • Referência POTA: como detalhado na secção POTA, o qFT8 pode introduzir automaticamente a referência do parque nos campos <MY_SIG>, <MY_SIG_INFO> e <MY_POTA_REF> de cada registo exportado. Vários parques, separados por vírgulas, dão um ficheiro por parque (veja «Que parque vai no ficheiro?»).

Os nomes dos ficheiros exportados

  • Sem referência: qFT8-YYYYMMDD-HHMMSS.adi, a data e a hora (UTC) da exportação, por exemplo qFT8-20261006-181500.adi. Os filtros de estado acrescentam _confirmed ou _notuploaded depois da hora, de modo que os ficheiros de uma pasta ficam ordenados por data.
  • Com uma referência POTA: CALLSIGN@PARK-YYYYMMDD.adi, por exemplo K1ABC@US-1234-20261006.adi. Este é o nome que o programa de parques pede. Há um ficheiro para cada parque e cada dia UTC; portanto, uma exportação que atravessa a meia-noite UTC dá dois ficheiros.
  • Com uma referência SOTA: um ficheiro, por exemplo K1ABC@W1_HA-001-20261006.adi (a «/» de um cume ou de um indicativo não pode fazer parte de um nome de ficheiro e é escrita «_»).
  • No computador, uma exportação nunca substitui um ficheiro que já existe: se o nome está ocupado, o novo ficheiro é guardado como name (1).adi, depois name (2).adi, e assim por diante.

Nota: para logs muito grandes (acima de 100KB), o qFT8 mostra um aviso, porque remover os duplicados e ordenar pode demorar um pouco, especialmente num telemóvel.

Serviços de envio de QSOs

O qFT8 pode enviar cada QSO que regista para vários logs online ou da sua rede doméstica: QRZ, LoTW, Wavelog, Cloudlog, eQSL e outro qFT8 (qFT8log). Cada um tem uma linha no topo das Definições: uma caixa de seleção para ativá-lo e um botão de engrenagem que abre a página do próprio serviço.

  • A caixa de seleção fica a cinzento até o serviço ser validado: abra a página dele, introduza os dados e prima VALIDAR.
  • Cada página começa com uma breve explicação e um botão ? que abre este manual na seção do serviço. Ela também mostra quantos QSOs ainda não foram enviados, com ENVIAR AGORA, e um botão REPOR PREDEFINIÇÕES (ele nunca apaga uma conta, uma chave ou uma palavra-passe).
  • Quando não foi possível alcançar um serviço desde a última vez que funcionou, a linha dele fica vermelha e uma linha vermelha abaixo diz Não foi possível ligar desde e a data e a hora.

Quando um QSO conta como enviado?

A marca verde no log, na lista de estações, no mapa e no controlo remoto web segue uma única regra. A página de cada serviço tem uma caixa Considerar um QSO enviado se estiver enviado aqui. Ela vem ativada para o QRZ e o LoTW e desativada para os demais.

  • Um serviço só conta quando está configurado: validado e ativado.
  • Um QSO é considerado enviado assim que qualquer serviço que conta o tem.
  • Quando nenhum dos serviços configurados tem a caixa marcada, todos os serviços configurados contam. Assim, se configurar só o qFT8log, a aplicação espera apenas pelo qFT8log, nunca pelo QRZ ou pelo LoTW.
  • Sem nenhum serviço configurado, as caixas marcadas decidem a partir do que o próprio QSO traz (por exemplo, um log importado de outro programa mantém as marcas dele).
  • Um QSO importado do LoTW conta como já presente no QRZ e não é enviado para lá. Um QSO que veio de um serviço conta como enviado a esse serviço e nunca é devolvido a ele.
  • A estrela (confirmado) exige que o QSO esteja enviado conforme essa regra e confirmado por qualquer serviço, a menos que o tenha confirmado ou desconfirmado manualmente.

A exportação ADIF pode escolher Não enviados para um serviço por vez; as opções dos serviços não configurados ficam a cinzentos. O qFT8 nunca apaga um QSO em nenhum serviço: apagar um QSO aqui apenas avisa que ele ainda está lá.

Integração com o QRZ

O qFT8 tem uma integração profunda com o QRZ.com para manter o seu logbook sincronizado automaticamente. Note que a integração com o QRZ é um serviço por subscrição, que requer uma subscrição paga do QRZ (XML Logbook Data ou superior). Se prefere uma alternativa gratuita, considere a integração com o LoTW, oferecida sem custo pela ARRL.

Como funciona

Para ativar a integração com o QRZ, tem de introduzir a sua Chave API do QRZ no separador Definições. Encontra a sua chave de API na página oficial da API do Logbook do QRZ. Depois de a introduzir e VALIDAR, pode ativar «Enviar QSOs para o QRZ quando concluídos e em segundo plano» para que tudo seja feito automaticamente em segundo plano.

  • Envios automáticos: sempre que um QSO é concluído (chegando ao estado 6/6 DONE), o qFT8 tenta enviá-lo imediatamente ao seu logbook do QRZ.
  • Fiabilidade em segundo plano: se um envio falha (por exemplo, por falta de ligação à internet ou tempo esgotado no servidor), o qFT8 não desiste. Uma tarefa em segundo plano repete automaticamente os envios que falharam a cada 5 minutos. Esse processo é silencioso e garante que o seu log acabe por chegar à nuvem quando a ligação voltar.
  • Omissões inteligentes: o qFT8 protege a integridade do seu logbook enviando apenas os QSOs que correspondem ao indicativo configurado e ao modo FT8. As entradas que não são FT8, os QSOs de outros indicativos e os QSOs importados do LoTW são saltados automaticamente, para evitar um excesso de pedidos à API.

Sincronização das confirmações

A integração vai além do envio. O qFT8 também consulta o QRZ para saber se os seus QSOs foram confirmados.

  • Verificação imediata: 30 segundos depois de um QSO ser concluído e enviado, o qFT8 consulta o QRZ para ver se a outra estação também enviou o QSO; se enviou, o QSO é sincronizado de imediato como confirmado.
  • Sincronização automática: por predefinição, o qFT8 consulta o QRZ a cada 6 horas (configurável), em lotes de 250 QSOs, percorrendo todo o seu log não confirmado para que mesmo os QSOs mais antigos acabem por ser verificados.
  • Estrela de confirmação (★): quando um QSO enviado ao QRZ é confirmado no QRZ ou no LoTW, ele é destacado com uma estrela dourada. Também pode confirmar manualmente qualquer QSO para mostrar esse indicador. Quando o QRZ informa uma confirmação, o ícone de estado no separador Log de QSOs muda automaticamente para uma estrela dourada.
  • Sincronização manual: a atualização dos 250 QSOs sincronizados há mais tempo também pode ser iniciada manualmente nas definições.

Dica: pode acompanhar o progresso da sincronização nas definições, em «QSO mais antigo sincronizado em». Não há pressa em manter isto em dia: o qFT8 cuida disso com o tempo.

Estratégia de sincronização do log

Nas definições de sincronização, pode escolher como o qFT8 decide que um QSO está «totalmente enviado», com a opção «Considerar um QSO enviado (✓) quando for enviado para:»

  • LoTW ou QRZ, qualquer um: uma boa predefinição se só tem um dos serviços configurado.
  • Ambos: escolha esta opção para o máximo de segurança; o QSO precisa de ser enviado com sucesso aos dois serviços antes de ser considerado finalizado e pronto para a verificação de confirmação.
  • QRZ (exceto os importados do LoTW): recomendado se o QRZ é o seu logbook principal. Nota: os QSOs importados do LoTW são marcados como sincronizados, mas não são enviados ao QRZ, para respeitar os limites da API (que só permite envios um a um); eles podem ser sincronizados depois, dentro do próprio QRZ.
  • LoTW: recomendado se considera o LoTW a sua referência principal.

Integração com o Logbook of the World (LoTW)

O qFT8 tem uma integração sólida com o ARRL Logbook of the World (LoTW). A integração com o LoTW é muito recomendável para confirmar os seus contactos e conquistar diplomas como o DXCC e o WAS.

Requisitos de configuração

Para ativar todas as funcionalidades do LoTW, incluindo os envios automáticos e as verificações de confirmação, precisa de indicar quatro dados no separador Definições:

  • 1. Nome de utilizador do LoTW: o seu indicativo oficial, usado no serviço LoTW.
  • 2. Palavra-passe do LoTW: a palavra-passe que usa para entrar no site do LoTW. Ela é diferente da palavra-passe do certificado.
  • 3. Certificado TQSL .p12: um ficheiro de assinatura digital exportado do programa TQSL. Para saber como pedir e exportar esse certificado, consulte a página oficial de ajuda do LoTW.
  • 4. Palavra-passe do certificado: a palavra-passe que definiu ao exportar o ficheiro .p12 do TQSL (pode ficar vazia, se preferiu não definir uma).

Local da estação automático: dados como a Zona ITU, a Zona CQ e o nome da estação são determinados automaticamente a partir do seu indicativo. Esses campos não precisam de configuração manual.

Funcionalidades

  • Envios automáticos: com Enviar QSOs para o LoTW quando concluídos e em segundo plano ativado, o qFT8 assina e envia automaticamente cada novo QSO ao LoTW, em segundo plano, assim que ele é registado.
  • Verificação automática da confirmação: quando ativada, o qFT8 faz uma única verificação de confirmação exatamente 30 segundos depois de um envio bem-sucedido. Assim vê quase de imediato se o contacto foi confirmado.
  • Sincronização periódica em segundo plano: configure Sincronizar confirmações a cada __ horas para procurar novas confirmações em segundo plano no intervalo que preferir (por exemplo, a cada 6 horas). Isto mantém todo o seu logbook em dia, sem intervenção manual.
  • Importar o logbook: toque em IMPORTAR QSOs DO LoTW para transferir todo o seu histórico do LoTW para o qFT8. Note que esses QSOs importados não são enviados automaticamente ao QRZ, para respeitar os limites de uso da API.
  • Indicador de pendências: um pequeno ponto amarelo no botão Log de QSOs indica que há QSOs à espera de envio ao LoTW.

Wavelog

O Wavelog é um programa de livro de registo que se executa num servidor web próprio (um pequeno computador em casa ou espaço web alugado) e se abre num navegador. O qFT8 envia-lhe cada QSO assim que é registado e lê de volta quais deles o seu Wavelog confirmou. O qFT8 comunica com ele através da interface publicada do Wavelog: docs.wavelog.org/developer/api.

Configuração

  1. No Wavelog, abra o menu da conta > API Keys e crie uma chave com direitos de leitura e escrita.
  2. No qFT8, abra as Definições, prima a roda dentada junto a Wavelog e introduza o Endereço do servidor (o endereço em que abre o Wavelog, por exemplo https://log.example.org) e a Chave API. Um endereço escrito sem http:// ou https:// é testado primeiro com https; se o servidor só fala http simples (o servidor de outro qFT8 fala), o qFT8 usa http e a página avisa que a chave circula sem proteção.
  3. Opcional, para que as edições também sejam enviadas: crie no Wavelog um token API v2 (menu da conta > API Keys, separador API v2, com os âmbitos qso:read e qso:write) e escreva-o como Token de edição. VALIDAR verifica-o sem alterar nada.
  4. Prima VALIDAR. O qFT8 verifica a chave e lista os locais de estação do seu Wavelog; escolha aquele a que os seus QSOs pertencem (havendo só um, é escolhido automaticamente).
  5. Assinale Wavelog no topo das Definições. A partir de agora todo o novo QSO é enviado para lá, e os registados antes também são enviados.

O que acontece

  • Offline: um QSO que não pode ser enviado fica à espera no registo e é enviado quando o servidor voltar a responder (nova tentativa ao fim de 1 minuto, depois com menos frequência, até uma vez por hora). Enquanto não for possível contactar o servidor, a respetiva linha nas Definições fica vermelha com "Couldn't connect as of ...".
  • Duplicados: um QSO que o seu Wavelog já tem conta como enviado.
  • Recusado: um QSO que o Wavelog recusa não é enviado de novo até o editar ou reenviar; o editor de QSO mostra o motivo. Uma chave que deixa de funcionar interrompe os envios até premir VALIDAR novamente.
  • Confirmações: uma vez por hora (e quando prime ENVIAR AGORA) o qFT8 pergunta ao Wavelog quais dos seus QSOs estão confirmados (LoTW, QSL em papel, eQSL) e assinala-os nas linhas Enviado e Situação do editor de QSO, as mesmas linhas e marcas de QRZ e LoTW.
  • Edições: com o Token de edição definido, um QSO editado é encontrado no seu Wavelog e atualizado lá (vale a alteração mais recente; as marcas de confirmação que o Wavelog guarda nunca são tocadas). Sem ele, a interface de envio do Wavelog só consegue adicionar QSOs, pelo que uma edição não é enviada: altere-a também no Wavelog.
  • QSOs de outros indicativos: um QSO registado com outro indicativo que não o seu (indicativo de clube ou de evento especial) fica retido para QRZ e LoTW, mas vai para o Wavelog enquanto Enviar também os QSO feitos com outros indicativos estiver assinalado (o predefinido).
  • Eliminações: o qFT8 nunca elimina nada no Wavelog. Elimine o QSO aí, por si.
  • "Considerar um QSO enviado se enviado aqui", na página, decide se um envio para o Wavelog conta para a marca de "enviado" (desativado por predefinição).

Importar QSOs do Wavelog

IMPORTAR QSOs DO WAVELOG, no fundo da página do Wavelog, copia os QSOs do local de estação escolhido para o log do qFT8, com as confirmações LoTW, QSL em papel e eQSL.

  • O que importa: todos os modos. De, Até, Bandas e O indicativo começa por limitam a importação (qualquer = sem limite). Os QSOs feitos com outro indicativo que não o seu são ignorados, a menos que Importar QSOs para indicativos diferentes do atual esteja assinalado.
  • Já no log: um QSO que o log já tem é fundido, nunca acrescentado duas vezes (as mesmas regras das importações do QRZ e do LoTW); um QSO que corrigiu aqui mantém a sua correção e recebe apenas as confirmações.
  • Nunca reenviados: os QSOs importados contam como já estando no Wavelog. Uma correção que faça depois no qFT8 vai para lá (com o Token de edição).
  • PARAR termina a importação depois da parte em curso; o que já chegou fica. A linha por baixo do botão conta o que foi recebido, acrescentado e fundido.
  • Nada é apagado, nem aqui nem no Wavelog. Um QSO que apagou no qFT8 volta com a importação seguinte.

Ligações seguras

  • Prefira um endereço https://. Com http:// a chave viaja sem proteção: utilize-o apenas na sua rede doméstica.
  • O Android 6 e o 7.0 não confiam em alguns certificados mais recentes que muitos destes servidores usam; nesses casos, um servidor https:// pode não ligar. Na sua rede doméstica, o endereço http:// do servidor funciona.
  • O iPhone liga-se apenas a endereços https://.

Diferenças em relação ao Wavelog

  • Sem confirmações de volta: o Cloudlog não oferece aos outros programas forma de ler quais os QSOs confirmados, pelo que o qFT8 apenas lhe envia.
  • Indicativo da estação: o Cloudlog recusa um QSO cujo indicativo da estação seja diferente do do local de estação escolhido. Esse QSO aparece como recusado no editor; escolha para ele, no Cloudlog, um local de estação correspondente.
  • As edições não são enviadas; nada é alguma vez eliminado; o modo offline, os duplicados, o aviso vermelho "Couldn't connect" e as notas sobre ligações seguras são como no Wavelog.
  • Importar: o Cloudlog não pode ser lido por outros programas. Para trazer o seu log para o qFT8, exporte um ficheiro ADIF no Cloudlog e use IMPORTAR QSOs DO ADIF em Definições > Importar/Exportar logs (ver ADIF).

Ativações (POTA / SOTA)

O Cloudlog obtém o seu parque ou cume do local de estação para onde vai um QSO, nunca do QSO em si. Para uma ativação, crie (ou escolha) no Cloudlog um local de estação com a referência do parque ou cume no campo POTA / SOTA e no nome, por exemplo Park US-0001. Enquanto a ativação decorre, o qFT8 envia os seus QSOs para esse local por si próprio. Quando nenhum local tem a referência, o qFT8 avisa uma vez por ativação e envia para o seu local habitual, sem a referência.

eQSL

O eQSL (eqsl.cc) troca cartões QSL eletrónicos: cada QSO enviado para lá passa a ser um cartão na caixa de entrada do eQSL da outra estação. O qFT8 só acrescenta cartões; nunca elimina nada no eQSL.

Configuração

  1. Toque na roda dentada da linha Sincronizar QSOs com eQSL no topo das Definições.
  2. Introduza o seu Nome de utilizador eQSL (normalmente o seu indicativo) e a sua Palavra-passe eQSL. Se tem várias contas do eQSL (localizações) sob um indicativo, introduza o Alcunha do QTH da localização tal como está escrito em eqsl.cc; caso contrário, deixe vazio e o eQSL escolhe a conta pela data do QSO.
  3. Prima VALIDAR. Apenas lê a sua caixa de entrada do eQSL para verificar o início de sessão: nenhum cartão é enviado.
  4. Assinale Sincronizar QSOs com eQSL. Os QSOs ainda não enviados saem de imediato, um por segundo, e cada novo QSO sai quando é registado.

O que deve saber

  • Considerar um QSO enviado se estiver enviado aqui está desativado para o eQSL: um cartão no eQSL não faz, por si só, aparecer o visto verde do registo (veja Serviços de envio de QSOs). Assinale-o se quiser.
  • Um cartão não pode ser alterado. Quando edita um QSO que já está no eQSL, nada é enviado por si só. Para enviar um cartão corrigido, use Reenviar para eQSL no editor de QSO; o cartão antigo fica na caixa de entrada da outra estação até o eliminar em eqsl.cc.
  • LQ8: o eQSL aceita apenas os modos ADIF oficiais, pelo que os seus QSOs são enviados como MFSK, e o comentário indica o modo real (“QSO by qFT8, mode LQ8”). Os outros serviços mantêm a sua própria forma.
  • Um QSO que o eQSL já tem é respondido como duplicado e conta como enviado. Um que ele recusa (por exemplo, uma data que nenhuma das suas contas cobre, ou um modo que não conhece) aparece como recusado no editor de QSO, com as palavras do próprio eQSL, e não é tentado de novo até o reenviar.
  • Offline, ou enquanto o eQSL está em baixo para manutenção, os cartões aguardam e são tentados de novo mais tarde (após 1 minuto, depois mais tempo, até uma hora); o aviso vermelho Couldn't connect da linha diz desde quando. Se a palavra-passe for recusada (por exemplo, alterou-a em eqsl.cc), o envio pára até fazer VALIDAR outra vez.
  • As confirmações (cartões recebidos) ainda não são lidas de volta.

O qFT8 como servidor Wavelog

Em Definições > Servidores qFT8 > Servidor Wavelog, o qFT8 responde na sua rede doméstica como se fosse um Wavelog: qualquer programa que consiga enviar QSOs para o Wavelog (incluindo outro qFT8) pode enviá-los para este qFT8.

Configuração

  1. Ative Executar o servidor Wavelog, mantenha a Porta (13500) ou escolha outra, e introduza uma Chave API com pelo menos 8 caracteres (faça-a longa e aleatória: é a única coisa que mantém os outros de fora).
  2. No outro programa, configure o Wavelog com o endereço que a página mostra, escrito por inteiro: http://, o endereço deste dispositivo, dois pontos e a porta, por exemplo http://192.168.1.20:13500/ (a maioria dos programas de registo precisa do http:// e da porta escritos; outro qFT8 encontra-os sozinho), a mesma chave e a estação 1 (noutro qFT8: VALIDAR escolhe-a).

A porta pode ser alterada a qualquer momento: o servidor passa para a nova porta de imediato (e para de imediato quando é desligado).

Ver o registo num navegador

Abra o mesmo endereço (http://192.168.1.20:13500/) num navegador da sua rede doméstica: depois de escrever a chave do servidor, mostra o seu registo de QSOs, do mais recente para o mais antigo, só de leitura; os QSOs mais antigos carregam à medida que se desloca, e os novos ou alterados aparecem sozinhos. A chave nunca é enviada: o navegador responde a um desafio de utilização única com um valor feito a partir dela, e um endereço que responde mal fica bloqueado durante algum tempo. O servidor Cloudlog e o servidor de registo do qFT8 mostram a mesma página nas suas próprias portas, com a sua própria chave ou palavra-passe.

O que faz

  • Cada QSO recebido, em qualquer modo e com qualquer indicativo, entra no registo e na lista de QSO e segue para os serviços configurados aqui (QRZ, LoTW, Wavelog, ...), nunca de volta para onde veio. Um QSO que o registo já tem é respondido como duplicado e não é reencaminhado.
  • Responde aos pontos de acesso que um programa de registo usa: api/qso (um ou vários QSOs em ADIF), api/version, api/station_info, api/check_auth, api/auth, api/get_contacts_adif (para que um qFT8 mais abaixo numa cadeia possa ler as confirmações de volta) e api/radio (aceite e ignorado). Não há forma de alterar ou eliminar um QSO através dele.
  • Segurança: apenas rede doméstica, http simples (como o servidor web de controlo remoto); a chave é comparada de forma a não ser revelada; um endereço que envie 10 chaves erradas fica bloqueado durante 10 minutos; no máximo 20 pedidos por segundo por endereço, 128 KB e 500 QSOs por pedido; tudo o que estiver mal formado recebe uma resposta de erro.
  • Onde funciona: no Android também em segundo plano quando "executar em segundo plano" está ativo; no computador enquanto o programa estiver aberto; no iPhone apenas enquanto o qFT8 estiver aberto.

Cadeias

Servidores e serviços combinam-se em cadeias: várias estações (telemóveis, computadores) enviam os seus QSOs para um qFT8 que os reúne e é o único a enviar para o QRZ e o LoTW; esse pode também reencaminhar tudo para um Wavelog ou para outro qFT8 mantido como cópia de segurança. As confirmações fazem o caminho inverso: o qFT8 coletor obtém-nas do QRZ / LoTW / do seu Wavelog, e os qFT8 que enviam para o respetivo servidor Wavelog leem-nas de volta de hora a hora. Os duplicados nunca são reencaminhados, pelo que um ciclo numa cadeia pára por si.

Summits On The Air (SOTA)

O qFT8 traz ferramentas completas e integradas para os caçadores (chasers) e para os ativadores do SOTA (Summits On The Air): obtenção automática de spots, acompanhamento das referências em tempo real, destaque das conquistas e filtros próprios de exportação ADIF.

Obtenção automática de spots de cumes em direto

Quando há acesso à internet, o qFT8 liga-se automaticamente à API oficial do SOTA em segundo plano (atualizando a cada 90 segundos) para obter as ativações de cumes em curso em todo o mundo.

  • Exibição no mapa mundial: os ativadores de cumes em atividade aparecem no mapa mundial com marcadores de cume (⛰️), indicativos, nomes dos cumes, altitudes e frequências.
  • Associação automática de referências: quando ouve um ativador no ar, o qFT8 cruza o indicativo dele com a base de spots em direto para obter a referência exata do cume (por exemplo, HB/BE-001, W6/NC-001).
  • Preenchimento posterior automático: se conclui um QSO com uma estação que chama CQ SOTA antes de o spot dela ter sido transferido ou de a referência ter sido recebida, o qFT8 acompanha os spots que chegam e preenche automaticamente a referência do cume nos QSOs registados recentemente (até 1 hora antes).

Operar como caçador (chaser) SOTA

Para caçar estações que estão a ativar cumes:

  1. No separador Estações, escolha Caçador SOTA (ou Caçador POTA + SOTA) no menu pendente de prioridade do alvo.
  2. Emblemas e coluna de referência: as estações SOTA em atividade (com spot online ou a transmitir CQ SOTA) são marcadas com um emblema SOTA na linha 2. Além disso, o cabeçalho da coluna DXCC muda para Referência SOTA e mostra diretamente o código do cume.
  3. Destaque de cumes trabalhados e por trabalhar:
    • Cume ainda não trabalhado: marcado com um emblema SOTA roxo vivo e com a referência em roxo, indicando um cume novo para caçar.
    • Cume já trabalhado: mostrado com um emblema cinzento discreto, para distinguir de imediato os cumes novos dos que já estão no seu log.
  4. Caça em AUTO: no modo AUTO, o qFT8 dá prioridade automaticamente aos ativadores SOTA ainda não trabalhados em relação às estações comuns que chamam CQ, ordenando-os pelo sinal mais forte (SNR).

Gerir e editar referências SOTA no log

O qFT8 tem ferramentas próprias para consultar e editar o seu histórico de caça SOTA:

  • Vista Caçador SOTA no separador Log de QSOs: no separador Log de QSOs, selecione a vista Caçador SOTA para ver as referências dos cumes. Os primeiros contactos confirmados com um cume são destacados em dourado, e as primeiras conquistas não confirmadas, em amarelo.
  • Editar referências de cumes: toque em qualquer QSO do log para abrir o editor de QSO e depois toque no campo SOTA dele para adicionar, alterar ou corrigir um código de cume (por exemplo, HB/BE-001).
  • Sincronização automática com o logbook do QRZ (ACTION=REPLACE): se o QSO já foi enviado ao QRZ, editar a referência do cume marca o registo automaticamente e atualiza o seu logbook do QRZ no próprio registo, sem criar entradas duplicadas.
  • Nota sobre o LoTW: o LoTW (Logbook of The World) não é atualizado automaticamente quando edita referências, porque o LoTW não permite modificar QSOs já enviados.

Operar como ativador SOTA

Para fazer uma ativação SOTA a partir de um cume:

  1. Sincronize a hora: verifique se o relógio do dispositivo está certo antes de sair para o campo.
  2. Inicie a ativação: no separador Definições, toque em ATIVAÇÃO SOTA e indique o seu cume, para que cada QSO seja registado com ele e contado (veja Ativar um parque ou um cume).
  3. Defina o seu modificador de CQ: no separador Definições, defina o Modificador de CQ como SOTA. Cada chamada de CQ transmitirá CQ SOTA [Callsign].
  4. Configure o modo AUTO: no separador Estações, escolha Chamar CQ como prioridade do alvo e ative o modo AUTO.
  5. Comece a ativar: ligue o TX. O qFT8 chama CQ automaticamente e responde, um por um, aos caçadores que chamam.

Intervenção manual: se vários caçadores chamam ao mesmo tempo e quer escolher uma estação, toque em CALL na linha dela. Quando esse contacto termina, o qFT8 volta automaticamente a chamar CQ.

Exportar os seus logs SOTA (caçadores e ativadores)

O qFT8 gera exportações ADIF à medida, tanto para os pedidos de caçador como para os logs de ativador:

  1. Vá a Definições e toque em Exportação de ficheiro ADIF.
  2. Para caçadores (chasers):
    • Defina Critérios de caçador como Exportar apenas caçador SOTA para exportar só os QSOs em que um cume foi contactado (com <SOTA_REF> preenchido).
  3. Para ativadores (o caminho mais rápido é o botão EXPORTAR da sua ativação; os passos abaixo fazem o mesmo à mão):
    • Selecione Período selecionado e ajuste-o às horas de início e de fim da sua ativação.
    • Em Evento, escolha SOTA e indique o código do cume ativado (por exemplo, HB/BE-001). O qFT8 insere a sua referência em <MY_SOTA_REF> em cada registo.
  4. Cume a cume (S2S): se trabalhou outro ativador enquanto ativava um cume, o qFT8 inclui no ficheiro exportado tanto o seu cume de ativador (<MY_SOTA_REF>) como o cume do contacto (<SOTA_REF>).
  5. Toque em EXPORTAR QSOs para partilhar ou guardar o ficheiro ADIF padronizado.

Ativar um parque ou um cume

Quando opera a partir de um parque (POTA) ou de um cume (SOTA), inicie uma ativação no qFT8. A partir daí, cada QSO que regista, em qualquer modo, leva automaticamente o seu parque ou cume, o qFT8 conta-os por si e, no fim, grava com um toque os ficheiros que os programas pedem.

Iniciar

  1. No separador Definições, toque em ATIVAÇÃO POTA ou ATIVAÇÃO SOTA (logo acima de EXPORTAR DEFINIÇÕES / IMPORTAR DEFINIÇÕES).
  2. Escreva a sua referência, por exemplo US-1234 para um parque ou W1/HA-001 para um cume. Se está em vários parques ao mesmo tempo (um «two-fer»), separe-os com vírgulas. O qFT8 verifica o formato enquanto escreve e oferece as referências que usou recentemente.
  3. Toque em INICIAR. O botão fica azul e mostra a referência e o número de QSOs.

Uma ativação de parque e uma de cume podem estar abertas ao mesmo tempo; cada QSO recebe então as duas referências. Para chamar CQ POTA ou CQ SOTA nos modos digitais, ajuste o Modificador de CQ como descrito nas secções POTA e SOTA.

O qFT8 também pode oferecer-se para a iniciar por si: se os spots que transfere para o mapa mundial mostram o seu próprio indicativo como ativador, pergunta Iniciar aí uma ativação POTA? E se escrever o seu parque ou cume na caixa vazia O meu POTA / O meu SOTA do registo manual, pergunta se deve iniciar uma ativação com ela.

Anunciar, para que os caçadores o encontrem

Quando inicia uma ativação por si próprio (não a partir de um spot que já o anunciou), o qFT8 pergunta Anunciar no POTA? (ou no SOTA) e mostra o que os caçadores veriam, por exemplo FT8 on 20m (14074 kHz). AGORA NÃO não anuncia nada. ANUNCIAR abre um diálogo curto:

  • Bandas e Modos: assinale um ou mais de cada. A banda e o modo em que o qFT8 está já vêm assinalados. O qFT8 envia um anúncio por cada parque, banda e modo escolhidos e diz quantos são antes de premir ANUNCIAR.
  • Os modos que o programa não lista são anunciados como DATA, com o modo real no comentário do anúncio. Uma banda e um modo sem frequência habitual (RTTY nos 60 m) ficam de fora, e o diálogo avisa.
  • A frequência é aquela em que o seu rádio está para a banda e o modo em que se encontra, e a frequência de chamada habitual para os outros.
  • Só SOTA: o diálogo pede também o seu nome de utilizador e a palavra-passe do SOTAwatch (o seu próprio início de sessão no SOTA). O qFT8 guarda-os para a próxima vez, como as palavras-passe dos outros serviços.

Depois disso, o qFT8 volta a anunciar a ativação de 30 em 30 minutos (os anúncios desaparecem da lista passada cerca de uma hora), enquanto a ativação estiver aberta e o qFT8 estiver a funcionar: no ecrã, ou minimizado com o qFT8 a correr em segundo plano e o rádio ligado. Pára quando termina a ativação e nunca anuncia por si só se o qFT8 estava fechado: no arranque seguinte, depois de escolher continuar a ativação, pergunta Anunciar de novo?

Se um anúncio não chega (sem internet, o site recusa-o ou o início de sessão no SOTA está errado), o qFT8 diz o que correu mal e oferece TENTAR DE NOVO, ou ANUNCIAR MANUALMENTE, que abre a página de spots do programa no navegador para anunciar por si próprio. Sem ligação, tenta também de novo sozinho de 5 em 5 minutos.

Para anunciar com outras bandas ou modos, ou para ver quando foi anunciado pela última vez, prima ANUNCIAR no cartão da ativação (toque no marcador azul) ou na vista de QSOs da ativação. O diálogo oferece então também PARAR DE REANUNCIAR. Quando muda de modo durante uma ativação anunciada, o qFT8 pergunta se o novo modo deve ser anunciado também.

Enquanto está aberta: o marcador azul

Um marcador azul POTA ou SOTA fica no canto inferior direito da cascata enquanto a ativação está aberta, com o número de QSOs da ativação ao lado da palavra: POTA 10. Cada QSO que regista conta, e o número volta a diminuir quando um QSO é removido da ativação, eliminado ou desfeito no registo manual. Com dois parques ao mesmo tempo continua a haver um só número, porque cada QSO conta para os dois parques. Onde há pouco espaço, o marcador mostra só o número ao lado do ícone, e onde nem isto cabe ele é desenhado menor, junto com o aviso vermelho que divide a linha com ele. Toque nele para ver o estado da ativação:

  • A referência e a contagem: os QSOs feitos, em relação ao número que o programa exige para uma ativação válida (10 para um parque, 4 para um cume), e quantos deles foram com outro parque ou cume (P2P / S2S).
  • VER ATIVAÇÃO: a lista dos QSOs dela (abaixo).
  • TERMINAR ATIVAÇÃO: encerra a ativação. Pergunta sempre antes, com CONTINUAR para prosseguir.
  • FECHAR: fecha o cartão.

Os QSOs da ativação

  1. Voltar ao log completo de QSOs.
  2. A ativação: programa e referência, quando começou (UTC) e os QSOs dela.
  3. +: abre o registo manual para registar um QSO à mão diretamente nesta ativação.
  4. ADICIONAR QSOs: adiciona QSOs que já estão no seu log, por intervalo de tempo. Use quando tiver esquecido de iniciar a ativação: escolha de quando até quando, e o qFT8 diz quantos QSOs vai adicionar antes de fazê-lo.
  5. EXPORTAR: grava os ficheiros para enviar (abaixo).
  6. O parque ou o cume da outra estação, quando ela também estava a ativar.
  7. O marcador da ativação aberta.

Para tirar QSOs de uma ativação, mantenha um premido para selecioná-lo, toque nos outros, toque em AÇÕES e escolha REMOVER DESTA ATIVAÇÃO. Os QSOs ficam no seu log; apenas a sua referência é removida deles. Também pode mover um único QSO a partir do editor de QSO, com a linha Ativação POTA / Ativação SOTA.

Terminar e retomar

TERMINAR ATIVAÇÃO mostra um resumo: referências, hora de início e de fim, QSOs por modo e se a ativação é válida. Os QSOs registados depois de terminar não fazem parte dela.

  • Terminou por engano, ou regressou depois de uma pausa? Durante 24 horas, o resumo, a lista da ativação e o diálogo de início de ATIVAÇÃO POTA / ATIVAÇÃO SOTA oferecem RETOMAR ATIVAÇÃO, que a abre de novo como se nada tivesse acontecido.
  • Um novo dia UTC. No POTA, cada dia UTC é uma ativação separada. Depois da meia-noite UTC o qFT8 oferece INICIAR NOVA no mesmo parque em vez de retomar.
  • Ficou aberta. Se o qFT8 esteve fechado durante algum tempo, ou passou muito tempo sem nenhum QSO, no próximo arranque pergunta se quer CONTINUAR ou terminar.

Exportar

EXPORTAR (no resumo e na lista da ativação) grava ficheiros ADIF com o nome que cada programa espera, prontos para enviar no site dele:

  • POTA: um ficheiro para cada parque e cada dia UTC, com o nome CALLSIGN@PARK-DATE.adi (por exemplo K1ABC@US-1234-20261006.adi). Um two-fer dá um ficheiro por parque. Uma estação que estava ela própria em dois parques é escrita uma vez para cada um dos seus parques, de modo que ambos contam como parque a parque.
  • SOTA: um ficheiro para o cume, com o nome formado da mesma maneira (K1ABC@W1_HA-001-20261006.adi).

Pode guardar os ficheiros ou partilhá-los. O botão da lupa ao lado de ATIVAÇÃO POTA / ATIVAÇÃO SOTA nas Definições lista as suas ativações anteriores, da mais recente para a mais antiga, e marca cada uma como ATIVA, PODE SER RETOMADA, EXPORTADA ou não exportada; toque numa para abri-la e exportá-la de novo. O qFT8 não envia nada por conta própria aos sites dos programas.

Vários parques em sequência

Num dia com vários parques, um depois do outro, cada parque é a sua própria ativação e o seu próprio ficheiro:

  1. No primeiro parque, toque em ATIVAÇÃO POTA nas Definições, escreva a referência dele e toque em INICIAR.
  2. Opere. Cada QSO recebe o parque, e o marcador azul conta-os.
  3. Antes de sair, toque no marcador e em TERMINAR ATIVAÇÃO, depois em EXPORTAR no resumo, e guarde ou partilhe o ficheiro (K1ABC@US-1234-20261006.adi).
  4. No parque seguinte, comece de novo com a nova referência.

Não há nada para voltar a escrever nem para organizar em casa. Se não tiver tempo de exportar em campo, a lista de ativações anteriores (a lupa) exporta cada uma mais tarde.

«Que parque vai no ficheiro?»

O ficheiro de um parque só pode indicar um parque. Quando exporta QSOs que foram feitos de vários parques ao mesmo tempo sem passar por uma ativação (o log inteiro a partir das Definições, ou Exportar (ADIF) numa seleção), o qFT8 pergunta Que parque vai no ficheiro? Escolha o parque a que este ficheiro se destina; exporte de novo para o outro. O log não é alterado. A exportação a partir da própria ativação nunca pergunta: grava um ficheiro por parque.

Para obter um ficheiro para cada parque sem uma ativação, escreva os parques, separados por vírgulas (US-1234, US-5678), na caixa Referência POTA de IMPORTAR/EXPORTAR LOGS ou em Exportar com uma referência POTA numa seleção: o qFT8 grava um ficheiro por parque, com os mesmos QSOs em cada um. Um cume é sempre uma única referência.

Quando a estação que trabalha está em dois parques ao mesmo tempo, o qFT8 guarda os dois: ele lê o segundo parque no comentário do spot, quando quem fez o spot o escreveu lá. O log mostra o primeiro parque e quantos mais existem (US-1234 +1). Se um parque está errado ou em falta, corrija o campo POTA do QSO no editor de QSO; ele aceita vários parques separados por vírgulas. Um parque citado duas vezes para a mesma estação (no spot e de novo no comentário, ou duas vezes numa lista escrita) conta uma só vez, no log e em cada ficheiro exportado.

Chat JS8

No modo JS8, o qFT8 oferece uma interface de chat em texto livre, ao lado da operação tradicional de QSOs em FT8/FT4. O JS8 permite mensagens de teclado a teclado, robustas mesmo com sinais fracos, em várias velocidades configuráveis (intervalos de Slow 30s, Normal 15s, Fast 10s e Turbo 6s).

Tipos de canal e encaminhamento

O painel de chat, à direita, organiza o tráfego recebido e enviado em separadores de canal distintos:

  • Canal principal [GLOBAL]: mostra todas as transmissões JS8 descodificadas em toda a banda passante de áudio, e também todas as suas transmissões. É uma visão completa, em direto, de toda a atividade da banda num só lugar.
  • Canais de grupo de difusão (@CQ, @ALLCALL): usados para chamadas gerais e avisos a todas as estações na escuta. As mensagens enviadas para @CQ ou @ALLCALL são vistas por qualquer pessoa sintonizada na frequência.
  • Canais de grupo personalizados (@GROUPNAME): o qFT8 aceita grupos dirigidos personalizados (por exemplo, @EMERGENCY, @SOTA, @NET). Quando uma mensagem é enviada ou recebida com uma marca @GROUP, ela vai automaticamente para o separador do canal correspondente.
  • Canais diretos de estação (separadores de indicativo): selecionar uma estação na lista de canais ou na tabela de estações abre uma conversa própria com esse indicativo.

Transmissão pelo ar (não é privada): todas as mensagens JS8 são transmitidas em aberto, como sinais digitais comuns de radioamador. Os chats diretos de estação reúnem o histórico da conversa num separador próprio por comodidade, mas não são encriptados nem privados e podem ser recebidos por qualquer estação que esteja a ouvir a frequência.

Escrever e enviar mensagens

  1. Escolha um destino: no painel da direita, toque num separador de canal ([GLOBAL], @CQ, @ALLCALL, um grupo ou o indicativo de uma estação).
  2. Escreva a mensagem: escreva o texto na caixa de entrada, em baixo (aceita texto ASCII padrão de até 100 caracteres).
  3. Envie: toque no botão ENVIAR.

Tocar em mensagens (chat rápido e detalhes)

Tocar em qualquer mensagem do log do chat (no computador: clicar duas vezes nela) abre uma caixa de diálogo de detalhes com a data e a hora UTC completas, a frequência de áudio, a SNR, o grid Maidenhead e o conteúdo da mensagem:

  • Mensagens recebidas (RX): toque em CHAT para abrir de imediato um separador de chat direto com a estação que transmitiu, ou em GROUP CHAT se a mensagem foi endereçada a um grupo.
  • Mensagens transmitidas (TX): toque em REENVIAR para preencher de novo, automaticamente, a caixa de texto e o canal de destino e reenviar a mensagem com facilidade.

Mensagens em vários blocos

Se a sua mensagem for mais longa do que cabe numa única trama de transmissão JS8:

  • O qFT8 divide a mensagem automaticamente em tramas consecutivas, de vários blocos.
  • A aplicação transmite cada bloco automaticamente, em intervalos de tempo seguidos, até que a mensagem inteira tenha sido entregue.
  • Um indicador visual de progresso mostra o estado da transmissão em vários intervalos (por exemplo, TX (1/3)).
  • Se precisar de parar o envio antes de todos os blocos terminarem, tocar no botão Enviar/Parar abre uma pergunta que permite cancelar o restante da transmissão na fila.

Gerir canais (ações do toque longo)

Um toque longo (manter premido; no computador: clicar com o botão direito) em qualquer separador de indicativo de estação ou de canal de grupo, no painel da direita, abre um menu de contexto com opções de gestão:

  • Limpar chat: limpa o histórico de mensagens do separador de canal selecionado.
  • Fechar chat: fecha o separador e remove-o da barra de canais ativos.
  • Exportar chat: exporta todo o histórico de mensagens do canal selecionado para um ficheiro de texto ou para o menu de partilha.

Respostas automáticas a consultas (modo AUTO)

Quando o botão AUTO está ativado, o qFT8 responde automaticamente às consultas dirigidas enviadas por outras estações (como SNR?, HW CPY?, GRID?, INFO?, STATUS? e HEARING?) e também às mensagens de heartbeat (@HB HEARTBEAT).

Por exemplo, se outra estação transmite YOURCALL SNR? ou YOURCALL HW CPY?, o qFT8 coloca na fila e transmite automaticamente a resposta com o seu reporte de sinal (por exemplo, SNR -08), sem intervenção manual. Da mesma forma, ao receber uma transmissão de heartbeat (@HB HEARTBEAT), o qFT8 coloca na fila automaticamente uma confirmação de heartbeat (HEARTBEAT SNR -08), para indicar a receção à estação que transmitiu.

Consultas dirigidas e o botão Pedido

O botão Pedido permite enviar rapidamente consultas dirigidas padrão à estação ou ao grupo selecionado, sem ter de escrever a sintaxe do comando:

  • SNR? / HW CPY?: pede um reporte de sinal à estação distante.
  • GRID?: pede o locator Maidenhead da estação.
  • INFO?: pede a mensagem informativa configurada pela estação.
  • STATUS?: pede o texto de estado de operação da estação.
  • HEARING?: consulta a lista de estações ouvidas por essa estação nos últimos 10 minutos.

Modo WSPR

O WSPR (Weak Signal Propagation Reporter) é um protocolo digital especializado, criado para sondar caminhos de propagação com transmissões de potência muito baixa. Os sinais WSPR usam modulação 4-FSK estreita, com codificação convolucional robusta e descodificação sequencial de Fano, e podem ser descodificados bem abaixo do nível de ruído, até −28 dB de SNR.

Ciclos de 2 minutos e tempos

As transmissões WSPR acontecem em intervalos UTC sincronizados de 2 minutos (110,6 segundos de transmissão, com 162 símbolos de tom). Começam sempre exatamente um segundo depois dos minutos UTC pares (:00, :02, :04, :06...). Como uma transmissão dura quase dois minutos, um rádio pequeno tem de ter permissão para transmitir durante todo esse tempo: veja Limite de transmissão contínua. A deslocação vertical do espetrograma adapta-se automaticamente a um ritmo lento e suave, de acordo com o ciclo de 120 segundos.

Vista de atividade em painel único

Como o WSPR é um protocolo de beacons e de reportes de propagação, e não um modo de conversa bidirecional, o qFT8 mostra um log de atividade simplificado, num único painel de largura total, sem a divisão do log de QSOs:

  • Indicativo: o indicativo da estação.
  • Entidade DXCC: o nome do país / da entidade DXCC, resolvido automaticamente (com largura flexível).
  • Locator: o locator Maidenhead de 4 caracteres (por exemplo, JN45).
  • SNR: a relação sinal-ruído recebida, em dB, medida em relação ao ruído em 2.500 Hz, como fazem os outros recetores de WSPR.
  • Nível de potência: a potência de transmissão informada pela estação, em dBm (por exemplo, 37 dBm).
  • Data e hora UTC: a data e a hora UTC do intervalo de transmissão, no formato yyMMdd HH:mm.

Beacon automático e percentagem de Tx

No cabeçalho, no topo do ecrã de atividade WSPR:

  • Botão BEACON: arma ou desarma as transmissões automáticas de beacon. Quando armado (destacado em verde vivo), o qFT8 agenda automaticamente as transmissões de beacon em intervalos determinísticos, segundo a percentagem de Tx configurada.
  • Seletor de Tx %: configura o ciclo de trabalho determinístico da transmissão, com base no tempo decorrido desde a sua última transmissão (0% [Rx Only], 10%, 20%, 25%, 33%, 50% ou 100% Continuous). Por exemplo, 20% transmite de forma determinística a cada 10 minutos a partir da última transmissão (50% = a cada 4 min, 33% = a cada 6 min, 25% = a cada 8 min, 10% = a cada 20 min, 100% = em todos os ciclos de 2 minutos, continuamente).
  • Botão Send: põe na fila uma transmissão manual imediata, para o início do próximo ciclo de 2 minutos. Depois dela, o agendamento automático e determinístico do beacon continua a partir desse ciclo.

Envio de spots ao WSPRnet e ao PSKReporter

O qFT8 pode enviar automaticamente os spots recebidos à base de dados mundial WSPRnet e ao PSKReporter:

  • Transferir spots do WSPRnet: ativado por predefinição, traz em tempo real os spots do seu indicativo e da sua banda para mostrá-los no mapa mundial.
  • Enviar relatórios para o WSPRnet: quando ativado em Definições → WSPRnet, os spots recebidos são agrupados e enviados ao WSPRnet, com remoção de duplicados em 15 minutos e limitação de ritmo.
  • Abrir WSPRnet: abre diretamente a base de dados do WSPRnet filtrado pelo indicativo da sua estação.

Exportação ADIF independente

Toque no botão EXPORTAR, no canto superior direito do painel de atividade WSPR, para exportar todos os spots registados na sessão atual no formato ADIF padrão (.adi), para estudo da propagação e arquivo.

SSB (voz)

No modo SSB, o qFT8 é o microfone e o altifalante do seu transcetor: o sinal que o rádio recebe transforma-se em voz no seu altifalante ou nos seus auscultadores, e a sua voz vai do seu microfone para o rádio. O rádio continua ligado exatamente como para os modos digitais (o mesmo cabo USB, a mesma placa de som), pelo que não é preciso trocar nenhum cabo para passar de FT8 para voz e voltar.

Escolha SSB com o seletor de modo da barra inferior. A área de mensagens, os botões de sequência e a barra do ciclo desaparecem (a voz não tem janelas de tempo), aparece um botão USB / LSB ao lado do seletor de modo, e o separador Estações torna-se o painel SSB:

Estes são os componentes do ecrã de SSB, em detalhe:

  1. RX / TX / RX/TX: escolhe o que a roda de sintonia (item 12) move. Com RX/TX recebe e transmite na mesma frequência. Com RX ou TX só essa se move, de modo que pode escutar numa frequência e transmitir noutra (split).
  2. AUTO RIT: mantém centrada uma estação que está ligeiramente fora de frequência, para que a voz dela soe natural sem tocar na roda.
  3. A engrenagem: abre Definições > SSB (veja abaixo). VOLTAR regressa a este painel.
  4. QSO: Abre o registo manual com o modo, a banda lateral e a frequência já preenchidos, para registar o contacto que acabou de fazer (veja O registo manual). Um QSO por toque.
  5. Memórias de voz: As suas mensagens gravadas (uma chamada CQ, o seu indicativo...). Até gravar uma, esta área mostra o link Configure as memórias de voz nas Definições.
  6. IN: o nível do seu microfone e o controlo deslizante do ganho dele. A linha marcada VOX é o nível que a sua voz precisa de ultrapassar para acionar o rádio quando o VOX está ligado (item 10): arraste-a.
  7. OUT: O nível do áudio recebido e o controlo deslizante de volume do seu altifalante. As teclas de volume do telemóvel fazem o mesmo.
  8. FILTER e NR: O filtro de receção (desligado, 2,7, 2,4 ou 1,8 kHz) e a redução de ruído (desligada, 1, 2 ou 3). Cada toque passa para o valor seguinte.
  9. PTT: premir para falar. Mostra «mantenha premido para falar» ou «toque para falar», conforme a definição Modo PTT, e «NO AR» enquanto está a transmitir. No computador, a barra de espaço faz o mesmo enquanto o painel tem o foco.
  10. VOX: Quando ligado, o rádio é acionado pela sua voz em vez do botão PTT.
  11. USB / LSB: a banda lateral. É escolhida por si quando muda de banda (LSB abaixo de 10 MHz, USB acima); um toque troca-a, e a frequência que lê continua a mesma.
  12. A roda de sintonia: em SSB a escala de frequência do espetrograma é uma roda. Deslize o dedo ao longo dela para sintonizar o rádio; um deslize mais rápido dá passos maiores. Um toque não faz nada, pelo que a frequência nunca salta por acidente. No computador, a roda do rato também sintoniza (mantenha Shift premido para passos de 1 Hz). A sintonia precisa de uma ligação CAT ao rádio.
  13. Frequência e banda: A frequência que diria no ar (a portadora), e a banda. A linha laranja e a etiqueta RX/TX abaixo dela marcam a parte do espetrograma em que está a escutar e a transmitir.

Falar

  1. Arme a transmissão com o botão TX da barra inferior. Como em todos os outros modos, nada é transmitido enquanto disser TX OFF: a linha vermelha Prima TX ON para transmitir lembra-o disso.
  2. Mantenha PTT premido e fale, depois solte. Ou ligue o VOX e simplesmente fale.
  3. Para enviar uma memória de voz, toque nela. Com TX ON é transmitida, e também a ouve no seu altifalante. Com TX OFF só é reproduzida para si, o que é uma boa maneira de verificar uma gravação. Um toque longo (um clique com o botão direito no computador) reprodu-la sempre só para si.

A sua própria voz em direto nunca é reproduzida no seu altifalante. Se a frequência em que vai transmitir está fora da banda de radioamador, o qFT8 não aciona o rádio e avisa.

Limite de PTT: Com Tocar para alternar e com o VOX, uma transmissão para sozinha depois do Limite de PTT (100 segundos, a menos que o altere), e o botão PTT conta os segundos que faltam. Depois do limite, o VOX fica em pausa pelo mesmo tempo, ou até tocar em PTT. Isto protege o rádio de um microfone que não para de captar ruído. O limite de transmissão contínua do próprio rádio também se aplica: vale o mais curto dos dois.

Memórias de voz

Vá a Definições > SSB > Memórias de voz (ou toque em Configure as memórias de voz nas Definições no painel) e prima GRAVAR UMA NOVA MEMÓRIA DE VOZ. Pode guardar até 6 memórias de 30 segundos cada. Para cada uma pode dar um nome, gravá-la de novo, ajustar o volume ou premir NORMALIZAR, e cortar o silêncio do início e do fim arrastando as duas pegas sobre o desenho do som; REPRODUZIR toca a parte que manteve, e nada muda até guardar. As memórias fazem parte da exportação de definições, gravações incluídas.

Definições > SSB

  • Mecanismo de PTT: O botão PTT, ou o VOX.
  • Modo PTT: Manter premido para falar ou Tocar para alternar.
  • Atraso do PTT: o tempo entre comutar o rádio para transmissão e enviar a sua voz. Nada do que diz se perde: a sua primeira sílaba espera pelo rádio.
  • Limite de PTT: Veja acima (de 10 a 600 segundos).
  • Banda lateral: Automática pela banda, sempre USB ou sempre LSB.
  • Filtro e redução de ruído ao entrar em SSB.
  • Reproduzir o áudio recebido no altifalante e Silenciar o altifalante ao transmitir.
  • Memórias de voz e REPOR PREDEFINIÇÕES.

Do que o SSB precisa

  • Um microfone e um altifalante que não sejam a placa de som do rádio. Um telemóvel tem os seus; um headset também serve. Veja Altifalantes e microfone. Se o rádio e o seu microfone ou altifalante são o mesmo dispositivo, uma linha vermelha avisa e nada é enviado nem reproduzido.
  • Um rádio. Sem ele, o painel é substituído por um cartão que diz Ligue um rádio para usar SSB; o painel volta sozinho quando o rádio é ligado. Um rádio sem CAT que é acionado pelo seu próprio VOX também funciona, mas nesse caso a aplicação não consegue sintonizá-lo.
  • Um QMX ou QMX+ precisa do firmware 1_02_000 ou mais recente para transmitir voz a partir da aplicação. Com um firmware mais antigo a barra inferior diz Sem SSB e o modo é só de receção.
  • Na primeira vez que visita uma banda em SSB, o qFT8 sintoniza a frequência de voz habitual dessa banda na sua parte do mundo; depois disso, volta à última frequência que usou ali. A banda de 30 m não tem segmento de voz e não é oferecida.

Os QSOs são registados como SSB com a sua banda lateral, e são enviados ao QRZ e ao LoTW como qualquer outro QSO.

CW (código Morse)

No modo CW, o qFT8 lê todos os sinais de Morse da banda passante e escreve o texto deles sobre o espetrograma, e envia Morse com palhetas no ecrã, com os seus próprios manipuladores, com mensagens prontas ou com texto escrito. Com TX OFF tudo funciona como treino: ouve a sua manipulação no altifalante e nada vai ao ar.

Escolha CW com o seletor de modo da barra inferior:

Estes são os componentes do ecrã de CW, em detalhe:

  1. AUTO: Deixa o qFT8 fazer sozinho QSOs completos em CW (veja AUTO em CW).
  2. RX / TX / RX/TX: Escolhe qual barra um toque na cascata ou a roda de sintonia move: a barra de receção, a de transmissão ou as duas juntas.
  3. A engrenagem abre Definições > CW, e QSO abre o registo manual com CW, a frequência e o alvo já preenchidos.
  4. Alvo: o indicativo da estação que está a trabalhar. Preenche a parte [TARGET] das suas mensagens. Toque nele para escrever um, ou toque num indicativo na linha do descodificador (item 10) para o ir buscar lá.
  5. Memórias: mensagens prontas. Um toque envia uma. O seu próprio indicativo aparece em azul e o reporte em amarelo. Uma memória à qual ainda falta algo (um alvo, o seu nome...) fica esbatida; toque nela para ver o que falta.
  6. WPM e FARNSWORTH: A velocidade de envio em palavras por minuto, e a velocidade Farnsworth opcional (as letras mantêm a velocidade e os espaços entre elas ficam mais longos).
  7. FILTER e NR: A largura do filtro de receção em torno da barra de receção, e a redução de ruído.
  8. As palhetas: A esquerda envia pontos e a direita envia traços. Prima as duas para os modos iâmbicos.
  9. A linha vermelha: Prima TX ON para transmitir. Enquanto ela aparece, a sua manipulação é treino.
  10. A linha do descodificador: fica onde está o seletor de mensagem em FT8. Mostra em verde o texto da estação que está dentro do seu filtro e em vermelho o que envia, o mais recente à direita.
  11. Texto descodificado na cascata: Cada sinal tem o seu texto escrito ao longo do próprio traço, de modo que pode ler a banda inteira de uma vez. A etiqueta abaixo da barra de receção mostra o indicativo e a velocidade da estação em que está.
  12. A roda de sintonia: A escala de frequência. Deslize o dedo ao longo dela para mover a barra selecionada (e o rádio, quando a barra chega à borda). Um toque ou um arrasto na cascata move a barra diretamente.
  13. Ir para a frequência: Toque na faixa com a linha branca de intensidade de sinal para escrever uma frequência em kHz.

Enviar

Há quatro maneiras de enviar, e todas usam a velocidade definida com WPM:

  • As palhetas no ecrã, com um ou dois dedos.
  • Os seus próprios manipuladores: teclas do teclado, os botões do rato (no computador, o botão esquerdo é a palheta esquerda e o botão direito a palheta direita), ou um adaptador de manipulador ligado por USB ou Bluetooth que se comporte como um teclado. Veja Palhetas e manipulador.
  • Uma memória: toque nela. Uma segunda memória tocada entretanto espera a sua vez. Aparece uma faixa com PARAR enquanto um texto está a ser enviado, e tocar numa palheta também o interrompe.
  • Teclado (no fim das memórias): escreva uma mensagem e prima ENVIAR. Uma linha abaixo da caixa mostra exatamente o que será enviado. No Android, Voz faz o mesmo a partir da fala: diga a mensagem e ela é enviada em Morse.

No ar, o CW é sempre um tom limpo com flancos suaves, seja qual for o tom lateral que escolha ouvir. Como rede de segurança, um manipulador mantido premido durante 10 segundos é libertado, e uma transmissão é interrompida ao fim de 3 minutos.

Treino com TX OFF

Enquanto a barra inferior diz TX OFF, as palhetas, os seus manipuladores, as memórias e a caixa Teclado funcionam todos, mas só no seu altifalante. O que manipula é descodificado e mostrado em vermelho na linha do descodificador, de modo que pode ver se a sua manipulação é legível. Nada chega ao rádio. Para isto não é preciso rádio nenhum.

Palhetas e manipulador

Em Definições > CW, a secção Manipulador define como as palhetas se comportam:

  • Modo do manipulador: Manipulador vertical, Iâmbico A, Iâmbico B, as versões de um dedo de ambos, Ultimatic, Bug (semiautomático) e Cootie (sideswiper).
  • Velocidade, Farnsworth, Espaço entre palavras e Temporização rigorosa (espaços padrão entre letras e palavras).
  • Inverter palhetas: troca pontos e traços.
  • Atraso de break-in: quanto tempo o rádio permanece em transmissão depois do seu último ponto ou traço.
  • Igualar velocidade: envia à velocidade da estação que está a copiar.

A secção Entrada das palhetas define o que conta como palheta:

  • Palhetas: o interruptor geral. Desligado, não há palhetas no ecrã, e nenhuma tecla, botão do rato ou adaptador pode manipular o emissor.
  • Palhetas no ecrã, Botões do rato, Teclas do teclado e Adaptadores externos (USB / Bluetooth): cada fonte pode ser desligada separadamente.
  • Mapeamento de teclas: Predefinido usa uma lista pronta de teclas (entre elas [ e ], as teclas Ctrl esquerda e direita, F1 e F2). Com Personalizado monta as suas próprias listas para a palheta esquerda e para a direita: prima ADICIONAR TECLA e depois a tecla que quer. Uma tecla que já está na outra palheta é recusada.

Enquanto uma caixa de texto está aberta, só as teclas Ctrl e F1 / F2 funcionam como palhetas, de modo que escrever um indicativo nunca envia Morse.

Manipular com um adaptador, o teclado ou o rato

Não é preciso tocar no ecrã para enviar Morse. Quatro coisas podem servir de palhetas, e todas podem ser usadas ao mesmo tempo:

  • As palhetas no ecrã, com os dedos.
  • Um manipulador a sério num adaptador USB: uma caixinha ou um cabo com uma tomada para o manipulador de um lado e uma ficha USB do outro. Para o telemóvel ou o computador é um teclado (cada contacto do manipulador prime uma tecla) ou um rato (cada contacto prime um botão do rato). Os adaptadores Bluetooth funcionam da mesma maneira.
  • Um teclado: uma tecla para a palheta esquerda e outra para a direita.
  • Um rato: os seus botões esquerdo e direito.

Todos seguem o Modo do manipulador e a velocidade que escolheu, e todos funcionam com TX OFF como treino (veja Treino com TX OFF).

Ligar um adaptador

  1. Ligue o seu manipulador ao adaptador, e o adaptador ao telemóvel, ao tablet ou ao computador. Não é preciso instalar nada e o qFT8 não pede nenhuma permissão: o adaptador é um teclado ou um rato vulgar. Num telemóvel cuja única porta USB está ocupada pelo transcetor, use um hub USB ou um adaptador Bluetooth.
  2. Abra o ecrã de CW e manipule. Um adaptador que se comporta como um teclado funciona de imediato se enviar teclas da lista predefinida abaixo (as mais comuns são as teclas Ctrl esquerda e direita, e [ e ]). Foi testado com o adaptador VBand original.
  3. Se nada soar, o adaptador envia outras teclas. Vá a Definições > CW > Entrada das palhetas, prima ADICIONAR TECLA em Palheta esquerda (ponto) e feche o contacto dos pontos do seu manipulador; depois faça o mesmo em Palheta direita (traço) com o contacto dos traços.
  4. Um adaptador que se comporta como um rato precisa das palhetas no ecrã: deixe o ponteiro do rato sobre a palheta esquerda e manipule. O mesmo vale para um rato vulgar.

Um manipulador vertical, um de palhetas, um bug

O Modo do manipulador (Definições > CW > Manipulador) decide o que os dois lados fazem, seja qual for o meio que usa para manipular:

  • Manipulador vertical: um só manipulador, e cada ponto e cada traço são feitos à mão. Só o lado da palheta esquerda manipula: ligue um manipulador vertical ao contacto dos pontos do adaptador, ou ponha a tecla dele na lista Palheta esquerda (ponto). No ecrã as duas palhetas tornam-se um só manipulador.
  • Iâmbico A e Iâmbico B: para um manipulador de duas palhetas. O lado esquerdo faz pontos, o direito traços, e os dois juntos alternam-nos. Iâmbico A, um dedo e Iâmbico B, um dedo foram pensados para o ecrã, onde uma zona ao meio vale como as duas palhetas (a largura dela é Zona central (modos de um dedo)).
  • Ultimatic: como um manipulador de palhetas, mas com os dois lados premidos ganha o que foi premido por último.
  • Bug (semiautomático): o lado dos pontos faz os pontos sozinho; o lado dos traços é um manipulador manual, e soa enquanto o mantiver premido.
  • Cootie (sideswiper): os dois lados são o mesmo manipulador manual.

Pôr tudo a seu gosto

Está tudo em Definições > CW, na secção Entrada das palhetas:

  • Palhetas: o interruptor geral de tudo o que se segue.
  • Palhetas no ecrã e Altura das palhetas: oculte as palhetas para deixar mais espaço à cascata quando só usa um manipulador a sério, ou torne-as mais altas para os seus dedos. O rato precisa que elas estejam visíveis.
  • Botões do rato: desligue se um clique nas palhetas não deve fazer nada.
  • Teclas do teclado e Adaptadores externos (USB / Bluetooth): quem pode manipular. Veja mais abaixo as diferenças entre o Android e o computador.
  • Mapeamento de teclas: Predefinido é a tabela acima. Por baixo estão as duas listas, Palheta esquerda (ponto) e Palheta direita (traço). ADICIONAR TECLA espera que prima uma tecla (ou que feche um contacto do seu manipulador) e adiciona-a; o caixote do lixo ao lado de uma tecla remove-a. A primeira alteração passa o mapeamento para Personalizado, que começa como uma cópia das listas predefinidas. Voltar a Predefinido não apaga as suas próprias listas. Pode usar letras, algarismos, de F1 a F12, as setas, Ctrl, Shift, Alt, o teclado numérico, Espaço, Enter, Tab e as teclas de pontuação comuns. Uma tecla só pode estar numa palheta.

Há mais duas opções na secção Manipulador: Inverter palhetas troca pontos e traços para todas as fontes de uma vez (para um manipulador ligado ao contrário, ou para um operador canhoto), e o Modo do manipulador está descrito mais acima. REPOR PREDEFINIÇÕES, no fim da página, repõe todas as definições de CW nos valores iniciais, incluindo as listas de teclas.

O Android e o computador

  • No Android há dois interruptores: Teclas do teclado é o teclado do próprio dispositivo, e Adaptadores externos (USB / Bluetooth) é qualquer teclado ou adaptador que ligue ou emparelhe. Antes do Android 10, todo o teclado físico conta como externo. Um rato USB ou Bluetooth funciona sobre as palhetas como no computador.
  • No computador um adaptador é mais um teclado, por isso há um só interruptor, Teclas do teclado, para os dois. As palhetas no ecrã premem-se com o rato. As teclas só atuam enquanto a janela do qFT8 com o ecrã de CW é a janela ativa e nenhuma caixa de diálogo está aberta.

Se algo não funcionar

  • Os pontos e os traços estão trocados: assinale Inverter palhetas. Com o rato, verifique se o ponteiro está sobre a palheta esquerda, e não sobre a direita.
  • Nada acontece quando manipula: o ecrã de CW tem de estar à vista, Palhetas e o interruptor da sua fonte têm de estar ligados, e AUTO tem de estar desligado (o ecrã diz Desative AUTO para transmitir manualmente). No computador, clique primeiro na janela do qFT8. Depois verifique se a sua tecla está nas listas: prima ADICIONAR TECLA e manipule. Se a caixa de diálogo não reagir, o adaptador envia uma tecla que não pode ser usada, ou não está ligado.
  • Ouve o Morse mas o rádio não transmite: a linha vermelha diz Prima TX ON para transmitir. Isso é treino.
  • Um manipulador vertical não faz nada no modo Manipulador vertical: está no lado da palheta direita. Passe-o para o da esquerda (veja acima).
  • Ao manipular, escrevem-se letras numa caixa em vez de serem enviadas: enquanto uma caixa de texto está aberta só as teclas Ctrl e F1 / F2 são palhetas, para que escrever um indicativo nunca envie Morse. Feche a caixa, ou dê ao seu adaptador uma dessas teclas.
  • Ao manipular, escreve-se noutro programa: no computador as teclas vão para a janela ativa. Clique no qFT8.
  • O tom para enquanto mantém o manipulador premido: um manipulador mantido premido durante 10 segundos é libertado, com o aviso Manipulador premido demasiado tempo: libertado.

Memórias, macros e prossinais

Edite as suas mensagens em Definições > CW > Memórias (ADICIONAR MEMÓRIA, ou toque numa para alterá-la). Dois tipos de palavras especiais podem ser usados numa mensagem:

  • As macros, entre colchetes, são substituídas quando a mensagem é enviada: [MYCALL] o seu indicativo, [TARGET] o indicativo da caixa Alvo, [RST] o reporte a enviar, [NAME] o seu nome, [QTH] a sua localização, [EXCH] a sua troca do concurso e [MYPOTA] o parque ou o cume da sua ativação aberta. O editor tem um botão para cada uma delas e mostra a mensagem exatamente como será enviada.
  • Os prossinais, entre colchetes angulares, são enviados como um único carácter, sem espaços: <BK>, <SK>, <KN>, <AR>.

O seu reporte, o seu nome, a sua localização e a sua troca são escritos uma única vez, na mesma página das Definições. Uma mensagem pronta que precisa de um deles fica esbatida até o preencher, e tocar nela leva-o ao sítio onde o fazer. Enquanto uma ativação POTA ou SOTA está aberta, é oferecida uma mensagem CQ POTA como primeira memória.

Receber

A descodificação é automática e acompanha a velocidade própria de cada estação. A estação que está dentro do seu filtro é a que é escrita na linha do descodificador da barra inferior; leve a barra de receção para outro sinal para acompanhar esse outro (o que já tinha sido copiado nessa frequência aparece de imediato). Quando há duas estações dentro do filtro, a barra inferior avisa. O sinal recebido é tocado no seu altifalante no Tom do monitor que escolher, o mesmo tom do seu próprio tom lateral, de modo que uma estação que soa na mesma nota do seu tom lateral está exatamente na sua frequência.

Definições > CW tem também Tons (como soa o seu tom lateral: tom, volume, flancos suaves ou duras, um tom ou cliques de sounder), Descodificação e apresentação (Descodificação automática, Multidescodificador para o texto de cada sinal na cascata, o espetrograma horizontal, o filtro ao entrar no modo), Monitor (altifalante) e Prossinais e sinais.

AUTO em CW

O botão AUTO, no canto superior esquerdo do painel, deixa o qFT8 fazer QSOs completos em CW. Está desligado sempre que entra no modo. Toque nele para o ligar (fica verde) e de novo para o desligar. Só envia enquanto o TX está em ON: o AUTO nunca arma a transmissão sozinho.

Enquanto está ligado, e o TX está em ON, o qFT8:

  • chama CQ quando a frequência está em silêncio, ou responde a um CQ que ouve;
  • troca reportes, nome e localização, despede-se e regista o QSO;
  • pede de novo um indicativo ou um reporte que não conseguiu copiar, e atende aos pedidos de repetir ou de ir mais devagar;
  • nunca envia mais rápido que o seu WPM, e reduz para a velocidade da outra estação;
  • acompanha uma estação que deriva, não chama uma estação já trabalhada nesse dia e não começa por cima do QSO de outros;
  • nunca regista um QSO que não conseguiu completar.

Enquanto o AUTO está ligado as palhetas ficam desativadas e uma linha diz Desative AUTO para transmitir manualmente. PARAR também desliga o AUTO. Se nunca o quiser, desligue Mostrar modo automático em Definições > CW e o botão fica oculto.

RTTY

O RTTY (radioteletipo) envia texto como dois tons que se alternam. No qFT8 partilha o ecrã do CW, sem as palhetas: todos os sinais de RTTY da banda passante são descodificados, cada um à sua própria velocidade e desvio, e escritos ao longo do seu traço na cascata.

Estes são os componentes do ecrã de RTTY, em detalhe:

  1. Alvo e Troca: o indicativo da estação que está a trabalhar e a troca do concurso. Eles preenchem [TARGET] e [EXCH] nas suas mensagens.
  2. BAUD: A velocidade: 45,45 (a habitual), 50 ou 75. Cada toque passa para a seguinte.
  3. SHIFT: A distância entre os dois tons: 170 Hz (a habitual), 200, 425 ou 850 Hz.
  4. REV: Troca os dois tons, para uma estação que os envia ao contrário.
  5. FILTER e NR: O filtro de receção e a redução de ruído.
  6. Memórias: Mensagens prontas com as mesmas macros do CW. Um toque envia uma. Uma mensagem com um campo vazio fica esbatida. Teclado (e Voz no Android) ficam no fim da lista.
  7. A linha do descodificador: O texto da estação que está sob a barra de receção, em verde; o que envia, em vermelho.
  8. A barra de receção e a sua etiqueta: A etiqueta mostra o indicativo, a velocidade e o desvio da estação que está sob a barra. Um toque perto de um sinal coloca a barra no centro dele.
  9. igualar: quando a estação que está sob a barra usa uma velocidade, um desvio ou uma ordem de tons diferentes dos seus, uma linha laranja avisa. Toque nela e o qFT8 adota os valores dessa estação, para que lhe possa responder.
  10. Outros sinais: O texto deles é escrito ao longo dos seus próprios traços. Uma etiqueta laranja como 50 Bd ou 425 Hz marca um sinal que difere das suas definições.
  11. Frequência: em RTTY o cabeçalho mostra a frequência de marca, que é a frequência que os operadores citam e a que é escrita no log.

Enviar

Arme o TX e depois toque numa memória, ou abra Teclado, escreva e toque em ENVIAR. Uma faixa com PARAR aparece enquanto o texto sai. Com TX OFF, as mesmas ações são uma pré-visualização: a mensagem é tocada no seu altifalante e mostrada em vermelho, e nada vai ao ar. Os caracteres que o código RTTY não tem são omitidos e listados.

O RTTY é uma transmissão contínua em potência máxima, pelo que se aplica o limite de transmissão contínua do rádio: uma mensagem mais longa do que o limite não é iniciada, e uma transmissão para quando o limite é atingido.

Definições > RTTY

  • Modem: velocidade, desvio, Inverso, a Tabela de algarismos (Internacional (ITA2) ou EUA: elas diferem em cinco sinais, e as duas estações precisam de usar a mesma) e Voltar a letras após um espaço na receção e no envio (depois de um espaço o texto volta a letras, de modo que uma mudança para algarismos perdida estraga no máximo uma palavra). As estações que transmitem grupos de números, como as meteorológicas, não repetem a mudança para algarismos depois de cada espaço: os grupos de números delas saem como letras enquanto Voltar a letras após um espaço na receção está ligado; portanto, desligue-o para lê-las.
  • Transmissão: uma nova linha no início e no fim de cada transmissão, caracteres de preenchimento enquanto não há nada para enviar, e uma nova linha automática depois de um certo número de caracteres.
  • Descodificação e apresentação, Monitor (altifalante), Memórias com os seus valores (reporte, nome, localização, troca) e REPOR PREDEFINIÇÕES.

Os QSOs feitos com o botão QSO são registados como RTTY. Não há AUTO em RTTY.

Definições > JTTY

O JTTY (a linha JTTY (experimental) do seletor de modo) usa este mesmo painel com o modem JTTY. As definições dele têm uma página própria, ao lado de RTTY na lista de definições; o botão de roda dentada do painel abre-a enquanto o painel está em JTTY. Tem só o que o JTTY usa: Descodificação e apresentação, Monitor (altifalante), Memórias com os seus valores e REPOR PREDEFINIÇÕES; as definições de Modem e Transmissão do RTTY não se lhe aplicam. Da primeira vez que o JTTY é usado, fica com o que tinha alterado em Definições > RTTY (por exemplo as suas memórias, nome e localização); o que não tinha alterado começa com os valores próprios do JTTY, como memórias curtas que cabem cada uma numa mensagem JTTY. Depois disso, alterar um não altera o outro.

SSTV (imagens)

O SSTV (televisão de varrimento lento) envia uma imagem fixa em forma de som, linha a linha, em um a quatro minutos. O qFT8 recebe imagens sozinho enquanto está no modo, e envia imagens da sua galeria com o seu indicativo escrito sobre elas.

Escolha SSTV com o seletor de modo da barra inferior. A metade esquerda do painel é para enviar e a metade direita para receber:

Estes são os componentes do ecrã de SSTV, em detalhe:

  1. ENVIAR: o modo em que a imagem será enviada, com o tamanho dela. O modo é escolhido com o item 12.
  2. CARREGAR: Oferece «Escolher uma imagem» (da galeria ou de um ficheiro), «Tirar uma fotografia» (num telemóvel ou tablet com câmara) e «Imagens prontas»: cerca de vinte desenhos feitos pelo qFT8 no tamanho do modo, com o seu indicativo neles (cartões CQ, o logótipo do qFT8, paisagens, ilusões de ótica, um cartão QSL, 73...). Também pode partilhar uma imagem com o qFT8 a partir de outra aplicação; se outro modo estiver em uso, o qFT8 pergunta antes de mudar para SSTV.
  3. A imagem a enviar, mostrada exatamente como será enviada. Toque nela para ajustá-la ao formato do modo: mostrá-la inteira, recortá-la (arraste para mover, use dois dedos para ampliar), rodá-la e ajustar o brilho e o contraste.
  4. Estilo do texto: As setas percorrem as maneiras como o seu indicativo é escrito sobre a imagem (uma faixa em baixo, um canto, um contorno grande... ou sem indicativo). O lápis acrescenta um texto livre.
  5. REMOVER retira a imagem carregada. ENVIAR mostra quantos segundos a transmissão vai durar, e passa a PARAR, com os segundos que faltam, enquanto a imagem está no ar.
  6. A linha vermelha: Prima TX ON para enviar imagens. Por baixo dele, o espaço que sobra é preenchido com imagens pequenas: as últimas imagens que carregou, depois as prontas. Um toque carrega uma como a imagem a enviar (nunca é enviada até premir ENVIAR). Se o formato de uma imagem não for o do modo, o passo de ajuste abre primeiro.
  7. Estado da receção: À ESCUTA, ou A RECEBER com o modo, quanto a estação está fora de frequência e a linha que está a ser desenhada.
  8. A imagem recebida, desenhada à medida que chega. Abaixo dela: a hora, o modo e o progresso e, quando a imagem está completa, o campo do indicativo.
  9. GUARDAR grava a imagem na pasta de imagens do dispositivo (se for tocado enquanto a imagem ainda está a chegar, grava-a quando ela terminar). EDITAR melhora uma imagem recebida (contraste, brilho, cor, tonalidade, nitidez, redução de ruído); a imagem tal como foi recebida é sempre mantida, pelo que qualquer alteração pode ser desfeita. RESPONDER carrega a imagem recebida como a imagem a enviar, com o indicativo da outra estação ao lado do seu.
  10. Imagens mantidas: as últimas imagens recebidas. Toque numa para mostrá-la de novo.
  11. A engrenagem abre Definições > SSTV, e QSO abre o registo manual com o modo SSTV.
  12. O seletor de modo SSTV: modos Martin, Scottie, Robot, PD, Wraase e Pasokon. Ao lado, a área de mensagens diz o que está a acontecer («à escuta», «a receber», «a enviar» com os segundos que faltam).
  13. A faixa de SSTV: As imagens são enviadas e recebidas entre 1100 e 2300 Hz. Cada imagem ouvida ou enviada ganha uma caixa na cascata com o seu modo.

Receber imagens

Não há nada para ajustar. O qFT8 reconhece o modo de cada transmissão pelo sinal de início, e também quando sintoniza depois de a imagem já ter começado (as linhas já perdidas ficam vazias). Uma imagem enviada ligeiramente fora de frequência, ou por uma estação cuja temporização está um pouco errada, é endireitada automaticamente. Se duas estações enviam ao mesmo tempo em frequências claramente diferentes, as duas imagens são recebidas e mantidas; toque numa caixa na cascata para escolher a que é mostrada.

A aplicação mantém sozinha as últimas imagens. Com Guardar automaticamente no dispositivo cada imagem recebida também são gravadas na pasta de imagens; caso contrário, guarda as que quiser.

De quem é a imagem? O campo do indicativo

Muitas estações identificam-se em torno da sua imagem, em código Morse antes ou depois dela, ou com uma curta rajada de dados depois dela. O qFT8 lê as duas coisas, e escreve o indicativo no campo ao lado da hora e do modo, por baixo da imagem. Quando nada foi ouvido, o campo diz Indicativo desconhecido. Toque no campo para escrever o indicativo (muitas vezes está escrito na imagem) ou para o corrigir; o que escrever substitui o que foi ouvido.

As imagens guardadas recebem um nome com a data e a hora (UTC), a banda, a frequência em kHz, o modo e o indicativo, por exemplo 2026-10-05_1431_20m_14230_M1_F4ABC.png, ou ..._UNKNOWN.png quando não há indicativo. Se o indicativo chega ou é escrito depois de a imagem ter sido guardada, o ficheiro guardado muda de nome; não é feita uma segunda cópia.

Enviar uma imagem

  1. Escolha o modo com o seletor da barra inferior. Se responde a uma estação, use o modo que ela usou. Robot 36, Martin 1 e Scottie 1 são os mais comuns.
  2. Toque numa das imagens pequenas por baixo de ENVIAR, ou prima CARREGAR, escolha a imagem e ajuste-a se for pedido.
  3. Escolha com as setas como o seu indicativo aparece.
  4. Arme o TX e prima ENVIAR.

Desligar o TX, premir PARAR, ou mudar de banda ou de modo interrompe a imagem de imediato. Se uma imagem está a chegar quando prime ENVIAR, o qFT8 pergunta antes de parar de receber.

Modos longos e rádios pequenos: uma imagem é uma transmissão contínua em potência máxima: cerca de 40 segundos em Robot 36, dois minutos em Martin 1, e mais de quatro minutos nos modos mais lentos. Um modo mais longo do que o limite de transmissão contínua do seu rádio aparece a cinzento na lista, e ao escolhê-lo é explicado o motivo. Com um QMX na sua predefinição de 60 segundos, os modos curtos funcionam tal como estão.

Definições > SSTV

  • Enviar o seu indicativo em CW: desligado, antes da imagem (a predefinição), depois dela, ou ambos. Só o indicativo, a 20 WPM; os segundos dele contam no tempo de transmissão.
  • Enviar FSK ID depois de cada imagem: uma curta rajada de dados que permite ao programa da outra estação ler o seu indicativo.
  • Estilo do texto, Contraste automático e Aumentar a nitidez automaticamente.
  • Guardar automaticamente no dispositivo cada imagem recebida e quantas imagens recebidas são mantidas na aplicação.

Um QMX ou QMX+ precisa do firmware 1_02_000 ou mais recente para enviar imagens; com um firmware mais antigo o SSTV é só de receção.

Documentação das funcionalidades

Definições e ferramentas que não estão ligadas a um único modo: duas definições por rádio de CONFIGURAÇÃO DO DISPOSITIVO, a página web para operar o qFT8 a partir de outro dispositivo, o bridge que permite deixar o rádio noutra divisão e a organização do ecrã.

Desvio de sintonia do espetrograma

Em Definições > CONFIGURAÇÃO DO DISPOSITIVO, em Sintonia (este rádio), Desvio de sintonia do espetrograma desloca o que o espetrograma mostra até 300 Hz para baixo ou para cima. Por omissão vale −100 Hz na família QMX, −90 Hz no IC-7300 e −50 Hz em qualquer outro rádio; o valor que definir (incluindo 0) é mantido, separadamente para cada rádio.

A maioria dos rádios corta a parte mais baixa do áudio, de modo que os sinais nas primeiras centenas de hertz do espetrograma ficam fracos ou desaparecem. Com um desvio de −100 Hz, por exemplo, o qFT8 sintoniza o rádio 100 Hz mais abaixo e desloca o áudio na mesma medida, de modo que esses sinais passam para a parte que o rádio ouve bem.

Nada mais muda: a frequência mostrada, os desvios das estações, os spots, a sua frequência de transmissão e o log ficam exatamente como antes. Só o mostrador do próprio rádio indica um valor diferente, na medida do desvio. O desvio funciona em todos os modos e precisa de uma ligação CAT; com VOX ou com o altifalante não faz nada.

Limite de transmissão contínua

Esta é uma definição de segurança para o emissor. Os rádios pequenos são feitos para transmissões curtas com pausas: uma transmissão de FT8 dura menos de 13 segundos e é seguida de pelo menos 15 segundos de descanso. Alguns modos mantêm o rádio a transmitir em potência máxima durante muito mais tempo sem interrupção, e isso pode sobreaquecer o amplificador final de um rádio pequeno. O limite de transmissão contínua é o tempo máximo que o qFT8 mantém o seu rádio em transmissão de uma só vez.

Está em Definições > CONFIGURAÇÃO DO DISPOSITIVO, em Sintonia (este rádio). As opções são 20, 40, 60, 90, 120 e 150 segundos, e Sem limite. Por baixo de cada opção, o qFT8 lista o que essa opção acrescenta, para que veja o que ganha ao aumentá-lo. A definição é guardada separadamente para cada rádio.

A predefinição de cada rádio

  • 60 segundos: QRPLabs QMX, QMX+ e QDX, e o (tr)uSDX.
  • 120 segundos: Xiegu X6100 e X6200.
  • Sem limite: todos os outros rádios, e um rádio usado por VOX ou pelo altifalante (o qFT8 não tem como saber que rádio é).

Estas predefinições são cautelosas. Conhece o seu rádio, a regulação de potência e o arrefecimento dele: altere o limite se o permitirem. O qFT8 nunca aumenta o limite sozinho.

O que o limite faz

  • Uma transmissão de duração conhecida que é mais longa do que o limite não é iniciada. É por isso que o WSPR e os modos longos de SSTV pedem que o aumente: uma transmissão de WSPR dura 111 segundos, e muitas imagens de SSTV demoram dois minutos ou mais. Quando escolhe um desses modos, ou prime TX ON nele, uma mensagem indica de quantos segundos precisa e qual é o limite do seu rádio, com um botão Abrir a definição. A transmissão não é armada até que o limite permita o modo.
  • Uma transmissão sem duração fixa para quando o limite é atingido, e o rádio volta à receção: TUNE, SSB (o botão PTT, o VOX e as memórias de voz) e RTTY. Um aviso informa que o limite foi atingido.
  • O CW não é limitado: o manipulador só fica premido parte do tempo.

QMX e WSPR: com um QMX, QMX+ ou QDX, o WSPR precisa de que o limite seja aumentado de 60 para 120 segundos. Pela segurança do rádio, o qFT8 pede que o faça uma vez, à mão. Considere reduzir a potência do rádio para o WSPR: é, por conceção, um modo de baixa potência.

Servidor web de controlo remoto

O qFT8 inclui um servidor HTTP integrado que permite acompanhar e controlar a aplicação a partir de qualquer navegador da sua rede. É especialmente útil para operar à distância ou como segundo ecrã.

A página tem o mesmo aspeto e funciona como a própria aplicação, e preenche a janela do navegador em qualquer tamanho. Numa janela larga, o espetrograma fica à esquerda e o painel selecionado à direita; numa janela alta, como a de um telemóvel na vertical, o espetrograma fica em cima. A barra de baixo tem os mesmos controlos da barra da aplicação: o botão TX, a mensagem, a sequência, o modo e a banda, e os botões das estações, do log de QSOs, do mapa mundial e das definições. A cascata move-se em direto, com as mesmas etiquetas da aplicação. Esta é a vista das estações numa janela alta:

Permite operar com o botão AUTO, a lista pendente de critérios, o botão + para adicionar indicativos diretamente e a lista de estações com botões CALL para as chamar manualmente. A pequena luz na ponta direita da barra fica verde enquanto a página está ligada ao qFT8.

E esta é a vista do log de QSOs:

Esta vista mostra as entradas mais recentes do log. Os outros dois botões abrem:

  • O mapa mundial, como na aplicação. O seu botão de ecrã inteiro dá ao mapa a janela toda; o mesmo botão ou Esc traz os painéis de volta.
  • As definições da página (a engrenagem): o seu indicativo, o seu locator e o seu modificador de CQ como estão na aplicação (mostrados, não alterados a partir da página), o desvio de tempo em passos de 100 ms, com que frequência a aplicação envia a cascata, e Quadrantes, que mostra de uma só vez o espetrograma, as estações, o mapa mundial e o log de QSOs. Cada navegador lembra se usa Quadrantes.

Dois navegadores podem estar abertos ao mesmo tempo no mesmo qFT8; o que faz num aparece no outro em menos de um segundo. Uma funcionalidade que está desligada na aplicação (veja Layouts de ecrã) também fica oculta na página. A página não carrega nada da internet: tudo vem do qFT8.

Rede e conectividade

O servidor abre uma porta TCP específica (por predefinição, 13497) no seu telemóvel ou computador. Para lhe aceder, os seus dispositivos têm de se «ver» na rede:

  • Rede local: o telemóvel ou o computador que executa o qFT8 e o seu dispositivo de controlo (computador, tablet ou telemóvel) precisam de estar na mesma rede.
  • Definições do router: alguns routers vêm com uma funcionalidade chamada isolamento de AP (ou isolamento de clientes) ativada por predefinição. Tem de estar desativada para que os dispositivos comuniquem entre si.
  • Com o hotspot de um telemóvel: em campo, pode abrir um hotspot Wi-Fi num telemóvel (com internet) e ligar o telemóvel do qFT8 a essa rede Wi-Fi. Depois de ligar, feche e reabra o servidor web nas definições do qFT8; o endereço IP mostrado passa a ser acessível a partir do telemóvel que fornece o hotspot.
  • Acesso pela internet: aceder ao servidor de fora de casa (pela internet) exige o reencaminhamento de portas nas definições do router (associando o IP e a porta internos a uma porta externa). Note que isto geralmente não funciona em ligações 5G/LTE, por causa das restrições de NAT das operadoras.

Níveis de acesso

Pode configurar o nível de segurança do acesso remoto no painel de definições:

  • Apenas leitura: permite ver o espetrograma em direto, as estações ativas e o log de QSOs. Nenhuma ação pode ser feita.
  • Ler e parar TX: é, antes de tudo, um modo de segurança. Permite ver todos os dados e desarmar o transmissor (parar o TX) em caso de emergência, mas não permite iniciar o TX nem mudar definições.
  • Controlo total: dá autoridade completa sobre a aplicação, com todas as funcionalidades interativas.

Nota de segurança: qualquer pessoa com acesso à sua rede, ao endereço IP e à porta terá o nível de controlo que configurou. Com Controlo total, poderia começar a transmitir usando a sua estação.

O que é possível fazer

No modo Controlo total, a interface web oferece quase tudo o que a interface da aplicação oferece:

  • Modos de operação: alternar entre os modos AUTO e CALL manual.
  • Estratégia: mudar os critérios do AUTO (Qualquer um, DXCC, Locator, etc.) e as restrições da procura.
  • Transmissão: iniciar/parar o TX manualmente, escolher mensagens de TX específicas e mudar a sequência do FT8 (0/1).
  • Frequência e banda: toque no espetrograma da página para mover o seu desvio de frequência, ou mude a banda ativa do rádio.

SSB, CW, RTTY e SSTV são operados no próprio qFT8. Enquanto a aplicação está num deles, a página web mostra a cascata e se a aplicação está a transmitir, e não transmite; escolha um modo digital na página para voltar a operar a partir dela.

O limite de transmissão contínua do rádio vale para a página exatamente como para a aplicação. Quando ele mantém o TX desligado (por exemplo WSPR com um limite de 60 segundos) ou interrompe o TUNE, a página mostra por alguns segundos um aviso que explica o motivo, para que não fique em dúvida diante de um botão que não faz nada. O limite em si só é alterado na aplicação.

Nota: a interface web foi feita para continuar a responder mesmo que o ecrã do telemóvel fique lento por causa de interferência de RF, o que dá uma alternativa fiável de controlo.

Nota: o servidor web funciona com o ecrã desligado se as definições de execução em segundo plano estiverem ativadas (por predefinição, o qFT8 continua em execução em segundo plano quando está ligado a um transcetor).

qFT8 bridge

O qFT8 bridge permite deixar o rádio num sítio e operar a partir de outro. Um dispositivo ao lado do rádio, o bridge, passa os comandos do rádio e o seu áudio pela sua própria rede para o qFT8 noutro dispositivo. Esse qFT8 faz todo o resto: descodifica, regista no log e decide o que transmitir. Para ele, o rádio funciona como se estivesse ligado por USB.

Use-o quando o rádio está perto da antena, no sótão, na garagem ou no barracão do jardim, e quer operar de um sítio mais confortável; ou quando o dispositivo ao lado do rádio deve apenas tratar do rádio: um computador pequeno como um Raspberry Pi, ou um telemóvel ou tablet antigo.

Isto não é o mesmo que o servidor web de controlo remoto. Aí, o qFT8 funciona ao lado do rádio e é visto a partir de um navegador. Com o bridge, o qFT8 funciona no dispositivo à sua frente e só o rádio está noutro sítio.

O que é preciso

  • Um dispositivo ao lado do rádio, com o rádio ligado a ele por USB como habitualmente: um computador com Windows, macOS ou Linux (um Raspberry Pi chega), ou um telemóvel ou tablet Android. Este é o bridge.
  • O qFT8 no dispositivo a partir do qual opera: o programa para computador ou a aplicação Android. Qualquer um deles pode usar qualquer bridge: um telemóvel pode operar um rádio ao lado de um computador, um computador um rádio ao lado de um telemóvel, e assim por diante.
  • Ambos na mesma rede local. Um cabo de rede funciona tão bem como o Wi-Fi e é mais estável; se puder, dê um cabo pelo menos ao bridge. Um telemóvel ou tablet usa o seu Wi-Fi, nunca os dados móveis.
  • A palavra-passe do bridge. O bridge cria uma e mostra-lha.

Configurar o bridge

Há duas formas de pôr um bridge a funcionar. Escolha uma.

1. A partir das Definições do qFT8 (o programa para computador ou a aplicação Android). No dispositivo ao lado do rádio, abra Definições > qFT8 BRIDGE e marque Funcionar como qFT8 bridge na porta. Deixe a porta como está, a não ser que outro programa a use.

Palavra-passe mostra a palavra-passe de que o outro dispositivo vai precisar. NOVA PALAVRA-PASSE cria outra; toque na própria palavra-passe para escrever a sua (7 caracteres ou mais).

Enquanto é um bridge, o qFT8 nesse dispositivo não faz mais nada. O TX é desligado, o seu próprio uso do rádio para, e o ecrã mostra apenas qFT8 a funcionar em modo bridge, com o Endereço e a Palavra-passe a introduzir no outro dispositivo e quem está a usar o rádio (Ninguém está ligado, ou o nome do dispositivo). No Android o bridge continua a funcionar com o ecrã desligado, indicado por uma notificação; mantenha o telemóvel ou tablet no carregador.

DESLIGAR O MODO BRIDGE pergunta primeiro, porque o outro dispositivo perde o rádio de imediato, e depois repõe o qFT8 como estava, com o TX ainda desligado. Se fechar o qFT8 enquanto é um bridge, ele arranca de novo como bridge da próxima vez.

2. A partir da linha de comandos (só computadores). Para um computador sem outra função, também um Raspberry Pi ou um servidor sem ecrã: arranque o qFT8 com --bridge. Funciona então apenas como bridge, sem janela, e não carrega mais nada do qFT8 (nem definições, nem descodificação), pelo que precisa de muito pouca memória. Use o qFT8 que transferiu para esse computador, a partir de um terminal:

  • Windows: abra uma Linha de Comandos na pasta do qFT8 e escreva qFT8.exe --bridge --tx-volume 70. Se o Windows perguntar se deve permitir "OpenJDK Platform binary" nas suas redes, permita-o.
  • macOS: no Terminal, escreva /Applications/qFT8.app/Contents/MacOS/qFT8 --bridge --tx-volume 70. Da primeira vez, o macOS pede acesso ao microfone: permita-o, é assim que o áudio do rádio é lido.
  • Linux: na pasta do qFT8, escreva ./qFT8 --bridge --tx-volume 70.
  • Qualquer computador com Java 21 ou mais recente, por exemplo um Raspberry Pi com o Java do seu sistema: a transferência .jar do qFT8 funciona em qualquer sistema. Escreva java -jar, o nome do ficheiro .jar e --bridge. Traz o que precisa para usar portas série no Windows, macOS e Linux (PCs e placas ARM, 32 e 64 bits).

O terminal mostra a palavra-passe no primeiro arranque e guarda-a para os seguintes. Deixe o terminal aberto: o bridge funciona enquanto ele estiver aberto. Ctrl+C, ou fechar o terminal, para-o e põe o rádio de novo em receção.

Opções que podem ser úteis, acrescentadas a seguir a --bridge:

  • --tx-volume N: obrigatório: o nível de áudio, de 1 a 100 %, que a ponte define no dispositivo de som do rádio para emitir, como a definição de volume de TX do próprio qFT8 (70 por omissão; rádios QRP Labs: 100). É apenas o nível do som: a potência do rádio nunca é alterada.
  • --password TEXT: a sua própria palavra-passe em vez da que ele criou.
  • --show-password: mostra de novo a palavra-passe guardada.
  • --new-password: cria uma nova.
  • --name TEXT: o nome que os outros dispositivos veem na sua lista (caso contrário é "qFT8 bridge"), útil com mais de um bridge.
  • --only TEXT: partilha só a porta série e o dispositivo de som do rádio, indicados por uma parte do seu nome (por exemplo --only QMX); nada mais do computador é oferecido.

--bridge --help lista as restantes.

Ligar a partir do qFT8

No dispositivo a partir do qual opera, abra Definições > CONFIGURAÇÃO DO DISPOSITIVO e marque Ligar através de um qFT8 bridge, mesmo no topo. Aparecem estas linhas:

  • Método: qFT8 bridge.
  • Bridge: abre a lista dos bridges que o qFT8 encontra na sua rede. Escolha o seu. Procurar novamente procura mais uma vez. Se o seu não estiver na lista, escolha Escrever endereço e introduza o endereço que o bridge mostra.
  • Palavra-passe: a que o bridge mostra.
  • LIGAR: a caixa ao lado fica verde e mostra Ligado a seguido do nome do bridge.
  • Porta do rádio no bridge, Dispositivo de som no bridge (receção) e Dispositivo de som no bridge (transmissão): onde o rádio está ligado do lado do bridge. AUTO encontra-os; escolha manualmente só quando o bridge tiver vários. Um rádio acedido através do programa próprio dele no computador do bridge (uma porta série virtual e um cabo de áudio virtual) tem uma porta que o AUTO não consegue reconhecer: escolha a porta manualmente e verifique se os dois dispositivos de som são os do cabo.

A partir daqui tudo é como com um rádio por USB: o qFT8 reconhece o rádio, lê a frequência, recebe e transmite. O qFT8 lembra-se do bridge e da palavra-passe, e uma exportação das definições leva-os para os seus outros dispositivos. Enquanto a caixa estiver marcada, um rádio ligado ao dispositivo a partir do qual opera não é usado. Para voltar a ele, desmarque Ligar através de um qFT8 bridge; não é preciso reiniciar.

Num telemóvel ou tablet, a caixa de estado mostra Sem Wi-Fi. Ligue este dispositivo à rede do bridge. quando não está numa rede Wi-Fi: o bridge só é procurado aí.

A indicação da ligação

Abaixo dos dispositivos do bridge, uma linha indica como está a ligação, por exemplo Atraso 120 ms, ajustado automaticamente. Ligação: estável (variação 3.0 ms).

  • Atraso: uma rede nunca entrega o som de forma perfeitamente regular, por isso o áudio é retido por um instante antes de ser reproduzido, para compensar isso. Não há nada a ajustar: o qFT8 e o bridge escolhem o atraso sozinhos, aumentam-no quando o áudio chega tarde e voltam a reduzi-lo quando a ligação esteve limpa durante algum tempo. Isto não perturba a temporização dos modos digitais: as suas transmissões continuam a começar a horas, e o que recebe é colocado pelo momento em que o rádio o ouviu.
  • Ligação: estável: está tudo bem.
  • Ligação: irregular: o áudio está a chegar de forma irregular. O atraso trata disso; não há nada a fazer, a não ser que continue assim.
  • A vermelho, A ligação ao bridge está a perder áudio de transmissão: parte de uma transmissão não chegou ao rádio a tempo. O atraso é aumentado de imediato; se isto continuar a acontecer, veja Resolução de problemas.
  • A vermelho, A ligação ao bridge não aguenta: nem o maior atraso é suficiente e o áudio de transmissão falha. Veja Resolução de problemas.

Logo depois de ligar, a linha mostra Ainda nada medido.

Segurança da transmissão

  • Só o operador liga o TX, com o botão TX do qFT8 à sua frente. O bridge nunca inicia uma transmissão sozinho.
  • Se a ligação cair (o Wi-Fi desaparece, o dispositivo entra em suspensão, o qFT8 é fechado), o bridge põe o rádio de novo em receção sozinho, em um ou dois segundos. O qFT8 para o que estava a transmitir, desliga o TX e mostra um cartão vermelho que diz porquê, como Ligação perdida. A ligar de novo... Volta a ligar-se sozinho. Se a ligação voltar em menos de 10 segundos e tinha o TX ligado, o qFT8 volta a ligá-lo uma vez, como o tinha; depois de uma quebra mais longa fica desligado até o premir de novo.
  • O limite de transmissão contínua do seu rádio também é respeitado pelo bridge.
  • Parar o bridge, de qualquer uma das duas formas, também põe o rádio de novo em receção.

Nota de segurança: A palavra-passe protege o controlo do seu rádio: ninguém sem ela pode usar o bridge, e a própria palavra-passe nunca é enviada pela rede. Não torna a ligação privada: o áudio e os comandos do rádio não são cifrados. Use o bridge apenas dentro da sua própria rede e não o abra para a internet.

Limites

  • Só rede local. O bridge não foi feito para ser acedido pela internet. Uma VPN que envia o tráfego da sua rede doméstica pelo seu túnel também esconde o bridge: desligue-a, ou permita nela o acesso à rede local, nos dois dispositivos.
  • Um dispositivo de cada vez. Quando um segundo dispositivo se liga, fica com o bridge; o primeiro mostra Outro dispositivo ficou com o bridge. Prima LIGAR para o recuperar.
  • Todos os modos funcionam através de um bridge, a receber e a transmitir: FT8, FT4, FT2, JS8, WSPR, LQ8, SSB, CW, RTTY, SSTV e TUNE. O seu altifalante e o seu microfone ficam no dispositivo à sua frente; só o áudio do rádio atravessa a rede.
  • Um rádio que passa a transmissão por uma linha de controlo (RTS ou DTR) em vez de um comando também é manipulado através do bridge.

qFT8log

O qFT8log mantém juntos os logs de vários qFT8 pela sua própria rede. Um qFT8 é o servidor qFT8log; os outros enviam a ele cada QSO que fazem. O servidor os acrescenta ao seu próprio log (a lista de QSOs, o mapa, as estatísticas) e os repassa aos serviços configurados nele, como QRZ e LoTW. O que acontece depois com um QSO, uma confirmação ou uma correção, volta para o qFT8 que o fez enquanto os dois estiverem ligados.

Qualquer qFT8 pode ser servidor e cliente ao mesmo tempo: o programa para computador, a aplicação Android e a aplicação iPhone. No Android o servidor continua a funcionar em segundo plano quando Executar em segundo plano está ativado; no iPhone ele funciona só enquanto a aplicação está aberto.

Configurando o servidor

  1. No qFT8 que deve reunir os QSOs, abra Definições, vá em Servidores do qFT8 e abra Servidor qFT8log.
  2. Escreva uma palavra-passe. Use o mesmo tipo de palavra-passe do bridge do qFT8: sete caracteres ou mais.
  3. Deixe a porta em 13510, a menos que outra coisa a use, e ative o servidor. A página mostra o endereço do servidor e os qFT8 ligados a ele. Uma porta alterada tem efeito de imediato.
  4. O mesmo endereço aberto num navegador (por exemplo http://192.168.1.20:13510/) mostra o log, só de leitura, depois de escrever a palavra-passe do servidor (ela nunca é enviada): veja Ver o registo num navegador.

Configurando um cliente

  1. Em cada qFT8 que deve enviar seus QSOs, abra Definições e prima a engrenagem ao lado de qFT8log, no topo.
  2. Prima PROCURAR: os servidores qFT8log da sua rede aparecem listados por nome. Escolha um, ou escreva o endereço e a porta do servidor.
  3. Escreva a palavra-passe do servidor e prima VALIDAR. Quando o servidor a aceitar, marque qFT8log no topo das Definições.

A partir daí o cliente se liga sozinho sempre que inicia e se religa sozinho quando a rede ou o servidor voltam. Os QSOs feitos enquanto o servidor não está acessível esperam no log (aparecem como não enviados ao qFT8log) e são enviados assim que a ligação volta, também após uma reinício. Quando o cliente não consegue alcançar o servidor, a linha qFT8log nas Definições fica vermelha com Não foi possível ligar desde e a hora.

Considerar um QSO enviado se estiver enviado aqui vem desativada para o qFT8log. Marque-a quando o servidor for o lugar para onde seus QSOs vão, para que a marca de "aguardando envio" de um QSO suma assim que o servidor o tiver.

O que circula

  • QSOs novos, do cliente para o servidor, com todos os campos que o qFT8 guarda: os relatórios, grids, parques e cumes, equipamento, comentários, e se o QSO já foi enviado ao QRZ, ao LoTW ou a outro serviço, ou confirmado por eles (um QSO importado do LoTW continua confirmado).
  • Confirmações, nos dois sentidos, assim que chegam: uma confirmação que o servidor recebe do LoTW aparece no cliente que fez o QSO, e vice-versa.
  • Correções feitas no editor de QSOs, nos dois sentidos. Quando o mesmo QSO foi alterado nos dois lados, vale a alteração mais recente.
  • Os apagamentos nunca viajam. Apagar um QSO apaga-o apenas nesse qFT8; os outros mantêm o seu. Cada qFT8 lembra-se dos QSOs apagados nele e nunca os volta a aceitar de outro qFT8, nem por importação nem pela sincronização em direto.

O servidor aceita QSOs de todos os modos e de todos os indicativos: é o lugar onde se reúne, e os filtros do log escolhem o que se vê. Um QSO que o servidor já tem (o mesmo indicativo, hora, banda e modo) é fundido com o que ele tem, nunca é acrescentado duas vezes e não é enviado adiante de novo.

Importar do servidor e sincronização em direto

Um cliente envia apenas os seus próprios QSOs. Duas formas trazem também o log do servidor para ele:

  • IMPORTAR QSOs DO SERVIDOR, na página qFT8log do cliente, copia uma vez todos os QSOs do servidor dentro de De, Até, Bandas e O indicativo começa por, de todos os modos. Os QSOs feitos com outro indicativo que não o seu são ignorados, a menos que Importar QSOs para indicativos diferentes do atual esteja assinalado. Funciona também quando o qFT8log não está assinalado no topo das Definições: a importação liga-se então só para si mesma e não envia nada.
  • Manter sincronizado em direto com este servidor (requer o qFT8log assinalado no topo das Definições): os QSOs do servidor vêm para aqui e, a partir daí, cada QSO registado, corrigido ou confirmado no servidor, ou em qualquer outro qFT8 ligado a ele, aparece aqui de imediato, e os seus vão para lá. Vários qFT8 com esta caixa assinalada partilham um só log através do seu servidor e, com cadeias, através de todos os servidores da cadeia.
  • Quando a ligação cai, nada se perde: cada lado recupera quando volta, também depois de um reinício.
  • As horas das correções seguem o relógio do servidor, por isso um dispositivo com o relógio errado não ganha, nem perde, todas as correções.

Cadeias: reunir e fazer cópia de segurança

Um servidor pode ser ele mesmo cliente de outro servidor, então os qFT8 podem ser encadeados. Um QSO nunca é enviado de volta a um qFT8 por onde já passou, de modo que nem um anel de qFT8 forma um ciclo. Dois exemplos:

  • Um só local que envia. Os telemóveis e o computador portátil enviam para o computador da estação. Só o computador da estação tem o QRZ e o LoTW configurados: ele envia tudo, e as confirmações que recebe voltam para o qFT8 que fez cada QSO.
  • Uma cópia de segurança. O computador da estação também envia tudo a outro qFT8, digamos um tablet antigo que só guarda o log e mostra o mapa-múndi. Nada precisa ser configurado na cópia de segurança além do seu servidor.

Nota de segurança: a palavra-passe nunca é enviada pela rede: os dois qFT8 provam que a conhecem, e cada mensagem depois disso é assinada, de modo que nada pode ser alterado nem repetido no caminho. Os QSOs em si não são cifrados. Use o qFT8log só dentro da sua própria rede e não abra a porta dele para a internet.

Limites

  • Só rede local, como o bridge do qFT8.
  • Os dois qFT8 devem usar a mesma versão do qFT8log. Um servidor recusa um cliente de outra versão, e a linha do cliente diz qual deve ser atualizado.
  • No máximo 16 clientes por vez em cada servidor.
  • Um QSO que o servidor não consegue ler (por exemplo, um sem data) é marcado como recusado no cliente e só é enviado de novo depois de o corrigir.

Protocolo do qFT8log (versão 2)

Esta é a descrição completa do que dois qFT8 dizem um ao outro. Todo número é big-endian. O texto é UTF-8.

Encontrando servidores

Um cliente envia um datagrama UDP aos endereços de broadcast de suas redes, porta 13510: "qFT8L?" (6 bytes), a versão da API (2 bytes), um id aleatório (8 bytes). Cada servidor responde ao remetente: "qFT8L!", a versão da API dele (2), o mesmo id (8), a porta TCP dele (2), o id de instância dele (16 dígitos hexadecimais ASCII), o tamanho do nome dele (1) e o nome dele (no máximo 64 bytes). A resposta não diz nada secreto.

Tramas

Por TCP (porta 13510 por predefinição) tudo circula em tramas: o tipo (1 byte), o tamanho do corpo (3 bytes) e o corpo (no máximo 16384 bytes). Os quatro primeiros tipos circulam antes de as chaves existirem; o corpo de qualquer outra trama é selado: um contador de 8 bytes, a mensagem e os primeiros 16 bytes do HMAC-SHA256 (chave da direção) sobre o tipo, o contador e a mensagem. Cada direção conta a partir de 0 e uma trama deve trazer exatamente o número seguinte: uma trama alterada, repetida ou omitida encerra a ligação.

Tipo 0x01
Nome HELLO (cliente)
Corpo "QFT8LOG1", versão da API (2), aleatório do cliente (32), id de instância do cliente (16 ASCII), tamanho do nome (1), nome
Tipo 0x02
Nome CHALLENGE (servidor)
Corpo versão da API (2), aleatório do servidor (32), sal (16), rondas (4), id de instância do servidor (16 ASCII), tamanho do nome (1), nome, prova do servidor (32)
Tipo 0x03
Nome AUTH (cliente)
Corpo prova do cliente (32)
Tipo 0x04
Nome REFUSED (servidor)
Corpo motivo (1): 1 outra versão da API, 2 palavra-passe errada, 3 esperar (palavra-passes erradas demais), 4 ocupado, 5 não é um HELLO, 6 a própria instância do servidor; espera em ms (4); a versão da API do servidor (2)
Tipo 0x10
Nome WELCOME (servidor, selado)
Corpo versão da API (2), hora do servidor em ms (8): o cliente carimba as suas correções com este relógio
Tipo 0x11 / 0x12

Corpo vazio

Nome BYE

Tipo 0x22
Nome NACK

Corpo um objeto JSON: mode (once, live ou off), from e to (YYYYMMDD, vazio = sem limite), bands (uma lista), call (o início do indicativo), station (o indicativo da estação, vazio = qualquer)
Tipo 0x24
Nome BACKLOG_DONE (servidor)
Corpo QSOs enviados (4), novos aí (4), fundidos aí (4): todos os QSOs que a subscrição pediu foram enviados

O handshake

Os dois lados conhecem k = PBKDF2-HMAC-SHA256(palavra-passe, sal, rondas), 32 bytes. O servidor escolhe o sal e as rondas (200000; um cliente recusa menos de 10000 ou mais de 5000000). A transcrição t é o corpo do HELLO seguido do corpo do CHALLENGE sem a prova dele. Com L = o texto ASCII "qFT8 log v1 ":

  • prova do servidor = HMAC-SHA256(k, L + "server proof" + t); prova do cliente = HMAC-SHA256(k, L + "client proof" + t);
  • chave do cliente para o servidor = HMAC-SHA256(k, L + "key client>server" + t); chave do servidor para o cliente = HMAC-SHA256(k, L + "key server>client" + t).

O cliente confere primeiro a prova do servidor e fecha sem responder quando ela está errada, de modo que nada derivado da palavra-passe chega a um servidor que não a conhece. O servidor confere a prova do cliente; uma errada bloqueia esse endereço por 1 s, dobrando a cada tentativa errada seguida até 60 s. Os dois aleatórios são novos a cada ligação, então um handshake gravado não vale nada. As versões da API devem ser iguais: um servidor recusa qualquer outra com o motivo 1, e um cliente recusa um CHALLENGE de outra versão. Um servidor admite 8 handshakes ao mesmo tempo, 5 s para cada etapa e 16 clientes; um cliente que se liga de novo toma o lugar da ligação antiga dele.

Registos

Um registo de QSO é um objeto JSON com os nomes de campo que o qFT8 guarda (call, qso_date como YYYYMMDD, time_on como HHMM ou HHMMSS, band, mode, submode, rst_sent, rst_rcvd, gridsquare, freq, station_callsign, my_gridsquare, comment, as referências de parques e cumes, os estados do QRZ e do LoTW app_qrzlog_logid, app_qrzlog_status, app_lotw_qsl_rcvd, app_lotw_logid, app_lotw_upload_time, e app_svc), no máximo 16000 bytes. call, qso_date e time_on são obrigatórios; qualquer modo e qualquer indicativo são aceitos. app_svc guarda os estados dos outros serviços e três registos do próprio protocolo, como partes id:key=value,... separadas por ;:

  • q8u: id = o uid do QSO (criado uma vez pelo qFT8 que o enviou primeiro, mantido em todas as correções), t = quando o conteúdo dele foi corrigido pela última vez (ms UTC, ausente = nunca);
  • q8v: id = os ids de instância por onde o QSO passou, separados por pontos (no máximo 32);
  • um remetente omite a própria contabilidade: seus hashes por par, seu próprio estado de envio e suas marcas de trabalho locais.

Hash e fusão

O hash de um QSO são os primeiros 8 bytes do SHA-256, como 16 dígitos hexadecimais, sobre as linhas name=value do conteúdo dele, da hora de correção dele e dos estados de envio e de confirmação dele (não as instâncias por onde passou). Duas cópias de um mesmo QSO viram uma só do mesma forma em todo o lado: vale, como um todo, o conteúdo da cópia corrigida mais tarde (horas iguais: vale o conteúdo de maior hash); os estados de envio e de confirmação só avançam (uma confirmação nunca é desfeita); as instâncias são a união das duas. A fusão é a mesma qualquer que seja a ordem e fundir duas vezes não muda nada, então todas as cópias terminam iguais.

Quem envia o quê

  • Um cliente envia ao seu servidor cada QSO que ainda não passou por esse servidor, e cada QSO que os dois já trocaram antes e cujo hash mudou desde então.
  • Um servidor envia ao cliente os QSOs que os dois já trocaram e cujo hash mudou (uma confirmação, uma correção). Depois de um SUBSCRIBE envia também a esse cliente todos os QSOs do seu log dentro da subscrição que os dois nunca trocaram e que não passaram pelo cliente, e depois BACKLOG_DONE. Com live continua a fazê-lo para cada QSO que recebe mais tarde, enquanto a ligação durar (o cliente subscreve de novo após cada reconexão); once termina com BACKLOG_DONE; off termina a subscrição.
  • O recetor encontra a sua cópia pelo uid ou, na falta dele, por indicativo, data, hora (HHMM), banda e modo. Um servidor acrescenta um QSO que não tem; um cliente só acrescenta um dentro da subscrição que enviou. Nenhum dos dois acrescenta um QSO apagado nele (resultado 3 nos dois casos). Caso contrário, as cópias são fundidas; o ACK leva o hash do recetor e, quando a cópia fundida difere da enviada, o registo fundido, que o emissor funde por sua vez.
  • Cada lado lembra, por QSO e por par, o hash em que os dois concordaram por último, e só envia de novo quando a própria cópia difere dele. As eliminações nunca são enviadas.
  • No máximo 16 PUTs podem esperar a resposta. Um servidor aceita 100 PUTs por segundo de cada cliente (rajadas de 200) e responde NACK 2 acima disso; após 50 registos que não consegue ler, ele encerra a ligação.
  • Um lado envia PING quando não enviou nada por 15 s e encerra a ligação quando não ouviu nada por 45 s. Um cliente se religa com intervalos de 1 s, 2 s, 4 s ... até 60 s.

Layouts de ecrã

As capturas de ecrã deste manual mostram o layout predefinido: paisagem, com o espetrograma à esquerda. Na aplicação para Android, Definições > APLICAÇÃO > Interface do utilizador permite mudá-lo (o programa de computador não tem nenhuma destas definições: tem as suas próprias disposições, veja As disposições do ecrã e o botão de disposição):

  • Orientação: Paisagem, Retrato ou Seguir o telemóvel. Em retrato o espetrograma fica em cima, o separador em baixo dele, e num telemóvel a barra inferior ocupa duas linhas.
  • O divisor: arraste a linha fina entre o espetrograma e o separador para dar mais espaço a um deles. Cada orientação lembra a sua própria posição.
  • Quadrantes (tablets): o espetrograma, as estações, o mapa mundial e o log de QSOs de uma só vez, com as Definições a abrir à direita.
  • Funcionalidades: Funcionalidades de rádio, Log de QSOs e Mapa mundial podem ser desligados separadamente se não os usa, por exemplo para usar o qFT8 só como logbook. Enquanto um está desligado, aparece nas Definições um botão ATIVAR para ele. Desligar as funcionalidades de rádio também desliga o TX.
  • A aplicação cobre: permite que o qFT8 desenhe sobre a barra de navegação, a área da câmara e a barra de estado, para ganhar um pouco mais de espaço.

Relatórios de erros e novas versões

Comunicar um problema

COMUNICAR ERRO, no fim do separador Definições, abre um cartão onde descreve o que correu mal e, se quiser uma resposta, deixa o seu e-mail. Tocar em ENVIAR envia a sua descrição juntamente com o log da aplicação: definições, detalhes do rádio e do áudio e atividade recente. Palavras-passe, chaves de API, certificados e os dados de acesso dos seus serviços de QSO nunca são incluídos. Recebe uma referência como QFT8-7K3P9 para indicar mais tarde. Se não for possível aceder ao servidor de relatórios, o qFT8 oferece-se para enviar o relatório por e-mail.

«Enviar um relatório sobre isto?»

Quando o qFT8 deteta que deixou de responder por um momento, ou que a descodificação está a demorar demasiado no seu dispositivo, pode mostrar um pequeno cartão que se oferece para enviar um relatório sobre isso, com ENVIAR, NÃO ENVIAR e NÃO VOLTAR A PERGUNTAR. Nada é enviado sem o seu toque. O cartão aparece no máximo uma vez por dia, e NÃO VOLTAR A PERGUNTAR silencia-o durante uma semana. Depois de uma falha, o qFT8 pergunta no arranque seguinte se deve enviar um relatório de falha.

Procurar novas versões ao iniciar

Com esta caixa marcada (página principal das Definições, perto do fim), o qFT8 procura uma versão mais recente ao iniciar e, quando há uma, mostra um aviso com um botão de transferência. Nunca se atualiza sozinho.

Resumo anónimo de desempenho

Enviar um resumo diário anónimo de desempenho (página principal das Definições, logo acima de Idioma) fica desligado, a menos que o ligue. Quando ligado, cerca de uma vez por semana o qFT8 envia um breve resumo da velocidade com que funciona no seu dispositivo: tempo de arranque, fluidez do ecrã, tempos de descodificação, tempos de áudio e de rádio, e o modelo do dispositivo e o ecrã. Nunca contém o seu indicativo, locator, log, definições nem nada que o identifique. Ajuda a tornar o qFT8 mais rápido em dispositivos como o seu.

Resolução de problemas

O telemóvel ou o computador não reconhece o transcetor, ou a ligação cai

É quase sempre um problema de ligação física ou de interferência de rádio. As ligações USB são sensíveis à vibração, à qualidade do cabo e à sujidade acumulada na porta USB. No Android, outra causa comum é o USB OTG poder estar desativado por predefinição no seu dispositivo (em especial, se consegue receber sinais no qFT8, mas não transmitir, e os comandos CAT não funcionam mesmo com um dispositivo totalmente compatível, mostrado na lista de dispositivos, reconhecido automaticamente no modo AUTO, etc., é muito provável que seja esta a causa).

Experimente:

  • No Android, ativar o USB OTG nas definições do dispositivo (em alguns dispositivos o OTG vem desativado por predefinição e pode estar nas definições avançadas, do sistema ou adicionais).
  • Usar um cabo USB curto e de boa qualidade (um cabo mais curto pode ajudar bastante), e verificar se a porta USB está limpa e a ligação está firme.
  • No Linux, se o qFT8 disser que não tem permissão para abrir a porta do rádio, aceite a oferta para o corrigir (a sua conta entra no grupo da porta), ou peça ao administrador do sistema.
  • Se os problemas acontecem especificamente durante a transmissão, a causa pode ser interferência de rádio. Colocar chokes ou ferrites no cabo USB pode ajudar. Também pode tentar transmitir noutra banda, porque alguns dispositivos só são sensíveis à interferência em certas bandas.

O transcetor desaparece quando o telemóvel está totalmente carregado (Android)

Isto acontece com adaptadores USB OTG que têm uma entrada de carga, para que o telemóvel possa ser carregado enquanto o transcetor está ligado. Com alguns deles, quando a bateria chega a 100%, o telemóvel corta a ligação USB ao transcetor, e ela não volta até o carregador ser desligado. O qFT8 mostra então o transcetor como desligado e nada funciona: nem áudio, nem CAT.

Experimente: desligar o carregador do adaptador (o transcetor volta), operar sem carregar, ou usar outro adaptador ou um hub com alimentação.

qFT8 bridge: "Nenhum bridge encontrado nesta rede"

O qFT8 perguntou à rede e nenhum bridge respondeu. As causas habituais são o bridge não estar a funcionar, os dois dispositivos não estarem na mesma rede (um Wi-Fi de convidados conta como outra rede), ou algo entre eles bloquear a pergunta.

Experimente:

  • Verificar se o bridge está a funcionar: a janela dele está aberta, ou o qFT8 nesse dispositivo mostra qFT8 a funcionar em modo bridge. Depois, Procurar novamente.
  • Usar Escrever endereço e introduzir o endereço que o bridge mostra. Um bridge que a pesquisa não encontra muitas vezes responde quando é contactado diretamente.
  • Permitir o bridge na firewall do computador dele: portas TCP e UDP 13498, e porta UDP 13499 (a que a pesquisa usa).
  • Desativar o isolamento de AP (ou isolamento de clientes) no router, tal como para o servidor web de controlo remoto.
  • Desligar uma VPN nos dois dispositivos, ou permitir nela o acesso à rede local. Uma VPN que envia todo o tráfego pelo seu túnel esconde o bridge, mesmo com os dois dispositivos lado a lado.

qFT8 bridge: "Palavra-passe incorreta", ou o bridge recusa a ligação

A palavra-passe tem de ser escrita exatamente como o bridge a mostra. Uma palavra-passe criada pelo bridge tem só letras minúsculas e algarismos, e nunca os caracteres parecidos i, l, o, 0 e 1. Depois de várias tentativas erradas seguidas, o bridge faz esse dispositivo esperar antes da seguinte, até um minuto.

Experimente: Ler de novo a palavra-passe no bridge: no ecrã do modo bridge do qFT8, ou arrancando a transferência do bridge com --show-password. Em caso de dúvida, crie uma nova (NOVA PALAVRA-PASSE, ou --new-password) e escreva essa.

qFT8 bridge: ligado, mas sem rádio ou sem áudio

A ligação funciona, mas o bridge não consegue usar a porta do rádio ou o seu dispositivo de som. A caixa pode mostrar Ligado a e o nome do bridge, seguido de "mas não foi possível abrir o dispositivo de som dele".

Experimente:

  • Escolher Porta do rádio no bridge e as duas linhas de dispositivo de som manualmente em vez de AUTO.
  • Fechar qualquer outro programa no dispositivo do bridge que use o rádio, incluindo um qFT8 que não esteja em modo bridge.
  • No macOS, permitir o microfone para o bridge em Definições do Sistema > Privacidade e Segurança > Microfone.
  • No Linux, garantir que a conta que executa o bridge pode usar portas série (normalmente por pertencer ao grupo dialout) e o som.
  • Num bridge Android, permitir que o qFT8 use o rádio quando o Android perguntar, tal como para um rádio ligado ao próprio telemóvel.

qFT8 bridge: "A ligação ao bridge está a perder áudio de transmissão" ou "não aguenta"

A rede entre os dois dispositivos é demasiado irregular: o áudio de transmissão chega demasiado tarde para ser reproduzido. Enquanto o atraso ainda pode crescer, o qFT8 aumenta-o e diz que a ligação está a perder áudio; quando nem o maior atraso basta, diz que a ligação não aguenta e as transmissões falham. É uma questão da rede, não do rádio.

Experimente: Aproximar-se do ponto de acesso Wi-Fi, ligar o bridge (ou os dois dispositivos) com um cabo de rede, e pausar o que mais estiver a sobrecarregar a rede.

Em vez de receber o sinal do transcetor, o qFT8 está a receber áudio do microfone

No Android, isto indica que o telemóvel está a usar o microfone interno porque não reconhece o transcetor como uma fonte de áudio externa. No computador, verifique que entrada está escolhida em CONFIGURAÇÃO DO DISPOSITIVO nas definições: escolha o dispositivo de áudio do transcetor. As causas mais comuns são:

  • O cabo USB não é próprio para dados (cabo só de carga).
  • O adaptador USB (OTG) está avariado ou é incompatível (Android).
  • O cabo está ligado na direção errada (alguns cabos são direcionais).

Experimente: usar outro cabo USB, outro adaptador, ou inverter as pontas do cabo.

O mostrador do rádio não coincide com a frequência que o qFT8 mostra

O visor do rádio e o qFT8 diferem em alguns Hz até cerca de 100 Hz. Em regra é o desvio de sintonia do espetrograma, e é propositado: o qFT8 sintoniza o rádio um pouco mais abaixo e desloca o áudio na mesma quantidade, para que os sinais mesmo no início do espetrograma saiam da zona cega do rádio nos graves de áudio. As descodificações, os spots, o registo e a frequência mostrada pelo qFT8 continuam a ser a frequência real.

Experimente: Não há nada a corrigir. O valor por omissão depende do rádio (−100 Hz na família QMX, −90 Hz no IC-7300, −50 Hz em qualquer outro rádio). Para o alterar ou pôr a 0, abra Definições > CONFIGURAÇÃO DO DISPOSITIVO > Sintonia (este rádio) > Desvio de sintonia do espetrograma (veja Desvio de sintonia do espetrograma).

Nenhum sinal recebido; a cascata está totalmente preta

Se a cascata continua totalmente preta tanto com o transcetor ligado como desligado, provavelmente o qFT8 não tem as permissões necessárias para aceder ao áudio.

Experimente: no Android, vá a Definições > Aplicações > qFT8 > Autorizações do telemóvel e verifique se o Microfone (ou a gravação de áudio) está permitido durante a utilização do qFT8. Em alternativa, desinstale completamente o qFT8, reinstale-o e aceite todos os pedidos de permissão no primeiro arranque. No macOS, abra Definições do Sistema > Privacidade e Segurança > Microfone e permita o qFT8. Em qualquer computador, verifique a entrada escolhida em CONFIGURAÇÃO DO DISPOSITIVO.

Há sinais visíveis, mas nenhuma mensagem é descodificada

Se vê «linhas onduladas» verticais na cascata (sinais FT8), mas nenhum texto aparece no separador Estações, talvez o seu relógio não esteja sincronizado.

Experimente:

  • Verifique se há acesso à internet e reabra a aplicação para disparar uma sincronização NTP.
  • Se não houver internet disponível, tente uma sincronização por GPS (Android).
  • Se isto também não funcionar, mas os tons das mensagens forem visíveis no espetrograma, dispare uma sincronização de emergência da hora a partir das mensagens, no menu de definições de hora e localização.
  • Verifique se o rádio está de facto a receber sinais do ar.

Se não aparece nenhuma faixa ondulada na cascata, talvez a banda esteja fechada ou a antena esteja desligada ou desajustada.

As mensagens são descodificadas demasiado tarde

O processador do telemóvel (ou de um computador mais antigo) pode ser demasiado lento para descodificar as mensagens a tempo.

Experimente: não deixe de mudar para Fast decode nas definições, e esteja à vontade para antecipar o momento da descodificação (por exemplo, para 13000ms), criando mais margem para descodificar, à custa de talvez perder algumas mensagens atrasadas em cada ciclo.

Erro «SWR exceeded threshold — transmission stopped» com o transcetor QMX

Se o qFT8 mostra 0W durante a transmissão, há várias causas prováveis:

1. Proteção de SWR

Se o LCD do QMX mostra um «S» depois da frequência, a proteção de SWR entrou em ação. Isto significa que a sua antena não está bem ajustada para a banda atual e que o QMX parou de transmitir para proteger os seus circuitos.

Além disso, o qFT8 tem o seu próprio limiar de SWR, configurável nas definições da aplicação. Quando a SWR medida passa desse limiar, o qFT8 para a transmissão automaticamente, para proteger o seu equipamento.

  • Firmware 1_04_004+: o qFT8 reinicia automaticamente a proteção de SWR no final do ciclo.
  • Firmware 1_03_000+: pode definir "SWR Protection reset options" como Timer ou TX->RX no menu do QMX. Assim o qFT8 continua a operar sem que tenha de tocar no transcetor.
  • Firmware antigo: com firmware do QMX anterior a 1_03_000, é preciso reiniciar o transcetor manualmente (desligar/ligar) ou entrar e sair do menu TUNE do QMX para limpar o erro.

Nota: o qFT8 espera 1 segundo depois do início da transmissão antes de verificar se há 0W, para evitar falsos positivos enquanto o QMX sobe a potência. Se o QMX recuperar e a potência passar de 1W, o indicador de problema desaparece automaticamente.

2. O firmware não mede a potência

Se o QMX não mostra que a proteção de SWR está ativa, e mostra que a transmissão está a decorrer normalmente, pode ser que o firmware seja antigo e não meça a potência. Dispositivos como o QDX também não medem a potência. O qFT8 não sabe como interpretar 0W e fica confuso.

Experimente: se o firmware do seu QMX é antigo, atualize-o. Se usa um QDX, não há como contornar isto.

3. O sinal de áudio não chega ao QMX

Se o QMX não mostra o ícone «S» depois da frequência, é provável que o transcetor simplesmente não esteja a receber um sinal de áudio adequado do qFT8. O volume pode estar demasiado baixo (sinal insuficiente) ou demasiado alto (o corte/a distorção faz o QMX rejeitar o sinal).

Experimente: verifique o indicador de sinal do seu QMX. Um único ponto significa que não há áudio; dois pontos, que há áudio, mas não com volume suficiente. Vá à secção de definições de FT8 e ajuste a opção «Definir o volume do sistema para [X] ao usar o rádio» para valores diferentes (por exemplo, 70%, 80%, 90%), até encontrar o nível certo para o seu dispositivo.

4. A SWR é baixa na sintonia, mas a proteção de SWR entra em ação

Isto sugere que a SWR tem picos em potência alta durante alguns instantes na transmissão real, o que aciona a proteção de SWR. É sinal de uma antena temperamental (por exemplo, loops magnéticos), de um mau cabo, de uma má ligação ou de um problema na montagem.

Experimente: acrescentar chokes de corrente de modo comum (como anéis de ferrite) deve reduzir a corrente de modo comum.

O que é a notificação do qFT8 no Android? (Android)

Esta notificação permite que o qFT8 continue a processar o áudio e a conduzir os QSOs quando minimiza a aplicação ou desliga o ecrã.

  • Por predefinição, aparece automaticamente quando é ligado um transcetor.
  • Pode desativá-la nas definições do qFT8, mas o qFT8 deixará de funcionar em segundo plano.
  • Pode tocar em PARAR na notificação para fechar o qFT8 por completo.

O qFT8 deixa de funcionar quando o ecrã está desligado (Android)

Alguns fabricantes de aparelhos Android aplicam otimizações de bateria muito agressivas, que podem encerrar as aplicações em segundo plano mesmo que tenha concedido as permissões iniciais.

Verifique se concedeu as permissões: vá a Definições > Aplicações > qFT8 > Bateria do telemóvel e selecione «Sem restrições» (ou «Não otimizar»).

Os botões comportam-se de modo estranho ou o ecrã não responde durante o TX

Isto é causado por interferência de RF (RFI). Se a sua antena está perto do telemóvel ou do computador, ou o cabo é mal blindado, a energia de rádio pode interferir no ecrã sensível ao toque, no rato ou na ligação USB.

  • Dica: use um cabo USB blindado ou prenda um ferrite de encaixe no cabo.

O qFT8 está diferente das capturas de ecrã deste manual

A interface da aplicação é atualizada de vez em quando, pelo que alguns detalhes visuais podem ter mudado desde que as capturas de ecrã foram feitas. Mas, se faltam partes importantes da interface ou as cores parecem muito alteradas (por exemplo, a barra de progresso amarela, os seletores de sequência, etc.), o modo escuro do sistema do seu telemóvel pode estar a sobrepor-se indevidamente à paleta de cores da aplicação e a estragá-la.

Experimente: se o modo escuro do sistema está a causar problemas, pode desativá-lo temporariamente ou colocar o qFT8 na respetiva lista de exceções, para recuperar o aspeto correto.

O qFT8 diz «NO RADIO» mesmo com o transcetor ligado

Provavelmente não concedeu a permissão para ligar o qFT8 ao transcetor. Às vezes isto acontece porque se toca fora da caixa de diálogo de permissão, e ela fecha-se.

Experimente: desligue e volte a ligar o transcetor; isto deve fazer a pergunta aparecer de novo. Por comodidade, marque a opção «Abrir sempre o qFT8 quando o Transcetor for ligado», para nunca mais ter este problema.

O qFT8 mostra a distância em milhas e eu quero em quilómetros (ou vice-versa)

Isto vem da localidade do sistema operativo (isto é, da escolha de idioma).

Experimente: mudar essa definição para o país certo (por exemplo, inglês (Estados Unidos) para milhas, inglês (Reino Unido) para quilómetros) resolve.

O qFT8 mostra uma potência de transmissão baixa (por exemplo, 0.1W) ao transmitir com >10W no QMX

Este é um bug conhecido do firmware do QMX (pelo menos até ao 1.03.000). Se usa as modificações 2x4 (por exemplo, num QMX+) e a sua potência de transmissão passa de 9.9W, a formatação do rádio dá a volta. Por exemplo, 10.1W é indicado pelo transcetor à aplicação como 0.1W no protocolo CAT secundário.

Experimente: não há como contornar isto dentro do qFT8, porque a aplicação mostra diretamente o valor que recebe. Pode ignorar esse erro de exibição sem risco, ou reduzir a potência para menos de 10W para manter as leituras corretas até que o bug seja corrigido no firmware do transcetor.

Não consigo exportar os logs ADIF para o armazenamento local com Partilhar (Android)

O método predefinido, Partilhar, usa o mecanismo de partilha do próprio Android para exportar os logs. Às vezes, o menu de partilha de ficheiros do seu dispositivo não oferece uma opção direta para guardar no armazenamento local.

Experimente: mude o Método de exportação para Guardar localmente nas definições. Isto usa o seletor de ficheiros do Android para guardar o ficheiro diretamente no armazenamento local, sem depender do menu de partilha.

O qFT8 não consegue descodificar algumas mensagens

Experimente: ative a descodificação profunda nas definições. A descodificação profunda descodifica de forma recursiva e consegue descodificar mais mensagens quando a banda está cheia, ao custo de mais processamento. Ela também remove os harmónicos de estações muito fortes (as cópias ilegíveis que um sinal saturado deixa em frequências de áudio mais altas) para encontrar estações mais fracas debaixo deles. Fique de olho no espetrograma: se o tempo da descodificação profunda for demasiado alto no seu dispositivo (por exemplo, mais de 1 segundo) e a aplicação não conseguir tomar decisões a tempo, desative a descodificação profunda.

O qFT8 bloqueia ou comporta-se de modo estranho

Se isto só acontece durante a transmissão, provavelmente é RFI extrema, como mencionado acima. Se acontece noutros momentos, desloque-se até ao fim do separador Definições e toque em COMUNICAR ERRO (veja Comunicar um problema), ou use a ligação «Envie-me um e-mail para comunicar problemas e erros».
