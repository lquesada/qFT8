O que é o qFT8?

O qFT8 é um aplicativo de radioamadorismo para celulares e tablets Android, para iOS e para computadores com Windows, macOS e Linux que decodifica e transmite mensagens de dados digitais FT8, FT4, FT2, LQ8, JS8 ou WSPR usando um transceptor. Ele também opera em voz (SSB), código Morse (CW), RTTY e imagens (SSTV) com o mesmo transceptor e o mesmo cabo.

As duas versões funcionam da mesma maneira. Onde elas diferem, este manual avisa ("No Android...", "No computador..."). As capturas de tela mostram o aplicativo para Android, e "tocar" significa tocar na tela no Android ou clicar com o mouse no computador.

Embora o qFT8 ofereça suporte pronto para uso (plug-and-play) para o QMX e o ICOM 7300, você também pode usá-lo com qualquer transceptor colocando o celular ou o computador perto do alto-falante e do microfone com o VOX ativado, ou usando um cabo de áudio. Você também pode simplesmente experimentar o qFT8 sem transceptor: ele transmite pelo alto-falante e escuta os sinais pelo microfone. Vários celulares ou computadores com o qFT8 podem fazer contato entre si por áudio quando estão suficientemente próximos.

O qFT8 é um aplicativo gratuito e sem anúncios. A licença do código-fonte será decidida quando o código-fonte for publicado (LICENSE).

Deixe Configurações > Dispositivo em AUTO: um rádio compatível conectado por USB é reconhecido automaticamente. Você também pode escolher o seu rádio nessa lista.

Nota sobre interfaces externas (Digirig, cabos USB-serial genéricos): a detecção automática (AUTO) foi feita para transceptores com controladores USB nativos ou cabos da própria marca. Com uma interface externa genérica (como a Digirig), a detecção automática só enxerga o chip da interface genérica e usa o modo VOX. Para usar o controle CAT com rádios conectados por interfaces externas (por exemplo, Lab599 TX-500), selecione manualmente o modelo do seu transceptor em Configurações > Dispositivo; a porta serial e a velocidade são ajustadas em Configurações > CONFIGURAÇÃO DO DISPOSITIVO.

Mais dispositivos são compatíveis via VOX, que é uma integração parcial, apenas de áudio.

Nota: por segurança, o qFT8 não permite alterar a potência de transmissão do transceptor. Ajuste a potência manualmente no transceptor.

O qFT8 em um computador (Windows, macOS, Linux)

O qFT8 para computador faz o mesmo trabalho que o qFT8 para Android: os mesmos modos, a mesma operação AUTO e CALL, o mesmo log e os mesmos serviços. Esta seção trata do que é diferente quando você o usa no Windows, no macOS ou no Linux: como instalá-lo, como a janela é organizada, os dois controles deslizantes de volume, como os dispositivos de som e o rádio são escolhidos e como usar o mouse. O restante deste manual vale como está; onde uma parte é diferente no computador, ela avisa ("No computador ...").

Instalação e primeira inicialização

Baixe o arquivo para o seu sistema em qft8.com. Cada download contém uma pasta ou um aplicativo com o programa, a licença e este manual. Não é preciso instalar mais nada: o ambiente Java de que o qFT8 precisa já está incluído.

Você precisa de Windows 10 ou mais novo. Use o arquivo de 32 bits somente em um Windows de 32 bits.
Sistema macOS
Download .dmg, um arquivo para todos os Macs (Apple Silicon e Intel)
Você precisa de macOS 10.13 ou mais novo

O qFT8 precisa de um computador com pelo menos 2 núcleos de processador (4 são recomendados) e espaço para uma janela de pelo menos 960 x 560 pixels. Com 2 núcleos ele funciona, só que mais devagar: veja Computadores lentos.

Windows

  1. Abra o .zip e arraste a pasta qFT8 para um lugar onde você guarda programas, por exemplo a pasta Documentos ou a Área de Trabalho. Não execute o qFT8 de dentro do zip.
  2. Abra a pasta e dê um clique duplo em qFT8.exe.
  3. O Windows pode mostrar "Windows protected your PC" na primeira vez. Pressione More info e depois Run anyway. O qFT8.exe é assinado com o certificado do autor; o Windows demora a passar a confiar em um programa novo.
  4. Se o Windows perguntar se deve permitir que o qFT8 (mostrado como "OpenJDK Platform binary") passe pelo firewall, permita somente em uma rede privada, e somente se você usar o controle remoto web ou a bridge.

macOS

  1. Abra o .dmg e arraste o qFT8 para o atalho Applications na mesma janela. Depois ejete o .dmg.
  2. Inicie o qFT8 a partir de Aplicativos. Se você o iniciar de dentro da janela do .dmg, ou do lugar onde o navegador o colocou, o qFT8 pergunta "Mover o qFT8 para Aplicativos?": pressione MOVER (o macOS pode pedir a sua senha, como faz o Finder) ou AGORA NÃO.
  3. O macOS pergunta uma vez se o qFT8 pode usar o microfone. Pressione Allow: é assim que o qFT8 ouve o rádio. Se você perdeu a pergunta ou recusou, o qFT8 mostra um cartão dizendo que está esperando a permissão do microfone; conceda-a em System Settings > Privacy & Security > Microphone (macOS 13 e mais novo) ou System Preferences > Security & Privacy > Privacy > Microphone (macOS mais antigo) e inicie o qFT8 de novo.

Linux

  1. Descompacte o .tar.gz (tar -xzf qFT8-*.tar.gz, ou pelo seu gerenciador de arquivos). Isso gera uma pasta qFT8.
  2. Execute ./qFT8 nessa pasta (o clique duplo funciona se o seu gerenciador de arquivos executa programas). A primeira inicialização descompacta o programa em ~/.cache/qft8, o que leva alguns segundos; uma versão mais nova substitui a mais antiga ali por conta própria.
  3. A porta serial (CAT) do rádio pertence a um grupo: dialout no Ubuntu, Debian e Fedora, uucp no Arch. A placa de som USB dele pertence a audio. Se a sua conta não estiver no grupo da porta, o qFT8 avisa em um cartão: CORRIGIR adiciona você ao grupo (pede a sua senha) e reinicia o qFT8, de modo que a mudança vale sem sair da sessão. Se isso não funcionar, TENTAR EM UM TERMINAL e COPIAR COMANDO dão o comando para você executar; depois saia da sessão e entre de novo uma vez.

Primeira inicialização

O qFT8 pede o seu indicativo, como no Android (veja Informar o indicativo). Logo depois, abre-se um cartão chamado Configuração do dispositivo: escolha o rádio e depois os dispositivos de som ligados a ele. A cascata sob a entrada mostra o que o rádio está enviando: com o rádio ligado, você deve ver ruído ou sinais. Você pode abrir o mesmo cartão a qualquer momento com o botão à direita da engrenagem na barra inferior, e o selo vermelho Sem áudio na cascata também o abre. Veja Dispositivos de som e a conexão do rádio.

Os layouts de tela e o botão de layout

O botão na extremidade direita da barra inferior é o botão de layout. Cada clique nele muda para o layout seguinte: Flutuante, depois Fixado, depois Tudo em um, e de novo Flutuante. A figura dele mostra o layout em que você está agora (um leitor de tela diz o nome, por exemplo "Layout: Fixado"). O qFT8 lembra o layout para a próxima inicialização, e o tamanho e a posição de cada janela em cada layout separadamente.

  • Tudo em um (o layout em que o qFT8 inicia na primeira vez). Uma janela com quatro partes iguais: o espectrograma no alto à esquerda, a aba Estações no alto à direita, o Mapa mundial embaixo à esquerda e o log de QSOs embaixo à direita, acima da barra inferior. As Configurações são uma coluna alta à direita da mesma janela; o botão de engrenagem da barra inferior a mostra ou oculta, e o X no cabeçalho dela também. A barra inferior não tem botões para as quatro partes: elas estão sempre lá.
  • Fixado (como o aplicativo Android). Uma janela com o espectrograma à esquerda e a aba Estações à direita, acima da barra inferior. Arraste o divisor fino entre eles para dar mais espaço a um (a proporção fica entre 20 % e 80 %). Os botões Log de QSOs, Mapa mundial e Configurações da barra inferior abrem esses três como janelas separadas, e pressioná-los de novo os fecha.
  • Flutuante. A janela principal encolhe até ficar só a barra inferior, e cada painel é uma janela própria que você coloca onde quiser, até em outra tela: Espectrograma, Estações, Log de QSOs, Mapa mundial e Configurações. A barra inferior passa a ter um botão para cada um dos cinco, para abri-los e fechá-los. Use-o para espalhar o qFT8 por dois monitores, ou para manter só o espectrograma e a barra em uma tela pequena.

Mudar o layout só reorganiza as janelas: nada se perde, uma transmissão continua e o TX fica como estava. O Mapa mundial tem um botão de tela cheia (no alto à direita do mapa): ele preenche a tela até você pressionar o botão de novo ou Esc.

Dica: As configurações do Android Orientação, Quadrantes e O aplicativo cobre (veja Layouts de tela) não existem no computador: o botão de layout e o tamanho da janela as substituem.

Trabalhando com as janelas

  • Um programa na barra de tarefas. Seja qual for o layout, o qFT8 tem uma entrada na barra de tarefas, no Dock ou no Alt-Tab: a janela principal. As janelas de painel dos layouts Flutuante e Fixado não têm uma própria. (No Linux isso foi testado com GNOME, KDE Plasma, Xfce, Cinnamon, MATE e LXQt.)
  • As janelas de painel têm a sua própria moldura pequena (igual em todos os sistemas): uma borda fina que redimensiona a janela por qualquer lado ou canto, uma faixa de título com o nome do painel que você arrasta para mover a janela, e um X que fecha o painel como o botão dele na barra inferior. O Esc também fecha uma janela de painel, enquanto ela é a janela ativa.
  • A janela principal pode ser redimensionada e maximizada como de costume. No layout Tudo em um ela não pode ficar menor que 960 x 560 pixels, e na primeira vez abre com 85 % da tela.
  • As Configurações mantêm uma largura. A janela (e a coluna) de Configurações mantém a largura que a página de configurações do Android tem, para que cada linha caiba; você pode mudar a altura dela.
  • Tamanho de tudo. Configurações > APLICATIVO tem os dois controles deslizantes de tamanho (Interface do usuário e escala da fonte e Escala de componentes da interface (sem fonte)) como no Android. Em telas de alta resolução (um Mac Retina, o Windows a 125 % até 200 %) o qFT8 segue a escala do sistema.

Volumes: o dispositivo e o tom

Dois controles deslizantes pequenos ficam na barra inferior, entre o botão Configuração do dispositivo e o botão de layout, um acima do outro. Eles controlam duas coisas diferentes, e ambas importam para transmitir.

  • Controle de cima, com a figura do alto-falante: o volume do dispositivo. É o volume do dispositivo de som pelo qual o qFT8 transmite: a placa de som USB do rádio, ou o alto-falante ou os fones se é para lá que você envia o áudio. É o mesmo nível que o controle de volume do seu sistema mostra para esse dispositivo, e se você mudar um, o outro acompanha (o controle deslizante em alguns segundos).
  • Controle de baixo, com a figura da onda: o volume do tom. É o quanto é alto o áudio de transmissão que o próprio qFT8 gera (os tons do FT8, FT4, WSPR, JS8 e LQ8, o som do TUNE), de 0 a 100 %. Ele é alterado enquanto você transmite: você ouve e vê o resultado na mesma transmissão. Começa em 100 %. Cada rádio lembra o seu próprio volume do tom. O controle remoto web mostra o mesmo controle deslizante e move este.

Como o controle do dispositivo se comporta.

  • Quando o qFT8 inicia, ele lê o volume do dispositivo e o mostra; lê de novo a cada dois segundos, então se você mudar o volume no sistema, o controle acompanha. Se você trocar o dispositivo de saída, o controle mostra o volume do novo dispositivo.
  • O qFT8 só altera o volume do dispositivo quando você move este controle. Ele nunca o define por conta própria antes de uma transmissão. Isso é diferente do Android, onde o qFT8 pode definir o volume do celular com o valor das Configurações quando transmite; no computador essas duas configurações não existem.
  • Depois que você o move, o qFT8 lê o volume de volta, e assim o controle mostra o que o dispositivo realmente aceitou.
  • Um dispositivo sem controle de volume (algumas saídas no macOS) mostra o controle esmaecido e sem botão.
  • Na primeira vez que você transmite ou pressiona TUNE depois de iniciar o qFT8, a figura do alto-falante e o botão do controle do dispositivo passam de cinza para branco e voltam durante cinco segundos, para lembrar que este é o nível que decide com que força o rádio é excitado. Tocar nele interrompe isso.
  • Enquanto você arrasta um controle deslizante, o valor dele em porcentagem aparece ao lado.

Dica: Os dois controles fazem o trabalho do conselho de volume para Android em [Apenas QMX] Verificação de áudio: se o rádio mostrar que o áudio está baixo ou alto demais (os dois pontos do QMX em vez de uma barra), tente primeiro outras posições do controle de volume do dispositivo (por exemplo 70 %, 80 %, 60 %, 100 %), e use o volume do tom para o ajuste fino. Caso contrário, deixe o volume do tom no valor padrão (100 %). O qFT8 nunca define a potência de transmissão do seu rádio: ajuste-a no rádio.

Dispositivos de som e a conexão do rádio

O cartão Configuração do dispositivo

Abra-o com o botão à direita da engrenagem (ele também abre sozinho na primeira inicialização e pelo selo Sem áudio). Ele tem duas metades:

  • O RÁDIO (esquerda): o rádio e a placa de som do próprio rádio: Entrada do dispositivo de rádio (o que o rádio ouve: o que o qFT8 decodifica) e Saída para o dispositivo de rádio (o que o qFT8 transmite), cada uma com a sua taxa de amostragem, bits e canais. Deixe-os no padrão do sistema, a menos que o rádio precise de outra coisa. Uma pequena cascata ao vivo sob a entrada mostra se o som está chegando.
  • VOCÊ (O OPERADOR) (direita): o seu próprio microfone e os seus próprios alto-falantes ou fones, para SSB e CW (veja Alto-falantes e microfone, que é a mesma coisa), o botão TESTAR e a opção Tocar o som do rádio no alto-falante nos modos digitais. Estes nunca devem ser a placa de som do rádio.

As mesmas escolhas, e mais (tamanhos de buffer, o aviso de falhas), estão em Configurações > CONFIGURAÇÃO DO DISPOSITIVO. As linhas do Android "Sistema de áudio" e "Fonte de entrada de áudio" não existem no computador. Deixe os dispositivos em AUTO: ele prefere a placa de som do próprio rádio para o rádio e, para você, um dispositivo que não seja o do rádio.

Avisos que você pode ver

  • Saída para o rádio (selo): a saída de som padrão do seu computador é a placa de som do rádio, então os sons do sistema, o navegador e os alertas entram no rádio e poderiam ir ao ar se ele transmitir por VOX ou pela entrada de dados. O qFT8 oferece usar outra saída (USAR ...), abrir as configurações de som ou parar de perguntar. O áudio de transmissão do qFT8 também segue a saída padrão: escolha primeiro a placa de som do rádio como saída do qFT8 e depois mude o padrão do computador.
  • Sem entrada do rádio (selo, Linux): a placa de som do rádio não tem entrada no sistema de som porque está em um perfil só de saída. LER O RÁDIO DIRETAMENTE (recomendado) deixa o qFT8 ler a placa por conta própria; MUDAR PARA PRO AUDIO muda o perfil da placa para todos os programas.
  • Sem dispositivos de entrada: o sistema não oferece entrada; conecte o rádio ou uma placa de som e verifique se ela aparece como entrada nas configurações de som do computador.
  • O driver USB do rádio não está instalado (Windows e macOS): o Icom IC-7300 e outros rádios com um chip USB da Silicon Labs podem precisar do driver CP210x. Baixe-o na página de drivers do fabricante, instale-o e conecte o rádio de novo.
  • Outro rádio? (selo): o rádio conectado não é o escolhido no qFT8.

Por sistema

  • Windows: o qFT8 ouve o rádio pelo mecanismo de áudio do próprio Windows (WASAPI), que dá um fluxo mais estável que o modo antigo. O rádio aparece como uma porta COM (COM3, ...) e um dispositivo de som "USB Audio CODEC" ou parecido. O Windows deixa só um programa usar uma porta COM: se o qFT8 disser que o acesso foi negado, feche o outro programa (um logger, um programa de modos digitais, o software do próprio rádio) e pressione REPETIR.
  • macOS: a porta do rádio se parece com /dev/cu.usbmodem... (um QMX) ou /dev/cu.SLAB_USBtoUART (um IC-7300). O macOS não precisa de grupo nem de permissão para a porta, só da permissão de microfone acima. Se uma porta for recusada, outro programa a mantém aberta.
  • Linux: a porta se parece com /dev/ttyACM0 ou /dev/ttyUSB0 e precisa do grupo acima. Os dispositivos de som são os do servidor de som (PulseAudio ou PipeWire), de modo que o alto-falante do rádio, os seus fones e o seu microfone podem ser, cada um, um dispositivo diferente. O controle de volume do dispositivo usa o pactl, do pacote pulseaudio-utils (funciona também com o PipeWire).

Escolhendo o rádio e a sua porta

Como no Android, deixe Configurações > Dispositivo em AUTO: um rádio compatível é reconhecido quando é conectado. Para um rádio atrás de uma interface USB-serial genérica (um Digirig, por exemplo), escolha o rádio manualmente e depois a porta dele em Configurações > CONFIGURAÇÃO DO DISPOSITIVO > Configurações da porta de comunicação > Dispositivo USB; taxa de transmissão (baud), bits de dados, bits de parada, paridade e o método de acionamento (DTR, RTS ou CAT) também estão ali, definidos pelo qFT8 para o rádio escolhido, a menos que você marque Permitir substituir as configurações. Rádios que só usam som (VOX) não precisam de porta nenhuma. A linha de comando pode listar as portas e os dispositivos de som que o qFT8 vê.

O qFT8 guarda tudo o que armazena em uma pasta, a pasta de perfil: configurações, senhas, o log de QSOs, backups e imagens.

Levando as suas configurações de um celular (ou para um)

EXPORTAR CONFIGURAÇÕES e IMPORTAR CONFIGURAÇÕES, na página principal de Configurações (sob Arquivos de configurações), criam e leem um arquivo que é o mesmo no Android e no computador. Exporte no celular, copie o arquivo para o computador (e-mail, nuvem, cabo) e importe-o lá; o caminho inverso também funciona.

Computadores lentos

Configurações > APLICATIVO > Modo de dispositivo lento / bateria fraca deixa o qFT8 mais leve: cerca de 30 imagens por segundo, a cascata redesenhada com menos frequência e o mapa mundial trabalhando só enquanto é exibido. Ele muda apenas o que é desenhado, nunca o decodificador: o qFT8 decodifica igual com ele ligado ou desligado.

O modo lento só liga quando você marca a caixa dele, nunca por conta própria. Em um computador com um ou dois núcleos de processador, o qFT8 pergunta ao iniciar se deve ligá-lo: ATIVAR MODO LENTO marca a caixa, DISPENSAR pergunta de novo na próxima inicialização e NÃO PERGUNTAR DE NOVO para de perguntar. Em um computador assim o qFT8 também dá ao decodificador, por conta própria, uma parte justa do processador, com ou sem o modo lento, para que outro programa ocupado não o deixe sem recursos.

Atualizações e desinstalação

Atualizações

Com Procurar novas versões ao iniciar marcado (o padrão; veja Procurar novas versões ao iniciar), o qFT8 pergunta uma vez por dia se existe uma versão mais nova e mostra Há uma nova versão disponível com DISPENSAR e BAIXAR AGORA, que abre a página de download no seu navegador. O qFT8 nunca se atualiza sozinho. Para atualizar, baixe o arquivo novo e substitua o programa antigo:

  • Windows: feche o qFT8 e substitua a pasta qFT8 (ou só o qFT8.exe) pela nova.
  • macOS: feche o qFT8, arraste o novo qFT8 para Aplicativos e escolha Replace.
  • Linux: feche o qFT8 e execute o novo qFT8. Ele se descompacta sozinho e remove a versão antiga do cache.

As suas configurações e o seu log ficam na pasta de perfil.

Desinstalação

Feche o qFT8 e apague o programa: a pasta qFT8 (Windows, Linux) ou o qFT8 em Aplicativos (macOS); no Linux também ~/.cache/qft8. Isso mantém as suas configurações e o seu log. Para removê-los também, apague a pasta de perfil (acima). Isso apaga o seu log de QSOs: exporte-o antes com o ADIF.

Se algo não funciona

  • A cascata está vazia e o selo diz Sem áudio. Abra Configuração do dispositivo: a placa de som do rádio é a entrada, e o rádio está ligado? No macOS verifique a permissão do microfone; no Linux o selo Sem entrada do rádio e os grupos.
  • O rádio recebe mas não transmite, o TUNE não aciona nada. A porta foi recusada: outro programa a mantém (Windows, macOS) ou a sua conta não está no grupo (Linux). O qFT8 diz qual; feche o outro programa e pressione REPETIR, ou siga o cartão do Linux. Veja também O celular ou o computador não reconhece o transceptor ou ele é desconectado.
  • O rádio está baixo demais, alto demais ou mostra dois pontos em vez de uma barra (QMX): mova o controle de volume do dispositivo (Volumes). Verifique se o volume do próprio computador para esse dispositivo não está sem som.
  • Sons do computador são ouvidos no ar. A saída padrão é a placa de som do rádio: responda ao selo Saída para o rádio ou escolha outra saída padrão no seu sistema.
  • "Já em execução". Outra cópia usa a pasta de perfil. Feche-a, ou inicie esta com uma pasta --qft8_profile própria.
  • A janela está preta ou embaralhada (drivers gráficos antigos, uma máquina virtual, área de trabalho remota): atualize o driver gráfico. Se continuar, inicie o qFT8 com --opengl (qFT8 --opengl), que desenha a janela de outro modo; se isso também não ajudar, relate com RELATAR ERRO (Configurações), dizendo qual sistema e qual placa gráfica você tem.
  • Uma janela está fora da tela (um monitor foi desconectado): o qFT8 confere a posição salva de cada janela quando a abre, e uma cujo monitor sumiu, ou que ficaria em grande parte fora da tela, abre no meio da tela principal. Se uma janela continuar fora de alcance, feche o painel dela com o botão da barra inferior e abra de novo, ou reinicie o qFT8.
  • Cascata congelada, falhas de áudio ou carga alta em um computador de um ou dois núcleos: veja Computadores lentos, feche outros programas e envie um relatório com RELATAR ERRO se continuar.

qFT8 no iPhone e no iPad

O qFT8 para iPhone e iPad funciona como o qFT8 para Android, e o restante deste manual vale para ele; ele precisa do iOS 17 ou mais recente. O que muda é como ele chega ao rádio.

Um iPhone ou iPad não consegue controlar um rádio por cabo: não há CAT, então o qFT8 não consegue ajustar a frequência do rádio nem colocá-lo em transmissão pelo USB. Ele ouve o rádio e envia seus tons pela interface de som USB do rádio, outra interface de áudio ou um cabo de áudio. Para o rádio transmitir, use uma destas opções:

  • O VOX do rádio: o rádio entra em transmissão sozinho quando os tons do qFT8 chegam a ele. Escolha VOX nas configurações do qFT8.
  • Uma interface de áudio que aciona o rádio pelo próprio áudio: ela coloca o rádio em transmissão sempre que sai som do qFT8.
  • qFT8 bridge: um computador, um Raspberry Pi ou um celular ou tablet Android ao lado do rádio, com o rádio ligado a ele por USB. O qFT8 no iPhone ou iPad então controla o rádio pela sua própria rede como se estivesse ligado, incluindo frequência e transmissão. Um computador sem outra função, também um servidor sem tela, pode rodar o bridge pela linha de comando, sem janela.

Configuração rápida

Certifique-se de usar a fonte de alimentação correta para o transceptor (por exemplo, ≤12V para um QMX), ou você irá danificá-lo.

Certifique-se também de que o cabo USB e o adaptador que você usa para ligar o celular ou o computador ao transceptor sejam próprios para transferência de dados. No Android, para dispositivos com conectores diferentes de USB-C, muitas vezes é necessário um cabo OTG (on-the-go) específico. A maioria dos problemas de conexão em que o qFT8 não enxerga o transceptor se deve ao uso de um cabo ou adaptador incompatível.

No Android, alguns dispositivos vêm com o USB OTG desativado por padrão. Ele precisa ser ativado nas configurações do dispositivo (a opção pode estar escondida nas configurações avançadas, do sistema ou adicionais). Se você tiver problemas de conexão — em especial, se consegue receber sinais no qFT8, mas não transmitir, e os comandos CAT não funcionam mesmo com um dispositivo totalmente compatível (mostrado na lista de dispositivos, reconhecido automaticamente no modo AUTO etc.) —, é muito provável que esta seja a causa.

Conceder permissões iniciais

No Android, ao ser aberto pela primeira vez, o qFT8 pede várias permissões:

  • Permitir que o qFT8 grave áudio: esta permissão é obrigatória. O qFT8 precisa dela para captar os sinais do transceptor. O qFT8 não armazena, não compartilha e não envia nenhuma gravação de áudio.
  • Permitir que o qFT8 acesse a localização aproximada deste dispositivo: opcional, mas recomendada. O qFT8 a usa para obter seu grid locator Maidenhead, que é compartilhado durante as trocas em FT8. O qFT8 não acessa nem compartilha dados de localização precisa.
  • Permitir que o qFT8 envie notificações: opcional, mas recomendada. O qFT8 a usa para funcionar como serviço em primeiro plano, minimizado ou com a tela desligada, para economizar bateria. As notificações só ficam ativas quando há um transceptor conectado.
  • Permitir que o app sempre seja executado em segundo plano: opcional, mas recomendada. Necessária para o qFT8 funcionar de forma estável com a tela desligada.

No computador há menos permissões. No macOS, o sistema pergunta uma vez se o qFT8 pode usar o microfone: permita, pois é assim que o qFT8 ouve o transceptor. No Linux, para usar a porta serial (CAT) do rádio a sua conta precisa estar no grupo da porta (normalmente dialout); se não estiver, o qFT8 explica isso e se oferece para corrigir.

Princípio fundamental: o qFT8 não envia nenhuma informação a um servidor dedicado a este aplicativo. Todo o processamento de dados acontece localmente no seu dispositivo. Você pode autorizar explicitamente o compartilhamento do indicativo, da data e hora e, opcionalmente, da localização aproximada, se informar uma Chave de API do QRZ válida.

[Apenas QMX] Verificação de áudio

Antes de começar a operar, é importante verificar se o sinal de áudio entre o seu celular ou computador e o QMX está funcionando corretamente. Pressione o botão TX e espere o QMX começar a transmitir em uma das próximas sequências.

Tudo funcionando

Se o botão TX mostrar a potência de saída (por exemplo, 5W), tudo está funcionando corretamente. No LCD do QMX, você deve ver uma barra sob o marcador de VFO "A", no canto superior esquerdo da tela — isso significa que o QMX está recebendo um bom sinal de áudio do qFT8. Confirme também que não aparece um "S" depois da frequência no LCD, o que indicaria a proteção de SWR.

"S" depois da frequência

Se o LCD do QMX mostrar um "S" depois da frequência, a proteção de SWR foi acionada. Sua antena não está bem ajustada para a banda atual. Você pode usar a opção de verificação de SWR no menu do QMX para medir a SWR, e precisará ajustar a antena.

  • Firmware 1_04_004+: o qFT8 reinicia automaticamente a proteção de SWR ao final do ciclo.
  • Firmware 1_03_000+: você pode definir "SWR Protection reset options" como TX->RX no menu Protection do QMX, para que ela se reinicie automaticamente.
  • Firmware antigo (anterior a 1_03_000): é preciso entrar e sair do menu TUNE do QMX, ou desligá-lo e ligá-lo, para reiniciar a proteção de SWR.

Dois pontos em vez de uma barra

Se o QMX mostrar dois pontos em vez de uma barra sob o marcador de VFO "A", no canto superior esquerdo da tela, o volume do áudio está baixo demais ou alto demais.

Experimente: vá às Configurações do qFT8, encontre a opção "Definir o volume do sistema para [X] ao usar o rádio" e experimente valores diferentes (por exemplo, 70%, 80%, 60%, 100%). Um deles deve transformar os dois pontos em uma barra.

Em alguns celulares esta opção pode não funcionar. Nesse caso, desmarque-a e ajuste manualmente o volume do celular para valores diferentes (100%, 90%, 80% etc.) até a barra aparecer.

Além disso, a corrente de modo comum pode estar afetando o comportamento do QMX, e acrescentar um choke de modo comum à antena também pode ajudar nos problemas de áudio.

Nada sob o "A"

Se não houver barra nem pontos sob o marcador de VFO "A", no canto superior esquerdo do LCD do QMX, o qFT8 pode não estar controlando o transceptor corretamente. Em geral isso significa que as permissões de USB não foram concedidas ou foram dispensadas sem querer. A recepção funciona, mas a transmissão não.

Experimente: Desconecte o QMX e conecte-o novamente — no Android, a caixa de diálogo de permissão deve aparecer de novo. Também pode ser que o cabo não seja adequado para o QMX; experimente outro cabo USB-C.

Quando você vir uma barra sob o marcador de VFO "A", no canto superior esquerdo do LCD do QMX, e a potência de saída no botão TX, seu QMX estará bem configurado e pronto para operar!

Seu primeiro QSO com o qFT8

Nota: a hora exata é fundamental para o FT8. O qFT8 sincroniza a hora automaticamente ao iniciar, por NTP (internet) ou GPS (satélites). Se você estiver operando em campo, sem acesso à internet, pode usar o botão SINCR. GPS na aba Configurações para sincronizar o relógio diretamente pelos satélites GPS. Isso requer a permissão de localização precisa e céu aberto.

Neste ponto, o transceptor deve estar conectado à fonte de alimentação correta e à antena, e todas as permissões devem estar concedidas. Verifique se a antena está ajustada para uma banda com uma SWR razoável (de preferência sempre abaixo de 2), que não acione as proteções de SWR. É má ideia desativar a proteção de SWR do QMX; isso pode danificar os transistores finais ou o acoplador de antena.

Agora você pode escolher a banda que quer usar na barra inferior do qFT8 ou no transceptor. Ao escolher em um deles, o outro acompanha.

Neste ponto, o espectrograma mostra sinais e começa a decodificar mensagens, e a aba Estações vai sendo atualizada com as estações que você está ouvindo.

Pressionar o botão TX (o botão mais à esquerda da barra inferior) ativa a transmissão.

Se tudo estiver certo, o botão TX acabará acendendo com "TX Transmitting" e mostrará a potência de transmissão e a SWR (por exemplo, "5.0W SWR 1.2").

Como o modo "AUTO" vem selecionado por padrão, o qFT8 começa a fazer QSOs e a registrá-los na aba Log de QSOs.

Você pode tocar no espectrograma para mudar o desvio de frequência de Tx (além disso, tocar na parte de cima do espectrograma, onde ficam os indicadores de pico, permite digitar uma frequência), pode mudar de sequência tocando nos botões 0 e 1 da barra inferior, pode tocar nos vários botões "CALL" para chamar estações específicas, ou pode ajustar a barra do botão "AUTO" na aba Estações para definir a estratégia. As próximas seções trazem mais detalhes sobre todos esses recursos avançados.

Note que o qFT8 começa chamando estações ou, se nenhuma estiver ao alcance, chamando CQ. Com tudo bem configurado e boa propagação, o qFT8 acabará fazendo QSOs.

Se o qFT8 não está recebendo sinais adequados e não decodifica mensagens, é um sinal claro de que algo está errado: a propagação nessa banda pode estar fechada, a antena pode não estar bem sintonizada, a antena pode não estar bem conectada ao transceptor, o transceptor pode não estar bem conectado ao celular ou ao computador, ou algum dos seus equipamentos pode não estar funcionando corretamente. Introdução aos modos digitais

Os modos digitais de radioamador codificam texto e dados em tons de áudio com modulação por deslocamento de frequência (FSK), transmitidos em banda lateral única (SSB). Combinando larguras de banda estreitas, correção de erros avançada (FEC) e sincronização de tempo rigorosa, os modos digitais permitem comunicações confiáveis com o mundo todo, mesmo com sinais muito abaixo do ruído audível. O qFT8 opera os principais modos digitais modernos — FT8, FT4, FT2, JS8, WSPR e LQ8 —, cada um criado para um objetivo diferente, desde beacons de propagação com sinais ultrafracos até contests rápidos e conversas de teclado a teclado.

FT8

O FT8 (projeto de Franke e Taylor, 8-GFSK) é o protocolo digital para sinais fracos mais usado no mundo, criado para condições difíceis em HF/VHF, esporádica-E com vários saltos e bandas congestionadas. Ele funciona com mensagens estruturadas, sincronização de tempo precisa em ciclos de 15 segundos e correção de erros robusta.

Ciclos e sequências

O FT8 funciona em ciclos de 15 segundos. Cada ciclo de comunicação tem horário rígido e começa exatamente aos 00, 15, 30 e 45 segundos de cada minuto. Por isso, o relógio do seu dispositivo precisa estar sincronizado com precisão com a hora UTC.

Há duas sequências no protocolo:

  • Sequência 0 (par): ciclos que começam aos 00 e 30 segundos.
  • Sequência 1 (ímpar): ciclos que começam aos 15 e 45 segundos.

Em geral, as estações alternam entre transmitir e receber. Uma estação que transmite na sequência 0 escuta a resposta na sequência 1, e vice-versa. Dentro de cada ciclo de 15 segundos, a mensagem é transmitida em uma janela entre aproximadamente +0,5s e +13s. Isso deixa tempo no fim do ciclo para a decodificação e no início para preparar a próxima transmissão.

Características do sinal

Cada mensagem FT8 é transmitida como uma sequência de tons com pequenas variações de frequência (às vezes descritas como um "ziguezague"). Um sinal FT8 é muito estreito e ocupa apenas cerca de 50Hz de largura de banda. Essa eficiência permite que dezenas de conversas simultâneas caibam em uma única faixa de 3kHz.

As 6 etapas de um QSO

Um contato FT8 padrão costuma passar por seis etapas. Veja um exemplo de troca entre HB9IPH e XX1XXX:

  1. 1/6 CQ: uma estação procura alguém para contatar.
    Exemplo: CQ HB9IPH JN47
    Nota: JN47 é um grid locator Maidenhead, que indica a localização geográfica aproximada da estação. Também pode haver um modificador de CQ, que é um aviso para os outros operadores (por exemplo, CQ SOTA HB9IPH para o programa Summits On The Air, ou CQ US HB9IPH para quem quer contatar alguém nos EUA). O modificador e a localização podem não caber juntos na mesma mensagem; nesse caso, a localização é omitida. Se o indicativo for muito longo, pode ser que nem a localização nem o modificador caibam no CQ!
  2. 2/6 CALL: outra estação responde ao CQ.
    Exemplo: HB9IPH XX1XXX JO21
    Nota: quem responde também informa sua localização (JO21), que pode ser omitida se os indicativos forem longos demais para caber tudo.
  3. 3/6 RPT: a primeira estação envia um reporte de sinal.
    Exemplo: XX1XXX HB9IPH -10
    Nota: o reporte de sinal (por exemplo, -10) indica a intensidade do sinal em relação ao piso de ruído, em dB.
  4. 4/6 RRPT: a segunda estação confirma o reporte e envia o seu.
    Exemplo: HB9IPH XX1XXX R-12
    Nota: o prefixo "R" confirma que o reporte anterior foi recebido, e é seguido pelo reporte de sinal para a primeira estação.
  5. 5/6 RR73: a primeira estação confirma tudo e envia um "Roger-Roger 73".
    Exemplo: XX1XXX HB9IPH RR73
  6. 6/6 73: a segunda estação envia um "73" final para encerrar o contato.
    Exemplo: HB9IPH XX1XXX 73

Por causa do problema dos dois generais, é teoricamente impossível ter certeza de que a outra estação recebeu sua última comunicação, a menos que ela confirme. Mas então você teria de confirmar a confirmação dela, ela teria de confirmar a sua, e assim por diante. O modo digital FT8 contorna isso com etapas estruturadas: tecnicamente, um QSO pode ser considerado completo depois da etapa 4/6 (quando os dois reportes de sinal foram trocados). Na prática, para garantir que as duas estações concordem que a troca aconteceu, um QSO é registrado quando uma estação recebeu um RR73 e enviou um 73. Ou seja, transmitir um RR73 ou um 73 dispara o registro do QSO.

Note que uma estação também pode chamar outra que não transmitiu um CQ antes. Por exemplo, estações em lugares raros podem ter um "pile-up" de muitas estações chamando ao mesmo tempo; nesses casos, a estação rara pode simplesmente passar de um QSO para o seguinte, sem precisar convidar novas chamadas com um CQ.

Algumas estações usam RRR em vez de RR73 na etapa 5. Nesse caso, o contato exige uma troca a mais: a segunda estação envia 73, e a primeira envia 73 de novo para terminar.

O FT8 também permite mensagens de texto livre (até 13 caracteres), mas o qFT8 ainda não envia essas mensagens personalizadas.

Limitações do protocolo e alternativas

As mensagens FT8 são fortemente compactadas em 77 bits. Às vezes, informações complexas (como indicativos longos e não padrão) não cabem no formato padrão de mensagem.

  • Indicativos com hash: se um indicativo é longo demais, ele pode ser enviado como um hash. Se a estação que recebe viu esse indicativo chamando CQ recentemente, o programa dela consegue ligar o hash ao indicativo original. Caso contrário, ele aparece como <...>. É muito mais difícil fazer QSOs quando seu indicativo não é padrão.
  • Recurso ao texto livre: algumas mensagens podem ser forçadas ao formato de texto livre de 13 caracteres, que é menos robusto que as mensagens estruturadas padrão.
  • Indicativos não padrão: se duas estações usam ambas indicativos muito longos e não padrão, pode ser simplesmente impossível que se comuniquem entre si no modo digital FT8.
  • Etapas puladas: se os indicativos são longos demais, o protocolo pode não conseguir encaixar os reportes de sinal (etapas 3/6 e 4/6). Nesses casos, a troca pode pular direto do CALL (2/6) inicial para as confirmações finais (5/6 e 6/6).

Mensagens que você verá, mas nunca enviará

Algumas estações enviam formatos de mensagem que o qFT8 mostra, mas não envia:

  • Uma mensagem para duas estações: uma expedição que trabalha muitas estações ao mesmo tempo pode encerrar um QSO e começar o seguinte em uma única transmissão: K1ABC RR73; W9XYZ <VP8XYZ> -08. Significa "K1ABC, seu QSO está completo" e "W9XYZ, seu reporte é -08", ambos de VP8XYZ. O qFT8 mostra a mensagem como foi enviada, na lista de estações e uma única vez na cascata. Se você é uma das duas estações, ela vale como o seu RR73 ou como o seu reporte, exatamente como se a expedição a tivesse enviado só para você, e o QSO continua ou é registrado como de costume. Se você não é nenhuma das duas, não há nada a fazer, e o AUTO não faz nada com ela.
  • Trocas de contest: em alguns contests as estações enviam uma classe e uma seção (Field Day) ou um reporte com um estado ou um número de série (contests de RTTY) em vez de um locator e um reporte. O qFT8 mostra essas mensagens para que você veja o que há na banda, e nunca responde a elas: ele não envia trocas de contest.

Especificações: S. Franke, B. Somerville, J. Taylor, “The FT4 and FT8 Communication Protocols”, QEX, July/August 2020.

FT4

O FT4 é um modo digital enxuto, criado especificamente para contests de radioamador, nos quais concluir contatos depressa é essencial:

  • O dobro da velocidade: funciona em ciclos de 7,5 segundos (duas vezes mais rápido que o FT8) e transmite por cerca de 4,48 segundos, com quatro intervalos de transmissão por minuto.
  • O dobro da largura de banda: ocupa cerca de 90 Hz de largura de banda de RF (aproximadamente o dobro dos ~50 Hz do FT8).
  • Perda de sensibilidade: em troca do dobro da vazão, o FT4 tem um limiar de decodificação de cerca de -16,4 dB a -17,5 dB de SNR (uma perda de sensibilidade de uns 3,5 a 4 dB em relação ao FT8).
  • Uso na prática: usa modulação 4-GFSK e a mesma carga estruturada de 77 bits, o que permite concluir as trocas padrão de contest na metade do tempo quando a propagação ajuda.

Especificações: S. Franke, B. Somerville, J. Taylor, “The FT4 and FT8 Communication Protocols”, QEX, July/August 2020.

FT2

O FT2 foi criado para trocas ultrarrápidas com sinais favoráveis, rajadas de meteor scatter em VHF/UHF e contests de ritmo alto:

  • O dobro da velocidade do FT4 (4x FT8): funciona em ciclos de 3,75 segundos, com cerca de 2,24 segundos de transmissão, o que permite até 16 ciclos por minuto.
  • O dobro da largura de banda do FT4 (4x FT8): ocupa cerca de 180 Hz de largura de banda de RF (o dobro do FT4 e quase quatro vezes a do FT8).
  • Perda adicional de sensibilidade: tem um limiar de decodificação de cerca de -13 dB a -14 dB de SNR (uma perda adicional de ~3 dB em relação ao FT4, ou ~6 a 7 dB menos sensível que o FT8).
  • Uso na prática: ideal para contatos em rajada durante aberturas com sinais fortes e em modos de propagação por rajadas, em que as janelas de contato são momentâneas e os sinais estão bem acima do piso de ruído.

Especificações: nenhuma especificação publicada.

JS8

O JS8 (projeto de Jordan Sherer, 8-GFSK) foi criado para bate-papo, conversa de teclado a teclado e redes ad hoc, e não para trocas estruturadas de contest:

  • Divisão e remontagem de mensagens: usa a mesma modulação 8-GFSK do FT8, mas os quadros levam 75 bits, e uma camada de transporte corta a mensagem em quadros e a remonta. Mensagens de texto livre de qualquer tamanho fluem por intervalos de tempo consecutivos.
  • Vários modos de velocidade: cinco velocidades para acompanhar as condições da banda:
    • Slow: ciclos de 30 segundos, ~25 Hz de largura de banda, decodifica até -25 dB de SNR.
    • Normal: ciclos de 15 segundos, ~50 Hz de largura de banda, decodifica até -21 dB de SNR.
    • Fast: ciclos de 10 segundos, ~80 Hz de largura de banda, decodifica até -18 dB de SNR.
    • Turbo: ciclos de 6 segundos, ~160 Hz de largura de banda, decodifica até -15 dB de SNR.
    • Ultra: ciclos de 4 segundos, ~250 Hz de largura de banda, só para sinais fortes.
  • Recursos de rede: mensagens para uma estação ou para um grupo, perguntas padrão respondidas automaticamente e heartbeats. O qFT8 mostra mensagens retransmitidas, mas não retransmite nem guarda mensagens para outras estações (veja JS8 (chat de teclado)).

Especificações: nenhuma especificação publicada.

WSPR

O WSPR (Weak Signal Propagation Reporter) foi criado exclusivamente para sondar caminhos de propagação e funcionar como beacon automático, e não para QSOs bidirecionais de conversa:

  • Ciclos de dois minutos: funciona em ciclos de 2 minutos (120 segundos) rigorosamente sincronizados e transmite uma sequência de tons 4-FSK de 162 símbolos ao longo de 110,6 segundos.
  • Largura de banda ultraestreita: ocupa apenas cerca de 6 Hz de largura de banda de RF, concentrando a potência irradiada em uma fatia excepcionalmente compacta do espectro.
  • Sensibilidade extrema a sinais fracos: consegue decodificar sinais tão fracos quanto -28 dB a -31 dB de SNR em uma largura de banda de referência padrão de 2,5 kHz, o que permite a transmissores de miliwatts (QRPp) cobrir distâncias globais.
  • Reportes automáticos de propagação: transmite o indicativo da estação, o grid locator Maidenhead (4 ou 6 caracteres) e a potência do transmissor em dBm. Os spots decodificados podem ser enviados ao banco de dados mundial WSPRnet, que mapeia a propagação em tempo real (veja Spots para o WSPRnet e o PSKReporter).

Especificações: J. Taylor (K1JT), “WSPRing Around the World”, QST, November 2010.

LQ8

O LQ8 é um modo digital avançado para sinais fracos desenvolvido por Luis Quesada (HB9IPH), autor e criador do qFT8:

  • QSOs mais rápidos, mesma sensibilidade: O LQ8 mantém o limiar de sinal fraco do FT8, -21 dB SNR, e completa um contato confirmado em 4 transmissões (60 segundos), enquanto o FT8 precisa de 5 ou 6 (75 a 90 segundos). As duas estações continuam trocando indicativos, localizadores e reportes de sinal.
  • Troca de quatro mensagens: CQ, depois CALL (o localizador e o reporte da estação que responde em uma só mensagem), depois REPORT+73 (o reporte e a confirmação em uma só mensagem) e depois 73; não há uma etapa RR73 separada. Em pileups, MULTI-REPORT+73 confirma duas estações ao mesmo tempo em uma única portadora, e MULTI-73 encerra com as duas.
  • Arquitetura moderna: Ciclos de 15 segundos, modulação 8-GFSK com 79 símbolos em 12,64 segundos (50 Hz de largura de banda), mensagens de 77 bits cujo tipo é codificado com prefixos de comprimento variável (Huffman), CRC de 14 bits e correção de erros LDPC(174,91). Seu próprio padrão de sincronismo impede que LQ8 e FT8 decodifiquem um ao outro.

Especificações: L. Quesada (HB9IPH), “The LQ Digital Mode Family: Protocol Architecture and Reference Specification for Weak-Signal Communications”, arXiv:2609.06427 (2026); biblioteca de referência: lq_lib.

Para mais informações, especificações e ferramentas, visite https://lq8.org, o portal dos modos LQ.

Q65

Q65 é um modo de QSO com sinais fracos para trajetos difíceis: espalhamento ionosférico e troposférico em 6 m e 2 m, e reflexão lunar (EME) a partir de 2 m. No qFT8 ele é experimental:

  • Submodos: Cada submodo é um período (15, 30, 60, 120 ou 300 segundos) e um espaçamento de tons (A a E), escrito como 30A ou 60C. Períodos mais longos são mais sensíveis; espaçamentos maiores lidam melhor com sinais borrados pelo espalhamento ou pela Lua. As duas estações precisam usar o mesmo submodo.
  • As mesmas mensagens do FT8: Q65 leva as mesmas mensagens de 77 bits, então um QSO tem as mesmas seis etapas do FT8.
  • Média: Transmissões repetidas, fracas demais para decodificar uma a uma, podem ser somadas até serem decodificadas.

O seletor de submodo, as bandas e todas as opções estão descritos em Configurações > Q65; a lista de estações no Q65 está descrita em A aba Estações.

MSK144

MSK144 é feito para espalhamento meteórico em 10 m, 6 m, 2 m e 70 cm. No qFT8 ele é experimental:

  • Pings: O rastro de um meteoro reflete o sinal só por um instante. Uma transmissão repete sua mensagem durante todo o período, e qualquer ping longo o bastante para levar uma cópia dela é decodificado.
  • Períodos: 5, 10, 15 ou 30 segundos; 15 segundos é a escolha usual.
  • Sempre em 1500 Hz: Todas as estações transmitem em 1500 Hz de áudio, com tons em 1000 e 2000 Hz.
  • Mensagens curtas: Reportes, RRR e 73 podem ser enviados como mensagens curtas, que cabem em um ping bem mais breve.

As opções estão descritas em Configurações > MSK144; a lista de estações no MSK144 está descrita em A aba Estações.

FST4

FST4 é um modo de QSO com sinais fracos para as bandas baixas (2200 m, 630 m, 160 m) e para HF quando os sinais são muito fracos. No qFT8 ele é experimental:

  • Períodos: 15, 30, 60, 120, 300, 900 ou 1800 segundos. Quanto mais longo o período, mais estreito e sensível o sinal: de cerca de -21 dB em 15 segundos a cerca de -43 dB em 1800 segundos.
  • As mesmas mensagens do FT8: FST4 leva as mesmas mensagens de 77 bits, então um QSO tem as mesmas seis etapas do FT8, só que muito mais devagar.

As opções estão descritas em Configurações > FST4; a lista de estações no FST4 está descrita em A aba Estações. Seu modo de beacon, FST4W, funciona como o WSPR.

Interface do usuário do qFT8

O aplicativo qFT8 se divide em três partes:

  1. A barra inferior: sempre visível, para acompanhar e controlar a transmissão e para controlar o qFT8.
  2. O espectrograma: sempre visível, para ver as mensagens decodificadas, a hora UTC ao vivo e a frequência sintonizada, e para controlar o desvio de frequência de transmissão.
  3. A área das abas: mostra uma das quatro abas (Estações, Log de QSOs, Mapa mundial e Configurações). Os botões da parte direita da barra inferior escolhem qual delas aparece.

As seções a seguir descrevem todos esses componentes em detalhes.

A barra inferior

A barra inferior mostra informações importantes: se a transmissão está armada ou desarmada, se o qFT8 está transmitindo, a potência de transmissão, a relação de ondas estacionárias (SWR), a mensagem que está sendo transmitida, a sequência atual e a selecionada, o seletor de banda e os botões para navegar entre as abas.

Estes são os componentes da barra inferior, em detalhes:

  1. A barra de progresso do ciclo: a barra amarela começa em 0s do ciclo (extrema esquerda) e termina em 15s do ciclo (extrema direita).
  2. O marcador de início do Tx: o ponto vermelho na parte esquerda da barra indica o momento de início do Tx. Se o Tx está ON (veja o item 4) e a sequência atual é a selecionada (veja o item 6), a transmissão começa nesse ponto.
  3. O marcador do momento de decodificação: o ponto branco na parte direita da barra indica o momento da decodificação, isto é, quando as mensagens são decodificadas a partir dos sinais recebidos e depois processadas.
  4. O botão TX: pode estar desarmado (OFF) ou armado (ON). Também mostra quando há transmissão, a potência de transmissão e a SWR. Com firmwares do QMX acima de 1_04, este botão mostra "HOLD: TUNE". Manter o botão pressionado ativa o modo de sintonia e mostra a SWR ao vivo.
  5. O seletor de mensagem: mostra a mensagem selecionada para envio ou em envio (nesse caso, destacada em amarelo). No modo AUTO, ele é controlado automaticamente. No modo CALL, por padrão também é automático, mas você pode tocar nele para escolher manualmente a próxima mensagem a enviar.
  6. O seletor de sequência: a linha amarela acima dos botões mostra a sequência atual (0 ou 1). Tocar em 0 ou 1 seleciona essa sequência para as suas transmissões.
  7. O seletor de modo: muda o modo de transmissão usado (por exemplo, FT8, FT4, FT2, LQ8, Q65, MSK144, FST4, FST4W, JS8 ou WSPR), e também SSB, CW, RTTY e SSTV, que mudam a barra inferior e a aba Estações como descrevem as respectivas seções. Passar dos modos digitais para um desses quatro, voltar, ou trocar entre eles coloca o TX em OFF: arme-o de novo quando estiver pronto. Trocar entre modos digitais o deixa como está.
  8. O seletor de banda: com um transceptor conectado, muda a banda no transceptor.
  9. O botão da aba Estações: abre a aba que lista todas as estações que você ouviu ou com as quais pode se comunicar.
  10. O botão da aba Log de QSOs: abre a aba que lista todos os QSOs que você fez. Este botão fica marcado com um ponto amarelo quando há QSOs que não foram enviados ao QRZ.
  11. O botão da aba Mapa mundial: abre a aba que mostra o mapa-múndi interativo.
  12. O botão da aba Configurações: abre a aba para configurar o qFT8.

O espectrograma

O espectrograma mostra uma vista de picos e a cascata, com os sinais e as mensagens que chegam, os sinais e as mensagens que saem, marcadores da mudança de sequência anotados com a hora UTC e o tempo de decodificação, e o desvio de frequência selecionado para transmissão.

Estes são os componentes do espectrograma, em detalhes:

  1. Vista da cascata: mostra o histórico recente dos sinais recebidos ao longo do tempo. Tocar nessa vista muda o desvio de frequência selecionado.
  2. Picos em tempo real: mostram a intensidade instantânea dos sinais em toda a faixa de frequências. Tocar nessa vista abre uma caixa de diálogo para digitar o desvio de frequência exato.
  3. Separadores de sequência: estas linhas horizontais vermelhas separam visualmente os ciclos e são anotadas com a hora UTC e o tempo gasto na decodificação.
  4. Desvio de frequência selecionado: esta faixa vertical amarela sobre o espectrograma indica o desvio de frequência atualmente selecionado para transmissão.
  5. Mensagens recebidas, mostradas com um código de cores:
    • Verde: mensagens de CQ.
    • Ciano: mensagens entre outras estações.
    • Amarelo: as mensagens que você transmitiu.
    • Laranja: mensagens recebidas direcionadas a você.
  6. Hora UTC e sequência atuais: mostradas no alto da cascata.
  7. Frequência e banda sintonizadas: a frequência e a banda em que o transceptor está sintonizado.
  8. Eixo de frequência: mostra a escala de frequência em Hz dentro da banda selecionada.

A aba Estações

A aba Estações é o centro de comando para acompanhar a atividade na banda e operar o qFT8. Ela traz os controles de filtro e de automação no alto, seguidos de uma lista das estações ativas.

Estes são os componentes da aba Estações, em detalhes:

  1. Botão do modo de chamada AUTO: com "AUTO" ativado, o qFT8 tenta chamar a melhor estação segundo os critérios escolhidos pelo usuário.
  2. Botão do modo manual CALL: ativar "CALL" em uma estação faz o qFT8 insistir em chamá-la até conseguir um QSO, e depois voltar para "AUTO".
  3. Alvo: define os critérios do modo AUTO:
    • Qualquer um: qualquer indicativo com o qual você ainda não tem QSO.
    • Perto: prioriza as estações mais próximas, pela distância entre grids Maidenhead.
    • Distante: prioriza as estações mais distantes, pela distância entre grids Maidenhead.
    • Intensidade do sinal: prioriza as estações com o sinal mais forte (SNR).
    • Chamar CQ: apenas chama CQ e responde a qualquer estação que chame a sua.
    • Caçador POTA: prioriza as estações de Parks on the Air.
    • Caçador SOTA: prioriza as estações de Summits on the Air.
    • Caçador POTA + SOTA: prioriza as estações de Parks on the Air e de Summits on the Air, e depois as que não são nem uma coisa nem outra, ordenadas por SNR.
    • DXCC: prioriza países/entidades novos.
    • Grid: prioriza quadrículas Maidenhead novas.
    • Zona ITU: prioriza zonas ITU novas.
    • Zona CQ: prioriza zonas CQ novas.
    • I/C/D/G: prioriza primeiro a zona ITU, depois a zona CQ, depois o DXCC e depois o Grid.
    Em todos os casos, as estações que atendem ao mesmo critério são ordenadas pela intensidade do sinal. Por exemplo, Qualquer um prioriza primeiro os indicativos novos, mas, entre eles, os sinais mais fortes ficam no alto da lista. As estações que atendem aos critérios do alvo ficam sempre no início da lista; um pequeno intervalo com a linha "As estações abaixo não atendem aos critérios de alvo" as separa das demais. Quando nenhuma estação atende aos critérios, a linha "Nenhuma estação é alvo – veja-as abaixo" aparece no topo da lista.
  4. Periodicidade: com que frequência contatar esse alvo:
    • uma vez: uma vez na vida.
    • por dia: uma vez por data UTC.
    • por semana: uma vez a cada 7 dias (janela móvel).
    • por mês: uma vez por mês (janela móvel).
    • por ano: uma vez por ano (janela móvel).
  5. Qualificador: como essas restrições se aplicam:
    • por indicativo
    • em bandas diferentes
    • em modos diferentes
    • até zona confirmada
    • por banda + até zona
    • por modo + até zona
    • em bandas ou modos diferentes
    • por banda/modo + até zona
  6. Modo Espião: quando ativado, o qFT8 também tenta chamar estações que você ainda não ouviu chamar CQ (marcadas como DIRECT). É útil para ter mais estações ao alcance e entrar em pile-ups.
  7. Modo Ocupado: quando ativado, o qFT8 também tenta chamar estações que estão em QSO com outra (marcadas como BUSY). É útil para entrar em um pile-up.
  8. Botão +: chama manualmente qualquer estação, digitando o indicativo dela.
  9. Informações da estação: mostra o estado detalhado de cada estação decodificada.

Cada estação da lista tem quatro linhas cheias de informação:

A primeira linha mostra os dados da estação (da esquerda para a direita):

  • Estado do QSO: indica seu histórico de QSOs com esta estação (✗ = nenhum QSO, ✓ = registrado localmente, ★ = confirmado via QRZ ou LoTW).
  • Indicativo: o indicativo da estação.
  • DXCC: o país ou a entidade a que pertence o indicativo desta estação.
  • Grid: a quadrícula Maidenhead que esta estação informa.
  • Zona CQ: a zona CQ a que pertence o indicativo desta estação.
  • Zona ITU: a zona ITU a que pertence o indicativo desta estação.
  • Banda: a banda em que a estação foi ouvida pela última vez.

A segunda linha mostra o estado da comunicação (da esquerda para a direita):

  • Estado: a fase atual da comunicação:
    • DIRECT: ouvida e aparentemente livre agora, mas nunca chamou CQ.
    • 1/6 CQ: ouvida chamando CQ e aparentemente livre agora.
    • 2/6 CALL: chamou você.
    • 3/6 RPT: enviou a você um reporte de sinal.
    • 4/6 RRPT: respondeu ao seu reporte com o dela.
    • 5/6 RR73: confirmou seu reporte com RR73.
    • 6/6 DONE: QSO concluído (73 trocados).
    • BUSY: Ouvida em um QSO com outra estação.
    • GONE: não foi ouvida nos últimos ciclos.
    • TOO LONG: o seu indicativo e o dela são, juntos, longos demais para estabelecer uma comunicação, pelos limites do modo digital FT8.
  • Intensidade do sinal: intensidade em dB (mostra "????" se não foi ouvida recentemente).
  • Sequência: a última sequência em que esta estação foi ouvida transmitindo (0 ou 1).
  • Delta de tempo (Δt): diferença de sincronização, em segundos, entre o relógio dela e o seu.
  • Distância: distância estimada entre o grid dela e o da sua estação.

A terceira e a quarta linhas mostram as trocas de mensagens com essa estação, incluindo a hora UTC, o desvio de frequência e o texto da mensagem (com o prefixo RX: para as mensagens recebidas ou TX: para as transmitidas). Conforme o modo de exibição das estações escolhido em Configurações → Aplicativo → Interface do usuário (o padrão é Compacto - Último Rx; as outras opções são Compacto - Último Rx/Tx alternando, Compacto - Último Rx/Tx e Expandido - Últimos Rx e Tx), os cartões das estações mostram três linhas, ou quatro linhas com as mensagens de Rx e de Tx.

Indicadores visuais importantes:

  • Mensagem Rx em coral (UTC, desvio e texto): uma mensagem Rx recebida desta estação foi direcionada especificamente à sua estação / ao seu indicativo (incluindo indicativos compostos como /P e correspondências de indicativos com hash) no ciclo atual ou no anterior. É uma pista visual imediata de que a estação acabou de chamar você ou de responder às suas transmissões. As chamadas gerais de CQ e as mensagens direcionadas a outras estações nunca são destacadas, e o texto volta automaticamente ao cinza normal quando a mensagem fica mais antiga que o ciclo anterior. As mensagens transmitidas (TX:) ficam sempre em cinza neutro.
  • Indicativo em vermelho: o modo AUTO ultrapassou o limite de tentativas para esta estação. Ela é ignorada temporariamente, a menos que você toque em "CALL" para reiniciar a contagem manualmente.
  • Indicativo em roxo: este indicativo é um alvo segundo seus critérios atuais.
  • Indicativo em cinza: o indicativo corresponde à sua configuração de prefixos excluídos (separados por vírgulas). O modo AUTO nunca escolhe esta estação.
  • Zona destacada em roxo: esta zona/entidade (DXCC, Grid, Zona CQ, Zona ITU) é um alvo segundo seus critérios atuais.
  • Número de sequência em vermelho: a estação está na mesma sequência que você selecionou, o que causa um conflito. Tocar em "CALL" muda a sua sequência automaticamente.
  • Banda em vermelho: a estação foi ouvida pela última vez em outra banda.

As estações são ordenadas automaticamente por relevância. Mudar seus critérios de alvo ou suas restrições reordena a lista na hora.

A ordem da lista

Do topo da lista para baixo:

  1. Estações com que você acabou de completar um QSO (DONE).
  2. A estação que você escolheu com CALL.
  3. Estações em QSO com você, as mais adiantadas primeiro: as que esperam o seu 73, depois as que lhe enviaram o reporte delas, depois as que chamaram você.
  4. Estações na sua banda que atendem aos critérios de alvo, a melhor correspondência primeiro. Em caso de empate, o sinal mais forte vem primeiro; com um alvo de distância, a distância decide primeiro.
  5. A linha “As estações abaixo não atendem aos critérios de alvo” e depois todas as outras estações, na mesma ordem.
  6. Estações que não são mais ouvidas (GONE) e, bem no fim, estações cujo indicativo e o seu não cabem juntos em uma mensagem (TOO LONG).

Dentro de cada grupo, as estações ouvidas por último em outra banda vêm depois das da sua banda. Estações ouvidas em outro modo não são mostradas; elas voltam na primeira vez que forem ouvidas no modo atual. Estações que você adicionou com o botão + ficam sempre na lista. A linha entre os alvos e as outras estações é a mesma no celular, no computador, no iPhone e no controle remoto web; é só um rótulo, e tocar nela não faz nada.

O seletor ao lado do modo na barra inferior existe no celular, no computador, no iPhone e no controle remoto web. As sequências 0 e 1 são os períodos pares e ímpares do modo, seja qual for a duração. Com os períodos longos, uma estação só conta como não mais ouvida (GONE) depois de um número correspondente de períodos em silêncio.

FT4 / FT2: Tudo funciona como no FT8, só que mais rápido. Cada período é curto, então um QSO anda depressa: no FT2 um QSO inteiro pode terminar em bem menos de um minuto.

LQ8: Um QSO em LQ8 tem quatro etapas em vez de seis, e a coluna de estado as mostra:

  • 1/4 CQ: Ouvida chamando CQ, por exemplo CQ DL1XYZ JO62.
  • 2/4 CALL: Chamou você, com o localizador dela e o seu reporte na mesma mensagem, por exemplo HB9IPH DL1XYZ JO62 -11.
  • 3/4 RPT73: Enviou o reporte dela junto com a confirmação; aparece como HB9IPH DL1XYZ R-11.
  • 4/4 DONE: QSO completado (73 trocados).

No LQ8 não há uma etapa de reporte separada nem RR73: o protocolo é feito assim. DIRECT, BUSY, GONE e TOO LONG significam o mesmo que no FT8. Se você tocar em CALL numa estação cujo indicativo não pode ser enviado em LQ8 junto com o seu, o qFT8 avisa e não chama.

Q65: Escolha o submodo ao lado do modo na barra inferior antes de chamar; estações que usam outro submodo não são decodificadas. Com os submodos mais longos, cada etapa do QSO leva um período inteiro (até 5 minutos), então um QSO demora muito mais, e as linhas de estações mudam uma vez por período. Com a média ligada, uma estação pode aparecer só depois de várias transmissões dela serem somadas. Os submodos longos precisam de um Limite de transmissão contínua grande o bastante.

MSK144: Escolha o período ao lado do modo na barra inferior. Uma estação aparece quando um de seus pings é decodificado, então as linhas vêm e vão com os meteoros; a intensidade do sinal é a do ping, e o Δt é o momento do ping dentro do período, não um erro de relógio. Uma mensagem curta aparece com os dois indicativos, como a forma longa, por exemplo K1ABC W9XYZ R+03; só as duas estações daquele QSO podem lê-la. Com mensagens curtas ligadas nas Configurações, o qFT8 envia assim as suas reportes, RRR e 73; o seu CQ, a sua chamada e o seu RR73 sempre saem como mensagens normais. Todas as estações transmitem em 1500 Hz, então o deslocamento de uma estação diz pouco.

FST4: Escolha o período ao lado do modo na barra inferior; ele precisa ser o mesmo da outra estação. Com períodos de 900 ou 1800 segundos um QSO pode levar uma hora ou mais, e cada transmissão sua mantém o rádio transmitindo por até 30 minutos: ajuste o Limite de transmissão contínua para permitir isso, ou o qFT8 não vai transmitir.

As configurações do AUTO, os alvos e as novas tentativas são os mesmos em todos esses modos; veja Operação automática (AUTO).

A aba Mapa mundial

A aba Mapa mundial mostra um mapa global interativo, em tempo real, com a geografia das estações, o tráfego decodificado, suas conquistas em QSOs e as condições de propagação solar.

Estes são os componentes e recursos da aba Mapa mundial, em detalhes:

  1. Mapa interativo e controles:
    • Navegação: arraste para percorrer o globo suavemente, com continuidade horizontal ao cruzar o antimeridiano. Use o gesto de pinça com dois dedos para aproximar e afastar.
    • Temas do mapa: alterne entre quatro estilos visuais (Futuro brilhante, Console, Terra e Azul meia-noite) na barra de ferramentas superior.
    • Coordenadas no HUD: mostra em tempo real as coordenadas geográficas (latitude, longitude) e o grid locator Maidenhead do ponto que você toca.
  2. Barra de ferramentas esquerda (camadas e informações):
    • INFO: liga e desliga os cartões de informação sobrepostos na tela (hora, terminador solar, posição subsolar e coordenadas da mira).
    • MSGs: liga e desliga as rotas e os marcadores de mensagens diretas: em laranja para as mensagens recebidas (endereçadas à sua estação) e em amarelo para as enviadas (transmitidas pela sua estação). Tocar no ponto médio da seta abre o texto da mensagem.
    • QSOs: liga e desliga os marcadores dos contatos recentes da sessão (âmbar para os registrados, esmeralda para os confirmados). Com MSGs e Spot ambos desligados, uma linha fina liga a sua estação a cada estação de QSO no mapa (sem setas), para você ver de relance para onde foram os seus contatos; a imagem do mapa compartilhada também mostra essas linhas.

    • SOTA: liga e desliga as referências de cumes do Summits On The Air e os ativadores de cumes em atividade (⛰️).
    • POTA: liga e desliga as referências de parques do Parks On The Air e os ativadores de parques em atividade (🌲).
    • Banda: mostra a propagação da banda a partir de relatórios online e uma zona cega ao redor do usuário. Com conexão com a internet, é atualizado em tempo real ao mudar de banda.

    • CQ: sobrepõe as 40 zonas WAZ da revista CQ, preenchidas conforme as conquistas.

    Tocar em qualquer estação, spot, parque ou cume abre um cartão de detalhes com:

    • Indicativo ou nome da referência, entidade DXCC e nome do parque/cume.
    • Texto da mensagem decodificada, frequência, banda e modo.
    • Intensidade do sinal (SNR) ou reporte de sinal (RST).
    • Grid locator, distância (km / mi), rumo (°) e tempo decorrido.
    • Botão CALL: inicia na hora o contato com a estação (mudando automaticamente de banda e de modo, se necessário).

A aba Configurações

A aba Configurações permite configurar o qFT8.

A aba Configurações está organizada assim:

  • Indicativo: seu indicativo de radioamador (obrigatório para transmitir). Deve estar de acordo com a sua licença.
  • Modificador de CQ: texto opcional acrescentado às suas chamadas de CQ (por exemplo, "SOTA").
  • Dispositivo: serve para selecionar e configurar seu transceptor (por exemplo, QMX, QDX, série Kenwood TS-480 / TS-590 / TS-2000, ou VOX/apenas áudio) e os parâmetros de conexão.
  • Rádio / Antena: o rádio e a antena com que você opera. Cada QSO registrado os guarda (ADIF MY_RIG / MY_ANTENNA), e o PSKReporter os recebe junto com seus spots. Com Rádio vazio, é usado o nome do rádio conectado.

Submenus e opções

  • CONFIGURAÇÃO DO DISPOSITIVO: selecione o dispositivo de áudio, ajuste o volume de transmissão e os limiares do VOX e configure como o rádio é colocado em transmissão. Também o Desvio de sintonia do espectrograma e o Limite de transmissão contínua de cada rádio (ambos em Documentação dos recursos).

  • SINCRONIZAÇÃO DE QSOs: configure a integração com QRZ e LoTW para sincronizar e confirmar o log.
  • EXCLUIR QSOs: apaga QSOs locais (esta ação só afeta o log local do aplicativo).
  • APLICATIVO: configurações gerais, incluindo o idioma da interface.
  • ESPECTROGRAMA: escolha quais sobreposições a cascata desenha — tempo de decodificação, hora UTC e sequência, mensagens, linhas de picos e a frequência da estação selecionada — e a escala da fonte das sobreposições.
  • MAPA MUNDIAL: escolha o que o mapa mostra e por quanto tempo: QSOs realizados, spots e mensagens enviadas e recebidas, cada um com a sua janela de tempo.
  • HORA E LOCALIZAÇÃO: configure a sincronização do desvio de tempo (NTP ou GPS) e seu grid locator Maidenhead.
  • OPERAÇÃO AUTOMÁTICA: configure as preferências de automação, o número de tentativas, os prefixos excluídos e se o AUTO responde a CQs direcionados que não são para você.

  • SERVIDOR WEB DE CONTROLE REMOTO: ative e configure o servidor web embutido para controle remoto.
  • CONFIGURAÇÕES DO PSKREPORTER: serve para enviar ao PSKReporter as estações que você recebe.
  • CONFIGURAÇÕES DO WSPRNET: envie spots WSPR ao WSPRnet e consulte o log recente de envios.
  • Procurar novas versões ao iniciar: mostra um aviso quando existe uma versão mais nova do qFT8 (veja Relatórios de erros e novas versões).

Alto-falantes e microfone

Os modos digitais só precisam de um dispositivo de som: o do rádio. SSB e CW precisam de um segundo, para você: um alto-falante ou fones de ouvido para ouvir o rádio e, para SSB, um microfone para falar. Esses dois nunca devem ser a própria placa de som do rádio, porque o que você diz voltaria direto, em laço.

  • No Android: Configurações > Alto-falantes e microfone, logo abaixo de CONFIGURAÇÃO DO DISPOSITIVO.
  • No computador: o cartão CONFIGURAÇÃO DO DISPOSITIVO tem duas metades: O RÁDIO à esquerda (a placa de som do rádio: o que o rádio ouve e o que ele envia) e VOCÊ (O OPERADOR) à direita.

Há duas escolhas:

  • Seu microfone (você fala, o rádio transmite). Abaixo dele, uma pequena cascata ao vivo e um medidor de nível mostram o que o microfone está captando: fale, e você deve vê-los se mexer.
  • Seus alto-falantes / fones de ouvido (você ouve o rádio), com um botão TESTAR que toca neles um som curto.

Os dois começam em AUTO, que escolhe um dispositivo que não é o do rádio: em um celular, um headset quando há um conectado e, caso contrário, o microfone e o alto-falante do próprio celular; no computador, o primeiro dispositivo de som que não seja a placa do rádio. Mude-os apenas se o AUTO escolheu o dispositivo errado.

Dica: use fones de ouvido para SSB. Com um alto-falante ao lado do microfone, o áudio recebido pode acionar o VOX ou ser ouvido na sua transmissão.

Operação automática (AUTO)

O modo AUTO é a principal forma de usar o qFT8. Nesse modo, o aplicativo analisa automaticamente as mensagens decodificadas ao fim de cada ciclo e escolhe a estação mais relevante para contatar, segundo seus critérios de alvo.

Como funciona a escolha do alvo

A aba Estações mostra uma lista das estações ativas, ordenada de modo que as candidatas mais relevantes (segundo seus critérios) fiquem no alto. Ao fim de cada ciclo de decodificação, o qFT8 examina essa lista ordenada e tenta chamar a primeira estação elegível. Se não houver nenhum alvo elegível, ele começa automaticamente a chamar CQ para atrair chamadas. No modo AUTO, o qFT8 sempre responde a quem o chama.

Critérios e filtros

Você pode ajustar a automação com os três menus suspensos do alto da aba Estações:

  • Alvo: define que "conquista" você procura (Qualquer um, DXCC, Zona CQ, Zona ITU, Grid).
  • Intervalo: com que frequência você aceita contatar a mesma entidade (uma vez, sempre, diário, semanal, mensal).
  • Qualificador: restringe a exigência de unicidade (por indicativo, por banda, até zona/entidade confirmada).

Intervenção manual: você sempre pode intervir tocando no botão CALL de uma estação específica. Isso entra no modo CALL para esse QSO. Ao terminar, o qFT8 volta naturalmente ao modo AUTO.

Mecanismo de novas tentativas

Para evitar que o qFT8 chame indefinidamente uma estação que não responde, ele tem um sistema embutido de novas tentativas e de bloqueio temporário, ativado por padrão. Você pode configurá-lo na aba Configurações, em Lógica de novas tentativas:

  • Limite de tentativas: o número máximo de vezes que o qFT8 repete uma etapa de transmissão para uma estação que não responde.
  • Janela de tentativas: o período durante o qual essas tentativas são contadas.
  • Tempo de espera: se o limite é atingido, a estação fica "bloqueada" por esse tempo. O modo AUTO ignora as estações bloqueadas até o tempo de espera acabar ou a estação responder.

Operação manual (CALL)

Embora o qFT8 seja bastante automatizado, você pode assumir o controle a qualquer momento. Tocar no botão CALL ao lado de qualquer estação na aba Estações entra imediatamente no modo CALL e tenta estabelecer um QSO com essa estação.

Quando o QSO com o alvo manual termina (com sucesso ou não), o qFT8 volta automaticamente ao modo AUTO e retoma sua estratégia automática anterior (por exemplo, chamar CQ).

Tempos para quem opera manualmente

Se você quiser mais tempo no fim do ciclo para tomar decisões manuais, pode ganhar margem ajustando as Configurações de FT8 na aba Configurações:

  • Diminuir "Início da decodificação": começa a processar o áudio mais cedo.
  • Aumentar "Início da transmissão": atrasa o começo da sua resposta.

Aviso: levar esses valores muito para as margens pode tornar suas mensagens bem mais difíceis de decodificar pelas outras estações, porque você reduz o tempo efetivo disponível para o sinal FT8 dentro da janela de sincronização.

Editar e registrar QSOs à mão

O qFT8 registra sozinho os QSOs que faz nos modos digitais. Esta seção trata das três coisas que você faz à mão na aba Log de QSOs: corrigir um QSO, registrar um QSO feito de outra maneira (voz, Morse, outro rádio) e trabalhar com vários QSOs de uma vez.

O editor de QSO

Toque em um QSO na aba Log de QSOs e a aba se torna o editor dele. Estão lá todos os campos guardados: seu indicativo e seu locator, os da outra estação, modo, banda, frequências, data e horas, potência, reportes, referências POTA e SOTA e o comentário.

  1. O QSO que está sendo editado: indicativo, modo, banda, data e hora.
  2. Status: se o QSO está confirmado. Toque nele para Confirmar manualmente ou Desconfirmar manualmente (isso só altera o seu próprio log).
  3. Enviado: em que situação o QSO está no QRZ e no LoTW. Toque nele para enviar o QSO de novo a um serviço ou a todos.
  4. Um campo alterado fica destacado, com o valor antigo em vermelho ao lado e uma seta que restaura o valor antigo. Toque em qualquer valor para alterá-lo. O modo e a banda são escolhidos nas listas do aplicativo, a banda acompanha a frequência que você digita, e um valor que não pode estar certo (um indicativo, um locator, uma data...) é recusado, com o motivo.
  5. VOLTAR: sai do editor. Se houver alterações, pergunta se devem ser descartadas.
  6. O número de alterações ainda não salvas.
  7. EXCLUIR: exclui o QSO apenas do log deste aplicativo, depois que você digita yes.
  8. SALVAR: pede confirmação e depois salva.

O que acontece no QRZ e no LoTW quando você salva. A pergunta de confirmação informa, para o QSO que você está editando:

  • QRZ: o QSO é atualizado lá. Se você alterou o indicativo, a data, a hora, a banda ou o modo, o QRZ o trata como outro QSO: uma entrada nova é criada e a antiga permanece, para você excluir em qrz.com.
  • LoTW: o QSO corrigido é enviado de novo como entrada nova; a antiga fica lá, sem confirmação e inofensiva.
  • Uma alteração que quebra uma confirmação (o indicativo, o seu indicativo, a data ou a hora de um QSO) precisa ser confirmada digitando yes, porque o QSO deixará de coincidir com o log da outra estação.
  • Um QSO feito com um indicativo diferente do que está nas Configurações não é enviado.

O qFT8 nunca exclui nada no QRZ nem no LoTW. Excluir um QSO só o remove do aplicativo. Se esse QSO está em um serviço, ele pode voltar na próxima sincronização: exclua-o primeiro no serviço. A exclusão é irreversível, a menos que você guarde uma cópia exportada do log.

O registro manual

O botão + da aba Log de QSOs abre o registro manual, um formulário rápido para os QSOs que você mesmo faz. Em um celular ele gira a tela para retrato, com uma faixa estreita do espectrograma no alto (isso pode ser desligado em Configurações > APLICATIVO > Interface do usuário).

  1. Indicativo: digite o indicativo e pressione Enter no teclado: o QSO é registrado com a hora atual, a caixa esvazia e você pode digitar o próximo. O teclado fica aberto de um QSO para o seguinte.
  2. REGISTRAR: o mesmo que Enter.
  3. LIMPAR / DESFAZER: enquanto há um indicativo digitado, o botão diz LIMPAR e esvazia a caixa. Caso contrário, diz DESFAZER e tira do log o último QSO desta sessão, devolvendo-o ao formulário para ser corrigido.
  4. CONCLUÍDO: fecha o registro manual. Se há um indicativo digitado, mas não registrado, pergunta se deve registrá-lo.
  5. A linha de consulta: o país do indicativo, seu último QSO com ele e se é um duplicado. DUPE em laranja significa que você já registrou hoje essa estação nessa banda e nesse modo (você pode registrá-la mesmo assim).
  6. Os detalhes (deslize para os lados para ver mais): a hora (Agora, ou toque nela para definir uma data e uma hora), banda, modo, frequência em kHz, a frequência de recepção quando é diferente, potência, reportes enviado e recebido, a referência POTA / SOTA da outra estação e a sua. Eles partem do que o aplicativo está sintonizando e são mantidos de um QSO para o seguinte.
  7. Esta sessão: quantos QSOs você registrou desde que abriu o registro manual. Em um celular, toque nela para vê-los em uma lista.
  8. Os QSOs da sessão aparecem em coral com um ícone de relógio: já estão no seu log, mas não são enviados ao QRZ nem ao LoTW até você tocar em CONCLUÍDO, para que um erro de digitação ainda possa ser desfeito. Toque em um deles para desfazê-lo ou editá-lo.

O botão QSO dos painéis SSB, CW, RTTY e SSTV abre o mesmo formulário como um pequeno cartão, já preenchido com o modo, a frequência e a estação, para um QSO de cada vez.

Selecionar vários QSOs

Mantenha pressionado um QSO na aba Log de QSOs para iniciar uma seleção (no computador, Ctrl-clique, ou Shift-clique para um intervalo). Depois toque em outros QSOs para adicioná-los ou removê-los.

  1. X: sai da seleção sem fazer nada.
  2. Quantos QSOs estão selecionados.
  3. SELECIONAR INTERVALO: toque nele e depois no QSO onde o intervalo termina: tudo o que está no meio é selecionado.
  4. TODOS e NENHUMA.
  5. AÇÕES: o que fazer com os QSOs selecionados:
    • Confirmar manualmente / Desconfirmar manualmente.
    • Exportar (ADIF): um arquivo só com esses QSOs.
    • Exportar com uma referência POTA / SOTA: o mesmo, com o seu parque ou cume escrito em cada QSO do arquivo (o log em si não é alterado).
    • Adicionar a uma ativação POTA / SOTA e Remover da respectiva ativação (veja Ativar um parque ou um cume).
  6. Os QSOs selecionados ficam marcados e destacados.

Cada ação informa primeiro quantos QSOs vai alterar e pede confirmação, e uma alteração pode ser desfeita logo em seguida. Nada é excluído no QRZ nem no LoTW, nunca.

Importação/exportação ADIF

O qFT8 usa o formato padrão ADIF (Amateur Data Interchange Format) para a interoperabilidade com outros programas de log e serviços na nuvem, e para backups manuais.

Importar QSOs

A importação permite trazer para o seu log local do qFT8 registros de outras origens (como outros programas de log ou backups de outros dispositivos).

  • Opções de filtro: todos os modos são importados. Você escolhe se limita a importação ao seu indicativo atual ou inclui todos os operadores.
  • Remoção automática de duplicados: o qFT8 mescla os registros de forma inteligente. Ele evita duplicados comparando os Log IDs do QRZ e as datas e horas dos QSOs. Se um registro importado tem um estado de confirmado ou um Log ID válido que falta no seu registro local, a entrada local é atualizada com os dados melhores.

Exportar QSOs

Tocar em EXPORTAR QSOs gera um arquivo ADIF 3.1.6. No Android abre-se o menu de compartilhamento do sistema, que permite salvar o log no dispositivo ou enviá-lo por e-mail ou mensagem; no computador você escolhe onde salvar o arquivo.

  • Intervalo de tempo: você pode exportar todo o seu histórico ou usar os seletores de data/hora UTC para isolar uma ativação ou um período de contest.
  • Filtros de estado: úteis para pedir diplomas (exporte "Apenas confirmados") ou para envios manuais a outros serviços (exporte "Apenas não enviados para o QRZ", para evitar duplicados).
  • Critérios de caçador: filtre seu log para exportar "Exportar todo o log", "Exportar apenas caçador POTA" ou "Exportar apenas caçador SOTA" e gerar arquivos específicos para pedidos de diplomas, com as referências dos contatos preenchidas (<POTA_REF> / <SOTA_REF>).
  • Referência SOTA: como detalhado na seção SOTA, o qFT8 pode inserir automaticamente a referência do cume no campo <MY_SOTA_REF> de cada registro exportado.
  • Referência POTA: como detalhado na seção POTA, o qFT8 pode inserir automaticamente a referência do parque nos campos <MY_SIG>, <MY_SIG_INFO> e <MY_POTA_REF> de cada registro exportado. Vários parques, separados por vírgulas, dão um arquivo por parque (veja "Qual parque vai no arquivo?").

Os nomes dos arquivos exportados

  • Sem referência: qFT8-YYYYMMDD-HHMMSS.adi, a data e a hora (UTC) da exportação, por exemplo qFT8-20261006-181500.adi. Os filtros de estado acrescentam _confirmed ou _notuploaded depois da hora, de modo que os arquivos de uma pasta ficam ordenados por data.
  • Com uma referência POTA: CALLSIGN@PARK-YYYYMMDD.adi, por exemplo K1ABC@US-1234-20261006.adi. Este é o nome que o programa de parques pede. Há um arquivo para cada parque e cada dia UTC; portanto, uma exportação que atravessa a meia-noite UTC dá dois arquivos.
  • Com uma referência SOTA: um arquivo, por exemplo K1ABC@W1_HA-001-20261006.adi (a "/" de um cume ou de um indicativo não pode fazer parte de um nome de arquivo e é escrita "_").
  • No computador, uma exportação nunca substitui um arquivo que já existe: se o nome está ocupado, o novo arquivo é salvo como name (1).adi, depois name (2).adi, e assim por diante.

Nota: para logs muito grandes (acima de 100KB), o qFT8 mostra um aviso, porque remover os duplicados e ordenar pode demorar um pouco, especialmente em um celular.

Serviços de envio de QSOs

O qFT8 pode enviar cada QSO que você registra para vários logs online ou da sua rede doméstica: QRZ, LoTW, Wavelog, Cloudlog, eQSL e outro qFT8 (qFT8log). Cada um tem uma linha no alto das Configurações: uma caixa de seleção para ativá-lo e um botão de engrenagem que abre a página do próprio serviço.

  • A caixa de seleção fica acinzentada até o serviço ser validado: abra a página dele, informe os dados e pressione VALIDAR.
  • Cada página começa com uma breve explicação e um botão ? que abre este manual na seção do serviço. Ela também mostra quantos QSOs ainda não foram enviados, com ENVIAR AGORA, e um botão RESTAURAR PADRÕES (ele nunca apaga uma conta, uma chave ou uma senha).
  • Quando não foi possível alcançar um serviço desde a última vez que funcionou, a linha dele fica vermelha e uma linha vermelha abaixo diz Não foi possível conectar desde e a data e a hora.

Quando um QSO conta como enviado?

A marca verde no log, na lista de estações, no mapa e no controle remoto web segue uma única regra. A página de cada serviço tem uma caixa Considerar um QSO enviado se estiver enviado aqui. Ela vem ativada para o QRZ e o LoTW e desativada para os demais.

  • Um serviço só conta quando está configurado: validado e ativado.
  • Um QSO é considerado enviado assim que qualquer serviço que conta o tem.
  • Quando nenhum dos serviços configurados tem a caixa marcada, todos os serviços configurados contam. Assim, se você configurar só o qFT8log, o app espera apenas pelo qFT8log, nunca pelo QRZ ou pelo LoTW.
  • Sem nenhum serviço configurado, as caixas marcadas decidem a partir do que o próprio QSO traz (por exemplo, um log importado de outro programa mantém as marcas dele).
  • Um QSO importado do LoTW conta como já presente no QRZ e não é enviado para lá. Um QSO que veio de um serviço conta como enviado a esse serviço e nunca é devolvido a ele.
  • A estrela (confirmado) exige que o QSO esteja enviado conforme essa regra e confirmado por qualquer serviço, a menos que você o tenha confirmado ou desconfirmado manualmente.

A exportação ADIF pode escolher Não enviados ao um serviço por vez; as opções dos serviços não configurados ficam acinzentadas. O qFT8 nunca apaga um QSO em nenhum serviço: apagar um QSO aqui apenas avisa que ele ainda está lá.

HRDLog, HamQTH, World Radio League e Club Log

Cada um tem sua página. Programas de log na sua rede

O qFT8 pode enviar cada QSO que você registra para programas de log e de mapa da sua rede local. Em ADICIONAR MAIS SERVIÇOS marque FT8 network log (porta UDP 2237) ou ADIF over UDP (porta UDP 2333); a linha aparece em Sincronização de QSOs. Na página dele, digite o endereço do computador onde roda o outro programa (127.0.0.1 é este computador) e a porta, toque em VALIDAR e depois marque a caixa. O FT8 network log também pode enviar suas decodificações e o status da sua estação (Enviar também minhas decodificações e o status da minha estação (para mapas e alertas)), usados pelo mapa e pelos alertas do outro programa. Essas mensagens não têm confirmação de recebimento, então um QSO enviado assim nunca conta como enviado. As configurações mostram, abaixo de cada um, os programas com que ele foi testado.

No sentido inverso, o qFT8 pode receber no seu log os QSOs de outros programas. Em ADICIONAR MAIS SERVIDORES marque o receptor do formato que o outro programa envia: FT8 network log (UDP 2237), ADIF over UDP (UDP 2333), a interface AC Log (TCP 1100) ou a interface DXLab (TCP 52001); depois marque a linha dele em Servidores. A página dele mostra o endereço a colocar no outro programa e permite mudar a porta e aceitar QSOs só de alguns endereços. Nada recebido assim pode transmitir, mudar o rádio ou apagar um QSO. Os receptores ficam desligados até você ligá-los; no iPhone eles só funcionam enquanto o qFT8 está aberto e nunca entram em um grupo multicast.

O log por UDP não é perfeito: FT8 network log e ADIF over UDP enviam cada QSO uma única vez, sem recibo, então se esse pacote se perder (por exemplo, numa conexão Wi-Fi ruim) o QSO se perde. Nenhum desses formatos tem senha: um receptor que você ativa deixa qualquer pessoa da rede enviar QSOs como se fosse você, e um cliente envia os seus QSOs para o que estiver escutando no endereço que você digitou. As Configurações mostram isso sob cada um dos seus interruptores, nas linhas e nas suas páginas. A lista de endereços aceitos de um receptor limita quem pode enviar para ele. Para os seus QSOs, recomenda-se o qFT8log: compatível entre qFT8, o mais seguro e criptografado (veja qFT8log).

PSKReporter

O PSKReporter reúne relatórios de recepção do mundo todo: qual estação foi ouvida onde, em que banda e modo, e com que intensidade. Integração com o QRZ

O qFT8 tem uma integração profunda com o QRZ.com para manter seu logbook sincronizado automaticamente. Note que a integração com o QRZ é um serviço por assinatura, que requer uma assinatura paga do QRZ (XML Logbook Data ou superior). Se você prefere uma alternativa gratuita, considere a integração com o LoTW, oferecida sem custo pela ARRL.

Como funciona

Para ativar a integração com o QRZ, você precisa informar sua Chave API do QRZ na aba Configurações. Você encontra sua chave de API na página oficial da API do Logbook do QRZ. Depois de informá-la e VALIDAR, você pode ativar "Enviar QSOs para o QRZ quando concluídos e em segundo plano" para que tudo seja feito automaticamente em segundo plano.

  • Envios automáticos: toda vez que um QSO é concluído (chegando ao estado 6/6 DONE), o qFT8 tenta enviá-lo imediatamente ao seu logbook do QRZ.
  • Confiabilidade em segundo plano: se um envio falha (por exemplo, por falta de conexão com a internet ou tempo esgotado no servidor), o qFT8 não desiste. Uma tarefa em segundo plano repete automaticamente os envios que falharam a cada 5 minutos. Esse processo é silencioso e garante que seu log acabe chegando à nuvem quando a conexão voltar.
  • Omissões inteligentes: o qFT8 protege a integridade do seu logbook enviando apenas os QSOs que correspondem ao indicativo configurado e ao modo FT8. As entradas que não são FT8, os QSOs de outros indicativos e os QSOs importados do LoTW são pulados automaticamente, para evitar um excesso de requisições à API.

Sincronização das confirmações

A integração vai além do envio. O qFT8 também consulta o QRZ para saber se seus QSOs foram confirmados.

  • Verificação imediata: 30 segundos depois que um QSO é concluído e enviado, o qFT8 consulta o QRZ para ver se a outra estação também enviou o QSO; se enviou, o QSO é sincronizado como confirmado na hora.
  • Sincronização automática: por padrão, o qFT8 consulta o QRZ a cada 6 horas (configurável), em lotes de 250 QSOs, percorrendo todo o seu log não confirmado para que mesmo os QSOs mais antigos acabem sendo verificados.
  • Estrela de confirmação (★): quando um QSO enviado ao QRZ é confirmado no QRZ ou no LoTW, ele é destacado com uma estrela dourada. Você também pode confirmar manualmente qualquer QSO para mostrar esse indicador. Quando o QRZ informa uma confirmação, o ícone de estado na aba Log de QSOs muda automaticamente para uma estrela dourada.
  • Sincronização manual: a atualização dos 250 QSOs sincronizados há mais tempo também pode ser iniciada manualmente nas configurações.

Dica: você pode acompanhar o progresso da sincronização nas configurações, em "QSO mais antigo sincronizado em". Não há pressa em manter isso em dia: o qFT8 cuida disso com o tempo.

Estratégia de sincronização do log

Nas configurações de sincronização, você pode escolher como o qFT8 decide que um QSO está "totalmente enviado", com a opção "Considerar um QSO enviado (✓) quando for enviado para:"

  • LoTW ou QRZ, qualquer um: um bom padrão se você só tem um dos serviços configurado.
  • Ambos: escolha esta opção para o máximo de segurança; o QSO precisa ser enviado com sucesso aos dois serviços antes de ser considerado finalizado e pronto para a verificação de confirmação.
  • QRZ (exceto os importados do LoTW): recomendado se o QRZ é o seu logbook principal. Nota: os QSOs importados do LoTW são marcados como sincronizados, mas não são enviados ao QRZ, para respeitar os limites da API (que só permite envios um a um); eles podem ser sincronizados depois, dentro do próprio QRZ.
  • LoTW: recomendado se você considera o LoTW a sua referência principal.

Integração com o Logbook of the World (LoTW)

O qFT8 tem uma integração sólida com o ARRL Logbook of the World (LoTW). Integrar-se ao LoTW é muito recomendável para confirmar seus contatos e conquistar diplomas como o DXCC e o WAS.

Requisitos de configuração

Para ativar todos os recursos do LoTW, incluindo os envios automáticos e as verificações de confirmação, você precisa informar quatro dados na aba Configurações:

  • 1. Nome de usuário do LoTW: seu indicativo oficial, usado no serviço LoTW.
  • 2. Senha do LoTW: a senha que você usa para entrar no site do LoTW. Ela é diferente da senha do certificado.
  • 3. Certificado TQSL .p12: um arquivo de assinatura digital exportado do programa TQSL. Para saber como pedir e exportar esse certificado, consulte a página oficial de ajuda do LoTW.
  • 4. Senha do certificado: a senha que você definiu ao exportar o arquivo .p12 do TQSL (pode ficar vazia, se você preferiu não definir uma).

Local da estação automático: dados como a Zona ITU, a Zona CQ e o nome da estação são determinados automaticamente a partir do seu indicativo. Esses campos não precisam de configuração manual.

Recursos

  • Envios automáticos: com Enviar QSOs para o LoTW quando concluídos e em segundo plano ativado, o qFT8 assina e envia automaticamente cada novo QSO ao LoTW, em segundo plano, assim que ele é registrado.
  • Verificação automática da confirmação: quando ativada, o qFT8 faz uma única verificação de confirmação exatamente 30 segundos depois de um envio bem-sucedido. Assim você vê quase na hora se o contato foi confirmado.
  • Sincronização periódica em segundo plano: configure Sincronizar confirmações a cada __ horas para procurar novas confirmações em segundo plano no intervalo que preferir (por exemplo, a cada 6 horas). Isso mantém todo o seu logbook em dia, sem intervenção manual.
  • Importar o logbook: toque em IMPORTAR QSOs DO LoTW para baixar todo o seu histórico do LoTW para o qFT8. Note que esses QSOs importados não são enviados automaticamente ao QRZ, para respeitar os limites de uso da API.
  • Indicador de pendências: um pequeno ponto amarelo no botão Log de QSOs indica que há QSOs à espera de envio ao LoTW.

Wavelog

O Wavelog é um programa de diário de bordo que você executa em um servidor web próprio (um pequeno computador em casa ou espaço web alugado) e abre em um navegador. O qFT8 envia cada QSO a ele assim que é registrado e lê de volta quais deles o seu Wavelog confirmou. O qFT8 se comunica com ele pela interface publicada do Wavelog: docs.wavelog.org/developer/api.

Como configurar

  1. No Wavelog, abra o menu da conta > API Keys e crie uma chave com direitos de leitura e gravação.
  2. No qFT8, abra Configurações, toque na engrenagem ao lado de Wavelog e digite o Endereço do servidor (o endereço em que você abre o Wavelog, por exemplo https://log.example.org) e a Chave de API. Um endereço digitado sem http:// ou https:// é testado primeiro com https; se o servidor só fala http simples (o servidor de outro qFT8 fala), o qFT8 usa http e a página avisa que a chave trafega sem proteção.
  3. Opcional, para que as edições também sejam enviadas: crie no Wavelog um token API v2 (menu da conta > API Keys, aba API v2, com os escopos qso:read e qso:write) e digite-o como Token de edição. VALIDAR o verifica sem alterar nada.
  4. Toque em VALIDAR. O qFT8 verifica a chave e lista os locais de estação do seu Wavelog; escolha aquele a que seus QSOs pertencem (se houver só um, ele é escolhido para você).
  5. Marque Wavelog na parte superior de Configurações. A partir de agora todo novo QSO é enviado para lá, e os registrados antes também são enviados.

O que acontece

  • Offline: um QSO que não pode ser enviado fica esperando no log e é enviado quando o servidor voltar a responder (nova tentativa após 1 minuto, depois com menos frequência, até uma vez por hora). Enquanto o servidor não pode ser alcançado, a linha dele em Configurações fica vermelha com "Couldn't connect as of ...".
  • Duplicados: um QSO que o seu Wavelog já tem conta como enviado.
  • Recusado: um QSO que o Wavelog recusa não é enviado de novo até você editá-lo ou reenviá-lo; o editor de QSO mostra o motivo. Uma chave que deixa de funcionar interrompe os envios até você tocar em VALIDAR novamente.
  • Confirmações: uma vez por hora (e quando você toca em ENVIAR AGORA) o qFT8 pergunta ao Wavelog quais dos seus QSOs estão confirmados (LoTW, QSL em papel, eQSL) e os marca nas linhas Enviado e Status do editor de QSO, as mesmas linhas e marcas de QRZ e LoTW.
  • Edições: com o Token de edição definido, um QSO editado é encontrado no seu Wavelog e atualizado lá (vale a alteração mais recente; as marcas de confirmação que o Wavelog guarda nunca são tocadas). Sem ele, a interface de envio do Wavelog só consegue adicionar QSOs, então uma edição não é enviada: altere-a também no Wavelog.
  • QSOs de outros indicativos: um QSO registrado com outro indicativo que não o seu (indicativo de clube ou de evento especial) fica retido para QRZ e LoTW, mas vai para o Wavelog enquanto Enviar também QSOs feitos com outros indicativos estiver marcado (o padrão).
  • Exclusões: o qFT8 nunca exclui nada no Wavelog. Exclua o QSO por lá mesmo.
  • "Considerar um QSO enviado se enviado aqui", na página, decide se um envio ao Wavelog conta para a marca de "enviado" (desativado por padrão).

Importando QSOs do Wavelog

IMPORTAR QSOs DO WAVELOG, na parte de baixo da página do Wavelog, copia os QSOs do local de estação escolhido para o log do qFT8, com suas confirmações LoTW, QSL em papel e eQSL.

  • O que é importado: todos os modos. De, Até, Bandas e O indicativo começa com limitam a importação (qualquer = sem limite). Os QSOs feitos com outro indicativo que não o seu são ignorados, a menos que Importar QSOs para indicativos diferentes do atual esteja marcado.
  • Já no log: um QSO que o log já tem é mesclado, nunca adicionado duas vezes (as mesmas regras das importações do QRZ e do LoTW); um QSO que você corrigiu aqui mantém a sua correção e recebe apenas as confirmações.
  • Nunca reenviados: os QSOs importados contam como já presentes no Wavelog. Uma correção que você fizer depois no qFT8 vai para lá (com o Token de edição).
  • PARAR encerra a importação depois da parte em andamento; o que já entrou permanece. A linha sob o botão conta o que foi recebido, adicionado e mesclado.
  • Nada é apagado, nem aqui nem no Wavelog. Um QSO que você apagou no qFT8 volta na próxima importação.

Conexões seguras

  • Prefira um endereço https://. Com http:// a chave trafega sem proteção: use apenas na sua rede doméstica.
  • O Android 6 e o 7.0 não confiam em alguns certificados mais novos que muitos desses servidores usam; nesses casos, um servidor https:// pode falhar ao conectar. Na sua rede doméstica, o endereço http:// do servidor funciona.
  • O iPhone se conecta apenas a endereços https://.

O Cloudlog é o programa do qual o Wavelog surgiu: um diário de bordo em um servidor web próprio. É um serviço separado no qFT8, com configurações próprias, configurado exatamente como o Wavelog (no Cloudlog: menu da conta > API > criar uma chave com direitos de leitura e gravação). Diferenças em relação ao Wavelog

  • Importação: o Cloudlog não pode ser lido por outros programas. Para trazer o log dele para o qFT8, exporte um arquivo ADIF no Cloudlog e use IMPORTAR QSOs DO ADIF em Configurações > Importar/Exportar logs (veja ADIF).

eQSL

O eQSL (eqsl.cc) troca cartões QSL eletrônicos: cada QSO enviado para lá vira um cartão na caixa de entrada do eQSL da outra estação. O qFT8 só adiciona cartões; nunca exclui nada no eQSL.

Configuração

  1. Toque na engrenagem da linha Sincronizar QSOs com eQSL no topo das Configurações.
  2. Digite seu Nome de usuário do eQSL (geralmente seu indicativo) e sua Senha do eQSL. Se você tem várias contas do eQSL (locais) sob um indicativo, digite o Apelido do QTH do local como está escrito em eqsl.cc; caso contrário, deixe vazio e o eQSL escolhe a conta pela data do QSO.
  3. Pressione VALIDAR. Ele só lê sua caixa de entrada do eQSL para verificar o login: nenhum cartão é enviado.
  4. Marque Sincronizar QSOs com eQSL. Os QSOs ainda não enviados saem de imediato, um por segundo, e cada novo QSO sai quando é registrado.

O que saber

  • Considerar um QSO enviado se estiver enviado aqui fica desativado para o eQSL: um cartão no eQSL não faz sozinho o visto verde do log aparecer (veja Serviços de envio de QSOs). Marque se quiser.
  • Um cartão não pode ser alterado. Quando você edita um QSO que já está no eQSL, nada é enviado sozinho. Para enviar um cartão corrigido, use Reenviar para eQSL no editor de QSO; o cartão antigo continua na caixa de entrada da outra estação até você excluí-lo em eqsl.cc.
  • LQ8: o eQSL aceita apenas os modos ADIF oficiais, então seus QSOs são enviados como MFSK, e o comentário informa o modo real (“QSO by qFT8, mode LQ8”). Os outros serviços mantêm sua própria forma.
  • Um QSO que o eQSL já tem é respondido como duplicado e conta como enviado. Um que ele recusa (por exemplo, uma data que nenhuma das suas contas cobre, ou um modo que ele não conhece) aparece como recusado no editor de QSO, com as palavras do próprio eQSL, e não é tentado de novo até você reenviá-lo.
  • Offline, ou enquanto o eQSL está fora do ar para manutenção, os cartões esperam e são tentados de novo mais tarde (após 1 minuto, depois mais tempo, até uma hora); o aviso vermelho Couldn't connect da linha diz desde quando. Se a senha for recusada (por exemplo, você a alterou em eqsl.cc), o envio para até você fazer VALIDAR de novo.
  • As confirmações (cartões recebidos) ainda não são lidas de volta.

O qFT8 como servidor Wavelog

Em Configurações > Servidores do qFT8 > Servidor Wavelog, o qFT8 responde na sua rede doméstica como se fosse um Wavelog: qualquer programa que consiga enviar QSOs ao Wavelog (inclusive outro qFT8) pode enviá-los a este qFT8.

Como configurar

  1. Ative Executar o servidor Wavelog, mantenha a Porta (13500) ou escolha outra, e digite uma Chave de API de pelo menos 8 caracteres (faça-a longa e aleatória: é a única coisa que mantém os outros de fora).
  2. No outro programa, configure o Wavelog com o endereço que a página mostra, escrito por inteiro: http://, o endereço deste dispositivo, dois-pontos e a porta, por exemplo http://192.168.1.20:13500/ (a maioria dos programas de log precisa do http:// e da porta digitados; outro qFT8 os encontra sozinho), a mesma chave e a estação 1 (em outro qFT8: VALIDAR a escolhe).

A porta pode ser alterada a qualquer momento: o servidor passa para a nova porta na hora (e para na hora quando é desligado).

Vendo o log em um navegador

Abra o mesmo endereço (http://192.168.1.20:13500/) em um navegador da sua rede doméstica: depois de digitar a chave do servidor, ele mostra o seu log de QSOs, do mais recente ao mais antigo, somente leitura; os QSOs mais antigos carregam conforme você rola, e os novos ou alterados aparecem sozinhos. A chave nunca é enviada: o navegador responde a um desafio de uso único com um valor feito a partir dela, e um endereço que responde errado fica bloqueado por um tempo. O servidor Cloudlog e o servidor de log do qFT8 mostram a mesma página em suas próprias portas, com sua própria chave ou senha.

O que ele faz

  • Todo QSO recebido, em qualquer modo e com qualquer indicativo, entra no log e na lista de QSO e segue para os serviços configurados aqui (QRZ, LoTW, Wavelog, ...), nunca de volta para onde veio. Um QSO que o log já tem é respondido como duplicado e não é encaminhado de novo.
  • Ele responde aos endpoints que um programa de registro usa: api/qso (um ou vários QSOs como ADIF), api/version, api/station_info, api/check_auth, api/auth, api/get_contacts_adif (para que um qFT8 mais adiante na cadeia possa ler as confirmações de volta) e api/radio (aceito e ignorado). Não há como alterar ou excluir um QSO por ele.
  • Segurança: somente rede doméstica, http simples (como o servidor web de controle remoto); a chave é comparada de um modo que não a vaza; um endereço que envia 10 chaves erradas é bloqueado por 10 minutos; no máximo 20 requisições por segundo por endereço, 128 KB e 500 QSOs por requisição; qualquer coisa malformada recebe uma resposta de erro.
  • Onde executa: no Android também em segundo plano quando "executar em segundo plano" está ativado; no computador enquanto o programa está aberto; no iPhone somente enquanto o qFT8 está aberto.

Cadeias

Servidores e serviços se combinam em cadeias: várias estações (celulares, computadores) enviam seus QSOs a um qFT8 que os reúne e é o único a enviar ao QRZ e ao LoTW; esse também pode encaminhar tudo a um Wavelog ou a outro qFT8 mantido como backup. As confirmações voltam pela cadeia: o qFT8 coletor as obtém do QRZ / LoTW / do seu Wavelog, e os qFT8 que enviam ao servidor Wavelog dele as leem de volta a cada hora. Duplicados nunca são encaminhados, então um laço em uma cadeia termina sozinho.

Summits On The Air (SOTA)

O qFT8 traz ferramentas completas e integradas para os caçadores (chasers) e para os ativadores do SOTA (Summits On The Air): busca automática de spots, acompanhamento das referências em tempo real, destaque das conquistas e filtros próprios de exportação ADIF.

Busca automática de spots de cumes ao vivo

Quando há acesso à internet, o qFT8 se conecta automaticamente à API oficial do SOTA em segundo plano (atualizando a cada 90 segundos) para obter as ativações de cumes em andamento no mundo todo.

  • Exibição no mapa mundial: os ativadores de cumes em atividade aparecem no mapa mundial com marcadores de cume (⛰️), indicativos, nomes dos cumes, altitudes e frequências.
  • Associação automática de referências: quando você ouve um ativador no ar, o qFT8 cruza o indicativo dele com a base de spots ao vivo para obter a referência exata do cume (por exemplo, HB/BE-001, W6/NC-001).
  • Preenchimento posterior automático: se você conclui um QSO com uma estação que chama CQ SOTA antes de o spot dela ter sido baixado ou de a referência ter sido recebida, o qFT8 acompanha os spots que chegam e preenche automaticamente a referência do cume nos QSOs registrados recentemente (até 1 hora antes).

Operar como caçador (chaser) SOTA

Para caçar estações que estão ativando cumes:

  1. Na aba Estações, escolha Caçador SOTA (ou Caçador POTA + SOTA) no menu suspenso de prioridade do alvo.
  2. Emblemas e coluna de referência: as estações SOTA em atividade (com spot online ou transmitindo CQ SOTA) são marcadas com um emblema SOTA na linha 2. Além disso, o cabeçalho da coluna DXCC muda para Referência SOTA e mostra diretamente o código do cume.
  3. Destaque de cumes trabalhados e por trabalhar:
    • Cume ainda não trabalhado: marcado com um emblema SOTA roxo vivo e com a referência em roxo, indicando um cume novo para caçar.
    • Cume já trabalhado: mostrado com um emblema cinza discreto, para você distinguir na hora os cumes novos dos que já estão no seu log.
  4. Caça em AUTO: no modo AUTO, o qFT8 dá prioridade automaticamente aos ativadores SOTA ainda não trabalhados em relação às estações comuns que chamam CQ, ordenando-os pelo sinal mais forte (SNR).

Gerenciar e editar referências SOTA no log

O qFT8 tem ferramentas próprias para consultar e editar seu histórico de caça SOTA:

  • Vista Caçador SOTA na aba Log de QSOs: na aba Log de QSOs, selecione a vista Caçador SOTA para ver as referências dos cumes. Os primeiros contatos confirmados com um cume são destacados em dourado, e as primeiras conquistas não confirmadas, em amarelo.
  • Editar referências de cumes: toque em qualquer QSO do log para abrir o editor de QSO e depois toque no campo SOTA dele para adicionar, alterar ou corrigir um código de cume (por exemplo, HB/BE-001).
  • Sincronização automática com o logbook do QRZ (ACTION=REPLACE): se o QSO já foi enviado ao QRZ, editar a referência do cume marca o registro automaticamente e atualiza seu logbook do QRZ no próprio registro, sem criar entradas duplicadas.
  • Nota sobre o LoTW: o LoTW (Logbook of The World) não é atualizado automaticamente quando você edita referências, porque o LoTW não permite modificar QSOs já enviados.

Operar como ativador SOTA

Para fazer uma ativação SOTA a partir de um cume:

  1. Sincronize a hora: verifique se o relógio do dispositivo está certo antes de sair para o campo.
  2. Inicie a ativação: na aba Configurações, toque em ATIVAÇÃO SOTA e informe seu cume, para que cada QSO seja registrado com ele e contado (veja Ativar um parque ou um cume).
  3. Defina seu modificador de CQ: na aba Configurações, defina o Modificador de CQ como SOTA. Cada chamada de CQ transmitirá CQ SOTA [Callsign].
  4. Configure o modo AUTO: na aba Estações, escolha Chamar CQ como prioridade do alvo e ative o modo AUTO.
  5. Comece a ativar: ligue o TX. O qFT8 chama CQ automaticamente e responde, um por um, aos caçadores que chamam.

Intervenção manual: se vários caçadores chamam você ao mesmo tempo e você quer escolher uma estação, toque em CALL na linha dela. Quando esse contato termina, o qFT8 volta automaticamente a chamar CQ.

Exportar seus logs SOTA (caçadores e ativadores)

O qFT8 gera exportações ADIF sob medida, tanto para os pedidos de caçador quanto para os logs de ativador:

  1. Vá em Configurações e toque em Exportação de arquivo ADIF.
  2. Para caçadores (chasers):
    • Defina Critérios de caçador como Exportar apenas caçador SOTA para exportar só os QSOs em que um cume foi contatado (com <SOTA_REF> preenchido).
  3. Para ativadores (o caminho mais rápido é o botão EXPORTAR da sua ativação; os passos abaixo fazem o mesmo à mão):
    • Selecione Período selecionado e ajuste-o às horas de início e de fim da sua ativação.
    • Em Evento, escolha SOTA e informe o código do cume ativado (por exemplo, HB/BE-001). O qFT8 insere sua referência em <MY_SOTA_REF> em cada registro.
  4. Cume a cume (S2S): se você trabalhou outro ativador enquanto ativava um cume, o qFT8 inclui no arquivo exportado tanto o seu cume de ativador (<MY_SOTA_REF>) quanto o cume do contato (<SOTA_REF>).
  5. Toque em EXPORTAR QSOs para compartilhar ou salvar o arquivo ADIF padronizado.

Ativar um parque ou um cume

Quando você opera de um parque (POTA) ou de um cume (SOTA), inicie uma ativação no qFT8. A partir daí, cada QSO que você registra, em qualquer modo, leva automaticamente o seu parque ou cume, o qFT8 os conta para você e, no fim, grava com um toque os arquivos que os programas pedem.

A seção Eventos das Configurações

As Configurações têm uma seção Eventos para eventos de operação. Hoje ela contém:

  • ATIVAÇÃO POTA e ATIVAÇÃO SOTA: ativar um parque ou um cume, descrito abaixo. A lupa ao lado de cada uma lista as suas ativações anteriores; a engrenagem, onde aparece, abre as configurações de anúncio do programa.
  • INICIAR CONTADOR: o contador de QSOs, para qualquer outro evento (um concurso, um dia de clube, uma estação de evento especial).

Caçar parques e cumes de casa é descrito nas seções de POTA e de SOTA.

Iniciar

  1. Na aba Configurações, toque em ATIVAÇÃO POTA ou ATIVAÇÃO SOTA (logo acima de EXPORTAR CONFIGURAÇÕES / IMPORTAR CONFIGURAÇÕES).
  2. Digite sua referência, por exemplo US-1234 para um parque ou W1/HA-001 para um cume. Se você está em vários parques ao mesmo tempo (um "two-fer"), separe-os com vírgulas. O qFT8 confere o formato enquanto você digita e oferece as referências que você usou recentemente.
  3. Toque em INICIAR. O botão fica azul e mostra a referência e o número de QSOs.

Uma ativação de parque e uma de cume podem estar abertas ao mesmo tempo; cada QSO recebe então as duas referências. Para chamar CQ POTA ou CQ SOTA nos modos digitais, ajuste o Modificador de CQ como descrito nas seções POTA e SOTA.

O qFT8 também pode se oferecer para iniciá-la por você: se os spots que ele baixa para o mapa mundial mostram o seu próprio indicativo como ativador, ele pergunta Iniciar uma ativação POTA lá? E se você digita seu parque ou cume na caixa vazia Meu POTA / Meu SOTA do registro manual, ele pergunta se deve iniciar uma ativação com ela.

Anunciar, para os caçadores encontrarem você

Quando você inicia uma ativação por conta própria (não a partir de um spot que já anunciou você), o qFT8 pergunta Anunciar no POTA? (ou no SOTA) e mostra o que os caçadores veriam, por exemplo FT8 on 20m (14074 kHz). AGORA NÃO não anuncia nada. ANUNCIAR abre um diálogo curto:

  • Bandas e Modos: marque um ou mais de cada. A banda e o modo em que o qFT8 está já vêm marcados. O qFT8 envia um anúncio para cada parque, banda e modo escolhidos e diz quantos são antes de você apertar ANUNCIAR.
  • Os modos que o programa não lista são anunciados como DATA, com o modo real no comentário do anúncio. Uma banda e um modo sem frequência habitual (RTTY em 60 m) ficam de fora, e o diálogo avisa.
  • A frequência é onde está o seu rádio para a banda e o modo em que você está, e a frequência de chamada habitual para os outros.
  • Só SOTA: o diálogo também pede seu nome de usuário e senha do SOTAwatch (seu próprio login do SOTA). O qFT8 guarda os dois para a próxima vez, como as senhas dos outros serviços.

Depois disso, o qFT8 anuncia a ativação de novo a cada 30 minutos (os anúncios somem da lista após cerca de uma hora), enquanto a ativação estiver aberta e o qFT8 estiver funcionando: na tela, ou minimizado com o qFT8 rodando em segundo plano e o rádio conectado. Para quando você finaliza a ativação e nunca anuncia por conta própria se o qFT8 estava fechado: na próxima abertura, depois que você escolher continuar a ativação, ele pergunta Anunciar de novo?

Se um anúncio não chega (sem internet, o site o recusa ou o login do SOTA está errado), o qFT8 diz o que deu errado e oferece TENTAR DE NOVO, ou ANUNCIAR NA MÃO, que abre a página de spots do programa no navegador para você anunciar por conta própria. Sem conexão, ele também tenta de novo sozinho a cada 5 minutos.

Para anunciar com outras bandas ou modos, ou para ver quando foi anunciado pela última vez, aperte ANUNCIAR no cartão da ativação (toque no marcador azul) ou na visão de QSOs da ativação. O diálogo então também oferece PARAR DE REANUNCIAR. Quando você troca de modo durante uma ativação anunciada, o qFT8 pergunta se o novo modo também deve ser anunciado.

Enquanto está aberta: o marcador azul

Um marcador azul POTA ou SOTA fica no canto inferior direito da cascata enquanto a ativação está aberta, com o número de QSOs da ativação ao lado da palavra: POTA 10. Cada QSO que você registra conta uma vez: trabalhar de novo a mesma estação na mesma banda e no mesmo modo é uma duplicata e não é contado. O número volta a diminuir quando um QSO é removido da ativação, excluído ou desfeito no registro manual. Em POTA ele recomeça do zero às 00:00 UTC. Com dois parques ao mesmo tempo continua havendo um só número, porque cada QSO conta para os dois parques. Onde há pouco espaço, o marcador mostra só o número ao lado do ícone, e onde nem isso cabe ele é desenhado menor, junto com o aviso vermelho que divide a linha com ele. Toque nele para ver o estado da ativação:

  • A referência e a contagem: os QSOs contados até agora, mostrados em relação a 10 para um parque ou 4 para um cume, e quantos deles foram com outro parque ou cume (P2P / S2S).
  • VER ATIVAÇÃO: a lista dos QSOs dela (abaixo).
  • TERMINAR ATIVAÇÃO: encerra a ativação. Sempre pergunta antes, com CONTINUAR para seguir em frente.
  • FECHAR: fecha o cartão.

Os QSOs da ativação

  1. Voltar ao log completo de QSOs.
  2. A ativação: programa e referência, quando começou (UTC) e os QSOs dela.
  3. +: abre o registro manual para registrar um QSO à mão diretamente nesta ativação.
  4. ADICIONAR QSOs: adiciona QSOs que já estão no seu log, por intervalo de tempo. Use quando tiver esquecido de iniciar a ativação: escolha de quando até quando, e o qFT8 diz quantos QSOs vai adicionar antes de fazê-lo.
  5. EXPORTAR: grava os arquivos para enviar (abaixo).
  6. O parque ou o cume da outra estação, quando ela também estava ativando.
  7. O marcador da ativação aberta.

Para tirar QSOs de uma ativação, mantenha um pressionado para selecioná-lo, toque nos outros, toque em AÇÕES e escolha REMOVER DESTA ATIVAÇÃO. Os QSOs ficam no seu log; apenas a sua referência é removida deles. Você também pode mover um único QSO a partir do editor de QSO, com a linha Ativação POTA / Ativação SOTA.

Terminar e retomar

TERMINAR ATIVAÇÃO mostra um resumo: referências, hora de início e de fim e QSOs por modo. Os QSOs registrados depois de terminar não fazem parte dela.

  • Terminou por engano, ou voltou depois de uma pausa? Por 24 horas, o resumo, a lista da ativação e o diálogo de início de ATIVAÇÃO POTA / ATIVAÇÃO SOTA oferecem RETOMAR ATIVAÇÃO, que a abre de novo como se nada tivesse acontecido.
  • Um novo dia UTC. No POTA, cada dia UTC é uma ativação separada. Depois da meia-noite UTC o qFT8 oferece INICIAR NOVA no mesmo parque em vez de retomar.
  • Ficou aberta. Se o qFT8 ficou fechado por um tempo, ou passou muito tempo sem nenhum QSO, na próxima inicialização ele pergunta se você quer CONTINUAR ou terminar.

Exportar

EXPORTAR (no resumo e na lista da ativação) grava arquivos ADIF com o nome que cada programa espera, prontos para enviar no site dele:

  • POTA: um arquivo para cada parque e cada dia UTC, com o nome CALLSIGN@PARK-DATE.adi (por exemplo K1ABC@US-1234-20261006.adi). Um two-fer dá um arquivo por parque. Uma estação que estava ela própria em dois parques é escrita uma vez para cada um dos seus parques, de modo que ambos contam como parque a parque.
  • SOTA: um arquivo para o cume, com o nome formado da mesma maneira (K1ABC@W1_HA-001-20261006.adi).

Você pode salvar os arquivos ou compartilhá-los. O botão da lupa ao lado de ATIVAÇÃO POTA / ATIVAÇÃO SOTA nas Configurações lista as suas ativações anteriores, da mais recente para a mais antiga, e marca cada uma como ATIVA, PODE SER RETOMADA, EXPORTADA ou não exportada; toque em uma para abri-la e exportá-la de novo. O qFT8 não envia nada por conta própria aos sites dos programas.

Vários parques em sequência

Em um dia com vários parques, um depois do outro, cada parque é a sua própria ativação e o seu próprio arquivo:

  1. No primeiro parque, toque em ATIVAÇÃO POTA nas Configurações, digite a referência dele e toque em INICIAR.
  2. Opere. Cada QSO recebe o parque, e o marcador azul os conta.
  3. Antes de sair, toque no marcador e em TERMINAR ATIVAÇÃO, depois em EXPORTAR no resumo, e salve ou compartilhe o arquivo (K1ABC@US-1234-20261006.adi).
  4. No parque seguinte, comece de novo com a nova referência.

Não há nada para redigitar nem para organizar em casa. Se você não tiver tempo de exportar em campo, a lista de ativações anteriores (a lupa) exporta cada uma mais tarde.

"Qual parque vai no arquivo?"

O arquivo de um parque só pode citar um parque. Quando você exporta QSOs que foram feitos de vários parques ao mesmo tempo sem passar por uma ativação (o log inteiro a partir das Configurações, ou Exportar (ADIF) em uma seleção), o qFT8 pergunta Qual parque vai no arquivo? Escolha o parque a que este arquivo se destina; exporte de novo para o outro. O log não é alterado. A exportação a partir da própria ativação nunca pergunta: ela grava um arquivo por parque.

Para obter um arquivo para cada parque sem uma ativação, digite você mesmo os parques, separados por vírgulas (US-1234, US-5678), na caixa Referência POTA de IMPORTAR/EXPORTAR LOGS ou em Exportar com uma referência POTA em uma seleção: o qFT8 grava um arquivo por parque, com os mesmos QSOs em cada um. Um cume é sempre uma única referência.

Quando a estação que você trabalha está em dois parques ao mesmo tempo, o qFT8 guarda os dois: ele lê o segundo parque no comentário do spot, quando quem fez o spot o escreveu lá. O log mostra o primeiro parque e quantos mais existem (US-1234 +1). Se um parque está errado ou faltando, corrija o campo POTA do QSO no editor de QSO; ele aceita vários parques separados por vírgulas. Um parque citado duas vezes para a mesma estação (no spot e de novo no comentário, ou duas vezes em uma lista digitada) conta uma só vez, no log e em cada arquivo exportado.

O contador de QSOs

Para qualquer outro evento, INICIAR CONTADOR na seção Eventos conta cada QSO que você registrar a partir dali. Enquanto conta, o botão fica azul e mostra CONTADOR 12, e o mesmo rótulo azul aparece no canto inferior direito da cascata. Um toque em qualquer um dos dois encerra a contagem; nada fica guardado depois. A contagem continua se o app for fechado e aberto de novo.

JS8 (chat de teclado)

O JS8 serve para conversas digitadas no teclado: texto livre de qualquer tamanho, mensagens para uma estação ou para um grupo e perguntas curtas que o programa da outra estação responde sozinho. Uma mensagem mais longa que uma transmissão é cortada em quadros e enviada um quadro por intervalo de tempo; a estação receptora junta os quadros de novo em uma só mensagem.

Escolha JS8 no seletor de modo da barra inferior. A aba Estações vira o painel do chat JS8, e o botão de velocidade (item #11) ocupa o lugar do botão de sequência na barra inferior. O espectrograma, o seletor de banda, o botão principal TX ON / TX OFF e a barra vermelha da sua frequência de transmissão funcionam como no FT8.

O painel do chat JS8

Da esquerda para a direita e de cima para baixo:

  1. AUTO: Respostas automáticas, ligadas (verde) ou desligadas (preto); ligadas por padrão. Com AUTO ligado e o botão principal em TX ON, o qFT8 responde às perguntas que outras estações enviam a você (veja Respostas automáticas). O AUTO nunca liga o seu transmissor.
  2. Chat JS8: O título do painel.
  3. Solicitação: Abre a lista de perguntas padrão para enviar ao chat aberto (veja Perguntas a outras estações). Fica cinza em um chat com um grupo diferente de @ALLCALL.
  4. QSO: Registra um QSO com a estação cujo chat está aberto (veja Registrar um QSO JS8). Fica cinza em [GLOBAL] e nos chats de grupo.
  5. CQ: Envia uma chamada geral para @ALLCALL: CQ seguido dos quatro primeiros caracteres do seu localizador, por exemplo CQ JN47.
  6. +: Abre Adicionar chat, onde você digita um indicativo ou um grupo (@NAME) para iniciar um chat com ele, mesmo antes de se ouvir qualquer coisa dele.
  7. As mensagens: As mensagens do chat aberto, a mais nova embaixo. Acima de cada uma: a banda, a frequência de áudio, a intensidade do sinal (nas mensagens recebidas), a data e a hora UTC. Suas próprias mensagens são verdes; as mensagens para você são azuis; as outras são azul-acinzentadas. Uma mensagem esperando o seu intervalo é amarelo-escura, e a que está no ar tem uma borda dourada e começa com TX (sending 2/5)...: enquanto os quadros saem, com a parte já enviada ficando verde.
  8. A lista de chats: Os chats que você pode abrir (veja A lista de chats). O chat aberto fica destacado em azul; um chat com mensagens ainda não lidas fica âmbar.
  9. A caixa de mensagem: Onde você digita. As letras viram maiúsculas; até 100 caracteres.
  10. A seta de envio: Envia o que você digitou ao chat aberto. Com a caixa vazia, não faz nada.
  11. O botão de velocidade na barra inferior: Slow, Normal, Fast, Turbo ou Ultra (veja Velocidades).

Enquanto o botão principal diz TX OFF, uma linha vermelha sobre a caixa de mensagem diz Ligue o TX para iniciar a transmissão quando há uma mensagem esperando, ou Ligue o TX para permitir a operação AUTO quando o AUTO está ligado. As mensagens enviadas com TX OFF ficam esperando no chat; nada vai ao ar até você apertar o botão principal.

Velocidades

Cada velocidade tem o seu próprio intervalo de tempo. Velocidades menores usam menos largura de banda e decodificam sinais mais fracos; as maiores enviam mais texto por minuto. O qFT8 recebe só a velocidade escolhida com o botão de velocidade, então escolha a mesma velocidade das estações com que quer falar (Normal é a mais usada).

Os nomes das velocidades ficam em inglês em todos os idiomas. Cada quadro leva 75 bits; quanto texto cabe em um quadro depende das palavras, porque as palavras comuns são enviadas em um código mais curto.

A lista de chats

De cima para baixo:

  • [GLOBAL]: Tudo o que foi decodificado na banda e tudo o que você envia. Uma mensagem enviada daqui vai para @ALLCALL, a menos que você mesmo a comece com um indicativo ou um grupo; digitar só HB ou HEARTBEAT envia um heartbeat (veja Respostas automáticas).
  • @ALLCALL: Mensagens para todas as estações.
  • Seus grupos (@NAME): Os grupos em que você entrou, mesmo um ainda sem tráfego.
  • Chats de indicativo: Um chat por estação que escreveu para você, para a qual você escreveu ou que você abriu com +.
  • Grupos ouvidos: Abaixo de uma linha fina e esmaecidos, os grupos ouvidos na banda em que você não entrou. Sobre um grupo assim aparece uma faixa dizendo Você não faz parte deste grupo, com Entrar no grupo. Enviar uma mensagem a um grupo ouvido faz você entrar nele.

Um toque longo em um chat (no computador: um clique com o botão direito) abre as suas opções: Entrar no grupo ou Sair do grupo (só para grupos; nunca para @ALLCALL), Exportar (salvar localmente) e Exportar (compartilhar) (as mensagens dele em um arquivo de texto), Limpar (apaga as mensagens dele), Limpar e fechar (também o tira da lista; um grupo é deixado), Limpar todos os chats e Limpar e fechar todos os chats. [GLOBAL] e @ALLCALL não podem ser fechados.

Não é privado: toda mensagem JS8 vai ao ar em aberto. Um chat de indicativo só organiza as mensagens para você; qualquer pessoa na frequência pode lê-las.

Enviar uma mensagem

  1. Abra o chat: uma estação, um grupo, @ALLCALL ou [GLOBAL].
  2. Escolha a sua frequência de transmissão no espectrograma, em um ponto livre, como no FT8.
  3. Digite o texto e aperte a seta de envio. A mensagem aparece no chat, esperando o próximo intervalo.
  4. Aperte o botão principal para que ele mostre TX ON. Os quadros saem um por intervalo; a mensagem mostra quantos já foram enviados. Várias mensagens saem uma depois da outra.

Uma mensagem esperando ou no ar tem um x ao lado: ele abre Abortar transmissão? com Abortar mensagem e, quando há mais de uma esperando, Abortar todas as mensagens. TX OFF também interrompe a mensagem que está no ar.

Uma mensagem longa mantém o rádio em transmissão por muitos intervalos seguidos. Quando ela o manteria em transmissão por mais tempo do que o Limite de transmissão contínua do rádio permite, o qFT8 pergunta uma vez, antes do primeiro quadro: Enviar com pausas (alguns intervalos ficam vazios para o rádio descansar; a outra estação ainda recebe uma só mensagem), Encurtar (volta ao texto, com a parte que teria de esperar selecionada) ou Cancelar. Sempre enviar mensagens JS8 longas com pausas nessa pergunta (e nas Configurações) deixa de fazer a pergunta.

O JS8 precisa de um indicativo padrão: no JS8, as Configurações avisam Este indicativo não é padrão e não cabe no JS8. quando o seu não pode ser enviado.

Tocar em uma mensagem

Um toque em uma mensagem recebida ou enviada (no computador: um clique duplo) abre os detalhes dela: a data e a hora UTC, quem a enviou e para quem, a banda, a frequência, a velocidade, a intensidade do sinal, o localizador e a distância quando conhecidos, e o texto. Abaixo deles, as ações:

  • Para uma mensagem recebida: RESPONDER (só para uma pergunta a você: envia a resposta), o grupo para o qual foi enviada (abre esse chat), Chat (abre o chat com quem enviou), Ajustar desvio de tempo (corrige o seu relógio pelo tempo dessa estação; não no computador) e Excluir.
  • Para uma mensagem sua: Reenviar (põe o texto dela de volta na caixa de mensagem, no chat dela), Chat ou o grupo, Ajustar desvio de tempo e Excluir.

Uma pergunta para você que ainda não foi respondida também mostra uma pequena seta ao lado: um toque envia a resposta na hora. No computador, um clique simples em uma mensagem coloca o indicativo de quem a enviou na caixa de mensagem.

Cores dentro do texto: o seu indicativo é vermelho, os nomes de grupo são laranja, as perguntas e os comandos (SNR?, GRID? ...) são amarelos, os caminhos de retransmissão (>CALL>) são verde-azulados, e a marca ◇ que termina uma mensagem é ciano. Um ~ em laranja marca um quadro que não foi recebido, para você saber que falta uma parte do texto.

Perguntas a outras estações

Solicitação envia uma das perguntas padrão do JS8 ao chat aberto (a partir de [GLOBAL]: para @ALLCALL):

  • SNR? e HW CPY?: com que força você é recebido lá.
  • INFO? e STATUS?: os textos de info e de status da estação.
  • GRID?: o localizador dela.
  • HEARING?: quais estações ela ouve.
  • AGN?: pede para repetir a última mensagem.
  • QSL?: pergunta se a sua mensagem foi recebida.
  • QUERY CALL: pergunta se ela ouve um indicativo que você digita.
  • QUERY MSGS: pergunta se ela guarda mensagens para você.
  • @HB HEARTBEAT: avisa a todos que você está no ar, com o seu localizador.

Você também pode digitar outros comandos JS8 por conta própria, por exemplo MSG TO:, ou um spot para a rede APRS: @APRSIS GRID JN47AB. Um caminho de retransmissão como K1ABC>W9XYZ HELLO é enviado como você o digita; o qFT8 não retransmite mensagens para outras estações e não guarda mensagens para elas.

Respostas automáticas (AUTO)

Com AUTO ligado e o botão principal em TX ON, quando uma pergunta para o seu indicativo foi recebida por inteiro, o qFT8 põe a resposta na fila e a envia no próximo intervalo:

  • SNR? ou HW CPY?: SNR -08 (com que força essa estação é recebida aqui).
  • GRID?: os quatro primeiros caracteres do seu localizador.
  • INFO? e STATUS?: os seus textos das Configurações (USING QFT8 até você os mudar).
  • HEARING?: até quatro estações ouvidas nos últimos 10 minutos.
  • QSL?: QSL. QUERY CALL: YES com a intensidade do sinal e há quanto tempo, se essa estação foi ouvida na última hora, senão NO. QUERY MSGS: NO MSG.
  • Um heartbeat de outra estação (@HB HEARTBEAT): HEARTBEAT SNR -08.
  • SNR? ou GRID? enviado a um grupo em que você entrou; nunca uma pergunta a @ALLCALL ou a um grupo de que você não faz parte.

A mesma pergunta não é respondida duas vezes enquanto a resposta ainda está esperando, e as suas próprias mensagens nunca são respondidas. O qFT8 não envia heartbeats nem CQ por conta própria: só os envia quando você aperta CQ ou os escolhe em Solicitação. O AUTO no JS8 é separado do AUTO no FT8.

Registrar um QSO JS8

O JS8 não tem uma sequência fixa de mensagens, então um QSO é registrado quando você decide que está completo. Abra o chat da estação e aperte QSO: Registrar QSO JS8 pergunta Registrar QSO JS8 com K1ABC? (e diz quando foi feito o último registro em JS8 de um QSO com essa estação, se houver). Registrar QSO o grava no log com o modo JS8, a banda e a frequência, a hora, o localizador da estação quando foi ouvido, e os reports trocados no chat como números de dois dígitos com sinal (+05, -12). Do log ele é enviado como qualquer outro QSO, e o chat da estação na lista mostra um visto (registrado), um visto com um relógio (esperando para ser enviado) ou uma estrela (confirmado).

WSPR e FST4W (balizas)

O WSPR não é para conversas: cada estação transmite uma baliza curta com o seu indicativo, o seu locator e a sua potência, e escuta as outras. O resultado é uma lista de quem você ouve e, pelo WSPRnet e pelo PSKReporter, um mapa de quem ouve você. Uma transmissão WSPR dura 110,6 segundos e começa um segundo depois de um minuto UTC par; a banda funciona, portanto, em janelas de 2 minutos. O FST4W é um modo de baliza do mesmo tipo, com janelas mais longas (veja FST4W neste painel).

Escolha WSPR no seletor de modo da barra inferior. A aba Estações vira o painel WSPR (no controle remoto web a aba se chama Modo WSPR), o espectrograma rola devagar, no ritmo das janelas de 2 minutos, e a parte do espectrograma fora de 1400–1600 Hz fica escurecida: todos os sinais WSPR da banda ficam nesses 200 Hz.

O painel WSPR

Da esquerda para a direita e de cima para baixo:

  1. BEACON: Liga (verde) e desliga (preto) a sua própria baliza. Com a baliza ligada, o qFT8 transmite em parte das janelas, tantas quantas o percentual de transmissão (item 2) indicar. A baliza nunca liga o seu transmissor sozinha: enquanto o botão principal da barra inferior mostrar TX OFF, nada é transmitido e uma linha vermelha diz Ligue o TX para iniciar a transmissão.
  2. TX: 20%: A parcela das janelas em que a baliza transmite. Um toque abre Percentual de Tx WSPR: 0% (Apenas Rx), 10%, 20%, 25%, 33%, 50% ou 100% (Contínuo). As janelas são sorteadas, uma a uma, para que duas estações com a mesma configuração não transmitam sempre juntas; 20% significa, em média, uma janela em cada cinco, cerca de uma transmissão a cada 10 minutos. O valor fica vermelho quando o limite de transmissão contínua do rádio permite menos janelas: a baliza então espera e transmite na próxima janela que puder usar.
  3. A potência (por exemplo 5 W): A potência que a mensagem da sua baliza informa às estações que ouvem você. Um toque abre Potência reportada:, uma lista de 1 mW (0 dBm) a 1000 W (60 dBm) nos degraus que o WSPR consegue transmitir. Ajuste para a potência que o seu rádio realmente entrega. É só um número na sua mensagem: o qFT8 nunca muda a potência do rádio, ela fica nos controles do próprio rádio.
  4. EXPORTAR: Salva os spots da lista em um arquivo ADIF. No celular, a caixa de diálogo Compartilhar log ADIF WSPR oferece Salvar localmente e Compartilhar; o computador pergunta onde salvar o arquivo; o iPhone abre o menu de compartilhamento; o controle remoto web baixa o arquivo para o aparelho que você estiver usando.
  5. LIMPAR: Esvazia a lista.
  6. A lista: Uma linha para cada sinal WSPR decodificado, o mais recente no topo: o indicativo, o país (DXCC), o locator (Grid), o SNR em dB (medido em 2500 Hz, como todo receptor WSPR informa), a potência que a outra estação informa, e a data e a hora UTC da sua janela (yyMMdd HH:mm). A lista é mantida quando o app é fechado; quantas linhas e por quanto tempo se define em Configurações > WSPR.
  7. A linha de status: O que vem a seguir: Ciclo de Rx termina em 01:12. Tx: Desativado enquanto a baliza não tem nada programado, Próxima transmissão em 05:40 enquanto espera a sua janela, Transmitindo — termina em 01:30 enquanto está no ar, e Transmissão desligada quando há uma transmissão programada mas o botão principal mostra TX OFF. Uma linha vermelha aqui quer dizer que a sua baliza não pode ser transmitida: Tx: configure o seu indicativo e grid (os dois são necessários, em Configurações), ou O indicativo é longo demais para transmitir WSPR / Tx: este indicativo não pode ser enviado em WSPR.
  8. Tx PRÓX: Transmite na próxima janela, seja qual for o percentual; depois a baliza continua como antes. Fica verde enquanto a próxima janela vai ser usada (também quando a baliza a escolheu), e um segundo toque desiste dessa janela. Fica cinza enquanto o botão principal mostra TX OFF.

A barra de mensagens da barra inferior mostra a mensagem que a sua baliza transmite: o seu indicativo, os quatro primeiros caracteres do seu locator e a potência do item 3, por exemplo HB9IPH JN47 37.

Recepção e baliza

  1. Escolha a banda no seletor de bandas: o rádio vai para a frequência WSPR da banda (veja abaixo). Para receber não é preciso mais nada: a cada 2 minutos, alguns segundos depois do fim da janela, os sinais decodificados entram na lista.
  2. Para transmitir a baliza, confira se o seu indicativo e o seu locator estão configurados e se A potência (item 3) é a que o seu rádio transmite. Escolha um percentual de transmissão (20% é o usual), deixe BEACON verde e aperte o botão principal da barra inferior até ele mostrar TX ON. A linha de status faz a contagem regressiva até a sua próxima transmissão.
  3. Para transmitir uma baliza agora, ou com a baliza desligada, aperte Tx PRÓX.
  4. Para parar, aperte de novo o botão principal (TX OFF) ou desligue BEACON. Uma transmissão no ar termina quando TX OFF é apertado.

Uma transmissão WSPR dura quase dois minutos: um rádio cujo limite de transmissão contínua é menor que isso não consegue transmiti-la, e o qFT8 avisa. No WSPR nada é registrado no log: os spots ficam na lista deste painel e não são QSOs.

Bandas e frequências

Cada banda do seletor de bandas tem uma frequência WSPR, de 2200 m a 13 cm: 2200 m 136.000 kHz, 630 m 474.200 kHz, 160 m 1.836600 MHz, 80 m 3.568600, 60 m 5.287200, 40 m 7.038600, 30 m 10.138700, 20 m 14.095600, 17 m 18.104600, 15 m 21.094600, 12 m 24.924600, 10 m 28.124600, 6 m 50.293000, 4 m 70.091000, 2 m 144.489000, 70 cm 432.300000, 23 cm 1296.500000 e 13 cm 2400.048000 MHz (banda lateral superior).

A sua baliza é transmitida na frequência de áudio escolhida no espectrograma, dentro de 1400–1600 Hz. Com Habilitar jitter aleatório de frequência (±60 Hz) ligado (o padrão), cada transmissão muda para um ponto aleatório até 60 Hz de distância, para você não cair sempre em cima da mesma estação.

Spots para o WSPRnet e o PSKReporter

  • Enviar relatórios para o WSPRnet (desligado por padrão; Configurações, Relatórios, e a engrenagem ao lado): as estações que você decodifica são enviadas ao WSPRnet, algumas de cada vez. A mesma estação na mesma frequência é enviada no máximo uma vez a cada 15 minutos. A página do WSPRnet tem também Enviar também os relatórios ao comunicar por alto-falante/microfone (desligado: nada é enviado enquanto o app escuta pelo microfone do celular em vez de um cabo), o Log recente de envios ao WSPRnet: com ENVIAR AGORA e LIMPAR LOG, e RESTAURAR PADRÕES.
  • Enviar relatórios para o PSKReporter (Configurações, Relatórios): envia também as suas decodificações WSPR e FST4W, como em todos os outros modos.
  • Baixar spots do WSPRnet (ligado por padrão; Configurações, Fontes de dados): busca quem recebeu a sua baliza e mostra essas estações no mapa-múndi com o botão SPOT dele.

Configurações > WSPR

A seção WSPR de Configurações > MODOS DIGITAIS tem:

  • Habilitar jitter aleatório de frequência (±60 Hz) (ligado): veja Bandas e frequências.
  • Armazenar até 1000 mensagens, e Armazenar mensagens por até 1 mês: quantas linhas a lista guarda, e por quanto tempo.
  • Início da decodificação (114000 ms): quando, dentro da janela de 2 minutos, a decodificação começa.
  • Início da transmissão (1000 ms): quando, dentro da janela, a baliza começa a transmitir.

FST4W neste painel

O FST4W (a linha FST4W (experimental) do seletor de modo) usa o mesmo painel: a mesma lista, BEACON, Tx PRÓX, a potência, EXPORTAR e LIMPAR, e os mesmos envios ao WSPRnet e ao PSKReporter. O que muda:

  • A janela é o Período: 120, 300, 900 ou 1800 segundos, escolhido na barra inferior ou em Configurações. Quanto mais longo o período, mais fracos os sinais que ele decodifica (cerca de -33 dB em 120 s, -45 dB em 1800 s) e mais tempo você transmite: até quase 30 minutos, o que o limite de transmissão contínua precisa permitir. As duas estações precisam usar o mesmo período.
  • O percentual de transmissão é próprio (Percentual de transmissão, 20 % por padrão): mudá-lo no FST4W não muda o do WSPR.
  • Ele só decodifica em torno da frequência de recepção (normalmente 1500 Hz), dentro da sua tolerância de recepção.
  • Em 2200 m, 630 m e 160 m ele tem frequências próprias (136.000 kHz, 474.200 kHz, 1.8368 MHz); nas outras bandas usa as frequências do WSPR.

As configurações dele estão descritas em Configurações > FST4W.

SSB (voz)

No modo SSB, o qFT8 é o microfone e o alto-falante do seu transceptor: o sinal que o rádio recebe vira voz no seu alto-falante ou nos seus fones de ouvido, e a sua voz vai do seu microfone para o rádio. O rádio continua conectado exatamente como para os modos digitais (o mesmo cabo USB, a mesma placa de som), de modo que não é preciso trocar nenhum cabo para passar de FT8 para voz e voltar.

Especificações: classe de emissão J3E da UIT (Regulamento de Radiocomunicações); a voz não tem protocolo digital.

O qFT8 gera o sinal de voz por conta própria e o envia pela placa de som do rádio. Ele coloca o rádio no seu modo de dados da mesma banda lateral (por exemplo USB-D / LSB-D, DATA-U / DATA-L, DIGU / DIGL; num QMX, o seu próprio modo USB ou LSB), assim o visor do rádio mostra a mesma frequência que o qFT8. A banda lateral segue a banda: LSB abaixo de 10 MHz, USB a partir de 10 MHz e em 60 m.

Escolha SSB com o seletor de modo da barra inferior. A área de mensagens, os botões de sequência e a barra do ciclo desaparecem (a voz não tem janelas de tempo), um botão USB / LSB aparece ao lado do seletor de modo, e a aba Estações se torna o painel SSB:

Estes são os componentes da tela de SSB, em detalhes:

  1. RX / TX / RX/TX: escolhe o que a roda de sintonia (item 12) move. Com RX/TX você recebe e transmite na mesma frequência. Com RX ou TX só essa se move, de modo que você pode escutar em uma frequência e transmitir em outra (split). Sem conexão CAT, esses botões ficam cinza e permanecem em RX/TX; um toque mostra A sintonia requer uma conexão CAT com o rádio.
  2. AUTO RIT: Mantém centralizada uma estação que está ligeiramente fora de frequência, para que a voz dela soe natural sem você tocar na roda.
  3. A engrenagem: Abre Configurações > SSB (veja abaixo). VOLTAR retorna a este painel.
  4. QSO: Abre o registro manual com o modo, a banda lateral e a frequência já preenchidos, para registrar o contato que você acabou de fazer (veja O registro manual). Um QSO por toque. Os reportes (59 / 59) também são preenchidos e, depois de um contato em split, tanto a frequência em que você transmitiu quanto a em que ouviu.
  5. Memórias de voz: As suas mensagens gravadas (uma chamada CQ, o seu indicativo...). Até você gravar uma, esta área mostra o link Configure as memórias de voz nas Configurações.
  6. IN: o nível do seu microfone e o controle deslizante do ganho dele. A linha marcada VOX é o nível que a sua voz precisa ultrapassar para acionar o rádio quando o VOX está ligado (item 10): arraste-a.
  7. OUT: O nível do áudio recebido e o controle deslizante de volume do seu alto-falante. As teclas de volume do celular fazem o mesmo. Bem no fim do controle o som fica desligado (MUTE).
  8. FILTER e NR: O filtro de recepção (desligado, 2,7, 2,4 ou 1,8 kHz) e a redução de ruído (desligada, 1, 2 ou 3). Cada toque passa para o valor seguinte. Esses rótulos são iguais em todos os idiomas.
  9. PTT: apertar para falar. Mostra "segure para falar" ou "toque para falar", conforme a configuração Modo PTT, e "NO AR" enquanto você está transmitindo. Com um teclado (o computador, o controle remoto pela web, um celular ou tablet), a barra de espaço faz o mesmo enquanto o último lugar em que você clicou ou tocou for a barra inferior, o espectrograma, o mapa-múndi ou este painel; numa caixa de texto ela continua digitando um espaço. Durante a transmissão ele também mostra os segundos restantes quando há um limite (veja abaixo). Quando o VOX atingiu o limite ele mostra "VOX em pausa", e "Sem SSB" quando o rádio não pode transmitir voz a partir do app.
  10. VOX: Quando ligado, o rádio é acionado pela sua voz em vez do botão PTT.
  11. USB / LSB: A banda lateral. Ela é escolhida para você quando você muda de banda (LSB abaixo de 10 MHz, USB acima); um toque a troca, e a frequência que você lê continua a mesma. Em 60 m também é USB, e uma troca de banda feita no botão do próprio rádio também escolhe a banda lateral da banda.
  12. A roda de sintonia: Em SSB a escala de frequência do espectrograma é uma roda. Deslize o dedo ao longo dela para sintonizar o rádio; um deslize mais rápido dá passos maiores. Um toque não faz nada, de modo que a frequência nunca salta por acidente. No computador a roda do mouse também sintoniza (segure Shift para passos de 1 Hz). A sintonia precisa de uma conexão CAT com o rádio.
  13. Frequência e banda: A frequência que você diria no ar (a portadora), e a banda. A linha laranja e a etiqueta RX/TX abaixo dela marcam a parte do espectrograma em que você está escutando e transmitindo. Um toque na frequência abre Frequência do rádio (kHz) para digitar uma; uma frequência de outra banda troca a banda. Isso também precisa de CAT.

Com um QMX ou QMX+, uma linha cinza acima do botão PTT lembra que a fonte de áudio SSB do rádio (seu menu SSB > Input) deve ser a placa de som USB (veja O que o SSB precisa).

Falar

  1. Arme a transmissão com o botão TX da barra inferior. Como em todos os outros modos, nada é transmitido enquanto ele diz TX OFF: a linha vermelha Pressione TX ON para transmitir lembra você disso.
  2. Segure PTT e fale, depois solte. Ou ligue o VOX e simplesmente fale.
  3. Para enviar uma memória de voz, toque nela. Com TX ON ela é transmitida, e você também a ouve no seu alto-falante. Com TX OFF ela só é tocada para você, o que é uma boa maneira de conferir uma gravação. Um toque longo (um clique com o botão direito no computador) sempre a toca só para você.
  4. Quando o contato terminar, toque em QSO para registrá-lo.

A sua própria voz ao vivo nunca é reproduzida no seu alto-falante. Se a frequência em que você vai transmitir está fora da banda de radioamador, o qFT8 não aciona o rádio e avisa.

Limite de transmissão: Toda transmissão SSB termina sozinha no limite de transmissão contínua do rádio (Configuração do dispositivo), ou depois de 3 minutos se o rádio não tiver limite. Com Tocar para alternar e com VOX, o botão PTT faz a contagem regressiva dos segundos restantes (com Segurar para falar e com as memórias de voz, só quando o rádio tem um limite). Depois do limite, o VOX fica em pausa pelo mesmo tempo, ou até você tocar em PTT. Isso protege o rádio de um microfone que fica ouvindo ruído.

Memórias de voz

Vá em Configurações > SSB > Memórias de voz (ou toque em Configure as memórias de voz nas Configurações no painel) e pressione GRAVAR UMA NOVA MEMÓRIA DE VOZ. Você pode salvar até 6 memórias de 30 segundos cada. Para cada uma você pode dar um nome, gravá-la de novo, ajustar o volume ou pressionar NORMALIZAR, e cortar o silêncio do início e do fim arrastando as duas alças sobre o desenho do som; REPRODUZIR toca a parte que você manteve, e nada muda até você salvar. As memórias fazem parte da exportação de configurações, gravações incluídas. Uma memória de voz grava a sua própria voz pelo seu microfone, não o som do rádio. O qFT8 não grava os seus contatos.

Configurações > SSB

  • Mecanismo de PTT: O botão PTT, ou o VOX.
  • Modo PTT: Segurar para falar ou Tocar para alternar.
  • Atraso do PTT: O tempo entre acionar o rádio e enviar a sua voz. Nada do que você diz se perde: a sua primeira sílaba espera pelo rádio.
  • Banda lateral: Automática pela banda, sempre USB ou sempre LSB. Uma mudança vale na hora, também enquanto você está em SSB.
  • Filtro e redução de ruído ao entrar em SSB.
  • Reproduzir o áudio recebido no alto-falante e Silenciar o alto-falante ao transmitir. A segunda fica sempre ligada enquanto o microfone e o alto-falante do próprio celular são usados, para que o celular não ouça a si mesmo.
  • Memórias de voz e RESTAURAR PADRÕES.

O que o SSB precisa

  • Um microfone e um alto-falante que não sejam a placa de som do rádio. Um celular tem os seus; um headset também serve. Veja Alto-falantes e microfone. Se o rádio e o seu microfone ou alto-falante são o mesmo dispositivo, uma linha vermelha avisa e nada é enviado nem reproduzido.
  • Um rádio. Sem ele, o painel é substituído por um cartão que diz Conecte um rádio para usar SSB; o painel volta sozinho quando o rádio é conectado. Um rádio sem CAT que é acionado pelo seu próprio VOX também funciona, mas nesse caso o aplicativo não consegue sintonizá-lo. O cartão tem um botão para Configuração do dispositivo. Sem CAT você sintoniza no botão do rádio: os botões RX / TX, a roda e o AUTO RIT ficam cinza. Outros cartões avisam quando nenhum microfone ou alto-falante foi escolhido, quando Duplex total está desligado em Configuração do dispositivo, ou quando o áudio do celular não consegue gravar e tocar ao mesmo tempo.
  • Um QMX ou QMX+ precisa do firmware 1_04_001 ou mais novo para transmitir voz a partir do app. Com firmware mais antigo, o botão PTT mostra Sem SSB, uma linha vermelha explica o motivo e o modo é só de recepção.
  • Num QMX o qFT8 coloca o SSB > Input do rádio em USB enquanto você está em SSB e devolve a sua própria escolha quando você sai; nada é gravado no rádio. Se o firmware não permitir, uma linha vermelha pede que você ajuste isso no menu do rádio. Se o rádio não emitir potência enquanto a sua voz chega a ele, uma mensagem lista o que verificar (SSB > Input, o ganho USB do rádio, o firmware).
  • Em alguns celulares o VOX não pode ser usado com um rádio USB, porque o celular não consegue ouvir o seu microfone e o rádio ao mesmo tempo; use ali o botão PTT.
  • Na primeira vez que você visita uma banda em SSB, o qFT8 sintoniza a frequência de voz usual dessa banda na sua parte do mundo; depois disso ele volta à última frequência que você usou ali. A banda de 30 m não tem segmento de voz e não é oferecida.
  • Se o qFT8 não puder mudar o modo do rádio (esse ajuste está desligado em Configuração do dispositivo) ou o comando de dados LSB do rádio não for conhecido, o rádio fica no seu modo de dados USB e o qFT8 gera o LSB por conta própria: nas bandas LSB o visor do rádio mostra então uma frequência 3 kHz abaixo da que o qFT8 mostra. De qualquer forma, fale no microfone escolhido em Alto-falantes e microfone e use o PTT do qFT8, não o do rádio.

Os QSOs são registrados como SSB com a sua banda lateral, e são enviados ao QRZ e ao LoTW como qualquer outro QSO.

No computador, no iPhone e no controle remoto pela web

  • O computador e o iPhone mostram o mesmo painel com os mesmos botões. No computador, um clique direito numa memória de voz a toca só para você, e a roda do mouse sobre o espectrograma sintoniza.
  • O controle remoto pela web não pode mudar o app para SSB. Enquanto o app está em SSB, a página mostra a cascata e três botões: Ouvir toca o áudio do rádio na página, Microfone torna o microfone do navegador o microfone do rádio, e PTT transmite (um toque liga, outro desliga; a barra de espaço faz o mesmo). Só transmite com TX ON no app. Os navegadores só dão o microfone a uma página num endereço seguro: ligue o endereço seguro (https) nos ajustes do servidor web e abra o link que a página mostra.

CW (código Morse)

No modo CW, o qFT8 lê todos os sinais de Morse da banda passante e escreve o texto deles sobre o espectrograma, e envia Morse com palhetas na tela, com os seus próprios manipuladores, com mensagens prontas ou com texto digitado. Com TX OFF tudo funciona como treino: você ouve a sua manipulação no alto-falante e nada vai ao ar.

Especificações: ITU-R Recomendação M.1677-1, “International Morse code” (2009).

O qFT8 envia o CW como um tom de áudio limpo e com envoltória suavizada, pelo modo de dados do rádio (por exemplo DIGU ou DIGL, USB-D ou LSB-D); por isso o rádio muda para esse modo durante a transmissão, e a recepção continua larga. A exceção é o QRP Labs QMX, que é manipulado em CW verdadeiro por CAT.

Escolha CW com o seletor de modo da barra inferior:

Estes são os componentes da tela de CW, em detalhes:

  1. AUTO: Deixa o qFT8 fazer sozinho QSOs completos em CW (veja AUTO em CW).
  2. RX / TX / RX/TX: Escolhe qual barra um toque na cascata ou a roda de sintonia move: a barra de recepção, a de transmissão ou as duas juntas. AUTO RIT, logo depois, leva a barra de recepção para uma estação que chama você (veja AUTO RIT).
  3. A engrenagem abre Configurações > CW, e QSO abre o registro manual com CW, a frequência e o alvo já preenchidos.
  4. Alvo: O indicativo da estação que você está trabalhando. Ele preenche a parte [TARGET] das suas mensagens. Toque nele para digitar um, ou toque em um indicativo na linha do decodificador (item 10) para pegá-lo de lá. Enquanto AUTO está ligado e TX desligado, uma linha cinza abaixo diz K1ABC está chamando você – pressione TX ON quando uma estação chama você.
  5. Memórias: mensagens prontas. Um toque envia uma. O seu próprio indicativo aparece em azul e o reporte em amarelo. Uma memória à qual ainda falta algo (um alvo, o seu nome...) fica esmaecida; toque nela para ver o que falta. Com AUTO RIT ligado, as linhas Seguir K1ABC +150 Hz? das estações que chamam você aparecem no topo desta lista.
  6. WPM e FARNSWORTH: A velocidade de envio em palavras por minuto, e a velocidade Farnsworth opcional (as letras mantêm a velocidade e os espaços entre elas ficam mais longos).
  7. FILTER, NR e SIDETONE: a largura do filtro de recepção em volta da barra de recepção, a redução de ruído e o volume do seu próprio tom de monitoração (veja Tom de monitoração).
  8. As palhetas: A esquerda envia pontos e a direita envia traços. Pressione as duas para os modos iâmbicos.
  9. A linha vermelha: Pressione TX ON para transmitir. Enquanto ela aparece, a sua manipulação é treino.
  10. A linha do decodificador: Fica onde no FT8 fica o seletor de mensagens. Mostra o texto da estação dentro do seu filtro em branco e o que você envia em verde, o mais recente à direita. Um toque num indicativo o oferece como alvo; um toque em qualquer outro lugar põe toda a conversa naquela frequência no lugar do espectrograma, o mais recente embaixo (arraste para ler o texto anterior), enquanto a linha do decodificador vira uma pequena cascata: um toque curto nela traz o espectrograma de volta, e segurar e arrastar para o lado muda a sintonia.
  11. Texto decodificado na cascata: Cada sinal tem seu texto escrito ao longo do próprio traço, então você lê a banda inteira de uma vez: a estação dentro do seu filtro em verde, o alvo em magenta, as outras em branco e o que você envia em amarelo; uma palavra que ainda está sendo relida aparece em itálico. O rótulo sob a barra de recepção mostra o indicativo e a velocidade da estação em que você está.
  12. A roda de sintonia: A escala de frequência. Deslize o dedo ao longo dela para mover a barra selecionada (e o rádio, quando a barra chega à borda). Um toque ou um arrasto na cascata move a barra diretamente.
  13. Ir para a frequência: Toque na faixa com a linha branca de intensidade de sinal para digitar uma frequência em kHz.

Enviar

Há quatro maneiras de enviar, e todas usam a velocidade definida com WPM:

  • As palhetas na tela, com um ou dois dedos.
  • Os seus próprios manipuladores: teclas do teclado, os botões do mouse (no computador, o botão esquerdo é a palheta esquerda e o botão direito a palheta direita), ou um adaptador de manipulador conectado por USB ou Bluetooth que se comporte como um teclado. Veja Palhetas e manipulador.
  • Uma memória: toque nela. Uma segunda memória tocada nesse meio-tempo espera a sua vez. Uma faixa com PARAR aparece enquanto um texto está sendo enviado, e tocar em uma palheta também o interrompe.
  • Teclado (no fim das memórias): digite uma mensagem e pressione ENVIAR. Uma linha abaixo da caixa mostra exatamente o que será enviado. No Android, Voz faz o mesmo a partir da fala: diga a mensagem e ela é enviada em Morse.

No ar, o CW é sempre um tom limpo com bordas suaves, seja qual for o tom lateral que você escolha ouvir. Como rede de segurança, um manipulador mantido pressionado por 10 segundos é solto, e uma transmissão é interrompida depois de 3 minutos.

Treino com TX OFF

Enquanto a barra inferior diz TX OFF, as pás, suas teclas, as memórias e a caixa Teclado funcionam, mas só no seu alto-falante. O que você manipula é decodificado e mostrado em verde na linha do decodificador, para você ver se sua manipulação é legível. Nada chega ao rádio. Nenhum rádio é necessário para isso.

Palhetas e manipulador

Em Configurações > CW, a seção Manipulador define como as palhetas se comportam:

  • Modo do manipulador: Manipulador vertical, Iâmbico A, Iâmbico B, as versões de um dedo de ambos, Ultimatic, Bug (semiautomático) e Cootie (sideswiper).
  • Velocidade, Farnsworth, Espaço entre palavras e Temporização rigorosa (espaços padrão entre letras e palavras).
  • Inverter palhetas: troca pontos e traços.
  • Atraso de break-in: quanto tempo o rádio permanece em transmissão depois do seu último ponto ou traço.
  • Igualar velocidade: envia na velocidade da estação que você está copiando.

A seção Entrada das palhetas define o que conta como palheta:

  • Palhetas: a chave geral. Desligada, não há palhetas na tela, e nenhuma tecla, botão do mouse ou adaptador pode acionar o transmissor.
  • Palhetas na tela, Botões do mouse, Teclas do teclado e Adaptadores externos (USB / Bluetooth): cada fonte pode ser desligada separadamente.
  • Mapeamento de teclas: Padrão usa uma lista pronta de teclas (entre elas [ e ], as teclas Ctrl esquerda e direita, F1 e F2). Com Personalizado você monta as suas próprias listas para a palheta esquerda e para a direita: pressione ADICIONAR TECLA e depois a tecla que você quer. Uma tecla que já está na outra palheta é recusada.

Enquanto uma caixa de texto está aberta, só as teclas Ctrl e F1 / F2 funcionam como palhetas, de modo que digitar um indicativo nunca envia Morse.

Manipular com um adaptador, o teclado ou o mouse

Não é preciso tocar na tela para enviar Morse. Quatro coisas podem servir de palhetas, e todas podem ser usadas ao mesmo tempo:

  • As palhetas na tela, com os dedos.
  • Um manipulador de verdade em um adaptador USB: uma caixinha ou um cabo com uma tomada para o manipulador de um lado e um plugue USB do outro. Para o celular ou o computador ele é um teclado (cada contato do manipulador pressiona uma tecla) ou um mouse (cada contato pressiona um botão do mouse). Os adaptadores Bluetooth funcionam do mesmo jeito.
  • Um teclado: uma tecla para a palheta esquerda e outra para a direita.
  • Um mouse: os seus botões esquerdo e direito.

Todos seguem o Modo do manipulador e a velocidade que você escolheu, e todos funcionam com TX OFF como treino (veja Treino com TX OFF).

Conectar um adaptador

  1. Ligue o seu manipulador ao adaptador, e o adaptador ao celular, ao tablet ou ao computador. Não é preciso instalar nada e o qFT8 não pede nenhuma permissão: o adaptador é um teclado ou um mouse comum. Em um celular cuja única porta USB está ocupada pelo transceptor, use um hub USB ou um adaptador Bluetooth.
  2. Abra a tela de CW e manipule. Um adaptador que se comporta como um teclado funciona na hora se enviar teclas da lista padrão abaixo (as mais comuns são as teclas Ctrl esquerda e direita, e [ e ]). Foi testado com o adaptador VBand original.
  3. Se nada soar, o adaptador envia outras teclas. Vá em Configurações > CW > Entrada das palhetas, pressione ADICIONAR TECLA em Palheta esquerda (ponto) e feche o contato dos pontos do seu manipulador; depois faça o mesmo em Palheta direita (traço) com o contato dos traços.
  4. Um adaptador que se comporta como um mouse precisa das palhetas na tela: deixe o ponteiro do mouse sobre a palheta esquerda e manipule. O mesmo vale para um mouse comum.

Um manipulador vertical, um de palhetas, um bug

O Modo do manipulador (Configurações > CW > Manipulador) decide o que os dois lados fazem, seja qual for o meio que você usa para manipular:

  • Manipulador vertical: um manipulador só, e você faz cada ponto e cada traço à mão. Só o lado da palheta esquerda manipula: ligue um manipulador vertical ao contato dos pontos do adaptador, ou coloque a tecla dele na lista Palheta esquerda (ponto). Na tela as duas palhetas viram um manipulador só.
  • Iâmbico A e Iâmbico B: para um manipulador de duas palhetas. O lado esquerdo faz pontos, o direito traços, e os dois juntos os alternam. Iâmbico A, um dedo e Iâmbico B, um dedo foram pensados para a tela, onde uma zona no meio vale como as duas palhetas (a largura dela é Zona central (modos de um dedo)).
  • Ultimatic: como um manipulador de palhetas, mas com os dois lados pressionados vence o que foi pressionado por último.
  • Bug (semiautomático): o lado dos pontos faz os pontos sozinho; o lado dos traços é um manipulador manual, e soa enquanto você o segura.
  • Cootie (sideswiper): os dois lados são o mesmo manipulador manual.

Deixar do seu jeito

Está tudo em Configurações > CW, na seção Entrada das palhetas:

  • Palhetas: a chave geral de tudo o que vem a seguir.
  • Palhetas na tela e Altura das palhetas: oculte as palhetas para deixar mais espaço para a cascata quando você só usa um manipulador de verdade, ou deixe-as mais altas para os seus dedos. O mouse precisa que elas estejam à mostra.
  • Botões do mouse: desligue se um clique nas palhetas não deve fazer nada.
  • Teclas do teclado e Adaptadores externos (USB / Bluetooth): quem pode manipular. Veja mais abaixo as diferenças entre o Android e o computador.
  • Mapeamento de teclas: Padrão é a tabela acima. Abaixo estão as duas listas, Palheta esquerda (ponto) e Palheta direita (traço). ADICIONAR TECLA espera você pressionar uma tecla (ou fechar um contato do seu manipulador) e a adiciona; a lixeira ao lado de uma tecla a remove. A primeira alteração passa o mapeamento para Personalizado, que começa como uma cópia das listas padrão. Voltar para Padrão não apaga as suas próprias listas. Você pode usar letras, algarismos, de F1 a F12, as setas, Ctrl, Shift, Alt, o teclado numérico, Espaço, Enter, Tab e as teclas de pontuação comuns. Uma tecla só pode estar em uma palheta.

Há mais duas opções na seção Manipulador: Inverter palhetas troca pontos e traços para todas as fontes de uma vez (para um manipulador ligado ao contrário, ou para um operador canhoto), e o Modo do manipulador está descrito mais acima. RESTAURAR PADRÕES, no fim da página, devolve todas as configurações de CW aos valores iniciais, inclusive as listas de teclas.

O Android e o computador

  • No Android há duas chaves: Teclas do teclado é o teclado do próprio aparelho, e Adaptadores externos (USB / Bluetooth) é qualquer teclado ou adaptador que você conecte ou pareie. Antes do Android 10, todo teclado físico conta como externo. Um mouse USB ou Bluetooth funciona sobre as palhetas como no computador.
  • No computador um adaptador é mais um teclado, por isso há uma chave só, Teclas do teclado, para os dois. As palhetas na tela são pressionadas com o mouse. As teclas só atuam enquanto a janela do qFT8 com a tela de CW é a janela ativa e nenhum diálogo está aberto.

Se algo não funcionar

  • Pontos e traços estão trocados: marque Inverter palhetas. Com o mouse, verifique se o ponteiro está sobre a palheta esquerda, e não sobre a direita.
  • Nada acontece quando você manipula: a tela de CW precisa estar à mostra, Palhetas e a chave da sua fonte precisam estar ligadas, e AUTO precisa estar desligado (a tela diz Desative AUTO para transmitir manualmente). No computador, clique antes na janela do qFT8. Depois verifique se a sua tecla está nas listas: pressione ADICIONAR TECLA e manipule. Se o diálogo não reagir, o adaptador envia uma tecla que não pode ser usada, ou não está conectado.
  • Você ouve o Morse mas o rádio não transmite: a linha vermelha diz Pressione TX ON para transmitir. Isso é treino.
  • Um manipulador vertical não faz nada no modo Manipulador vertical: ele está no lado da palheta direita. Passe-o para o da esquerda (veja acima).
  • Ao manipular, letras são digitadas em uma caixa em vez de serem enviadas: enquanto uma caixa de texto está aberta só as teclas Ctrl e F1 / F2 são palhetas, para que digitar um indicativo nunca envie Morse. Feche a caixa, ou dê ao seu adaptador uma dessas teclas.
  • Ao manipular, digita-se em outro programa: no computador as teclas vão para a janela ativa. Clique no qFT8.
  • O tom para enquanto você segura o manipulador: um manipulador mantido pressionado por 10 segundos é solto, com o aviso Manipulador pressionado por tempo demais: liberado.

Memórias, macros e prossinais

Edite as suas mensagens em Configurações > CW > Memórias (ADICIONAR MEMÓRIA, ou toque em uma para alterá-la). Dois tipos de palavras especiais podem ser usados em uma mensagem:

  • As macros, entre colchetes, são substituídas quando a mensagem é enviada: [MYCALL] o seu indicativo, [TARGET] o indicativo da caixa Alvo, [RST] o reporte a enviar, [NAME] o seu nome, [QTH] a sua localização, [EXCH] a sua troca do contest e [MYPOTA] o parque ou o cume da sua ativação aberta. O editor tem um botão para cada uma delas e mostra a mensagem exatamente como será enviada.
  • Os prossinais, entre colchetes angulares, são enviados como um único caractere, sem espaços: <BK>, <SK>, <KN>, <AR>.

O seu reporte, o seu nome, a sua localização e a sua troca são digitados uma única vez, na mesma página das Configurações. Uma mensagem pronta que precisa de um deles fica esmaecida até você preenchê-lo, e tocar nela leva você ao lugar onde fazer isso. Enquanto uma ativação POTA ou SOTA está aberta, uma mensagem CQ POTA é oferecida como primeira memória.

Receber

A decodificação é automática e acompanha a velocidade própria de cada estação. A estação que está dentro do seu filtro é a que é escrita na linha do decodificador da barra inferior; leve a barra de recepção para outro sinal para acompanhar esse outro (o que já tinha sido copiado nessa frequência aparece na hora). Quando há duas estações dentro do filtro, a barra inferior avisa. O sinal recebido é tocado no seu alto-falante no Tom do monitor que você escolher, o mesmo tom do seu próprio tom lateral, de modo que uma estação que soa na mesma nota do seu tom lateral está exatamente na sua frequência.

Configurações > CW tem também Tons (como soa o seu tom lateral: tom, volume, bordas suaves ou duras, um tom ou cliques de sounder), Decodificação e exibição (Decodificação automática, Multidecodificador para o texto de cada sinal na cascata, o espectrograma horizontal, o filtro ao entrar no modo), Monitor (alto-falante) e Prossinais e sinais.

Tom de monitoração

O tom de monitoração é o que você ouve da sua própria manipulação, no alto-falante ou nos fones do celular ou do computador. Ele nunca vai para o rádio. SIDETONE, o último botão da coluna da direita, mostra o volume; um toque abre um controle deslizante ao lado, Volume do tom lateral, e outro toque o fecha. É o mesmo ajuste que em Configurações > CW > Tons. Enquanto você transmite, as teclas de volume também mudam o tom de monitoração.

Em Tons você também escolhe Tom do monitor (a mesma altura do sinal recebido), Subida / descida do tom lateral, Onda do tom lateral e Som do tom lateral (Tom ou Cliques (sounder)). Isso só muda o que você ouve: no ar, o CW é sempre um tom limpo com bordas suaves. Manter alto-falante ativo mantém celulares e fones Bluetooth acordados entre os toques, para que o primeiro ponto não seja cortado; aumente se faltar o começo de um ponto. Para desligar o tom de monitoração ou o sinal recebido, use Reproduzir o que envia (tom lateral) e Reproduzir o sinal recebido no alto-falante em Monitor (alto-falante).

No iPhone não há tom de monitoração nem botão SIDETONE.

AUTO em CW

O botão AUTO, no canto superior esquerdo do painel, deixa o qFT8 fazer QSOs completos em CW. Ele está desligado toda vez que você entra no modo. Toque nele para ligá-lo (ele fica verde) e de novo para desligá-lo. Ele só envia enquanto o TX está em ON: o AUTO nunca arma a transmissão sozinho.

Enquanto ele está ligado, e o TX está em ON, o qFT8:

  • chama CQ quando a frequência está em silêncio, ou responde a um CQ que ouve;
  • troca reportes, nome e localização, se despede e registra o QSO;
  • pede de novo um indicativo ou um reporte que não conseguiu copiar, e atende aos pedidos de repetir ou de ir mais devagar;
  • nunca envia mais rápido que o seu WPM, e reduz para a velocidade da outra estação;
  • acompanha uma estação que deriva, não chama uma estação já trabalhada naquele dia e não começa em cima do QSO de outros;
  • nunca registra um QSO que não conseguiu completar.

Enquanto o AUTO está ligado as palhetas ficam desativadas e uma linha diz Desative AUTO para transmitir manualmente. PARAR também desliga o AUTO. Se você nunca o quiser, desligue Mostrar modo automático em Configurações > CW e o botão fica oculto.

AUTO RIT: seguir uma estação que chama você

Uma estação que responde ao seu CQ muitas vezes está um pouco fora da sua frequência. AUTO RIT, o botão depois de RX/TX, cuida disso. Fica desligado até você ligar, e o qFT8 lembra a sua escolha. Ligado, fica verde, e:

  • uma estação que chama você (o câmbio dela tem o seu indicativo e não é um CQ nem uma chamada para outra pessoa) dentro do seu filtro puxa sozinha a barra de recepção para ela. A barra de transmissão nunca se move: você continua transmitindo onde chamou;
  • uma estação que chama você fora do seu filtro é oferecida como uma linha no topo das memórias, Seguir K1ABC +150 Hz?, com a distância até a sua barra de recepção. SEGUIR leva a barra de recepção até ela, e o X remove a linha. São mostradas até três linhas, a mais recente primeiro; cada uma some um minuto depois da última chamada daquela estação;
  • enquanto você está num QSO com o seu alvo, outra estação que chama você só ganha uma linha; ela nunca tira a barra de recepção do seu correspondente.

AUTO RIT só move a barra de recepção. Nunca transmite, nunca liga TX, e nada ouvido enquanto você transmite conta.

Como o rádio é manipulado

  • A maioria dos rádios: o qFT8 envia o CW como um tom de áudio moldado para o modo de dados do rádio, então você ajusta o nível de transmissão com o volume de TX, como no FT8. O rádio vai para o modo de dados durante a transmissão e a recepção continua larga.
  • O QRP Labs QMX e o QMX+: o qFT8 manipula o rádio por CAT, elemento por elemento, e o rádio gera a própria portadora exatamente na sua frequência de transmissão. Ele fica o tempo todo no modo digital, nenhum áudio é enviado a ele e o volume de TX não importa. Seu tom de monitoração continua tocando no celular ou no computador, com a sua velocidade e o seu ritmo.

Nos dois casos, STOP ou TX OFF no meio de um ponto ou traço o termina de forma limpa e o rádio volta para a recepção. Enquanto o qFT8 transmite, o botão de TX mostra que está transmitindo.

Registrar um QSO em CW

QSO, no canto superior direito do painel, abre o registrador já preenchido: modo CW, a banda e a sua frequência de transmissão (e a de recepção quando as duas barras estão separadas), o indicativo de Alvo e as reportagens. São as reportagens realmente trocadas quando o AUTO trabalhou aquela estação; senão, a reportagem enviada é o seu Reporte a enviar [RST] (ou, se estiver vazio, a medida do sinal) e a recebida é a lida da manipulação da outra estação. O parque ou cume de uma ativação aberta também é preenchido. Confira, mude o que precisar e salve (veja O registro manual).

O AUTO registra sozinho cada QSO que completa, com as duas reportagens e o nome e a localização da outra estação no comentário, e diz Registrado K1ABC. Com Enviar números abreviados (5NN) ligado, as reportagens são manipuladas como 5NN, mas o registro sempre guarda 599.

No computador, no iPhone e no controle remoto web

  • No computador o painel é o mesmo. Os botões do mouse e o teclado são as pás (veja Manipular com um adaptador, o teclado ou o mouse), a roda do mouse sobre o espectrograma move a barra selecionada, e não há Voz.
  • No iPhone o painel é o mesmo, sem tom de monitoração (veja acima). Voz abre a caixa de envio com o teclado, para você ditar.
  • No controle remoto web (veja Servidor web de controle remoto) a página mostra o texto que o qFT8 decodifica, uma linha por sinal, o mais recente primeiro, e uma caixa para digitar uma mensagem e enviá-la; STOP a interrompe. As teclas de pá do teclado do seu computador manipulam o próprio manipulador do qFT8, com os ajustes dele. AUTO RIT e suas linhas SEGUIR também estão lá; o botão SIDETONE não. Um toque na faixa de picos pede a frequência do rádio.

RTTY e JTTY

O RTTY (radioteletipo) envia texto como dois tons que se alternam. No qFT8 ele compartilha a tela do CW, sem as palhetas: todos os sinais de RTTY da banda passante são decodificados, cada um na sua própria velocidade e desvio, e escritos ao longo do seu traço na cascata. A mesma tela também opera o JTTY, um modo de texto mais recente para sinais fracos (veja RTTY e JTTY: as diferenças).

Especificações: ITU-T Recomendação S.1, “International Telegraph Alphabet No. 2”; 45,45 bauds e 170 Hz de shift são a prática dos radioamadores.

Estes são os componentes da tela de RTTY, em detalhes:

  1. Alvo e Troca: o indicativo da estação que você está trabalhando e a troca do contest. Eles preenchem [TARGET] e [EXCH] nas suas mensagens. Toque em um deles para digitá-lo; toque em um indicativo na linha do decodificador (item nº 7) para usá-lo como alvo.
  2. BAUD: A velocidade: 45,45 (a usual), 50 ou 75. Cada toque passa para a seguinte.
  3. SHIFT: A distância entre os dois tons: 170 Hz (a usual), 200, 425 ou 850 Hz. O filtro acompanha o shift.
  4. REV: Troca os dois tons, para uma estação que os envia ao contrário. Fica âmbar enquanto está ligado.
  5. FILTER e NR: O filtro de recepção e a redução de ruído.
  6. Memórias: Mensagens prontas com as mesmas macros do CW. Um toque envia uma. Uma mensagem com um campo vazio fica esmaecida: toque nela para ver o que falta. Teclado (e Voz no telefone e no iPhone) ficam no fim da lista.
  7. A linha do decodificador: O texto da estação que está sob a barra de recepção, em verde; o que você envia, em vermelho. Toque nela (em qualquer lugar, menos sobre um indicativo) para ver toda a conversa naquela frequência no lugar do espectrograma; toque no pequeno espectrograma que substitui a linha para voltar.
  8. A barra de recepção e a sua etiqueta: A etiqueta mostra o indicativo, a velocidade e o desvio da estação que está sob a barra. Um toque perto de um sinal coloca a barra no centro dele.
  9. Uma estação com outros ajustes: Quando a estação sob a barra usa uma velocidade, um shift ou uma ordem de tons diferente da sua, o rótulo dela fica âmbar, e os botões BAUD, SHIFT ou REV que diferem ficam âmbar e mostram igualar com o valor daquela estação. Toque no rótulo ou em um desses botões e o qFT8 adota todos os valores daquela estação, para que você possa responder a ela.
  10. Outros sinais: O texto deles é escrito ao longo dos próprios rastros. Só a estação sob a barra de recepção indica em que difere dos seus ajustes.
  11. Frequência: em RTTY o cabeçalho mostra a frequência de marca, que é a frequência que os operadores citam e a que é escrita no log.

Também nesta tela:

  • RX / TX / RX/TX: Escolhe qual barra um toque na cascata ou a roda de sintonia move: a barra de recepção, a de transmissão ou as duas juntas. Com RX ou TX você pode ouvir em uma frequência e transmitir em outra.
  • AUTO RIT: Leva a barra de recepção até uma estação que responde um pouco fora da sua frequência (veja AUTO RIT e as fichas de seguir).
  • A engrenagem abre Configurações > RTTY (ou Configurações > JTTY enquanto a tela opera em JTTY), e QSO abre o registro manual (veja Registro).
  • A linha vermelha: Press TX ON to transmit. Enquanto ela aparece, o que você envia é só uma prévia.

No computador a mesma tela é usada com o mouse e o teclado. O controle remoto web mostra o texto recebido com uma caixa para escrever e enviar uma mensagem, um botão para pará-la, o botão AUTO RIT e as fichas de seguir; o botão TX dele é o do próprio aplicativo.

Enviar

Arme o TX e depois toque em uma memória, ou abra Teclado, digite e toque em ENVIAR. Uma faixa com PARAR aparece enquanto o texto sai. Com TX OFF, as mesmas ações são uma prévia: a mensagem é tocada no seu alto-falante e mostrada em vermelho, e nada vai ao ar. Os caracteres que o código RTTY não tem são omitidos e listados. A memória sendo enviada fica verde até terminar.

O RTTY é uma transmissão contínua em potência máxima, portanto o limite de transmissão contínua do rádio se aplica: uma mensagem mais longa que o limite não é iniciada, e uma transmissão para quando o limite é atingido.

AUTO RIT e as fichas de seguir

Uma estação que responde ao seu CQ muitas vezes está um pouco fora da sua frequência. AUTO RIT, ao lado de RX/TX, cuida disso. Fica desligado até você ligá-lo; fica verde enquanto está ligado, e o qFT8 se lembra dele. RTTY e JTTY têm cada um seu próprio interruptor. Enquanto está ligado:

  • Quando uma estação termina uma transmissão que contém o seu indicativo, e está dentro do seu filtro, a barra de recepção vai sozinha até ela. Um CQ, uma mensagem entre duas outras estações e a sua própria mensagem lida de volta não contam. A barra de transmissão nunca se move: RX/TX passa a RX, então você continua respondendo na sua própria frequência.
  • Uma estação que chama você de mais longe ganha uma ficha no alto das memórias, por exemplo Seguir Q0ABC +150 Hz?. SEGUIR leva a barra de recepção até ela; o X fecha a ficha até essa estação chamar de novo. Há no máximo três fichas, a mais recente primeiro. Uma ficha some um minuto depois da última chamada dessa estação, e fica oculta enquanto você está sobre ela.
  • Enquanto a estação com quem você está fazendo o contato chama você, qualquer outra estação que chamar só ganha uma ficha.
  • Nada é lido enquanto você transmite. O AUTO RIT nunca liga o TX e nunca envia nada.

No JTTY uma mensagem chega em quadros, então a transmissão da estação conta como terminada quando o último quadro chegou.

Registro

QSO abre o registro manual (veja O registro manual) com o modo, a banda, a frequência de marca, o alvo e as reportagens já preenchidos: a reportagem que você envia é a dos seus ajustes, e a recebida é lida do texto da estação quando ela enviou uma. Um QSO por toque. Os QSOs em RTTY são registrados como RTTY; os em JTTY como JTTY (nos arquivos ADIF e nos envios, modo MFSK com submodo JTTY). Enquanto uma ativação de parque ou cume está aberta, a referência dela também vai para o QSO.

Configurações > RTTY

  • Modem: velocidade, desvio, Inverso, a Tabela de algarismos (Internacional (ITA2) ou EUA: elas diferem em cinco sinais, e as duas estações precisam usar a mesma) e Voltar a letras após um espaço na recepção e no envio (depois de um espaço o texto volta a letras, de modo que uma mudança para algarismos perdida estraga no máximo uma palavra). As estações que transmitem grupos de números, como as meteorológicas, não repetem a mudança para algarismos depois de cada espaço: os grupos de números delas saem como letras enquanto Voltar a letras após um espaço na recepção está ligado; portanto, desligue-o para lê-las.
  • Transmissão: uma nova linha no início e no fim de cada transmissão, caracteres de preenchimento enquanto não há nada para enviar, e uma nova linha automática depois de um certo número de caracteres.
  • Decodificação e exibição, Monitor (alto-falante), Memórias com os seus valores (reporte, nome, localização, troca) e RESTAURAR PADRÕES.

Não há AUTO em RTTY nem em JTTY: o qFT8 não conduz esses QSOs sozinho.

RTTY e JTTY: as diferenças

Escolha JTTY (experimental) no seletor de modo: a mesma tela abre com o modem JTTY e o botão de modo mostra JTTY; a linha RTTY traz o RTTY de volta. Cada um tem sua própria frequência em cada banda, então trocar entre eles move o dial (em 20 m, por exemplo, o JTTY fica em 14,090 MHz). O JTTY é novo e ainda pode mudar. Funciona no telefone, no computador e no iPhone; o controle remoto web o mostra como mostra o RTTY: o texto recebido, o AUTO RIT e suas fichas, e o texto enviado.

  • O sinal: RTTY são dois tons, na velocidade e no shift que você escolher. JTTY são quatro tons em uma velocidade fixa, com cerca de 130 Hz de largura, centrados na barra de transmissão, e pode ser copiado muito mais fraco. A tela não tem os botões BAUD, SHIFT e REV no JTTY.
  • O texto: o RTTY escreve cada caractere assim que chega. O JTTY envia uma mensagem em quadros de cerca de 2 segundos e a escreve um quadro de cada vez, uma mensagem por linha.
  • Suas mensagens: no JTTY cada linha de uma memória, ou de uma mensagem digitada no teclado, é uma mensagem de no máximo 80 caracteres, no conjunto de caracteres próprio do JTTY. O editor de memórias de Configurações > JTTY mostra como uma memória vai sair.
  • Ajustes: o JTTY tem sua própria página de ajustes e seus próprios valores (veja abaixo), e seu próprio interruptor AUTO RIT.
  • Registro: RTTY ou JTTY, como descrito em Registro.

Configurações > JTTY

O JTTY (a linha JTTY (experimental) do seletor de modo) usa este mesmo painel com o modem JTTY. As configurações dele têm uma página própria, ao lado de RTTY na lista de configurações; o botão de engrenagem do painel a abre enquanto o painel está em JTTY. Ela tem só o que o JTTY usa: Decodificação e exibição, Monitor (alto-falante), Memórias com seus valores e RESTAURAR PADRÕES; as configurações de Modem e Transmissão do RTTY não se aplicam a ele. Na primeira vez que o JTTY é usado, ele assume o que você tinha mudado em Configurações > RTTY (por exemplo suas memórias, nome e localização); o que você não tinha mudado começa com os padrões do próprio JTTY, como memórias curtas que cabem cada uma em uma mensagem JTTY. Depois disso, mudar um não muda o outro.

Especificações: nenhuma especificação publicada.

Configurações > Q65

Q65 (a linha Q65 (experimental) do seletor de modo) é um modo único com um seletor de submodo ao lado do seletor: o período (15, 30, 60, 120 ou 300 s) e o espaçamento de tons (A a E), com nomes como 30A. Há 22 submodos (15 s: A-C, 30 s: A-D, 60, 120 e 300 s: A-E); o padrão é 30A. O Q65 usa as mensagens do FT8 e o mesmo fluxo de QSO (CQ, relatórios, RR73/73, AUTO, a lista de estações). Os QSOs são registrados como MODE=MFSK SUBMODE=Q65 e os spots vão para o PSKReporter como Q65.

Especificações: J. Taylor, B. Somerville, S. Franke, N. Palermo, “Q65 Quick Start”, 2021.

Usos típicos: dispersão ionosférica em 6 m (30A, 50.275 MHz), dispersão em 2 m (60C, 144.170 MHz) e EME em 2 m e acima (60A, 60B, 60C). As bandas oferecidas são 10 m (28.140), 6 m (50.275), 2 m (144.170), 70 cm, 23 cm e 13 cm (estas três usam a frequência do FT8 até haver uma do Q65 confirmada). As transmissões duram 12,75, 25,5, 51, 113,3 ou 293,8 s e aparecem na configuração Limite de transmissão contínua; um submodo de 300 s precisa de um limite suficientemente grande. O Q65 é enviado só como áudio: o qFT8 não o transmite pelo modo de tom CAT do rádio.

A seção Q65 de Configurações > MODOS DIGITAIS tem:

  • Submodo: o período e o espaçamento de tons, como no seletor.
  • Média (ativada): soma transmissões fracas repetidas para as poder decodificar.
  • A priori (ativado): usa o seu indicativo e o do seu parceiro de QSO para ajudar o decodificador.
  • Decodificação única (desativada): desativada decodifica toda a banda; ativada, só ao redor da frequência de recepção.
  • Tolerância Rx: a largura em Hz ao redor da frequência de recepção (padrão 100).
  • LIMPAR MÉDIA: esquece as transmissões recolhidas até agora.
  • Referências: as descrições do protocolo pelos seus autores: o «Quick-Start Guide to Q65» de Taylor, Somerville, Franke e Palermo, e o trabalho de Palermo sobre códigos q-ários de repetição-acumulação.

Nada é decodificado que não tenha sido recebido: uma decodificação encontrada com informação a priori precisa passar pelas mesmas verificações que qualquer outra.

Configurações > MSK144

MSK144 (a linha MSK144 (experimental) do seletor de modo) foi feito para a dispersão meteórica: o rastro de um meteoro reflete o sinal por um instante, então ele só é ouvido em breves rajadas (pings). Uma transmissão repete sua mensagem durante todo o período, e qualquer ping longo o bastante para carregá-la é decodificado. MSK144 usa as mensagens do FT8 e o mesmo fluxo de QSO (CQ, indicativos e grid, reportagens, RRR/RR73/73, AUTO, a lista de estações). Os QSOs são registrados como MODE=MSK144 e os spots vão para o PSKReporter como MSK144.

Especificações: S. Franke, J. Taylor, “The MSK144 Protocol for Meteor-Scatter Communication”, QEX, July/August 2017.

Toda transmissão é centrada em 1500 Hz de áudio, com os tons em 1000 e 2000 Hz: o deslocamento de TX não se aplica ao MSK144. A frequência de chamada MSK144 de cada banda é definida quando você escolhe a banda. MSK144 aparece na configuração Limite de transmissão contínua como todos os modos.

A seção MSK144 de Configurações > MODOS DIGITAIS tem:

  • Período: quanto dura cada transmissão e cada período de escuta (5, 10, 15 ou 30 s); 15 s é a escolha usual.
  • Mensagens curtas para reportagens, RRR e 73: reportagens, RRR e 73 são enviados como mensagens curtas, que levam um hash dos dois indicativos: só o seu correspondente pode lê-las. Mais úteis em 144 MHz e acima.
  • Tolerância de recepção: a que distância de 1500 Hz (mais o deslocamento de RX) um sinal é procurado: 25, 50, 100, 200 ou 300 Hz.

Referências: o artigo sobre MSK144 de Franke e Taylor na QEX (2016).

Configurações > FST4

FST4 (a linha FST4 (experimental) do seletor de modo) é um modo de QSO para sinais fracos em LF, MF e HF. Usa as mensagens do FT8 e o mesmo fluxo de QSO (CQ, relatórios, RR73/73, AUTO, a lista de estações, o log), com 4 tons (GFSK) e 160 símbolos. Os QSOs são registrados como MODE=MFSK SUBMODE=FST4 e os spots vão para o PSKReporter como FST4.

Especificações: S. Franke, J. Taylor, B. Somerville, “Protocol Specifications” (FST4, FST4W), 2020.

O período de transmissão e recepção é de 15, 30, 60, 120, 300, 900 ou 1800 s, escolhido na barra inferior ou em Configurações. Quanto mais longo o período, mais estreito e sensível é o modo: cerca de -21 dB com 15 s até -43 dB com 1800 s (em 2500 Hz). Frequências habituais: 2200 m 136.000 kHz, 630 m 474.200 kHz, 160 m 1.8390 MHz. Com os períodos muito longos o transmissor fica ligado por até 30 minutos: a configuração Limite de transmissão contínua precisa permitir isso. FST4 é experimental.

A seção FST4 de Configurações > MODOS DIGITAIS tem:

  • Período (60 s): o período de transmissão e recepção, como na barra inferior.
  • A priori (ativado): usa o seu indicativo e o do seu parceiro de QSO para ajudar o decodificador.
  • Decodificação única (desativada): desativada decodifica toda a banda; ativada, só ao redor da frequência de recepção.
  • Tolerância Rx: a largura em Hz ao redor da frequência de recepção (padrão 100).
  • Referências: S. Franke K9AN, B. Somerville G4WJS, J. Taylor K1JT: “The FST4 and FST4W Protocols for Weak Signal Communication on LF, MF and HF”, QEX (2021).

Configurações > FST4W

FST4W (a linha FST4W (experimental) do seletor de modo) é um modo de baliza como o WSPR: usa o mesmo painel do WSPR (lista de spots, porcentagem de transmissão da baliza, envio ao WSPRnet). As mensagens têm 50 bits: CALL GRID POWER, ou PFX/CALL POWER ou CALL/X POWER. O período é de 120, 300, 900 ou 1800 s; a sensibilidade vai de cerca de -33 dB (120 s) a -45 dB (1800 s). Decodifica dentro da tolerância de recepção (padrão 100 Hz) em torno da frequência de recepção (normalmente 1500 Hz). Os spots vão para o WSPRnet com o período.

Especificações: S. Franke, J. Taylor, B. Somerville, “Protocol Specifications” (FST4, FST4W), 2020.

Frequências habituais: 2200 m 136.000 kHz, 630 m 474.200 kHz, 160 m 1.8368 MHz. Nas bandas mais altas usa as frequências ao lado das frequências de dial do WSPR. Com os períodos muito longos o transmissor fica ligado por até 30 minutos: a configuração Limite de transmissão contínua precisa permitir isso. FST4W é experimental.

A seção FST4W de Configurações > MODOS DIGITAIS tem:

  • Período (120 s): o período de transmissão e recepção, como na barra inferior.
  • Tolerância Rx: a largura em Hz ao redor da frequência de recepção (padrão 100).
  • Percentual de transmissão (20 %): a parte dos períodos em que a baliza transmite.
  • Referências: S. Franke K9AN, B. Somerville G4WJS, J. Taylor K1JT: “The FST4 and FST4W Protocols for Weak Signal Communication on LF, MF and HF”, QEX (2021).

SSTV (imagens)

A SSTV (televisão de varredura lenta) envia uma imagem parada em forma de som, linha por linha, em meio minuto a cerca de quatro minutos. O qFT8 recebe imagens sozinho enquanto você está no modo, e envia suas próprias imagens, uma foto ou uma das imagens prontas dele, com o seu indicativo escrito nelas.

Especificações: J. L. Barber (N7CXI), “Proposal for SSTV Mode Specifications”, Dayton Hamvention SSTV forum, May 2000.

Escolha SSTV com o seletor de modo da barra inferior. O rádio vai para a frequência de chamada SSTV da banda, em USB. O painel mostra uma metade de cada vez: RX, as imagens recebidas, ou TX, a imagem a enviar. Os dois botões no canto superior esquerdo alternam entre elas; alternar só muda o que você vê, nunca envia nada.

A metade de recepção (RX)

  1. AUTO: Ligado (verde, o padrão), o qFT8 encontra cada imagem sozinho, em qualquer modo. Desligado, ele recebe o tempo todo num só modo, como uma imagem contínua (recepção manual). A escolha é lembrada.
  2. RX | TX: A metade mostrada. Um ponto amarelo em RX indica que chegou uma imagem enquanto a metade de envio estava à vista. ENVIAR mostra sozinho a metade de envio, e o painel volta para a metade de recepção quando a imagem termina.
  3. Estado da recepção: OUVINDO (todos os modos, toda a banda passante); RECEBENDO com o modo, quanto a estação está fora da frequência e a linha sendo desenhada; MANUAL quando AUTO está desligado; EM PAUSA enquanto você envia.
  4. A engrenagem abre Configurações > SSTV.
  5. QSO abre o registro manual para a imagem mostrada (registrar).
  6. A imagem recebida: a que está chegando, desenhada linha por linha, ou a imagem guardada que você escolheu na faixa. A marca no canto: um anel âmbar que se enche enquanto ela chega (com uma seta verde dentro quando será salva no fim), um visto verde depois de salva, uma seta cinza enquanto não estiver salva. Toque numa imagem guardada para editá-la.
  7. A legenda: a hora (UTC) e o modo; enquanto a imagem chega, a porcentagem e os segundos restantes; numa imagem guardada, "recebida a partir da linha ...", "sinal perdido na linha ..." ou "... linhas perdidas" quando ela não está completa. Ao lado, o campo do indicativo.
  8. SALVAR grava a imagem na pasta de imagens e fica verde (SALVA). Pressionado enquanto a imagem ainda está chegando, mostra GUARDA QUANDO TERMINAR.
  9. EDITAR melhora uma imagem guardada: brilho, contraste, cor, tonalidade, nitidez e redução de ruído. A imagem como foi recebida é sempre mantida: REVERTER desfaz tudo, e SALVAR CÓPIA salva a versão editada como um arquivo próprio.
  10. RESPONDER pede o indicativo da outra estação (partindo do campo do indicativo) e escreve "o indicativo dela DE o seu" na sua imagem a enviar, num de cinco layouts de resposta; a imagem recebida nunca é devolvida. O modo muda para o que a imagem recebida usou. Se o seu limite de transmissão contínua for curto demais para esse modo, um aviso diz isso; o limite nunca é alterado por você.
  11. A lixeira apaga do qFT8 a imagem mostrada, depois de uma pergunta. Uma cópia já salva na pasta de imagens continua lá, e a pergunta diz isso.
  12. A faixa: primeiro a imagem que está chegando, depois as imagens guardadas, a mais recente primeiro (as imagens recebidas).
  13. O seletor de modo SSTV da barra inferior: modos Martin, Scottie, Robot, PD, Wraase e Pasokon, cada um com os segundos que uma imagem leva. É o modo em que as imagens são enviadas, e o modo recebido quando AUTO está desligado. Ao lado, a área de mensagens diz o que está acontecendo ("ouvindo", "recebendo" com a porcentagem, "enviando" com os segundos restantes).
  14. A faixa SSTV na cascata: as imagens são enviadas e recebidas entre 1100 e 2300 Hz, com a identificação Morse em 1000 Hz. Cada imagem ouvida ou enviada ganha uma caixa com seu modo e indicativo; toque numa caixa para mostrar essa imagem.

A metade de envio (TX)

  1. O modo em que a imagem será enviada, com seu tamanho e sistema de cores. É escolhido com o seletor de modo da barra inferior.
  2. CARREGAR abre Escolher uma imagem.
  3. A imagem a enviar, exatamente como irá ao ar. Vazia, ela diz Toque para carregar uma imagem. Toque nela para ajustá-la de novo à forma do modo. A pequena seta no canto a salva, tal como será enviada, na pasta de imagens.
  4. O estilo do indicativo: as setas percorrem os 16 estilos e Sem indicativo; um toque no nome do estilo abre a escolha de estilo e cor.
  5. A paleta abre a mesma escolha: os estilos numa lista e oito cores de texto. Cada escolha aparece na imagem na hora e fica para a próxima imagem.
  6. O lápis acrescenta à imagem uma linha de texto seu (o lápis fica amarelo enquanto houver uma).
  7. REMOVER tira a imagem carregada.
  8. ENVIAR mostra os segundos que a transmissão inteira leva. Enquanto a imagem está no ar, vira PARAR com os segundos restantes, e as linhas já enviadas ficam marcadas na imagem.
  9. A linha vermelha: Pressione TX ON para enviar imagens. Com um QMX cujo firmware não consegue enviar imagens, ela diz isso no lugar.
  10. As imagens rápidas: as seis últimas imagens que você carregou, depois as prontas, já no seu estilo de indicativo. Um toque carrega uma como imagem a enviar; ela nunca é enviada antes de você pressionar ENVIAR.

Receber imagens

Com AUTO ligado não há nada para ajustar. O qFT8 reconhece o modo de cada transmissão pelo sinal de início, e também quando você sintoniza depois que a imagem já começou (as linhas perdidas ficam vazias). Ele escuta em toda a banda passante, de cerca de 1000 Hz abaixo até 800 Hz acima dos tons habituais. Uma imagem enviada um pouco fora da frequência, ou por uma estação com a temporização um pouco desviada, é endireitada automaticamente. Se duas estações enviarem ao mesmo tempo em frequências claramente diferentes, as duas imagens são recebidas e guardadas; toque numa caixa da cascata para escolher a que é mostrada.

Recepção manual (AUTO desligado)

Para uma estação cujo sinal de início você perdeu, ou que o qFT8 não capta sozinho, desligue AUTO. O qFT8 passa então a receber o tempo todo o modo escolhido na barra inferior, como uma longa imagem contínua: as linhas mais novas são acrescentadas embaixo e a imagem sobe. O estado diz MANUAL com o modo e o deslocamento; quando um sinal de início é ouvido em algum modo, ele avisa, só como dica (mude o modo você mesmo).

  • O marcador de recepção: na cascata a faixa vira um marcador com duas bordas amarelas. Arraste-o para cima do sinal (com o dedo, ou com o mouse num computador); o qFT8 segue o sinal dentro de cerca de 100 Hz dele. A posição é lembrada.
  • SALVAR e EDITAR abrem primeiro Recortar a imagem: arraste as duas bordas amarelas em volta da imagem que você quer; elas começam na última imagem inteira. O recorte vira uma imagem guardada na faixa, e depois é salvo ou aberto no editor.
  • A lixeira faz a imagem contínua recomeçar vazia; as imagens guardadas não são tocadas.

De quem é a imagem? O campo do indicativo

Muitas estações se identificam em volta da imagem, em código Morse antes ou depois dela, ou com uma curta rajada de dados depois. O qFT8 lê as duas coisas, e escreve o indicativo no campo ao lado da legenda. Quando nada foi ouvido, o campo diz Indicativo desconhecido. Toque no campo para digitar você mesmo o indicativo (muitas vezes ele está escrito na imagem) ou para corrigi-lo; o que você digita substitui o que foi ouvido, e RESPONDER e QSO partem dele.

As imagens recebidas

O qFT8 guarda sozinho as últimas imagens recebidas, quer você as salve ou não: 100 delas, a menos que você mude Imagens recebidas mantidas no aplicativo; a mais antiga é descartada quando chega uma nova. Elas sobrevivem a um reinício. A faixa sob a imagem as mostra, a mais recente primeiro, cada uma com sua marca de salva / não salva; a imagem que ainda está chegando vem primeiro. Toque numa para mostrá-la; enquanto uma imagem chega, toque na primeira para segui-la de novo. Quando nada está chegando, é mostrada a imagem guardada mais recente.

A pasta de imagens

SALVAR (ou Salvar automaticamente no dispositivo cada imagem recebida) grava a imagem como arquivo PNG, e um aviso diz onde:

  • Celular ou tablet: Pictures/qFT8 SSTV, por isso as imagens aparecem na galeria. O Android 6 a 9 pede uma vez acesso ao armazenamento; sem ele, as imagens vão para a pasta própria do qFT8 e o aviso diz isso.
  • Computador: uma pasta qFT8 SSTV dentro da sua pasta de Imagens (a que o seu desktop usa, mesmo quando ela tem outro nome no seu idioma).
  • iPhone e iPad: uma pasta qFT8 SSTV no armazenamento próprio do qFT8.
  • Controle remoto web: a imagem é salva onde o qFT8 está rodando, e o navegador baixa uma cópia. Uma página que só pode olhar mostra no lugar BAIXAR, que apenas baixa.

O salvamento automático vem desligado num celular, num tablet e num iPhone, e ligado num computador. As imagens salvas recebem como nome a data e a hora (UTC), a banda, a frequência em kHz, o modo e o indicativo, por exemplo 2026-10-05_1431_20m_14230_M1_Q1ABC.png, ou ..._UNKNOWN.png quando não há indicativo. Se o indicativo chegar ou for digitado depois que a imagem foi salva, o arquivo salvo é renomeado; não se faz uma segunda cópia. Uma cópia editada termina em _edit.png, e uma imagem salva a partir da metade de envio em _tx.png. Apagar uma imagem no qFT8 nunca apaga um arquivo salvo.

Enviar uma imagem

  1. Escolha o modo com o seletor da barra inferior. Se você estiver respondendo a uma estação, use o modo que ela usou (RESPONDER faz isso por você). Robot 36, Martin 1 e Scottie 1 são os mais comuns.
  2. Pressione CARREGAR (ou toque na imagem vazia). Escolher uma imagem mostra as suas imagens (Galeria; Arquivos num computador), a Câmera onde houver uma, e 59 imagens prontas (cartões CQ, o logotipo do qFT8, paisagens, ilusões de ótica, um cartão QSL, 73...). Você também pode compartilhar uma imagem com o qFT8 a partir de outro app; se outro modo estiver em uso, o qFT8 pergunta antes de mudar para SSTV.
  3. Se a imagem não tiver a forma do modo, vem Ajustar a imagem: INTEIRA a mostra completa com bordas, RECORTAR preenche o quadro (arraste para mover, faça pinça para ampliar), GIRAR a gira, e brilho, contraste e Contraste automático a ajustam. USAR IMAGEM a aceita.
  4. Vem então Estilo do indicativo: a sua imagem em cada um dos 16 estilos de indicativo. Toque num e pressione USAR; VOLTAR retorna às imagens.
  5. Arme o TX com o botão TX ON e pressione ENVIAR.

Desligar o TX, pressionar PARAR, ou mudar de banda ou de modo para a imagem na hora; depois de PARAR, o TX continua ligado, pronto para enviar de novo. Se uma imagem estiver chegando quando você pressionar ENVIAR, o qFT8 pergunta antes de parar de receber.

Os estilos de indicativo

A data é a data UTC em que a imagem é enviada, e a banda aquela em que você está. "CQ" num estilo é escrito como CQ DE e o seu indicativo.

  1. CQ + data + banda, numa faixa embaixo (o padrão).
  2. Indicativo sozinho, numa faixa embaixo.
  3. Data + banda grandes, embaixo: CQ e o seu indicativo, com a banda e a data em letras grandes.
  4. Data + banda grandes, em cima: a banda e a data em letras grandes em cima, CQ e o seu indicativo embaixo.
  5. Faixa: indicativo + data + banda: a imagem um pouco menor, sobre uma faixa com CQ, o seu indicativo, a data e a banda.
  6. Faixa: indicativo: o mesmo, só com o seu indicativo.
  7. CQ grande + etiqueta de data: um CQ grande no canto e uma pequena etiqueta com a banda e a data.
  8. Indicativo no centro: o seu indicativo em letras grandes no meio.
  9. Ingresso + data: um ingresso no canto com o seu indicativo, a banda e a data.
  10. Indicativo no canto superior esquerdo.
  11. Moldura + data: uma moldura colorida, com o seu indicativo e a banda e a data nela.
  12. Indicativo com sombra: o seu indicativo com uma sombra projetada.
  13. CQ CQ + data: CQ CQ CQ em cima, o seu indicativo, a banda e a data embaixo.
  14. Indicativo em faixa no topo: o seu indicativo numa faixa clara ao longo do topo.
  15. Carimbo postal com data: o seu indicativo no canto superior esquerdo e um carimbo postal redondo com a banda e a data.
  16. Indicativo com vários contornos: o seu indicativo com vários contornos em volta das letras.

Sem indicativo não escreve nada na imagem (só a sua linha de texto, se você acrescentou uma). O indicativo continua sendo enviado em Morse ou como FSK ID se essas opções estiverem ligadas nas Configurações. Uma imagem de resposta usa no lugar um dos cinco layouts de resposta (um acima do outro, lado a lado, em cima e embaixo, contorno grande, com data + banda); as setas e a paleta percorrem esses.

Limites de transmissão

Uma imagem é uma única transmissão contínua com potência máxima: cerca de 40 segundos em Robot 36, dois minutos em Martin 1, e mais de quatro minutos nos modos mais lentos. Tudo conta: o sinal de início, o indicativo em Morse, a imagem e o FSK ID, e os segundos em ENVIAR e na lista de modos são todo esse tempo.

  • Um modo mais longo que o limite de transmissão contínua do seu rádio aparece em cinza na lista de modos. Escolhê-lo, ou pressionar ENVIAR nele, explica o motivo e oferece abrir a configuração; nada é enviado.
  • Sob cada opção da configuração, o qFT8 lista os modos SSTV que essa opção acrescenta, para você ver o que ganha ao aumentá-lo.
  • Desligar o indicativo em Morse ou o FSK ID em Configurações > SSTV deixa cada imagem alguns segundos mais curta.
  • O limite nunca é alterado por você, nem mesmo por RESPONDER.

Um QMX ou QMX+ precisa do firmware 1_04_001 ou mais novo para enviar imagens; com um firmware mais antigo a SSTV só recebe e a linha vermelha da metade de envio diz isso.

Registrar um QSO em SSTV

Nada é registrado sozinho. Mostre a imagem da outra estação e pressione QSO: o registro manual abre com o modo SSTV, a banda, a frequência do rádio, o indicativo do campo do indicativo, e 595 enviado e recebido. Um aviso pede que você confira o indicativo, ou que o digite quando nenhum foi encontrado. Salve como qualquer outro QSO; depois ele é enviado aos seus serviços como os outros.

No computador, no iPhone e no controle remoto web

  • Computador: o mesmo painel, com RECEBER | ENVIAR no lugar de RX | TX, o mouse no lugar do dedo (clique para carregar, arraste o marcador), e Arquivos no lugar da galeria e da câmera.
  • iPhone e iPad: o mesmo painel e os mesmos controles de um celular Android.
  • Controle remoto web: as colunas de recepção e de envio lado a lado, com AUTO, o marcador de recepção, a faixa, SALVAR e RESPONDER de um lado, e o seletor de modo, CARREGAR, os estilos, REMOVER e ENVIAR do outro. CARREGAR escolhe uma imagem no navegador e a recorta ali mesmo (arraste; amplie com o controle deslizante ou a roda do mouse). Editar, apagar e registrar são feitos no próprio qFT8. ENVIAR só funciona quando o operador está com TX ON no qFT8.

Configurações > SSTV

Abra com a engrenagem do painel, ou pela aba Configurações. Recepção:

  • Salvar automaticamente no dispositivo cada imagem recebida (desligado nos celulares e no iPhone, ligado no computador).
  • Imagens recebidas mantidas no aplicativo: 25, 50, 100 (o padrão), 200 ou 500.

Envio:

  • Enviar o seu indicativo em CW: desligado, antes da imagem (o padrão), depois dela, ou os dois. Só o indicativo, a 20 WPM; os segundos dele contam no tempo de transmissão.
  • Enviar FSK ID depois de cada imagem (ligado): uma curta rajada de dados que permite ao programa da outra estação ler o seu indicativo.
  • Estilo do texto: o estilo de indicativo com que a próxima imagem começa (estilo 1 numa instalação nova), e Cor do texto (branco).
  • Contraste automático e Aumentar a nitidez automaticamente (ambos ligados): aplicados à imagem que você envia.

RESTAURAR PADRÕES devolve todas as configurações de SSTV aos valores iniciais.

DRAW (imagens na cascata)

O DRAW pinta uma imagem em tons de cinza diretamente na cascata das outras estações: cada coluna da imagem é um tom, 6.25 Hz distante do próximo, e cada linha da imagem é enviada por uma fração de segundo, da linha de baixo até a de cima. Qualquer pessoa com uma cascata vê a sua imagem aparecer, com ou sem o qFT8. Uma imagem pode ter qualquer formato: uma foto, um desenho ou apenas uma linha de texto, como o seu indicativo. O DRAW não é um modo padrão; foi feito para ser visto.

Especificações: projeto próprio do qFT8.

Escolha DRAW no seletor de modo da barra inferior. RX e TX no alto do painel mostram a metade de recepção ou a de envio:

  1. Os dados: a largura, o tamanho da imagem em colunas e linhas, e a velocidade.
  2. CARREGAR: "Tirar uma foto" ou "Escolher uma imagem". A imagem mantém o seu próprio formato.
  3. A imagem a enviar, em cinza, desenhada nas cores da sua própria cascata: é o que as outras estações vão ver. Enquanto está no ar, uma linha amarela marca a linha que está sendo enviada, com "No ar: linha N de M".
  4. Placa de indicativo (ativada por padrão): o seu indicativo em letras grandes sob a imagem. O lápis muda o texto da placa (vazio = o seu indicativo). Contraste automático deixa a parte mais escura da imagem preta e a mais clara branca, com um toque; Contraste e Brilho ficam por sua conta depois, à mão.
  5. REMOVER volta para a placa de indicativo sozinha. ENVIAR mostra quantos segundos a imagem leva e vira PARAR com os segundos restantes.
  6. A linha vermelha diz por que a imagem não pode ser enviada agora, e fica oculta quando nada impede: "Pressione TX ON para enviar imagens"; "20 s: acima do seu limite de 15 s" (a imagem é mais longa que o limite de transmissão contínua do seu rádio); "Em 30 m só pode ser enviada a largura de 500 Hz"; "A transmissão ficaria fora das bandas de radioamador"; ou, com um QMX cujo firmware não consegue passar o rádio para SSB via CAT, que as imagens só podem ser recebidas.
  7. VELOCIDADE: 3.125, 6.25 (o padrão: uma linha dura o mesmo que um tom do FT8) ou 12.5 linhas por segundo. Ao lado: quanto do seu limite de transmissão contínua a imagem usa. A lista mostra os segundos da imagem em cada velocidade; uma velocidade longa demais para o seu limite avisa quando você a toca. O indicador mostra, por exemplo, "20 s do seu limite de 30 s".
  8. Placas de texto: um toque carrega "CQ" e o seu indicativo, "73" e o seu indicativo, ou só o seu indicativo, como a imagem inteira.
  9. GIRAR (ao lado de REMOVER) gira toda a transmissão, placa incluída, um quarto de volta a cada toque, para que ela seja lida na posição certa numa cascata que rola para o lado. Na recepção, GIRAR gira a imagem mostrada (e salva) da mesma forma.
  10. A largura na barra inferior: 500, 700 (o padrão) ou 1200 Hz, com os segundos da imagem em cada largura. Uma imagem mais larga tem mais colunas, por isso é mais nítida e demora mais.
  11. A banda do DRAW na cascata: a imagem fica entre 1000 Hz e 1000 Hz mais a sua largura.

Receber imagens

Não há nada para iniciar: o qFT8 escuta o tempo todo enquanto você está no modo, também enquanto a metade de envio é mostrada.

  1. RX e TX: a metade de recepção e a de envio.
  2. A linha de status: escutando, a largura e a faixa escutada (1000–1700 Hz com 700 Hz). Enquanto sua própria imagem está no ar, a recepção pausa e a linha avisa.
  3. A imagem recebida: a faixa do DRAW dos últimos três minutos como uma só imagem, a linha mais nova em cima, com pixels quadrados, nas cores da sua cascata: uma imagem enviada com o qFT8 aparece em pé. Antes de chegar alguma coisa, ela diz em quais frequências escuta.
  4. A etiqueta ao vivo: o modo, a largura e a velocidade em que a imagem é desenhada.
  5. SALVAR (azul assim que há algo para salvar) salva a imagem mostrada, cortada onde ela se destaca do ruído, em cinza, como recebida, como PNG com a data e a hora (UTC) e a largura no nome. Num celular ou tablet ela vai para a pasta de imagens, em Pictures/qFT8 DRAW; se o qFT8 não puder gravar lá, ela fica na pasta do próprio qFT8 e o aviso diz onde.
  6. GIRAR gira a imagem mostrada (e salva) um quarto de volta a cada toque; o botão mostra o giro (90°, 180°, 270°).
  7. VELOCIDADE: ajuste para a velocidade que a outra estação usa (3.125, 6.25 ou 12.5 linhas por segundo); toda a imagem recebida é redesenhada na nova velocidade. Isso não muda a velocidade em que você envia.

O AGC do seu rádio: o controle automático de ganho de um rádio reduz o ganho numa linha clara e aumenta numa escura, o que deixa a imagem recebida listrada. O qFT8 mede o ruído ao lado da imagem em cada linha e corrige isso, e avisa quando vê o ganho se mover com a imagem: então coloque o AGC do rádio em OFF ou SLOW (e reduza um pouco o ganho de RF se a banda estiver barulhenta).

Enviar uma imagem

  1. Escolha a largura na barra inferior e a velocidade com VELOCIDADE.
  2. Carregue uma imagem ou toque numa placa de texto. Ajuste o contraste ou pressione Contraste automático.
  3. Ative o TX e pressione ENVIAR.

Desligar o TX, pressionar PARAR, TUNE, ou mudar de banda ou de modo interrompe a imagem na hora. Uma imagem mais longa que o limite de transmissão contínua do rádio não é enviada: a linha vermelha diz quanto ela dura, e uma velocidade maior, uma largura menor ou uma imagem menor a deixam dentro do limite. Todos os tons são enviados ao mesmo tempo, então mantenha o nível de transmissão como para o FT8, com o ALC do rádio baixo.

No computador, no iPhone e no controle remoto web

O painel é igual em todo lugar, com os mesmos botões. As diferenças:

  • O computador: CARREGAR abre um arquivo de imagem; SALVAR grava na pasta qFT8 DRAW dentro da sua pasta de Imagens.
  • O iPhone: CARREGAR oferece "Tirar uma foto" ou "Escolher uma imagem", como num celular; SALVAR guarda a imagem na pasta qFT8 DRAW dos arquivos do próprio qFT8.
  • O controle remoto web mostra a mesma imagem a enviar e a imagem recebida. CARREGAR pega uma imagem do aparelho em que o navegador roda (reduzida a no máximo 192 colunas de largura, a imagem mais larga que o DRAW envia); SALVAR salva no celular ou computador que roda o qFT8, não no navegador. Enviar exige o nível de acesso controle total e, como no app, só vai ao ar com o TX armado.

Até onde chega?

O DRAW foi feito para ser visto, não para tirar sinais do ruído. Uma placa com o indicativo nos 700 Hz e 6.25 linhas por segundo padrão é legível até cerca de -2 dB de SNR (largura de banda de 2500 Hz), a 3.125 linhas por segundo até cerca de -5 dB; uma foto fica boa a partir de cerca de +4 dB. O FT8 chega a cerca de -21 dB, então se a outra estação mal decodifica seu FT8, ela não verá sua imagem. Velocidades mais lentas e larguras mais estreitas chegam mais longe. O fading custa cerca de 6 dB a todos os modos. O que o DRAW oferece e os outros modos não: quem olha uma cascata vê sua imagem, sem nenhum programa especial.

Frequências, banda lateral e registro

O qFT8 sintoniza a sua frequência do DRAW em cada banda, escolhida nos segmentos "todos os modos" dos planos de bandas da IARU das três regiões, longe dos centros de atividade de SSTV, digitais e de voz (dial, USB): 160 m 1.865, 80 m 3.665, 40 m 7.190, 30 m 10.145 (só 500 Hz), 20 m 14.335, 17 m 18.140, 15 m 21.400, 12 m 24.975, 10 m 28.520 e 6 m 50.380 MHz. Os 60 m não têm frequência (as regras variam de país para país). Nos 30 m os planos de bandas permitem no máximo 500 Hz, então só a largura de 500 Hz é enviada ali. Confira a sua própria licença e o plano de bandas local.

O rádio fica em USB em todas as bandas. Uma estação que escuta em LSB vê a imagem espelhada da esquerda para a direita.

QSO abre o log com o modo DRAW: o padrão de registro (ADIF) não tem DRAW, e uma imagem parada enviada linha por linha é o que FAX significa ali (conta como modo de imagem, como o SSTV). Um QMX precisa do mesmo firmware que para o SSTV. O log, os arquivos e os envios o gravam como FAX com o submodo DRAW; parques (POTA) e eQSL recebem só FAX.

Desvio de sintonia do espectrograma

Em Configurações > CONFIGURAÇÃO DO DISPOSITIVO, em Sintonia (este rádio), Desvio de sintonia do espectrograma desloca o que o espectrograma mostra em até 300 Hz para baixo ou para cima. O padrão é −100 Hz na família QMX, −90 Hz no IC-7300 e −50 Hz em qualquer outro rádio; o valor que você definir (inclusive 0) é mantido, separadamente para cada rádio.

A maioria dos rádios corta a parte mais baixa do áudio, de modo que os sinais nas primeiras centenas de hertz do espectrograma ficam fracos ou somem. Com um desvio de −100 Hz, por exemplo, o qFT8 sintoniza o rádio 100 Hz mais abaixo e desloca o áudio na mesma medida, de modo que esses sinais passam para a parte que o rádio ouve bem.

Nada mais muda: a frequência mostrada, os desvios das estações, os spots, a sua frequência de transmissão e o log ficam exatamente como antes. Só o mostrador do próprio rádio indica um valor diferente, na medida do desvio. O desvio funciona em todos os modos e precisa de uma conexão CAT; com VOX ou com o alto-falante ele não faz nada.

Limite de transmissão contínua

Esta é uma configuração de segurança para o transmissor. Os rádios pequenos são feitos para transmissões curtas com pausas: uma transmissão de FT8 dura menos de 13 segundos e é seguida de pelo menos 15 segundos de descanso. Alguns modos mantêm o rádio transmitindo em potência máxima por muito mais tempo sem interrupção, e isso pode superaquecer o amplificador final de um rádio pequeno. O limite de transmissão contínua é o tempo máximo que o qFT8 mantém o seu rádio em transmissão de uma só vez.

Ele fica em Configurações > CONFIGURAÇÃO DO DISPOSITIVO, em Sintonia (este rádio). As opções são 20, 40, 60, 90, 120 e 150 segundos, e Sem limite. Abaixo de cada opção o qFT8 lista o que essa opção acrescenta, para que você veja o que ganha ao aumentá-lo. A configuração é salva separadamente para cada rádio.

O padrão de cada rádio

  • 60 segundos: QRPLabs QMX, QMX+ e QDX, e o (tr)uSDX.
  • 120 segundos: Xiegu X6100 e X6200.
  • Sem limite: todos os outros rádios, e um rádio usado por VOX ou pelo alto-falante (o qFT8 não tem como saber que rádio é).

Esses padrões são cautelosos. Você conhece o seu rádio, o ajuste de potência e a refrigeração dele: altere o limite se eles permitirem. O qFT8 nunca aumenta o limite sozinho.

O que o limite faz

  • Uma transmissão de duração conhecida que é mais longa que o limite não é iniciada. É por isso que o WSPR e os modos longos de SSTV pedem que você o aumente: uma transmissão de WSPR dura 111 segundos, e muitas imagens de SSTV levam dois minutos ou mais. Quando você escolhe um desses modos, ou pressiona TX ON nele, uma mensagem informa quantos segundos ele precisa e qual é o limite do seu rádio, com um botão Abrir a configuração. A transmissão não é armada até que o limite permita o modo.
  • Uma transmissão sem duração fixa para quando o limite é atingido, e o rádio volta à recepção: TUNE, SSB (o botão PTT, o VOX e as memórias de voz) e RTTY. Um aviso informa que o limite foi atingido.
  • O CW não é limitado: o manipulador só fica pressionado parte do tempo.

QMX e WSPR: Com um QMX, QMX+ ou QDX, o WSPR precisa que o limite seja aumentado de 60 para 120 segundos. Pela segurança do rádio, o qFT8 pede que você faça isso uma vez, à mão. Considere reduzir a potência do rádio para o WSPR: ele é, por concepção, um modo de baixa potência.

Rede e conectividade

O servidor abre uma porta TCP específica (por padrão, 13497) no seu celular ou computador. Para acessá-la, seus dispositivos precisam "se enxergar" na rede:

  • Rede local: o celular ou o computador que executa o qFT8 e o seu dispositivo de controle (computador, tablet ou celular) precisam estar na mesma rede.
  • Configurações do roteador: alguns roteadores vêm com um recurso chamado isolamento de AP (ou isolamento de clientes) ativado por padrão. Ele precisa estar desativado para que os dispositivos se comuniquem entre si.
  • Com o hotspot de um celular: em campo, você pode abrir um hotspot Wi-Fi em um celular (com internet) e conectar o celular do qFT8 a essa rede Wi-Fi. Depois de conectar, feche e reabra o servidor web nas configurações do qFT8; o endereço IP mostrado passa a ser acessível a partir do celular que fornece o hotspot.
  • Acesso pela internet: acessar o servidor de fora da sua casa (pela internet) exige o redirecionamento de portas nas configurações do roteador (associando o IP e a porta internos a uma porta externa). Note que isso geralmente não funciona em conexões 5G/LTE, por causa das restrições de NAT das operadoras.

Níveis de acesso

Você pode configurar o nível de segurança do acesso remoto no painel de configurações:

  • Apenas leitura: permite ver o espectrograma ao vivo, as estações ativas e o log de QSOs. Nenhuma ação pode ser feita.
  • Ler e parar TX: é, antes de tudo, um modo de segurança. Permite ver todos os dados e desarmar o transmissor (parar o TX) em caso de emergência, mas não permite iniciar o TX nem mudar configurações.
  • Controle total: dá autoridade completa sobre o aplicativo, com todos os recursos interativos.

Nota de segurança: qualquer pessoa com acesso à sua rede, ao endereço IP e à porta terá o nível de controle que você configurou. Com Controle total, ela poderia começar a transmitir usando a sua estação.

O que é possível fazer

No modo Controle total, a interface web oferece quase tudo o que a interface do aplicativo oferece:

  • Modos de operação: alternar entre os modos AUTO e CALL manual.
  • Estratégia: mudar os critérios do AUTO (Qualquer um, DXCC, Grid etc.) e as restrições da busca.
  • Transmissão: iniciar/parar o TX manualmente, escolher mensagens de TX específicas e mudar a sequência do FT8 (0/1).
  • Frequência e banda: toque no espectrograma da página para mover seu desvio de frequência, ou mude a banda ativa do rádio.

SSB, CW, RTTY e SSTV são operados no próprio qFT8. Enquanto o aplicativo está em um deles, a página web mostra a cascata e se o aplicativo está transmitindo, e não transmite; escolha um modo digital na página para voltar a operar a partir dela.

O limite de transmissão contínua do rádio vale para a página exatamente como para o aplicativo. Quando ele mantém o TX desligado (por exemplo WSPR com um limite de 60 segundos) ou interrompe o TUNE, a página mostra por alguns segundos um aviso que explica o motivo, para que você não fique em dúvida diante de um botão que não faz nada. O limite em si só é alterado no aplicativo.

Nota: a interface web foi feita para continuar respondendo mesmo que a tela do celular fique lenta por causa de interferência de RF, o que dá uma alternativa confiável de controle.

Nota: o servidor web funciona com a tela desligada se as configurações de execução em segundo plano estiverem ativadas (por padrão, o qFT8 continua em execução em segundo plano quando está conectado a um transceptor).

qFT8 bridge

O qFT8 bridge permite deixar o rádio em um lugar e operar de outro. Um dispositivo ao lado do rádio, o bridge, passa os comandos do rádio e o seu áudio pela sua própria rede para o qFT8 em outro dispositivo. Esse qFT8 faz todo o resto: decodifica, registra no log e decide o que transmitir. Para ele, o rádio funciona como se estivesse conectado por USB.

Use-o quando o rádio fica perto da antena, no sótão, na garagem ou no quartinho do quintal, e você quer operar de um lugar mais confortável; ou quando o dispositivo ao lado do rádio deve apenas cuidar do rádio: um computador pequeno como um Raspberry Pi, ou um celular ou tablet antigo.

Isto não é o mesmo que o servidor web de controle remoto. Lá, o qFT8 roda ao lado do rádio e você o vê em um navegador. Com o bridge, o qFT8 roda no dispositivo à sua frente e só o rádio fica em outro lugar.

O que você precisa

  • Um dispositivo ao lado do rádio, com o rádio conectado a ele por USB como de costume: um computador com Windows, macOS ou Linux (um Raspberry Pi basta), ou um celular ou tablet Android. Este é o bridge.
  • O qFT8 no dispositivo de onde você opera: o programa para computador ou o aplicativo Android. Qualquer um deles pode usar qualquer bridge: um celular pode operar um rádio ao lado de um computador, um computador um rádio ao lado de um celular, e assim por diante.
  • Os dois na mesma rede local. Um cabo de rede funciona tão bem quanto o Wi-Fi e é mais estável; se puder, dê um cabo pelo menos ao bridge. Um celular ou tablet usa o seu Wi-Fi, nunca os dados móveis.
  • A senha do bridge. O bridge cria uma e a mostra para você.

Configurando o bridge

Há duas maneiras de rodar um bridge. Escolha uma.

1. Pelas Configurações do qFT8 (o programa para computador ou o aplicativo Android). No dispositivo ao lado do rádio, abra Configurações > qFT8 BRIDGE e marque Funcionar como qFT8 bridge na porta. Deixe a porta como está, a menos que outro programa a use.

Senha mostra a senha de que o outro dispositivo vai precisar. NOVA SENHA cria outra; toque na própria senha para digitar a sua (7 caracteres ou mais).

Enquanto é um bridge, o qFT8 nesse dispositivo não faz mais nada. O TX é desligado, o seu próprio uso do rádio para, e a tela mostra apenas qFT8 funcionando em modo bridge, com o Endereço e a Senha a digitar no outro dispositivo e quem está usando o rádio (Ninguém está conectado, ou o nome do dispositivo). No Android o bridge continua funcionando com a tela desligada, indicado por uma notificação; deixe o celular ou tablet no carregador.

DESLIGAR O MODO BRIDGE pergunta primeiro, porque o outro dispositivo perde o rádio imediatamente, e depois devolve o qFT8 ao estado anterior, com o TX ainda desligado. Se você fechar o qFT8 enquanto ele é um bridge, ele começa como bridge de novo na próxima vez.

2. Pela linha de comando (só computadores). Para um computador sem outra função, também um Raspberry Pi ou um servidor sem tela: inicie o qFT8 com --bridge. Ele então roda apenas como bridge, sem janela, e não carrega mais nada do qFT8 (nem configurações, nem decodificação), então precisa de muito pouca memória. Use o qFT8 que você baixou para esse computador, a partir de um terminal:

  • Windows: abra um Prompt de Comando na pasta do qFT8 e digite qFT8.exe --bridge --tx-volume 70. Se o Windows perguntar se deve permitir "OpenJDK Platform binary" nas suas redes, permita.
  • macOS: no Terminal, digite /Applications/qFT8.app/Contents/MacOS/qFT8 --bridge --tx-volume 70. Na primeira vez, o macOS pede acesso ao microfone: permita, é assim que o áudio do rádio é lido.
  • Linux: na pasta do qFT8, digite ./qFT8 --bridge --tx-volume 70.
  • Qualquer computador com Java 21 ou mais recente, por exemplo um Raspberry Pi com o Java do seu sistema: o download .jar do qFT8 roda em qualquer sistema. Digite java -jar, o nome do arquivo .jar e --bridge. Ele traz o que precisa para usar portas seriais no Windows, macOS e Linux (PCs e placas ARM, 32 e 64 bits).

O terminal mostra a senha na primeira execução e a guarda para as próximas. Deixe o terminal aberto: o bridge funciona enquanto ele estiver aberto. Ctrl+C, ou fechar o terminal, o encerra e põe o rádio de volta em recepção.

Opções que podem ser úteis, acrescentadas depois de --bridge:

  • --tx-volume N: obrigatório: o nível de áudio, de 1 a 100 %, que a ponte define no dispositivo de som do rádio para transmitir, como a configuração de volume de TX do próprio qFT8 (70 por padrão; rádios QRP Labs: 100). É só o nível do som: a potência do rádio nunca é alterada.
  • --password TEXT: a sua própria senha em vez da que ele criou.
  • --show-password: mostra de novo a senha guardada.
  • --new-password: cria uma nova.
  • --name TEXT: o nome que os outros dispositivos veem na lista deles (senão é "qFT8 bridge"), útil com mais de um bridge.
  • --only TEXT: compartilha só a porta serial e o dispositivo de som do rádio, indicados por uma parte do nome deles (por exemplo --only QMX); nada mais do computador é oferecido.

--bridge --help lista o resto.

Conectando a partir do qFT8

No dispositivo de onde você opera, abra Configurações > CONFIGURAÇÃO DO DISPOSITIVO e marque Conectar por um qFT8 bridge, bem no topo. Aparecem estas linhas:

  • Método: qFT8 bridge.
  • Bridge: abre a lista dos bridges que o qFT8 encontra na sua rede. Escolha o seu. Procurar novamente procura mais uma vez. Se o seu não estiver na lista, escolha Digitar endereço e digite o endereço que o bridge mostra.
  • Senha: a que o bridge mostra.
  • CONECTAR: a caixa ao lado fica verde e mostra Conectado a seguido do nome do bridge.
  • Porta do rádio no bridge, Dispositivo de som no bridge (recepção) e Dispositivo de som no bridge (transmissão): onde o rádio está conectado do lado do bridge. AUTO os encontra; escolha manualmente só quando o bridge tiver vários. Um rádio acessado pelo programa próprio dele no computador do bridge (uma porta serial virtual e um cabo de áudio virtual) tem uma porta que o AUTO não consegue reconhecer: escolha a porta manualmente e verifique se os dois dispositivos de som são os do cabo.

A partir daqui tudo é como com um rádio por USB: o qFT8 reconhece o rádio, lê a frequência, recebe e transmite. O qFT8 se lembra do bridge e da senha, e uma exportação das configurações os leva aos seus outros dispositivos. Enquanto a caixa estiver marcada, um rádio conectado ao dispositivo de onde você opera não é usado. Para voltar a ele, desmarque Conectar por um qFT8 bridge; não é preciso reiniciar.

Em um celular ou tablet, a caixa de estado mostra Sem Wi-Fi. Conecte este dispositivo à rede do bridge. quando ele não está em uma rede Wi-Fi: o bridge só é procurado ali.

A indicação da conexão

Abaixo dos dispositivos do bridge, uma linha diz como vai a conexão, por exemplo Atraso 120 ms, ajustado automaticamente. Conexão: estável (variação 3.0 ms).

  • Atraso: uma rede nunca entrega o som de forma perfeitamente regular, então o áudio é retido por um instante antes de ser tocado, para compensar isso. Não há nada a ajustar: o qFT8 e o bridge escolhem o atraso sozinhos, aumentam-no quando o áudio chega tarde e o diminuem de novo quando a conexão fica limpa por um tempo. Isso não atrapalha a temporização dos modos digitais: suas transmissões continuam começando na hora, e o que você recebe é posicionado pelo momento em que o rádio o ouviu.
  • Conexão: estável: está tudo bem.
  • Conexão: irregular: o áudio está chegando de forma irregular. O atraso cuida disso; não há nada a fazer, a menos que continue assim.
  • Em vermelho, A conexão com o bridge está perdendo áudio de transmissão: parte de uma transmissão não chegou ao rádio a tempo. O atraso é aumentado imediatamente; se isso continuar acontecendo, veja Solução de problemas.
  • Em vermelho, A conexão com o bridge não dá conta: nem o maior atraso é suficiente e o áudio de transmissão falha. Veja Solução de problemas.

Logo depois de conectar, a linha mostra Nada medido ainda.

Segurança da transmissão

  • Só você liga o TX, com o botão TX do qFT8 à sua frente. O bridge nunca inicia uma transmissão sozinho.
  • Se a conexão cair (o Wi-Fi some, o dispositivo entra em repouso, o qFT8 é fechado), o bridge põe o rádio de volta em recepção sozinho, em um ou dois segundos. O qFT8 para o que estava transmitindo, desliga o TX e mostra um cartão vermelho dizendo o porquê, como Conexão perdida. Conectando novamente... Ele se reconecta sozinho. Se a conexão voltar em até 10 segundos e você estava com o TX ligado, o qFT8 o liga de novo uma vez, como você o tinha; depois de uma queda mais longa ele fica desligado até você pressioná-lo de novo.
  • O limite de transmissão contínua do seu rádio também é respeitado pelo bridge.
  • Parar o bridge, de qualquer uma das duas maneiras, também põe o rádio de volta em recepção.

Nota de segurança: A senha protege o controle do seu rádio: ninguém sem ela pode usar o bridge, e a própria senha nunca é enviada pela rede. Ela não torna a conexão privada: o áudio e os comandos do rádio não são criptografados. Use o bridge somente dentro da sua própria rede e não o abra para a internet.

Limites

  • Só rede local. O bridge não foi feito para ser acessado pela internet. Uma VPN que envia o tráfego da sua rede doméstica pelo túnel dela também esconde o bridge: desligue-a, ou permita nela o acesso à rede local, nos dois dispositivos.
  • Um dispositivo de cada vez. Quando um segundo dispositivo se conecta, ele assume; o primeiro mostra Outro dispositivo assumiu o bridge. Pressione CONECTAR para retomá-lo.
  • Todos os modos funcionam através de um bridge, recebendo e transmitindo: FT8, FT4, FT2, JS8, WSPR, LQ8, SSB, CW, RTTY, SSTV e TUNE. Seu alto-falante e seu microfone continuam no dispositivo à sua frente; só o áudio do rádio atravessa a rede.
  • Um rádio que é posto em transmissão por uma linha de controle (RTS ou DTR) em vez de um comando também é chaveado através do bridge.

qFT8log

O qFT8log mantém juntos os logs de vários qFT8 pela sua própria rede. Um qFT8 é o servidor qFT8log; os outros enviam a ele cada QSO que fazem. O servidor os acrescenta ao seu próprio log (a lista de QSOs, o mapa, as estatísticas) e os repassa aos serviços configurados nele, como QRZ e LoTW. O que acontece depois com um QSO, uma confirmação ou uma correção, volta para o qFT8 que o fez enquanto os dois estiverem conectados.

Qualquer qFT8 pode ser servidor e cliente ao mesmo tempo: o programa para computador, o app Android e o app iPhone. No Android o servidor continua rodando em segundo plano quando Executar em segundo plano está ativado; no iPhone ele roda só enquanto o app está aberto.

Configurando o servidor

  1. No qFT8 que deve reunir os QSOs, abra Configurações, vá em Servidores e abra Servidor qFT8log.
  2. Digite uma senha. Use o mesmo tipo de senha do bridge do qFT8: sete caracteres ou mais.
  3. Deixe a porta em 13510, a menos que outra coisa a use, e ative o servidor. A página mostra o endereço do servidor e os qFT8 conectados a ele. Uma porta alterada vale na hora.
  4. O mesmo endereço aberto em um navegador (por exemplo http://192.168.1.20:13510/) mostra o log, somente leitura, depois que você digita a senha do servidor (ela nunca é enviada): veja Vendo o log em um navegador.

Configurando um cliente

  1. Em cada qFT8 que deve enviar seus QSOs, abra Configurações e pressione a engrenagem ao lado de qFT8log, no alto.
  2. Pressione PROCURAR: os servidores qFT8log da sua rede aparecem listados por nome. Escolha um, ou digite você mesmo o endereço e a porta do servidor.
  3. Digite a senha do servidor e pressione VALIDAR. Quando o servidor a aceitar, marque qFT8log no alto das Configurações.

A partir daí o cliente se conecta sozinho sempre que inicia e se reconecta sozinho quando a rede ou o servidor voltam. Os QSOs feitos enquanto o servidor não está acessível esperam no log (aparecem como não enviados ao qFT8log) e são enviados assim que a conexão volta, também após uma reinicialização. Quando o cliente não consegue alcançar o servidor, a linha qFT8log nas Configurações fica vermelha com Não foi possível conectar desde e a hora.

Considerar um QSO enviado se estiver enviado aqui vem desativada para o qFT8log. Marque-a quando o servidor for o lugar para onde seus QSOs vão, para que a marca de "aguardando envio" de um QSO suma assim que o servidor o tiver.

O que trafega

  • QSOs novos, do cliente para o servidor, com todos os campos que o qFT8 guarda: os relatórios, grids, parques e cumes, equipamento, comentários, e se o QSO já foi enviado ao QRZ, ao LoTW ou a outro serviço, ou confirmado por eles (um QSO importado do LoTW continua confirmado).
  • Confirmações, nos dois sentidos, assim que chegam: uma confirmação que o servidor recebe do LoTW aparece no cliente que fez o QSO, e vice-versa.
  • Correções feitas no editor de QSOs, nos dois sentidos. Quando o mesmo QSO foi alterado nos dois lados, vale a alteração mais recente.
  • Exclusões nunca viajam. Excluir um QSO o exclui apenas naquele qFT8; os outros mantêm o deles. Cada qFT8 lembra os QSOs excluídos nele e nunca os recebe de volta de outro qFT8, nem por uma importação nem pela sincronização ao vivo.

O servidor aceita QSOs de todos os modos e de todos os indicativos: é o lugar onde você reúne, e os filtros do log escolhem o que você vê. Um QSO que o servidor já tem (o mesmo indicativo, hora, banda e modo) é mesclado com o que ele tem, nunca é acrescentado duas vezes e não é enviado adiante de novo.

Importando do servidor e sincronização ao vivo

Um cliente envia apenas os seus próprios QSOs. Duas maneiras trazem também o log do servidor para ele:

  • IMPORTAR QSOs DO SERVIDOR, na página do qFT8log do cliente, copia uma vez cada QSO do servidor dentro de De, Até, Bandas e O indicativo começa com, de todos os modos. QSOs feitos com outro indicativo que não o seu são ignorados, a menos que Importar QSOs para indicativos diferentes do atual esteja marcado. Funciona também quando o qFT8log não está marcado no topo das Configurações: a importação então se conecta só para si e não envia nada.
  • Manter sincronizado ao vivo com este servidor (exige o qFT8log marcado no topo das Configurações): os QSOs do servidor vêm para cá e, a partir daí, todo QSO registrado, corrigido ou confirmado no servidor, ou em qualquer outro qFT8 conectado a ele, aparece aqui na hora, e os seus vão para lá. Vários qFT8 com esta caixa marcada compartilham um só log pelo seu servidor e, com cadeias, por todos os servidores da cadeia.
  • Se a conexão cair, nada se perde: cada lado se atualiza quando ela voltar, também depois de uma reinicialização.
  • Os horários das correções seguem o relógio do servidor, de modo que um aparelho com o relógio errado não ganhe nem perca todas as correções.

Cadeias: reunir e fazer backup

Um servidor pode ser ele mesmo cliente de outro servidor, então os qFT8 podem ser encadeados. Um QSO nunca é enviado de volta a um qFT8 por onde já passou, de modo que nem um anel de qFT8 forma laço. Dois exemplos:

  • Um só lugar que envia. Os celulares e o computador portátil enviam para o computador da estação. Só o computador da estação tem o QRZ e o LoTW configurados: ele envia tudo, e as confirmações que recebe voltam para o qFT8 que fez cada QSO.
  • Um backup. O computador da estação também envia tudo a outro qFT8, digamos um tablet antigo que só guarda o log e mostra o mapa-múndi. Nada precisa ser configurado no backup além do seu servidor.

Nota de segurança: a senha nunca é enviada pela rede: os dois qFT8 provam que a conhecem, e cada mensagem depois disso é assinada, de modo que nada pode ser alterado nem repetido no caminho. Com Criptografar as conexões do qFT8 log ativado (por padrão, tanto no cliente quanto no servidor) os QSOs também são criptografados, então ninguém mais na rede consegue lê-los. Use o qFT8log só dentro da sua própria rede e não abra a porta dele para a internet.

Limites

  • Só rede local, como o bridge do qFT8.
  • Os dois qFT8 devem rodar a mesma versão do qFT8log. Um servidor recusa um cliente de outra versão, e a linha do cliente diz qual deve ser atualizado.
  • No máximo 16 clientes por vez em cada servidor.
  • Um QSO que o servidor não consegue ler (por exemplo, um sem data) é marcado como recusado no cliente e só é enviado de novo depois que você o corrigir.

Protocolo do qFT8log (versão 2)

Esta é a descrição completa do que dois qFT8 dizem um ao outro. Todo número é big-endian. O texto é UTF-8.

Encontrando servidores

Um cliente envia um datagrama UDP aos endereços de broadcast de suas redes, porta 13510: "qFT8L?" (6 bytes), a versão da API (2 bytes), um id aleatório (8 bytes). Cada servidor responde ao remetente: "qFT8L!", a versão da API dele (2), o mesmo id (8), a porta TCP dele (2), o id de instância dele (16 dígitos hexadecimais ASCII), o tamanho do nome dele (1) e o nome dele (no máximo 64 bytes). A resposta não diz nada secreto.

Quadros

Por TCP (porta 13510 por padrão) tudo trafega em quadros: o tipo (1 byte), o tamanho do corpo (3 bytes) e o corpo (no máximo 16384 bytes). Os quatro primeiros tipos trafegam antes de as chaves existirem; o corpo de qualquer outro quadro é selado: um contador de 8 bytes, a mensagem e os primeiros 16 bytes do HMAC-SHA256 (chave da direção) sobre o tipo, o contador e a mensagem. Cada direção conta a partir de 0 e um quadro deve trazer exatamente o número seguinte: um quadro alterado, repetido ou omitido encerra a conexão.

Tipo 0x01

Corpo "QFT8LOG1", versão da API (2), aleatório do cliente (32), id de instância do cliente (16 ASCII), tamanho do nome (1), nome
Tipo 0x02
Nome CHALLENGE (servidor)
Corpo versão da API (2), aleatório do servidor (32), sal (16), rodadas (4), id de instância do servidor (16 ASCII), tamanho do nome (1), nome, prova do servidor (32)
Tipo 0x03
Nome AUTH (cliente)
Corpo prova do cliente (32)
Tipo 0x04

Tipo 0x10

Tipo 0x24

O handshake

Os dois lados conhecem k = PBKDF2-HMAC-SHA256(senha, sal, rodadas), 32 bytes. O servidor escolhe o sal e as rodadas (200000; um cliente recusa menos de 10000 ou mais de 5000000). A transcrição t é o corpo do HELLO seguido do corpo do CHALLENGE sem a prova dele. Com L = o texto ASCII "qFT8 log v1 ":

  • prova do servidor = HMAC-SHA256(k, L + "server proof" + t); prova do cliente = HMAC-SHA256(k, L + "client proof" + t);
  • chave do cliente para o servidor = HMAC-SHA256(k, L + "key client>server" + t); chave do servidor para o cliente = HMAC-SHA256(k, L + "key server>client" + t).

O cliente confere primeiro a prova do servidor e fecha sem responder quando ela está errada, de modo que nada derivado da senha chega a um servidor que não a conhece. O servidor confere a prova do cliente; uma errada bloqueia esse endereço por 1 s, dobrando a cada tentativa errada seguida até 60 s. Os dois aleatórios são novos a cada conexão, então um handshake gravado não vale nada. As versões da API devem ser iguais: um servidor recusa qualquer outra com o motivo 1, e um cliente recusa um CHALLENGE de outra versão. Um servidor admite 8 handshakes ao mesmo tempo, 5 s para cada etapa e 16 clientes; um cliente que se conecta de novo assume o lugar da conexão antiga dele.

Registros

Um registro de QSO é um objeto JSON com os nomes de campo que o qFT8 guarda (call, qso_date como YYYYMMDD, time_on como HHMM ou HHMMSS, band, mode, submode, rst_sent, rst_rcvd, gridsquare, freq, station_callsign, my_gridsquare, comment, as referências de parques e cumes, os estados do QRZ e do LoTW app_qrzlog_logid, app_qrzlog_status, app_lotw_qsl_rcvd, app_lotw_logid, app_lotw_upload_time, e app_svc), no máximo 16000 bytes. call, qso_date e time_on são obrigatórios; qualquer modo e qualquer indicativo são aceitos. app_svc guarda os estados dos outros serviços e três registros do próprio protocolo, como partes id:key=value,... separadas por ;:

  • q8u: id = o uid do QSO (criado uma vez pelo qFT8 que o enviou primeiro, mantido em todas as correções), t = quando o conteúdo dele foi corrigido pela última vez (ms UTC, ausente = nunca);
  • q8v: id = os ids de instância por onde o QSO passou, separados por pontos (no máximo 32);
  • um remetente omite a própria contabilidade: seus hashes por par, seu próprio estado de envio e suas marcas de trabalho locais.

Hash e mesclagem

O hash de um QSO são os primeiros 8 bytes do SHA-256, como 16 dígitos hexadecimais, sobre as linhas name=value do conteúdo dele, da hora de correção dele e dos estados de envio e de confirmação dele (não as instâncias por onde passou). Duas cópias de um mesmo QSO viram uma só do mesmo jeito em todo lugar: vale, como um todo, o conteúdo da cópia corrigida mais tarde (horas iguais: vale o conteúdo de maior hash); os estados de envio e de confirmação só avançam (uma confirmação nunca é desfeita); as instâncias são a união das duas. A mesclagem é a mesma qualquer que seja a ordem e mesclar duas vezes não muda nada, então todas as cópias terminam iguais.

Quem envia o quê

  • Um cliente envia ao seu servidor cada QSO que ainda não passou por esse servidor, e cada QSO que os dois já trocaram antes e cujo hash mudou desde então.
  • Um servidor envia a um cliente os QSOs que os dois já trocaram e cujo hash mudou (uma confirmação, uma correção). Depois de um SUBSCRIBE, ele envia também a esse cliente todo QSO do seu log dentro da assinatura que os dois nunca trocaram e que não passou pelo cliente, e então BACKLOG_DONE. Com live ele continua fazendo isso para cada QSO que receber depois, enquanto durar a conexão (o cliente assina de novo a cada reconexão); once termina com BACKLOG_DONE; off encerra a assinatura.
  • O receptor encontra a sua cópia pelo uid ou, senão, por indicativo, data, hora (HHMM), banda e modo. Um servidor adiciona um QSO que não tem; um cliente adiciona um apenas dentro da assinatura que enviou. Nenhum dos dois adiciona um QSO excluído nele (resultado 3 nos dois casos). Caso contrário, as cópias são mescladas; o ACK leva o hash do receptor e, quando a cópia mesclada difere do que foi enviado, o registro mesclado, que o remetente por sua vez mescla.
  • Cada lado lembra, por QSO e por par, o hash em que os dois concordaram por último, e só envia de novo quando a própria cópia difere dele. As exclusões nunca são enviadas.
  • No máximo 16 PUTs podem esperar a resposta. Um servidor aceita 100 PUTs por segundo de cada cliente (rajadas de 200) e responde NACK 2 acima disso; após 50 registros que não consegue ler, ele encerra a conexão.
  • Um lado envia PING quando não enviou nada por 15 s e encerra a conexão quando não ouviu nada por 45 s. Um cliente se reconecta com intervalos de 1 s, 2 s, 4 s ... até 60 s.

Layouts de tela

As capturas de tela deste manual mostram o layout padrão: paisagem, com o espectrograma à esquerda. No aplicativo para Android, Configurações > APLICATIVO > Interface do usuário permite mudá-lo (o programa de computador não tem nenhuma destas configurações: ele tem os seus próprios layouts, veja Os layouts de tela e o botão de layout):

  • Orientação: Paisagem, Retrato ou Seguir o celular. Em retrato o espectrograma fica em cima, a aba embaixo dele, e em um celular a barra inferior ocupa duas linhas.
  • O divisor: arraste a linha fina entre o espectrograma e a aba para dar mais espaço a um deles. Cada orientação lembra a sua própria posição.
  • Quadrantes (tablets): o espectrograma, as estações, o mapa mundial e o log de QSOs de uma só vez, com as Configurações abrindo à direita.
  • Recursos: Recursos de rádio, Log de QSOs e Mapa mundial podem ser desligados separadamente se você não os usa, por exemplo para usar o qFT8 só como logbook. Enquanto um está desligado, um botão ATIVAR para ele aparece nas Configurações. Desligar os recursos de rádio também desliga o TX.
  • O aplicativo cobre: permite que o qFT8 desenhe sobre a barra de navegação, a área da câmera e a barra de status, para ganhar um pouco mais de espaço.

Relatórios de erros e novas versões

Relatar um problema

RELATAR ERRO, no fim da aba Configurações, abre um cartão onde você descreve o que deu errado e, se quiser uma resposta, deixa seu e-mail. Tocar em ENVIAR envia sua descrição junto com o log do aplicativo: configurações, detalhes do rádio e do áudio e atividade recente. Senhas, chaves de API, certificados e os dados de acesso dos seus serviços de QSO nunca são incluídos. Você recebe uma referência como QFT8-7K3P9 para citar depois. Se não for possível acessar o servidor de relatórios, o qFT8 se oferece para enviar o relatório por e-mail.

"Enviar um relatório sobre isso?"

Quando o qFT8 percebe que parou de responder por um momento, ou que a decodificação está demorando demais no seu dispositivo, ele pode mostrar um pequeno cartão que oferece enviar um relatório sobre isso, com ENVIAR, NÃO ENVIAR e NÃO PERGUNTAR DE NOVO. Nada é enviado sem o seu toque. O cartão aparece no máximo uma vez por dia, e NÃO PERGUNTAR DE NOVO o silencia por uma semana. Depois de um travamento, o qFT8 pergunta na próxima inicialização se deve enviar um relatório de falha.

Procurar novas versões ao iniciar

Com esta caixa marcada (página principal das Configurações, perto do fim), o qFT8 procura uma versão mais recente ao iniciar e, quando há uma, mostra um aviso com um botão de download. Ele nunca se atualiza sozinho.

Resumo anônimo de desempenho

Enviar um resumo diário anônimo de desempenho (página principal das Configurações, logo acima de Idioma) fica desligado, a menos que você o ligue. Quando ligado, cerca de uma vez por semana o qFT8 envia um breve resumo da velocidade com que funciona no seu dispositivo: tempo de inicialização, fluidez da tela, tempos de decodificação, tempos de áudio e de rádio, e o modelo do dispositivo e a tela. Nunca contém seu indicativo, grid, log, configurações nem nada que identifique você. Ajuda a deixar o qFT8 mais rápido em dispositivos como o seu.

Solução de problemas

O celular ou o computador não reconhece o transceptor ou ele é desconectado

Quase sempre é um problema de conexão física ou de interferência de rádio. As conexões USB são sensíveis à vibração, à qualidade do cabo e à sujeira acumulada na porta USB. No Android, outra causa comum é que o USB OTG pode estar desativado por padrão no seu dispositivo (em especial, se você consegue receber sinais no qFT8, mas não transmitir, e os comandos CAT não funcionam mesmo com um dispositivo totalmente compatível, mostrado na lista de dispositivos, reconhecido automaticamente no modo AUTO etc., é muito provável que esta seja a causa).

Experimente:

  • No Android, ativar o USB OTG nas configurações do dispositivo (em alguns dispositivos o OTG vem desativado por padrão e pode estar nas configurações avançadas, do sistema ou adicionais).
  • Usar um cabo USB curto e de boa qualidade (um cabo mais curto pode ajudar bastante), e verificar se a porta USB está limpa e a conexão está firme.
  • No Linux, se o qFT8 disser que não tem permissão para abrir a porta do rádio, aceite a oferta dele para corrigir isso (a sua conta entra no grupo da porta), ou peça ao administrador do seu sistema.
  • Se os problemas acontecem especificamente durante a transmissão, a causa pode ser interferência de rádio. Colocar chokes ou ferrites no cabo USB pode ajudar. Você também pode tentar transmitir em outra banda, porque alguns dispositivos só são sensíveis à interferência em certas bandas.

O transceptor desaparece quando o celular está totalmente carregado (Android)

Isso acontece com adaptadores USB OTG que têm uma entrada de carga, para que o celular possa ser carregado enquanto o transceptor está conectado. Com alguns deles, quando a bateria chega a 100% o celular corta a conexão USB com o transceptor, e ela não volta até que o carregador seja desconectado. O qFT8 mostra então o transceptor como desconectado e nada funciona: nem áudio, nem CAT.

Experimente: Desconectar o carregador do adaptador (o transceptor volta), operar sem carregar, ou usar outro adaptador ou um hub com alimentação.

qFT8 bridge: "Nenhum bridge encontrado nesta rede"

O qFT8 perguntou à rede e nenhum bridge respondeu. As causas habituais são que o bridge não está rodando, que os dois dispositivos não estão na mesma rede (um Wi-Fi de convidados conta como outra rede), ou que algo entre eles bloqueia a pergunta.

Experimente:

  • Verificar se o bridge está rodando: a janela dele está aberta, ou o qFT8 nesse dispositivo mostra qFT8 funcionando em modo bridge. Depois, Procurar novamente.
  • Usar Digitar endereço e digitar o endereço que o bridge mostra. Um bridge que a busca não encontra muitas vezes ainda responde quando é chamado diretamente.
  • Liberar o bridge no firewall do computador dele: portas TCP e UDP 13498, e porta UDP 13499 (a que a busca usa).
  • Desligar o isolamento de AP (ou isolamento de clientes) no roteador, como para o servidor web de controle remoto.
  • Desligar uma VPN nos dois dispositivos, ou permitir nela o acesso à rede local. Uma VPN que envia todo o tráfego pelo túnel esconde o bridge, mesmo com os dois dispositivos lado a lado.

qFT8 bridge: "Senha incorreta", ou o bridge recusa a conexão

A senha deve ser digitada exatamente como o bridge a mostra. Uma senha criada pelo bridge tem só letras minúsculas e dígitos, e nunca os caracteres parecidos i, l, o, 0 e 1. Depois de várias tentativas erradas seguidas, o bridge faz esse dispositivo esperar antes da próxima, até um minuto.

Experimente: Ler a senha de novo no bridge: na tela do modo bridge do qFT8, ou iniciando o download do bridge com --show-password. Na dúvida, crie uma nova (NOVA SENHA, ou --new-password) e digite essa.

qFT8 bridge: conectado, mas sem rádio ou sem áudio

A conexão funciona, mas o bridge não consegue usar a porta do rádio ou o seu dispositivo de som. A caixa pode mostrar Conectado a e o nome do bridge, seguido de "mas o dispositivo de som dele não pôde ser aberto".

Experimente:

  • Escolher Porta do rádio no bridge e as duas linhas de dispositivo de som manualmente em vez de AUTO.
  • Fechar qualquer outro programa no dispositivo do bridge que use o rádio, inclusive um qFT8 que não esteja em modo bridge.
  • No macOS, permitir o microfone para o bridge em Ajustes do Sistema > Privacidade e Segurança > Microfone.
  • No Linux, garantir que a conta que roda o bridge possa usar portas seriais (normalmente por pertencer ao grupo dialout) e o som.
  • Em um bridge Android, permitir que o qFT8 use o rádio quando o Android perguntar, como para um rádio conectado ao próprio celular.

qFT8 bridge: "A conexão com o bridge está perdendo áudio de transmissão" ou "não dá conta"

A rede entre os dois dispositivos é irregular demais: o áudio de transmissão chega tarde demais para ser tocado. Enquanto o atraso ainda pode crescer, o qFT8 o aumenta e diz que a conexão está perdendo áudio; quando nem o maior atraso basta, diz que a conexão não dá conta e as transmissões falham. É uma questão da rede, não do rádio.

Experimente: Aproximar-se do ponto de acesso Wi-Fi, conectar o bridge (ou os dois dispositivos) com um cabo de rede, e pausar o que mais estiver sobrecarregando a rede.

Em vez de receber o sinal do transceptor, o qFT8 está recebendo áudio do microfone

No Android, isso indica que o celular está usando o microfone interno porque não reconhece o transceptor como uma fonte de áudio externa. No computador, verifique qual entrada está escolhida em CONFIGURAÇÃO DO DISPOSITIVO nas configurações: escolha o dispositivo de áudio do transceptor. As causas mais comuns são:

  • O cabo USB não é próprio para dados (cabo só de carga).
  • O adaptador USB (OTG) está com defeito ou é incompatível (Android).
  • O cabo está conectado na direção errada (alguns cabos são direcionais).

Experimente: usar outro cabo USB, outro adaptador, ou inverter as pontas do cabo.

O mostrador do rádio não coincide com a frequência que o qFT8 mostra

O visor do rádio e o qFT8 diferem em alguns Hz até cerca de 100 Hz. Em geral é o desvio de sintonia do espectrograma, e é de propósito: o qFT8 sintoniza o rádio um pouco mais baixo e desloca o áudio na mesma quantidade, para que os sinais bem no início do espectrograma saiam da zona cega do rádio nos graves de áudio. Decodificações, spots, o log e a frequência mostrada pelo qFT8 continuam sendo a frequência real.

Experimente: Não há nada a consertar. O padrão depende do rádio (−100 Hz na família QMX, −90 Hz no IC-7300, −50 Hz em qualquer outro rádio). Para mudá-lo ou colocá-lo em 0, abra Configurações > CONFIGURAÇÃO DO DISPOSITIVO > Sintonia (este rádio) > Desvio de sintonia do espectrograma (veja Desvio de sintonia do espectrograma).

Nenhum sinal recebido; a cascata está totalmente preta

Se a cascata continua totalmente preta tanto com o transceptor conectado quanto desconectado, provavelmente o qFT8 não tem as permissões necessárias para acessar o áudio.

Experimente: no Android, vá em Configurações > Apps > qFT8 > Permissões do celular e verifique se o Microfone (ou a gravação de áudio) está permitido durante o uso do qFT8. Como alternativa, desinstale completamente o qFT8, reinstale-o e aceite todos os pedidos de permissão na primeira inicialização. No macOS, abra Ajustes do Sistema > Privacidade e Segurança > Microfone e permita o qFT8. Em qualquer computador, verifique a entrada escolhida em CONFIGURAÇÃO DO DISPOSITIVO.

Há sinais visíveis, mas nenhuma mensagem é decodificada

Se você vê "linhas onduladas" verticais na cascata (sinais FT8), mas nenhum texto aparece na aba Estações, talvez seu relógio não esteja sincronizado.

Experimente:

  • Verifique se há acesso à internet e reabra o aplicativo para disparar uma sincronização NTP.
  • Se não houver internet disponível, tente uma sincronização por GPS (Android).
  • Se isso também não funcionar, mas os tons das mensagens forem visíveis no espectrograma, dispare uma sincronização de emergência da hora a partir das mensagens, no menu de configurações de hora e localização.
  • Verifique se o rádio está de fato recebendo sinais do ar.

Se não aparece nenhuma faixa ondulada na cascata, talvez a banda esteja fechada ou a antena esteja desconectada ou desajustada.

As mensagens são decodificadas tarde demais

O processador do celular (ou de um computador mais antigo) pode ser lento demais para decodificar as mensagens a tempo.

Experimente: não deixe de mudar para Fast decode nas configurações, e fique à vontade para adiantar o momento da decodificação (por exemplo, para 13000ms), criando mais margem para decodificar, ao custo de talvez perder algumas mensagens atrasadas em cada ciclo.

Erro "SWR exceeded threshold — transmission stopped" com o transceptor QMX

Se o qFT8 mostra 0W durante a transmissão, há várias causas prováveis:

1. Proteção de SWR

Se o LCD do QMX mostra um "S" depois da frequência, a proteção de SWR entrou em ação. Isso significa que sua antena não está bem ajustada para a banda atual e que o QMX parou de transmitir para proteger seus circuitos.

Além disso, o qFT8 tem o seu próprio limiar de SWR, configurável nas configurações do aplicativo. Quando a SWR medida passa desse limiar, o qFT8 para a transmissão automaticamente, para proteger seu equipamento.

  • Firmware 1_04_004+: o qFT8 reinicia automaticamente a proteção de SWR ao final do ciclo.
  • Firmware 1_03_000+: você pode definir "SWR Protection reset options" como Timer ou TX->RX no menu do QMX. Assim o qFT8 continua operando sem que você precise tocar no transceptor.
  • Firmware antigo: com firmware do QMX anterior a 1_03_000, é preciso reiniciar o transceptor manualmente (desligar/ligar) ou entrar e sair do menu TUNE do QMX para limpar o erro.

Nota: o qFT8 espera 1 segundo depois do início da transmissão antes de verificar se há 0W, para evitar falsos positivos enquanto o QMX sobe a potência. Se o QMX se recupera e a potência passa de 1W, o indicador de problema some automaticamente.

2. O firmware não mede a potência

Se o QMX não mostra que a proteção de SWR está ativa, e mostra que a transmissão está acontecendo normalmente, pode ser que o firmware seja antigo e não meça a potência. Dispositivos como o QDX também não medem a potência. O qFT8 não sabe como interpretar 0W e se confunde.

Experimente: se o firmware do seu QMX é antigo, atualize-o. Se você usa um QDX, não há como contornar isso.

3. O sinal de áudio não chega ao QMX

Se o QMX não mostra o ícone "S" depois da frequência, é provável que o transceptor simplesmente não esteja recebendo um sinal de áudio adequado do qFT8. O volume pode estar baixo demais (sinal insuficiente) ou alto demais (o corte/a distorção faz o QMX rejeitar o sinal).

Experimente: confira o indicador de sinal do seu QMX. Um único ponto significa que não há áudio; dois pontos, que há áudio, mas não com volume suficiente. Vá à seção de configurações de FT8 e ajuste a opção "Definir o volume do sistema para [X] ao usar o rádio" para valores diferentes (por exemplo, 70%, 80%, 90%), até achar o nível certo para o seu dispositivo.

4. A SWR é baixa na sintonia, mas a proteção de SWR entra em ação

Isso sugere que a SWR dá picos em potência alta por alguns instantes durante a transmissão real, o que aciona a proteção de SWR. É sinal de uma antena temperamental (por exemplo, loops magnéticos), de um cabo ruim, de uma conexão ruim ou de um problema na montagem.

Experimente: acrescentar chokes de corrente de modo comum (como anéis de ferrite) deve reduzir a corrente de modo comum.

O que é a notificação do qFT8 no Android? (Android)

Essa notificação permite que o qFT8 continue processando o áudio e conduzindo os QSOs quando você minimiza o aplicativo ou desliga a tela.

  • Por padrão, ela aparece automaticamente quando um transceptor é conectado.
  • Você pode desativá-la nas configurações do qFT8, mas o qFT8 deixará de funcionar em segundo plano.
  • Você pode tocar em PARAR na notificação para fechar o qFT8 por completo.

O qFT8 para de funcionar quando a tela está desligada (Android)

Alguns fabricantes de aparelhos Android aplicam otimizações de bateria muito agressivas, que podem encerrar os aplicativos em segundo plano mesmo que você tenha concedido as permissões iniciais.

Confira se você concedeu as permissões: vá em Configurações > Apps > qFT8 > Bateria do celular e selecione "Sem restrições" (ou "Não otimizar").

Os botões se comportam de modo estranho ou a tela não responde durante o TX

Isso é causado por interferência de RF (RFI). Se a sua antena está perto do celular ou do computador, ou o cabo é mal blindado, a energia de rádio pode interferir na tela sensível ao toque, no mouse ou na conexão USB.

  • Dica: use um cabo USB blindado ou prenda um ferrite de encaixe no cabo.

O qFT8 está diferente das capturas de tela deste manual

A interface do aplicativo é atualizada de vez em quando, de modo que alguns detalhes visuais podem ter mudado desde que as capturas de tela foram feitas. Mas, se faltam partes importantes da interface ou as cores parecem muito alteradas (por exemplo, a barra de progresso amarela, os seletores de sequência etc.), o modo escuro do sistema do seu celular pode estar se sobrepondo indevidamente à paleta de cores do aplicativo e bagunçando-a.

Experimente: se o modo escuro do sistema está causando problemas, você pode desativá-lo temporariamente ou colocar o qFT8 na lista de exceções dele, para recuperar o visual correto.

O qFT8 diz "NO RADIO" mesmo com o transceptor conectado

Provavelmente você não concedeu a permissão para conectar o qFT8 ao transceptor. Às vezes isso acontece porque se toca fora da caixa de diálogo de permissão, e ela se fecha.

Experimente: desconecte e reconecte o transceptor; isso deve fazer a pergunta aparecer de novo. Por comodidade, marque a opção "Sempre abrir o qFT8 quando o Transceptor for conectado", para nunca mais ter esse problema.

O qFT8 mostra a distância em milhas e eu quero em quilômetros (ou vice-versa)

Isso vem da localidade do sistema operacional (isto é, da escolha de idioma).

Experimente: mudar essa configuração para o país certo (por exemplo, inglês (Estados Unidos) para milhas, inglês (Reino Unido) para quilômetros) resolve.

O qFT8 mostra uma potência de transmissão baixa (por exemplo, 0.1W) ao transmitir com >10W no QMX

Este é um bug conhecido do firmware do QMX (pelo menos até o 1.03.000). Se você usa as modificações 2x4 (por exemplo, em um QMX+) e sua potência de transmissão passa de 9.9W, a formatação do rádio dá a volta. Por exemplo, 10.1W é informado pelo transceptor ao aplicativo como 0.1W no protocolo CAT secundário.

Experimente: não há como contornar isso dentro do qFT8, porque o aplicativo mostra diretamente o valor que recebe. Você pode ignorar esse erro de exibição sem risco, ou reduzir a potência para menos de 10W para manter as leituras corretas até que o bug seja corrigido no firmware do transceptor.

Não consigo exportar os logs ADIF para o armazenamento local com Compartilhar (Android)

O método padrão, Compartilhar, usa o mecanismo de compartilhamento do próprio Android para exportar os logs. Às vezes, o menu de compartilhamento de arquivos do seu dispositivo não oferece uma opção direta para salvar no armazenamento local.

Experimente: mude o Método de exportação para Salvar localmente nas configurações. Isso usa o seletor de arquivos do Android para salvar o arquivo diretamente no armazenamento local, sem depender do menu de compartilhamento.

O qFT8 não consegue decodificar algumas mensagens

Experimente: ative a decodificação profunda nas configurações. A decodificação profunda decodifica de forma recursiva e consegue decodificar mais mensagens quando a banda está cheia, ao custo de mais processamento. Ela também remove os harmônicos de estações muito fortes (as cópias ilegíveis que um sinal saturado deixa em frequências de áudio mais altas) para encontrar estações mais fracas debaixo deles. Fique de olho no espectrograma: se o tempo da decodificação profunda for alto demais no seu dispositivo (por exemplo, mais de 1 segundo) e o aplicativo não conseguir tomar decisões a tempo, desative a decodificação profunda.

O qFT8 trava ou se comporta de modo estranho

Se isso só acontece durante a transmissão, provavelmente é RFI extrema, como mencionado acima. Se acontece em outros momentos, role até o fim da aba Configurações e toque em RELATAR ERRO (veja Relatar um problema), ou use o link "Envie-me um e-mail para relatar problemas e bugs".
