qFT8 是什么？

qFT8 是一款业余无线电应用，可运行于 Android 手机和平板电脑、iPhone 和 iPad，以及 Windows、macOS 和 Linux 电脑，通过收发信机解码和发射 FT8、FT4、FT2、LQ8、JS8 或 WSPR 数字报文。使用同一台收发信机和同一根线缆，它还可以进行话音（SSB）、莫尔斯电码（CW）、RTTY 和图像（SSTV）通联。

两个版本的用法相同。有区别的地方，本手册会注明（“在 Android 上……”、“在电脑上……”）。截图显示的是 Android 应用；“点按”在 Android 上指触摸屏幕，在电脑上指用鼠标单击。

虽然 qFT8 对 QMX 和 ICOM 7300 提供开箱即用（即插即用）的支持，但您也可以把它用于任何收发信机：开启 VOX 后把手机或电脑放在扬声器和麦克风旁边，或者使用音频连接线。您也可以不接收发信机直接试用 qFT8：它用扬声器发射，用麦克风收听信号。几台运行 qFT8 的手机或电脑离得足够近时，可以通过声音互相通联。

qFT8 是一款免费应用，不含广告。其源代码的许可证将在源代码发布时确定（LICENSE）。

Luis Quesada Torres（HB9IPH）于 2026 年开发了 qFT8，拥有其版权并保留所有权利。

qFT8 包含来自以下项目的部分内容：usb-serial-for-android（版权所有 © 2011-2020 Google Inc., Mike Wakerly, Andreas Butti, Kai Morich, BSD-3-Clause）、Roboto（版权所有 © 2015 Google Inc. / Christian Robertson, Apache-2.0）、Roboto Mono（版权所有 © 2015 Google / The Roboto Mono Project Authors, OFL-1.1）、Natural Earth（Public Domain）、hamradio-zones-geojson（版权所有 © 2024 HB9HIL, HA8TKS, MIT license）、Big CTY（版权所有 © Jim Reisert AD1C）以及 Eclipse Temurin / BellSoft Liberica (OpenJDK) Java Runtime（版权所有 © Oracle and/or its affiliates and other contributors，GPLv2 with the Classpath Exception）。这些第三方作者或项目均未对 qFT8 表示认可，也与 qFT8 没有关联。

电脑上的 qFT8（Windows、macOS、Linux）

电脑版 qFT8 与 Android 版 qFT8 的工作相同：同样的模式，同样的 AUTO 和 CALL 操作，同样的日志和服务。本节只讲在 Windows、macOS 或 Linux 上使用时有何不同：如何安装，窗口如何排布，两个音量滑块，声音设备和电台如何选择， 以及如何使用鼠标。本手册的其余部分照常适用；某部分在电脑上不同时，会注明（“在电脑上……”）。

安装与首次启动

从 qft8.com 下载适合您系统的文件。每个下载包里都有一个文件夹或应用，内含程序、许可证和本手册。 无需再安装其他东西：qFT8 所需的 Java 运行环境已包含在内。

系统 Windows
下载 .zip，64 位或 32 位
您需要 Windows 10 或更新版本。只有在 32 位 Windows 上才使用 32 位文件。
系统 macOS
下载 .dmg，所有 Mac 通用一个文件（Apple Silicon 和 Intel）
您需要 macOS 10.13 或更新版本
系统 Linux
下载 .tar.gz：64 位电脑、32 位电脑、ARM 64 位或 ARM 32 位（Raspberry Pi）
您需要 带有声音服务器（PulseAudio 或 PipeWire）的桌面系统。已在较新的 Ubuntu 上测试，支持 X11 和 Wayland（通过 XWayland）。
系统 其他任何电脑
下载 .jar
您需要 Java 21 或更新版本，由您自行安装

qFT8 需要至少有 2 个处理器核心的电脑（建议 4 个），以及至少 960 x 560 像素的窗口空间。2 个核心也能运行，只是更慢： 见运行缓慢的电脑。

Windows

  1. 打开 .zip，把 qFT8 文件夹拖到您存放程序的地方，例如“文档”或桌面文件夹。不要在 zip 压缩包内直接运行 qFT8。
  2. 打开该文件夹，双击 qFT8.exe。
  3. 第一次运行时，Windows 可能显示 “Windows protected your PC”。点击 More info，然后点击 Run anyway。qFT8.exe 已用作者的证书签名；Windows 对新程序的信任需要慢慢建立。
  4. 如果 Windows 询问是否允许 qFT8（显示为“OpenJDK Platform binary”）通过防火墙，请只在专用网络上允许，并且只有在您使用网页遥控或桥接时才允许。

macOS

  1. 打开 .dmg，把 qFT8 拖到同一窗口中的 Applications 快捷方式上。然后推出 .dmg。
  2. 从“应用程序”文件夹启动 qFT8。如果您是从 .dmg 窗口内，或从浏览器存放下载文件的位置启动，qFT8 会询问 “将 qFT8 移到“应用程序”？”：请点击 移动（macOS 可能像访达一样要求输入您的密码）或 以后再说。
  3. macOS 会询问一次是否允许 qFT8 使用麦克风。请点击 Allow：qFT8 就是这样听到电台的。如果您错过或拒绝了，qFT8 会显示一张卡片，说明它正在等待麦克风权限；请在 System Settings > Privacy & Security > Microphone（macOS 13 及更新版本）或 System Preferences > Security & Privacy > Privacy > Microphone（较旧的 macOS）中授予权限，然后重新启动 qFT8。

Linux

  1. 解压 .tar.gz（tar -xzf qFT8-*.tar.gz，或使用您的文件管理器）。会得到一个 qFT8 文件夹。
  2. 在该文件夹中运行 ./qFT8（如果您的文件管理器可以运行程序，双击也行）。第一次启动会把程序解压到 ~/.cache/qft8，需要几秒钟；较新的版本会自动替换那里的旧版本。
  3. 电台的串行（CAT）端口属于某个用户组：在 Ubuntu、Debian 和 Fedora 上是 dialout，在 Arch 上是 uucp。其 USB 声卡属于 audio。 如果您的账户不在该端口所属的组中，qFT8 会在一张卡片中告诉您：立即修复会把您加入该组（会要求输入密码）并重新启动 qFT8，因此无需注销即可生效。如果这样不行，在终端中尝试和复制命令会给出命令让您自己运行；之后请注销并重新登录一次。

首次启动

与 Android 一样，qFT8 会要求输入您的呼号（见输入呼号）。紧接着会打开一张名为设备配置的卡片：选择电台，然后选择与之相连的声音设备。输入下方的瀑布图显示电台正在送来的声音：电台开机后，您应该能看到噪声或信号。您可以随时用底部栏中齿轮右边的按钮打开这张卡片，瀑布图上红色的无音频标记也能打开它。 见声音设备与电台连接。

相同之处与不同之处

操作方面一切都相同：您的第一次 QSO、数字模式、AUTO、CALL、日志、ADIF、QRZ、LoTW 和其他服务、SSB、CW、RTTY、SSTV、发射限制以及安全规则：qFT8 启动时 TX 总是关闭的，只有 TX 按钮才能打开它，而且 qFT8 绝不会更改您电台的发射功率。本手册中的截图显示的是 Android 应用；“点按”相当于用鼠标点击。不同之处如下：

屏幕
Android 一个屏幕：频谱图和一个选项卡；屏幕方向和四分屏在“设置”中
电脑 三种布局，用布局按钮选择：全部在一个窗口中、像手机一样并排，或每个面板各自一个窗口。 详情
音量
Android 手机的音量，以及“设置”中的“按音量产生音调”和“发射时设置系统音量……”
电脑 底部栏中的两个滑块：声音设备自身的音量和 qFT8 的音调音量。qFT8 绝不会自行更改设备音量。详情
声音设备
Android 手机自带的，或电台的 USB 声卡
电脑 在设备配置中选择：电台和您（操作员）。 详情
电台连接
Android USB，带权限对话框

输入
Android 触摸：点按、长按、滑动

设置与数据
Android 在应用内部
电脑 在您用户文件夹中的一个文件夹里；设置文件与 Android 相同。 详情
后台
Android 前台服务、关闭屏幕、省电
电脑 都没有：窗口打开时就一直运行。运行缓慢的电脑有自己的模式。 详情
更新
Android Google Play
电脑 带下载按钮的通知；由您自己替换程序。 详情

屏幕布局与布局按钮

底部栏最右端的按钮就是布局按钮。每点击一次，布局就切换到下一个：浮动，然后是固定，再是一体式，然后又回到浮动。它的图案显示您当前所处的布局（读屏软件会读出其名称，例如“布局：固定”）。qFT8 会记住布局供下次启动使用，并且在每种布局中分别记住每个窗口的大小和位置。

  • 一体式（qFT8 第一次启动时的布局）。一个窗口分成四个相等的部分：左上是频谱图，右上是电台选项卡，左下是世界地图，右下是 QSO 日志，下面是底部栏。设置是同一窗口右侧的一个高列；底部栏中的齿轮按钮可以显示或隐藏它，其标题中的 X 也可以。底部栏没有这四个部分的按钮：它们始终都在。
  • 固定（与 Android 应用类似）。一个窗口，频谱图在左，电台选项卡在右，下面是底部栏。拖动两者之间的细分隔条，可以给其中一方更多空间（占比在 20 % 到 80 % 之间）。底部栏的 QSO 日志、世界地图和设置按钮会把这三个部分作为单独的窗口打开，再按一次则关闭。
  • 浮动。主窗口缩小到只剩底部栏，每个面板都是自己的窗口，您可以随意摆放，甚至放到另一块屏幕上：频谱图、电台、QSO 日志、世界地图和设置。此时底部栏为这五个窗口各有一个按钮，用来打开和关闭它们。可用它把 qFT8 铺在两个显示器上，或在小屏幕上只保留频谱图和底部栏。

更改布局只是重新排列窗口：什么都不会丢失，正在进行的发射会继续，TX 保持原样。 世界地图有一个全屏按钮（地图右上角）：它会铺满屏幕，直到您再次按该按钮或按 Esc。

提示：Android 的设置屏幕方向、四分屏和应用覆盖（见屏幕布局）在电脑上不存在：由布局按钮和窗口大小取代它们。

窗口的使用

  • 任务栏中只有一个程序。无论哪种布局，qFT8 在任务栏、程序坞（Dock）或 Alt-Tab 中都只有一个条目：主窗口。“浮动”和“固定”布局中的面板窗口没有自己的条目。（在 Linux 上已用 GNOME、KDE Plasma、Xfce、Cinnamon、MATE 和 LXQt 测试。）
  • 面板窗口有自己的小边框（在所有系统上相同）：细边缘可从任意一边或一角调整窗口大小；带面板名称的标题条可拖动来移动窗口；X 与底部栏按钮一样关闭该面板。当面板窗口是活动窗口时，Esc 也会关闭它。
  • 主窗口可以照常调整大小和最大化。在一体式布局中，它不能小于 960 x 560 像素，第一次打开时占屏幕的 85 %。
  • 设置保持固定宽度。设置窗口（和列）保持 Android 设置页面的宽度，因此每一行都能放下；您可以更改它的高度。
  • 所有内容的大小。设置 > 应用中有与 Android 相同的两个大小滑块（用户界面与字体缩放和用户界面组件（不含字体）缩放）。在高分辨率屏幕上（Retina Mac、缩放 125 % 到 200 % 的 Windows），qFT8 会跟随系统的缩放比例。

音量：设备音量与音调音量

底部栏中，在设备配置按钮和布局按钮之间，上下排着两个小滑块。它们控制两件不同的事，两者对发射都很重要。

  • 上面的滑块，带扬声器图案：设备音量。它是 qFT8 用来发射的声音设备的音量：电台的 USB 声卡，或者在您把音频送到扬声器或耳机时的扬声器或耳机。它与您系统自己的音量控制对该设备显示的是同一个级别，改动其中一个，另一个会跟着变化（滑块在几秒钟内跟上）。
  • 下面的滑块，带波形图案：音调音量。它决定 qFT8 自己产生的发射音频有多响（FT8、FT4、WSPR、JS8 和 LQ8 的音调，以及 TUNE 的声音），范围 0 到 100 %。发射期间可以调整：在同一次发射中就能听到和看到结果。初始为 100 %。每台电台各自记住自己的音调音量。网页遥控显示同样的滑块，调节的就是这一个。

设备滑块的行为。

  • qFT8 启动时会读取设备的音量并显示出来；之后每两秒再读取一次，所以如果您在系统中更改音量，滑块会跟着变。如果您切换输出设备，滑块会显示新设备的音量。
  • 只有当您移动这个滑块时，qFT8 才会更改设备音量。它绝不会在发射前自行设置。这与 Android 不同：在 Android 上，qFT8 发射时可以把手机音量设为设置中的值；在电脑上不存在这两个设置。
  • 您移动滑块之后，qFT8 会把音量读回来，所以滑块显示的是设备实际接受的值。
  • 没有音量控制的设备（macOS 上的某些输出）会把滑块显示为灰色，且没有滑钮。
  • 启动 qFT8 后第一次发射或按 TUNE 时，设备滑块的扬声器图案和滑钮会在灰色和白色之间渐变闪烁五秒钟，提醒您这个级别决定电台被推动的力度。碰一下滑块即可停止。
  • 拖动滑块时，其百分比数值会显示在旁边。

提示：这两个滑块起到 Android 上 [仅限 QMX] 音频检查中音量建议的作用：如果电台显示音频过低或过高（QMX 显示两个点而不是一条横条），请先试试设备音量滑块的其他位置（例如 70 %、80 %、60 %、100 %），再用音调音量微调。否则请把音调音量保持在默认值（100 %）。qFT8 绝不会设置您电台的发射功率：请在电台上调整。

声音设备与电台连接

设备配置卡片

用齿轮右边的按钮打开它（首次启动时以及点击无音频标记时，它也会自动打开）。它分为两半：

  • 电台（左）：电台，以及电台自己的声卡：来自电台设备的输入（电台听到的内容：qFT8 解码的对象）和输出到电台设备（qFT8 发射的内容），各自带有采样率、位数和声道数。除非电台需要别的设置，否则请保持系统默认值。输入下方的小型实时瀑布图显示是否有声音传入。
  • 您（操作员）（右）：您自己的麦克风和您自己的扬声器或耳机，用于 SSB 和 CW（见扬声器和麦克风，是同一回事）、测试按钮，以及在数字模式下用扬声器播放电台声音。这些绝不能是电台自己的声卡。

同样的选项以及更多（缓冲区大小、故障警告）在设置 > 设备配置中。Android 上的“音频系统”和“音频输入源”行在电脑上不存在。请让设备保持在 AUTO：对电台它优先选用电台自己的声卡，对您则选用不是电台的设备。

您可能看到的提示

  • 输出到电台（标记）：您电脑的默认声音输出是电台的声卡，所以系统声音、浏览器和提示音都会进入电台，如果电台通过 VOX 或数据输入发射，它们可能被发射到空中。qFT8 会提供改用另一个输出（使用 ...）、打开声音设置或不再询问。qFT8 的发射音频也跟随默认输出：请先把电台的声卡选为 qFT8 的输出，再更改电脑的默认输出。
  • 电台无输入（标记，Linux）：电台的声卡在声音系统中没有输入，因为它处于仅输出的配置文件。直接读取电台（推荐）让 qFT8 自己读取声卡；切换到 PRO AUDIO 会为所有程序更改声卡的配置文件。
  • 没有输入设备：系统没有提供任何输入；请连接电台或声卡，并检查它在电脑的声音设置中是否作为输入设备出现。
  • 电台的 USB 驱动程序尚未安装（Windows 和 macOS）：Icom IC-7300 以及其他采用 Silicon Labs USB 芯片的电台可能需要 CP210x 驱动程序。请从厂商的驱动程序页面下载并安装，然后重新插上电台。
  • 不同的电台？（标记）：插入的电台不是在 qFT8 中选择的那一台。

按系统区分

  • Windows：qFT8 通过 Windows 自带的音频引擎（WASAPI）听电台，比旧方式的音频流更稳定。电台会显示为一个 COM 端口（COM3，……）和一个“USB Audio CODEC”或类似的声音设备。Windows 只允许一个程序使用某个 COM 端口：如果 qFT8 提示访问被拒绝，请关闭另一个程序（日志程序、数字模式程序、电台自带的软件），然后点击重试。
  • macOS：电台的端口形如 /dev/cu.usbmodem...（QMX）或 /dev/cu.SLAB_USBtoUART（IC-7300）。macOS 对端口不需要用户组或权限，只需要上面说的麦克风权限。如果端口被拒绝，说明有另一个程序打开了它。
  • Linux：端口形如 /dev/ttyACM0 或 /dev/ttyUSB0，需要上面说的用户组。声音设备是声音服务器（PulseAudio 或 PipeWire）的设备，所以电台的扬声器、您的耳机和您的麦克风可以各是不同的设备。设备音量滑块使用来自软件包 pulseaudio-utils 的 pactl（在 PipeWire 上也可用）。

选择电台及其端口

与 Android 一样，请让设置 > 设备保持在 AUTO：插入受支持的电台时会被自动识别。对于通过通用 USB 串行接口连接的电台（例如 Digirig），请手动选择电台，然后在设置 > 设备配置 > 通信端口设置 > USB 设备中选择它的端口；波特率、数据位、停止位、校验位以及键控方式（DTR、RTS或CAT）也在那里，除非您勾选允许覆盖设置，否则由 qFT8 按您选择的电台设定。只用声音（VOX）的电台完全不需要端口。命令行可以列出 qFT8 看到的端口和声音设备。

把设置从手机迁移过来（或迁移到手机）

多个副本、桥接、网页遥控、命令行

  • 每个配置文件夹一个副本。如果您在另一个副本正在使用同一文件夹时启动 qFT8，它会显示已在运行并提供重试或退出：同一文件夹上的两个副本可能损坏您的设置和日志。要同时运行多个副本，例如每台电台一个，启动时请给每个副本指定各自的文件夹：qFT8 --qft8_profile D:\qft8-radio2（Windows：qFT8.exe）。如果无法写入该文件夹，qFT8 会报错并停止。
  • 网页遥控。电脑程序拥有与 Android 相同的远程控制网络服务器（默认关闭，端口 13497），显示同样的页面，包括音量滑块。可用它从手机或网络上的另一台电脑操作。
  • 桥接。电脑是常见的桥接：电台插在它上面，手机、iPhone 或另一台电脑上的 qFT8 对其进行操作。它也可以不带窗口运行（qFT8 --bridge），用于没有其他用途的电脑。
  • 命令行。qFT8 --help 列出各选项（在 Windows 中会弹出一个小窗口显示）：--list-devices 列出 qFT8 看到的所有串行端口和声音设备并退出；--port <device> 设置默认串行端口（COM3、/dev/ttyACM0）；--qft8_profile <folder> 选择配置文件夹；--bridge 启动桥接；--opengl 通过 OpenGL 绘制窗口（见出现问题时）。

运行缓慢的电脑

设置 > 应用 > 慢速设备 / 低电量模式让 qFT8 更轻量：每秒约 30 幅画面，瀑布图重绘得更少，世界地图只在显示时工作。它只改变绘制的内容，绝不改变解码器：无论开关，qFT8 的解码结果都一样。

慢速模式只有在您勾选其复选框时才会打开，绝不会自行打开。在只有一个或两个处理器核心的电脑上，qFT8 启动时会询问是否打开它：启用慢速模式会勾选该复选框，忽略会在下次启动时再次询问，不再询问则不再询问。在这样的电脑上，无论是否使用慢速模式，qFT8 也会自行给解码器分配公平的处理器份额，这样其他繁忙的程序就不会让它饿死。

更新与卸载

更新

勾选启动时检查新版本时（默认如此；见启动时检查新版本），qFT8 每天询问一次是否有更新的版本，并显示有新版本可用，带有忽略和立即下载，后者会在浏览器中打开下载页面。qFT8 绝不会自行更新。要更新，请下载新文件并替换旧程序：

  • Windows：关闭 qFT8，用新的 qFT8 文件夹（或只用 qFT8.exe）替换旧的。
  • macOS：关闭 qFT8，把新的 qFT8 拖到“应用程序”上并选择 Replace。
  • Linux：关闭 qFT8 并运行新的 qFT8。它会自行解压，并从缓存中删除旧版本。

您的设置和日志保留在配置文件夹中。

卸载

关闭 qFT8 并删除程序：qFT8 文件夹（Windows、Linux）或“应用程序”中的 qFT8（macOS）；在 Linux 上还有 ~/.cache/qft8。这样会保留您的设置和日志。要连它们一起删除，请删除配置文件夹（见上文）。 这会删除您的 QSO 日志：请先用 ADIF 导出。

出现问题时

  • 瀑布图是空的，标记显示无音频。打开设备配置：电台的声卡是不是输入？电台开机了吗？在 macOS 上检查麦克风权限；在 Linux 上检查电台无输入标记和用户组。
  • 电台能接收但不能发射，TUNE 没有键控。端口被拒绝：另一个程序占用了它（Windows、macOS），或您的账户不在该用户组中（Linux）。qFT8 会告诉您是哪种情况；请关闭另一个程序并点击重试，或按 Linux 卡片的提示操作。另见手机或电脑无法识别收发信机，或连接断开。
  • 电台声音太小、太大，或显示两个点而不是横条（QMX）：移动设备音量滑块（音量）。检查电脑自身对该设备的音量没有静音。
  • 电脑的声音被发射到空中。默认输出是电台的声卡：请回应输出到电台标记，或在系统中选择另一个默认输出。
  • “已在运行”。另一个副本正在使用该配置文件夹。关闭它，或用它自己的 --qft8_profile 文件夹启动本副本。
  • 窗口是黑的或显示混乱（旧的显卡驱动、虚拟机、远程桌面）：更新显卡驱动程序。如果仍然如此，请用 --opengl（qFT8 --opengl）启动 qFT8，它会以另一种方式绘制窗口；如果这样也没有帮助，请用报告错误（设置）报告，并说明您的系统和显卡。
  • 窗口跑到屏幕之外（拔掉了一块屏幕）：qFT8 在打开每个窗口时会检查其保存的位置，如果它所在的屏幕已不存在，或窗口大部分会落在屏幕之外，就会改在主屏幕中央打开。如果某个窗口仍然够不着，请用其底部栏按钮关闭该面板再重新打开，或重新启动 qFT8。
  • 单核或双核电脑上瀑布图冻结、音频中断或负载很高：见运行缓慢的电脑，关闭其他程序，如果仍然持续，请用报告错误发送报告。

iPhone 和 iPad 上的 qFT8

iPhone 和 iPad 版 qFT8 的用法与 Android 版相同，本手册其余内容同样适用；需要 iOS 17 或更高版本。不同之处在于它如何连接电台。

iPhone 或 iPad 无法通过线缆控制电台：没有 CAT，因此 qFT8 无法通过 USB 设置电台频率或让电台发射。它通过电台的 USB 声音接口、其他音频接口或音频线收听电台并发送音调。要让电台发射，请使用以下方式之一：

  • 电台的 VOX：qFT8 的音调到达电台时，电台自动转为发射。在 qFT8 的设置中选择 VOX。
  • 由音频触发电台的音频接口：只要 qFT8 发出声音，它就让电台转为发射。
  • qFT8 bridge：放在电台旁边的电脑、Raspberry Pi 或 Android 手机或平板，电台通过 USB 连接到它。这样 iPhone 或 iPad 上的 qFT8 就能通过您自己的网络控制电台，如同直接连接一样，包括频率和发射。没有其他用途的电脑（包括没有屏幕的服务器）可以从命令行、无窗口地运行 bridge。

快速设置

请确保为收发信机使用正确的电源（例如 QMX 不得超过 12V），否则会损坏它。

另请确保连接手机或电脑与收发信机的 USB 线缆和转接头支持数据传输。在 Android 上，接口不是 USB-C 的设备通常需要专用的 OTG（On-The-Go）线。qFT8 找不到收发信机的连接问题，大多是线缆或转接头不兼容造成的。

在 Android 上，有些设备的 USB OTG 默认是关闭的，必须在设备的系统设置中打开（该选项可能藏在高级设置、系统设置或更多设置里）。如果您遇到连接问题——特别是 qFT8 能收到信号却无法发射，而且即使设备完全受支持（出现在设备下拉列表中、在 AUTO 模式下被自动识别等）CAT 命令也不起作用——原因很可能就在这里。

授予初始权限

在 Android 上，第一次打开 qFT8 时，它会请求几项权限：

  • 允许 qFT8 录制音频：此权限是必需的。qFT8 需要它来接收来自收发信机的信号。qFT8 不会存储、分享或上传任何录音。
  • 允许 qFT8 访问此设备的大致位置：可选，但建议允许。qFT8 用它来得到您的 Maidenhead 网格定位，在 FT8 通联中会发送这个网格。qFT8 不会访问也不会分享精确位置数据。
  • 允许 qFT8 向您发送通知：可选，但建议允许。qFT8 借此作为前台服务运行，这样在最小化或关闭屏幕时仍能工作，以节省电量。只有连接了收发信机时才会显示通知。
  • 允许应用始终在后台运行：可选，但建议允许。屏幕关闭时 qFT8 要稳定工作，就需要这项权限。

在电脑上，需要的权限更少。在 macOS 上，系统会询问一次是否允许 qFT8 使用麦克风：请允许，因为 qFT8 就是这样收听收发信机的。在 Linux 上，使用电台的串行（CAT）端口需要您的账户属于该端口所在的用户组（通常是 dialout）；如果不属于，qFT8 会说明情况并提出为您修复。

基本原则：qFT8 不会向任何专为本应用设立的服务器提交信息。所有数据都在您的设备本地处理。如果您输入了有效的 QRZ API 密钥，即表示您明确授权分享呼号、日期和时间，以及（可选的）大致位置。

更多详情请参阅 qFT8 的隐私政策和许可证。

数字模式简介

业余无线电数字通信模式将结构化文本和数据转换为音频频移键控（FSK）信号，并通过单边带（SSB）电台发射。结合超窄的射频带宽、先进的前向纠错（FEC）编码和严格的时间同步，使通联能够在信号远低于人耳可闻底噪的恶劣条件下顺利实现。qFT8 全面支持主流的现代数字模式：FT8、FT4、FT2、JS8、WSPR 以及 LQ8，各自针对超弱信号信标探测、高节奏竞赛通联以及自由文本键盘对话等不同场景进行了深度优化。

FT8

FT8（Franke-Taylor 设计，8-GFSK）是全球使用最广泛的弱信号数字协议，针对恶劣的 HF/VHF 条件、多跳突发 E 层传播和拥挤的波段而设计。它使用结构化报文、精确的 15 秒时间同步和强大的纠错能力。

周期与序列

FT8 以 15 秒为一个周期工作。每个通信周期都有严格的定时，准确地从每分钟的第 00、15、30 和 45 秒开始。因此，您设备的时钟必须与 UTC 时间精确同步。

协议中有两个序列：

  • 序列 0（偶数）：从第 00 和 30 秒开始的周期。
  • 序列 1（奇数）：从第 15 和 45 秒开始的周期。

电台通常轮流发射和接收。在序列 0 发射的电台会在序列 1 守听回答，反之亦然。在每个 15 秒周期内，报文大约在 +0.5 秒到 +13 秒之间的窗口内发出。这样周期末尾留有时间解码，周期开头留有时间准备下一次发射。

信号特性

每条 FT8 报文都以一串频率略有变化的单音发出（有人形容它“扭来扭去”）。FT8 信号非常窄，只占大约 50Hz 带宽。正因为如此高效，一个 3kHz 的通带内可以同时容纳几十组通联。

QSO 的 6 个阶段

一个标准的 FT8 通联通常经过六个阶段。下面是 HB9IPH 和 XX1XXX 之间一次交换的例子：

  1. 1/6 CQ：一个电台寻找任何愿意通联的对象。
    示例：CQ HB9IPH JN47
    注：JN47 是 Maidenhead 网格定位，表示该电台的大致地理位置。也可能带有 CQ 修饰符，它是给其他操作员看的附注（例如 CQ SOTA HB9IPH 表示参加山峰通联（Summits On The Air）活动，CQ US HB9IPH 表示想联络美国的电台）。修饰符和位置不一定能放进同一条报文；这时会省略位置。如果呼号很长，CQ 里可能位置和修饰符都放不下！
  2. 2/6 CALL：另一个电台回答这个 CQ。
    示例：HB9IPH XX1XXX JO21
    注：回答方也会发送自己的位置（JO21）；如果呼号太长、放不下全部内容，位置可能被省略。
  3. 3/6 RPT：第一个电台发出信号报告。
    示例：XX1XXX HB9IPH -10
    注：信号报告（例如 -10）表示信号相对于底噪的强度，单位为 dB。
  4. 4/6 RRPT：第二个电台确认收到报告，并发出自己的报告。
    示例：HB9IPH XX1XXX R-12
    注：前缀“R”确认已收到对方的报告，后面是给第一个电台的信号报告。
  5. 5/6 RR73：第一个电台确认全部收妥，并发出“Roger-Roger 73”。
    示例：XX1XXX HB9IPH RR73
  6. 6/6 73：第二个电台发出最后的“73”，结束通联。
    示例：HB9IPH XX1XXX 73

由于两军问题（Two Generals' Problem），理论上无法确知对方电台收到了您的最后一次发射，除非对方加以确认。可是那样您又得确认对方的确认，对方再确认您的确认，如此没完没了。FT8 数字模式用结构化的阶段来缓解这个问题：严格说来，在阶段 4/6 之后（双方的信号报告都已交换）QSO 就可以算完成。在实际操作中，为了确保双方都认可这次交换，电台在收到 RR73 并发出 73 后才记录 QSO。实际效果是：发出 RR73 或发出 73 都会触发记录 QSO。

请注意，即使对方没有先发 CQ，电台也可以直接呼叫它。例如，位于稀有地区的电台可能遇到“pile-up”（许多电台同时呼叫它）；这时稀有电台可以直接从一个 QSO 转到下一个，不必再发 CQ 招呼新的呼叫者。

有些电台在第 5 阶段会用 RRR 代替 RR73。这时通联需要多一轮交换：第二个电台发 73，然后第一个电台再发一次 73 作为结束。

FT8 还支持自由文本报文（最多 13 个字符），但 qFT8 目前不支持发送这类自定义报文。

协议的限制与退路

FT8 报文被高度压缩到 77 位。有时复杂的信息（例如很长的非标准呼号）放不进标准报文格式。

  • 哈希呼号：呼号太长时，可能以哈希值的形式发送。如果接收方最近见过这个呼号呼叫 CQ，其软件就能把哈希值还原成原来的呼号；否则会显示为 <...>。呼号不标准时，完成 QSO 要困难得多。
  • 退回自由文本：有些报文可能只能用 13 个字符的自由文本格式发送，它不如标准的结构化报文可靠。
  • 非标准呼号：如果两个电台都使用很长的非标准呼号，它们可能根本无法用 FT8 数字模式互相通联。
  • 跳过阶段：如果呼号太长，协议可能放不下信号报告（阶段 3/6 和 4/6）。这时交换可能从最初的 CALL (2/6) 直接跳到最后的确认（5/6 和 6/6）。

您会看到但不会发送的报文

有些电台发送的报文形式，qFT8 会显示，但自己不会发送：

  • 一条报文发给两个电台：同时与许多电台通联的远征台，可以在一次发射中结束一个 QSO 并开始下一个：K1ABC RR73; W9XYZ <VP8XYZ> -08。意思是“K1ABC，您的 QSO 已完成”和“W9XYZ，您的信号报告是 -08”，两者都来自 VP8XYZ。qFT8 按原样显示它：在电台列表中显示，并在瀑布图上显示一次。如果您是这两个电台之一，它就算作给您的 RR73 或给您的信号报告，与远征台单独发给您完全一样，QSO 照常继续或记入日志。如果两者都不是您，就无需任何操作，AUTO 也不会对它做任何事。
  • 比赛交换内容：在某些比赛中，电台发送的不是网格定位和信号报告，而是类别和分区（Field Day），或者带有州名或序号的报告（RTTY 比赛）。qFT8 会显示这些报文，让您了解波段上的情况，但从不应答：它不发送比赛交换内容。

FT4

FT4 是专为业余无线电比赛设计的精简数字模式，比赛中快速完成一个又一个通联至关重要：

  • 速度翻倍：以 7.5 秒为周期工作（比 FT8 快一倍），每次发射约 4.48 秒，每分钟有四个发射时段。
  • 带宽翻倍：占用约 90 Hz 的射频带宽（约为 FT8 ~50 Hz 带宽的两倍）。
  • 灵敏度损耗：换取两倍速率的代价是解码门限约为 -16.4 dB 至 -17.5 dB SNR（相比 FT8 存在约 3.5 至 4 dB 的接收灵敏度损耗）。
  • 实际应用：采用 4-GFSK 调制和标准的 77 位结构化报文载荷，传播条件允许时只用一半时间即可完成标准的比赛交换。

FT2

FT2 为信号条件良好时的超高速交换、VHF/UHF 流星余迹突发和高速率比赛而设计：

  • 速度比 FT4 再翻倍（FT8 的 4 倍）：以 3.75 秒为周期工作，发射时间约 2.24 秒，每分钟最多 16 个周期。
  • 带宽比 FT4 再翻倍（FT8 的 4 倍）：占用约 180 Hz 射频带宽（FT4 的两倍，接近 FT8 的四倍）。
  • 灵敏度进一步降低：解码门限约为 -13 dB 至 -14 dB SNR（比 FT4 进一步损失约 3 dB，比 FT8 损失约 6 至 7 dB）。
  • 实际应用：非常适合在信号强的传播开通期间，以及通联窗口转瞬即逝的突发传播模式下进行快速通联，此时信号明显高于底噪。

JS8

JS8（Jordan Sherer 设计，8-GFSK）是为闲聊（ragchew）、键盘对键盘的对话和临时组网而创建的，而不是用于结构化的比赛交换：

  • 报文分片与成帧：使用与 FT8 相同的 8-GFSK 基本调制和 77 位帧，但增加了一层上层传输协议来分片和重组报文。这样任意长度的自由文本就能跨越连续的周期顺畅地发送。
  • 多种速度模式：提供四种可选的速度档，以适应波段条件：
    • Slow：30 秒周期，带宽约 25 Hz，可解码低至 -25 dB SNR 的信号。
    • Normal：15 秒周期，带宽约 50 Hz，可解码低至 -21 dB SNR 的信号。
    • Fast：10 秒周期，带宽约 80 Hz，可解码低至 -18 dB SNR 的信号。
    • Turbo：6 秒周期，带宽约 160 Hz，可解码低至 -15 dB SNR 的信号。
  • 组网能力：支持定向报文、经中间电台自动中继报文、心跳在线监测，以及异步的存储转发信箱网络。

WSPR

WSPR（Weak Signal Propagation Reporter，弱信号传播报告）专门用于探测电波传播路径和自动信标，而不是双向对话式的 QSO：

  • 两分钟周期：以严格同步的 2 分钟（120 秒）周期工作，在 110.6 秒内发射 162 个符号的 4-FSK 单音序列。
  • 极窄带宽：只占用约 6 Hz 射频带宽，把辐射功率集中在极窄的一段频谱内。
  • 极高的弱信号灵敏度：在标准的 2.5 kHz 参考带宽下，能解码低至 -28 dB 至 -31 dB SNR 的微弱信号，使毫瓦级（QRPp）发射机也能跨越全球距离。
  • 自动传播报告：发射内容包括电台呼号、Maidenhead 网格定位（4 位或 6 位）和以 dBm 表示的发射功率。解码出的 spot 会自动转发到全球的 WSPRnet 数据库，实时描绘电离层传播情况。

LQ8

LQ8 是由 qFT8 的作者 Luis Quesada（HB9IPH）开发的先进弱信号数字模式：

  • 更快完成 QSO，且没有代价：LQ8 完成双向 QSO 比 FT8 快得多，而且灵敏度没有任何损失。它保留了完整的 -21 dB SNR 弱信号解码门限（与 FT8 相同），同时通过优化的协议设计，用少得多的发射轮次完成有效通联。
  • 复合报文：支持合并发射，例如把信号报告和确认合在一起（REPORT+RR73），以及同时回答多个电台（MULTI_CALL），把标准 QSO 的时长从 4–6 个周期缩短到只需 2–3 个周期。
  • 现代架构：以标准的 15 秒周期工作，79 个符号的 8-GFSK 调制（带宽约 65 Hz），77 位载荷采用优化的哈夫曼编码压缩，14 位 CRC 检错，并有结构化的应急调度信令。

欲了解更多信息、规范和工具，请访问 LQ 模式的门户网站 https://lq8.org。

底部栏各组成部分的详细说明：

  1. 周期进度条：黄色进度条从周期的 0 秒（最左端）开始，到周期的 15 秒（最右端）结束。
  2. Tx 触发标记：进度条左侧的红色圆点表示 Tx 触发时刻。如果 Tx 为 ON（见第 4 项），并且当前序列就是所选序列（见第 6 项），发射就从这一刻开始。
  3. 解码时刻标记：进度条右侧的白色圆点表示解码时刻，也就是从收到的信号中解出报文并随后处理的时刻。
  4. TX 按钮：可以处于禁止发射（OFF）或允许发射（ON）状态。它还显示是否正在发射，以及发射功率和 SWR。QMX 固件高于 1_04 时，此按钮会显示“HOLD: TUNE”。按住按钮即进入调谐模式，并实时报告 SWR。
  5. 报文选择器：显示已选定要发射或正在发射的报文（正在发射时以黄色高亮）。在 AUTO 模式下它由程序自动管理。在 CALL 模式下默认也是自动管理，但可以点按它，手动选择下一条要发的报文。
  6. 序列选择器：按钮上方的黄色线条表示当前序列（0 或 1）。点按 0 或 1，即选择在该序列发射。
  7. 模式选择器：切换所用的发射模式（例如 FT8、FT4、FT2、LQ8、JS8 或 WSPR），也可切换到 SSB、CW、RTTY 和 SSTV，它们会按各自章节所述改变底部栏和电台选项卡。从数字模式切换到这四种模式之一、切换回来或在它们之间切换时，TX 会变为 OFF：准备好后请重新打开。在数字模式之间切换则保持原状态。
  8. 波段选择器：连接了收发信机时，它会更改收发信机的波段。
  9. 电台选项卡按钮：打开电台选项卡，其中列出您收到的或可以通联的所有电台。
  10. 日志选项卡按钮：打开日志选项卡，其中列出您完成的所有 QSO。如果有 QSO 尚未上传到 QRZ，这个按钮上会出现一个黄点。
  11. 世界地图选项卡按钮：打开显示交互式世界地图的选项卡。
  12. 设置选项卡按钮：打开用于配置 qFT8 的选项卡。

电台选项卡

电台选项卡是监视波段活动和操作 qFT8 的指挥中心。顶部是筛选和自动操作的控件，下面是活跃电台的列表。

电台选项卡各组成部分的详细说明：

  1. AUTO 呼叫模式按钮：启用“AUTO”后，qFT8 会按用户选定的条件尝试呼叫最合适的电台。
  2. 手动 CALL 模式按钮：对某个电台启用“CALL”后，qFT8 会一直呼叫该电台，直到完成 QSO，然后回到“AUTO”。
  3. 目标：设置 AUTO 模式的选台条件：
    • 任何人：任何您还没有通联过（没有 QSO）的呼号。
    • 较近：按 Maidenhead 网格距离，优先最近的电台。
    • 较远：按 Maidenhead 网格距离，优先最远的电台。
    • 信号强度：优先信号最强（SNR）的电台。
    • 呼叫 CQ：只呼叫 CQ，并回答任何呼叫您的电台。
    • POTA 猎人：优先 Parks on the Air（公园通联）电台。
    • SOTA 猎人：优先 Summits on the Air（山峰通联）电台。
    • POTA + SOTA 猎人：优先 Parks on the Air 和 Summits on the Air 电台，然后是两者都不是的电台，按 SNR 排序。
    • DXCC：优先新的国家/实体。
    • 网格：优先新的 Maidenhead 网格。
    • ITU 分区：优先新的 ITU 分区。
    • CQ 分区：优先新的 CQ 分区。
    • I/C/D/G：先优先 ITU 分区，再 CQ 分区，再 DXCC，最后网格。
    无论哪种条件，符合同一条件的电台都按信号强度排序。例如，任何人会优先新的呼号，而其中信号最强的排在列表最前面。
  4. 周期：多久与该目标通联一次：
    • 一次：一生只通联一次。
    • 每天：每个 UTC 日期一次。
    • 每周：每 7 天的滚动窗口内一次。
    • 每月：每一个月的滚动窗口内一次。
    • 每年：每一年的滚动窗口内一次。
  5. 限定条件：上述限制如何适用：
    • 按呼号
    • 在不同波段
    • 在不同模式
    • 直到分区确认
    • 每个波段 + 直到分区确认
    • 每个模式 + 直到分区确认
    • 在不同波段或模式
    • 波段/模式 + 直到分区确认
  6. 侦听（侦听）模式：启用后，qFT8 也会尝试呼叫您还没听到它发过 CQ 的电台（标记为 DIRECT）。这样可通联的电台更多，也便于加入 pile-up。
  7. 忙碌（忙碌）模式：启用后，qFT8 也会尝试呼叫正在与别人进行 QSO 的电台（标记为 BUSY）。这便于加入 pile-up。
  8. + 按钮：输入呼号，手动呼叫任意一个电台。
  9. 电台信息：显示每个已解码电台的详细状态。

每个电台条目由信息丰富的四行组成：

第一行显示电台的基本信息（从左到右）：

  • QSO Status（QSO 状态）：表示您与该电台的 QSO 历史（✗ = 没有 QSO，✓ = 已记入本地日志，★ = 已通过 QRZ 或 LoTW 确认）。
  • 呼号：该电台的呼号。
  • DXCC：该电台呼号所属的国家或实体。
  • 网格：该电台报告的 Maidenhead 网格。
  • CQ 分区：该电台呼号所属的 CQ 分区。
  • ITU 分区：该电台呼号所属的 ITU 分区。
  • 波段：最近一次收到该电台时所在的波段。

第二行显示通联状态（从左到右）：

  • 状态：通联当前所处的阶段：
    • DIRECT：已收到，眼下似乎空闲，但从未发过 CQ。
    • 1/6 CQ：收到它在呼叫 CQ，眼下似乎空闲。
    • 2/6 CALL：呼叫了您。
    • 3/6 RPT：给您发了信号报告。
    • 4/6 RRPT：收到您的报告并回了它自己的报告。
    • 5/6 RR73：用 RR73 确认了您的报告。
    • 6/6 DONE：QSO 已完成（已互致 73）。
    • GONE：最近几个周期没有再收到。
    • TOO LONG：受 FT8 数字模式的限制，您的呼号和对方的呼号加起来太长，无法建立通联。
  • 信号强度：以 dB 表示的强度（最近没有收到时显示“????”）。
  • 序列：最近一次收到该电台发射时它所在的序列（0 或 1）。
  • 时间差（Δt）：对方时间与您的时间之间的同步偏差，单位为秒。
  • 距离：对方网格与您电台网格之间的估算距离。

第三行和第四行显示与该电台往来的报文，包括 UTC 时间、频率偏移和报文文本（收到的报文以 RX: 开头，发出的报文以 TX: 开头）。根据设置 → 应用 → 用户界面中设定的电台显示方式（默认为紧凑 - 最新接收(Rx)，另有紧凑 - 最新Rx/Tx交替、紧凑 - 最新Rx/Tx 和展开 - 同时显示最新Rx和Tx可选），电台卡片显示三行，或者显示同时带有 Rx 和 Tx 报文的四行。

值得留意的几种视觉提示：

  • 珊瑚色的 Rx 报文（UTC、偏移和文本）：在当前或上一个周期内，从该电台收到的 Rx 报文是专门发给您的电台 / 呼号的（包括 /P 之类的复合呼号，以及与哈希呼号匹配的情况）。这是一个一目了然的提示：该电台刚刚呼叫了您，或回答了您的发射。广播式的 CQ 呼叫和发给其他电台的报文从不高亮；报文一旦早于上一个周期，文本就自动恢复为普通的灰色。发出的报文（TX:）始终是中性的灰色。
  • 红色呼号：AUTO 模式对该电台的重试次数已超过上限。它会被暂时忽略，除非您点按“CALL”手动重置。
  • 紫色呼号：按您当前的条件，这个呼号是目标。
  • 灰色呼号：该呼号与您设置的排除前缀（用逗号分隔）相符。AUTO 模式永远不会把这个电台当作目标。
  • 紫色高亮的分区：按您当前的条件，这个分区/实体（DXCC、网格、CQ分区、ITU分区）是目标。
  • 红色序列号：该电台与您所选的序列相同，会发生冲突。按“CALL”会自动切换您的序列。
  • 红色波段：最近一次收到该电台是在另一个波段。

电台会按相关程度自动排序。更改目标条件或限制后，列表会立即重新排序。

设置选项卡

设置选项卡用于配置 qFT8。

设置选项卡的组织如下：

  • 呼号：您的业余无线电呼号（发射必须填写）。必须与您的执照相符。
  • CQ 修饰符：附加在您 CQ 呼叫中的可选文本（例如“SOTA”）。
  • 设备：用于选择和配置您的收发信机（例如 QMX、QDX、Kenwood TS-480 / TS-590 / TS-2000 系列，或 VOX/仅音频）及其连接参数。
  • 电台 / 天线：您使用的电台和天线。您记录的每个 QSO 都会保存它们（ADIF MY_RIG / MY_ANTENNA），PSKReporter 也会随您的报告一起收到。电台一栏为空时，使用已连接电台的名称。

子菜单和选项

  • 设备配置：选择音频设备，设置发射音量和 VOX 阈值，并配置电台的键控方式。每台电台的频谱图调谐偏移和连续发射时间上限也在这里（两者见功能说明）。
  • 扬声器和麦克风：您自己的麦克风以及扬声器或耳机，用于 SSB 和 CW（见紧接在下面的扬声器和麦克风）。
  • POTA 激活 / SOTA 激活：开始、查看或结束一次激活；每个按钮旁边的放大镜列出以往的激活。
  • 导入/导出日志：用标准的 ADIF（.adi）文件导入或导出您的 QSO 日志。
  • QSO 同步：设置与 QRZ 和 LoTW 的集成，用于同步日志和核对确认。
  • 删除 QSO：清除本地的 QSO（此操作只影响应用本地的日志）。
  • 应用：通用设置，包括用户界面语言。
  • 频谱图：选择瀑布图上绘制哪些覆盖内容 — 解码耗时、UTC 时间和序列、报文、峰值线以及所选电台的频率 — 以及覆盖文字的字体比例。
  • 世界地图：选择地图显示什么、显示多久：已完成的 QSO、spot 以及收发的报文，各有自己的时间窗口。
  • 时间和位置：配置时间偏差同步（NTP 或 GPS）和您的 Maidenhead 网格定位。
  • 自动操作：配置自动操作的偏好、重试次数、排除的前缀，以及 AUTO 是否回答不是发给您的定向 CQ。
  • 数字模式：所有模式的解码选项集中在一处 — FT8/FT4/FT2、LQ8、JS8 和 WSPR — 包括共用的深度解码设置，以及解码可以使用多少个线程。
  • SSB、CW、RTTY, JTTY 和 SSTV：这些模式各自的设置，在它们的章节中说明。每种模式面板上的齿轮按钮打开的是同一页面。
  • 波段选择：自定义启用哪些波段，以及切换波段时的行为。
  • 远程控制 Web 服务器：启用并配置用于远程控制的内置 Web 服务器。
  • PSKReporter 设置：将您接收到的电台上传到 PSKReporter。
  • WSPRnet 设置：把 WSPR spot 上传到 WSPRnet，并查看最近的上传记录。
  • 启动时检查新版本：有更新的 qFT8 版本时显示通知（见错误报告和新版本）。
  • 发送匿名的每日性能摘要（就在“语言”上方，默认关闭）：应用打开期间，大约每周一次发送一份简短摘要，说明 qFT8 在您设备上运行得有多快（启动时间、画面流畅度、解码时间、音频和电台时序、设备型号和屏幕）。其中绝不包含您的呼号、网格、日志、设置或任何标识符。

扬声器和麦克风

数字模式只需要一个声音设备：电台的声卡。SSB 和 CW 还需要给您自己用的第二个设备：用来收听电台的扬声器或耳机，SSB 还需要一个用来讲话的麦克风。这两者绝不能是电台自己的声卡，否则您说的话会直接形成回路。

  • 在 Android 上：设置 > 扬声器和麦克风，就在设备配置下面。
  • 在电脑上：设备配置卡片分为两半：左边是 电台（电台的声卡：电台听到的和它发出的），右边是 您（操作员）。

有两项选择：

  • 您的麦克风（您说话，电台发射）。它下面有一个小的实时瀑布图和电平指示，显示麦克风拾取到的声音：说句话，应该能看到它们在动。
  • 您的扬声器 / 耳机（您收听电台），带一个 测试 按钮，可在其上播放一段短促的声音。

两者一开始都是 AUTO，它会选择一个不属于电台的设备：在手机上，接有耳麦时用耳麦，否则用手机自带的麦克风和扬声器；在电脑上，用第一个不是电台声卡的声音设备。只有在 AUTO 选错时才需要更改。

提示：SSB 请使用耳机。如果麦克风旁边有扬声器，接收到的声音可能触发 VOX，或者混入您的发射信号。

自动操作（AUTO）

AUTO 模式是使用 qFT8 的主要方式。在此模式下，应用会在每个周期结束时自动分析解码出的报文，并按您的目标条件选出最值得通联的电台。

目标是怎样选出来的

电台选项卡显示活跃电台的列表，并把（按您的条件）最合适的候选电台排在最前面。每个解码周期结束时，qFT8 查看这个排好序的列表，尝试呼叫第一个符合条件的电台。如果找不到符合条件的目标，它会自动开始呼叫 CQ 来招呼别人呼叫。在 AUTO 模式下，qFT8 总会回答别人的呼叫。

条件和筛选

您可以用电台选项卡顶部的三个下拉菜单对自动操作进行细调：

  • 目标：定义您追求哪一种“成绩”（任何人、DXCC、CQ分区、ITU分区、网格）。
  • 间隔：您愿意隔多久再与同一实体通联一次（一次、Always、每天、每周、每月）。
  • 限定条件：进一步限定“不重复”的要求（按呼号、在不同波段、直到分区确认）。

手动干预：您随时可以点按某个电台的 CALL 按钮进行手动干预。这会针对这一个 QSO 进入 CALL 模式。完成后，qFT8 会顺畅地回到 AUTO 模式。

重试机制

为了避免 qFT8 没完没了地呼叫一个不回答的电台，qFT8 内置了重试和暂时屏蔽机制，默认启用。您可以在设置选项卡的 Retry Logic（重试逻辑）下进行配置：

  • Retry Limit（重试上限）：对一个不回答的电台，qFT8 重复同一个发射阶段的最多次数。
  • Retry Window（重试窗口）：统计这些尝试次数的时间段。
  • Retry Cooldown（重试冷却时间）：达到上限后，该电台在这段时间内被“屏蔽”。AUTO 模式会忽略被屏蔽的电台，直到冷却时间结束或该电台回答。

手动操作（CALL）

虽然 qFT8 高度自动化，但您随时可以自己接手。点按电台选项卡中任何电台旁边的 CALL 按钮，会立即进入 CALL 模式，并尝试与这个电台建立 QSO。

这个手动目标的 QSO 结束后（不论成功与否），qFT8 会自动回到 AUTO 模式，继续您原先的自动策略（例如呼叫 CQ）。

手动操作时的时间余量

如果您希望在周期末尾有更多时间手动做决定，可以调整设置选项卡中的 FT8 设置，给自己多留一些余量：

  • 减小“开始解码时间”：更早开始处理音频。
  • 增大“开始发射时间”：推迟您回答的起始时刻。

警告：把这些值调得过于激进，会使其他电台更难解出您的报文，因为这样缩短了同步窗口内真正可用于 FT8 信号的有效时间。

手动编辑和记录 QSO

qFT8 在数字模式下完成的 QSO 会自动记入日志。本节介绍您在日志选项卡中手动做的三件事：更正一个 QSO、记录以其他方式完成的 QSO（话音、莫尔斯电码、另一台电台），以及同时处理多个 QSO。

QSO 编辑器

在日志选项卡中点按一个 QSO，该选项卡就变成它的编辑器。所有已保存的字段都在这里：您的呼号和网格定位、对方的呼号和网格定位、模式、波段、频率、日期和时间、功率、信号报告、POTA 和 SOTA 编号以及备注。

  1. 正在编辑的 QSO：呼号、模式、波段、日期和时间。
  2. 状态：该 QSO 是否已确认。点按它可选择手动确认或手动取消确认（只改变您自己的日志）。
  3. 已上传：该 QSO 在 QRZ 和 LoTW 上的状态。点按它可把 QSO 重新上传到某一项服务或全部服务。
  4. 改过的字段会高亮显示，旁边用红色显示旧值，并有一个恢复旧值的箭头。点按任意值即可修改。模式和波段从应用的列表中选取，波段会跟随您输入的频率；不可能正确的值（呼号、网格定位、日期……）会被拒绝并说明原因。
  5. 返回：退出编辑器。如果有更改，会询问是否放弃。
  6. 尚未保存的更改数量。
  7. 删除：在您输入 yes 之后，只从本应用的日志中删除该 QSO。
  8. 保存：先请您确认，然后保存。

保存时 QRZ 和 LoTW 上会发生什么。确认提示会针对您正在编辑的 QSO 说明：

  • QRZ：该 QSO 在那里被更新。如果您改了呼号、日期、时间、波段或模式，QRZ 会把它当作另一个 QSO：新建一条记录，旧记录保留，需要您自己到 qrz.com 上删除。
  • LoTW：更正后的 QSO 作为新记录重新上传；旧记录留在那里，处于未确认状态，没有影响。
  • 会使确认失效的更改（QSO 的对方呼号、您的呼号、日期或时间）必须输入 yes 来确认，因为该 QSO 将不再与对方的日志相符。
  • 用与“设置”中不同的呼号完成的 QSO 不会上传。

qFT8 绝不会在 QRZ 或 LoTW 上删除任何内容。删除 QSO 只是把它从应用中移除。如果该 QSO 在某项服务上，下次同步时它可能会回来：请先在该服务上删除。除非您保留了导出的日志副本，否则删除无法恢复。

记录器

日志选项卡的 + 按钮打开记录器，这是一个用于您自己手动完成的 QSO 的快速表单。在手机上它会把屏幕转为竖屏，顶部保留一条窄窄的频谱图（可在设置 > 应用 > 用户界面中关闭）。

  1. 呼号：输入呼号并按键盘上的回车键：QSO 以当前时间记录，输入框清空，您可以接着输入下一个。从一个 QSO 到下一个，键盘一直保持打开。
  2. 记录：与回车键相同。
  3. 清除 / 撤销：输入了呼号时，按钮显示 清除，用来清空输入框。其他时候显示 撤销，把本次会话的最后一个 QSO 从日志中取出放回表单，以便更正。
  4. 完成：关闭记录器。如果已输入呼号但还没有记录，会询问是否记录。
  5. 查询行：呼号所属的国家或地区、您与它的上一次 QSO，以及是否重复。橙色的 DUPE 表示您今天已经在该波段、该模式下记录过这个电台（仍然可以记录）。
  6. 详细信息（左右滑动查看更多）：时间（现在，或点按它来设置日期和时间）、波段、模式、以 kHz 表示的频率、与之不同时的接收频率、功率、发出和收到的信号报告、对方的 POTA / SOTA 编号和您自己的编号。它们的初始值取自应用当前调谐的状态，并从一个 QSO 保留到下一个。
  7. 本次：打开记录器以来您记录了多少个 QSO。在手机上点按它可以列表形式查看。
  8. 本次会话的 QSO 以珊瑚色显示并带有时钟图标：它们已经在您的日志里，但要等您按下 完成 后才会上传到 QRZ 或 LoTW，这样输入错误还来得及撤销。点按其中一个即可撤销或编辑。

SSB、CW、RTTY 和 SSTV 面板上的 QSO 按钮会以小卡片的形式打开同一个表单，其中已填好模式、频率和对方电台，每次记录一个 QSO。

选择多个 QSO

在日志选项卡中长按一个 QSO 即可开始选择（在电脑上按住 Ctrl 单击，或按住 Shift 单击来选择一个范围）。然后点按其他 QSO 来添加或移除。

  1. X：退出选择，不做任何操作。
  2. 已选择的 QSO 数量。
  3. 选择范围：点按它，再点按范围结束处的 QSO：两者之间的所有 QSO 都会被选中。
  4. 全选 和 无。
  5. 操作：对所选 QSO 执行的操作：
    • 手动确认 / 取消手动确认。
    • 导出 (ADIF)：只包含这些 QSO 的文件。
    • 带 POTA / SOTA 编号导出：同上，并把您的公园或山峰写入文件中的每个 QSO（日志本身不变）。
    • 加入一次 POTA / SOTA 激活和从其激活中移出（见激活公园或山峰）。
  6. 所选的 QSO 会被打勾并高亮显示。

每项操作都会先告诉您它将更改多少个 QSO 并请您确认，更改之后可以立即撤销。QRZ 和 LoTW 上的内容绝不会被删除。

ADIF 导入/导出

qFT8 支持标准的 ADIF（Amateur Data Interchange Format，业余无线电数据交换格式），以便与其他日志软件和云服务互通，并用于手动备份。

导入 QSO

导入功能可以把其他来源（例如其他日志程序，或其他设备上的备份）的记录导入您本地的 qFT8 日志。

  • 筛选选项：导入所有模式。您可以选择只导入当前呼号的记录，还是包括所有操作员。
  • 自动去重：qFT8 会智能地合并记录。它通过比对 QRZ Log ID 和 QSO 的时间戳来避免重复。如果导入的记录带有您本地记录所没有的确认状态或有效的 Log ID，qFT8 会用这些更完整的数据更新本地条目。

导出 QSO

点按 导出 QSO 会生成一个 ADIF 3.1.6 文件。在 Android 上会打开系统的分享面板，您可以把日志保存到设备，或通过电子邮件或即时通讯发送；在电脑上则由您选择文件的保存位置。

  • 时间范围：您可以导出全部历史，也可以用 UTC 日期/时间选择器只取某一次激活或某一段比赛时间。
  • 状态筛选：申请奖状时很有用（导出“仅限已确认”），手动上传到其他服务时也很有用（导出“仅限未上传到 QRZ”，以免重复）。
  • 猎人条件：筛选日志，导出“导出所有日志”、“仅导出 POTA 猎人”或“仅导出 SOTA 猎人”，生成专门用于申请奖状的文件，其中填好了对方的参考编号（<POTA_REF> / <SOTA_REF>）。
  • SOTA 参考：如 SOTA 章节所述，qFT8 可以自动把山峰编号写入每条导出记录的 <MY_SOTA_REF> 字段。
  • POTA 参考：如 POTA 章节所述，qFT8 可以自动把公园编号写入每条导出记录的 <MY_SIG>、<MY_SIG_INFO> 和 <MY_POTA_REF> 字段。用逗号分隔的多个公园会为每个公园生成一个文件（见“文件中写哪个公园？”）。

导出文件的名称

  • 不带编号：qFT8-YYYYMMDD-HHMMSS.adi，即导出时的日期和时间（UTC），例如 qFT8-20261006-181500.adi。状态筛选会在时间后面加上 _confirmed 或 _notuploaded，这样同一文件夹里的文件就按日期排序。
  • 带 POTA 编号：CALLSIGN@PARK-YYYYMMDD.adi，例如 K1ABC@US-1234-20261006.adi。这是公园活动要求的文件名。每个公园、每个 UTC 日各一个文件，因此跨越 UTC 零点的导出会生成两个文件。
  • 带 SOTA 编号：一个文件，例如 K1ABC@W1_HA-001-20261006.adi（山峰编号或呼号中的“/”不能用在文件名里，写作“_”）。
  • 在电脑上，导出绝不会覆盖已有的文件：如果名称已被占用，新文件会保存为 name (1).adi，然后是 name (2).adi，依此类推。

注意：对于很大的日志（超过 100KB），qFT8 会显示一条警告，因为去重和排序可能需要一些时间才能完成，在手机上尤其如此。

QSO 上传服务

qFT8 可以把您记录的每个 QSO 发送到多个在线或家庭网络中的日志： QRZ、LoTW、Wavelog、 Cloudlog，eQSL，以及另一个 qFT8（qFT8log）。 每个服务在设置顶部都有一行：一个用于启用它的复选框，和一个打开该服务自己页面的齿轮按钮。

  • 在服务通过验证之前，复选框会一直是灰色的：打开它的页面， 输入它的信息，然后点验证。
  • 每个页面开头都有一段简短说明和一个?按钮，它会在本手册中打开该服务的章节。页面还显示 还有多少 QSO 尚未上传，并带有立即上传，以及一个恢复默认设置按钮 （它绝不会清除账户、密钥或密码）。
  • 当某个服务自上次正常工作以来无法连接时，它那一行会变红，其下的一行红字会显示 自 日期和时间 起无法连接。

QSO 何时算作已上传？

日志、电台列表、地图和 Web 远程控制中的绿色对勾都遵循同一条规则。每个服务的页面上都有一个复选框 上传到此处即视为 QSO 已上传。它对 QRZ 和 LoTW 是开启的，对其他服务是关闭的。

  • 服务只有在已设置时才计入：已验证并已启用。
  • 只要任何一个计入的服务已有某个 QSO，该 QSO 就算已上传。
  • 当已设置的服务都没有勾选这个框时，所有已设置的服务都计入。因此如果您只设置了 qFT8log， 应用只会等待 qFT8log，绝不会等待 QRZ 或 LoTW。
  • 完全没有设置任何服务时，由勾选的框根据 QSO 自身携带的信息来决定（例如从其他程序导入的日志会保留它的勾选）。
  • 从 LoTW 导入的 QSO 视为已在 QRZ 上，不会再发送到那里。从某个服务传来的 QSO 视为已上传到该服务，绝不会再发回给它。
  • 星标（已确认）要求该 QSO 按此规则已上传，并且已被任一服务确认，除非您手动将它设为已确认或未确认。

ADIF 导出一次可以选择未上传到 服务这一个服务；尚未设置的服务，其选项是灰色的。 qFT8 绝不会删除任何服务上的 QSO：在这里删除 QSO 时，只会提醒您它仍然留在那里。

qFT8 服务器

在设置的靠下位置，两条线之间，qFT8 服务器里是本设备可以向其他程序提供的服务： 远程控制 Web 服务器、qFT8 bridge，以及 Wavelog、Cloudlog 和 qFT8log 服务器。

QRZ 集成

qFT8 与 QRZ.com 深度集成，让您的日志自动保持同步。请注意，QRZ 集成是一项订阅服务，需要 QRZ 付费订阅（XML Logbook Data 或更高级别）。如果您想用免费的方案，可以考虑 LoTW 集成，它由 ARRL 免费提供。

工作方式

要启用 QRZ 集成，需要在设置选项卡中填入您的 QRZ API 密钥。API 密钥可以在 QRZ Logbook API 官方页面上找到。输入并验证之后，就可以启用“交信建立时在后台上传联络到 QRZ”，由后台自动处理。

  • 自动上传：每完成一个 QSO（顺利到达 6/6 DONE 状态），qFT8 就立即尝试把它上传到您的 QRZ 日志。
  • 后台可靠重试：如果上传失败（例如没有互联网连接，或服务器超时），qFT8 不会放弃。后台任务会每 5 分钟自动重试失败的上传。这个过程不打扰您，并确保网络恢复后您的日志最终能传到云端。
  • 智能跳过：为保护日志的完整性，qFT8 只上传与当前所设呼号相符、并且是 FT8 模式的 QSO。非 FT8 的条目、其他呼号的 QSO，以及从 LoTW 导入的 QSO都会自动跳过，以免产生过多的 API 请求。

同步确认

集成不只是上传。qFT8 还会向 QRZ 查询，看您的 QSO 是否已得到确认。

  • 即时检查：一个 QSO 完成并上传 30 秒后，qFT8 会再向 QRZ 查询一次，看对方电台是否也上传了这个 QSO；如果已上传，这个 QSO 会立即同步为已确认。
  • 自动同步：默认情况下，qFT8 每 6 小时（可设置）查询一次 QRZ，每批 250 个 QSO，在您全部未确认的日志中轮流进行，确保较早的 QSO 最终也会被检查有没有新的确认。
  • 确认星标（★）：已上传到 QRZ 的 QSO 在 QRZ 或 LoTW 上得到确认后，会以金色星标突出显示。您也可以手动确认任何 QSO 来显示这个标记。当 QRZ 报告确认时，日志选项卡中的状态图标会自动变成金色星标。
  • 手动同步：也可以在设置中手动触发，对最久没有同步过的 250 个 QSO 进行更新。

小提示：在设置中的“最旧的已同步联络日期”一项可以看到同步进度。不必急着让它保持最新，qFT8 会随着时间推移自行处理。

日志同步策略

在同步设置中，您可以通过“上传到以下服务时，视作已上传联络”选项，选择 qFT8 如何判定一个 QSO 已“完全上传”：

  • LoTW 或 QRZ 任意一个：如果您只配置了其中一项服务，这是合适的默认选项。
  • 两者：最稳妥的选择，要求 QSO 成功发送到两项服务之后，才算完成并可以开始检查确认。
  • QRZ (从 LoTW 导入的除外)：如果 QRZ 是您的主日志，建议选这一项。注：从 LoTW 导入的 QSO 会标记为已同步，但不会上传到 QRZ，以免触及 API 限制（只允许逐条上传）；以后可以在 QRZ 网站内自行同步。
  • LoTW：如果您以 LoTW 作为最权威的记录，建议选这一项。

  • 待上传标记：日志按钮上的小黄点表示有 QSO 正等待上传到 LoTW。

Wavelog

Wavelog 是一款日志程序，您在自己的网络服务器上运行它（家里的一台小型电脑或租用的网络空间），并在浏览器中打开。qFT8 会在每个 QSO 记录后立即把它发送过去，并读回您的 Wavelog 已确认了其中哪些。qFT8 通过 Wavelog 公开的接口与它通信： docs.wavelog.org/developer/api.

设置方法

  1. 在 Wavelog 中，打开账户菜单 > API Keys，创建一个具有读取和写入权限的密钥。
  2. 在 qFT8 中，打开设置，点击 Wavelog 旁边的齿轮，输入服务器地址（您打开 Wavelog 所用的地址，例如 https://log.example.org）和 API 密钥。 不带 http:// 或 https:// 输入的地址会先用 https 尝试;如果服务器只支持普通 http(另一个 qFT8 的服务器就是这样),qFT8 就使用 http,页面会提示密钥未受保护地传输。
  3. 可选,要同时发送编辑:在 Wavelog 中创建一个 API v2 令牌(账户菜单 > API Keys,API v2 标签页,权限范围为 qso:read 和 qso:write),并将其输入为编辑令牌。验证 会在不更改任何内容的情况下检查它。
  4. 点击验证。qFT8 会检查密钥并列出您的 Wavelog 电台位置；选择您的 QSOs 所属的那个（只有一个时会自动选中）。
  5. 在设置顶部勾选 Wavelog。从现在起，每个新的 QSO 都会发送过去，之前记录的也会一并发送。

会发生什么

  • 离线：无法发送的 QSO 会留在日志中，待服务器再次响应时发送（1 分钟后重试，之后间隔逐渐变长，最长每小时一次）。无法连接服务器时，它在设置中的那一行会变红，并显示“自 ... 起无法连接”。
  • 重复：您的 Wavelog 已有的 QSO 视为已上传。
  • 被拒绝：被 Wavelog 拒绝的 QSO 在您编辑或重新上传之前不会再次发送；QSO 编辑器会显示原因。失效的密钥会停止上传，直到您再次点击验证。
  • 确认:每小时一次(以及你按下 立即上传 时),qFT8 会向 Wavelog 询问你的哪些 QSOs 已被确认(LoTW、纸质 QSL、eQSL),并在 QSO 编辑器的 已上传 行和 状态 行中标出,行和标记与 QRZ、LoTW 相同。
  • 编辑:设置了编辑令牌后,已编辑的 QSO 会在你的 Wavelog 中找到并在那里更新(以最新的更改为准;Wavelog 自己保存的确认标记绝不会被改动)。未设置时,Wavelog 的上传接口只能添加 QSOs,因此编辑不会被发送:请在 Wavelog 中也做同样的修改。
  • 其他呼号的 QSOs:以你的呼号之外的另一个呼号记录的 QSO(俱乐部或特别活动呼号)不会发送到 QRZ 和 LoTW,但只要勾选了也发送使用其他呼号进行的 QSO(默认),就会发送到 Wavelog。
  • 删除：qFT8 绝不会删除 Wavelog 中的任何内容。请自行在那里删除 QSO。
  • 页面上的“如果已上传到此处，则视该 QSO 为已上传”决定上传到 Wavelog 是否计入“已上传”标记（默认关闭）。

从 Wavelog 导入 QSO

Wavelog 页面底部的从 WAVELOG 导入 QSO会把所选电台位置的 QSOs 复制到 qFT8 的日志中，同时带上它们的 LoTW、纸质 QSL 和 eQSL 确认。

  • 导入内容：所有模式。从、到、波段和呼号开头为可限制范围（任意 = 不限）。用您以外的呼号进行的 QSOs 会被跳过，除非勾选了导入当前呼号以外其他呼号的 QSO。
  • 已在日志中：日志中已有的 QSO 会被合并，绝不会重复添加（规则与 QRZ 和 LoTW 导入相同）；您在这里更正过的 QSO 保留您的更正，只接收确认。
  • 绝不回传：导入的 QSOs 视为已在 Wavelog 上。您之后在 qFT8 中所做的更正会发送到那里（使用编辑令牌）。
  • 停止会在当前这一部分完成后结束导入；已经导入的内容会保留。按钮下方的一行统计已接收、已添加和已合并的数量。
  • 不会删除任何内容，无论在这里还是在 Wavelog。您在 qFT8 中删除的 QSO 会在下次导入时回来。

安全连接

  • 请优先使用 https:// 地址。使用 http:// 时密钥会不受保护地传输：仅在您的家庭网络中使用。
  • Android 6 和 7.0 不信任许多此类服务器使用的一些较新的证书；在这些系统上，https:// 服务器可能无法连接。在家庭网络中，可使用服务器的 http:// 地址。
  • iPhone 只连接 https:// 地址。

Cloudlog

Cloudlog 是 Wavelog 的前身程序：一款运行在您自己网络服务器上的日志。它在 qFT8 中是一项独立的服务，有自己的设置，设置方式与 Wavelog 完全相同（在 Cloudlog 中：账户菜单 > API > 创建具有读取和写入权限的密钥）。它公开的接口： github.com/magicbug/Cloudlog/wiki/API.

与 Wavelog 的区别

  • 没有确认返回：Cloudlog 不允许其他程序读取哪些 QSOs 已被确认，因此 qFT8 只向它上传。
  • 电台呼号：如果 QSO 的电台呼号与所选电台位置的呼号不同，Cloudlog 会拒绝它。这样的 QSO 在编辑器中显示为被拒绝；请在 Cloudlog 中为它选择匹配的电台位置。
  • 编辑不会发送；绝不删除任何内容；离线、重复、红色的“无法连接”提示以及安全连接说明均与 Wavelog 相同。
  • 导入：其他程序无法读取 Cloudlog。要把它的日志带入 qFT8，请在 Cloudlog 中导出 ADIF 文件，然后在设置 > 导入/导出日志中使用从 ADIF 导入 QSO（见 ADIF）。

激活（POTA / SOTA）

Cloudlog 从 QSO 所发往的电台位置获取您自己的公园或山峰，绝不从 QSO 本身获取。进行激活时，请在 Cloudlog 中创建（或选择）一个电台位置，其 POTA / SOTA 字段和名称中都带有公园或山峰参考编号，例如 Park US-0001。激活进行期间，qFT8 会自动把它的 QSOs 上传到该位置。若没有任何位置带有该参考编号，qFT8 会在每次激活中提示一次，并上传到您常用的位置，不带参考编号。

eQSL

eQSL（eqsl.cc）交换电子 QSL 卡：发送到那里的每个 QSO 都会成为对方电台 eQSL 收件箱中的一张卡片。qFT8 只添加卡片，绝不删除 eQSL 上的任何内容。

设置方法

  1. 点按“设置”顶部 与 eQSL 同步 QSO 一行的齿轮。
  2. 输入您的 eQSL 用户名（通常是您的呼号）和 eQSL 密码。如果您在一个呼号下有多个 eQSL 账户（地点），请按 eqsl.cc 上的写法输入该地点的 QTH 昵称；否则留空，eQSL 会根据 QSO 的日期选择账户。
  3. 按 验证。它只读取您的 eQSL 收件箱来检查登录：不会发送任何卡片。
  4. 勾选 与 eQSL 同步 QSO。尚未发送的 QSOs 会立即发出，每秒一个，之后每个新 QSO 在记录时发出。

须知

  • 对 eQSL 来说，上传到此处即视为 QSO 已上传 是关闭的：eQSL 上有一张卡片本身不会让日志出现绿色勾号（参见 QSO 上传服务）。如果您希望如此，请勾选。
  • 卡片无法更改。 编辑已经在 eQSL 上的 QSO 时，不会自动发送任何内容。要发送更正后的卡片，请使用 QSO 编辑器中的 重新上传到 eQSL；旧卡片会留在对方电台的收件箱中，直到您在 eqsl.cc 上将其删除。
  • LQ8：eQSL 只接受官方的 ADIF 模式，因此其 QSOs 以 MFSK 发送，备注中会写明真实模式（“QSO by qFT8, mode LQ8”）。其他服务保持各自的形式。
  • eQSL 已有的 QSO 会被答复为重复，并算作已发送。它拒绝的 QSO（例如您的任何账户都不涵盖的日期，或它不认识的模式）会在 QSO 编辑器中显示为被拒绝，并附上 eQSL 自己的原话，在您重新上传之前不会再次尝试。
  • 离线时，或 eQSL 因维护而停止服务时，卡片会等待并稍后重试（1 分钟后，然后间隔更长，最长一小时）；该行红色的 无法连接 提示会说明从何时起。如果密码被拒绝（例如您在 eqsl.cc 上改了密码），发送会停止，直到您再次 验证。
  • 确认（收到的卡片）暂不回读。

qFT8 作为 Wavelog 服务器

在设置 > qFT8 服务器 > Wavelog 服务器中，qFT8 在您的家庭网络中就像一个 Wavelog 那样应答：任何能把 QSOs 发送到 Wavelog 的程序（包括另一个 qFT8）都可以改为把它们发送到这个 qFT8。

设置方法

  1. 打开运行 Wavelog 服务器，保留端口（13500）或另选一个，并输入至少 8 个字符的 API 密钥（请设得又长又随机：这是阻止他人进入的唯一屏障）。
  2. 在另一个程序中,用页面显示的地址设置 Wavelog,并写完整:http://、本设备的地址、冒号和端口,例如 http://192.168.1.20:13500/(大多数日志程序需要把 http:// 和端口都写出来;另一个 qFT8 会自动找到它们),使用相同的密钥和电台 1(在另一个 qFT8 中:验证 会选择它)。

端口可以随时更改:服务器会立即切换到新端口(关闭时立即停止)。

在浏览器中查看日志

在家庭网络的浏览器中打开同一个地址(http://192.168.1.20:13500/):输入服务器的密钥后,它会按从新到旧的顺序以只读方式显示你的 QSO 日志;较早的 QSOs 会在滚动时加载,新的或已更改的会自动出现。密钥绝不会被发送:浏览器用由密钥算出的值回应一次性质询,回应错误的地址会被锁定一段时间。Cloudlog 服务器和 qFT8 日志服务器在各自的端口上以各自的密钥或密码显示同一个页面。

它做什么

  • 收到的每个 QSO，无论何种模式、何种呼号，都会进入日志和 QSO 列表，并转发到此处设置的服务（QRZ、LoTW、Wavelog 等），但绝不会返回其来源。日志中已有的 QSO 会作为重复应答，不会再次转发。
  • 它应答日志程序使用的各个端点：api/qso（以 ADIF 格式的一个或多个 QSOs）、api/version、api/station_info、api/check_auth、api/auth、api/get_contacts_adif（使链条下游的 qFT8 能读回确认）以及 api/radio（接受并忽略）。无法通过它修改或删除 QSO。
  • 安全：仅限家庭网络，使用普通 http（与遥控网络服务器相同）；密钥以不会泄露它的方式比较；发送 10 次错误密钥的地址会被锁定 10 分钟；每个地址每秒最多 20 个请求，每个请求最多 128 KB 和 500 个 QSOs；任何格式错误的内容都会收到错误应答。
  • 运行位置：在 Android 上，开启“后台运行”时也在后台运行；在电脑上，程序打开期间运行；在 iPhone 上，仅在 qFT8 打开期间运行。

链式连接

服务器和服务可以组合成链：多个电台（手机、电脑）把各自的 QSOs 发送到同一个 qFT8，由它汇总，并且只有它向 QRZ 和 LoTW 上传；它还可以把所有内容转发到 Wavelog 或作为备份的另一个 qFT8。确认沿链向下回传：汇总的 qFT8 从 QRZ / LoTW / 它的 Wavelog 得知确认，而向其 Wavelog 服务器发送的各个 qFT8 每小时读回它们。重复项绝不会被转发，因此链中的环路会自行停止。

山峰通联（SOTA）

qFT8 为 SOTA（Summits On The Air，山峰通联）的追逐者（猎人）和激活者都提供了完整的内置工具，包括自动获取 spot、实时跟踪参考编号、成绩高亮，以及专用的 ADIF 导出筛选。

自动获取实时山峰 spot

有互联网连接时，qFT8 会在后台自动连接 SOTA 官方 API（每 90 秒刷新一次），获取全球正在进行的山峰激活。

  • 世界地图显示：正在活动的山峰激活者会以山峰标记（⛰️）标在世界地图上，并带有呼号、山峰名称、海拔和频率。
  • 自动匹配参考编号：当您在波段上收到一位激活者时，qFT8 会把他的呼号与实时 spot 数据库对照，查出确切的山峰编号（例如 HB/BE-001、W6/NC-001）。
  • 自动补填：如果您与一个呼叫 CQ SOTA 的电台完成了 QSO，而当时它的 spot 还没有下载到，或者还没有收到参考编号，qFT8 会留意后来收到的 spot，自动把山峰编号补填到最近（1 小时以内）记录的 QSO 上。

作为 SOTA 追逐者 / 猎人操作

要追逐正在激活山峰的电台：

  1. 在电台选项卡中，把目标优先级下拉菜单设为 SOTA 猎人（或 POTA + SOTA 猎人）。
  2. 标记和参考编号列：正在活动的 SOTA 电台（网上有 spot，或正在发 CQ SOTA）会在第 2 行标上 SOTA 标记。此外，DXCC 列的标题会变成 SOTA 编号，直接显示山峰编号。
  3. 已通联与待通联山峰的高亮：
    • 未通联过的山峰：以醒目的紫色 SOTA 标记和紫色编号文字显示，表示这是一座值得追逐的新山峰。
    • 已通联过的山峰：以不显眼的灰色标记显示，让您一眼就能把新山峰和日志里已有的山峰区分开。
  4. AUTO 追逐：在 AUTO 模式下，qFT8 会自动优先呼叫未通联过的 SOTA 激活者，其次才是普通的 CQ 电台，并按信号强度（SNR）从强到弱排序。

在日志中管理和编辑 SOTA 参考编号

qFT8 提供专门的工具，用来查看和编辑您的 SOTA 追逐记录：

  • 日志选项卡中的 SOTA猎人视图：在日志选项卡中选择 SOTA猎人视图即可查看山峰编号。首次得到确认的山峰通联以金色高亮，首次但尚未确认的成绩以黄色高亮。
  • 编辑山峰编号：点按日志中的任意 QSO 打开 QSO 编辑器，再点按其中的 SOTA 字段，即可添加、修改或更正山峰编号（例如 HB/BE-001）。
  • 自动同步到 QRZ 日志（ACTION=REPLACE）：如果这个 QSO 已经上传到 QRZ，编辑山峰编号后该记录会被自动标记，并在您的 QRZ 日志中原地更新，不会产生重复条目。
  • 关于 LoTW：请注意，编辑参考编号时 LoTW（Logbook of The World）不会自动更新，因为 LoTW 不支持修改已上传的 QSO。

作为 SOTA 激活者操作

要在山峰上进行 SOTA 激活：

  1. 同步时间：出发去野外之前，先确认设备的时钟准确。
  2. 开始激活：在设置选项卡中按 SOTA 激活 并输入您的山峰，这样每个 QSO 都会带着它记入日志并计数（见激活公园或山峰）。
  3. 设置 CQ 修饰符：在设置选项卡中，把 CQ 修饰符设为 SOTA。每次 CQ 呼叫都会发出 CQ SOTA [Callsign]。
  4. 配置 AUTO 模式：在电台选项卡中，把目标优先级设为 呼叫 CQ，并启用 AUTO 模式。
  5. 开始激活：打开 TX。qFT8 会自动呼叫 CQ，并依次回答前来呼叫的追逐者。

手动干预：如果几位追逐者同时呼叫您，而您想挑选其中某一个电台，请点按该电台条目上的 CALL。这次通联完成后，qFT8 会自动回到呼叫 CQ。

导出 SOTA 日志（追逐者和激活者）

qFT8 可以生成有针对性的 ADIF 导出文件，既可用于猎人提交成绩，也可用于激活者的日志：

  1. 进入设置，点按 ADIF 文件导出。
  2. 追逐者 / 猎人：
    • 把猎人条件设为 仅导出 SOTA 猎人，只导出与山峰通联的 QSO（即填有 <SOTA_REF> 的记录）。
  3. 激活者（最快的办法是使用您的激活中的 导出 按钮；下面的步骤是手动完成同样的事）：
    • 选择所选时间段，使之与您激活的开始和结束时间一致。
    • 在活动中选择 SOTA，并输入您激活的山峰编号（例如 HB/BE-001）。qFT8 会把您的编号写入每条记录的 <MY_SOTA_REF>。
  4. 山峰对山峰（S2S）：如果您在激活山峰期间通联了另一位激活者，qFT8 会在导出文件中同时写入您激活的山峰（<MY_SOTA_REF>）和对方的山峰（<SOTA_REF>）。
  5. 按导出 QSO，分享或保存这个标准的 ADIF 文件。

激活公园或山峰

当您在公园（POTA）或山峰（SOTA）操作时，请在 qFT8 中开始一次激活。此后您记录的每个 QSO，无论哪种模式，都会自动带上您的公园或山峰；qFT8 替您计数，最后只需点按一次，就能生成这些活动要求的文件。

开始

  1. 在设置选项卡中，按 POTA 激活 或 SOTA 激活（就在导出设置 / 导入设置的上方）。
  2. 输入您的编号，例如公园用 US-1234，山峰用 W1/HA-001。如果您同时身处多个公园（“two-fer”），请用逗号分隔。qFT8 会在您输入时检查格式，并提供您最近用过的编号。
  3. 按 开始。按钮变为蓝色，并显示编号和 QSO 数量。

公园激活和山峰激活可以同时开启；这时每个 QSO 都会带上两个编号。要在数字模式下呼叫 CQ POTA 或 CQ SOTA，请按 POTA 和 SOTA 章节的说明设置 CQ 修饰符。

qFT8 也会主动提出为您开始：如果它为世界地图下载的 spot 中，您自己的呼号被列为激活者，它会询问在那里开始 POTA 激活? 如果您在记录器空着的我的 POTA / 我的 SOTA 框中输入公园或山峰，它会询问是否用它开始一次激活。

公告，让猎人找到你

当你自己开始一次激活（而不是从已经公告了你的 spot 开始）时，qFT8 会询问在 POTA 上公告？（或 SOTA），并说明猎人会看到什么，例如 FT8 on 20m (14074 kHz)。暂不 不公告任何内容。公告 会打开一个简短的对话框：

  • 波段和模式：每项各勾选一个或多个。qFT8 当前所在的波段和模式已经勾选。qFT8 会为你所选的每个公园、波段和模式各发送一条公告，并在你按下 公告 之前告知数量。
  • 程序未列出的模式会以 DATA 公告，真实模式写在公告的备注中。没有常用频率的波段和模式组合（60 m 上的 RTTY）会被略去，对话框会说明。
  • 对于你当前所在的波段和模式，频率就是电台所在的频率；对于其他组合，则使用常用的呼叫频率。
  • 仅 SOTA：对话框还会要求输入你的 SOTAwatch 用户名和密码（你自己的 SOTA 登录）。qFT8 会为下次保存它们，和其他服务的密码一样。

之后，只要激活处于打开状态且 qFT8 在工作（在屏幕上，或最小化但 qFT8 在后台运行且电台已连接），qFT8 每 30 分钟重新公告一次激活（公告大约一小时后会从列表中消失）。结束激活时它会停止；qFT8 关闭期间它绝不会自行公告：下次启动时，在你选择继续激活之后，它会询问再次公告？

如果公告没有发送成功（没有网络、网站拒绝，或 SOTA 登录有误），qFT8 会说明出了什么问题，并提供重试，或手动公告，后者会在浏览器中打开该程序的 spot 页面，方便你自己公告。没有网络连接时，它还会每 5 分钟自动重试。

要用其他波段或模式公告，或查看上次公告的时间，请在激活的卡片上（点按蓝色标记）或激活的 QSO 视图中按下 公告。此时对话框还会提供停止重新公告。在已公告的激活期间更换模式时，qFT8 会询问是否也公告新模式。

激活进行期间：蓝色标记

只要激活处于开启状态，瀑布图右下角就会一直显示蓝色的 POTA 或 SOTA 标记，旁边是本次激活的 QSO 数量：POTA 10。您记录的每个 QSO 都会计入；当某个 QSO 被移出激活、被删除或在记录器中被撤销时，数字会相应减少。同时激活两个公园时仍然只有一个数字，因为每个 QSO 同时计入两个公园。空间不足时，标记只在图标旁显示数字；连这也放不下时，它会连同共用一行的红色警告一起缩小显示。点按它可查看激活的状态：

  • 编号和计数：已完成的 QSO 数，以及该活动认定有效激活所要求的数量（公园 10 个，山峰 4 个），还有其中多少个是与另一个公园或山峰通联的（P2P / S2S）。
  • 查看激活：本次激活的 QSO 列表（见下文）。
  • 结束激活：结束本次激活。它总会先询问，按 继续 可接着进行。
  • 关闭：关闭卡片。

激活的 QSO

  1. 返回完整的 QSO 日志。
  2. 激活：活动和编号、开始时间（UTC）及其 QSO。
  3. +：打开记录器，把一个 QSO 直接手动记入本次激活。
  4. 添加 QSO：按时间范围添加日志中已有的 QSO。忘记开始激活时可以用它：选择起止时间，qFT8 会在添加之前告诉您将添加多少个 QSO。
  5. 导出：生成用于上传的文件（见下文）。
  6. 对方电台的公园或山峰（对方也在激活时）。
  7. 开启中的激活的标记。

要把 QSO 从激活中移出，请长按其中一个将其选中，再点按其他要移出的 QSO，按 操作 并选择 从本次激活中移出。这些 QSO 仍留在您的日志中，只是去掉了您的编号。您也可以在 QSO 编辑器中，用 POTA 激活 / SOTA 激活一行移动单个 QSO。

结束与恢复

结束激活 会显示一份摘要：编号、开始和结束时间、各模式的 QSO 数，以及激活是否有效。结束之后记录的 QSO 不属于本次激活。

  • 误点了结束，还是休息后回来了？ 24 小时之内，摘要、激活列表以及 POTA 激活 / SOTA 激活 开始对话框都会提供 恢复激活，可以重新开启它，就像什么都没发生过。
  • 新的 UTC 日。 对 POTA 来说，每个 UTC 日是一次单独的激活。UTC 零点之后，qFT8 提供的不是恢复，而是在同一公园 开始新的。
  • 忘了结束。 如果 qFT8 关闭了一段时间，或者很久没有 QSO，下次启动时它会询问是 继续 还是结束。

导出

导出（在摘要和激活列表中）会按各活动要求的方式命名并生成 ADIF 文件，可直接上传到其网站：

  • POTA：每个公园、每个 UTC 日各一个文件，名称为 CALLSIGN@PARK-DATE.adi（例如 K1ABC@US-1234-20261006.adi）。同时激活两个公园时，每个公园一个文件。本身就在两个公园的对方电台，会针对它的每个公园各写入一次，这样两个都算作公园对公园。
  • SOTA：山峰一个文件，命名方式相同（K1ABC@W1_HA-001-20261006.adi）。

您可以保存或分享这些文件。“设置”中 POTA 激活 / SOTA 激活 旁边的放大镜按钮会列出您以往的激活，最新的排在最前，并把每一次标为 进行中、可恢复、已导出 或未导出；点按其中一次即可打开并再次导出。qFT8 自己不会向这些活动的网站上传。

连续多个公园

在一天之内先后去多个公园时，每个公园各是一次激活、一个文件：

  1. 在第一个公园，按“设置”中的 POTA 激活，输入它的编号并按 开始。
  2. 开始操作。每个 QSO 都会带上这个公园，蓝色标记负责计数。
  3. 离开之前，点按标记并按 结束激活，再在摘要中按 导出，然后保存或分享文件（K1ABC@US-1234-20261006.adi）。
  4. 到了下一个公园，用新的编号重新开始。

回到家后不需要重新输入或整理任何东西。如果在野外来不及导出，以往激活的列表（放大镜）可以在以后逐个导出。

“文件中写哪个公园？”

一个公园的文件只能写一个公园。当您不通过激活来导出同时在多个公园完成的 QSO 时（从“设置”导出整个日志，或对所选 QSO 使用导出 (ADIF)），qFT8 会询问文件中写哪个公园？ 请选择这个文件对应的公园；另一个公园再导出一次。日志不会改变。从激活本身导出时不会询问：它为每个公园生成一个文件。

要在没有激活的情况下为每个公园各得到一个文件，请自己输入用逗号分隔的公园（US-1234, US-5678），可以填在导入/导出日志的 POTA 参考框中，也可以填在对所选 QSO 使用的带 POTA 编号导出中：qFT8 会为每个公园生成一个文件，其中的 QSO 相同。山峰始终只有一个编号。

当您通联的电台同时身处两个公园时，qFT8 会把两个都保留下来：如果发 spot 的人把第二个公园写在了 spot 的备注里，它就从那里读取。日志显示第一个公园以及还有几个（US-1234 +1）。如果公园有误或缺失，请在 QSO 编辑器中更正该 QSO 的 POTA 字段；它可以填写用逗号分隔的多个公园。同一电台的同一个公园被提到两次时（spot 中一次、备注中又一次，或在输入的列表中出现两次），在日志和每个导出文件中都只算一次。

JS8 聊天

在 JS8 模式下，除了传统的 FT8/FT4 式 QSO 操作之外，qFT8 还提供一个对话式的自由文本聊天界面。JS8 可以在弱信号条件下可靠地进行键盘对键盘的消息往来，并有多种速度可选（Slow 30 秒、Normal 15 秒、Fast 10 秒和 Turbo 6 秒时隙）。

频道类型与消息归类

右侧的聊天面板把收发的消息分别归入各自的频道标签：

  • [GLOBAL] 主频道：显示在整个音频通带内解码到的每一次 JS8 发射，以及您自己的全部发射。在这一处就能实时纵览波段上的所有活动。
  • 广播群组频道（@CQ、@ALLCALL）：用于向所有守听的电台发出一般呼叫和通告。发到 @CQ 或 @ALLCALL 的消息，调谐在该频率上的任何人都能看到。
  • 自定义群组频道（@GROUPNAME）：qFT8 支持自定义的定向群组（例如 @EMERGENCY、@SOTA、@NET）。收发带有 @GROUP 标记的消息时，它会自动归入该群组专用的频道标签。
  • 电台直接频道（呼号标签）：从频道列表或电台表格中选择某个电台，会打开与该呼号的专用对话。

空中发射（不保密）：所有 JS8 消息都作为普通的业余无线电数字信号以明文发射。与某个电台的直接聊天只是为了方便而把对话记录归入专用标签，它既不加密也不私密，任何守听该频率的电台都能收到。

撰写和发送消息

  1. 选择目标：在右侧面板中点按一个频道标签（[GLOBAL]、@CQ、@ALLCALL、某个群组或某个电台的呼号）。
  2. 输入消息：在底部的输入框中输入文本（支持全部标准 ASCII 字符，最多 100 个字符）。
  3. 发送：点按发送按钮。

点按消息（快速聊天和详情）

点按聊天记录中的任何一条消息（在电脑上：双击），会打开详情对话框，显示完整的 UTC 时间戳、音频频率、SNR、Maidenhead 网格和消息内容：

  • 收到的消息（RX）：点按 CHAT 可立即打开与发信电台的直接聊天标签；如果消息是发给群组的，则点按 GROUP CHAT。
  • 发出的消息（TX）：点按 RESEND 会自动把文本填回输入框并选好目标频道，方便重新发送。

多分块消息的连续发送

如果您的消息太长，一个 JS8 发射帧放不下：

  • qFT8 会自动把消息拆成连续的多个分块帧。
  • 应用会在接连的时隙中自动依次发出每个分块，直到整条消息发完。
  • 进度指示会显示这次多时隙发射的进展（例如 TX (1/3)）。
  • 如果需要在全部分块发完之前停止，点按发送/停止按钮会弹出提示，可以取消队列中剩余的发射。

管理频道（长按操作）

在右侧面板中长按（按住不放；在电脑上：右键单击）任何电台呼号标签或群组频道标签，会打开带有管理选项的菜单：

  • 清除聊天：清除所选频道标签的消息记录。
  • 关闭聊天：关闭该标签，并把它从活动频道栏中移除。
  • 导出聊天：把所选频道的全部消息记录导出为文本文件，或通过分享面板发送。

自动回答查询（AUTO 模式）

启用 AUTO 按钮后，qFT8 会自动回答其他电台发来的定向查询（例如 SNR?、HW CPY?、GRID?、INFO?、STATUS? 和 HEARING?）以及心跳消息（@HB HEARTBEAT）。

例如，如果另一个电台发来 YOURCALL SNR? 或 YOURCALL HW CPY?（YOURCALL 即您的呼号），qFT8 会自动把您的信号报告回答（例如 SNR -08）排入队列并发出，无需手动操作。同样，收到心跳发射（@HB HEARTBEAT）时，qFT8 会自动把心跳确认（HEARTBEAT SNR -08）排入队列，向发射电台报告接收情况。

定向查询和“请求”按钮

请求按钮可以让您快速向当前选定的目标电台或群组发送标准的定向查询，不必手动输入命令：

  • SNR? / HW CPY?：请对方电台给出信号报告。
  • GRID?：请求对方电台的 Maidenhead 网格定位。
  • INFO?：请求对方电台设定的信息文本。
  • STATUS?：请求对方电台的工作状态文本。
  • HEARING?：查询对方电台在最近 10 分钟内收到的电台列表。

WSPR 模式

WSPR（Weak Signal Propagation Reporter，弱信号传播报告）是一种专门的数字协议，用极低功率的发射来探测电波传播路径。WSPR 信号采用窄带 4-FSK 调制、稳健的卷积编码和序贯 Fano 译码，能解出远低于底噪的信号，低至 −28 dB SNR。

2 分钟周期与定时

WSPR 发射在同步的 2 分钟 UTC 时隙内进行（发射持续 110.6 秒，共 162 个音调符号）。发射总是在偶数 UTC 分钟过后整一秒开始（:00, :02, :04, :06...）。由于一次发射持续将近两分钟，小功率电台必须被允许发射这么长时间：见连续发射时间上限。频谱图的垂直滚动会自动调整为平滑的慢速滚动，与 120 秒的周期相匹配。

单面板活动视图

WSPR 是信标和传播报告协议，而不是双向对话的模式，因此 qFT8 提供一个简洁的全宽单面板活动记录，不再分出 QSO 日志：

  • 呼号：电台的呼号。
  • DXCC 实体：自动识别出的国家 / DXCC 实体名称（宽度自适应）。
  • 网格定位：4 字符的 Maidenhead 网格（例如 JN45）。
  • SNR：接收信号的信噪比，单位 dB，与其他 WSPR 接收机一样，以 2,500 Hz 带宽内的噪声为基准测量。
  • 功率：电台报告的发射功率，单位 dBm（例如 37 dBm）。
  • 日期和 UTC 时间：发射时隙的 UTC 时间戳，格式为 yyMMdd HH:mm。

自动信标和发射比例（Tx %）

在 WSPR 活动界面顶部的标题栏中：

  • 信标开关：打开或关闭自动信标发射。打开时（以亮绿色高亮），qFT8 会按您设定的发射比例，以确定的间隔自动安排信标发射。
  • Tx % 选择器：设置确定性的发射占空比，按距上次发射经过的时间计算（0% [Rx Only]（仅接收）、10%、20%、25%、33%、50% 或 100% Continuous（连续））。例如，20% 表示从上次发射起每 10 分钟发射一次（50% = 每 4 分钟，33% = 每 6 分钟，25% = 每 8 分钟，10% = 每 20 分钟，100% = 每个 2 分钟周期都发射）。
  • Tx 下次按钮：安排在下一个 2 分钟周期开始时立即手动发射一次。发射之后，自动的确定性信标安排从该周期起继续。

向 WSPRnet 和 PSKReporter 上传 spot

qFT8 可以把收到的 spot 自动上传到全球的 WSPRnet 数据库和 PSKReporter：

  • 从 WSPRnet 下载 Spot：默认开启，实时获取与您的呼号和波段有关的 spot，显示在世界地图上。
  • 上传报告至 WSPRnet：在设置 → WSPRnet 中启用后，收到的 spot 会成批上传到 WSPRnet，并带有 15 分钟去重和速率限制。
  • 打开 WSPRnet：直接在浏览器中打开 WSPRnet 数据库，并已按您电台的呼号筛选。

单独的 ADIF 导出

点按 WSPR 活动面板右上角的 导出 按钮，可以把本次会话记录的所有 spot 导出为标准 ADIF 格式（.adi），用于传播研究和存档。

SSB（话音）

在 SSB 模式下，qFT8 就是您收发信机的麦克风和扬声器：电台收到的信号在您的扬声器或耳机中变成话音，您的声音从您的麦克风送到电台。电台的连接方式与数字模式完全相同（同一根 USB 线、同一块声卡），因此在 FT8 和话音之间来回切换时，不需要重新插拔任何东西。

用底部栏的模式选择器选择 SSB。报文区域、序列按钮和周期进度条会消失（话音没有时隙），模式选择器旁边出现 USB / LSB 按钮，“电台”选项卡变为 SSB 面板：

SSB 界面的各个组成部分如下：

  1. RX / TX / RX/TX：选择调谐轮（第 12 项）移动的对象。选 RX/TX 时，收发在同一频率上。选 RX 或 TX 时只移动其中一个，这样可以在一个频率上收听、在另一个频率上发射（异频操作）。
  2. AUTO RIT：让稍微偏离频率的电台保持居中，不用碰调谐轮，对方的声音听起来也自然。
  3. 齿轮：打开设置 > SSB（见下文）。返回回到此面板。
  4. QSO：打开已填好模式、边带和频率的记录器，记录您刚完成的通联（见记录器）。每按一次记录一个 QSO。
  5. 语音存储：您录制的语音（CQ 呼叫、您的呼号……）。在录制第一条之前，这个区域显示链接在设置中配置语音存储。
  6. IN：您麦克风的电平及其增益滑块。标有 VOX 的线，是 VOX 开启时（第 10 项）您的声音必须超过才能让电台发射的电平：可以拖动它。
  7. OUT：接收音频的电平和您扬声器的音量滑块。手机的音量键作用相同。
  8. FILTER 和 NR：接收滤波器（关、2.7、2.4 或 1.8 kHz）和降噪（关、1、2 或 3）。每点按一次切换到下一个值。
  9. PTT：按键通话。根据 PTT 模式设置，它显示“按住说话”或“点按说话”，发射时显示“发射中”。在电脑上，面板获得焦点时空格键的作用相同。
  10. VOX：开启后，由您的声音而不是 PTT 按钮控制电台发射。
  11. USB / LSB：边带。更换波段时会自动替您选好（10 MHz 以下为 LSB，以上为 USB）；点按即可切换，而您读到的频率保持不变。
  12. 调谐轮：在 SSB 中，频谱图的频率刻度是一个转轮。沿着它滑动即可调谐电台；滑得越快，步进越大。点按不起作用，所以频率不会意外跳变。在电脑上也可以用鼠标滚轮调谐（按住 Shift 为 1 Hz 步进）。调谐需要与电台的 CAT 连接。
  13. 频率和波段：您在空中报出的频率（载波频率）和波段。橙色线及其下方的 RX/TX 标签，标出您正在收听和发射的那一段频谱图。

通话

  1. 用底部栏的 TX 按钮开启发射。和其他所有模式一样，它显示 TX OFF 时不会有任何发射：红色的一行按 TX ON 发射会提醒您。
  2. 按住 PTT 讲话，讲完松开。或者开启 VOX，直接讲话。
  3. 要发送一条语音存储，点按它即可。TX ON 时它会被发射出去，您也能在扬声器里听到。TX OFF 时它只播放给您听，适合用来检查录音。长按（在电脑上是右键单击）则始终只播放给您听。

您自己的实时语音绝不会在您的扬声器中回放。如果您要发射的频率在业余波段之外，qFT8 不会让电台发射，并会告诉您。

PTT 限时：使用点按切换和 VOX 时，发射会在 PTT 限时（除非您更改，否则为 100 秒）到达后自动停止，PTT 按钮上会倒数剩余秒数。到达限时后，VOX 会暂停同样长的时间，或直到您点按 PTT。这样可以保护电台，避免麦克风一直拾取到噪声而持续发射。电台自身的连续发射时间上限同样有效：以两者中较短的为准。

语音存储

进入设置 > SSB > 语音存储（或在面板中点按在设置中配置语音存储），按 录制新语音存储。最多可保存 6 条存储，每条 30 秒。每一条都可以命名、重新录制、设置音量或按 归一化，还可以拖动声音波形图上的两个手柄，裁掉开头和结尾的静音；播放 播放您保留的部分，保存之前不会有任何改变。存储连同录音一起包含在设置导出中。

设置 > SSB

  • PTT 方式：PTT 按钮，或 VOX。
  • PTT 模式：按住说话或点按切换。
  • PTT 延迟：让电台转入发射到送出您的声音之间的时间。您说的话不会丢失：第一个音节会等电台准备好。
  • PTT 限时：见上文（10 至 600 秒）。
  • 边带：按波段自动选择、始终 USB 或始终 LSB。
  • 进入 SSB 时的滤波器和进入 SSB 时的降噪。
  • 在扬声器上播放接收到的声音和发射时扬声器静音。
  • 语音存储和 恢复默认设置。

SSB 需要什么

  • 不是电台声卡的麦克风和扬声器。手机自带这两样；耳麦也可以。见扬声器和麦克风。如果电台与您的麦克风或扬声器是同一个设备，会有一行红字提示，并且不会发射或播放任何声音。
  • 一台电台。没有电台时，面板会被一张卡片取代，上面写着请连接电台以使用 SSB；电台接好后面板会自动恢复。没有 CAT、靠自身 VOX 转入发射的电台也可以用，只是应用无法为它调谐。
  • QMX 或 QMX+ 需要 1_02_000 或更新的固件才能从应用发射话音。固件较旧时，底部栏显示无 SSB，该模式只能接收。
  • 第一次在 SSB 下进入某个波段时，qFT8 会调谐到该波段在您所在地区常用的话音频率；此后则回到您上次在该波段使用的频率。30 米波段没有话音段，因此不提供。

QSO 以 SSB 连同边带记入日志，并像其他 QSO 一样上传到 QRZ 和 LoTW。

CW（莫尔斯电码）

在 CW 模式下，qFT8 会抄收通带内的每一个莫尔斯信号，并把文字写在频谱图上；发报可以用屏幕上的电键桨、您自己的按键、预设报文或输入的文字。TX OFF 时一切都可以当作练习：您在扬声器里听到自己拍发的电码，但什么都不会发射出去。

用底部栏的模式选择器选择 CW：

CW 界面的各个组成部分如下：

  1. AUTO：让 qFT8 自己完成整个 CW QSO（见 CW 中的 AUTO）。
  2. RX / TX / RX/TX：选择点按瀑布图或转动调谐轮时移动哪一条标线：接收标线、发射标线，或两者一起。
  3. 齿轮打开设置 > CW，QSO 打开已填好 CW、频率和目标的记录器。
  4. 目标：您正在通联的电台的呼号。它会填入您报文中的 [TARGET] 部分。点按它可输入呼号，也可以点按解码行（第 10 项）中的呼号，直接取用。
  5. 存储：预设报文。点按即发送。您自己的呼号显示为蓝色，信号报告显示为黄色。还缺内容的存储（目标、您的名字……）会变暗；点按它可以看到缺什么。
  6. WPM 和 FARNSWORTH：以每分钟词数表示的发报速度，以及可选的 Farnsworth 速度（字符保持原速，字符之间的间隔加长）。
  7. FILTER 和 NR：接收标线两侧接收滤波器的宽度，以及降噪。
  8. 电键桨：左桨发点，右桨发划。同时按下两桨用于 Iambic 模式。
  9. 红色的一行：按 TX ON 发射。它显示时，您的拍发只是练习。
  10. 解码行：位于 FT8 中报文选择器所在的位置。它用绿色显示您滤波器内那个电台的文字，用红色显示您发出的内容，最新的在右边。
  11. 瀑布图上的解码文字：每个信号的文字都沿着它自己的轨迹写出，因此您可以一次读到整个波段。接收标线下方的标签显示您所在的那个电台的呼号和速度。
  12. 调谐轮：即频率刻度。沿着它滑动可移动所选的标线（标线到达边缘时也会带动电台）。在瀑布图上点按或拖动可直接移动标线。
  13. 转到频率：点按带有白色信号强度线的窄条，可输入以 kHz 为单位的频率。

发送

发报有四种方式，都使用由 WPM 设定的速度：

  • 屏幕上的电键桨，用一根或两根手指。
  • 您自己的按键：键盘按键、鼠标按键（在电脑上，左键是左桨，右键是右桨），或通过 USB 或蓝牙连接、表现为键盘的电键适配器。见电键桨和电键器。
  • 一条存储：点按它。此时再点按第二条存储，它会排队等候。发送文字期间会出现带 停止 的窄条，触碰电键桨也会停止发送。
  • 键盘（在存储列表的末尾）：输入报文并按 发送。输入框下面的一行准确显示将要发出的内容。在 Android 上，语音 可通过说话完成同样的事：说出报文，它就以莫尔斯电码发出。

在空中，无论您选择听什么样的侧音，CW 始终是边沿柔和的纯净单音。作为保险措施，电键按住 10 秒会被松开，一次发射在 3 分钟后会被停止。

在 TX OFF 下练习

底部栏显示 TX OFF 时，电键桨、您的按键、存储和键盘输入框都可以使用，但只在您的扬声器上发声。您拍发的内容会被解码并以红色显示在解码行中，这样您可以看出自己的手法是否清晰可辨。没有任何信号到达电台。做这件事根本不需要电台。

电键桨和电键器

在设置 > CW 中，键控器一节设置电键桨的行为：

  • 键控器模式：手键、Iambic A、Iambic B、两者的单指版本、Ultimatic、Bug（半自动）和 Cootie（侧摆键）。
  • 速度、Farnsworth、词间隔和严格定时（字符之间和词之间使用标准间隔）。
  • 反转左右桨：对调点和划。
  • 插入延时：您发出最后一个点或划之后，电台保持发射状态的时间。
  • 速度匹配：以您正在抄收的电台的速度发报。

桨式输入一节设置哪些东西可以当作电键桨：

  • 桨：总开关。关闭后，屏幕上没有电键桨，任何按键、鼠标按键或适配器都不能让发射机发射。
  • 屏幕桨、鼠标按键、键盘按键和外部适配器 (USB / Bluetooth)：每种来源都可以单独关闭。
  • 按键映射：默认使用一份现成的按键列表（其中包括 [ 和 ]、左右 Ctrl 键、F1 和 F2）。选择自定义后，您可以为左桨和右桨建立自己的列表：按 添加按键，再按您想用的键。已经分配给另一侧桨的键会被拒绝。

文本框打开时，只有 Ctrl 键和 F1 / F2 可作为电键桨，因此输入呼号时绝不会发出莫尔斯电码。

用适配器、键盘或鼠标拍发

发送莫尔斯电码不一定要点按屏幕。下面四样东西都可以当作电键桨，而且可以同时使用：

  • 屏幕上的电键桨，用手指操作。
  • 接在 USB 电键适配器上的真电键或真电键桨：适配器是一个小盒子或一根线，一头是接电键的插孔，另一头是 USB 插头。对手机或电脑来说，它就是一个键盘（电键的每个触点按下一个键盘按键）或一个鼠标（每个触点按下一个鼠标按键）。蓝牙适配器的工作方式相同。
  • 键盘：一个键当左桨，一个键当右桨。
  • 鼠标：它的左键和右键。

它们都遵循您选定的键控器模式和速度，并且在 TX OFF 时都可以用来练习（见在 TX OFF 下练习）。

连接适配器

  1. 把电键或电键桨插到适配器上，再把适配器插到手机、平板或电脑上。不需要安装任何东西，qFT8 也不会请求任何权限：适配器就是一个普通的键盘或鼠标。如果手机唯一的 USB 口已被收发信机占用，请使用 USB 集线器或蓝牙适配器。
  2. 打开 CW 界面，开始拍发。表现为键盘的适配器，只要发出的是下面默认列表中的按键，就可以直接使用（常见的是左右 Ctrl 键，以及 [ 和 ]）。已用原装 VBand 适配器测试过。
  3. 如果没有声音，说明适配器发出的是别的按键。进入设置 > CW > 桨式输入，在左桨（点）下按添加按键，然后闭合电键的点触点；再在右桨（划）下用划触点做同样的操作。
  4. 表现为鼠标的适配器需要屏幕上的电键桨：把鼠标指针停在左桨上，然后拍发。普通鼠标也是如此。

手键、电键桨、半自动键

无论您用什么拍发，两侧各起什么作用都由键控器模式（设置 > CW > 电键器）决定：

  • 手键：只有一个键，每个点和每个划都由您手动拍出。只有左桨一侧起作用：请把手键接到适配器的点触点上，或者把它对应的按键放进左桨（点）列表。在屏幕上，两片桨合并成一个键。
  • Iambic A 和 Iambic B：用于双桨电键。左侧发点，右侧发划，两侧同时按下则点划交替。Iambic A，单指 和 Iambic B，单指 是为屏幕准备的，屏幕中间有一块区域算作同时按下两侧桨（其宽度由中间区域（单指模式）设定）。
  • Ultimatic：与电键桨相同，但两侧同时按下时，以后按下的一侧为准。
  • Bug（半自动）：点一侧自动发出点；划一侧是手动键，按住多久就响多久。
  • Cootie（侧摆键）：两侧是同一个手动键。

按自己的习惯设置

全部选项都在设置 > CW的桨式输入一节中：

  • 桨：以下所有选项的总开关。
  • 屏幕桨和桨高度：只用真电键时，可以隐藏电键桨，给瀑布图留出更多空间；也可以把它调高一些，方便手指操作。使用鼠标时必须显示电键桨。
  • 鼠标按键：如果不希望点击电键桨有任何作用，就把它关掉。
  • 键盘按键和外部适配器 (USB / Bluetooth)：决定哪些设备可以拍发。Android 与电脑的区别见下文。
  • 按键映射：默认就是上面的表格。它下面有两个列表，左桨（点）和右桨（划）。按添加按键后，它会等您按下一个键（或闭合电键的一个触点），然后把这个键加入列表；按键旁边的垃圾桶可将其移除。第一次改动会把映射切换为自定义，它最初是默认列表的副本。改回默认不会清除您自己的列表。可以使用字母、数字、F1 到 F12、方向键、Ctrl、Shift、Alt、数字小键盘、空格、回车、Tab 以及常用的标点键。一个键只能分配给一侧桨。

键控器一节中还有两个选项：反转左右桨一次对所有输入来源对调点和划（适用于接线相反的电键桨，或左手操作的人），键控器模式已在上文说明。页面末尾的恢复默认设置会把 CW 的所有设置恢复原状，包括按键列表。

Android 与电脑

  • 在 Android 上有两个开关：键盘按键指设备自带的键盘，外部适配器 (USB / Bluetooth)指您插上或配对的任何键盘或适配器。在 Android 10 之前，所有实体键盘都算作外部设备。USB 或蓝牙鼠标可以像在电脑上一样在电键桨上使用。
  • 在电脑上，适配器只是又一个键盘，所以两者共用一个开关：键盘按键。屏幕上的电键桨用鼠标按。只有当带 CW 界面的 qFT8 窗口是活动窗口、并且没有打开任何对话框时，按键才起作用。

如果有什么不正常

  • 点和划反了：勾选反转左右桨。使用鼠标时，请确认指针在左桨上，而不是在右桨上。
  • 拍发时没有任何反应：CW 界面必须正在显示，桨和您所用来源的开关必须打开，AUTO 必须关闭（否则屏幕上会显示关闭 AUTO 以手动发射）。在电脑上，请先点击 qFT8 窗口。然后检查您的按键是否在列表中：按添加按键并拍发。如果对话框没有反应，说明适配器发出的是无法使用的按键，或者适配器没有连接好。
  • 能听到莫尔斯电码，但电台不发射：红色的一行显示按 TX ON 发射。这是练习状态。
  • 在 手键 模式下手键没有反应：它接在了右桨一侧。请把它改到左桨一侧（见上文）。
  • 拍发时字母被输入到文本框里，而没有发送：文本框打开时，只有 Ctrl 键和 F1 / F2 是电键桨，这样输入呼号时绝不会发出莫尔斯电码。请关闭文本框，或者让适配器使用这几个键之一。
  • 拍发时字符被输入到别的程序里：在电脑上，按键会送到活动窗口。请点击 qFT8。
  • 按住电键时声音中断：电键按住 10 秒会被松开，并出现提示电键按下过久：已松开。

存储、宏和勤务符号

在设置 > CW > 存储中编辑您的报文（添加存储，或点按某一条进行修改）。报文中可以使用两类特殊词：

  • 方括号中的宏在报文发出时被替换：[MYCALL] 是您的呼号，[TARGET] 是“目标”框中的呼号，[RST] 是要发出的信号报告，[NAME] 是您的名字，[QTH] 是您的位置，[EXCH] 是您的比赛交换内容，[MYPOTA] 是您当前开启的激活的公园或山峰。编辑器为每个宏都提供了按钮，并准确显示报文发出时的样子。
  • 尖括号中的勤务符号作为一个字符连续发出，中间没有间隔：<BK>、<SK>、<KN>、<AR>。

您的信号报告、名字、位置和交换内容只需在同一个设置页面中输入一次。需要其中某一项的预设报文会保持变暗，直到您填好为止；点按它会带您到填写的地方。POTA 或 SOTA 激活开启期间，第一条存储会提供一条 CQ POTA 报文。

接收

解码是自动的，并跟随每个电台自己的速度。您滤波器内的那个电台，就是底部栏解码行中显示的那个；把接收标线移到另一个信号上，就改为跟随它（该频率上已经抄收到的内容会立即显示）。滤波器内有两个电台时，底部栏会提示。接收到的信号以您选择的监听音高在扬声器中播放，与您自己的侧音音高相同，因此听起来与您的侧音同音的电台，正好在您的频率上。

设置 > CW 中还有音调（您的侧音听起来如何：音高、音量、柔和或陡峭的边沿、单音或发声器的咔嗒声）、解码与显示（自动解码、为瀑布图上每个信号显示文字的多路解码器、水平频谱图、进入该模式时的滤波器）、监听（扬声器）和勤务符号与标点。

CW 中的 AUTO

面板左上角的 AUTO 按钮让 qFT8 完成完整的 CW QSO。每次进入该模式时它都是关闭的。点按它即开启（变为绿色），再点按一次即关闭。它只在 TX 为 ON 时才会发射：AUTO 绝不会自行开启发射。

在它开启且 TX 为 ON 期间，qFT8 会：

  • 在频率空闲时呼叫 CQ，或应答它听到的 CQ；
  • 交换信号报告、名字和位置，道别，并把 QSO 记入日志；
  • 对没有抄收到的呼号或信号报告再次询问，并响应对方要求重发或放慢速度的请求；
  • 发报速度绝不超过您的 WPM，并会降到对方电台的速度；
  • 跟随频率漂移的电台，不呼叫当天已经通联过的电台，也不在别人的 QSO 上开始发射；
  • 绝不把没能完成的 QSO 记入日志。

AUTO 开启期间电键桨被禁用，并有一行文字提示 关闭 AUTO 以手动发射。停止 也会关闭 AUTO。如果您从不需要它，可在设置 > CW 中关闭显示 AUTO 模式，按钮就会隐藏。

RTTY

RTTY（无线电传）用两个交替的音调传送文字。在 qFT8 中它与 CW 共用同一个界面，只是没有电键桨：通带内的每个 RTTY 信号都会按各自的速度和频移解码，并沿着它的轨迹写在瀑布图上。

RTTY 界面的各个组成部分如下：

  1. 目标 和 交换：您正在通联的电台的呼号，以及比赛交换内容。它们会填入您报文中的 [TARGET] 和 [EXCH]。
  2. BAUD：速度：45.45（常用）、50 或 75。每点按一次切换到下一个。
  3. 频移：两个音调之间的间距：170 Hz（常用）、200、425 或 850 Hz。
  4. REV：对调两个音调，用于对方以相反方式发送的情况。
  5. FILTER 和 NR：接收滤波器和降噪。
  6. 存储：预设报文，使用与 CW 相同的宏。点按即发送。有空字段的报文会变暗。键盘（以及 Android 上的 语音）在列表末尾。
  7. 解码行：接收标线下那个电台的文字，显示为绿色；您发出的内容，显示为红色。
  8. 接收标线及其标签：标签显示标线下电台的呼号、速度和频移。在信号附近点按，标线会落到信号的中心。
  9. 点按以匹配：当标线下的电台使用的速度、频移或音调顺序与您的不同时，会有一行橙色文字提示。点按它，qFT8 就采用该电台的参数，这样您就可以应答它。
  10. 其他信号：它们的文字沿各自的轨迹写出。50 Bd 或 425 Hz 这样的橙色标签，表示该信号与您的设置不同。
  11. 频率：在 RTTY 中，顶部显示的是 mark（传号）频率，这是操作员通常报出的频率，也是写入日志的频率。

发送

先开启 TX，然后点按一条存储，或打开 键盘，输入后按 发送。文字发出期间会显示带 停止 的窄条。TX OFF 时，同样的操作只是预览：报文在您的扬声器中播放并以红色显示，不会有任何发射。RTTY 码表中没有的字符会被略去并列出。

RTTY 是满功率的连续发射，因此受电台连续发射时间上限的约束：长度超过上限的报文不会开始发送，发射在到达上限时停止。

设置 > RTTY

  • 调制解调器：速度、频移、反相、数字表（国际（ITA2） 或 美国：两者有五个符号不同，双方电台必须使用同一种），以及接收时和发送时的空格后回到字母（空格之后文字回到字母，因此丢失一次换档最多只会弄错一个词）。播发数字组的电台，例如气象台，不会在每个空格后重复换档：接收时空格后回到字母开启时，它们的数字组会显示成字母，所以要读这些内容时请把它关闭。
  • 发射：每次发射的开头和结尾换行、无内容可发时发送空闲字符，以及达到一定字符数后自动换行。
  • 解码与显示、监听（扬声器）、存储及其取值（信号报告、名字、位置、交换内容）和 恢复默认设置。

用 QSO 按钮记录的 QSO 以 RTTY 记入日志。RTTY 中没有 AUTO。

设置 > JTTY

JTTY（模式选择器中的 JTTY（实验性） 一行）使用同一个面板，配合 JTTY 调制解调器。它的设置有单独的页面，在设置列表中 RTTY 的旁边；面板运行 JTTY 时，面板的齿轮按钮会打开该页面。页面中只有 JTTY 用到的内容：解码与显示、监听（扬声器）、带数值的 存储，以及 恢复默认设置；RTTY 的 调制解调器 和 发射 设置不适用于它。第一次使用 JTTY 时，它会沿用你在 设置 > RTTY 中改过的内容（例如存储内容、姓名和位置）；你没改过的部分从 JTTY 自己的默认值开始，例如每条都能放进一条 JTTY 消息的简短存储。此后，改动其中一个不会改动另一个。

SSTV（图像）

SSTV（慢扫描电视）把一幅静止图像变成声音逐行传送，耗时一到四分钟。您处于该模式时，qFT8 会自动接收图片，并可发送您相册中的图片，图片上写有您的呼号。

用底部栏的模式选择器选择 SSTV。面板的左半部分用于发送，右半部分用于接收：

SSTV 界面的各个组成部分如下：

  1. 发送：发送图片所用的模式及其尺寸。模式用第 12 项选择。
  2. 载入：提供“选择图片”（从相册或文件）、“拍照”（在带摄像头的手机或平板上）和“现成图片”：约二十幅由 qFT8 按模式大小绘制、印有您的呼号的图画（CQ 卡片、qFT8 标志、风景、视错觉图、QSL 卡、73 等）。您也可以从其他应用把图片分享给 qFT8；如果当时正在使用别的模式，qFT8 会先询问再切换到 SSTV。
  3. 待发送的图片，按发送时的样子原样显示。点按它可让图片适配该模式的画幅：完整显示、裁剪（拖动可移动，双指捏合可缩放）、旋转，以及调整亮度和对比度。
  4. 文字样式：用箭头逐一切换把呼号写在图片上的方式（底部横条、角落、大号描边……或不写呼号）。铅笔按钮可添加自由文字。
  5. 移除 移除已载入的图片。发送 显示发射需要多少秒；发射期间它变为 停止，并显示剩余秒数。
  6. 红色的一行：按 TX ON 发送图片。其下的剩余空间排满小图片：先是您最近载入的图片，然后是现成图片。点一下就把其中一张载入为待发送的图片（在您按 发送 之前绝不会发送）。图片的形状与模式不同时，会先打开调整画幅的步骤。
  7. 接收状态：守听中，或 正在接收 并显示模式、对方电台的频率偏差以及正在绘制的行。
  8. 接收到的图片，随到随画。图片下方是时间、模式和进度；图片接收完成后，还有呼号栏。
  9. 保存 把图片存入设备的图片文件夹（图片还在接收时按下，会在接收结束后保存）。编辑 可改善接收到的图片（对比度、亮度、色彩、色调、锐化、去噪）；接收到的原图始终保留，因此每项修改都可以撤销。回复 把接收到的图片载入为待发送的图片，并在您的呼号旁边写上对方电台的呼号。
  10. 保留的图片：最近接收到的图片。点按其中一张可重新显示。
  11. 齿轮打开设置 > SSTV，QSO 打开模式为 SSTV 的记录器。
  12. SSTV 模式选择器：Martin、Scottie、Robot、PD、Wraase 和 Pasokon 各模式。它旁边的报文区域说明当前的状态（“守听中”、“正在接收”、带剩余秒数的“正在发送”）。
  13. SSTV 频段：图片在 1100 至 2300 Hz 之间发送和接收。每张听到或发出的图片都会在瀑布图上得到一个标有模式的方框。

接收图片

不需要任何设置。qFT8 根据每次发射的起始信号识别模式；图片开始之后您才调谐进来时，它也能识别（已经错过的行保持空白）。频率略有偏差的图片，或由时序略有偏差的电台发出的图片，会被自动校正。如果两个电台在明显不同的频率上同时发送，两张图片都会被接收并保留；点按瀑布图上的方框可选择显示哪一张。

应用会自动保留最近的图片。开启自动将每张接收到的图片保存到设备后，它们还会写入图片文件夹；否则由您保存想要的图片。

这是谁的图片？呼号栏

许多电台会在图片前后表明身份：在图片之前或之后用莫尔斯电码，或在图片之后发一小段数据突发。这两种 qFT8 都能读取，并把呼号写在图片下方时间和模式旁边的栏中。什么都没听到时，该栏显示 呼号未知。点按该栏可自己输入呼号（它通常写在图片上）或加以更正；您输入的内容会替换听到的内容。

保存的图片以日期和时间（UTC）、波段、以 kHz 表示的频率、模式和呼号命名，例如 2026-10-05_1431_20m_14230_M1_F4ABC.png；没有呼号时为 ..._UNKNOWN.png。如果呼号是在图片保存之后才收到或输入的，已保存的文件会被重命名，不会另存一份。

发送图片

  1. 用底部栏的选择器选择模式。如果您是回应某个电台，请使用它所用的模式。Robot 36、Martin 1 和 Scottie 1 是常用的模式。
  2. 点按 发送 下方的小图片之一，或按 载入，选取图片，如有提示则调整画幅。
  3. 用箭头选择您的呼号的显示方式。
  4. 开启 TX 并按 发送。

关闭 TX、按 停止，或更换波段或模式，都会立即停止发送图片。如果您按 发送 时正有图片在接收，qFT8 会先询问再停止接收。

长模式与小功率电台：一张图片就是一次满功率的连续发射：Robot 36 约 40 秒，Martin 1 约两分钟，最慢的模式超过四分钟。比您电台的连续发射时间上限还长的模式在列表中显示为灰色，选择它时会说明原因。QMX 在默认的 60 秒下，短模式无需更改即可使用。

设置 > SSTV

  • 用 CW 发送您的呼号：关闭、在图片之前（默认）、在图片之后，或前后都发。只发呼号，速度 20 WPM；它占用的秒数计入发射时间。
  • 每张图片后发送 FSK ID：一小段数据突发，让对方电台的程序读出您的呼号。
  • 文字样式、自动对比度和自动锐化。
  • 自动将每张接收到的图片保存到设备，以及应用中保留的接收图片数量。

QMX 或 QMX+ 需要 1_02_000 或更新的固件才能发送图片；固件较旧时，SSTV 只能接收。

功能说明

不与某一种模式绑定的设置和工具：设备配置中针对每台电台分别保存的两项设置、从另一台设备操作 qFT8 的网页、让您把电台留在另一个房间的 bridge，以及屏幕的布局。

频谱图调谐偏移

在设置 > 设备配置的调谐（此电台）下，频谱图调谐偏移可把频谱图显示的内容向下或向上移动最多 300 Hz。默认值：QMX 系列为 −100 Hz，IC-7300 为 −90 Hz，其他电台为 −50 Hz；您设置的值（包括 0）会保留，并为每台电台分别保存。

大多数电台会切掉音频的最低部分，因此频谱图最初几百赫兹内的信号很弱，甚至看不到。例如偏移设为 −100 Hz 时，qFT8 会把电台调低 100 Hz，并把音频移动相同的量，这些信号就移到了电台能听清的部分。

其他一切不变：显示的频率、各电台的频偏、spot、您的发射频率和日志都与之前完全一样。只有电台自身的显示屏读数相差一个偏移量。偏移在所有模式下都有效，并且需要 CAT 连接；使用 VOX 或扬声器时它不起作用。

连续发射时间上限

这是保护发射机的一项安全设置。小功率电台是按带间歇的短时间发射设计的：一次 FT8 发射不到 13 秒，之后至少休息 15 秒。有些模式会让电台以满功率不间断地发射长得多的时间，这可能使小功率电台的末级功放过热。连续发射时间上限是 qFT8 让您的电台一次连续发射的最长时间。

它位于设置 > 设备配置的调谐（此电台）下。可选值为 20、40、60、90、120 和 150 秒，以及不限制。qFT8 在每个选项下列出该选项新增的内容，您可以看到调高上限能得到什么。此设置为每台电台分别保存。

每种电台的默认值

  • 60 秒：QRPLabs QMX、QMX+ 和 QDX，以及 (tr)uSDX。
  • 120 秒：Xiegu X6100 和 X6200。
  • 不限制：其他所有电台，以及通过 VOX 或扬声器使用的电台（qFT8 无法知道那是哪种电台）。

这些默认值偏保守。您了解自己的电台、它的功率设置和散热情况：如果条件允许，可以更改上限。qFT8 绝不会自行调高上限。

上限的作用

  • 时长已知且超过上限的发射不会开始。这就是 WSPR 和较长的 SSTV 模式要求您调高上限的原因：一次 WSPR 发射持续 111 秒，许多 SSTV 图片需要两分钟或更长。当您选择这样的模式，或在其中按下 TX ON 时，会有一条消息告诉您它需要多少秒、您电台的上限是多少，并带有打开该设置按钮。在上限允许该模式之前，发射不会被开启。
  • 没有固定时长的发射在到达上限时停止，电台回到接收状态：TUNE、SSB（PTT 按钮、VOX 和语音存储）以及 RTTY。会有通知说明已到达上限。
  • CW 不受限制：电键只有一部分时间处于按下状态。

QMX 与 WSPR：使用 QMX、QMX+ 或 QDX 时，WSPR 需要把上限从 60 秒调高到 120 秒。为了电台的安全，qFT8 请您亲手做一次这项更改。可以考虑为 WSPR 降低电台功率：它本来就是一种小功率模式。

网络与连接

服务器会在您的手机或电脑上打开一个特定的 TCP 端口（默认 13497）。要访问它，您的设备必须能在网络上互相“看到”：

  • 本地网络：运行 qFT8 的手机或电脑，与您用来控制的设备（电脑、平板或手机）必须在同一个网络中。
  • 路由器设置：有些路由器默认开启了名为 AP 隔离（或客户端隔离）的功能。必须把它关闭，设备之间才能互相通信。
  • 手机热点的用法：在野外，您可以用一部（能上网的）手机开启 Wi-Fi 热点，再让运行 qFT8 的手机连接到这个 Wi-Fi 网络。连接之后，在 qFT8 的设置中把 Web 服务器关闭再重新打开；此时显示的 IP 地址就可以从提供热点的那部手机上访问了。
  • 通过互联网访问：要从家庭网络之外（经互联网）访问服务器，需要在路由器设置中配置端口转发（把内部 IP 和端口映射到外部）。请注意，由于运营商的 NAT 限制，这在 5G/LTE 连接上通常行不通。

访问级别

您可以在设置面板中配置远程访问的安全级别：

  • 只读：可以查看实时频谱图、活跃电台和 QSO 日志。不能执行任何操作。
  • Read + Stop TX（只读 + 停止发射）：主要是一种安全模式。可以查看所有数据，并允许在紧急情况下禁止发射（停止 TX），但不能开始发射，也不能更改设置。
  • 完全控制：授予对应用的全部控制权，所有交互功能都可使用。

安全提示：任何能访问您的网络、IP 地址和端口的人，都将拥有您所设定的控制级别。如果设为完全控制，他们就有可能用您的电台开始发射。

功能范围

在完全控制模式下，网页界面几乎提供了应用界面的全部功能：

  • 操作模式：在 AUTO 和手动 CALL 模式之间切换。
  • 策略：更改 AUTO 的条件（任何人、DXCC、网格等）和选台限制。
  • 发射：手动开始/停止 TX，选择具体的 TX 报文，并更改 FT8 序列（0/1）。
  • 频率和波段：点按网页上的频谱图可移动您的频率偏移，也可以更改当前的波段。

SSB、CW、RTTY 和 SSTV 要在 qFT8 本身中操作。应用处于其中某个模式时，网页显示瀑布图以及应用是否正在发射，但网页本身不发射；在页面上选择一种数字模式，即可重新从页面操作。

电台的连续发射时间上限对页面与对应用完全一样有效。当它使 TX 保持关闭（例如上限为 60 秒时的 WSPR）或停止 TUNE 时，页面会显示几秒钟的通知说明原因，免得您面对一个毫无反应的按钮不知所措。上限本身只能在应用中更改。

注意：即使手机屏幕因射频干扰而变得迟钝，网页界面仍能保持灵敏，因此是一个可靠的备用控制手段。

注意：如果开启了后台运行的相关设置，屏幕关闭时 Web 服务器仍会工作（默认情况下，qFT8 连接着收发信机时会保持在后台运行）。

qFT8 bridge

qFT8 bridge 让您把电台留在一个地方，而在另一个地方操作。电台旁边的一台设备，也就是 bridge，通过您自己的网络把电台的命令和音频传给另一台设备上的 qFT8。其余的一切都由那个 qFT8 完成：解码、记录日志、决定发送什么。对它来说，电台就像用 USB 直接连接一样工作。

当电台放在天线附近，比如阁楼、车库或花园小屋里，而您想在更舒适的地方操作时，就可以使用它；或者当电台旁边的设备只需要照看电台时也可以：比如 Raspberry Pi 这样的小电脑，或一部旧手机、旧平板。

这与远程控制 Web 服务器不同。那里 qFT8 在电台旁边运行，您从浏览器查看它。使用 bridge 时，qFT8 在您面前的设备上运行，只有电台在别处。

您需要什么

  • 电台旁边的一台设备，电台像平常一样用 USB 连接到它：一台运行 Windows、macOS 或 Linux 的电脑（Raspberry Pi 就够了），或一部 Android 手机或平板。这台就是 bridge。
  • 您用来操作的设备上的 qFT8：电脑程序或 Android 应用。任何一个都可以使用任何一个 bridge：手机可以操作电脑旁边的电台，电脑也可以操作手机旁边的电台，依此类推。
  • 两者在同一个局域网中。网线和 Wi-Fi 一样能用，而且更稳定；如果可以，至少给 bridge 接上网线。手机或平板使用它的 Wi-Fi，绝不使用移动数据。
  • bridge 的密码。bridge 会生成一个密码并显示给您。

设置 bridge

运行 bridge 有两种方式，任选其一。

1. 在 qFT8 的设置中（电脑程序或 Android 应用）。在电台旁边的设备上，打开 设置 > qFT8 BRIDGE，勾选作为 qFT8 bridge 运行，端口。除非有其他程序占用该端口，否则保持端口不变。

密码显示另一台设备需要的密码。新密码生成另一个密码；点按密码本身可以输入您自己的密码（7 个字符或更多）。

作为 bridge 时，该设备上的 qFT8 不做其他任何事。TX 被关闭，它自己对电台的使用停止，屏幕上只显示qFT8 正以 bridge 模式运行，以及要在另一台设备上输入的 地址和密码，还有谁在使用电台（没有设备连接，或该设备的名称）。在 Android 上，bridge 在屏幕关闭时也会继续运行，并以一条通知显示；请让手机或平板保持充电。

关闭 BRIDGE 模式会先询问，因为另一台设备会立即失去电台，然后把 qFT8 恢复成原来的样子，TX 仍然关闭。如果您在 qFT8 作为 bridge 时关闭它，下次它仍会以 bridge 方式启动。

2. 从命令行运行（仅限电脑）。适合没有其他用途的电脑，也适合 Raspberry Pi 或没有屏幕的服务器：用 --bridge 启动 qFT8。这样它只作为 bridge 运行，没有窗口，也不加载 qFT8 的其他任何部分（没有设置，没有解码），因此只需要很少的内存。在终端中使用您为这台电脑下载的 qFT8：

  • Windows：在 qFT8 文件夹中打开命令提示符，输入 qFT8.exe --bridge --tx-volume 70。如果 Windows 询问是否允许“OpenJDK Platform binary”访问您的网络，请允许。
  • macOS：在“终端”中输入 /Applications/qFT8.app/Contents/MacOS/qFT8 --bridge --tx-volume 70。第一次时 macOS 会请求麦克风权限：请允许，电台的音频就是这样读取的。
  • Linux：在 qFT8 文件夹中输入 ./qFT8 --bridge --tx-volume 70。
  • 任何装有 Java 21 或更新版本的电脑，例如使用系统自带 Java 的 Raspberry Pi：qFT8 的 .jar 下载版可在所有系统上运行。输入 java -jar、.jar 文件名和 --bridge。它自带在 Windows、macOS 和 Linux（PC 和 ARM 开发板，32 位和 64 位）上使用串口所需的一切。

终端在第一次启动时显示密码，并为以后的启动保留它。请让终端保持打开：终端开着，bridge 就一直运行。 Ctrl+C 或关闭终端会停止它，并让电台回到接收状态。

可能用到的选项，加在 --bridge 后面：

  • --tx-volume N: 必需:网桥在发射时为电台的声音设备设置的音频电平(1 到 100 %),与 qFT8 自己的 TX 音量设置相同(默认 70;QRP Labs 电台:100)。这只是声音电平:电台的功率从不改变。
  • --password TEXT：使用您自己的密码，而不是它生成的密码。
  • --show-password：再次显示保存的密码。
  • --new-password：生成一个新密码。
  • --name TEXT：其他设备在列表中看到的名称（否则为“qFT8 bridge”），有多个 bridge 时很有用。
  • --only TEXT：只共享电台的串口和声音设备，用其名称的一部分指定（例如 --only QMX）；电脑上的其他任何东西都不提供。

--bridge --help 列出其余选项。

从 qFT8 连接

在您用来操作的设备上，打开设置 > 设备配置，勾选最上面的 通过 qFT8 bridge 连接。会出现以下各行：

  • 方式：qFT8 bridge。
  • Bridge：打开 qFT8 在您的网络中找到的 bridge 列表。选择您的那一个。 重新搜索会再找一次。如果列表中没有您的 bridge，请选择输入地址，然后输入 bridge 显示的地址。
  • 密码：bridge 显示的那个密码。
  • 连接：旁边的方框变成绿色，显示已连接到，后面是 bridge 的名称。
  • bridge 上的电台端口、bridge 上的声音设备（接收）和 bridge 上的声音设备（发射）：电台在 bridge 一侧接在什么上。 AUTO 会自动找到它们；只有当 bridge 上有多个时才需要手动选择。通过 bridge 电脑上自带的程序访问的电台（虚拟串口和虚拟音频线）所用的端口，AUTO 无法识别：请手动选择端口，并确认两个声音设备都是那条音频线的。

此后一切都和 USB 连接的电台一样：qFT8 识别电台、读取频率、接收和发射。qFT8 会记住 bridge 及其密码，导出设置时也会把它们带到您的其他设备上。方框勾选期间，接在您操作设备上的电台不会被使用。要改回使用它，取消勾选通过 qFT8 bridge 连接即可，无需重启。

在手机或平板上，如果设备没有连接 Wi-Fi 网络，状态框会显示没有 Wi-Fi。请将此设备连接到 bridge 所在的网络。因为只会在那里寻找 bridge。

链路显示

在 bridge 的设备下方，有一行告诉您链路的情况，例如 延迟 120 ms，自动调整。链路：平稳（抖动 3.0 ms）。

  • 延迟：网络传送声音从来不是完全均匀的，所以音频在播放前会先保留片刻，把不均匀抹平。这里没有需要设置的东西：qFT8 和 bridge 自己选择延迟，音频迟到时加大它，链路干净一段时间后再减小。它不会打乱数字模式的时序：您的发射仍然准时开始，接收到的内容按电台听到它的时刻定位。
  • 链路：平稳：一切正常。
  • 链路：不稳定：音频到达得不均匀。延迟会处理这个问题；除非一直这样，否则无需做什么。
  • 红色的到 bridge 的链路正在丢失发射音频：一次发射的一部分没有及时到达电台。延迟会立即加大；如果反复出现，请参阅故障排除。
  • 红色的到 bridge 的链路跟不上：即使最大的延迟也不够，发射音频断断续续。请参阅 故障排除。

发射安全

  • 只有您能打开 TX，用您面前 qFT8 的 TX 按钮。bridge 从不自行开始发射。
  • 如果链路中断（Wi-Fi 断开、设备休眠、qFT8 被关闭），bridge 会在一两秒内自行让电台回到接收状态。qFT8 停止正在发送的内容，关闭 TX，并显示一张说明原因的红色卡片，例如连接已断开。正在重新连接...它会自行重新连接。如果链路在 10 秒内恢复，而您原来开着 TX，qFT8 会按您原来的状态重新打开它一次；中断时间更长时，它保持关闭，直到您再次按下。
  • 电台的连续发射限制同样由 bridge 执行。
  • 无论用哪种方式停止 bridge，都会让电台回到接收状态。

安全提示：密码保护的是对电台的控制：没有密码的人无法使用 bridge，而且密码本身从不通过网络发送。它并不能让链路保密：音频和电台的命令都没有加密。只在您自己的网络内使用 bridge，不要把它开放到互联网。

限制

  • 仅限局域网。bridge 不是为通过互联网访问而设计的。如果 VPN 把您家庭网络的流量送入它的隧道，也会把 bridge 隐藏起来：请在两台设备上关闭它，或在其中允许访问本地网络。
  • 同一时间只能一台设备。第二台设备连接时会接管；第一台设备显示 另一台设备接管了 bridge。按“连接”把它拿回来。
  • 所有模式都可以通过 bridge 工作，接收和发射都可以： FT8、FT4、 FT2、JS8、 WSPR、LQ8、 SSB、CW、 RTTY、SSTV 和 TUNE。您的扬声器和麦克风留在您面前的设备上；只有电台的音频经过网络。
  • 通过控制线（RTS 或 DTR）而不是命令切换到发射的电台，同样可以通过 bridge 键控。

qFT8log

qFT8log 通过您自己的网络，把多个 qFT8 的日志合在一起。其中一个 qFT8 是 qFT8log 服务器；其他的把它们做的每个 QSO 发给它。服务器把这些 QSO 加入自己的日志 （QSO 列表、地图、统计），并转发给在它上面设置的服务，例如 QRZ 和 LoTW。之后发生在 QSO 上的事，比如确认或更正，只要两者保持连接， 就会回到做这个 QSO 的那个 qFT8。

任何一个 qFT8 都可以同时是服务器和客户端：电脑程序、Android 应用和 iPhone 应用。在 Android 上， 当在后台运行开启时，服务器会在后台持续运行；在 iPhone 上，它只在应用打开时运行。

设置服务器

  1. 在要收集 QSO 的那个 qFT8 上，打开设置，进入 qFT8 服务器，再打开qFT8log 服务器。
  2. 输入密码。使用与 qFT8 bridge 相同类型的密码：七个字符或更多。
  3. 除非端口被其他程序占用，否则保持端口为 13510，然后启用服务器。页面会显示服务器的地址和连到它的 qFT8。更改端口后立即生效。
  4. 在浏览器中打开同一个地址（例如 http://192.168.1.20:13510/），输入服务器的密码后 （密码绝不会被发送），就能以只读方式看到日志：参见 在浏览器中查看日志。

设置客户端

  1. 在每个要发送 QSO 的 qFT8 上，打开设置，点顶部 qFT8log 旁边的齿轮。
  2. 点查找：您网络中的 qFT8log 服务器会按名称列出。选择其中一个， 或者自己输入服务器的地址和端口。
  3. 输入服务器的密码，点验证。服务器接受之后， 在设置顶部勾选 qFT8log。

从此以后，客户端每次启动时会自动连接，并在网络或服务器恢复时自动重新连接。服务器无法连接期间做的 QSO 会留在日志中等待（它们显示为未上传到 qFT8log），连接恢复后立即发送，重启之后也一样。当客户端无法连接到服务器时， 设置中的 qFT8log 一行会变红，并显示自 (时间) 起无法连接。

对 qFT8log，上传到此处即视为 QSO 已上传默认是关闭的。当服务器就是您的 QSO 要去的地方时请勾选它， 这样一旦服务器收到某个 QSO，该 QSO 的“等待上传”标记就会消失。

传输的内容

  • 新的 QSO，从客户端到服务器，包含 qFT8 保存的每个字段： 报告、网格、公园和山峰、设备、备注，以及该 QSO 是否已上传到 QRZ、LoTW 或其他服务或已被它们确认（从 LoTW 导入的 QSO 保持已确认）。
  • 确认，双向，一收到就传：服务器从 LoTW 收到的确认会显示在做这个 QSO 的客户端上， 反过来也一样。
  • 在 QSO 编辑器中做的更正，双向。当同一个 QSO 在两边都被修改时，较晚的修改生效。
  • 删除绝不会传播。删除 QSO 只会在那台 qFT8 上删除；其他的仍保留。每台 qFT8 都会记住在它上面删除的 QSO，并且绝不会从另一台 qFT8 把它们取回，无论是通过导入还是实时同步。

服务器接收每种模式、每个呼号的 QSO：它是您收集的地方，由日志的筛选器决定您看到什么。服务器已经有的 QSO （相同的呼号、时间、波段和模式）会合并到它已有的那个中，绝不会重复添加，也不会再次转发。

从服务器导入与实时同步

客户端只发送自己的 QSO。有两种方式可把服务器的日志也带给它：

  • 客户端 qFT8log 页面上的从服务器导入 QSO会一次性复制服务器上位于从、到、波段和呼号开头为范围内、所有模式的全部 QSO。用您以外的呼号进行的 QSO 会被跳过，除非勾选了导入当前呼号以外其他呼号的 QSO。当设置顶部未勾选 qFT8log 时它也能工作：此时导入只为自己连接，不发送任何内容。
  • 与此服务器实时同步（需要在设置顶部勾选 qFT8log）：服务器的 QSO 会来到这里，此后在服务器上或连接到它的任何其他 qFT8 上记录、更正或确认的每个 QSO 都会立即出现在这里，您的 QSO 也会发送过去。多台勾选此框的 qFT8 通过各自的服务器共享同一份日志；对于链式连接，则通过链上的每台服务器共享。
  • 连接断开时不会丢失任何内容：恢复后各方会补齐，重启之后也一样。
  • 更正时间以服务器的时钟为准，因此时钟不准的设备不会赢得或输掉每一次更正。

链式连接：收集与备份

一个服务器自己也可以是另一个服务器的客户端，因此 qFT8 可以串成链。QSO 绝不会被发回给它已经经过的 qFT8， 所以即使 qFT8 连成环也不会循环。两个例子：

  • 一个负责上传的地方。手机和便携电脑把 QSO 发给电台房间里的电脑。只有这台电脑设置了 QRZ 和 LoTW：它上传所有 QSO，它收到的确认会回到做每个 QSO 的那个 qFT8。
  • 备份。电台房间里的电脑还会把所有内容发给另一个 qFT8，比如一台只保存日志并显示世界地图的 旧平板。备份上除了它的服务器，什么都不用设置。

安全提示：密码绝不会通过网络发送：两个 qFT8 互相证明自己知道密码， 之后的每条消息都经过签名，因此途中不可能被篡改或重放。QSO 本身没有加密。 请只在您自己的网络内使用 qFT8log，不要把它的端口开放到互联网。

限制

  • 仅限家庭网络，与 qFT8 bridge 相同。
  • 两个 qFT8 必须运行相同的 qFT8log 版本。服务器会拒绝其他版本的客户端， 客户端的那一行会说明应更新哪一个。
  • 每个服务器同时最多 16 个客户端。
  • 服务器无法读取的 QSO（例如没有日期的）会在客户端上标为已被拒绝，只有在您更正之后才会再次发送。

qFT8log 协议（版本 2）

这是对两个 qFT8 之间相互传递内容的完整描述。所有数字都是大端序。文本为 UTF-8。

查找服务器

客户端向其各个网络的广播地址、端口 13510 发送一个 UDP 数据报： "qFT8L?"（6 字节）、API 版本（2 字节）、一个随机 id（8 字节）。每个服务器 向发送者回应："qFT8L!"、它的 API 版本（2）、相同的 id（8）、它的 TCP 端口 （2）、它的实例 id（16 个 ASCII 十六进制数字）、它的名称长度（1）和它的名称（最多 64 字节）。这个回应不含任何机密。

帧

通过 TCP（默认端口 13510），一切都以帧传输：类型（1 字节）、正文长度（3 字节）和正文（最多 16384 字节）。 前四种类型在密钥建立之前传输；其他每个帧的正文都是密封的：一个 8 字节计数器、消息， 以及对类型、计数器和消息计算的 HMAC-SHA256（该方向的密钥）的前 16 字节。 每个方向都从 0 开始计数，帧必须恰好带有下一个编号：被改动、重复或丢失的帧会使连接结束。

正文 已发送 QSO (4)，对方新增 (4)，对方合并 (4)：订阅所要求的每个 QSO 都已发送

握手

双方都知道 k = PBKDF2-HMAC-SHA256(密码, 盐, 轮数)，32 字节。服务器 选择盐和轮数（200000；客户端拒绝少于 10000 或多于 5000000 的值）。会话记录 t 是 HELLO 正文，后面接不含其证明的 CHALLENGE 正文。 令 L = ASCII 文本 "qFT8 log v1 "：

  • 服务器证明 = HMAC-SHA256(k, L + "server proof" + t)；客户端证明 = HMAC-SHA256(k, L + "client proof" + t)；
  • 客户端到服务器的密钥 = HMAC-SHA256(k, L + "key client>server" + t)；服务器到客户端的密钥 = HMAC-SHA256(k, L + "key server>client" + t)。

客户端先检查服务器的证明，如果不对就不作回应直接关闭， 这样由密码派生出的任何内容都不会发给不知道密码的服务器。服务器检查客户端的证明； 错误的证明会把该地址锁定 1 秒，之后每连续错误一次就加倍，最多到 60 秒。 两个随机数每次连接都是新的，所以录下来的握手毫无用处。API 版本必须相同：服务器以原因 1 拒绝任何其他版本， 客户端也拒绝其他版本的 CHALLENGE。服务器允许同时进行 8 个握手，每一步 5 秒， 最多 16 个客户端；重新连接的客户端会接替它原来的连接。

记录

QSO 记录是一个 JSON 对象，字段名是 qFT8 所存储的（call、 qso_date（格式 YYYYMMDD）、time_on（格式 HHMM 或 HHMMSS）、band、 mode、submode、rst_sent、rst_rcvd、 gridsquare、freq、station_callsign、 my_gridsquare、comment、公园和山峰的引用、QRZ 和 LoTW 的状态 app_qrzlog_logid、app_qrzlog_status、 app_lotw_qsl_rcvd、app_lotw_logid、app_lotw_upload_time，以及 app_svc），最多 16000 字节。call、qso_date 和 time_on 是必需的；任何模式和任何呼号都会被接受。app_svc 保存其他服务的状态和协议本身的三类记录，格式为 id:key=value,... 的各部分，用 ; 分隔：

  • q8u：id = QSO 的 uid（由最先发送它的那个 qFT8 一次生成， 在所有更正中保持不变），t = 其内容最后一次被更正的时间（UTC 毫秒， 缺失 = 从未）；
  • q8v：id = 该 QSO 经过的实例 id，用点分隔 （最多 32 个）；
  • 发送方会省略它自己的簿记信息：它针对每个对端的哈希、它自己的上传状态和它的本地工作标记。

哈希与合并

QSO 的哈希是 SHA-256 的前 8 字节，以 16 个十六进制数字表示，计算对象是其内容、更正时间以及上传和确认状态的 name=value 各行（不包括它经过的实例）。同一个 QSO 的两份副本在任何地方都以相同的方式合并成一份： 较晚被更正的那份副本的内容整体胜出（时间相同时：内容哈希较大的胜出）； 上传和确认状态只会向前推进（确认绝不会被撤销）； 实例取两者的并集。合并与顺序无关，合并两次也不会有任何改变，所以所有副本最终都相同。

谁发送什么

  • 客户端向其服务器发送每个尚未经过该服务器的 QSO，以及两者此前交换过、但其哈希此后已改变的每个 QSO。
  • 服务器会把两者此前交换过且哈希已变化的 QSO（确认、更正）发送给客户端。SUBSCRIBE 之后，它还会把自己日志中位于订阅范围内、两者从未交换过且没有经过该客户端的每个 QSO 发送给该客户端，然后发送 BACKLOG_DONE。使用 live 时，只要连接保持，它就会对之后收到的每个 QSO 继续这样做（每次重新连接后客户端会重新订阅）；once 以 BACKLOG_DONE 结束；off 结束订阅。
  • 接收方通过 uid 找到自己的副本，否则通过呼号、日期、时间 (HHMM)、波段和模式。服务器添加自己没有的 QSO；客户端只添加位于它所发订阅范围内的 QSO。双方都不会添加在自己这里已删除的 QSO（两种情况下结果均为 3）。否则副本会被合并；ACK 携带接收方的哈希，并且当合并后的副本与所发送的不同时，还携带合并后的记录，发送方再将其合并。
  • 每一方针对每个 QSO 和每个对端记住双方最后一致同意的哈希，只有当自己的副本与之不同时才再次发送。 删除从不发送。
  • 最多可以有 16 个 PUT 在等待应答。服务器接收每个客户端每秒 100 个 PUT（突发 200 个）， 超过时回复 NACK 2；遇到 50 条它无法读取的记录后，它会结束连接。
  • 一方在 15 秒内没有发送任何内容时发送 PING，在 45 秒内没有收到任何内容时结束连接。客户端以 1 秒、2 秒、4 秒 …… 直到 60 秒的间隔重新连接。

屏幕布局

本手册中的截图显示的是默认布局：横屏，频谱图在左。在 Android 应用中，可通过设置 > 应用 > 用户界面更改（电脑程序没有这些设置，它有自己的布局，见屏幕布局与布局按钮）：

  • 屏幕方向：横屏、竖屏或跟随手机。竖屏时频谱图在上，选项卡在其下方；在手机上，底部栏占两行。
  • 分隔条：拖动频谱图和选项卡之间的细线，可以给其中一方更多空间。每种屏幕方向各自记住自己的位置。

  • 应用覆盖：让 qFT8 绘制到导航栏、摄像头区域和状态栏上，以获得稍多一点的空间。

报告问题

“设置”选项卡底部的 报告错误 会打开一张卡片，您可以在其中描述出了什么问题；如果希望得到答复，请留下您的电子邮件。按 发送 会把您的描述连同应用的运行日志一起发送：设置、电台和音频的详细信息，以及最近的活动。密码、API 密钥、证书和您各项 QSO 服务的登录信息绝不会包含在内。您会得到一个类似 QFT8-7K3P9 的编号，供日后引用。如果连接不上报告服务器，qFT8 会提出改用电子邮件发送报告。

“要就此发送报告吗？”

当 qFT8 发现自己曾短暂停止响应，或者解码在您的设备上耗时过长时，可能会显示一张小卡片，询问是否就此发送报告，上面有 发送、不发送 和 不再询问。没有您的点按，绝不会发送任何内容。这张卡片每天最多出现一次，不再询问 会让它一周内不再出现。发生崩溃后，qFT8 会在下次启动时询问是否发送崩溃报告。

启动时检查新版本

勾选此项后（“设置”主页面，靠近底部），qFT8 会在启动时查找更新的版本，有新版本时显示带下载按钮的通知。它绝不会自行更新。

匿名性能摘要

发送匿名的每日性能摘要（“设置”主页面，就在“语言”上方）在您开启之前是关闭的。开启后，qFT8 大约每周一次发送一份简短摘要，说明它在您设备上运行得有多快：启动时间、画面流畅度、解码时间、音频和电台时序，以及设备型号和屏幕。其中绝不包含您的呼号、网格、日志、设置或任何能识别您身份的信息。它有助于让 qFT8 在与您类似的设备上运行得更快。

故障排除

手机或电脑无法识别收发信机，或连接中断

这几乎总是硬件连接问题或射频干扰问题。USB 连接对振动、线缆质量以及安家在手机 USB 口里的绒毛团都很敏感。在 Android 上，另一个常见原因是您的设备可能默认关闭了 USB OTG（特别是 qFT8 能收到信号却无法发射，而且即使设备完全受支持、出现在设备下拉列表中、在 AUTO 模式下被自动识别等等，CAT 命令也不起作用时，原因很可能就在这里）。

请尝试：

  • 在 Android 上，在设备的系统设置中打开 USB OTG（有些设备默认关闭 OTG，该选项可能在高级设置、系统设置或更多设置里）。
  • 使用质量好的短 USB 线（换一根更短的线往往大有帮助），并确认 USB 口干净、插接牢固。
  • 在 Linux 上，如果 qFT8 提示没有权限打开电台的端口，请接受它提出的修复办法（把您的账户加入该端口所在的用户组），或咨询您的系统管理员。
  • 如果问题只在发射时出现，可能是射频干扰造成的。在 USB 线上加扼流圈或磁环可能有帮助。您也可以换一个波段发射试试，因为有些设备只对某些波段的干扰敏感。

手机充满电后收发信机消失（Android）

这种情况出现在带充电输入口的 USB OTG 转接器上，这类转接器可以在连接收发信机的同时给手机充电。其中有些转接器，在电池充到 100% 时手机会断开与收发信机的 USB 连接，并且在拔掉充电器之前一直不恢复。这时 qFT8 显示收发信机已断开，什么都无法工作：没有音频，没有 CAT。

请尝试：从转接器上拔掉充电器（收发信机会重新出现），不充电操作，或者换用其他转接器或带供电的集线器。

qFT8 bridge：“此网络中未找到 bridge”

qFT8 询问了网络，但没有 bridge 应答。常见原因是 bridge 没有运行、两台设备不在同一个网络中（访客 Wi-Fi 算作另一个网络），或者两者之间有东西挡住了询问。

请尝试：

  • 检查 bridge 是否在运行：它的窗口是打开的，或者那台设备上的 qFT8 显示 qFT8 正以 bridge 模式运行。然后点重新搜索。
  • 选择输入地址，输入 bridge 显示的地址。搜索找不到的 bridge，直接按地址连接时往往仍会应答。
  • 在 bridge 所在电脑的防火墙中放行它：TCP 和 UDP 端口 13498，以及 UDP 端口 13499（搜索使用的端口）。
  • 在路由器中关闭 AP Isolation（或 Client Isolation），与 远程控制 Web 服务器相同。
  • 在两台设备上关闭 VPN，或在其中允许访问本地网络。把所有流量送入隧道的 VPN 会把 bridge 隐藏起来，即使两台设备就放在一起。

qFT8 bridge：“密码错误”，或 bridge 拒绝连接

密码必须与 bridge 显示的完全一致。bridge 生成的密码只有小写字母和数字，从不包含容易混淆的 i、l、o、0 和 1。连续几次输错后，bridge 会让该设备等待一段时间才能再试，最长一分钟。

请尝试：在 bridge 上重新查看密码：在 qFT8 的 bridge 模式屏幕上，或者用 --show-password 启动 bridge 下载版。如有疑问，生成一个新密码（新密码，或 --new-password）并输入它。

qFT8 bridge：已连接，但没有电台或没有声音

链路正常，但 bridge 无法使用电台的端口或声音设备。方框可能显示已连接到 bridge 的名称，后面跟着“但无法打开它的声音设备”。

请尝试：

  • 手动选择bridge 上的电台端口和两个声音设备行，而不是 AUTO。
  • 关闭 bridge 设备上其他所有使用电台的程序，包括不处于 bridge 模式的 qFT8。
  • 在 macOS 上，在系统设置 > 隐私与安全性 > 麦克风中允许 bridge 使用麦克风。
  • 在 Linux 上，确保运行 bridge 的账户可以使用串口（通常是加入 dialout 组）和声音。
  • 在 Android bridge 上，当 Android 询问时允许 qFT8 使用电台，就像电台直接插在这部手机上一样。

qFT8 bridge：“到 bridge 的链路正在丢失发射音频”或“跟不上”

两台设备之间的网络太不均匀：发射音频到达得太晚，来不及播放。只要延迟还能加大，qFT8 就会加大它，并提示链路正在丢失音频；当最大的延迟也不够时，它会提示链路跟不上，发射会断断续续。这是网络的问题，不是电台的问题。

请尝试：靠近 Wi-Fi 接入点，用网线连接 bridge（或两台设备），并暂停其他占用网络的活动。

qFT8 收到的不是收发信机的信号，而是麦克风的声音

在 Android 上，这表明手机正在使用内置麦克风，因为它没有把收发信机识别为外部音频源。在电脑上，请检查“设置”的设备配置中选择的是哪个输入：选择收发信机的音频设备。最常见的原因是：

  • USB 线不支持数据传输（只能充电的线）。
  • USB 转接头（OTG）有故障或不兼容（Android）。
  • 线插反了（有些线是有方向的）。

请尝试：换一根 USB 线、换一个转接头，或者把线的两端对调。

电台的刻度与 qFT8 显示的频率不一致

电台自己的显示与 qFT8 显示的频率相差几 Hz 到约 100 Hz。这通常是频谱图调谐偏移，而且是有意为之：qFT8 会把电台调得略低一些，并把音频平移相同的量，这样频谱图最底部的信号就离开了电台低音频的盲区。解码结果、spot、日志以及 qFT8 显示的频率仍然是真实频率。

请尝试： 这不是故障，无需处理。默认值因电台而异（QMX 系列为 −100 Hz，IC-7300 为 −90 Hz，其他电台为 −50 Hz）。要更改或设为 0，请打开 设置 > 设备配置 > 调谐（此电台） > 频谱图调谐偏移（参见 频谱图调谐偏移）。

完全收不到信号；瀑布图一片漆黑

如果不论收发信机接上还是断开，瀑布图都完全是黑的，很可能是 qFT8 没有获得访问音频所需的权限。

请尝试：在 Android 上，进入手机的设置 > 应用 > qFT8 > 权限，确认使用 qFT8 时允许麦克风（或录音）。或者彻底卸载并重新安装 qFT8，并在首次启动时接受所有权限提示。在 macOS 上，打开系统设置 > 隐私与安全性 > 麦克风并允许 qFT8。在任何电脑上，都请检查设备配置中选择的输入。

看得到信号，但解不出报文

如果您在瀑布图上看到竖直的“扭动的线条”（FT8 信号），电台选项卡里却没有文字出现，可能是您的时钟没有同步。

请尝试：

  • 确认可以上网，然后重新打开应用，以触发一次 NTP同步。
  • 如果没有互联网，请尝试 GPS 同步（Android）。
  • 如果这也不行，但在频谱图上能看到报文的单音，请在“时间和位置”设置菜单中触发“从消息紧急同步”。
  • 确认您的电台确实从空中收到了信号。

如果瀑布图上完全没有扭动的条纹，可能是波段没有传播，或者天线没有接上/没有调谐。

报文解码得太晚

手机（或较旧电脑）的处理器可能太慢，无法及时解码报文。

请尝试：务必在设置中切换到 Fast decode（快速解码），也可以把解码时刻提前（例如提前到 13000ms），给解码留出更多余量，代价是每个周期可能漏掉一些发得较晚的报文。

QMX 收发信机出现错误 “驻波比超限 — 发射已停止”

如果 qFT8 在发射时显示 0W，有几种可能的原因：

1. SWR 保护

如果 QMX 的 LCD 显示屏在频率后面显示“S”，说明 SWR 保护已经动作。这表示您的天线在当前波段没有调谐好，QMX 为保护自身电路已停止发射。

此外，qFT8 在应用设置中还有自己的 SWR 阈值，可以调整。测得的 SWR 超过这个阈值时，qFT8 会自动停止发射，以保护您的设备。

  • 固件 1_04_004+：qFT8 会在周期结束时自动重置 SWR 保护。
  • 固件 1_03_000+：可以在 QMX 菜单中把"SWR Protection reset options"设为 Timer 或 TX->RX。这样 qFT8 就能继续工作，您不必动手去碰收发信机。
  • 旧版固件：QMX 固件早于 1_03_000 时，必须手动重启收发信机（关机再开机），或在 QMX 上进入再退出 TUNE 菜单，才能清除错误。

注意：qFT8 在发射开始 1 秒后才检查是否为 0W，以免在 QMX 功率爬升期间误报。如果 QMX 恢复正常、功率升到 1W 以上，问题提示会自动消失。

2. 固件不支持功率测量

如果 QMX 没有显示 SWR 保护已动作，并且显示发射正常，那么可能是固件太旧，不支持功率测量。QDX 这类设备同样不支持功率测量。qFT8 不知道该如何理解 0W，于是无所适从。

请尝试：如果您的 QMX 固件较旧，请更新。如果您用的是 QDX，这一点没有办法解决。

3. 音频信号没有到达 QMX

如果 QMX 在频率后面没有显示“S”图标，那么很可能只是收发信机没有从 qFT8 收到合适的音频信号。音量可能太低（信号不够）或太高（削波/失真使 QMX 拒绝该信号）。

请尝试：查看 QMX 上的信号指示。一个点表示没有音频，两个点表示有音频但不够响。进入 FT8 设置部分，把“使用电台时将系统音量设置为 [X]”调到不同的值（例如 70%、80%、90%），找出适合您设备的电平。

4. 调谐时 SWR 很低，但 SWR 保护仍然动作

这看起来是实际发射过程中，SWR 在大功率下的某些瞬间出现尖峰，从而触发了 SWR 保护。这说明天线比较挑剔（例如磁环天线）、线缆不良、接触不良，或者架设有问题。

请尝试：加共模扼流圈（例如铁氧体磁环）应该能减小共模电流。

qFT8 的 Android 通知是什么？（Android）

有了这条通知，您把应用最小化或关闭屏幕之后，qFT8 仍能继续处理音频和管理 QSO。

  • 默认情况下，接上收发信机时它会自动出现。
  • 您可以在 qFT8 的设置中关闭它，但那样 qFT8 将不再在后台工作。
  • 在通知中按停止可以完全关闭 qFT8。

屏幕关闭后 qFT8 停止工作（Android）

有些 Android 厂商的电池优化非常激进，即使您已授予最初的那些权限，后台应用仍可能被系统结束。

请再次确认已授予权限：进入手机的设置 > 应用 > qFT8 > 电池，选择“无限制”（或“不优化”）。

发射时按钮反应异常或屏幕没有反应

这是射频干扰 (RFI) 造成的。如果您的天线离手机或电脑很近，或者线缆屏蔽不良，射频能量会干扰触摸屏、鼠标或 USB 连接。

  • 提示：使用带屏蔽的 USB 线，或在线上夹一个磁环。

qFT8 看起来与本手册中的截图不一样

应用的用户界面会不时更新，所以截图之后一些细小的视觉元素可能已有变化。但是，如果界面的重要部分完全不见了，或者颜色明显不对（例如黄色进度条、序列选择器等），可能是手机系统的深色模式错误地覆盖并打乱了应用的配色。

请尝试：如果是系统的深色模式造成的问题，可以暂时关闭它，或把 qFT8 加入它的排除列表，以恢复正确的外观。

收发信机已经接上，qFT8 却显示“NO RADIO”

很可能是您没有授予 qFT8 连接收发信机的权限。有时是因为点到了权限对话框之外的地方，对话框就被关掉了。

请尝试：断开收发信机再重新接上，这应该会再次弹出提示。为方便起见，请勾选“连接 Transceiver 时始终打开 qFT8”，这样就不会再遇到这个问题。

qFT8 用英里显示距离，而我想用公里（或者相反）

这取决于操作系统的区域设置（即语言选择）。

请尝试：把该设置改为相应的国家或地区（例如“英语（美国）”显示英里，“英语（英国）”显示公里）即可。

QMX 以 >10W 发射时，qFT8 显示的发射功率很低（例如 0.1W）

这是 QMX 固件（至少到 1.03.000 为止）的一个已知缺陷。如果您使用了 2x4 改装（例如在 QMX+ 上），并且发射功率超过 9.9W，电台输出的数值格式会溢出回绕。例如 10.1W 会被收发信机通过辅助 CAT 协议报告给应用为 0.1W。

请尝试：在 qFT8 内部没有变通办法，因为应用只是原样显示它收到的值。您可以放心地忽略这个显示错误，或者把功率降到 10W 以下以保持读数准确，直到收发信机固件修复这个缺陷。

无法用分享把 ADIF 日志导出到本地存储（Android）

默认的分享方法依靠 Android 自带的分享机制导出日志。有时设备内置的分享菜单不提供直接保存到本地文件系统的选项。

请尝试：在设置中把导出方法改为本地保存。这会使用 Android 的文件选择器把文件直接保存到本地存储，不依赖分享菜单。

qFT8 有些报文解不出来

请尝试：在设置中启用深度解码。深度解码进行递归解码，在波段繁忙时能解出更多报文，代价是需要更多的处理能力。它还会去除很强电台的谐波（过激励信号在较高音频频率上留下的无法解读的副本），以便找出其下方较弱的电台。请留意频谱图：如果深度解码在您的设备上耗时过长（例如超过 1 秒），应用来不及做出决定，请关闭深度解码。

qFT8 卡死或行为异常

如果这种情况只在发射时出现，很可能是前面提到的严重射频干扰。如果在其他时候出现，请滚动到“设置”选项卡的底部并按 报告错误（见报告问题），或者使用“如有问题或错误，请向我发送电子邮件”链接。
