qFT8 是什麼？

qFT8 是一款業餘無線電應用程式，可運行於 Android 手機和平板電腦，以及 Windows、macOS 和 Linux 電腦，透過收發信機解碼和發射 FT8、FT4、FT2、LQ8、JS8 或 WSPR 數位訊息。使用同一台收發信機和同一條纜線，它還可以進行語音（SSB）、摩斯電碼（CW）、RTTY 和影像（SSTV）通聯。

兩個版本的用法相同。有差異的地方，本手冊會註明（「在 Android 上……」、「在電腦上……」）。螢幕截圖顯示的是 Android 應用程式；「點按」在 Android 上指觸控螢幕，在電腦上指用滑鼠按一下。

雖然 qFT8 對 QMX 和 ICOM 7300 提供開箱即用（隨插即用）的支援，但您也可以把它用於任何收發信機：開啟 VOX 後把手機或電腦放在喇叭和麥克風旁邊，或者使用音訊連接線。您也可以不接收發信機直接試用 qFT8：它用喇叭發射，用麥克風收聽訊號。幾台執行 qFT8 的手機或電腦離得足夠近時，可以透過聲音互相通聯。

qFT8 是一款免費應用程式，不含廣告。其原始碼的授權條款將在原始碼發布時確定（LICENSE）。

Luis Quesada Torres（HB9IPH）於 2026 年開發了 qFT8，擁有其著作權並保留所有權利。

qFT8 包含來自以下專案的部分內容：usb-serial-for-android（版權所有 © 2011-2020 Google Inc., Mike Wakerly, Andreas Butti, Kai Morich, BSD-3-Clause）、Roboto（版權所有 © 2015 Google Inc. / Christian Robertson, Apache-2.0）、Roboto Mono（版權所有 © 2015 Google / The Roboto Mono Project Authors, OFL-1.1）、Natural Earth（Public Domain）、hamradio-zones-geojson（版權所有 © 2024 HB9HIL, HA8TKS, MIT license）、Big CTY（版權所有 © Jim Reisert AD1C）以及 Eclipse Temurin / BellSoft Liberica (OpenJDK) Java Runtime（版權所有 © Oracle and/or its affiliates and other contributors，GPLv2 with the Classpath Exception）。這些第三方作者或專案均未對 qFT8 表示認可，也與 qFT8 沒有關聯。

電腦版 qFT8（Windows、macOS、Linux）

電腦版 qFT8 的功能與 Android 版 qFT8 相同：相同的模式、相同的 AUTO 和 CALL 操作、相同的日誌和服務。本節說明在 Windows、macOS 或 Linux 上使用時不同的地方：如何安裝、視窗如何排列、兩個音量滑桿、如何選擇音效裝置和電台，以及如何使用滑鼠。本手冊的其餘部分照常適用；某一部分在電腦上有所不同時，會註明（「在電腦上……」）。

安裝與首次啟動

請從 qft8.com 下載適合您系統的檔案。每個下載檔都包含一個資料夾或應用程式，內有程式本身、授權條款和本手冊。不需要另外安裝任何東西：qFT8 所需的 Java 執行環境已內含其中。

系統 Windows
下載 .zip，64 位元或 32 位元
您需要 Windows 10 或更新版本。只有在 32 位元的 Windows 上才使用 32 位元檔案。
系統 macOS
下載 .dmg，所有 Mac 共用一個檔案（Apple Silicon 和 Intel）
您需要 macOS 10.13 或更新版本
系統 Linux
下載 .tar.gz：64 位元電腦、32 位元電腦、ARM 64 位元或 ARM 32 位元（Raspberry Pi）
您需要 具有音效伺服器（PulseAudio 或 PipeWire）的桌面環境。已在較新的 Ubuntu 上測試，包括 X11 和 Wayland（透過 XWayland）。
系統 任何其他電腦
下載 .jar
您需要 Java 21 或更新版本，由您自行安裝

qFT8 需要至少有 2 個處理器核心的電腦（建議 4 個），以及至少能容納 960 x 560 像素視窗的螢幕空間。在 2 個核心上可以運作，只是比較慢：請見速度較慢的電腦。

Windows

  1. 開啟 .zip 檔，將 qFT8 資料夾拖到您存放程式的地方，例如「文件」或「桌面」資料夾。請不要直接在 zip 檔裡執行 qFT8。
  2. 開啟該資料夾，連按兩下 qFT8.exe。
  3. 第一次執行時，Windows 可能會顯示 "Windows protected your PC"。按下 More info，再按 Run anyway。qFT8.exe 已用作者的憑證簽署；Windows 對新程式的信任需要慢慢累積。
  4. 如果 Windows 詢問是否允許 qFT8（顯示為 "OpenJDK Platform binary"）通過防火牆，請只在私人網路上允許，而且只有在您使用網頁遙控或 bridge 時才需要。

macOS

  1. 開啟 .dmg 檔，將 qFT8 拖到同一視窗中的 Applications 捷徑上。然後退出 .dmg。
  2. 從「應用程式」資料夾啟動 qFT8。如果您是從 .dmg 視窗內，或從瀏覽器存放的位置啟動，qFT8 會詢問「將 qFT8 移到「應用程式」？」：請按移動（macOS 可能會像 Finder 一樣要求輸入密碼）或稍後再說。
  3. macOS 會詢問一次是否允許 qFT8 使用麥克風。請按 Allow：qFT8 就是這樣聽到電台的聲音。如果您錯過或拒絕了，qFT8 會顯示一張卡片，說明它正在等待麥克風權限；請在 System Settings > Privacy & Security > Microphone（macOS 13 及更新版本）或 System Preferences > Security & Privacy > Privacy > Microphone（較舊的 macOS）中授予權限，然後重新啟動 qFT8。

Linux

  1. 解壓縮 .tar.gz（tar -xzf qFT8-*.tar.gz，或使用檔案管理員）。會得到一個 qFT8 資料夾。
  2. 在該資料夾中執行 ./qFT8（如果您的檔案管理員可以執行程式，連按兩下也行）。第一次啟動時會將程式解壓縮到 ~/.cache/qft8，需要幾秒鐘；較新的版本會自動取代那裡的舊版本。
  3. 電台的序列埠（CAT）屬於某個群組：在 Ubuntu、Debian 和 Fedora 上是 dialout，在 Arch 上是 uucp。其 USB 音效卡屬於 audio。如果您的帳號不在該連接埠的群組中，qFT8 會用一張卡片告訴您：立即修復會將您加入該群組（會要求輸入密碼）並重新啟動 qFT8，因此不必登出就能使變更生效。如果這樣不行，在終端機中嘗試和複製命令會給您一個命令，讓您自己執行；之後請登出再重新登入一次。

首次啟動

qFT8 會像在 Android 上一樣要求輸入您的呼號（見輸入呼號）。輸入之後，會開啟一張名為裝置設定的卡片：先選擇電台，再選擇與它相連的音效裝置。輸入下方的瀑布圖顯示電台正在送來的內容：電台開機時，您應該會看到雜訊或信號。您隨時可以用底部列中齒輪右側的按鈕開啟同一張卡片，瀑布圖上紅色的無音訊標記也可以開啟它。請見音效裝置與電台的連線。

相同之處與不同之處

所有操作方面的內容都相同：您的第一個 QSO、數位模式、AUTO、CALL、日誌、ADIF、QRZ、LoTW 和其他服務、SSB、CW、RTTY、SSTV、發射上限以及安全規則：qFT8 啟動時 TX 一律是關閉的，只有 TX 按鈕才能將它開啟，而且 qFT8 絕不會更改您電台的發射功率。本手冊中的截圖顯示的是 Android 應用程式；「點一下」在電腦上就是用滑鼠按一下。不同之處如下：

螢幕
Android 單一畫面：頻譜圖和一個頁籤；螢幕方向和四分割畫面在「設定」中
電腦 三種版面配置，用版面配置按鈕選擇：全部放在一個視窗中、像手機一樣並排，或每個窗格各自一個視窗。 詳情
音量
Android 手機的音量，以及「設定」中的「發聲音量」和「發射時設定系統音量……」
電腦 底部列中的兩個滑桿：音效裝置本身的音量和 qFT8 的音調音量。qFT8 絕不會自行更改裝置音量。詳情
音效裝置
Android 手機本身的，或電台的 USB 音效卡
電腦 在裝置設定中選擇：電台和您（操作員）。 詳情
電台連線
Android USB，會出現權限對話方塊
電腦 序列（COM）連接埠；沒有對話方塊，但在 Linux 上需要群組，在 macOS 上需要麥克風權限。 詳情
輸入
Android 觸控：點一下、長按、滑動
電腦 滑鼠：按一下、按右鍵、滾輪。鍵盤不能操作控制項。 詳情
設定與資料
Android 在應用程式內
電腦 在您使用者資料夾內的一個資料夾中；與 Android 使用相同的設定檔。 詳情
背景執行
Android 前景服務、螢幕關閉、省電
電腦 這些都沒有：視窗開著時就會持續執行。速度較慢的電腦有自己的模式。 詳情
更新
Android Google Play
電腦 一則附有下載按鈕的通知；由您自己更換程式。 詳情

螢幕版面配置與版面配置按鈕

底部列最右端的按鈕就是版面配置按鈕。每按一下，版面配置就切換到下一種：浮動，然後固定，然後一體式，然後再回到浮動。按鈕上的圖示顯示您目前所在的版面配置（螢幕閱讀器會唸出它的名稱，例如「版面配置：固定」）。qFT8 會記住下次啟動時使用的版面配置，並且分別記住每種版面配置中每個視窗的大小和位置。

  • 一體式（qFT8 第一次啟動時使用的版面配置）。一個視窗，分成四個相等的部分：左上是頻譜圖，右上是「電台」頁籤，左下是世界地圖，右下是 QSO 日誌，位於底部列上方。設定是同一視窗右側的一個高欄；底部列中的齒輪按鈕可以顯示或隱藏它，其標題上的 X 也可以。底部列中沒有這四個部分的按鈕：它們一直都在。
  • 固定（像 Android 應用程式一樣）。一個視窗，頻譜圖在左，「電台」頁籤在右，位於底部列上方。拖曳兩者之間的細分隔條，可以讓其中一方有更多空間（比例在 20 % 到 80 % 之間）。底部列的 QSO 日誌、世界地圖和設定按鈕會將這三者各自開啟為獨立的視窗，再按一次就會關閉。
  • 浮動。主視窗縮小到只剩底部列，每個窗格都是各自獨立的視窗，您可以放在任何喜歡的位置，甚至放到另一個螢幕上：頻譜圖、電台、QSO 日誌、世界地圖和設定。此時底部列為這五者各有一個按鈕，用來開啟和關閉它們。可用來讓 qFT8 橫跨兩個螢幕，或在小螢幕上只保留頻譜圖和底部列。

更改版面配置只會重新排列視窗：不會遺失任何東西，正在進行的發射會繼續，TX 保持原狀。 世界地圖有一個全螢幕按鈕（地圖右上角）：它會填滿整個螢幕，直到您再按一次該按鈕或按 Esc。

提示：Android 的設定方向、四分割畫面和應用程式覆蓋範圍（見螢幕版面配置）在電腦上並不存在：由版面配置按鈕和視窗的大小取代它們。

視窗的操作

  • 工作列中只有一個程式。無論使用哪種版面配置，qFT8 在工作列、Dock 或 Alt-Tab 中都只有一個項目：主視窗。浮動和固定版面配置中的窗格視窗不會有自己的項目。（在 Linux 上已用 GNOME、KDE Plasma、Xfce、Cinnamon、MATE 和 LXQt 測試過。）
  • 窗格視窗有自己的小邊框（在所有系統上都一樣）：一條細邊，可從任何一邊或任何一角調整視窗大小；一個標題條，上面有窗格的名稱，拖曳它就能移動視窗；還有一個 X，其作用與底部列中對應的按鈕一樣，會關閉該窗格。視窗在使用中時，按 Esc 也會關閉窗格視窗。
  • 主視窗可以照常調整大小和最大化。在一體式版面配置中，它不能縮小到 960 x 560 像素以下，第一次開啟時佔螢幕的 85 %。
  • 設定的寬度固定。設定視窗（和欄）保持 Android 設定頁面的寬度，讓每一列都能完整顯示；您可以更改它的高度。
  • 所有內容的大小。設定 > 應用程式中有兩個大小滑桿（使用者介面與字型縮放和使用者介面元件（不含字型）縮放），與 Android 相同。在高解析度螢幕上（Retina Mac、縮放 125 % 到 200 % 的 Windows），qFT8 會跟隨系統的縮放比例。

音量：裝置與音調

底部列中，在「裝置設定」按鈕和版面配置按鈕之間，有兩個小滑桿，一上一下。它們控制兩個不同的東西，兩者對發射都很重要。

  • 上方的滑桿，附喇叭圖示：裝置音量。它是qFT8 用來發射的音效裝置的音量：電台的 USB 音效卡，或者喇叭或耳機（如果您把音訊送到那裡的話）。它與您系統自己的音量控制為該裝置顯示的是同一個音量，改變其中一個，另一個會跟著變（滑桿約在幾秒內跟上）。
  • 下方的滑桿，附波形圖示：音調音量。這是qFT8 本身產生發射音訊（FT8、FT4、WSPR、JS8 和 LQ8 的音調，以及 TUNE 的聲音）的大小聲，範圍從 0 到 100 %。可以在發射期間更改：同一次發射中您就能聽到並看到結果。預設為 100 %。每台電台都會記住自己的音調音量。網頁遙控顯示同樣的滑桿，並且移動的是這一個。

裝置滑桿的行為。

  • qFT8 啟動時會讀取裝置的音量並顯示出來；之後每兩秒再讀一次，所以如果您在系統中更改音量，滑桿會跟著動。如果您切換輸出裝置，滑桿會顯示新裝置的音量。
  • 只有當您移動這個滑桿時，qFT8 才會更改裝置音量。它絕不會在發射前自行設定。這與 Android 不同：在 Android 上，qFT8 發射時可以將手機音量設為設定中的值；在電腦上沒有這兩項設定。
  • 您移動滑桿後，qFT8 會把音量讀回來，所以滑桿顯示的是裝置實際接受的值。
  • 沒有音量控制的裝置（macOS 上的某些輸出）會顯示灰色、沒有旋鈕的滑桿。
  • 啟動 qFT8 後第一次發射或按 TUNE 時，裝置滑桿的喇叭圖示和旋鈕會在五秒內從灰色漸變為白色再變回來，提醒您這個音量決定了電台被驅動的強度。碰一下滑桿就會停止閃動。
  • 拖曳滑桿時，旁邊會顯示它的百分比數值。

提示：這兩個滑桿的作用相當於 Android 版[僅限 QMX] 音訊檢查中的音量建議：如果電台顯示音訊太低或太高（QMX 會顯示兩個點，而不是一條長條），請先試試裝置音量滑桿的其他位置（例如 70 %、80 %、60 %、100 %），再用音調音量微調。否則請讓音調音量保持預設值（100 %）。qFT8 絕不會設定您電台的發射功率：請在電台上調整。

音效裝置與電台的連線

裝置設定卡片

用齒輪右側的按鈕開啟它（第一次啟動時以及從無音訊標記也會自動開啟）。它分成兩半：

  • 電台（左側）：電台，以及電台自己的音效卡：來自電台裝置的輸入（電台聽到的聲音：qFT8 解碼的內容）和輸出到電台裝置（qFT8 發射的內容），各有取樣率、位元數和聲道數。除非電台需要其他設定，否則請保持系統預設值。輸入下方的小型即時瀑布圖會顯示是否有聲音進來。
  • 您（操作員）（右側）：您自己的麥克風，以及您自己的喇叭或耳機，用於 SSB 和 CW（見喇叭和麥克風，是同一回事）、測試按鈕，以及在數位模式下用喇叭播放電台聲音。這些絕不能是電台自己的音效卡。

同樣的選項，以及更多選項（緩衝區大小、雜音警告），位於設定 > 裝置設定。Android 上的「Audio system」和「音訊輸入來源」這兩列在電腦上不存在。請讓裝置保持在 AUTO：對於電台，它優先選擇電台自己的音效卡；對於您，則選擇不是電台的裝置。

您可能會看到的通知

  • 輸出到電台（標記）：您電腦的預設聲音輸出是電台的音效卡，所以系統音效、瀏覽器和提示音都會進入電台；如果電台以 VOX 或其資料輸入發射，這些聲音可能會被發射出去。qFT8 提供改用其他輸出（使用 ...）、開啟聲音設定，或不再詢問的選項。qFT8 的發射音訊也跟隨預設輸出：請先將電台的音效卡選為 qFT8 的輸出，再更改電腦的預設輸出。
  • 電台無輸入（標記，Linux）：由於電台的音效卡處於僅輸出的設定檔，它在音效系統中沒有輸入。直接讀取電台（建議）讓 qFT8 自己讀取該音效卡；切換到 PRO AUDIO會為所有程式更改該音效卡的設定檔。
  • 沒有輸入裝置：系統沒有提供任何輸入；請連接電台或音效卡，並檢查它是否出現在電腦聲音設定的輸入中。
  • 電台的 USB 驅動程式尚未安裝（Windows 和 macOS）：Icom IC-7300 以及其他使用 Silicon Labs USB 晶片的電台可能需要 CP210x 驅動程式。請從製造商的驅動程式頁面下載並安裝，然後重新插上電台。
  • 不同的電台？（標記）：插上的電台不是在 qFT8 中選擇的那一台。

依系統區分

  • Windows：qFT8 透過 Windows 自己的音訊引擎（WASAPI）聽電台，它比舊的方式提供更穩定的串流。電台會顯示為一個 COM 連接埠（COM3、……）和一個「USB Audio CODEC」或類似名稱的音效裝置。Windows 只允許一個程式使用 COM 連接埠：如果 qFT8 說存取被拒絕，請關閉另一個程式（日誌程式、數位模式程式、電台自己的軟體），然後按重試。
  • macOS：電台的連接埠看起來像 /dev/cu.usbmodem...（QMX）或 /dev/cu.SLAB_USBtoUART（IC-7300）。macOS 對連接埠不需要群組或權限，只需要上面提到的麥克風權限。如果連接埠被拒絕，表示另一個程式已將它開啟。
  • Linux：連接埠看起來像 /dev/ttyACM0 或 /dev/ttyUSB0，需要上面提到的群組。音效裝置是音效伺服器（PulseAudio 或 PipeWire）的裝置，所以電台的喇叭、您的耳機和您的麥克風可以各是不同的裝置。裝置音量滑桿使用 pactl，它來自套件 pulseaudio-utils（也適用於 PipeWire）。

選擇電台及其連接埠

與 Android 一樣，請讓設定 > 裝置保持在 AUTO：插上受支援的電台時會自動辨識。對於透過通用 USB 序列介面連接的電台（例如 Digirig），請手動選擇電台，然後在設定 > 裝置設定 > 通訊埠設定 > USB 裝置中選擇它的連接埠；傳輸速率、資料位元、停止位元、同位檢查和鍵控方式（DTR、RTS 或 CAT）也都在那裡，除非您勾選允許覆寫設定，否則由 qFT8 依您選擇的電台自動設定。只使用聲音的電台（VOX）完全不需要連接埠。命令列可以列出 qFT8 看到的連接埠和音效裝置。

滑鼠與鍵盤

電腦版程式是用滑鼠操作的。為了安全，鍵盤絕不會按下控制項：Tab 鍵不會在控制項之間移動，空白鍵和 Enter 鍵也絕不會按下按鈕、勾選方塊或開啟 TX。（不小心按到按鍵不會造成發射。）鍵盤能做的事：

  • 文字欄位照常接受所有按鍵：輸入呼號、訊息或搜尋。Enter 確認對話方塊的文字方塊。複製和貼上可用：Windows 和 Linux 用 Ctrl，macOS 用 Cmd（Ctrl 在那裡也可用）。
  • Esc 會關閉對話方塊、窗格視窗、全螢幕地圖，以及 QSO 編輯器或記錄器。
  • Ctrl-S（macOS 上是 Cmd-S）在 QSO 編輯器中儲存。
  • CW：您的鍵盤可以當作電鍵或雙槳（設定 > CW）；當 CW 畫面是使用中的視窗時，這些按鍵（包括空白鍵和 Tab）都可用（見 CW）。
  • SSB：當 SSB 窗格取得焦點時，按住空白鍵即為通話（push-to-talk）（見 SSB）。

在電腦上 按滑鼠右鍵
在 Android 上 在 JS8 聊天中的訊息上點兩下
在電腦上 連按兩下

設定：儲存位置，以及從手機移轉

qFT8 將它儲存的所有內容放在一個資料夾中，即設定檔資料夾：設定、密碼、QSO 日誌、備份和圖片。

  • Windows：C:\Users\<you>\qFT8
  • macOS 和 Linux：您主目錄中的 .qft8（~/.qft8；在 Finder 和大多數檔案管理員中是隱藏的）

更新或刪除程式時，這個資料夾會保留，所以新版本會找到您的設定和日誌。在主設定頁面的最下方、版本號碼之下，設定目錄：會顯示該資料夾（按一下即可開啟），而回報錯誤旁邊的開啟記錄檔資料夾按鈕會開啟存放 qFT8 記錄檔的資料夾，在您寄送錯誤報告時很有用。 較早的 Windows 版本把它存放在 qFT8.exe 旁邊的 settings 資料夾中：較新版本第一次啟動時會移動它、檢查副本，並把舊資料夾保留為 settings.old。

將設定從手機移過來（或移到手機）

主設定頁面上的匯出設定和匯入設定（位於設定檔案之下），會建立和讀取一個在 Android 和電腦上相同的檔案。在手機上匯出，把檔案複製到電腦（郵件、雲端、傳輸線），再在電腦上匯入；反過來也可以。

  • 這個檔案包含您的 QRZ API 金鑰、LoTW 憑證和密碼。絕對不要分享它。
  • 它不包含 QSO：請用 ADIF 移動日誌，或讓 qFT8 日誌伺服器複製它。
  • 它不包含只與這台電腦有關的內容：音效裝置的選擇（它們是不同的裝置）、版面配置和視窗。請在電腦上重新選擇。
  • 匯入時要求您輸入 yes 來確認，要求 TX 處於關閉狀態，會保留您的 QSO，而且絕不會開啟 TX。

在電腦上，匯出絕不會取代已經存在的檔案（見 ADIF 匯入/匯出）。

多個副本、bridge、網頁遙控、命令列

  • 每個設定檔資料夾一個副本。如果您啟動 qFT8 時，另一個副本正在使用同一個資料夾，它會顯示已在執行，並提供重試或結束：兩個副本使用同一個資料夾可能會損壞您的設定和日誌。若要同時執行多個副本，例如每台電台一個，請在啟動時為每個副本指定各自的資料夾：qFT8 --qft8_profile D:\qft8-radio2（Windows：qFT8.exe）。如果 qFT8 無法寫入該資料夾，就會顯示錯誤並停止。
  • 網頁遙控。電腦版程式具有與 Android 相同的遠端控制 Web 伺服器（預設關閉，連接埠 13497），並顯示相同的頁面，包括音量滑桿。可用來在您網路上的手機或另一台電腦上操作。
  • Bridge。電腦是常見的 bridge：電台插在它上面，由手機、iPhone 或另一台電腦上的 qFT8 來操作。它也可以不開視窗執行（qFT8 --bridge），適合沒有其他用途的電腦。
  • 命令列。qFT8 --help 會列出各個選項（在 Windows 中會以小視窗顯示）：--list-devices 列出 qFT8 看到的所有序列埠和音效裝置，然後結束；--port <device> 設定預設序列埠（COM3、/dev/ttyACM0）；--qft8_profile <folder> 選擇設定檔資料夾；--bridge 啟動 bridge；--opengl 透過 OpenGL 繪製視窗（見如果某些功能無法運作）。

速度較慢的電腦

設定 > 應用程式 > 慢速裝置 / 低電量模式會讓 qFT8 更輕量：每秒約 30 個畫面、瀑布圖的重繪次數減少，世界地圖只在顯示時才運作。它只改變繪製的內容，絕不影響解碼器：無論開啟或關閉，qFT8 的解碼結果都相同。

慢速模式只有在您勾選其核取方塊時才會開啟，絕不會自行開啟。在只有一個或兩個處理器核心的電腦上，qFT8 啟動時會詢問是否要開啟它：啟用慢速模式會勾選該方塊，忽略會在下次啟動時再問，不再詢問則不再詢問。在這樣的電腦上，無論是否使用慢速模式，qFT8 也會自行讓它的解碼器分到公平的處理器份額，這樣其他忙碌的程式就不會餓死它。

更新與解除安裝

更新

勾選啟動時檢查新版本（預設，見啟動時檢查新版本）時，qFT8 每天會詢問一次是否有較新的版本，並顯示有新版本可用，附有忽略和立即下載，後者會在您的瀏覽器中開啟下載頁面。qFT8 絕不會自行更新。要更新，請下載新檔案並更換舊程式：

  • Windows：關閉 qFT8，用新的 qFT8 資料夾（或只用 qFT8.exe）取代舊的。
  • macOS：關閉 qFT8，將新的 qFT8 拖到「應用程式」，並選擇Replace。
  • Linux：關閉 qFT8，執行新的 qFT8。它會自行解壓縮，並從快取中移除舊版本。

您的設定和日誌會留在設定檔資料夾中。

解除安裝

關閉 qFT8 並刪除程式：qFT8 資料夾（Windows、Linux）或「應用程式」中的 qFT8（macOS）；在 Linux 上還要刪除 ~/.cache/qft8。這樣會保留您的設定和日誌。若要連它們一併移除，請刪除設定檔資料夾（見上文）。 這會清除您的 QSO 日誌：請先用 ADIF 匯出。

如果某些功能無法運作

  • 瀑布圖是空的，標記顯示無音訊。開啟裝置設定：輸入是否為電台的音效卡，電台是否已開機？在 macOS 上請檢查麥克風權限；在 Linux 上請檢查電台無輸入標記和群組。
  • 電台能接收但不能發射，TUNE 沒有鍵控。連接埠被拒絕：另一個程式正在使用它（Windows、macOS），或您的帳號不在該群組中（Linux）。qFT8 會說明是哪一種；請關閉另一個程式並按重試，或依照 Linux 的卡片操作。另請見手機或電腦無法識別收發信機，或連線中斷。
  • 電台太小聲、太大聲，或顯示兩個點而不是長條（QMX）：移動裝置音量滑桿（音量）。請檢查電腦自己對該裝置的音量沒有被靜音。
  • 電腦的聲音被發射出去了。預設輸出是電台的音效卡：請回應輸出到電台標記，或在您的系統中選擇另一個預設輸出。
  • 「已在執行」。另一個副本正在使用設定檔資料夾。請關閉它，或用它自己的 --qft8_profile 資料夾來啟動這一個。
  • 視窗是黑的或亂碼（舊的顯示驅動程式、虛擬機器、遠端桌面）：請更新顯示驅動程式。如果仍然如此，請用 --opengl 啟動 qFT8（qFT8 --opengl），它會用另一種方式繪製視窗；如果這樣也沒有幫助，請用回報錯誤（設定）回報，並說明您的系統和顯示卡。
  • 視窗跑到螢幕外了（拔掉了某個螢幕）：qFT8 在開啟每個視窗時會檢查它儲存的位置，如果該位置的螢幕已不存在，或視窗大部分會在螢幕之外，就會改在主螢幕中央開啟。如果視窗仍然拿不到，請用它在底部列的按鈕關閉其窗格再重新開啟，或重新啟動 qFT8。
  • 在只有一個或兩個核心的電腦上，瀑布圖凍結、音訊中斷或負載很高：請見速度較慢的電腦，關閉其他程式；如果仍然如此，請用回報錯誤寄送報告。

快速設定

請確保為收發信機使用正確的電源（例如 QMX 不得超過 12V），否則會損壞它。

另請確保連接手機或電腦與收發信機的 USB 纜線和轉接頭支援資料傳輸。在 Android 上，接口不是 USB-C 的裝置通常需要專用的 OTG（On-The-Go）線。qFT8 找不到收發信機的連線問題，大多是纜線或轉接頭不相容造成的。

在 Android 上，有些裝置的 USB OTG 預設是關閉的，必須在裝置的系統設定中開啟（該選項可能藏在進階設定、系統設定或更多設定裡）。如果您遇到連線問題——特別是 qFT8 能收到訊號卻無法發射，而且即使裝置完全受支援（出現在裝置下拉清單中、在 AUTO 模式下被自動識別等）CAT 指令也不起作用——原因很可能就在這裡。

授予初始權限

在 Android 上，第一次開啟 qFT8 時，它會請求幾項權限：

  • 允許 qFT8 錄製音訊：此權限是必需的。qFT8 需要它來接收來自收發信機的訊號。qFT8 不會儲存、分享或上傳任何錄音。
  • 允許 qFT8 存取此裝置的大致位置：選用，但建議允許。qFT8 用它來得到您的 Maidenhead 網格定位，在 FT8 通聯中會發送這個網格。qFT8 不會存取也不會分享精確位置資料。
  • 允許 qFT8 向您傳送通知：選用，但建議允許。qFT8 藉此作為前景服務執行，這樣在最小化或關閉螢幕時仍能運作，以節省電量。只有連接了收發信機時才會顯示通知。
  • 允許應用程式一律在背景執行：選用，但建議允許。螢幕關閉時 qFT8 要穩定運作，就需要這項權限。

在電腦上，需要的權限較少。在 macOS 上，系統會詢問一次是否允許 qFT8 使用麥克風：請允許，因為 qFT8 就是這樣收聽收發信機的。在 Linux 上，使用電台的序列（CAT）連接埠需要您的帳號屬於該連接埠所在的使用者群組（通常是 dialout）；如果不屬於，qFT8 會說明情況並提出為您修復。

基本原則：qFT8 不會向任何專為本應用程式設立的伺服器提交資訊。所有資料都在您的裝置本機處理。如果您輸入了有效的 QRZ API 金鑰，即表示您明確授權分享呼號、日期和時間，以及（選用的）大致位置。

更多詳情請參閱 qFT8 的隱私權政策和授權條款。

qFT8 會要求您輸入呼號，並確認以下幾點：

  • 連接收發信機使用本軟體時，您必須持有有效的電台執照。
  • 您不得讓本軟體在無人值守的情況下運作。
  • 免責聲明：使用 qFT8 即表示您自行承擔遵守法律法規、人身安全和裝置損壞方面的全部責任。

[僅限 QMX] 音訊檢查

開始操作之前，務必先確認手機或電腦與 QMX 之間的音訊訊號運作正常。按下 TX 按鈕，等待 QMX 在接下來的某個序列中開始發射。

一切正常

如果 TX 按鈕顯示輸出功率（例如 5W），說明一切正常。在 QMX LCD 上，螢幕左上角的「A」VFO 標記下方應當出現一條橫條——這表示 QMX 正從 qFT8 收到良好的音訊訊號。您還應確認 LCD 上頻率後面沒有顯示「S」，它表示 SWR 保護已動作。

頻率後面顯示「S」

如果 QMX LCD 在頻率後面顯示「S」，說明 SWR 保護已經動作：您的天線在目前波段沒有調諧好。您可以用 QMX 選單中的 SWR 檢查功能測量 SWR，並需要重新調諧天線。

  • 韌體 1_04_004+：qFT8 會在週期結束時自動重設 SWR 保護。
  • 韌體 1_03_000+：可以在 QMX 保護選單中將「SWR Protection reset options」設定為 TX->RX，以便自動重設。
  • 舊版韌體（早於 1_03_000）：必須在 QMX 上進入再退出 TUNE 選單，或者把它斷電重啟，才能重設 SWR 保護。

出現兩個點，而不是橫條

如果 QMX 在螢幕左上角「A」VFO 標記下方顯示的是兩個點而不是橫條，說明音訊音量太低或太高。

請嘗試：進入 qFT8 的設定，找到「使用電台時將系統音量設定為 [X]」選項，試幾個不同的值（例如 70%、80%、60%、100%）。其中某個值應該會讓兩個點變成橫條。

在某些手機上，這個選項可能不起作用。這時請取消勾選，然後手動把手機音量調到不同的值（100%、90%、80% 等），直到橫條出現。

另外，共模電流也可能影響 QMX 的運作；在天線上加一個共模扼流圈，對音訊問題也可能有幫助。

「A」下方什麼都沒有

如果 QMX LCD 螢幕左上角「A」VFO 標記下方既沒有橫條也沒有點，可能是 qFT8 沒能正確控制收發信機。這通常意味著 USB 權限沒有授予，或者授權對話方塊被不小心關掉了。此時可以接收，但無法發射。

請嘗試：拔下 QMX 再重新插上——在 Android 上，權限對話方塊應該會再次出現。也可能是這條線不適合 QMX；請換一條 USB-C 線試試。

當您在 QMX LCD 螢幕左上角「A」VFO 標記下方看到橫條，並且 TX 按鈕上顯示輸出功率時，您的 QMX 就已設定妥當，可以開始通聯了！

數字模式簡介

業餘無線電數字通訊模式將結構化文字和資料轉換為音訊頻移鍵控（FSK）訊號，並透過單邊帶（SSB）電臺發射。結合超窄的射頻頻寬、先進的前向糾錯（FEC）編碼和嚴格的時間同步，使通聯能夠在訊號遠低於人耳可聞底噪的惡劣條件下順利實現。qFT8 全面支援主流的現代數字模式：FT8、FT4、FT2、JS8、WSPR 以及 LQ8，各自針對超弱訊號信標探測、高節奏競賽通聯以及自由文字鍵盤對話等不同場景進行了深度最佳化。

FT8

FT8（Franke-Taylor 設計，8-GFSK）是全球使用最廣泛的弱訊號數字協議，針對惡劣的 HF/VHF 條件、多跳突發 E 層傳播和擁擠的波段而設計。它使用結構化報文、精確的 15 秒時間同步和強大的糾錯能力。

週期與序列

FT8 以 15 秒為一個週期工作。每個通訊週期都有嚴格的定時，準確地從每分鐘的第 00、15、30 和 45 秒開始。因此，您裝置的時鐘必須與 UTC 時間精確同步。

協議中有兩個序列：

  • 序列 0（偶數）：從第 00 和 30 秒開始的週期。
  • 序列 1（奇數）：從第 15 和 45 秒開始的週期。

電臺通常輪流發射和接收。在序列 0 發射的電臺會在序列 1 守聽回答，反之亦然。在每個 15 秒週期內，報文大約在 +0.5 秒到 +13 秒之間的視窗內發出。這樣週期末尾留有時間解碼，週期開頭留有時間準備下一次發射。

訊號特性

每條 FT8 報文都以一串頻率略有變化的單音發出（有人形容它“扭來扭去”）。FT8 訊號非常窄，只佔大約 50Hz 頻寬。正因為如此高效，一個 3kHz 的通帶內可以同時容納幾十組通聯。

QSO 的 6 個階段

一個標準的 FT8 通聯通常經過六個階段。下面是 HB9IPH 和 XX1XXX 之間一次交換的例子：

  1. 1/6 CQ：一個電臺尋找任何願意通聯的物件。
    示例：CQ HB9IPH JN47
    注：JN47 是 Maidenhead 網格定位，表示該電臺的大致地理位置。也可能帶有 CQ 修飾符，它是給其他操作員看的附註（例如 CQ SOTA HB9IPH 表示參加山峰通聯（Summits On The Air）活動，CQ US HB9IPH 表示想聯絡美國的電臺）。修飾符和位置不一定能放進同一條報文；這時會省略位置。如果呼號很長，CQ 裡可能位置和修飾符都放不下！
  2. 2/6 CALL：另一個電臺回答這個 CQ。
    示例：HB9IPH XX1XXX JO21
    注：回答方也會傳送自己的位置（JO21）；如果呼號太長、放不下全部內容，位置可能被省略。
  3. 3/6 RPT：第一個電臺發出訊號報告。
    示例：XX1XXX HB9IPH -10
    注：訊號報告（例如 -10）表示訊號相對於底噪的強度，單位為 dB。
  4. 4/6 RRPT：第二個電臺確認收到報告，併發出自己的報告。
    示例：HB9IPH XX1XXX R-12
    注：字首“R”確認已收到對方的報告，後面是給第一個電臺的訊號報告。
  5. 5/6 RR73：第一個電臺確認全部收妥，併發出“Roger-Roger 73”。
    示例：XX1XXX HB9IPH RR73
  6. 6/6 73：第二個電臺發出最後的“73”，結束通聯。
    示例：HB9IPH XX1XXX 73

由於兩軍問題（Two Generals' Problem），理論上無法確知對方電臺收到了您的最後一次發射，除非對方加以確認。可是那樣您又得確認對方的確認，對方再確認您的確認，如此沒完沒了。FT8 數字模式用結構化的階段來緩解這個問題：嚴格說來，在階段 4/6 之後（雙方的訊號報告都已交換）QSO 就可以算完成。在實際操作中，為了確保雙方都認可這次交換，電臺在收到 RR73 併發出 73 後才記錄 QSO。實際效果是：發出 RR73 或發出 73 都會觸發記錄 QSO。

請注意，即使對方沒有先發 CQ，電臺也可以直接呼叫它。例如，位於稀有地區的電臺可能遇到“pile-up”（許多電臺同時呼叫它）；這時稀有電臺可以直接從一個 QSO 轉到下一個，不必再發 CQ 招呼新的呼叫者。

有些電臺在第 5 階段會用 RRR 代替 RR73。這時通聯需要多一輪交換：第二個電臺發 73，然後第一個電臺再發一次 73 作為結束。

FT8 還支援自由文字報文（最多 13 個字元），但 qFT8 目前不支援傳送這類自定義報文。

協議的限制與退路

FT8 報文被高度壓縮到 77 位。有時複雜的資訊（例如很長的非標準呼號）放不進標準報文格式。

  • 雜湊呼號：呼號太長時，可能以雜湊值的形式傳送。如果接收方最近見過這個呼號呼叫 CQ，其軟體就能把雜湊值還原成原來的呼號；否則會顯示為 <...>。呼號不標準時，完成 QSO 要困難得多。
  • 退回自由文字：有些報文可能只能用 13 個字元的自由文字格式傳送，它不如標準的結構化報文可靠。
  • 非標準呼號：如果兩個電臺都使用很長的非標準呼號，它們可能根本無法用 FT8 數字模式互相通聯。
  • 跳過階段：如果呼號太長，協議可能放不下訊號報告（階段 3/6 和 4/6）。這時交換可能從最初的 CALL (2/6) 直接跳到最後的確認（5/6 和 6/6）。

您會看到但不會傳送的報文

有些電臺傳送的報文形式，qFT8 會顯示，但自己不會傳送：

  • 一條報文發給兩個電臺：同時與許多電臺通聯的遠征臺，可以在一次發射中結束一個 QSO 並開始下一個：K1ABC RR73; W9XYZ <VP8XYZ> -08。意思是“K1ABC，您的 QSO 已完成”和“W9XYZ，您的訊號報告是 -08”，兩者都來自 VP8XYZ。qFT8 按原樣顯示它：在電臺列表中顯示，並在瀑布圖上顯示一次。如果您是這兩個電臺之一，它就算作給您的 RR73 或給您的訊號報告，與遠征臺單獨發給您完全一樣，QSO 照常繼續或記入日誌。如果兩者都不是您，就無需任何操作，AUTO 也不會對它做任何事。
  • 比賽交換內容：在某些比賽中，電臺傳送的不是網格定位和訊號報告，而是類別和分區（Field Day），或者帶有州名或序號的報告（RTTY 比賽）。qFT8 會顯示這些報文，讓您瞭解波段上的情況，但從不應答：它不傳送比賽交換內容。

FT4

FT4 是專為業餘無線電比賽設計的精簡數字模式，比賽中快速完成一個又一個通聯至關重要：

  • 速度翻倍：以 7.5 秒為週期工作（比 FT8 快一倍），每次發射約 4.48 秒，每分鐘有四個發射時段。
  • 頻寬翻倍：佔用約 90 Hz 的射頻頻寬（約為 FT8 ~50 Hz 頻寬的兩倍）。
  • 靈敏度損耗：換取兩倍速率的代價是解碼門限約為 -16.4 dB 至 -17.5 dB SNR（相比 FT8 存在約 3.5 至 4 dB 的接收靈敏度損耗）。
  • 實際應用：採用 4-GFSK 調製和標準的 77 位結構化報文載荷，傳播條件允許時只用一半時間即可完成標準的比賽交換。

FT2

FT2 為訊號條件良好時的超高速交換、VHF/UHF 流星餘跡突發和高速率比賽而設計：

  • 速度比 FT4 再翻倍（FT8 的 4 倍）：以 3.75 秒為週期工作，發射時間約 2.24 秒，每分鐘最多 16 個週期。
  • 頻寬比 FT4 再翻倍（FT8 的 4 倍）：佔用約 180 Hz 射頻頻寬（FT4 的兩倍，接近 FT8 的四倍）。
  • 靈敏度進一步降低：解碼門限約為 -13 dB 至 -14 dB SNR（比 FT4 進一步損失約 3 dB，比 FT8 損失約 6 至 7 dB）。
  • 實際應用：非常適合在訊號強的傳播開通期間，以及通聯視窗轉瞬即逝的突發傳播模式下進行快速通聯，此時訊號明顯高於底噪。

JS8

JS8（Jordan Sherer 設計，8-GFSK）是為閒聊（ragchew）、鍵盤對鍵盤的對話和臨時組網而建立的，而不是用於結構化的比賽交換：

  • 報文分片與成幀：使用與 FT8 相同的 8-GFSK 基本調製和 77 位幀，但增加了一層上層傳輸協議來分片和重組報文。這樣任意長度的自由文字就能跨越連續的週期順暢地傳送。
  • 多種速度模式：提供四種可選的速度檔，以適應波段條件：
    • Slow：30 秒週期，頻寬約 25 Hz，可解碼低至 -25 dB SNR 的訊號。
    • Normal：15 秒週期，頻寬約 50 Hz，可解碼低至 -21 dB SNR 的訊號。
    • Fast：10 秒週期，頻寬約 80 Hz，可解碼低至 -18 dB SNR 的訊號。
    • Turbo：6 秒週期，頻寬約 160 Hz，可解碼低至 -15 dB SNR 的訊號。
  • 組網能力：支援定向報文、經中間電臺自動中繼報文、心跳線上監測，以及非同步的儲存轉發信箱網路。

WSPR

WSPR（Weak Signal Propagation Reporter，弱訊號傳播報告）專門用於探測電波傳播路徑和自動信標，而不是雙向對話式的 QSO：

  • 兩分鐘週期：以嚴格同步的 2 分鐘（120 秒）週期工作，在 110.6 秒內發射 162 個符號的 4-FSK 單音序列。
  • 極窄頻寬：只佔用約 6 Hz 射頻頻寬，把輻射功率集中在極窄的一段頻譜內。
  • 極高的弱訊號靈敏度：在標準的 2.5 kHz 參考頻寬下，能解碼低至 -28 dB 至 -31 dB SNR 的微弱訊號，使毫瓦級（QRPp）發射機也能跨越全球距離。
  • 自動傳播報告：發射內容包括電臺呼號、Maidenhead 網格定位（4 位或 6 位）和以 dBm 表示的發射功率。解碼出的 spot 會自動轉發到全球的 WSPRnet 資料庫，實時描繪電離層傳播情況。

LQ8

LQ8 是由 qFT8 的作者 Luis Quesada（HB9IPH）開發的先進弱訊號數字模式：

  • 更快完成 QSO，且沒有代價：LQ8 完成雙向 QSO 比 FT8 快得多，而且靈敏度沒有任何損失。它保留了完整的 -21 dB SNR 弱訊號解碼門限（與 FT8 相同），同時透過最佳化的協議設計，用少得多的發射輪次完成有效通聯。
  • 複合報文：支援合併發射，例如把訊號報告和確認合在一起（REPORT+RR73），以及同時回答多個電臺（MULTI_CALL），把標準 QSO 的時長從 4–6 個週期縮短到只需 2–3 個週期。
  • 現代架構：以標準的 15 秒週期工作，79 個符號的 8-GFSK 調製（頻寬約 65 Hz），77 位載荷採用最佳化的哈夫曼編碼壓縮，14 位 CRC 檢錯，並有結構化的應急排程信令。

欲瞭解更多資訊、規範和工具，請訪問 LQ 模式的入口網站 https://lq8.org。

qFT8 使用者介面

qFT8 應用分為三個部分：

  1. 底部欄：始終可見，用於監視和控制發射，並控制 qFT8。
  2. 頻譜圖：始終可見，用於檢視解碼出的報文、實時的 UTC 時間和當前調諧的頻率，並控制發射頻率偏移。
  3. 選項卡區域：顯示四個選項卡（電臺、日誌、世界地圖和設定）中的一個。顯示哪一個，由底部欄最右側的按鈕控制。

下面各節詳細介紹這些組成部分。

底部欄

底部欄顯示重要資訊：發射處於允許還是禁止狀態、qFT8 是否正在發射、發射功率、駐波比（SWR）、正在發射的報文、當前序列和所選序列、波段選擇器，以及切換各個選項卡的按鈕。

底部欄各組成部分的詳細說明：

  1. 週期進度條：黃色進度條從週期的 0 秒（最左端）開始，到週期的 15 秒（最右端）結束。
  2. Tx 觸發標記：進度條左側的紅色圓點表示 Tx 觸發時刻。如果 Tx 為 ON（見第 4 項），並且當前序列就是所選序列（見第 6 項），發射就從這一刻開始。
  3. 解碼時刻標記：進度條右側的白色圓點表示解碼時刻，也就是從收到的訊號中解出報文並隨後處理的時刻。
  4. TX 按鈕：可以處於禁止發射（OFF）或允許發射（ON）狀態。它還顯示是否正在發射，以及發射功率和 SWR。QMX 韌體高於 1_04 時，此按鈕會顯示“HOLD: TUNE”。按住按鈕即進入調諧模式，並實時報告 SWR。
  5. 報文選擇器：顯示已選定要發射或正在發射的報文（正在發射時以黃色高亮）。在 AUTO 模式下它由程式自動管理。在 CALL 模式下預設也是自動管理，但可以點按它，手動選擇下一條要發的報文。
  6. 序列選擇器：按鈕上方的黃色線條表示當前序列（0 或 1）。點按 0 或 1，即選擇在該序列發射。
  7. 模式選擇器：切換所用的發射模式（例如 FT8、FT4、FT2、LQ8、JS8 或 WSPR），也可切換到 SSB、CW、RTTY 和 SSTV，它們會按各自章節所述改變底部欄和電臺選項卡。從數字模式切換到這四種模式之一、切換回來或在它們之間切換時，TX 會變為 OFF：準備好後請重新開啟。在數字模式之間切換則保持原狀態。
  8. 波段選擇器：連線了收發信機時，它會更改收發信機的波段。
  9. 電臺選項卡按鈕：開啟電臺選項卡，其中列出您收到的或可以通聯的所有電臺。
  10. 日誌選項卡按鈕：開啟日誌選項卡，其中列出您完成的所有 QSO。如果有 QSO 尚未上傳到 QRZ，這個按鈕上會出現一個黃點。
  11. 世界地圖選項卡按鈕：開啟顯示互動式世界地圖的選項卡。
  12. 設定選項卡按鈕：開啟用於配置 qFT8 的選項卡。

電臺選項卡

電臺選項卡是監視波段活動和操作 qFT8 的指揮中心。頂部是篩選和自動操作的控制元件，下面是活躍電臺的列表。

電臺選項卡各組成部分的詳細說明：

  1. AUTO 呼叫模式按鈕：啟用“AUTO”後，qFT8 會按使用者選定的條件嘗試呼叫最合適的電臺。
  2. 手動 CALL 模式按鈕：對某個電臺啟用“CALL”後，qFT8 會一直呼叫該電臺，直到完成 QSO，然後回到“AUTO”。
  3. 目標：設定 AUTO 模式的選臺條件：
    • 任何人：任何您還沒有通聯過（沒有 QSO）的呼號。
    • 較近：按 Maidenhead 網格距離，優先最近的電臺。
    • 較遠：按 Maidenhead 網格距離，優先最遠的電臺。
    • 訊號強度：優先訊號最強（SNR）的電臺。
    • 呼叫 CQ：只呼叫 CQ，並回答任何呼叫您的電臺。
    • POTA 獵人：優先 Parks on the Air（公園通聯）電臺。
    • SOTA 獵人：優先 Summits on the Air（山峰通聯）電臺。
    • POTA + SOTA 獵人：優先 Parks on the Air 和 Summits on the Air 電臺，然後是兩者都不是的電臺，按 SNR 排序。
    • DXCC：優先新的國家/實體。
    • 網格：優先新的 Maidenhead 網格。
    • ITU 分區：優先新的 ITU 分區。
    • CQ 分區：優先新的 CQ 分區。
    • I/C/D/G：先優先 ITU 分區，再 CQ 分區，再 DXCC，最後網格。
    無論哪種條件，符合同一條件的電臺都按訊號強度排序。例如，任何人會優先新的呼號，而其中訊號最強的排在列表最前面。
  4. 週期：多久與該目標通聯一次：
    • 一次：一生只通聯一次。
    • 每天：每個 UTC 日期一次。
    • 每週：每 7 天的滾動視窗內一次。
    • 每月：每一個月的滾動視窗內一次。
    • 每年：每一年的滾動視窗內一次。
  5. 限定條件：上述限制如何適用：
    • 按呼號
    • 在不同波段
    • 在不同模式
    • 直到分區確認
    • 每個波段 + 直到分區確認
    • 每個模式 + 直到分區確認
    • 在不同波段或模式
    • 波段/模式 + 直到分區確認
  6. 偵聽（偵聽）模式：啟用後，qFT8 也會嘗試呼叫您還沒聽到它發過 CQ 的電臺（標記為 DIRECT）。這樣可通聯的電臺更多，也便於加入 pile-up。
  7. 忙碌（忙碌）模式：啟用後，qFT8 也會嘗試呼叫正在與別人進行 QSO 的電臺（標記為 BUSY）。這便於加入 pile-up。
  8. + 按鈕：輸入呼號，手動呼叫任意一個電臺。
  9. 電臺資訊：顯示每個已解碼電臺的詳細狀態。

每個電臺條目由資訊豐富的四行組成：

第一行顯示電臺的基本資訊（從左到右）：

  • QSO Status（QSO 狀態）：表示您與該電臺的 QSO 歷史（✗ = 沒有 QSO，✓ = 已記入本地日誌，★ = 已透過 QRZ 或 LoTW 確認）。
  • 呼號：該電臺的呼號。
  • DXCC：該電臺呼號所屬的國家或實體。
  • 網格：該電臺報告的 Maidenhead 網格。
  • CQ 分區：該電臺呼號所屬的 CQ 分區。
  • ITU 分區：該電臺呼號所屬的 ITU 分區。
  • 頻段：最近一次收到該電臺時所在的波段。

第二行顯示通聯狀態（從左到右）：

  • 狀態：通聯當前所處的階段：
    • DIRECT：已收到，眼下似乎空閒，但從未發過 CQ。
    • 1/6 CQ：收到它在呼叫 CQ，眼下似乎空閒。
    • 2/6 CALL：呼叫了您。
    • 3/6 RPT：給您發了訊號報告。
    • 4/6 RRPT：收到您的報告並回了它自己的報告。
    • 5/6 RR73：用 RR73 確認了您的報告。
    • 6/6 DONE：QSO 已完成（已互致 73）。
    • GONE：最近幾個週期沒有再收到。
    • TOO LONG：受 FT8 數字模式的限制，您的呼號和對方的呼號加起來太長，無法建立通聯。
  • 訊號強度：以 dB 表示的強度（最近沒有收到時顯示“????”）。
  • 序列：最近一次收到該電臺發射時它所在的序列（0 或 1）。
  • 時間差（Δt）：對方時間與您的時間之間的同步偏差，單位為秒。
  • 距離：對方網格與您電臺網格之間的估算距離。

第三行和第四行顯示與該電臺往來的報文，包括 UTC 時間、頻率偏移和報文文字（收到的報文以 RX: 開頭，發出的報文以 TX: 開頭）。根據設定 → 應用 → 使用者介面中設定的電臺顯示方式（預設為緊湊 - 最新接收(Rx)，另有緊湊 - 最新Rx/Tx交替、緊湊 - 最新Rx/Tx 和展開 - 同時顯示最新Rx和Tx可選），電臺卡片顯示三行，或者顯示同時帶有 Rx 和 Tx 報文的四行。

值得留意的幾種視覺提示：

  • 珊瑚色的 Rx 報文（UTC、偏移和文字）：在當前或上一個週期內，從該電臺收到的 Rx 報文是專門發給您的電臺 / 呼號的（包括 /P 之類的複合呼號，以及與雜湊呼號匹配的情況）。這是一個一目瞭然的提示：該電臺剛剛呼叫了您，或回答了您的發射。廣播式的 CQ 呼叫和發給其他電臺的報文從不高亮；報文一旦早於上一個週期，文字就自動恢復為普通的灰色。發出的報文（TX:）始終是中性的灰色。
  • 紅色呼號：AUTO 模式對該電臺的重試次數已超過上限。它會被暫時忽略，除非您點按“CALL”手動重置。
  • 紫色呼號：按您當前的條件，這個呼號是目標。
  • 灰色呼號：該呼號與您設定的排除字首（用逗號分隔）相符。AUTO 模式永遠不會把這個電臺當作目標。
  • 紫色高亮的分區：按您當前的條件，這個分區/實體（DXCC、網格、CQ分區、ITU分區）是目標。
  • 紅色序列號：該電臺與您所選的序列相同，會發生衝突。按“CALL”會自動切換您的序列。
  • 紅色頻段：最近一次收到該電臺是在另一個波段。

電臺會按相關程度自動排序。更改目標條件或限制後，列表會立即重新排序。

日誌選項卡

日誌選項卡顯示已完成的 QSO。

日誌選項卡各組成部分的詳細說明：

  1. 呼號文字篩選：按呼號是否包含所輸入的文字來篩選 QSO。
  2. 狀態篩選：按以下狀態篩選 QSO：
    • 全部：顯示所有已記錄的 QSO。
    • 已確認：只顯示已得到確認的 QSO。
    • 未確認：顯示尚未得到確認的 QSO。
    • 未上傳：顯示還沒有上傳到 QRZ 的 QSO。
    • 重複：顯示被 QRZ 認定為重複的 QSO。
    • 已拒絕：顯示在 QRZ 上被對方電臺拒絕的 QSO。
    • 其他呼號：顯示用不同於當前所設呼號記錄的 QSO。
    • Non FT8/FT4：顯示以 FT8、FT4 之外的模式記錄的 QSO。
  3. “最近”篩選：只顯示符合上述條件的最近 100 個 QSO。
  4. QSO 列表：顯示日誌條目，各列如下（從左到右）：
    • QRZ：表示您與該電臺的通聯歷史：
      • ✗：沒有 QSO 記錄。
      • ✓：已記入本地日誌 / 等待上傳。
      • ✓🕒：已上傳到 LoTW，等待確認。
      • ✓：已上傳到 QRZ。
      • ★：已在 QRZ 或 LoTW 上確認（對已上傳到 QRZ 的 QSO），或已手動確認。
      • ⟳ / ♻️：環形箭頭：被 QRZ 報告為重複（只有日誌中確實存在重複條目時才顯示；QRZ 上已有的不重複 QSO 會自動以綠色對勾標記為已上傳）。
      • ❕：本臺呼號不符，已上傳。
      • ⚠️：本臺呼號不符，未上傳。
      • ⛔：已被拒絕。
    • 呼號：該電臺的呼號。
    • DXCC：該電臺呼號所屬的國家或實體。
    • 網格：該電臺報告的 Maidenhead 網格。
    • CQ 分區：該電臺呼號所屬的 CQ 分區。
    • ITU 分區：該電臺呼號所屬的 ITU 分區。
    • 頻段：最近一次收到該電臺時所在的波段。

值得留意的幾種視覺提示：

  • 呼號下方的黃色附註：這個 QSO 所用的本台呼號與目前所設的不同。
  • 綠色醒目標示的分區（DXCC、網格、ITU分區、CQ分區）：這是您日誌中該分區的第一個 QSO，尚未確認。
  • 黃色醒目標示的分區（DXCC、網格、ITU分區、CQ分區）：這是您日誌中該分區的第一個已確認 QSO。

編輯 QSO：點按清單中的任一 QSO 會開啟 QSO 編輯器，可以在其中更正該 QSO 的每個欄位、手動把 QSO 標記為已確認或未確認、重新上傳或刪除。刪除 QSO 只會在應用程式中刪除，絕不會在 QRZ 或 LoTW 上刪除；除非您保留了匯出的日誌檔案副本，或該 QSO 已上傳到 QRZ，否則刪除後無法復原。

設定分頁

設定分頁用於設定 qFT8。

設定分頁的組織如下：

  • 呼號：您的業餘無線電呼號（發射時必須填寫）。必須與您的執照相符。
  • CQ 修飾符：附加在您 CQ 呼叫中的選用文字（例如「SOTA」）。
  • 裝置：用於選擇和設定您的收發信機（例如 QMX、QDX、Kenwood TS-480 / TS-590 / TS-2000 系列，或 VOX/僅音訊）及其連線參數。
  • 電台 / 天線：您使用的電台和天線。您記錄的每個 QSO 都會儲存它們（ADIF MY_RIG / MY_ANTENNA），PSKReporter 也會隨您的報告一起收到。電台欄位為空時，使用已連線電台的名稱。

子選單和選項

  • 裝置設定：選擇音訊裝置，設定發射音量和 VOX 閾值，並設定電台的鍵控方式。每台電台的頻譜圖調諧偏移和連續發射時間上限也在這裡（兩者見功能說明）。
  • 喇叭和麥克風：您自己的麥克風以及喇叭或耳機，用於 SSB 和 CW（見緊接在下面的喇叭和麥克風）。
  • POTA 啟動 / SOTA 啟動：開始、檢視或結束一次啟動；每個按鈕旁邊的放大鏡會列出以往的啟動記錄。
  • 匯入/匯出日誌：用標準的 ADIF（.adi）檔案匯入或匯出您的 QSO 日誌。
  • QSO 同步：設定與 QRZ 和 LoTW 的整合，用於同步日誌和核對確認。
  • 刪除 QSO：清除本機的 QSO（此操作只影響應用程式本機的日誌）。
  • 應用程式：一般設定，包括使用者介面語言。
  • 頻譜圖：選擇瀑布圖上繪製哪些覆蓋內容 — 解碼耗時、UTC 時間和序列、訊息、峰值線以及所選電台的頻率 — 以及覆蓋文字的字型比例。
  • 世界地圖：選擇地圖顯示什麼、顯示多久：已完成的 QSO、spot 以及收發的訊息，各有自己的時間視窗。
  • 時間和位置：設定時間偏差同步（NTP 或 GPS）和您的 Maidenhead 網格定位。
  • 自動操作：設定自動操作的偏好、重試次數、排除的前綴，以及 AUTO 是否回答不是發給您的定向 CQ。
  • 數位模式：所有模式的解碼選項集中在一處 — FT8/FT4/FT2、LQ8、JS8 和 WSPR — 包括共用的深度解碼設定，以及解碼可以使用多少個執行緒。
  • SSB、CW、RTTY, JTTY 和 SSTV：這些模式各自的設定，在它們的章節中說明。每種模式面板上的齒輪按鈕開啟的是同一個頁面。
  • 波段選擇：自訂啟用哪些波段，以及切換波段時的行為。
  • 遠端控制 Web 伺服器：啟用並設定用於遠端控制的內建 Web 伺服器。
  • PSKReporter 設定：將您接收到的電台上傳到 PSKReporter。
  • WSPRnet 設定：把 WSPR spot 上傳到 WSPRnet，並檢視最近的上傳記錄。
  • 啟動時檢查新版本：有更新的 qFT8 版本時顯示通知（見錯誤報告和新版本）。
  • 傳送匿名的每日效能摘要（就在「語言」上方，預設關閉）：應用程式開啟期間，大約每週一次傳送一份簡短摘要，說明 qFT8 在您裝置上執行得有多快（啟動時間、畫面流暢度、解碼時間、音訊和電台時序、裝置型號和螢幕）。其中絕不包含您的呼號、網格、日誌、設定或任何識別碼。

喇叭和麥克風

數位模式只需要一個音效裝置：電台的音效卡。SSB 和 CW 還需要給您自己用的第二個裝置：用來收聽電台的喇叭或耳機，SSB 還需要一支用來講話的麥克風。這兩者絕不能是電台自己的音效卡，否則您說的話會直接形成迴路。

  • 在 Android 上：設定 > 喇叭和麥克風，就在裝置設定下面。
  • 在電腦上：裝置設定卡片分為兩半：左邊是 電台（電台的音效卡：電台聽到的和它發出的），右邊是 您（操作員）。

有兩項選擇：

  • 您的麥克風（您說話，電台發射）。它下面有一個小的即時瀑布圖和電平指示，顯示麥克風拾取到的聲音：說句話，應該能看到它們在動。
  • 您的喇叭 / 耳機（您收聽電台），帶一個 測試 按鈕，可在其上播放一段短促的聲音。

兩者一開始都是 AUTO，它會選擇一個不屬於電台的裝置：在手機上，接有耳麥時用耳麥，否則用手機內建的麥克風和喇叭；在電腦上，用第一個不是電台音效卡的音效裝置。只有在 AUTO 選錯時才需要更改。

提示：SSB 請使用耳機。如果麥克風旁邊有喇叭，接收到的聲音可能觸發 VOX，或者混入您的發射信號。

自動操作（AUTO）

AUTO 模式是使用 qFT8 的主要方式。在此模式下，應用程式會在每個週期結束時自動分析解碼出的訊息，並依您的目標條件選出最值得通聯的電台。

目標是怎樣選出來的

電台分頁顯示活躍電台的清單，並把（依您的條件）最合適的候選電台排在最前面。每個解碼週期結束時，qFT8 查看這個排好序的清單，嘗試呼叫第一個符合條件的電台。如果找不到符合條件的目標，它會自動開始呼叫 CQ 來招呼別人呼叫。在 AUTO 模式下，qFT8 總會回答別人的呼叫。

條件和篩選

您可以用電台分頁頂部的三個下拉選單對自動操作進行細部調整：

  • 目標：定義您追求哪一種「成績」（任何人、DXCC、CQ分區、ITU分區、網格）。
  • 間隔：您願意隔多久再與同一實體通聯一次（一次、Always、每天、每週、每月）。
  • 限定條件：進一步限定「不重複」的要求（依呼號、在不同波段、直到分區確認）。

手動介入：您隨時可以點按某個電台的 CALL 按鈕進行手動介入。這會針對這一個 QSO 進入 CALL 模式。完成後，qFT8 會順暢地回到 AUTO 模式。

重試機制

為了避免 qFT8 沒完沒了地呼叫一個不回應的電台，qFT8 內建了重試和暫時封鎖機制，預設啟用。您可以在設定分頁的 Retry Logic（重試邏輯）下進行設定：

  • Retry Limit（重試上限）：對一個不回應的電台，qFT8 重複同一個發射階段的最多次數。
  • Retry Window（重試視窗）：統計這些嘗試次數的時間段。
  • Retry Cooldown（重試冷卻時間）：達到上限後，該電台在這段時間內被「封鎖」。AUTO 模式會忽略被封鎖的電台，直到冷卻時間結束或該電台回應。

手動操作（CALL）

雖然 qFT8 高度自動化，但您隨時可以自己接手。點按電台分頁中任何電台旁邊的 CALL 按鈕，會立即進入 CALL 模式，並嘗試與這個電台建立 QSO。

這個手動目標的 QSO 結束後（不論成功與否），qFT8 會自動回到 AUTO 模式，繼續您原先的自動策略（例如呼叫 CQ）。

手動操作時的時間餘量

如果您希望在週期末尾有更多時間手動做決定，可以調整設定分頁中的 FT8 設定，給自己多留一些餘量：

  • 減小「開始解碼時間」：更早開始處理音訊。
  • 增大「開始發射時間」：延後您回答的起始時刻。

警告：把這些值調得過於激進，會使其他電台更難解出您的訊息，因為這樣縮短了同步視窗內真正可用於 FT8 訊號的有效時間。

手動編輯和記錄 QSO

qFT8 在數位模式下完成的 QSO 會自動記入日誌。本節介紹您在日誌分頁中手動做的三件事：更正一筆 QSO、記錄以其他方式完成的 QSO（語音、摩斯電碼、另一台電台），以及同時處理多筆 QSO。

QSO 編輯器

在日誌分頁中點按一筆 QSO，該分頁就變成它的編輯器。所有已儲存的欄位都在這裡：您的呼號和網格定位、對方的呼號和網格定位、模式、波段、頻率、日期和時間、功率、訊號報告、POTA 和 SOTA 編號以及備註。

  1. 正在編輯的 QSO：呼號、模式、波段、日期和時間。
  2. 狀態：該 QSO 是否已確認。點按它可選擇手動確認或手動取消確認（只改變您自己的日誌）。
  3. 已上傳：該 QSO 在 QRZ 和 LoTW 上的狀態。點按它可把 QSO 重新上傳到某一項服務或全部服務。
  4. 改過的欄位會醒目標示，旁邊用紅色顯示舊值，並有一個還原舊值的箭頭。點按任意值即可修改。模式和波段從應用程式的清單中選取，波段會跟隨您輸入的頻率；不可能正確的值（呼號、網格定位、日期……）會被拒絕並說明原因。
  5. 返回：離開編輯器。如果有變更，會詢問是否捨棄。
  6. 尚未儲存的變更數量。
  7. 刪除：在您輸入 yes 之後，只從本應用程式的日誌中刪除該 QSO。
  8. 儲存：先請您確認，然後儲存。

儲存時 QRZ 和 LoTW 上會發生什麼。確認提示會針對您正在編輯的 QSO 說明：

  • QRZ：該 QSO 在那裡被更新。如果您改了呼號、日期、時間、波段或模式，QRZ 會把它當作另一筆 QSO：新建一筆記錄，舊記錄保留，需要您自己到 qrz.com 上刪除。
  • LoTW：更正後的 QSO 作為新記錄重新上傳；舊記錄留在那裡，處於未確認狀態，沒有影響。
  • 會使確認失效的變更（QSO 的對方呼號、您的呼號、日期或時間）必須輸入 yes 來確認，因為該 QSO 將不再與對方的日誌相符。
  • 用與「設定」中不同的呼號完成的 QSO 不會上傳。

qFT8 絕不會在 QRZ 或 LoTW 上刪除任何內容。刪除 QSO 只是把它從應用程式中移除。如果該 QSO 在某項服務上，下次同步時它可能會回來：請先在該服務上刪除。除非您保留了匯出的日誌副本，否則刪除後無法復原。

記錄器

日誌分頁的 + 按鈕會開啟記錄器，這是一個用於您自己手動完成的 QSO 的快速表單。在手機上它會把螢幕轉為直向，頂部保留一條窄窄的頻譜圖（可在設定 > 應用程式 > 使用者介面中關閉）。

  1. 呼號：輸入呼號並按鍵盤上的 Enter 鍵：QSO 以目前時間記錄，輸入欄清空，您可以接著輸入下一筆。從一筆 QSO 到下一筆，鍵盤一直保持開啟。
  2. 記錄：與 Enter 鍵相同。
  3. 清除 / 復原：輸入了呼號時，按鈕顯示 清除，用來清空輸入欄。其他時候顯示 復原，把本次工作階段的最後一筆 QSO 從日誌中取出放回表單，以便更正。
  4. 完成：關閉記錄器。如果已輸入呼號但還沒有記錄，會詢問是否記錄。
  5. 查詢列：呼號所屬的國家或地區、您與它的上一次 QSO，以及是否重複。橙色的 DUPE 表示您今天已經在該波段、該模式下記錄過這個電台（仍然可以記錄）。
  6. 詳細資訊（左右滑動檢視更多）：時間（現在，或點按它來設定日期和時間）、波段、模式、以 kHz 表示的頻率、與之不同時的接收頻率、功率、發出和收到的訊號報告、對方的 POTA / SOTA 編號和您自己的編號。它們的初始值取自應用程式目前調諧的狀態，並從一筆 QSO 保留到下一筆。
  7. 本次：開啟記錄器以來您記錄了多少筆 QSO。在手機上點按它可以清單形式檢視。
  8. 本次工作階段的 QSO 以珊瑚色顯示並帶有時鐘圖示：它們已經在您的日誌裡，但要等您按下 完成 後才會上傳到 QRZ 或 LoTW，這樣輸入錯誤還來得及復原。點按其中一筆即可復原或編輯。

SSB、CW、RTTY 和 SSTV 面板上的 QSO 按鈕會以小卡片的形式開啟同一個表單，其中已填好模式、頻率和對方電台，每次記錄一筆 QSO。

選擇多筆 QSO

在日誌分頁中長按一筆 QSO 即可開始選擇（在電腦上按住 Ctrl 按一下，或按住 Shift 按一下來選擇一個範圍）。然後點按其他 QSO 來加入或移除。

  1. X：離開選擇模式，不做任何操作。
  2. 已選擇的 QSO 數量。
  3. 選取範圍：點按它，再點按範圍結束處的 QSO：兩者之間的所有 QSO 都會被選取。
  4. 全選 和 無。
  5. 操作：對所選 QSO 執行的操作：
    • 手動確認 / 取消手動確認。
    • 匯出 (ADIF)：只包含這些 QSO 的檔案。
    • 帶 POTA / SOTA 編號匯出：同上，並把您的公園或山峰寫入檔案中的每筆 QSO（日誌本身不變）。
    • 加入一次 POTA / SOTA 啟動和從其啟動中移出（見啟動公園或山峰）。
  6. 所選的 QSO 會被打勾並醒目標示。

每項操作都會先告訴您它將變更多少筆 QSO 並請您確認，變更之後可以立即復原。QRZ 和 LoTW 上的內容絕不會被刪除。

ADIF 匯入/匯出

qFT8 支援標準的 ADIF（Amateur Data Interchange Format，業餘無線電資料交換格式），以便與其他日誌軟體和雲端服務互通，並用於手動備份。

匯入 QSO

匯入功能可以把其他來源（例如其他日誌程式，或其他裝置上的備份）的記錄匯入您本機的 qFT8 日誌。

  • 篩選選項：匯入所有模式。您可以選擇只匯入目前呼號的記錄，還是包括所有操作員。
  • 自動去重：qFT8 會智慧地合併記錄。它透過比對 QRZ Log ID 和 QSO 的時間戳記來避免重複。如果匯入的記錄帶有您本機記錄所沒有的確認狀態或有效的 Log ID，qFT8 會用這些更完整的資料更新本機項目。

匯出 QSO

點按 匯出 QSO 會產生一個 ADIF 3.1.6 檔案。在 Android 上會開啟系統的分享面板，您可以把日誌儲存到裝置，或透過電子郵件或即時通訊傳送；在電腦上則由您選擇檔案的儲存位置。

  • 時間範圍：您可以匯出全部歷史，也可以用 UTC 日期/時間選擇器只取某一次啟動或某一段比賽時間。
  • 狀態篩選：申請獎狀時很有用（匯出「僅限已確認」），手動上傳到其他服務時也很有用（匯出「僅限未上傳到 QRZ」，以免重複）。
  • 獵人條件：篩選日誌，匯出「匯出所有日誌」、「僅匯出 POTA 獵人」或「僅匯出 SOTA 獵人」，產生專門用於申請獎狀的檔案，其中填好了對方的參考編號（<POTA_REF> / <SOTA_REF>）。
  • SOTA 參考：如 SOTA 章節所述，qFT8 可以自動把山峰編號寫入每筆匯出記錄的 <MY_SOTA_REF> 欄位。
  • POTA 參考：如 POTA 章節所述，qFT8 可以自動把公園編號寫入每筆匯出記錄的 <MY_SIG>、<MY_SIG_INFO> 和 <MY_POTA_REF> 欄位。用逗號分隔的多個公園會為每個公園產生一個檔案（見「檔案中寫哪個公園？」）。

匯出檔案的名稱

  • 不帶編號：qFT8-YYYYMMDD-HHMMSS.adi，即匯出時的日期和時間（UTC），例如 qFT8-20261006-181500.adi。狀態篩選會在時間後面加上 _confirmed 或 _notuploaded，這樣同一資料夾裡的檔案就按日期排序。
  • 帶 POTA 編號：CALLSIGN@PARK-YYYYMMDD.adi，例如 K1ABC@US-1234-20261006.adi。這是公園活動要求的檔名。每個公園、每個 UTC 日各一個檔案，因此跨越 UTC 零點的匯出會產生兩個檔案。
  • 帶 SOTA 編號：一個檔案，例如 K1ABC@W1_HA-001-20261006.adi（山峰編號或呼號中的「/」不能用在檔名裡，寫作「_」）。
  • 在電腦上，匯出絕不會覆蓋已有的檔案：如果名稱已被占用，新檔案會儲存為 name (1).adi，然後是 name (2).adi，依此類推。

注意：對於很大的日誌（超過 100KB），qFT8 會顯示一則警告，因為去重和排序可能需要一些時間才能完成，在手機上尤其如此。

QSO 上傳服務

qFT8 可以把您記錄的每筆 QSO 傳送到多個線上或家用網路中的日誌： QRZ、LoTW、Wavelog、 Cloudlog，eQSL，以及另一個 qFT8（qFT8log）。 每個服務在設定頂部都有一列：一個用於啟用它的核取方塊，和一個開啟該服務自己頁面的齒輪按鈕。

  • 在服務通過驗證之前，核取方塊會一直是灰色的：開啟它的頁面， 輸入它的資訊，然後點驗證。
  • 每個頁面開頭都有一段簡短說明和一個?按鈕，它會在本手冊中開啟該服務的章節。頁面還顯示 還有多少 QSO 尚未上傳，並帶有立即上傳，以及一個恢復預設設定按鈕 （它絕不會清除帳戶、金鑰或密碼）。
  • 當某個服務自上次正常運作以來無法連線時，它那一列會變紅，其下的一行紅字會顯示 自 日期和時間 起無法連線。

QSO 何時算作已上傳？

日誌、電台清單、地圖和 Web 遠端控制中的綠色勾號都遵循同一條規則。每個服務的頁面上都有一個核取方塊 上傳到此處即視為 QSO 已上傳。它對 QRZ 和 LoTW 是開啟的，對其他服務是關閉的。

  • 服務只有在已設定時才計入：已驗證並已啟用。
  • 只要任何一個計入的服務已有某筆 QSO，該 QSO 就算已上傳。
  • 當已設定的服務都沒有勾選這個方塊時，所有已設定的服務都計入。因此如果您只設定了 qFT8log， 應用程式只會等待 qFT8log，絕不會等待 QRZ 或 LoTW。
  • 完全沒有設定任何服務時，由勾選的方塊根據 QSO 自身攜帶的資訊來決定（例如從其他程式匯入的日誌會保留它的勾選）。
  • 從 LoTW 匯入的 QSO 視為已在 QRZ 上，不會再傳送到那裡。從某個服務傳來的 QSO 視為已上傳到該服務，絕不會再傳回給它。
  • 星號（已確認）要求該 QSO 按此規則已上傳，並且已被任一服務確認，除非您手動將它設為已確認或未確認。

ADIF 匯出一次可以選擇未上傳到 服務這一個服務；尚未設定的服務，其選項是灰色的。 qFT8 絕不會刪除任何服務上的 QSO：在這裡刪除 QSO 時，只會提醒您它仍然留在那裡。

qFT8 伺服器

在設定的靠下位置，兩條線之間，qFT8 伺服器裡是本裝置可以向其他程式提供的服務： 遠端控制 Web 伺服器、qFT8 bridge，以及 Wavelog、Cloudlog 和 qFT8log 伺服器。

QRZ 整合

qFT8 與 QRZ.com 深度整合，讓您的日誌自動保持同步。請注意，QRZ 整合是一項訂閱服務，需要 QRZ 付費訂閱（XML Logbook Data 或更高級別）。如果您想用免費的方案，可以考慮 LoTW 整合，它由 ARRL 免費提供。

運作方式

要啟用 QRZ 整合，需要在設定分頁中填入您的 QRZ API 金鑰。API 金鑰可以在 QRZ Logbook API 官方頁面上找到。輸入並驗證之後，就可以啟用「交信建立時在背景上傳聯絡到 QRZ」，由背景自動處理。

  • 自動上傳：每完成一筆 QSO（順利到達 6/6 DONE 狀態），qFT8 就立即嘗試把它上傳到您的 QRZ 日誌。
  • 背景可靠重試：如果上傳失敗（例如沒有網際網路連線，或伺服器逾時），qFT8 不會放棄。背景工作會每 5 分鐘自動重試失敗的上傳。這個過程不打擾您，並確保網路恢復後您的日誌最終能傳到雲端。
  • 智慧略過：為保護日誌的完整性，qFT8 只上傳與目前所設呼號相符、並且是 FT8 模式的 QSO。非 FT8 的項目、其他呼號的 QSO，以及從 LoTW 匯入的 QSO都會自動略過，以免產生過多的 API 請求。

同步確認

整合不只是上傳。qFT8 還會向 QRZ 查詢，看您的 QSO 是否已得到確認。

  • 即時檢查：一筆 QSO 完成並上傳 30 秒後，qFT8 會再向 QRZ 查詢一次，看對方電台是否也上傳了這筆 QSO；如果已上傳，這筆 QSO 會立即同步為已確認。
  • 自動同步：預設情況下，qFT8 每 6 小時（可設定）查詢一次 QRZ，每批 250 筆 QSO，在您全部未確認的日誌中輪流進行，確保較早的 QSO 最終也會被檢查有沒有新的確認。
  • 確認星號（★）：已上傳到 QRZ 的 QSO 在 QRZ 或 LoTW 上得到確認後，會以金色星號醒目標示。您也可以手動確認任何 QSO 來顯示這個標記。當 QRZ 回報確認時，日誌分頁中的狀態圖示會自動變成金色星號。
  • 手動同步：也可以在設定中手動觸發，對最久沒有同步過的 250 筆 QSO 進行更新。

小提示：在設定中的「最舊的已同步聯絡日期」一項可以看到同步進度。不必急著讓它保持最新，qFT8 會隨著時間推移自行處理。

日誌同步策略

在同步設定中，您可以透過「上傳到以下服務時，視作已上傳聯絡」選項，選擇 qFT8 如何判定一筆 QSO 已「完全上傳」：

  • LoTW 或 QRZ 任一個：如果您只設定了其中一項服務，這是合適的預設選項。
  • 兩者：最穩妥的選擇，要求 QSO 成功傳送到兩項服務之後，才算完成並可以開始檢查確認。
  • QRZ (從 LoTW 匯入的除外)：如果 QRZ 是您的主日誌，建議選這一項。註：從 LoTW 匯入的 QSO 會標記為已同步，但不會上傳到 QRZ，以免觸及 API 限制（只允許逐筆上傳）；以後可以在 QRZ 網站內自行同步。
  • LoTW：如果您以 LoTW 作為最權威的記錄，建議選這一項。

Logbook of the World (LoTW) 整合

qFT8 與 ARRL Logbook of the World (LoTW) 的整合穩定可靠。強烈建議整合 LoTW，用來確認您的通聯並申請 DXCC、WAS 等獎狀。

設定所需的資訊

要完整啟用 LoTW 功能（包括自動上傳和確認檢查），需要在設定分頁中提供四項資訊：

  • 1. LoTW 使用者名稱：您在 LoTW 服務中使用的正式呼號。
  • 2. LoTW 密碼：您登入 LoTW 網站所用的密碼。它與憑證密碼不同。
  • 3. .p12 TQSL 憑證：從 TQSL 程式匯出的數位簽章檔案。如何申請和匯出這份憑證，請參閱 LoTW 官方說明頁面。
  • 4. 憑證密碼：您從 TQSL 匯出 .p12 檔案時設定的密碼（如果當時選擇不設密碼，則可以留空）。

台站位置自動填寫：ITU 分區、CQ 分區和台站名稱等資訊會根據您的呼號自動確定。這些欄位無需手動設定。

功能

  • 自動上傳：啟用交信建立時在背景上傳聯絡到 LoTW後，每筆新的 QSO 一記入日誌，qFT8 就會在背景自動簽章並上傳到 LoTW。
  • 自動檢查確認：啟用後，qFT8 會在上傳成功後正好 30 秒時做一次即時的確認檢查。這樣您幾乎馬上就能知道這次通聯有沒有得到確認。
  • 定期背景同步：設定每 __ 小時同步確認，按您希望的間隔（例如每 6 小時）在背景檢查新的確認。這樣整個日誌無需手動操作就能保持最新。
  • 匯入日誌：點按從 LoTW 匯入 QSO，把您在 LoTW 上的全部歷史下載到 qFT8。請注意，這些匯入的 QSO 不會自動上傳到 QRZ，以免觸及 API 的速率限制。
  • 待上傳標記：日誌按鈕上的小黃點表示有 QSO 正等待上傳到 LoTW。

日誌同步策略

在同步設定中，您可以透過「上傳到以下服務時，視作已上傳聯絡」選項，選擇 qFT8 如何判定一筆 QSO 已「完全上傳」：

  • LoTW 或 QRZ 任一個：如果您只設定了其中一項服務，這是合適的預設選項。
  • 兩者：最穩妥的選擇，要求 QSO 成功傳送到兩項服務之後，才算完成並可以開始檢查確認。
  • QRZ (從 LoTW 匯入的除外)：如果 QRZ 是您的主日誌，建議選這一項。註：從 LoTW 匯入的 QSO 會標記為已同步，但不會上傳到 QRZ，以免觸及 API 限制（只允許逐筆上傳）；以後可以在 QRZ 網站內自行同步。
  • LoTW：如果您以 LoTW 作為最權威的記錄，建議選這一項。

Wavelog

Wavelog 是一款日誌程式，您在自己的網路伺服器上執行它（家裡的一台小型電腦或租用的網路空間），並在瀏覽器中開啟。qFT8 會在每筆 QSO 記錄後立即把它傳送過去，並讀回您的 Wavelog 已確認了其中哪些。qFT8 透過 Wavelog 公開的介面與它通訊： docs.wavelog.org/developer/api.

設定方法

  1. 在 Wavelog 中，開啟帳戶選單 > API Keys，建立一個具有讀取和寫入權限的金鑰。
  2. 在 qFT8 中，開啟設定，點選 Wavelog 旁邊的齒輪，輸入伺服器位址（您開啟 Wavelog 所用的位址，例如 https://log.example.org）和 API 金鑰。 不帶 http:// 或 https:// 輸入的位址會先用 https 嘗試；如果伺服器只支援一般的 http（另一個 qFT8 的伺服器就是這樣），qFT8 就使用 http，頁面會提示金鑰未受保護地傳輸。
  3. 選用，要同時傳送編輯：在 Wavelog 中建立一個 API v2 權杖（帳戶選單 > API Keys，API v2 分頁，權限範圍為 qso:read 和 qso:write），並將其輸入為編輯權杖。驗證 會在不變更任何內容的情況下檢查它。
  4. 點選驗證。qFT8 會檢查金鑰並列出您的 Wavelog 電台位置；選擇您的 QSOs 所屬的那個（只有一個時會自動選取）。
  5. 在設定頂部勾選 Wavelog。從現在起，每筆新的 QSO 都會傳送過去，之前記錄的也會一併傳送。

會發生什麼

  • 離線：無法傳送的 QSO 會留在日誌中，待伺服器再次回應時傳送（1 分鐘後重試，之後間隔逐漸變長，最長每小時一次）。無法連線到伺服器時，它在設定中的那一列會變紅，並顯示「自 ... 起無法連線」。
  • 重複：您的 Wavelog 已有的 QSO 視為已上傳。
  • 被拒絕：被 Wavelog 拒絕的 QSO 在您編輯或重新上傳之前不會再次傳送；QSO 編輯器會顯示原因。失效的金鑰會停止上傳，直到您再次點選驗證。
  • 確認：每小時一次（以及你按下 立即上傳 時），qFT8 會向 Wavelog 詢問你的哪些 QSOs 已被確認（LoTW、紙本 QSL、eQSL），並在 QSO 編輯器的 已上傳 列和 狀態 列中標出，列和標記與 QRZ、LoTW 相同。
  • 編輯：設定了編輯權杖後，已編輯的 QSO 會在你的 Wavelog 中找到並在那裡更新（以最新的變更為準；Wavelog 自己儲存的確認標記絕不會被改動）。未設定時，Wavelog 的上傳介面只能新增 QSOs，因此編輯不會被傳送：請在 Wavelog 中也做同樣的修改。
  • 其他呼號的 QSOs：以你的呼號之外的另一個呼號記錄的 QSO（俱樂部或特別活動呼號）不會傳送到 QRZ 和 LoTW，但只要勾選了也傳送使用其他呼號進行的 QSO（預設），就會傳送到 Wavelog。
  • 刪除：qFT8 絕不會刪除 Wavelog 中的任何內容。請自行在那裡刪除 QSO。
  • 頁面上的「如果已上傳到此處，則視該 QSO 為已上傳」決定上傳到 Wavelog 是否計入「已上傳」標記（預設關閉）。

從 Wavelog 匯入 QSO

Wavelog 頁面底部的從 WAVELOG 匯入 QSO會把所選電台位置的 QSOs 複製到 qFT8 的日誌中，同時帶上它們的 LoTW、紙本 QSL 和 eQSL 確認。

  • 匯入內容：所有模式。從、到、頻段和呼號開頭為可限制範圍（任意 = 不限）。用您以外的呼號進行的 QSOs 會被略過，除非勾選了匯入目前呼號以外其他呼號的 QSO。
  • 已在日誌中：日誌中已有的 QSO 會被合併，絕不會重複新增（規則與 QRZ 和 LoTW 匯入相同）；您在這裡更正過的 QSO 保留您的更正，只接收確認。
  • 絕不回傳：匯入的 QSOs 視為已在 Wavelog 上。您之後在 qFT8 中所做的更正會傳送到那裡（使用編輯權杖）。
  • 停止會在目前這一部分完成後結束匯入；已經匯入的內容會保留。按鈕下方的一行統計已接收、已新增和已合併的數量。
  • 不會刪除任何內容，無論在這裡還是在 Wavelog。您在 qFT8 中刪除的 QSO 會在下次匯入時回來。

安全連線

  • 請優先使用 https:// 位址。使用 http:// 時金鑰會不受保護地傳輸：僅在您的家庭網路中使用。
  • Android 6 和 7.0 不信任許多此類伺服器使用的一些較新的憑證；在這些系統上，https:// 伺服器可能無法連線。在家庭網路中，可使用伺服器的 http:// 位址。
  • iPhone 只連線 https:// 位址。

Cloudlog

Cloudlog 是 Wavelog 的前身程式：一款執行在您自己網路伺服器上的日誌。它在 qFT8 中是一項獨立的服務，有自己的設定，設定方式與 Wavelog 完全相同（在 Cloudlog 中：帳戶選單 > API > 建立具有讀取和寫入權限的金鑰）。它公開的介面： github.com/magicbug/Cloudlog/wiki/API.

  • 匯入：其他程式無法讀取 Cloudlog。要把它的日誌帶入 qFT8，請在 Cloudlog 中匯出 ADIF 檔案，然後在設定 > 匯入/匯出日誌中使用從 ADIF 匯入 QSO（見 ADIF）。

eQSL

eQSL（eqsl.cc）交換電子 QSL 卡：傳送到那裡的每筆 QSO 都會成為對方電台 eQSL 收件匣中的一張卡片。qFT8 只新增卡片，絕不刪除 eQSL 上的任何內容。

設定方法

  1. 點按「設定」頂部 與 eQSL 同步 QSO 一列的齒輪。
  2. 輸入您的 eQSL 使用者名稱（通常是您的呼號）和 eQSL 密碼。如果您在一個呼號下有多個 eQSL 帳戶（地點），請按 eqsl.cc 上的寫法輸入該地點的 QTH 暱稱；否則留空，eQSL 會根據 QSO 的日期選擇帳戶。
  3. 按 驗證。它只讀取您的 eQSL 收件匣來檢查登入：不會傳送任何卡片。
  4. 勾選 與 eQSL 同步 QSO。尚未傳送的 QSOs 會立即發出，每秒一筆，之後每筆新 QSO 在記錄時發出。

須知

  • 對 eQSL 來說，上傳到此處即視為 QSO 已上傳 是關閉的：eQSL 上有一張卡片本身不會讓日誌出現綠色勾號（參見 QSO 上傳服務）。如果您希望如此，請勾選。
  • 卡片無法變更。 編輯已經在 eQSL 上的 QSO 時，不會自動傳送任何內容。要傳送更正後的卡片，請使用 QSO 編輯器中的 重新上傳到 eQSL；舊卡片會留在對方電台的收件匣中，直到您在 eqsl.cc 上將其刪除。
  • LQ8：eQSL 只接受官方的 ADIF 模式，因此其 QSOs 以 MFSK 傳送，備註中會寫明真實模式（「QSO by qFT8, mode LQ8」）。其他服務保持各自的形式。
  • eQSL 已有的 QSO 會被回覆為重複，並算作已傳送。它拒絕的 QSO（例如您的任何帳戶都不涵蓋的日期，或它不認識的模式）會在 QSO 編輯器中顯示為被拒絕，並附上 eQSL 自己的原話，在您重新上傳之前不會再次嘗試。
  • 離線時，或 eQSL 因維護而停止服務時，卡片會等待並稍後重試（1 分鐘後，然後間隔更長，最長一小時）；該列紅色的 無法連線 提示會說明從何時起。如果密碼被拒絕（例如您在 eqsl.cc 上改了密碼），傳送會停止，直到您再次 驗證。
  • 確認（收到的卡片）暫不回讀。

qFT8 作為 Wavelog 伺服器

在設定 > qFT8 伺服器 > Wavelog 伺服器中，qFT8 在您的家庭網路中就像一個 Wavelog 那樣應答：任何能把 QSOs 傳送到 Wavelog 的程式（包括另一個 qFT8）都可以改為把它們傳送到這個 qFT8。

設定方法

  1. 開啟執行 Wavelog 伺服器，保留連接埠（13500）或另選一個，並輸入至少 8 個字元的 API 金鑰（請設得又長又隨機：這是阻止他人進入的唯一防線）。
  2. 在另一個程式中,用頁面顯示的位址設定 Wavelog,並寫完整:http://、本裝置的位址、冒號和連接埠,例如 http://192.168.1.20:13500/(大多數日誌程式需要把 http:// 和連接埠都寫出來;另一個 qFT8 會自動找到它們),使用相同的金鑰和電台 1(在另一個 qFT8 中:驗證 會選擇它)。

連接埠可以隨時更改:伺服器會立即切換到新連接埠(關閉時立即停止)。

在瀏覽器中檢視日誌

在家庭網路的瀏覽器中開啟同一個位址(http://192.168.1.20:13500/):輸入伺服器的金鑰後,它會按從新到舊的順序以唯讀方式顯示你的 QSO 日誌;較早的 QSOs 會在滾動時載入,新的或已更改的會自動出現。金鑰絕不會被髮送:瀏覽器用由金鑰算出的值回應一次性質詢,回應錯誤的位址會被鎖定一段時間。Cloudlog 伺服器和 qFT8 日誌伺服器在各自的連接埠上以各自的金鑰或密碼顯示同一個頁面。

它做什麼

  • 收到的每個 QSO，無論何種模式、何種呼號，都會進入日誌和 QSO 清單，並轉發到此處設定的服務（QRZ、LoTW、Wavelog 等），但絕不會返回其來源。日誌中已有的 QSO 會作為重複應答，不會再次轉發。
  • 它應答日誌程式使用的各個端點：api/qso（以 ADIF 格式的一個或多個 QSOs）、api/version、api/station_info、api/check_auth、api/auth、api/get_contacts_adif（使鏈條下游的 qFT8 能讀回確認）以及 api/radio（接受並忽略）。無法透過它修改或刪除 QSO。
  • 安全：僅限家庭網路，使用普通 http（與遙控網路伺服器相同）；金鑰以不會洩漏它的方式比較；傳送 10 次錯誤金鑰的位址會被鎖定 10 分鐘；每個位址每秒最多 20 個要求，每個要求最多 128 KB 和 500 個 QSOs；任何格式錯誤的內容都會收到錯誤應答。
  • 執行位置：在 Android 上，開啟「背景執行」時也在背景執行；在電腦上，程式開啟期間執行；在 iPhone 上，僅在 qFT8 開啟期間執行。

鏈式連線

伺服器和服務可以組合成鏈：多個電台（手機、電腦）把各自的 QSOs 傳送到同一個 qFT8，由它彙整，並且只有它向 QRZ 和 LoTW 上傳；它還可以把所有內容轉發到 Wavelog 或作為備份的另一個 qFT8。確認沿鏈向下回傳：彙整的 qFT8 從 QRZ / LoTW / 它的 Wavelog 得知確認，而向其 Wavelog 伺服器傳送的各個 qFT8 每小時讀回它們。重複項絕不會被轉發，因此鏈中的迴圈會自行停止。

山峰通聯（SOTA）

qFT8 為 SOTA（Summits On The Air，山峰通聯）的追逐者（獵人）和啟動者都提供了完整的內建工具，包括自動取得 spot、即時追蹤參考編號、成績醒目標示，以及專用的 ADIF 匯出篩選。

自動取得即時山峰 spot

有網際網路連線時，qFT8 會在背景自動連線 SOTA 官方 API（每 90 秒重新整理一次），取得全球正在進行的山峰啟動。

  • 世界地圖顯示：正在活動的山峰啟動者會以山峰標記（⛰️）標在世界地圖上，並帶有呼號、山峰名稱、海拔和頻率。
  • 自動比對參考編號：當您在波段上收到一位啟動者時，qFT8 會把他的呼號與即時 spot 資料庫對照，查出確切的山峰編號（例如 HB/BE-001、W6/NC-001）。
  • 自動補填：如果您與一個呼叫 CQ SOTA 的電台完成了 QSO，而當時它的 spot 還沒有下載到，或者還沒有收到參考編號，qFT8 會留意後來收到的 spot，自動把山峰編號補填到最近（1 小時以內）記錄的 QSO 上。

作為 SOTA 追逐者 / 獵人操作

要追逐正在啟動山峰的電台：

  1. 在電台分頁中，把目標優先順序下拉式選單設為 SOTA 獵人（或 POTA + SOTA 獵人）。
  2. 標記和參考編號列：正在活動的 SOTA 電台（網路上有 spot，或正在發 CQ SOTA）會在第 2 行標上 SOTA 標記。此外，DXCC 列的標題會變成 SOTA 編號，直接顯示山峰編號。
  3. 已通聯與待通聯山峰的醒目標示：
    • 未通聯過的山峰：以醒目的紫色 SOTA 標記和紫色編號文字顯示，表示這是一座值得追逐的新山峰。
    • 已通聯過的山峰：以不顯眼的灰色標記顯示，讓您一眼就能把新山峰和日誌裡已有的山峰區分開。
  4. AUTO 追逐：在 AUTO 模式下，qFT8 會自動優先呼叫未通聯過的 SOTA 啟動者，其次才是普通的 CQ 電台，並按訊號強度（SNR）從強到弱排序。

在日誌中管理和編輯 SOTA 參考編號

qFT8 提供專門的工具，用來檢視和編輯您的 SOTA 追逐記錄：

  • 日誌分頁中的 SOTA獵人檢視：在日誌分頁中選擇 SOTA獵人檢視即可檢視山峰編號。首次得到確認的山峰通聯以金色醒目標示，首次但尚未確認的成績以黃色醒目標示。
  • 編輯山峰編號：點選日誌中的任意 QSO 開啟 QSO 編輯器，再點選其中的 SOTA 欄位，即可新增、修改或更正山峰編號（例如 HB/BE-001）。
  • 自動同步到 QRZ 日誌（ACTION=REPLACE）：如果這個 QSO 已經上傳到 QRZ，編輯山峰編號後該記錄會被自動標記，並在您的 QRZ 日誌中原地更新，不會產生重複條目。
  • 關於 LoTW：請注意，編輯參考編號時 LoTW（Logbook of The World）不會自動更新，因為 LoTW 不支援修改已上傳的 QSO。

作為 SOTA 啟動者操作

要在山峰上進行 SOTA 啟動：

  1. 同步時間：出發去野外之前，先確認裝置的時鐘準確。
  2. 開始啟動：在設定分頁中按 SOTA 啟動 並輸入您的山峰，這樣每個 QSO 都會帶著它記入日誌並計數（見啟動公園或山峰）。
  3. 設定 CQ 修飾符：在設定分頁中，把 CQ 修飾符設為 SOTA。每次 CQ 呼叫都會發出 CQ SOTA [Callsign]。
  4. 配置 AUTO 模式：在電台分頁中，把目標優先順序設為 呼叫 CQ，並啟用 AUTO 模式。
  5. 開始啟動：開啟 TX。qFT8 會自動呼叫 CQ，並依次回答前來呼叫的追逐者。

手動干預：如果幾位追逐者同時呼叫您，而您想挑選其中某一個電台，請點選該電台條目上的 CALL。這次通聯完成後，qFT8 會自動回到呼叫 CQ。

匯出 SOTA 日誌（追逐者和啟動者）

qFT8 可以產生有針對性的 ADIF 匯出檔案，既可用於獵人提交成績，也可用於啟動者的日誌：

  1. 進入設定，點選 ADIF 檔案匯出。
  2. 追逐者 / 獵人：
    • 把獵人條件設為 僅匯出 SOTA 獵人，只匯出與山峰通聯的 QSO（即填有 <SOTA_REF> 的記錄）。
  3. 啟動者（最快的辦法是使用您的啟動中的 匯出 按鈕；下面的步驟是手動完成同樣的事）：
    • 選擇所選時間段，使之與您啟動的開始和結束時間一致。
    • 在活動中選擇 SOTA，並輸入您啟動的山峰編號（例如 HB/BE-001）。qFT8 會把您的編號寫入每條記錄的 <MY_SOTA_REF>。
  4. 山峰對山峰（S2S）：如果您在啟動山峰期間通聯了另一位啟動者，qFT8 會在匯出檔案中同時寫入您啟動的山峰（<MY_SOTA_REF>）和對方的山峰（<SOTA_REF>）。
  5. 按匯出 QSO，分享或儲存這個標準的 ADIF 檔案。

公園通聯（POTA）

qFT8 與 POTA（Parks On The Air，公園通聯）活動原生、完整地整合，獵人和啟動者都適用，功能包括自動取得 spot、追蹤已通聯的公園、編輯參考編號，以及靈活的匯出選項。

自動取得即時公園 spot

連線網際網路時，qFT8 會在背景自動查詢 POTA 官方 API（每 90 秒一次），取得全球所有正在進行的公園啟動。

  • 世界地圖顯示：正在活動的公園啟動者會以公園標記（🏞️）顯示在世界地圖上，並帶有呼號、公園名稱和工作頻率。
  • 自動識別參考編號：收到正在活動的公園電台的發射時，qFT8 會把呼號與目前的 spot 對照，自動識別出公園編號（例如 K-1234、US-0001、VE-0123）。
  • 自動補填：如果您記錄了與一個呼叫 CQ POTA 的電台的通聯，而當時還沒有收到它的公園編號或它的 spot，qFT8 會留意後來收到的 spot，自動把公園編號補填到最近（1 小時以內）記錄的 QSO 上。

作為 POTA 獵人操作

要追逐正在啟動公園的電台：

  1. 在電台分頁中，把目標優先順序下拉式選單設為 POTA 獵人（或 POTA + SOTA 獵人）。
  2. 標記和參考編號列：正在活動的 POTA 電台會在第 2 行標上 POTA 標記，DXCC 列的標題會變成 POTA 編號，顯示公園編號。
  3. 已通聯與待通聯公園的醒目標示：
    • 未通聯過的公園：以明亮的紫色 POTA 標記和紫色編號文字顯示，表示這是您還沒有通聯過的公園。
    • 已通聯過的公園：以不顯眼的灰色標記顯示，波段繁忙時便於優先選擇未通聯過的公園。
  4. AUTO 追逐：在 AUTO 模式下，qFT8 優先呼叫未通聯過的 POTA 啟動者，其次才是普通電台，候選目標按訊號強度（SNR）排序。

在日誌中管理和編輯 POTA 參考編號

直接在App 內檢視和維護您的公園獵人日誌：

  • 日誌分頁中的 POTA獵人檢視：把日誌分頁的檢視切換到 POTA獵人模式，即可在通聯旁邊顯示公園編號。首次得到確認的公園成績以金色醒目標示，尚未確認的成績以黃色醒目標示。
  • 編輯公園編號：點選日誌中的任意 QSO 開啟 QSO 編輯器，再點選其中的 POTA 欄位，即可新增、修改或刪除公園編號（例如 K-1234）。
  • 自動同步到 QRZ 日誌（ACTION=REPLACE）：QSO 的公園編號更新後，qFT8 會自動在 QRZ 日誌中原地更新已有的記錄，不會產生重複條目。
  • 關於 LoTW：請注意，編輯參考編號時 LoTW（Logbook of The World）不會自動更新，因為 LoTW 不支援修改已上傳的 QSO。

作為 POTA 啟動者操作

要啟動一個公園：

  1. 同步時間：開始啟動之前，先確認裝置的時鐘準確。
  2. 開始啟動：在設定分頁中按 POTA 啟動 並輸入您的公園，這樣每個 QSO 都會帶著它記入日誌並計數（見啟動公園或山峰）。
  3. 設定 CQ 修飾符：在設定分頁中，把 CQ 修飾符設為 POTA，這樣發出的就是 CQ POTA [Callsign]。
  4. 配置 AUTO 模式：在電台分頁中，把目標優先順序設為 呼叫 CQ，並啟用 AUTO 模式。
  5. 開始啟動：開啟 TX。qFT8 會持續呼叫 CQ，並自動與前來呼叫的獵人通聯。

手動干預：點選排隊中任何一個電台的 CALL，會先完成與它的 QSO，然後再回到 AUTO CQ 模式。

匯出 POTA 日誌（獵人和啟動者）

產生可以直接上傳到 pota.app 的標準 ADIF 檔案：

  1. 進入設定，點選 ADIF 檔案匯出。
  2. 獵人：
    • 把獵人條件設為 僅匯出 POTA 獵人，只匯出追逐到公園的 QSO（即填有 <POTA_REF> 的記錄）。
  3. 啟動者（最快的辦法是使用您的啟動中的 匯出 按鈕；下面的步驟是手動完成同樣的事）：
    • 選擇所選時間段，使之與您的啟動時段一致。
    • 在活動中選擇 POTA，並輸入您的公園編號（例如 K-1234）。qFT8 會在所有匯出記錄中自動填入 <MY_SIG>POTA、<MY_SIG_INFO> 和 <MY_POTA_REF>。
  4. 公園對公園（P2P）和公園對山峰（P2S）：在啟動期間追逐其他公園或山峰時，您啟動的公園（<MY_POTA_REF>）和對方的參考編號（<POTA_REF> / <SOTA_REF>）會同時匯出。
  5. 按匯出 QSO，分享或儲存您的日誌檔案。

啟動公園或山峰

當您在公園（POTA）或山峰（SOTA）操作時，請在 qFT8 中開始一次啟動。此後您記錄的每個 QSO，無論哪種模式，都會自動帶上您的公園或山峰；qFT8 替您計數，最後只需點選一次，就能產生這些活動要求的檔案。

開始

  1. 在設定分頁中，按 POTA 啟動 或 SOTA 啟動（就在匯出設定 / 匯入設定的上方）。
  2. 輸入您的編號，例如公園用 US-1234，山峰用 W1/HA-001。如果您同時身處多個公園（「two-fer」），請用逗號分隔。qFT8 會在您輸入時檢查格式，並提供您最近用過的編號。
  3. 按 開始。按鈕變為藍色，並顯示編號和 QSO 數量。

公園啟動和山峰啟動可以同時開啟；這時每個 QSO 都會帶上兩個編號。要在數位模式下呼叫 CQ POTA 或 CQ SOTA，請按 POTA 和 SOTA 章節的說明設定 CQ 修飾符。

qFT8 也會主動提出為您開始：如果它為世界地圖下載的 spot 中，您自己的呼號被列為啟動者，它會詢問在那裡開始 POTA 啟動? 如果您在記錄器空著的我的 POTA / 我的 SOTA 欄位中輸入公園或山峰，它會詢問是否用它開始一次啟動。

公告，讓獵人找到你

當你自己開始一次啟動（而不是從已經公告了你的 spot 開始）時，qFT8 會詢問在 POTA 上公告？（或 SOTA），並說明獵人會看到什麼，例如 FT8 on 20m (14074 kHz)。暫不 不公告任何內容。公告 會開啟一個簡短的對話方塊：

  • 頻段和模式：每項各勾選一個或多個。qFT8 目前所在的波段和模式已經勾選。qFT8 會為你所選的每個公園、波段和模式各傳送一條公告，並在你按下 公告 之前告知數量。
  • 程式未列出的模式會以 DATA 公告，真實模式寫在公告的備註中。沒有常用頻率的波段和模式組合（60 m 上的 RTTY）會被略去，對話方塊會說明。
  • 對於你目前所在的波段和模式，頻率就是電台所在的頻率；對於其他組合，則使用常用的呼叫頻率。
  • 僅 SOTA：對話方塊還會要求輸入你的 SOTAwatch 使用者名稱和密碼（你自己的 SOTA 登入）。qFT8 會為下次儲存它們，和其他服務的密碼一樣。

之後，只要啟動處於開啟狀態且 qFT8 在工作（在螢幕上，或最小化但 qFT8 在背景執行且電台已連線），qFT8 每 30 分鐘重新公告一次啟動（公告大約一小時後會從清單中消失）。結束啟用時它會停止；qFT8 關閉期間它絕不會自行公告：下次啟動時，在你選擇繼續啟動之後，它會詢問再次公告？

如果公告沒有傳送成功（沒有網路、網站拒絕，或 SOTA 登入有誤），qFT8 會說明出了什麼問題，並提供重試，或手動公告，後者會在瀏覽器中開啟該程式的 spot 頁面，方便你自己公告。沒有網路連線時，它還會每 5 分鐘自動重試。

要用其他波段或模式公告，或檢視上次公告的時間，請在啟動的卡片上（點選藍色標記）或啟用的 QSO 檢視中按下 公告。此時對話方塊還會提供停止重新公告。在已公告的啟動期間更換模式時，qFT8 會詢問是否也公告新模式。

啟動進行期間：藍色標記

只要啟動處於開啟狀態，瀑布圖右下角就會一直顯示藍色的 POTA 或 SOTA 標記，旁邊是本次啟動的 QSO 數量：POTA 10。您記錄的每個 QSO 都會計入；當某個 QSO 被移出啟動、被刪除或在記錄器中被復原時，數位會相應減少。同時啟動兩個公園時仍然只有一個數位，因為每個 QSO 同時計入兩個公園。空間不足時，標記只在圖示旁顯示數位；連這也放不下時，它會連同共用一行的紅色警告一起縮小顯示。點選它可檢視啟動的狀態：

  • 編號和計數：已完成的 QSO 數，以及該活動認定有效啟動所要求的數量（公園 10 個，山峰 4 個），還有其中多少個是與另一個公園或山峰通聯的（P2P / S2S）。
  • 檢視啟動：本次啟動的 QSO 清單（見下文）。
  • 結束啟動：結束本次啟動。它總會先詢問，按 繼續 可接著進行。
  • 關閉：關閉卡片。

啟動的 QSO

  1. 返回完整的 QSO 日誌。
  2. 啟用：活動和編號、開始時間（UTC）及其 QSO。
  3. +：開啟記錄器，把一個 QSO 直接手動記入本次啟動。
  4. 新增 QSO：按時間範圍新增日誌中已有的 QSO。忘記開始啟動時可以用它：選擇起止時間，qFT8 會在新增之前告訴您將新增多少個 QSO。
  5. 匯出：產生用於上傳的檔案（見下文）。
  6. 對方電台的公園或山峰（對方也在啟動時）。
  7. 開啟中的啟用的標記。

要把 QSO 從啟動中移出，請長按其中一個將其選取，再點選其他要移出的 QSO，按 操作 並選擇 從本次啟動中移出。這些 QSO 仍留在您的日誌中，只是去掉了您的編號。您也可以在 QSO 編輯器中，用 POTA 啟動 / SOTA 啟動一行移動單一 QSO。

結束與恢復

結束啟動 會顯示一份摘要：編號、開始和結束時間、各模式的 QSO 數，以及啟用是否有效。結束之後記錄的 QSO 不屬於本次啟動。

  • 誤點了結束，還是休息後回來了？ 24 小時之內，摘要、啟動清單以及 POTA 啟動 / SOTA 啟動 開始對話方塊都會提供 恢復啟動，可以重新開啟它，就像什麼都沒發生過。
  • 新的 UTC 日。 對 POTA 來說，每個 UTC 日是一次單獨的啟動。UTC 零點之後，qFT8 提供的不是恢復，而是在同一公園 開始新的。
  • 忘了結束。 如果 qFT8 關閉了一段時間，或者很久沒有 QSO，下次啟動時它會詢問是 繼續 還是結束。

匯出

匯出（在摘要和啟用清單中）會按各活動要求的方式命名並產生 ADIF 檔案，可直接上傳到其網站：

  • POTA：每個公園、每個 UTC 日各一個檔案，名稱為 CALLSIGN@PARK-DATE.adi（例如 K1ABC@US-1234-20261006.adi）。同時啟動兩個公園時，每個公園一個檔案。本身就在兩個公園的對方電台，會針對它的每個公園各寫入一次，這樣兩個都算作公園對公園。
  • SOTA：山峰一個檔案，命名方式相同（K1ABC@W1_HA-001-20261006.adi）。

您可以儲存或分享這些檔案。「設定」中 POTA 啟動 / SOTA 啟動 旁邊的放大鏡按鈕會列出您以往的啟動，最新的排在最前，並把每一次標為 進行中、可恢復、已匯出 或未匯出；點選其中一次即可開啟並再次匯出。qFT8 自己不會向這些活動的網站上傳。

連續多個公園

在一天之內先後去多個公園時，每個公園各是一次啟動、一個檔案：

  1. 在第一個公園，按「設定」中的 POTA 啟動，輸入它的編號並按 開始。
  2. 開始操作。每個 QSO 都會帶上這個公園，藍色標記負責計數。
  3. 離開之前，點選標記並按 結束啟動，再在摘要中按 匯出，然後儲存或分享檔案（K1ABC@US-1234-20261006.adi）。
  4. 到了下一個公園，用新的編號重新開始。

回到家後不需要重新輸入或整理任何東西。如果在野外來不及匯出，以往啟用的清單（放大鏡）可以在以後逐個匯出。

「檔案中寫哪個公園？」

一個公園的檔案只能寫一個公園。當您不透過啟動來匯出同時在多個公園完成的 QSO 時（從「設定」匯出整個日誌，或對所選 QSO 使用匯出 (ADIF)），qFT8 會詢問檔案中寫哪個公園？ 請選擇這個檔案對應的公園；另一個公園再匯出一次。日誌不會改變。從啟動本身匯出時不會詢問：它為每個公園產生一個檔案。

要在沒有啟動的情況下為每個公園各得到一個檔案，請自己輸入用逗號分隔的公園（US-1234, US-5678），可以填在匯入/匯出日誌的 POTA 參考欄位中，也可以填在對所選 QSO 使用的帶 POTA 編號匯出中：qFT8 會為每個公園產生一個檔案，其中的 QSO 相同。山峰始終只有一個編號。

當您通聯的電台同時身處兩個公園時，qFT8 會把兩個都保留下來：如果發 spot 的人把第二個公園寫在了 spot 的備註裡，它就從那裡讀取。日誌顯示第一個公園以及還有幾個（US-1234 +1）。如果公園有誤或缺失，請在 QSO 編輯器中更正該 QSO 的 POTA 欄位；它可以填寫用逗號分隔的多個公園。同一電台的同一個公園被提到兩次時（spot 中一次、備註中又一次，或在輸入的清單中出現兩次），在日誌和每個匯出檔案中都只算一次。

右側的聊天面板把收發的訊息分別歸入各自的頻道標籤：

  • [GLOBAL] 主頻道：顯示在整個音訊通頻帶內解碼到的每一次 JS8 發射，以及您自己的全部發射。在這一處就能即時縱覽波段上的所有活動。
  • 廣播群組頻道（@CQ、@ALLCALL）：用於向所有監聽的電台發出一般呼叫和通告。發到 @CQ 或 @ALLCALL 的訊息，調頻在該頻率上的任何人都能看到。
  • 自訂群組頻道（@GROUPNAME）：qFT8 支援自訂的定向群組（例如 @EMERGENCY、@SOTA、@NET）。收發帶有 @GROUP 標記的訊息時，它會自動歸入該群組專用的頻道標籤。
  • 電台直接頻道（呼號標籤）：從頻道清單或電台表格中選擇某個電台，會開啟與該呼號的專用對話。

空中發射（不保密）：所有 JS8 訊息都作為普通的業餘無線電數位訊號以明文發射。與某個電台的直接聊天只是為了方便而把對話記錄歸入專用標籤，它既不加密也不私密，任何監聽該頻率的電台都能收到。

撰寫和傳送訊息

  1. 選擇目標：在右側面板中點選一個頻道標籤（[GLOBAL]、@CQ、@ALLCALL、某個群組或某個電台的呼號）。
  2. 輸入訊息：在底部的輸入欄位中輸入文字（支援全部標準 ASCII 字元，最多 100 個字元）。
  3. 傳送：點選傳送按鈕。

點選訊息（快速聊天和詳情）

點選聊天記錄中的任何一條訊息（在電腦上：按兩下），會開啟詳情對話方塊，顯示完整的 UTC 時間戳記、音訊頻率、SNR、Maidenhead 網格和訊息內容：

  • 收到的訊息（RX）：點選 CHAT 可立即開啟與發信電台的直接聊天標籤；如果訊息是發給群組的，則點選 GROUP CHAT。
  • 發出的訊息（TX）：點選 RESEND 會自動把文字填回輸入欄位並選好目標頻道，方便重新傳送。

多區塊訊息的連續傳送

如果您的訊息太長，一個 JS8 發射訊框放不下：

  • qFT8 會自動把訊息拆成連續的多個區塊訊框。
  • App 會在接連的時隙中自動依次發出每個區塊，直到整條訊息發完。
  • 進度指示會顯示這次多時隙發射的進展（例如 TX (1/3)）。
  • 如果需要在全部區塊發完之前停止，點選傳送/停止按鈕會彈出提示，可以取消佇列中剩餘的發射。

管理頻道（長按操作）

在右側面板中長按（按住不放；在電腦上：按滑鼠右鍵）任何電台呼號標籤或群組頻道標籤，會開啟帶有管理選項的選單：

  • 清除聊天：清除所選頻道標籤的訊息記錄。
  • 關閉聊天：關閉該標籤，並把它從活動頻道欄中移除。
  • 匯出聊天：把所選頻道的全部訊息記錄匯出為文字檔案，或透過分享面板傳送。

自動回答查詢（AUTO 模式）

啟用 AUTO 按鈕後，qFT8 會自動回答其他電台發來的定向查詢（例如 SNR?、HW CPY?、GRID?、INFO?、STATUS? 和 HEARING?）以及心跳訊息（@HB HEARTBEAT）。

例如，如果另一個電台發來 YOURCALL SNR? 或 YOURCALL HW CPY?（YOURCALL 即您的呼號），qFT8 會自動把您的訊號報告回答（例如 SNR -08）排入佇列並發出，無需手動操作。同樣，收到心跳發射（@HB HEARTBEAT）時，qFT8 會自動把心跳確認（HEARTBEAT SNR -08）排入佇列，向發射電台報告接收情況。

定向查詢和「請求」按鈕

請求按鈕可以讓您快速向目前選定的目標電台或群組傳送標準的定向查詢，不必手動輸入指令：

  • SNR? / HW CPY?：請對方電台給出訊號報告。
  • GRID?：要求對方電台的 Maidenhead 網格定位。
  • INFO?：要求對方電台設定的資訊文字。
  • STATUS?：要求對方電台的工作狀態文字。
  • HEARING?：查詢對方電台在最近 10 分鐘內收到的電台清單。

WSPR 模式

WSPR（Weak Signal Propagation Reporter，弱訊號傳播報告）是一種專門的數位協定，用極低功率的發射來探測電波傳播路徑。WSPR 訊號採用窄頻 4-FSK 調變、穩健的迴旋編碼和循序 Fano 解碼，能解出遠低於雜訊底限的訊號，低至 −28 dB SNR。

2 分鐘週期與定時

WSPR 發射在同步的 2 分鐘 UTC 時隙內進行（發射持續 110.6 秒，共 162 個音調符號）。發射總是在偶數 UTC 分鐘過後整一秒開始（:00, :02, :04, :06...）。由於一次發射持續將近兩分鐘，小功率電台必須被允許發射這麼長時間：見連續發射時間上限。頻譜圖的垂直滾動會自動調整為平滑的慢速滾動，與 120 秒的週期相符。

單面板活動檢視

WSPR 是信標和傳播報告協定，而不是雙向對話的模式，因此 qFT8 提供一個簡潔的全寬單面板活動記錄，不再分出 QSO 日誌：

  • 呼號：電台的呼號。
  • DXCC 實體：自動識別出的國家 / DXCC 實體名稱（寬度自動調整）。
  • 網格定位：4 字元的 Maidenhead 網格（例如 JN45）。
  • SNR：接收訊號的訊雜比，單位 dB，與其他 WSPR 接收機一樣，以 2,500 Hz 頻寬內的雜訊為基準測量。
  • 功率：電台回報的發射功率，單位 dBm（例如 37 dBm）。
  • 日期和 UTC 時間：發射時隙的 UTC 時間戳記，格式為 yyMMdd HH:mm。

自動信標和發射比例（Tx %）

在 WSPR 活動介面頂部的標題列中：

  • 信標開關：開啟或關閉自動信標發射。開啟時（以亮綠色醒目標示），qFT8 會依您設定的發射比例，以確定的間隔自動安排信標發射。
  • Tx % 選擇器：設定確定性的發射工作週期，依距上次發射經過的時間計算（0% [Rx Only]（僅接收）、10%、20%、25%、33%、50% 或 100% Continuous（連續））。例如，20% 表示從上次發射起每 10 分鐘發射一次（50% = 每 4 分鐘，33% = 每 6 分鐘，25% = 每 8 分鐘，10% = 每 20 分鐘，100% = 每個 2 分鐘週期都發射）。
  • Tx 下次按鈕：安排在下一個 2 分鐘週期開始時立即手動發射一次。發射之後，自動的確定性信標安排從該週期起繼續。

向 WSPRnet 和 PSKReporter 上傳 spot

qFT8 可以把收到的 spot 自動上傳到全球的 WSPRnet 資料庫和 PSKReporter：

  • 從 WSPRnet 下載 Spot：預設開啟，即時取得與您的呼號和波段有關的 spot，顯示在世界地圖上。
  • 上傳報告至 WSPRnet：在設定 → WSPRnet 中啟用後，收到的 spot 會成批上傳到 WSPRnet，並帶有 15 分鐘去重和速率限制。
  • 開啟 WSPRnet：直接在瀏覽器中開啟 WSPRnet 資料庫，並已依您電台的呼號篩選。

單獨的 ADIF 匯出

點按 WSPR 活動面板右上角的 匯出 按鈕，可以把本次工作階段記錄的所有 spot 匯出為標準 ADIF 格式（.adi），用於傳播研究和存檔。

SSB（語音）

在 SSB 模式下，qFT8 就是您收發信機的麥克風和喇叭：電台收到的訊號在您的喇叭或耳機中變成語音，您的聲音從您的麥克風送到電台。電台的連接方式與數位模式完全相同（同一條 USB 線、同一張音效卡），因此在 FT8 和語音之間來回切換時，不需要重新插拔任何東西。

用底部列的模式選擇器選擇 SSB。訊息區域、序列按鈕和週期進度條會消失（語音沒有時隙），模式選擇器旁邊出現 USB / LSB 按鈕，「電台」分頁變為 SSB 面板：

SSB 介面的各個組成部分如下：

  1. RX / TX / RX/TX：選擇調諧輪（第 12 項）移動的對象。選 RX/TX 時，收發在同一頻率上。選 RX 或 TX 時只移動其中一個，這樣可以在一個頻率上收聽、在另一個頻率上發射（異頻操作）。
  2. AUTO RIT：讓稍微偏離頻率的電台保持置中，不用碰調諧輪，對方的聲音聽起來也自然。
  3. 齒輪：開啟設定 > SSB（見下文）。返回回到此面板。
  4. QSO：開啟已填好模式、邊帶和頻率的記錄器，記錄您剛完成的通聯（見記錄器）。每按一次記錄一個 QSO。
  5. 語音記憶：您錄製的語音（CQ 呼叫、您的呼號……）。在錄製第一則之前，這個區域顯示連結在設定中設定語音記憶。
  6. IN：您麥克風的音量及其增益滑桿。標有 VOX 的線，是 VOX 開啟時（第 10 項）您的聲音必須超過才能讓電台發射的音量：可以拖曳它。
  7. OUT：接收音訊的音量和您喇叭的音量滑桿。手機的音量鍵作用相同。
  8. FILTER 和 NR：接收濾波器（關、2.7、2.4 或 1.8 kHz）和降噪（關、1、2 或 3）。每點按一次切換到下一個值。
  9. PTT：按鍵通話。依 PTT 模式設定，它顯示「按住說話」或「點按說話」，發射時顯示「發射中」。在電腦上，面板取得焦點時空白鍵的作用相同。
  10. VOX：開啟後，由您的聲音而不是 PTT 按鈕控制電台發射。
  11. USB / LSB：邊帶。更換波段時會自動替您選好（10 MHz 以下為 LSB，以上為 USB）；點按即可切換，而您讀到的頻率保持不變。
  12. 調諧輪：在 SSB 中，頻譜圖的頻率刻度是一個轉輪。沿著它滑動即可調諧電台；滑得越快，步進越大。點按不起作用，所以頻率不會意外跳變。在電腦上也可以用滑鼠滾輪調諧（按住 Shift 為 1 Hz 步進）。調諧需要與電台的 CAT 連線。
  13. 頻率和波段：您在空中報出的頻率（載波頻率）和波段。橙色線及其下方的 RX/TX 標籤，標出您正在收聽和發射的那一段頻譜圖。

通話

  1. 用底部列的 TX 按鈕開啟發射。和其他所有模式一樣，它顯示 TX OFF 時不會有任何發射：紅色的一行按 TX ON 發射會提醒您。
  2. 按住 PTT 講話，講完鬆開。或者開啟 VOX，直接講話。
  3. 要發送一則語音記憶，點按它即可。TX ON 時它會被發射出去，您也能在喇叭裡聽到。TX OFF 時它只播放給您聽，適合用來檢查錄音。長按（在電腦上是按滑鼠右鍵）則一律只播放給您聽。

您自己的即時語音絕不會在您的喇叭中回放。如果您要發射的頻率在業餘波段之外，qFT8 不會讓電台發射，並會告訴您。

PTT 限時：使用點按切換和 VOX 時，發射會在 PTT 限時（除非您更改，否則為 100 秒）到達後自動停止，PTT 按鈕上會倒數剩餘秒數。到達限時後，VOX 會暫停同樣長的時間，或直到您點按 PTT。這樣可以保護電台，避免麥克風一直拾取到雜訊而持續發射。電台自身的連續發射時間上限同樣有效：以兩者中較短的為準。

語音記憶

進入設定 > SSB > 語音記憶（或在面板中點按在設定中設定語音記憶），按 錄製新語音記憶。最多可儲存 6 則記憶，每則 30 秒。每一則都可以命名、重新錄製、設定音量或按 正規化，還可以拖曳聲音波形圖上的兩個控點，裁掉開頭和結尾的靜音；播放 播放您保留的部分，儲存之前不會有任何改變。記憶連同錄音一起包含在設定匯出中。

設定 > SSB

  • PTT 方式：PTT 按鈕，或 VOX。
  • PTT 模式：按住說話或點按切換。
  • PTT 延遲：讓電台轉入發射到送出您的聲音之間的時間。您說的話不會遺失：第一個音節會等電台準備好。
  • PTT 限時：見上文（10 至 600 秒）。
  • 邊帶：依波段自動選擇、一律 USB 或一律 LSB。
  • 進入 SSB 時的濾波器和進入 SSB 時的降噪。
  • 在喇叭上播放接收到的聲音和發射時喇叭靜音。
  • 語音記憶和 恢復預設設定。

SSB 需要什麼

  • 不是電台音效卡的麥克風和喇叭。手機自帶這兩樣；耳機麥克風也可以。見喇叭和麥克風。如果電台與您的麥克風或喇叭是同一個裝置，會有一行紅字提示，並且不會發射或播放任何聲音。
  • 一台電台。沒有電台時，面板會被一張卡片取代，上面寫著請連接電台以使用 SSB；電台接好後面板會自動恢復。沒有 CAT、靠自身 VOX 轉入發射的電台也可以用，只是應用程式無法為它調諧。
  • QMX 或 QMX+ 需要 1_02_000 或更新的韌體才能從應用程式發射語音。韌體較舊時，底部列顯示無 SSB，該模式只能接收。
  • 第一次在 SSB 下進入某個波段時，qFT8 會調諧到該波段在您所在地區常用的語音頻率；此後則回到您上次在該波段使用的頻率。30 公尺波段沒有語音段，因此不提供。

QSO 以 SSB 連同邊帶記入日誌，並像其他 QSO 一樣上傳到 QRZ 和 LoTW。

CW（摩斯電碼）

在 CW 模式下，qFT8 會抄收通帶內的每一個摩斯訊號，並把文字寫在頻譜圖上；發報可以用螢幕上的電鍵槳、您自己的按鍵、預設訊息或輸入的文字。TX OFF 時一切都可以當作練習：您在喇叭裡聽到自己拍發的電碼，但什麼都不會發射出去。

用底部列的模式選擇器選擇 CW：

CW 介面的各個組成部分如下：

  1. AUTO：讓 qFT8 自己完成整個 CW QSO（見 CW 中的 AUTO）。
  2. RX / TX / RX/TX：選擇點按瀑布圖或轉動調諧輪時移動哪一條標線：接收標線、發射標線，或兩者一起。
  3. 齒輪開啟設定 > CW，QSO 開啟已填好 CW、頻率和目標的記錄器。
  4. 目標：您正在通聯的電台的呼號。它會填入您訊息中的 [TARGET] 部分。點按它可輸入呼號，也可以點按解碼行（第 10 項）中的呼號，直接取用。
  5. 記憶：預設訊息。點按即發送。您自己的呼號顯示為藍色，訊號報告顯示為黃色。還缺內容的記憶（目標、您的名字……）會變暗；點按它可以看到缺什麼。
  6. WPM 和 FARNSWORTH：以每分鐘字數表示的發報速度，以及可選的 Farnsworth 速度（字元保持原速，字元之間的間隔加長）。
  7. FILTER 和 NR：接收標線兩側接收濾波器的寬度，以及降噪。
  8. 電鍵槳：左槳發點，右槳發劃。同時按下兩槳用於 Iambic 模式。
  9. 紅色的一行：按 TX ON 發射。它顯示時，您的拍發只是練習。
  10. 解碼行：位於 FT8 中訊息選擇器所在的位置。它用綠色顯示您濾波器內那個電台的文字，用紅色顯示您發出的內容，最新的在右邊。
  11. 瀑布圖上的解碼文字：每個訊號的文字都沿著它自己的軌跡寫出，因此您可以一次讀到整個波段。接收標線下方的標籤顯示您所在的那個電台的呼號和速度。
  12. 調諧輪：即頻率刻度。沿著它滑動可移動所選的標線（標線到達邊緣時也會帶動電台）。在瀑布圖上點按或拖曳可直接移動標線。
  13. 跳到頻率：點按帶有白色訊號強度線的窄條，可輸入以 kHz 為單位的頻率。

發送

發報有四種方式，都使用由 WPM 設定的速度：

  • 螢幕上的電鍵槳，用一根或兩根手指。
  • 您自己的按鍵：鍵盤按鍵、滑鼠按鍵（在電腦上，左鍵是左槳，右鍵是右槳），或透過 USB 或藍牙連接、表現為鍵盤的電鍵轉接器。見電鍵槳和電鍵器。
  • 一則記憶：點按它。此時再點按第二則記憶，它會排隊等候。發送文字期間會出現帶 停止 的窄條，觸碰電鍵槳也會停止發送。
  • 鍵盤（在記憶列表的末尾）：輸入訊息並按 發送。輸入框下面的一行準確顯示將要發出的內容。在 Android 上，語音 可透過說話完成同樣的事：說出訊息，它就以摩斯電碼發出。

在空中，無論您選擇聽什麼樣的側音，CW 始終是邊緣柔和的純淨單音。作為保險措施，電鍵按住 10 秒會被鬆開，一次發射在 3 分鐘後會被停止。

在 TX OFF 下練習

底部列顯示 TX OFF 時，電鍵槳、您的按鍵、記憶和鍵盤輸入框都可以使用，但只在您的喇叭上發聲。您拍發的內容會被解碼並以紅色顯示在解碼行中，這樣您可以看出自己的手法是否清晰可辨。沒有任何訊號到達電台。做這件事根本不需要電台。

電鍵槳和電鍵器

在設定 > CW 中，鍵控器一節設定電鍵槳的行為：

  • 鍵控器模式：手動電鍵、Iambic A、Iambic B、兩者的單指版本、Ultimatic、Bug（半自動）和 Cootie（側擺鍵）。
  • 速度、Farnsworth、詞間隔和嚴格定時（字元之間和詞之間使用標準間隔）。
  • 反轉左右槳：對調點和劃。
  • 插入延遲：您發出最後一個點或劃之後，電台保持發射狀態的時間。
  • 速度匹配：以您正在抄收的電台的速度發報。

槳式輸入一節設定哪些東西可以當作電鍵槳：

  • 槳：總開關。關閉後，螢幕上沒有電鍵槳，任何按鍵、滑鼠按鍵或轉接器都不能讓發射機發射。
  • 螢幕槳、滑鼠按鍵、鍵盤按鍵和外部轉接器 (USB / Bluetooth)：每種來源都可以單獨關閉。
  • 按鍵對應：預設使用一份現成的按鍵列表（其中包括 [ 和 ]、左右 Ctrl 鍵、F1 和 F2）。選擇自訂後，您可以為左槳和右槳建立自己的列表：按 新增按鍵，再按您想用的鍵。已經分配給另一側槳的鍵會被拒絕。

文字框開啟時，只有 Ctrl 鍵和 F1 / F2 可作為電鍵槳，因此輸入呼號時絕不會發出摩斯電碼。

用轉接器、鍵盤或滑鼠拍發

發送摩斯電碼不一定要點按螢幕。下面四樣東西都可以當作電鍵槳，而且可以同時使用：

  • 螢幕上的電鍵槳，用手指操作。
  • 接在 USB 電鍵轉接器上的真電鍵或真電鍵槳：轉接器是一個小盒子或一條線，一頭是接電鍵的插孔，另一頭是 USB 插頭。對手機或電腦來說，它就是一個鍵盤（電鍵的每個觸點按下一個鍵盤按鍵）或一個滑鼠（每個觸點按下一個滑鼠按鍵）。藍牙轉接器的運作方式相同。
  • 鍵盤：一個鍵當左槳，一個鍵當右槳。
  • 滑鼠：它的左鍵和右鍵。

它們都遵循您選定的鍵控器模式和速度，並且在 TX OFF 時都可以用來練習（見在 TX OFF 下練習）。

連接轉接器

  1. 把電鍵或電鍵槳插到轉接器上，再把轉接器插到手機、平板或電腦上。不需要安裝任何東西，qFT8 也不會要求任何權限：轉接器就是一個普通的鍵盤或滑鼠。如果手機唯一的 USB 埠已被收發信機佔用，請使用 USB 集線器或藍牙轉接器。
  2. 開啟 CW 介面，開始拍發。表現為鍵盤的轉接器，只要發出的是下面預設列表中的按鍵，就可以直接使用（常見的是左右 Ctrl 鍵，以及 [ 和 ]）。已用原裝 VBand 轉接器測試過。
  3. 如果沒有聲音，說明轉接器發出的是別的按鍵。進入設定 > CW > 槳式輸入，在左槳（點）下按新增按鍵，然後閉合電鍵的點觸點；再在右槳（劃）下用劃觸點做同樣的操作。
  4. 表現為滑鼠的轉接器需要螢幕上的電鍵槳：把滑鼠游標停在左槳上，然後拍發。一般滑鼠也是如此。

手鍵、電鍵槳、半自動鍵

無論您用什麼拍發，兩側各起什麼作用都由鍵控器模式（設定 > CW > 電鍵器）決定：

  • 手動電鍵：只有一個鍵，每個點和每個劃都由您手動拍出。只有左槳一側起作用：請把手鍵接到轉接器的點觸點上，或者把它對應的按鍵放進左槳（點）列表。在螢幕上，兩片槳合併成一個鍵。
  • Iambic A 和 Iambic B：用於雙槳電鍵。左側發點，右側發劃，兩側同時按下則點劃交替。Iambic A，單指 和 Iambic B，單指 是為螢幕準備的，螢幕中間有一塊區域算作同時按下兩側槳（其寬度由中間區域（單指模式）設定）。
  • Ultimatic：與電鍵槳相同，但兩側同時按下時，以後按下的一側為準。
  • Bug（半自動）：點一側自動發出點；劃一側是手動鍵，按住多久就響多久。
  • Cootie（側擺鍵）：兩側是同一個手動鍵。

依自己的習慣設定

全部選項都在設定 > CW的槳式輸入一節中：

  • 槳：以下所有選項的總開關。
  • 螢幕槳和槳高度：只用真電鍵時，可以隱藏電鍵槳，給瀑布圖留出更多空間；也可以把它調高一些，方便手指操作。使用滑鼠時必須顯示電鍵槳。
  • 滑鼠按鍵：如果不希望點按電鍵槳有任何作用，就把它關掉。
  • 鍵盤按鍵和外部轉接器 (USB / Bluetooth)：決定哪些裝置可以拍發。Android 與電腦的區別見下文。
  • 按鍵對應：預設就是上面的表格。它下面有兩個列表，左槳（點）和右槳（劃）。按新增按鍵後，它會等您按下一個鍵（或閉合電鍵的一個觸點），然後把這個鍵加入列表；按鍵旁邊的垃圾桶可將其移除。第一次改動會把對應切換為自訂，它最初是預設列表的副本。改回預設不會清除您自己的列表。可以使用字母、數字、F1 到 F12、方向鍵、Ctrl、Shift、Alt、數字小鍵盤、空白鍵、Enter、Tab 以及常用的標點鍵。一個鍵只能分配給一側槳。

鍵控器一節中還有兩個選項：反轉左右槳一次對所有輸入來源對調點和劃（適用於接線相反的電鍵槳，或左手操作的人），鍵控器模式已在上文說明。頁面末尾的恢復預設設定會把 CW 的所有設定恢復原狀，包括按鍵列表。

Android 與電腦

  • 在 Android 上有兩個開關：鍵盤按鍵指裝置自帶的鍵盤，外部轉接器 (USB / Bluetooth)指您插上或配對的任何鍵盤或轉接器。在 Android 10 之前，所有實體鍵盤都算作外部裝置。USB 或藍牙滑鼠可以像在電腦上一樣在電鍵槳上使用。
  • 在電腦上，轉接器只是又一個鍵盤，所以兩者共用一個開關：鍵盤按鍵。螢幕上的電鍵槳用滑鼠按。只有當帶 CW 介面的 qFT8 視窗是使用中視窗、並且沒有開啟任何對話方塊時，按鍵才起作用。

如果有什麼不正常

  • 點和劃反了：勾選反轉左右槳。使用滑鼠時，請確認游標在左槳上，而不是在右槳上。
  • 拍發時沒有任何反應：CW 介面必須正在顯示，槳和您所用來源的開關必須開啟，AUTO 必須關閉（否則螢幕上會顯示關閉 AUTO 以手動發射）。在電腦上，請先點按 qFT8 視窗。然後檢查您的按鍵是否在列表中：按新增按鍵並拍發。如果對話方塊沒有反應，說明轉接器發出的是無法使用的按鍵，或者轉接器沒有連接好。
  • 能聽到摩斯電碼，但電台不發射：紅色的一行顯示按 TX ON 發射。這是練習狀態。
  • 在 手動電鍵 模式下手鍵沒有反應：它接在了右槳一側。請把它改到左槳一側（見上文）。
  • 拍發時字母被輸入到文字框裡，而沒有發送：文字框開啟時，只有 Ctrl 鍵和 F1 / F2 是電鍵槳，這樣輸入呼號時絕不會發出摩斯電碼。請關閉文字框，或者讓轉接器使用這幾個鍵之一。
  • 拍發時字元被輸入到別的程式裡：在電腦上，按鍵會送到使用中視窗。請點按 qFT8。
  • 按住電鍵時聲音中斷：電鍵按住 10 秒會被鬆開，並出現提示電鍵按下過久：已鬆開。

記憶、巨集和勤務符號

在設定 > CW > 記憶中編輯您的訊息（新增記憶，或點按某一則進行修改）。訊息中可以使用兩類特殊詞：

  • 方括號中的巨集在訊息發出時被替換：[MYCALL] 是您的呼號，[TARGET] 是「目標」框中的呼號，[RST] 是要發出的訊號報告，[NAME] 是您的名字，[QTH] 是您的位置，[EXCH] 是您的比賽交換內容，[MYPOTA] 是您目前開啟的啟動的公園或山峰。編輯器為每個巨集都提供了按鈕，並準確顯示訊息發出時的樣子。
  • 角括號中的勤務符號作為一個字元連續發出，中間沒有間隔：<BK>、<SK>、<KN>、<AR>。

您的訊號報告、名字、位置和交換內容只需在同一個設定頁面中輸入一次。需要其中某一項的預設訊息會保持變暗，直到您填好為止；點按它會帶您到填寫的地方。POTA 或 SOTA 啟動開啟期間，第一則記憶會提供一則 CQ POTA 訊息。

接收

解碼是自動的，並跟隨每個電台自己的速度。您濾波器內的那個電台，就是底部列解碼行中顯示的那個；把接收標線移到另一個訊號上，就改為跟隨它（該頻率上已經抄收到的內容會立即顯示）。濾波器內有兩個電台時，底部列會提示。接收到的訊號以您選擇的監聽音高在喇叭中播放，與您自己的側音音高相同，因此聽起來與您的側音同音的電台，正好在您的頻率上。

設定 > CW 中還有音調（您的側音聽起來如何：音高、音量、柔和或陡峭的邊緣、單音或發聲器的喀嗒聲）、解碼與顯示（自動解碼、為瀑布圖上每個訊號顯示文字的多路解碼器、水平頻譜圖、進入該模式時的濾波器）、監聽（喇叭）和勤務符號與標點。

CW 中的 AUTO

面板左上角的 AUTO 按鈕讓 qFT8 完成完整的 CW QSO。每次進入該模式時它都是關閉的。點按它即開啟（變為綠色），再點按一次即關閉。它只在 TX 為 ON 時才會發射：AUTO 絕不會自行開啟發射。

在它開啟且 TX 為 ON 期間，qFT8 會：

  • 在頻率空閒時呼叫 CQ，或應答它聽到的 CQ；
  • 交換訊號報告、名字和位置，道別，並把 QSO 記入日誌；
  • 對沒有抄收到的呼號或訊號報告再次詢問，並回應對方要求重發或放慢速度的請求；
  • 發報速度絕不超過您的 WPM，並會降到對方電台的速度；
  • 跟隨頻率漂移的電台，不呼叫當天已經通聯過的電台，也不在別人的 QSO 上開始發射；
  • 絕不把沒能完成的 QSO 記入日誌。

AUTO 開啟期間電鍵槳被停用，並有一行文字提示 關閉 AUTO 以手動發射。停止 也會關閉 AUTO。如果您從不需要它，可在設定 > CW 中關閉顯示 AUTO 模式，按鈕就會隱藏。

RTTY

RTTY（無線電傳打字）用兩個交替的音調傳送文字。在 qFT8 中它與 CW 共用同一個介面，只是沒有電鍵槳：通帶內的每個 RTTY 訊號都會依各自的速度和頻移解碼，並沿著它的軌跡寫在瀑布圖上。

RTTY 介面的各個組成部分如下：

  1. 目標 和 交換：您正在通聯的電台的呼號，以及比賽交換內容。它們會填入您訊息中的 [TARGET] 和 [EXCH]。
  2. BAUD：速度：45.45（常用）、50 或 75。每點按一次切換到下一個。
  3. 頻移：兩個音調之間的間距：170 Hz（常用）、200、425 或 850 Hz。
  4. REV：對調兩個音調，用於對方以相反方式發送的情況。
  5. FILTER 和 NR：接收濾波器和降噪。
  6. 記憶：預設訊息，使用與 CW 相同的巨集。點按即發送。有空白欄位的訊息會變暗。鍵盤（以及 Android 上的 語音）在列表末尾。
  7. 解碼行：接收標線下那個電台的文字，顯示為綠色；您發出的內容，顯示為紅色。
  8. 接收標線及其標籤：標籤顯示標線下電台的呼號、速度和頻移。在訊號附近點按，標線會落到訊號的中心。
  9. 點按以匹配：當標線下的電台使用的速度、頻移或音調順序與您的不同時，會有一行橙色文字提示。點按它，qFT8 就採用該電台的參數，這樣您就可以應答它。
  10. 其他訊號：它們的文字沿各自的軌跡寫出。50 Bd 或 425 Hz 這樣的橙色標籤，表示該訊號與您的設定不同。
  11. 頻率：在 RTTY 中，頂部顯示的是 mark（傳號）頻率，這是操作員通常報出的頻率，也是寫入日誌的頻率。

發送

先開啟 TX，然後點按一則記憶，或開啟 鍵盤，輸入後按 發送。文字發出期間會顯示帶 停止 的窄條。TX OFF 時，同樣的操作只是預覽：訊息在您的喇叭中播放並以紅色顯示，不會有任何發射。RTTY 碼表中沒有的字元會被略去並列出。

RTTY 是滿功率的連續發射，因此受電台連續發射時間上限的約束：長度超過上限的訊息不會開始發送，發射在到達上限時停止。

設定 > RTTY

  • 數據機：速度、頻移、反相、數字表（國際（ITA2） 或 美國：兩者有五個符號不同，雙方電台必須使用同一種），以及接收時和發送時的空格後回到字母（空格之後文字回到字母，因此遺失一次換檔最多只會弄錯一個詞）。播送數字組的電台，例如氣象台，不會在每個空格後重複換檔：接收時空格後回到字母開啟時，它們的數字組會顯示成字母，所以要讀這些內容時請把它關閉。
  • 發射：每次發射的開頭和結尾換行、無內容可發時發送空閒字元，以及達到一定字元數後自動換行。
  • 解碼與顯示、監聽（喇叭）、記憶及其取值（訊號報告、名字、位置、交換內容）和 恢復預設設定。

用 QSO 按鈕記錄的 QSO 以 RTTY 記入日誌。RTTY 中沒有 AUTO。

設定 > JTTY

JTTY（模式選擇器中的 JTTY（實驗性） 一行）使用同一個面板，搭配 JTTY 數據機。它的設定有單獨的頁面，在設定列表中 RTTY 的旁邊；面板執行 JTTY 時，面板的齒輪按鈕會開啟該頁面。頁面中只有 JTTY 用到的內容：解碼與顯示、監聽（喇叭）、帶數值的 記憶，以及 恢復預設設定；RTTY 的 數據機 和 發射 設定不適用於它。第一次使用 JTTY 時，它會沿用您在 設定 > RTTY 中改過的內容（例如記憶內容、姓名和位置）；您沒改過的部分從 JTTY 自己的預設值開始，例如每則都能放進一則 JTTY 訊息的簡短記憶。此後，改動其中一個不會改動另一個。

SSTV（影像）

SSTV（慢掃描電視）把一幅靜止影像變成聲音逐行傳送，耗時一到四分鐘。您處於該模式時，qFT8 會自動接收圖片，並可發送您相簿中的圖片，圖片上寫有您的呼號。

用底部列的模式選擇器選擇 SSTV。面板的左半部分用於發送，右半部分用於接收：

SSTV 介面的各個組成部分如下：

  1. 發送：發送圖片所用的模式及其尺寸。模式用第 12 項選擇。
  2. 載入：提供「選擇圖片」（從相簿或檔案）、「拍照」（在帶相機的手機或平板上）和「現成圖片」：約二十幅由 qFT8 依模式大小繪製、印有您的呼號的圖畫（CQ 卡片、qFT8 標誌、風景、視錯覺圖、QSL 卡、73 等）。您也可以從其他應用程式把圖片分享給 qFT8；如果當時正在使用別的模式，qFT8 會先詢問再切換到 SSTV。
  3. 待發送的圖片，按發送時的樣子原樣顯示。點按它可讓圖片適配該模式的畫幅：完整顯示、裁剪（拖曳可移動，雙指捏合可縮放）、旋轉，以及調整亮度和對比。
  4. 文字樣式：用箭頭逐一切換把呼號寫在圖片上的方式（底部橫條、角落、大號描邊……或不寫呼號）。鉛筆按鈕可新增自由文字。
  5. 移除 移除已載入的圖片。發送 顯示發射需要多少秒；發射期間它變為 停止，並顯示剩餘秒數。
  6. 紅色的一行：按 TX ON 發送圖片。其下的剩餘空間排滿小圖片：先是您最近載入的圖片，然後是現成圖片。點一下就把其中一張載入為待發送的圖片（在您按 發送 之前絕不會發送）。圖片的形狀與模式不同時，會先開啟調整畫幅的步驟。
  7. 接收狀態：守聽中，或 正在接收 並顯示模式、對方電台的頻率偏差以及正在繪製的行。
  8. 接收到的圖片，隨到隨畫。圖片下方是時間、模式和進度；圖片接收完成後，還有呼號列。
  9. 儲存 把圖片存入裝置的圖片資料夾（圖片還在接收時按下，會在接收結束後儲存）。編輯 可改善接收到的圖片（對比、亮度、色彩、色調、銳利化、去雜訊）；接收到的原圖始終保留，因此每項修改都可以復原。回覆 把接收到的圖片載入為待發送的圖片，並在您的呼號旁邊寫上對方電台的呼號。
  10. 保留的圖片：最近接收到的圖片。點按其中一張可重新顯示。
  11. 齒輪開啟設定 > SSTV，QSO 開啟模式為 SSTV 的記錄器。
  12. SSTV 模式選擇器：Martin、Scottie、Robot、PD、Wraase 和 Pasokon 各模式。它旁邊的訊息區域說明目前的狀態（「守聽中」、「正在接收」、帶剩餘秒數的「正在發送」）。
  13. SSTV 頻段：圖片在 1100 至 2300 Hz 之間發送和接收。每張聽到或發出的圖片都會在瀑布圖上得到一個標有模式的方框。

接收圖片

不需要任何設定。qFT8 根據每次發射的起始訊號識別模式；圖片開始之後您才調諧進來時，它也能識別（已經錯過的行保持空白）。頻率略有偏差的圖片，或由時序略有偏差的電台發出的圖片，會被自動校正。如果兩個電台在明顯不同的頻率上同時發送，兩張圖片都會被接收並保留；點按瀑布圖上的方框可選擇顯示哪一張。

應用程式會自動保留最近的圖片。開啟自動將每張接收到的圖片儲存到裝置後，它們還會寫入圖片資料夾；否則由您儲存想要的圖片。

這是誰的圖片？呼號欄

許多電台會在圖片前後表明身份：在圖片之前或之後用莫爾斯電碼，或在圖片之後發一小段資料脈衝。這兩種 qFT8 都能讀取，並把呼號寫在圖片下方時間和模式旁邊的欄中。什麼都沒聽到時，該欄顯示 呼號未知。點按該欄可自己輸入呼號（它通常寫在圖片上）或加以更正；您輸入的內容會替換聽到的內容。

儲存的圖片以日期和時間（UTC）、波段、以 kHz 表示的頻率、模式和呼號命名，例如 2026-10-05_1431_20m_14230_M1_F4ABC.png；沒有呼號時為 ..._UNKNOWN.png。如果呼號是在圖片儲存之後才收到或輸入的，已儲存的檔案會被重新命名，不會另存一份。

傳送圖片

  1. 用底部欄的選擇器選擇模式。如果您是回應某個電台，請使用它所用的模式。Robot 36、Martin 1 和 Scottie 1 是常用的模式。
  2. 點按 傳送 下方的小圖片之一，或按 載入，選取圖片，如有提示則調整畫幅。
  3. 用箭頭選擇您的呼號的顯示方式。
  4. 開啟 TX 並按 傳送。

關閉 TX、按 停止，或更換波段或模式，都會立即停止傳送圖片。如果您按 傳送 時正有圖片在接收，qFT8 會先詢問再停止接收。

長模式與小功率電台：一張圖片就是一次滿功率的連續發射：Robot 36 約 40 秒，Martin 1 約兩分鐘，最慢的模式超過四分鐘。比您電台的連續發射時間上限還長的模式在列表中顯示為灰色，選擇它時會說明原因。QMX 在預設的 60 秒下，短模式無需更改即可使用。

設定 > SSTV

  • 用 CW 傳送您的呼號：關閉、在圖片之前（預設）、在圖片之後，或前後都發。只發呼號，速度 20 WPM；它占用的秒數計入發射時間。
  • 每張圖片後傳送 FSK ID：一小段資料脈衝，讓對方電台的程式讀出您的呼號。
  • 文字樣式、自動對比度和自動銳化。
  • 自動將每張接收到的圖片儲存到裝置，以及應用中保留的接收圖片數量。

QMX 或 QMX+ 需要 1_02_000 或更新的韌體才能傳送圖片；韌體較舊時，SSTV 只能接收。

功能說明

不與某一種模式繫結的設定和工具：裝置配置中針對每臺電台分別儲存的兩項設定、從另一臺裝置操作 qFT8 的網頁、讓您把電台留在另一個房間的 bridge，以及螢幕的佈局。

頻譜圖調諧偏移

在設定 > 裝置配置的調諧（此電台）下，頻譜圖調諧偏移可把頻譜圖顯示的內容向下或向上移動最多 300 Hz。預設值：QMX 系列為 −100 Hz，IC-7300 為 −90 Hz，其他電台為 −50 Hz；您設定的值（包括 0）會保留，並為每臺電台分別儲存。

大多數電台會切掉音訊的最低部分，因此頻譜圖最初幾百赫茲內的訊號很弱，甚至看不到。例如偏移設為 −100 Hz 時，qFT8 會把電台調低 100 Hz，並把音訊移動相同的量，這些訊號就移到了電台能聽清的部分。

其他一切不變：顯示的頻率、各電台的頻偏、spot、您的發射頻率和日誌都與之前完全一樣。只有電台自身的螢幕讀數相差一個偏移量。偏移在所有模式下都有效，並且需要 CAT 連線；使用 VOX 或揚聲器時它不起作用。

連續發射時間上限

這是保護發射機的一項安全設定。小功率電台是按帶間歇的短時間發射設計的：一次 FT8 發射不到 13 秒，之後至少休息 15 秒。有些模式會讓電台以滿功率不間斷地發射長得多的時間，這可能使小功率電台的末級功放過熱。連續發射時間上限是 qFT8 讓您的電台一次連續發射的最長時間。

它位於設定 > 裝置配置的調諧（此電台）下。可選值為 20、40、60、90、120 和 150 秒，以及不限制。qFT8 在每個選項下列出該選項新增的內容，您可以看到調高上限能得到什麼。此設定為每臺電台分別儲存。

每種電台的預設值

  • 60 秒：QRPLabs QMX、QMX+ 和 QDX，以及 (tr)uSDX。
  • 120 秒：Xiegu X6100 和 X6200。
  • 不限制：其他所有電台，以及透過 VOX 或揚聲器使用的電台（qFT8 無法知道那是哪種電台）。

這些預設值偏保守。您了解自己的電台、它的功率設定和散熱情況：如果條件允許，可以更改上限。qFT8 絕不會自行調高上限。

上限的作用

  • 時長已知且超過上限的發射不會開始。這就是 WSPR 和較長的 SSTV 模式要求您調高上限的原因：一次 WSPR 發射持續 111 秒，許多 SSTV 圖片需要兩分鐘或更長。當您選擇這樣的模式，或在其中按下 TX ON 時，會有一條訊息告訴您它需要多少秒、您電台的上限是多少，並帶有開啟該設定按鈕。在上限允許該模式之前，發射不會被開啟。
  • 沒有固定時長的發射在到達上限時停止，電台回到接收狀態：TUNE、SSB（PTT 按鈕、VOX 和語音儲存）以及 RTTY。會有通知說明已到達上限。
  • CW 不受限制：電鍵只有一部分時間處於按下狀態。

QMX 與 WSPR：使用 QMX、QMX+ 或 QDX 時，WSPR 需要把上限從 60 秒調高到 120 秒。為了電台的安全，qFT8 請您親手做一次這項更改。可以考慮為 WSPR 降低電台功率：它本來就是一種小功率模式。

遠端控制 Web 伺服器

qFT8 內建了一個 HTTP 伺服器，您可以用網路中的任何網頁瀏覽器來監視和控制應用。這在遠端操作或作為第二塊螢幕時特別有用。

該頁面的外觀和用法與應用本身相同，並且無論瀏覽器視窗大小如何都會填滿視窗。視窗較寬時，頻譜圖在左，所選面板在右；視窗較高時（例如直立拿的手機），頻譜圖在上。底部的欄與應用中的控制項相同：TX 按鈕、訊息、序列、模式和波段，以及電台、QSO 日誌、世界地圖和設定的按鈕。瀑布圖即時滾動，標註與應用中相同。這是較高視窗中的電台檢視：

可以使用 AUTO 按鈕、條件下拉式選單、直接新增呼號的 + 按鈕，以及帶 CALL 按鈕、可手動呼叫的電台列表進行操作。底部欄右端的小燈在頁面與 qFT8 連線期間為綠色。

此檢視顯示最近的日誌條目。另外兩個按鈕開啟：

  • 世界地圖，與應用中相同。它的全螢幕按鈕讓地圖佔滿整個視窗；再按同一個按鈕或按 Esc 可恢復各面板。
  • 頁面的設定（齒輪）：應用中設定的呼號、網格定位和 CQ 修飾詞（僅顯示，不能在頁面上更改）、以 100 ms 為步進的時間偏移、應用傳送瀑布圖的頻率，以及四分割畫面，即同時顯示頻譜圖、電台、世界地圖和 QSO 日誌。四分割畫面的選擇由每個瀏覽器各自記住。

可以同時有兩個瀏覽器連線到同一個 qFT8；您在其中一個上做的操作，一秒鐘之內就會顯示在另一個上。在應用中關閉的功能（見螢幕佈局）在頁面上也會隱藏。頁面不從網際網路載入任何內容：一切都來自 qFT8。

網路與連線

伺服器會在您的手機或電腦上開啟一個特定的 TCP 連接埠（預設 13497）。要存取它，您的裝置必須能在網路上互相「看到」：

  • 本地網路：執行 qFT8 的手機或電腦，與您用來控制的裝置（電腦、平板或手機）必須在同一個網路中。
  • 路由器設定：有些路由器預設開啟了名為 AP 隔離（或客戶端隔離）的功能。必須把它關閉，裝置之間才能互相通訊。
  • 手機熱點的用法：在野外，您可以用一部（能上網的）手機開啟 Wi-Fi 熱點，再讓執行 qFT8 的手機連線到這個 Wi-Fi 網路。連線之後，在 qFT8 的設定中把 Web 伺服器關閉再重新開啟；此時顯示的 IP 位址就可以從提供熱點的那部手機上存取了。
  • 透過網際網路存取：要從家庭網路之外（經網際網路）存取伺服器，需要在路由器設定中配置連接埠轉發（把內部 IP 和連接埠對應到外部）。請注意，由於電信業者的 NAT 限制，這在 5G/LTE 連線上通常行不通。

存取級別

您可以在設定面板中配置遠端存取的安全級別：

  • 唯讀：可以檢視即時頻譜圖、活躍電台和 QSO 日誌。不能執行任何操作。
  • Read + Stop TX（只讀 + 停止發射）：主要是一種安全模式。可以檢視所有資料，並允許在緊急情況下禁止發射（停止 TX），但不能開始發射，也不能更改設定。
  • 完全控制：授予對應用的全部控制權，所有互動功能都可使用。

安全提示：任何能存取您的網路、IP 位址和連接埠的人，都將擁有您所設定的控制級別。如果設為完全控制，他們就有可能用您的電台開始發射。

功能範圍

在完全控制模式下，網頁介面幾乎提供了應用介面的全部功能：

  • 操作模式：在 AUTO 和手動 CALL 模式之間切換。
  • 策略：更改 AUTO 的條件（任何人、DXCC、網格等）和選臺限制。
  • 發射：手動開始/停止 TX，選擇具體的 TX 訊息，並更改 FT8 序列（0/1）。
  • 頻率和波段：點按網頁上的頻譜圖可移動您的頻率偏移，也可以更改當前的波段。

SSB、CW、RTTY 和 SSTV 要在 qFT8 本身中操作。應用處於其中某個模式時，網頁顯示瀑布圖以及應用是否正在發射，但網頁本身不發射；在頁面上選擇一種數字模式，即可重新從頁面操作。

電台的連續發射時間上限對頁面與對應用完全一樣有效。當它使 TX 保持關閉（例如上限為 60 秒時的 WSPR）或停止 TUNE 時，頁面會顯示幾秒鐘的通知說明原因，免得您面對一個毫無反應的按鈕不知所措。上限本身只能在應用中更改。

注意：即使手機螢幕因射頻干擾而變得遲鈍，網頁介面仍能保持靈敏，因此是一個可靠的備用控制手段。

注意：如果開啟了背景執行的相關設定，螢幕關閉時 Web 伺服器仍會工作（預設情況下，qFT8 連線著收發信機時會保持在背景執行）。

qFT8 bridge

qFT8 bridge 讓您把電台留在一個地方，而在另一個地方操作。電台旁邊的一臺裝置，也就是 bridge，透過您自己的網路把電台的命令和音訊傳給另一臺裝置上的 qFT8。其餘的一切都由那個 qFT8 完成：解碼、記錄日誌、決定傳送什麼。對它來說，電台就像用 USB 直接連線一樣工作。

當電台放在天線附近，比如閣樓、車庫或花園小屋裡，而您想在更舒適的地方操作時，就可以使用它；或者當電台旁邊的裝置只需要照看電台時也可以：比如 Raspberry Pi 這樣的小電腦，或一部舊手機、舊平板。

這與遠端控制 Web 伺服器不同。那裡 qFT8 在電台旁邊執行，您從瀏覽器檢視它。使用 bridge 時，qFT8 在您面前的裝置上執行，只有電台在別處。

您需要什麼

  • 電台旁邊的一臺裝置，電台像平常一樣用 USB 連線到它：一臺執行 Windows、macOS 或 Linux 的電腦（Raspberry Pi 就夠了），或一部 Android 手機或平板。這臺就是 bridge。
  • 您用來操作的裝置上的 qFT8：電腦程式或 Android 應用。任何一個都可以使用任何一個 bridge：手機可以操作電腦旁邊的電台，電腦也可以操作手機旁邊的電台，依此類推。
  • 兩者在同一個區域網中。網路線和 Wi-Fi 一樣能用，而且更穩定；如果可以，至少給 bridge 接上網路線。手機或平板使用它的 Wi-Fi，絕不使用移動資料。
  • bridge 的密碼。bridge 會生成一個密碼並顯示給您。

設定 bridge

執行 bridge 有兩種方式，任選其一。

1. 在 qFT8 的設定中（電腦程式或 Android 應用）。在電台旁邊的裝置上，開啟 設定 > qFT8 BRIDGE，勾選以 qFT8 bridge 執行，連接埠。除非有其他程式占用該連接埠，否則保持連接埠不變。

密碼顯示另一臺裝置需要的密碼。新密碼生成另一個密碼；點按密碼本身可以輸入您自己的密碼（7 個字元或更多）。

作為 bridge 時，該裝置上的 qFT8 不做其他任何事。TX 被關閉，它自己對電台的使用停止，螢幕上只顯示qFT8 正以 bridge 模式執行，以及要在另一臺裝置上輸入的 位址和密碼，還有誰在使用電台（沒有裝置連線，或該裝置的名稱）。在 Android 上，bridge 在螢幕關閉時也會繼續執行，並以一條通知顯示；請讓手機或平板保持充電。

關閉 BRIDGE 模式會先詢問，因為另一臺裝置會立即失去電台，然後把 qFT8 恢復成原來的樣子，TX 仍然關閉。如果您在 qFT8 作為 bridge 時關閉它，下次它仍會以 bridge 方式啟動。

2. 從命令列執行（僅限電腦）。適合沒有其他用途的電腦，也適合 Raspberry Pi 或沒有螢幕的伺服器：用 --bridge 啟動 qFT8。這樣它只作為 bridge 執行，沒有視窗，也不載入 qFT8 的其他任何部分（沒有設定，沒有解碼），因此只需要很少的記憶體。在終端中使用您為這臺電腦下載的 qFT8：

  • Windows：在 qFT8 資料夾中開啟命令提示字元，輸入 qFT8.exe --bridge --tx-volume 70。如果 Windows 詢問是否允許「OpenJDK Platform binary」存取您的網路，請允許。
  • macOS：在「終端」中輸入 /Applications/qFT8.app/Contents/MacOS/qFT8 --bridge --tx-volume 70。第一次時 macOS 會請求麥克風權限：請允許，電台的音訊就是這樣讀取的。
  • Linux：在 qFT8 資料夾中輸入 ./qFT8 --bridge --tx-volume 70。
  • 任何裝有 Java 21 或更新版本的電腦，例如使用系統自帶 Java 的 Raspberry Pi：qFT8 的 .jar 下載版可在所有系統上執行。輸入 java -jar、.jar 檔名和 --bridge。它自帶在 Windows、macOS 和 Linux（PC 和 ARM 開發板，32 位和 64 位）上使用序列埠所需的一切。

終端在第一次啟動時顯示密碼，並為以後的啟動保留它。請讓終端保持開啟：終端開著，bridge 就一直執行。 Ctrl+C 或關閉終端會停止它，並讓電台回到接收狀態。

可能用到的選項，加在 --bridge 後面：

  • --tx-volume N: 必需:bridge在發射時為電台的聲音裝置設定的音訊電平(1 到 100 %),與 qFT8 自己的 TX 音量設定相同(預設 70;QRP Labs 電台:100)。這只是聲音電平:電台的功率從不改變。
  • --password TEXT：使用您自己的密碼，而不是它生成的密碼。
  • --show-password：再次顯示儲存的密碼。
  • --new-password：生成一個新密碼。
  • --name TEXT：其他裝置在列表中看到的名稱（否則為「qFT8 bridge」），有多個 bridge 時很有用。
  • --only TEXT：只共享電台的序列埠和聲音裝置，用其名稱的一部分指定（例如 --only QMX）；電腦上的其他任何東西都不提供。

--bridge --help 列出其餘選項。

從 qFT8 連線

在您用來操作的裝置上，開啟設定 > 裝置配置，勾選最上面的 透過 qFT8 bridge 連線。會出現以下各行：

  • 方式：qFT8 bridge。
  • Bridge：開啟 qFT8 在您的網路中找到的 bridge 列表。選擇您的那一個。 重新搜尋會再找一次。如果列表中沒有您的 bridge，請選擇輸入位址，然後輸入 bridge 顯示的位址。
  • 密碼：bridge 顯示的那個密碼。
  • 連線：旁邊的方框變成綠色，顯示已連線到，後面是 bridge 的名稱。
  • bridge 上的電台連接埠、bridge 上的音效裝置（接收）和 bridge 上的音效裝置（發射）：電台在 bridge 一側接在什麼上。 AUTO 會自動找到它們；只有當 bridge 上有多個時才需要手動選擇。透過 bridge 電腦上自帶的程式存取的電台（虛擬序列埠和虛擬音訊線）所用的連接埠，AUTO 無法識別：請手動選擇連接埠，並確認兩個聲音裝置都是那條音訊線的。

此後一切都和 USB 連線的電台一樣：qFT8 識別電台、讀取頻率、接收和發射。qFT8 會記住 bridge 及其密碼，匯出設定時也會把它們帶到您的其他裝置上。方框勾選期間，接在您操作裝置上的電台不會被使用。要改回使用它，取消勾選透過 qFT8 bridge 連線即可，無需重啟。

在手機或平板上，如果裝置沒有連線 Wi-Fi 網路，狀態框會顯示沒有 Wi-Fi。請將此裝置連線到 bridge 所在的網路。因為只會在那裡尋找 bridge。

連線顯示

在 bridge 的裝置下方，有一行告訴您連線的情況，例如 延遲 120 ms，自動調整。連線：平穩（抖動 3.0 ms）。

  • 延遲：網路傳送聲音從來不是完全均勻的，所以音訊在播放前會先保留片刻，把不均勻抹平。這裡沒有需要設定的東西：qFT8 和 bridge 自己選擇延遲，音訊遲到時加大它，連線乾淨一段時間後再減小。它不會打亂數字模式的時序：您的發射仍然準時開始，接收到的內容按電台聽到它的時刻定位。
  • 連線：平穩：一切正常。
  • 連線：不穩定：音訊到達得不均勻。延遲會處理這個問題；除非一直這樣，否則無需做什麼。
  • 紅色的到 bridge 的連線正在丟失發射音訊：一次發射的一部分沒有及時到達電台。延遲會立即加大；如果反覆出現，請參閱故障排除。
  • 紅色的到 bridge 的連線跟不上：即使最大的延遲也不夠，發射音訊斷斷續續。請參閱 故障排除。

剛連線時這一行顯示尚未測量。

發射安全

  • 只有您能開啟 TX，用您面前 qFT8 的 TX 按鈕。bridge 從不自行開始發射。
  • 如果連線中斷（Wi-Fi 斷開、裝置休眠、qFT8 被關閉），bridge 會在一兩秒內自行讓電台回到接收狀態。qFT8 停止正在傳送的內容，關閉 TX，並顯示一張說明原因的紅色卡片，例如連線已中斷。正在重新連線...它會自行重新連線。如果連線在 10 秒內恢復，而您原來開著 TX，qFT8 會按您原來的狀態重新開啟它一次；中斷時間更長時，它保持關閉，直到您再次按下。
  • 電台的連續發射限制同樣由 bridge 執行。
  • 無論用哪種方式停止 bridge，都會讓電台回到接收狀態。

安全提示：密碼保護的是對電台的控制：沒有密碼的人無法使用 bridge，而且密碼本身從不透過網路傳送。它並不能讓連線保密：音訊和電台的命令都沒有加密。只在您自己的網路內使用 bridge，不要把它開放到網際網路。

限制

  • 僅限區域網。bridge 不是為透過網際網路存取而設計的。如果 VPN 把您家庭網路的流量送入它的通道，也會把 bridge 隱藏起來：請在兩臺裝置上關閉它，或在其中允許存取本地網路。
  • 同一時間只能一臺裝置。第二臺裝置連線時會接管；第一臺裝置顯示 另一台裝置接管了 bridge。按「連線」把它拿回來。
  • 所有模式都可以透過 bridge 工作，接收和發射都可以： FT8、FT4、 FT2、JS8、 WSPR、LQ8、 SSB、CW、 RTTY、SSTV 和 TUNE。您的揚聲器和麥克風留在您面前的裝置上；只有電台的音訊經過網路。
  • 透過控制線（RTS 或 DTR）而不是命令切換到發射的電台，同樣可以透過 bridge 鍵控。

qFT8log

qFT8log 透過您自己的網路，把多個 qFT8 的日誌合在一起。其中一個 qFT8 是 qFT8log 伺服器；其他的把它們做的每個 QSO 發給它。伺服器把這些 QSO 加入自己的日誌 （QSO 列表、地圖、統計），並轉發給在它上面設定的服務，例如 QRZ 和 LoTW。之後發生在 QSO 上的事，比如確認或更正，只要兩者保持連線， 就會回到做這個 QSO 的那個 qFT8。

任何一個 qFT8 都可以同時是伺服器和客戶端：電腦程式、Android 應用和 iPhone 應用。在 Android 上， 當在背景執行開啟時，伺服器會在背景持續執行；在 iPhone 上，它只在應用開啟時執行。

設定伺服器

  1. 在要收集 QSO 的那個 qFT8 上，開啟設定，進入 qFT8 伺服器，再開啟qFT8log 伺服器。
  2. 輸入密碼。使用與 qFT8 bridge 相同類型的密碼：七個字元或更多。
  3. 除非連接埠被其他程式占用，否則保持連接埠為 13510，然後啟用伺服器。頁面會顯示伺服器的位址和連到它的 qFT8。更改連接埠後立即生效。
  4. 在瀏覽器中開啟同一個位址（例如 http://192.168.1.20:13510/），輸入伺服器的密碼後 （密碼絕不會被髮送），就能以只讀方式看到日誌：參見 在瀏覽器中檢視日誌。

設定客戶端

  1. 在每個要傳送 QSO 的 qFT8 上，開啟設定，點頂部 qFT8log 旁邊的齒輪。
  2. 點尋找：您網路中的 qFT8log 伺服器會按名稱列出。選擇其中一個， 或者自己輸入伺服器的位址和連接埠。
  3. 輸入伺服器的密碼，點驗證。伺服器接受之後， 在設定頂部勾選 qFT8log。

從此以後，客戶端每次啟動時會自動連線，並在網路或伺服器恢復時自動重新連線。伺服器無法連線期間做的 QSO 會留在日誌中等待（它們顯示為未上傳到 qFT8log），連線恢復後立即傳送，重啟之後也一樣。當客戶端無法連線到伺服器時， 設定中的 qFT8log 一行會變紅，並顯示自 (時間) 起無法連線。

對 qFT8log，上傳到此處即視為 QSO 已上傳預設是關閉的。當伺服器就是您的 QSO 要去的地方時請勾選它， 這樣一旦伺服器收到某個 QSO，該 QSO 的「等待上傳」標記就會消失。

傳輸的內容

  • 新的 QSO，從客戶端到伺服器，包含 qFT8 儲存的每個欄位： 報告、網格、公園和山峰、裝置、備註，以及該 QSO 是否已上傳到 QRZ、LoTW 或其他服務或已被它們確認（從 LoTW 匯入的 QSO 保持已確認）。
  • 確認，雙向，一收到就傳：伺服器從 LoTW 收到的確認會顯示在做這個 QSO 的客戶端上， 反過來也一樣。
  • 在 QSO 編輯器中做的更正，雙向。當同一個 QSO 在兩邊都被修改時，較晚的修改生效。
  • 刪除絕不會傳播。刪除 QSO 只會在那臺 qFT8 上刪除；其他的仍保留。每臺 qFT8 都會記住在它上面刪除的 QSO，並且絕不會從另一臺 qFT8 把它們取回，無論是透過匯入還是即時同步。

伺服器接收每種模式、每個呼號的 QSO：它是您收集的地方，由日誌的篩選器決定您看到什麼。伺服器已經有的 QSO （相同的呼號、時間、波段和模式）會合併到它已有的那個中，絕不會重複新增，也不會再次轉發。

從伺服器匯入與即時同步

客戶端只傳送自己的 QSO。有兩種方式可把伺服器的日誌也帶給它：

  • 客戶端 qFT8log 頁面上的從伺服器匯入 QSO會一次性複製伺服器上位於從、到、頻段和呼號開頭為範圍內、所有模式的全部 QSO。用您以外的呼號進行的 QSO 會被略過，除非勾選了匯入目前呼號以外其他呼號的 QSO。當設定頂部未勾選 qFT8log 時它也能工作：此時匯入只為自己連線，不傳送任何內容。
  • 與此伺服器即時同步（需要在設定頂部勾選 qFT8log）：伺服器的 QSO 會來到這裡，此後在伺服器上或連線到它的任何其他 qFT8 上記錄、更正或確認的每個 QSO 都會立即出現在這裡，您的 QSO 也會傳送過去。多臺勾選此框的 qFT8 透過各自的伺服器共享同一份日誌；對於鏈式連線，則透過鏈上的每臺伺服器共享。
  • 連線斷開時不會丟失任何內容：恢復後各方會補齊，重啟之後也一樣。
  • 更正時間以伺服器的時鐘為準，因此時鐘不準的裝置不會贏得或輸掉每一次更正。

鏈式連線：收集與備份

一個伺服器自己也可以是另一個伺服器的客戶端，因此 qFT8 可以串成鏈。QSO 絕不會被髮回給它已經經過的 qFT8， 所以即使 qFT8 連成環也不會循環。兩個例子：

  • 一個負責上傳的地方。手機和攜帶式電腦把 QSO 發給電台房間裡的電腦。只有這臺電腦設定了 QRZ 和 LoTW：它上傳所有 QSO，它收到的確認會回到做每個 QSO 的那個 qFT8。
  • 備份。電台房間裡的電腦還會把所有內容發給另一個 qFT8，比如一臺只儲存日誌並顯示世界地圖的 舊平板。備份上除了它的伺服器，什麼都不用設定。

安全提示：密碼絕不會透過網路傳送：兩個 qFT8 互相證明自己知道密碼， 之後的每條訊息都經過簽名，因此途中不可能被竄改或重送攻擊。QSO 本身沒有加密。 請只在您自己的網路內使用 qFT8log，不要把它的連接埠開放到網際網路。

限制

  • 僅限家庭網路，與 qFT8 bridge 相同。
  • 兩個 qFT8 必須執行相同的 qFT8log 版本。伺服器會拒絕其他版本的用戶端， 用戶端的那一行會說明應更新哪一個。
  • 每個伺服器同時最多 16 個用戶端。
  • 伺服器無法讀取的 QSO（例如沒有日期的）會在用戶端上標為已被拒絕，只有在您更正之後才會再次傳送。

qFT8log 協定（版本 2）

這是對兩個 qFT8 之間相互傳遞內容的完整描述。所有數字都是大端序。文字為 UTF-8。

尋找伺服器

用戶端向其各個網路的廣播位址、連接埠 13510 傳送一個 UDP 資料包： "qFT8L?"（6 位元組）、API 版本（2 位元組）、一個隨機 id（8 位元組）。每個伺服器 向傳送者回應："qFT8L!"、它的 API 版本（2）、相同的 id（8）、它的 TCP 連接埠 （2）、它的執行個體 id（16 個 ASCII 十六進位數字）、它的名稱長度（1）和它的名稱（最多 64 位元組）。這個回應不含任何機密。

握手

雙方都知道 k = PBKDF2-HMAC-SHA256(密碼, 鹽, 輪數)，32 位元組。伺服器 選擇鹽和輪數（200000；用戶端拒絕少於 10000 或多於 5000000 的值）。工作階段記錄 t 是 HELLO 本文，後面接不含其證明的 CHALLENGE 本文。 令 L = ASCII 文字 "qFT8 log v1 "：

  • 伺服器證明 = HMAC-SHA256(k, L + "server proof" + t)；用戶端證明 = HMAC-SHA256(k, L + "client proof" + t)；
  • 用戶端到伺服器的金鑰 = HMAC-SHA256(k, L + "key client>server" + t)；伺服器到用戶端的金鑰 = HMAC-SHA256(k, L + "key server>client" + t)。

用戶端先檢查伺服器的證明，如果不對就不作回應直接關閉， 這樣由密碼衍生出的任何內容都不會傳給不知道密碼的伺服器。伺服器檢查用戶端的證明； 錯誤的證明會把該位址鎖定 1 秒，之後每連續錯誤一次就加倍，最多到 60 秒。 兩個隨機數每次連線都是新的，所以錄下來的握手毫無用處。API 版本必須相同：伺服器以原因 1 拒絕任何其他版本， 用戶端也拒絕其他版本的 CHALLENGE。伺服器允許同時進行 8 個握手，每一步 5 秒， 最多 16 個用戶端；重新連線的用戶端會接替它原來的連線。

記錄

QSO 記錄是一個 JSON 物件，欄位名稱是 qFT8 所儲存的（call、 qso_date（格式 YYYYMMDD）、time_on（格式 HHMM 或 HHMMSS）、band、 mode、submode、rst_sent、rst_rcvd、 gridsquare、freq、station_callsign、 my_gridsquare、comment、公園和山峰的參照、QRZ 和 LoTW 的狀態 app_qrzlog_logid、app_qrzlog_status、 app_lotw_qsl_rcvd、app_lotw_logid、app_lotw_upload_time，以及 app_svc），最多 16000 位元組。call、qso_date 和 time_on 是必要的；任何模式和任何呼號都會被接受。app_svc 儲存其他服務的狀態和協定本身的三類記錄，格式為 id:key=value,... 的各部分，用 ; 分隔：

  • q8u：id = QSO 的 uid（由最先傳送它的那個 qFT8 一次產生， 在所有更正中保持不變），t = 其內容最後一次被更正的時間（UTC 毫秒， 缺少 = 從未）；
  • q8v：id = 該 QSO 經過的執行個體 id，用點分隔 （最多 32 個）；
  • 傳送方會省略它自己的簿記資訊：它針對每個對端的雜湊、它自己的上傳狀態和它的本機工作標記。

雜湊與合併

QSO 的雜湊是 SHA-256 的前 8 位元組，以 16 個十六進位數字表示，計算對象是其內容、更正時間以及上傳和確認狀態的 name=value 各行（不包括它經過的執行個體）。同一個 QSO 的兩份副本在任何地方都以相同的方式合併成一份： 較晚被更正的那份副本的內容整體勝出（時間相同時：內容雜湊較大的勝出）； 上傳和確認狀態只會向前推進（確認絕不會被撤銷）； 執行個體取兩者的聯集。合併與順序無關，合併兩次也不會有任何改變，所以所有副本最終都相同。

誰傳送什麼

  • 用戶端向其伺服器傳送每個尚未經過該伺服器的 QSO，以及兩者此前交換過、但其雜湊此後已改變的每個 QSO。
  • 伺服器會把兩者此前交換過且雜湊已變化的 QSO（確認、更正）傳送給用戶端。SUBSCRIBE 之後，它還會把自己日誌中位於訂閱範圍內、兩者從未交換過且沒有經過該用戶端的每個 QSO 傳送給該用戶端，然後傳送 BACKLOG_DONE。使用 live 時，只要連線保持，它就會對之後收到的每個 QSO 繼續這樣做（每次重新連線後用戶端會重新訂閱）；once 以 BACKLOG_DONE 結束；off 結束訂閱。
  • 接收方透過 uid 找到自己的副本，否則透過呼號、日期、時間 (HHMM)、波段和模式。伺服器新增自己沒有的 QSO；用戶端只新增位於它所送訂閱範圍內的 QSO。雙方都不會新增在自己這裡已刪除的 QSO（兩種情況下結果均為 3）。否則副本會被合併；ACK 攜帶接收方的雜湊，並且當合併後的副本與所傳送的不同時，還攜帶合併後的記錄，傳送方再將其合併。
  • 每一方針對每個 QSO 和每個對端記住雙方最後一致同意的雜湊，只有當自己的副本與之不同時才再次傳送。 刪除從不傳送。
  • 最多可以有 16 個 PUT 在等待回應。伺服器接收每個用戶端每秒 100 個 PUT（突發 200 個）， 超過時回覆 NACK 2；遇到 50 筆它無法讀取的記錄後，它會結束連線。
  • 一方在 15 秒內沒有傳送任何內容時傳送 PING，在 45 秒內沒有收到任何內容時結束連線。用戶端以 1 秒、2 秒、4 秒 …… 直到 60 秒的間隔重新連線。

螢幕版面配置

本手冊中的截圖顯示的是預設版面配置：橫向，頻譜圖在左。在 Android 應用程式中，可透過設定 > 應用程式 > 使用者介面變更（電腦程式沒有這些設定：它有自己的版面配置，請見螢幕版面配置與版面配置按鈕）：

  • 螢幕方向：橫向、直向或跟隨手機。直向時頻譜圖在上，頁籤在其下方；在手機上，底部列占兩行。
  • 分隔條：拖曳頻譜圖和頁籤之間的細線，可以給其中一方更多空間。每種螢幕方向各自記住自己的位置。
  • 四分割畫面（平板電腦）：同時顯示頻譜圖、電台、世界地圖和 QSO 日誌，「設定」在右側開啟。
  • 功能：電台功能、QSO 日誌和世界地圖不用時都可以單獨關閉，例如只把 qFT8 當作日誌本使用。某項功能關閉期間，「設定」中會顯示它的啟用按鈕。關閉電台功能的同時也會關閉 TX。
  • 應用程式覆蓋範圍：讓 qFT8 繪製到導覽列、相機區域和狀態列上，以獲得稍多一點的空間。

回報問題

「設定」頁籤底部的 回報錯誤 會開啟一張卡片，您可以在其中描述出了什麼問題；如果希望得到答覆，請留下您的電子郵件。按 發送 會把您的描述連同應用程式的執行記錄一起傳送：設定、電台和音訊的詳細資訊，以及最近的活動。密碼、API 金鑰、憑證和您各項 QSO 服務的登入資訊絕不會包含在內。您會得到一個類似 QFT8-7K3P9 的編號，供日後參照。如果連不上回報伺服器，qFT8 會提出改用電子郵件傳送回報。

「要就此傳送回報嗎？」

當 qFT8 發現自己曾短暫停止回應，或者解碼在您的裝置上耗時過長時，可能會顯示一張小卡片，詢問是否就此傳送回報，上面有 發送、不傳送 和 不再詢問。沒有您的點按，絕不會傳送任何內容。這張卡片每天最多出現一次，不再詢問 會讓它一週內不再出現。發生當機後，qFT8 會在下次啟動時詢問是否傳送當機回報。

啟動時檢查新版本

勾選此項後（「設定」主頁面，靠近底部），qFT8 會在啟動時尋找更新的版本，有新版本時顯示帶下載按鈕的通知。它絕不會自行更新。

匿名效能摘要

傳送匿名的每日效能摘要（「設定」主頁面，就在「語言」上方）在您開啟之前是關閉的。開啟後，qFT8 大約每週一次傳送一份簡短摘要，說明它在您裝置上執行得有多快：啟動時間、畫面流暢度、解碼時間、音訊和電台時序，以及裝置型號和螢幕。其中絕不包含您的呼號、網格、日誌、設定或任何能識別您身分的資訊。它有助於讓 qFT8 在與您類似的裝置上執行得更快。

疑難排解

手機或電腦無法識別收發信機，或連線中斷

這幾乎總是硬體連接問題或射頻干擾問題。USB 連接對震動、線材品質以及安家在手機 USB 孔裡的絨毛團都很敏感。在 Android 上，另一個常見原因是您的裝置可能預設關閉了 USB OTG（特別是 qFT8 能收到訊號卻無法發射，而且即使裝置完全受支援、出現在裝置下拉清單中、在 AUTO 模式下被自動識別等等，CAT 命令也不起作用時，原因很可能就在這裡）。

請嘗試：

  • 在 Android 上，在裝置的系統設定中開啟 USB OTG（有些裝置預設關閉 OTG，該選項可能在進階設定、系統設定或更多設定裡）。
  • 使用品質好的短 USB 線（換一條更短的線往往大有幫助），並確認 USB 孔乾淨、插接牢固。
  • 在 Linux 上，如果 qFT8 提示沒有權限開啟電台的連接埠，請接受它提出的修復辦法（把您的帳戶加入該連接埠所在的使用者群組），或諮詢您的系統管理員。
  • 如果問題只在發射時出現，可能是射頻干擾造成的。在 USB 線上加扼流圈或磁環可能有幫助。您也可以換一個波段發射試試，因為有些裝置只對某些波段的干擾敏感。

手機充滿電後收發信機消失（Android）

這種情況出現在帶充電輸入孔的 USB OTG 轉接器上，這類轉接器可以在連接收發信機的同時給手機充電。其中有些轉接器，在電池充到 100% 時手機會中斷與收發信機的 USB 連線，並且在拔掉充電器之前一直不恢復。這時 qFT8 顯示收發信機已中斷連線，什麼都無法運作：沒有音訊，沒有 CAT。

請嘗試：從轉接器上拔掉充電器（收發信機會重新出現），不充電操作，或者改用其他轉接器或有供電的集線器。

qFT8 bridge：「此網路中找不到 bridge」

qFT8 詢問了網路，但沒有 bridge 回應。常見原因是 bridge 沒有執行、兩台裝置不在同一個網路中（訪客 Wi-Fi 算作另一個網路），或者兩者之間有東西擋住了詢問。

請嘗試：

  • 檢查 bridge 是否在執行：它的視窗是開啟的，或者那台裝置上的 qFT8 顯示 qFT8 正以 bridge 模式執行。然後點重新搜尋。
  • 選擇輸入位址，輸入 bridge 顯示的位址。搜尋找不到的 bridge，直接按位址連線時往往仍會回應。
  • 在 bridge 所在電腦的防火牆中放行它：TCP 和 UDP 連接埠 13498，以及 UDP 連接埠 13499（搜尋使用的連接埠）。
  • 在路由器中關閉 AP Isolation（或 Client Isolation），與 遠端控制 Web 伺服器相同。
  • 在兩台裝置上關閉 VPN，或在其中允許存取區域網路。把所有流量送入通道的 VPN 會把 bridge 隱藏起來，即使兩台裝置就放在一起。

qFT8 bridge：「密碼錯誤」，或 bridge 拒絕連線

密碼必須與 bridge 顯示的完全一致。bridge 產生的密碼只有小寫字母和數字，從不包含容易混淆的 i、l、o、0 和 1。連續幾次輸錯後，bridge 會讓該裝置等待一段時間才能再試，最長一分鐘。

請嘗試：在 bridge 上重新查看密碼：在 qFT8 的 bridge 模式畫面上，或者用 --show-password 啟動 bridge 下載版。如有疑問，產生一個新密碼（新密碼，或 --new-password）並輸入它。

qFT8 bridge：已連線，但沒有電台或沒有聲音

連結正常，但 bridge 無法使用電台的連接埠或聲音裝置。方塊可能顯示已連線到 bridge 的名稱，後面跟著「但無法開啟它的聲音裝置」。

請嘗試：

  • 手動選擇bridge 上的電台連接埠和兩個聲音裝置列，而不是 AUTO。
  • 關閉 bridge 裝置上其他所有使用電台的程式，包括不處於 bridge 模式的 qFT8。
  • 在 macOS 上，在系統設定 > 隱私權與安全性 > 麥克風中允許 bridge 使用麥克風。
  • 在 Linux 上，確保執行 bridge 的帳戶可以使用序列埠（通常是加入 dialout 群組）和聲音。
  • 在 Android bridge 上，當 Android 詢問時允許 qFT8 使用電台，就像電台直接插在這部手機上一樣。

qFT8 bridge：「到 bridge 的連結正在遺失發射音訊」或「跟不上」

兩台裝置之間的網路太不穩定：發射音訊抵達得太晚，來不及播放。只要延遲還能加大，qFT8 就會加大它，並提示連結正在遺失音訊；當最大的延遲也不夠時，它會提示連結跟不上，發射會斷斷續續。這是網路的問題，不是電台的問題。

請嘗試：靠近 Wi-Fi 基地台，用網路線連接 bridge（或兩台裝置），並暫停其他占用網路的活動。

qFT8 收到的不是收發信機的訊號，而是麥克風的聲音

在 Android 上，這表示手機正在使用內建麥克風，因為它沒有把收發信機識別為外部音訊來源。在電腦上，請檢查「設定」的裝置設定中選擇的是哪個輸入：選擇收發信機的音訊裝置。最常見的原因是：

  • USB 線不支援資料傳輸（只能充電的線）。
  • USB 轉接頭（OTG）有故障或不相容（Android）。
  • 線插反了（有些線是有方向的）。

請嘗試：換一條 USB 線、換一個轉接頭，或者把線的兩端對調。

電台的刻度與 qFT8 顯示的頻率不一致

電台自己的顯示與 qFT8 顯示的頻率相差幾 Hz 到約 100 Hz。這通常是頻譜圖調諧偏移，而且是有意為之：qFT8 會把電台調得略低一些，並把音訊平移相同的量，這樣頻譜圖最底部的訊號就離開了電台低音訊的盲區。解碼結果、spot、日誌以及 qFT8 顯示的頻率仍然是真實頻率。

請嘗試： 這不是故障，無需處理。預設值因電台而異（QMX 系列為 −100 Hz，IC-7300 為 −90 Hz，其他電台為 −50 Hz）。要變更或設為 0，請開啟 設定 > 裝置設定 > 調諧（此電台） > 頻譜圖調諧偏移（參見 頻譜圖調諧偏移）。

完全收不到訊號；瀑布圖一片漆黑

如果不論收發信機接上還是中斷，瀑布圖都完全是黑的，很可能是 qFT8 沒有獲得存取音訊所需的權限。

請嘗試：在 Android 上，進入手機的設定 > 應用程式 > qFT8 > 權限，確認使用 qFT8 時允許麥克風（或錄音）。或者徹底解除安裝並重新安裝 qFT8，並在首次啟動時接受所有權限提示。在 macOS 上，開啟系統設定 > 隱私權與安全性 > 麥克風並允許 qFT8。在任何電腦上，都請檢查裝置設定中選擇的輸入。

看得到訊號，但解不出訊息

如果您在瀑布圖上看到垂直的「扭動的線條」（FT8 訊號），電台頁籤裡卻沒有文字出現，可能是您的時鐘沒有同步。

請嘗試：

  • 確認可以上網，然後重新開啟應用程式，以觸發一次 NTP同步。
  • 如果沒有網際網路，請嘗試 GPS 同步（Android）。
  • 如果這也不行，但在頻譜圖上能看到訊息的單音，請在「時間和位置」設定選單中觸發「從訊息緊急同步」。
  • 確認您的電台確實從空中收到了訊號。

如果瀑布圖上完全沒有扭動的條紋，可能是波段沒有傳播，或者天線沒有接上/沒有調諧。

訊息解碼得太晚

手機（或較舊電腦）的處理器可能太慢，無法及時解碼訊息。

請嘗試：務必在設定中切換到 Fast decode（快速解碼），也可以把解碼時刻提前（例如提前到 13000ms），給解碼留出更多餘裕，代價是每個週期可能漏掉一些發得較晚的訊息。

QMX 收發信機出現錯誤 「駐波比超限 — 發射已停止」

如果 qFT8 在發射時顯示 0W，有幾種可能的原因：

1. SWR 保護

如果 QMX 的 LCD 顯示螢幕在頻率後面顯示「S」，表示 SWR 保護已經動作。這表示您的天線在目前波段沒有調諧好，QMX 為保護自身電路已停止發射。

此外，qFT8 在應用程式設定中還有自己的 SWR 閾值，可以調整。測得的 SWR 超過這個閾值時，qFT8 會自動停止發射，以保護您的裝置。

  • 韌體 1_04_004+：qFT8 會在週期結束時自動重設 SWR 保護。
  • 韌體 1_03_000+：可以在 QMX 選單中把"SWR Protection reset options"設為 Timer 或 TX->RX。這樣 qFT8 就能繼續運作，您不必動手去碰收發信機。
  • 舊版韌體：QMX 韌體早於 1_03_000 時，必須手動重新啟動收發信機（關機再開機），或在 QMX 上進入再退出 TUNE 選單，才能清除錯誤。

注意：qFT8 在發射開始 1 秒後才檢查是否為 0W，以免在 QMX 功率爬升期間誤報。如果 QMX 恢復正常、功率升到 1W 以上，問題提示會自動消失。

2. 韌體不支援功率測量

如果 QMX 沒有顯示 SWR 保護已動作，並且顯示發射正常，那麼可能是韌體太舊，不支援功率測量。QDX 這類裝置同樣不支援功率測量。qFT8 不知道該如何理解 0W，於是無所適從。

請嘗試：如果您的 QMX 韌體較舊，請更新。如果您用的是 QDX，這一點沒有辦法解決。

3. 音訊訊號沒有抵達 QMX

如果 QMX 在頻率後面沒有顯示「S」圖示，那麼很可能只是收發信機沒有從 qFT8 收到合適的音訊訊號。音量可能太低（訊號不夠）或太高（削波/失真使 QMX 拒絕該訊號）。

請嘗試：查看 QMX 上的訊號指示。一個點表示沒有音訊，兩個點表示有音訊但不夠響。進入 FT8 設定部分，把「使用電台時將系統音量設定為 [X]」調到不同的值（例如 70%、80%、90%），找出適合您裝置的位準。

4. 調諧時 SWR 很低，但 SWR 保護仍然動作

這看起來是實際發射過程中，SWR 在大功率下的某些瞬間出現尖峰，從而觸發了 SWR 保護。這表示天線比較挑剔（例如磁環天線）、線材不良、接觸不良，或者架設有問題。

請嘗試：加共模扼流圈（例如鐵氧體磁環）應該能減小共模電流。

qFT8 的 Android 通知是什麼？（Android）

有了這則通知，您把應用程式最小化或關閉螢幕之後，qFT8 仍能繼續處理音訊和管理 QSO。

  • 預設情況下，接上收發信機時它會自動出現。
  • 您可以在 qFT8 的設定中關閉它，但那樣 qFT8 將不再在背景運作。
  • 在通知中按停止可以完全關閉 qFT8。

螢幕關閉後 qFT8 停止運作（Android）

有些 Android 廠商的電池最佳化非常激進，即使您已授予最初的那些權限，背景應用程式仍可能被系統結束。

請再次確認已授予權限：進入手機的設定 > 應用程式 > qFT8 > 電池，選擇「無限制」（或「不最佳化」）。

發射時按鈕反應異常或螢幕沒有反應

這是射頻干擾 (RFI) 造成的。如果您的天線離手機或電腦很近，或者線材屏蔽不良，射頻能量會干擾觸控螢幕、滑鼠或 USB 連線。

  • 提示：使用有屏蔽的 USB 線，或在線上夾一個磁環。

qFT8 看起來與本手冊中的截圖不一樣

應用程式的使用者介面會不時更新，所以截圖之後一些細小的視覺元素可能已有變化。但是，如果介面的重要部分完全不見了，或者顏色明顯不對（例如黃色進度列、序列選擇器等），可能是手機系統的深色模式錯誤地覆蓋並打亂了應用程式的配色。

請嘗試：如果是系統的深色模式造成的問題，可以暫時關閉它，或把 qFT8 加入它的排除清單，以恢復正確的外觀。

收發信機已經接上，qFT8 卻顯示「NO RADIO」

很可能是您沒有授予 qFT8 連接收發信機的權限。有時是因為點到了權限對話方塊之外的地方，對話方塊就被關掉了。

請嘗試：中斷收發信機再重新接上，這應該會再次彈出提示。為方便起見，請勾選「連接 Transceiver 時始終開啟 qFT8」，這樣就不會再遇到這個問題。

qFT8 用英里顯示距離，而我想用公里（或者相反）

這取決於作業系統的地區設定（即語言選擇）。

請嘗試：把該設定改為相應的國家或地區（例如「英語（美國）」顯示英里，「英語（英國）」顯示公里）即可。

QMX 以 >10W 發射時，qFT8 顯示的發射功率很低（例如 0.1W）

這是 QMX 韌體（至少到 1.03.000 為止）的一個已知缺陷。如果您使用了 2x4 改裝（例如在 QMX+ 上），並且發射功率超過 9.9W，電台輸出的數值格式會溢位回繞。例如 10.1W 會被收發信機透過輔助 CAT 協定回報給應用程式為 0.1W。

請嘗試：在 qFT8 內部沒有變通辦法，因為應用程式只是原樣顯示它收到的值。您可以放心地忽略這個顯示錯誤，或者把功率降到 10W 以下以保持讀數準確，直到收發信機韌體修復這個缺陷。

無法用分享把 ADIF 日誌匯出到本機儲存空間（Android）

預設的分享方法依靠 Android 內建的分享機制匯出日誌。有時裝置內建的分享選單不提供直接儲存到本機檔案系統的選項。

請嘗試：在設定中把匯出方法改為本機儲存。這會使用 Android 的檔案選擇器把檔案直接儲存到本機儲存空間，不依賴分享選單。

qFT8 有些訊息解不出來

請嘗試：在設定中啟用深度解碼。深度解碼進行遞迴解碼，在波段繁忙時能解出更多訊息，代價是需要更多的處理能力。它還會去除很強電台的諧波（過激勵訊號在較高音訊頻率上留下的無法解讀的副本），以便找出其下方較弱的電台。請留意頻譜圖：如果深度解碼在您的裝置上耗時過長（例如超過 1 秒），應用程式來不及做出決定，請關閉深度解碼。

qFT8 當機或行為異常

如果這種情況只在發射時出現，很可能是前面提到的嚴重射頻干擾。如果在其他時候出現，請捲動到「設定」頁籤的底部並按 回報錯誤（見回報問題），或者使用「如有問題或錯誤，請寄電子郵件給我」連結。
